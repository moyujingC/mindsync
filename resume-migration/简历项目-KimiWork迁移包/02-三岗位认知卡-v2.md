## 认知卡一：AI 应用工程师 / 大模型应用工程师

1. **岗位本质**：让 AI 应用在真实环境里稳定产生价值。课程印证：2025 年底以来 Agent 岗的筛选入口已从"会不会用 AI"变成"能不能讲清楚一个 Agent 项目的完整链路"；普通 demo 和套壳 API 项目已经打动不了面试官，要看真实场景、复杂链路、评估指标和失败处理。
2. **能力主张（按重要性排序）**：

   * ① AI 原生开发全流程（SDD / Harness Engineering）：需求拆解 → 规格 → AI 生成引导 → 代码审查 → 调试 → 部署排障

   * ② 评估驱动的质量闭环：评测集建设、模型选型与 A/B、失败样本归因、持续迭代（邓明课九类贡献中"评估与反馈闭环"为必选项）

   * ③ 生产级防御工程意识：终止与降级硬边界、安全边界、可观测与 trace、成本意识（李号双课核心：创造力让 Agent 诞生，防御性工程让 Agent 活下来）

   * ④ 快速进入陌生领域并产出（学习力）
3. **招聘方的雷**：手写代码能力（18 年经验但语言断档）→ 不回避，正面框定。本人 2026-08-05 新口径：早年多年手写代码经验（C++/Lua/C#/Obj-C/Java/Qt），需要时稍做温习即可手写；现在用 AI 原生开发是因为没必要手写，不是不能手写。简历可正面提手写功底，近 2 年项目仍表述为 AI 原生开发全流程；只投自己也在用 AI coding 的团队，这类团队 2026 年正在快速变多。课程印证：传统工程能力做底盘 + Agent 时代新表达，是这个岗位目前最现实的打法。
4. **差异化优势**：2200+ 提交的系统实证、真实上线且可访问的产品、方法论来自真实失败（v1 报废，天然契合面试的 v0→v1→v2 叙事结构）、懂业务懂客户（纯工程师没有）。
5. **不争**：算法/模型训练深度、大厂工程背书、现场手写算法题。
6. **证据映射**：

   * ① ← v1（Lovable，文档过时致 AI 生成出错）报废 → SDD/Harness 重建；MindSync 六阶段门

   * ② ← 双模型选型决策（DeepSeek V4 + qwen-vl-max，GLM 经 9 图×3 轮稳定性评测落选）；golden case 评测集（wealth-case-001\~005）；两段式链路 A/B 对照（"结构化 JSON 会压扁画面信息"的实验结论）

   * ③ ← 双失败降级为低置信度默认三圈；追问 avatar「曼曼」安全拦截设计；三台 CVM 分工 + nightly smoke + auto-repair；16 stage 解读智能体 + 5 个 execution block trace

   * ④ ← 疗愈领域 0→1（知识库三次重构 + 产品上线）
7. **面试表达口径（已定稿，2026-08-05 本人确认）**：

   * 项目名格式：业务场景 + Agent 核心能力 + 系统定位。曼陀罗项目可表述为「曼陀罗绘画解读 Agent 平台（视觉识别 + 多阶段解读链路）」

   * 每条贡献写法：关键技术词汇 + 优化动作 + 数据（绝对值 + 相对值），且每个数字都要能讲清统计口径

   * 叙事主线用三段式（每段有仓库物证，2026-08-05 本人确认）：
     - 阶段一（2026.02）Lovable v1 快速验证 → 主动报废：文档过时致 AI 生成出错、UI 移植失败；教训 = 文档必须成为 AI 的一等事实源
     - 阶段二（2026.03）ai-mandala 独立仓推倒重写：两周建成完整工程化雏形（183 commits 公开可查：FastAPI + 双前端、Obsidian 知识库、specs/ 决策记录、国产模型五维测评框架、CI/CD 三环境、5 级安全协议）
     - 阶段三（2026.04 至今）迁入 mindsync monorepo：项目级工程化升级为公司级治理（六阶段门、golden case 评测集、16 stage 解读智能体、nightly smoke + auto-repair、web.jingshu.cc 内测上线）
     - 叙事定位：不是"失败后才学会工程化"，而是"每一步都在主动提高工程标准"

   * 禁忌：不写无法解释口径的数字；技术词只写用过且能讲清"解决了什么问题"的

## 认知卡二：FDE / AI 解决方案工程师

1. **岗位本质（按课程定义改写）**：嵌入客户现场、主动交付有价值结果的产品探索者。两条硬标准：对**可衡量的业务结果**负责（不是对签单或工时负责）；**现场认知必须回流进产品**——前者区分售前和外包，后者是真假 FDE 的分水岭。AI 时代最稀缺的 FDE，是一个人把 Delta（前线交付）和 Echo（沉淀回产品）两头都担起来的人。
2. **能力主张（按重要性排序）**：

   * ① 高信任场景的需求诊断：从访谈中识别真实目标、约束、风险（不是问"你要什么"）

   * ② 现场认知的沉淀与回流：把单个客户的经验变成 SOP、知识库、培训体系、产品能力，让"第二个客户更容易"（新增。课程判断真假 FDE 最硬的两条：经验能否反哺产品、下一个客户是否更轻）。简历表述口径（2026-08-05 本人反馈）："认知回流"是 FDE 语境术语，HR 不一定认同——简历主句改用结果导向表述「经验能沉淀为体系、且不依赖我个人持续运转」，"第二个客户更容易"保留作面试官锚点

   * ③ 非标准化业务 → 标准化交付的翻译能力（SOP、知识库、验收口径）

   * ④ 方案设计与边界管理 + 技术可行性判断（能承诺什么、不能承诺什么；懂 AI 能力边界，不卖空中楼阁）

   * ⑤ 面客表达：业务问题与量级 → 关键证据 → 建议方案 → 风险与控制 → 资源诉求（二姐课第 20 讲模板；FDE 面客和面试表达同构）
3. **招聘方的雷**：没有大厂/知名企业 AI 交付案例 → 拆法升级：用课程"对什么负责"的框架正面回应——房产 5 年就是对可衡量业务结果负责的交付（4 人团队年营收 200 万、150+ 客户、约 70% 转介绍，全是可衡量指标）；且"第二个客户更容易"的复利标准有硬证据：经纪人上岗周期 18→6 个月、孵化 30+ 经纪人。AI 侧，自己的产品和系统就是"一人公司版 Delta + Echo"的活样本：一线服务认知 → 沉淀为 SOP/培训体系（房产）→ 沉淀为上线产品（曼陀罗）。
4. **差异化优势**：技术 + 高信任咨询 + 创业闭环的三重组合在市场上几乎没有竞争者；方法论可复制有实证（孵化出年成交 2 亿的经纪人）；明确不夸大（本人原则：不包装未成交的服务）。
5. **不争**：大厂项目履历、纯技术深度、英文交付（外企 FDE 岗除外）。
6. **选岗口径（按崔兴反馈拆成两层。注意：它是投递决策和面试工具，不写进简历；简历只承载能力主张和证据）**：

   * **JD 阶段可判断的**：薪资结构含销售提成的"FDE" → 售前换皮，不投（本人已确认接受）。JD 里强调"促成签单、方案宣讲、投标"的同理。

   * **JD 里判断不了、靠面试反问判断的**："经验是否回流产品""是否只做配置集成""第二个客户是否更容易"，这三条从 JD 文字几乎无法分辨——市面多数 FDE 岗位 JD 和交付实施岗的技能项几乎重叠（课程原话）。所以它们不作为筛 JD 的标准，而是面试反问清单：
     - "上一个客户项目里验证过的东西，有多少进了产品的下一个版本？"
     - "第二个同类客户交付时，团队规模和周期比第一个少了吗？"
     - "这个岗位的考核是签单、工时，还是客户的业务指标？"
   * 面试反问同时也在向对方展示自己对 FDE 的理解深度，本身就是加分动作。
7. **证据映射**：

   * ① ← 房产客户访谈→定制方案（150+ 客户、70% 转介绍）；保险需求诊断

   * ② ← RE/MAX 培训体系本土化重构、30+ 经纪人孵化、上岗周期 18→6 个月；高丽蕾 2025 年成交 32 套 / 2 亿+（只以"体系产出"框架引用，本人确认）。本人原话（2026-08-04，可直接用于面试）："每个客户都是一个样本，样本越多，对市场的认知就越全面——等于每个客户都在帮我们解锁一个新样本。"另有维塔士/实艺/镜月的外包驻场经历，亲历人天模式，能讲清外包与 FDE 的分界

   * ③ ← SOP/知识库/培训体系；委托协议与法务打磨"能承诺/不能承诺"

   * ④ ← 模型选型、两段式链路、上线产品；曼曼安全边界设计；v1→v2 的工程判断

   * ⑤ ←（待补：7/24 面试复盘校准这条）

## 认知卡三：AI 产品经理（中小团队 / 产品负责人方向）

1. **岗位本质（升级）**：AI 时代 PM 正在走向全栈 AI builder——需求、设计、开发同步开展、融合在少数几个人身上；在资源受限的小团队里，就是产品的 CEO：从真实问题定义产品，推动 0→1 上线，并管赛道、流量、留存、商业化。不是写 PRD 的岗位，是"对产品结果负责"的岗位。
2. **能力主张（按重要性排序）**：

   * ① 从真实场景定义产品的能力（需求不是脑补的，来自一线服务；课程三法之首：做自己长期、反复需要的产品，自己就是目标用户）

   * ② 产品判断与取舍（范围、分层、什么不做；含趋势性热点 vs 事件性热点的判断）

   * ③ AI 输出的产品化：质量标准、评测、边界（AI PM 区别于传统 PM 的核心）

   * ④ 商业化设计：价值事件收费点、按量 vs 按订阅、付费漏斗（新增。课程要点：AI 产品边际成本与 token 消耗挂钩，按量收费往往比订阅更合理；在深层价值事件发生后设付费墙）

   * ⑤ 端到端推动 + 让产品被看见（一个人走完需求→上线全流程；GEO/内容获客；don't show PRD, show the demo）
3. **招聘方的雷**：没有公司内的产品经理 title → 正面框定：只投"需要能独立交付的产品负责人"的中小团队/创业公司，不投大厂分工型产品岗；产品本身就是最好的作品集（可现场演示）。课程印证：Vibe Working 下 PM/工程师/设计师融合是行业方向，"能独立交付的产品负责人"正是小团队刚需。
4. **差异化优势**：懂技术（9 年研发）+ 懂业务（7 年高信任服务）+ 自己就是目标用户（曼陀罗产品源于自己的服务场景）；疗愈师试用反馈出的两个核心卖点（本人 2026-08-04 总结）：① UI 有调性、有审美，视觉和调性契合疗愈师需求；② 提效与赋能——明显提高疗愈师工作效率，并帮助他们更快学会这套解读方法。定价决策契合付费墙原则（Lite 9.9 低价体验 → Pro 29 仅升级不独立售卖 = 深层价值事件后收费；按份收费与 token 成本挂钩）。
5. **不争**：大厂产品方法论（AARRR 八股）、管理过产品团队、数据驱动的增长案例。
6. **证据映射**：

   * ① ← 产品源于自己 100+ 小时个案的真实痛点；用户分层与四类动机决策

   * ② ← 五类产品矩阵决策（账号内容 / 陪你画·共修营 / 报告 / 主题方案 / 21天定制方案，出自 2026-04-06 产品矩阵决策文档，配套 6 类用户分群与 AI 安全边界机制）

   * ③ ← 两段式链路设计、golden case 评测集、安全边界协议

   * ④ ← Lite 9.9 / Pro 29 仅升级定价逻辑；内测兑换码模式运行中（按份收费，与 token 成本挂钩）

   * ⑤ ← 需求→设计→开发→部署→试用全流程独立完成；小红书早期变现；content-matrix 多账号内容系统
