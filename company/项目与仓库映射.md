> 状态：current
> 最后更新：2026-04-02

这份文档定义 `墨予镜` 公司系统中的项目对象，和本地实际 Git 仓库之间的映射关系。

## 1. 设计原则

`墨予镜` 现阶段采用：

- 单仓库 Monorepo
- 单公司工作空间
- 项目级目录内聚

也就是：

- 公司级系统放在 `mindsync`
- 各产品项目逐步收束到 `mindsync/projects/`
- 公司级治理与项目级实现共处一个仓库，但保持目录边界清晰
- Paperclip 在公司层统一调度，在项目层按目录落地

## 4. Git 管理原则

### 4.1 Monorepo 作为唯一主工作区

当前目标：

- 所有长期维护中的项目工作区统一落在 `mindsync/projects/`
- 公司级治理继续留在 `mindsync/company/` 与根目录入口
- 历史独立仓库只作为迁移来源或归档参考，不再作为默认主入口

### 4.2 提交归属规则

改公司系统内容，提交到：

- [mindsync](/Users/xinran/Downloads/dev/mindsync)

改 `一镜一梳` 项目代码和项目文档，提交到：

- [projects/aimandala](/Users/xinran/Downloads/dev/mindsync/projects/aimandala)

改 `怀瑾握瑜` 项目代码和项目文档，提交到：

- [projects/aicareer](/Users/xinran/Downloads/dev/mindsync/projects/aicareer)

改 `墨予镜` 个人 IP 的账号规则、个人表达基线与账号内容资产，提交到：

- [mindsync/company/projects/墨予镜IP](/Users/xinran/Downloads/dev/mindsync/company/projects/墨予镜IP)

### 4.3 共享内容原则

优先共享：

- 规则
- 方法
- 模板
- 研究结论

不优先把项目实现继续放在仓库外部。

## 5. 后续接入 Paperclip 的方式

在 Paperclip 中，建议映射为：

- 一个公司：`墨予镜`
- 三个核心项目：
  - `一镜一梳`
  - `怀瑾握瑜`
  - `墨予镜 IP`

其中：

- 产品项目挂接各自的 `mindsync/projects/<project-slug>` workspace
- `墨予镜 IP` 作为公司侧内容项目，入口放在 `company/projects/墨予镜IP/`

## 6. 一句话结论

`墨予镜` 现在最适合的形态是：

- `mindsync` 既管公司，也承载项目工作区
- `company/` 管治理与知识
- `projects/` 管项目实现与项目级入口
- Paperclip 在公司层统一编排，在项目目录内执行
