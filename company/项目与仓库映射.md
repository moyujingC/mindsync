> 状态：current
> 最后更新：2026-04-04

这份文档定义 `墨予镜` 公司系统中的项目对象，和本地实际 Git 仓库之间的映射关系。
它不是对象主数据的维护入口；对象清单、类型、状态和主路径统一以
[company/项目注册表.yaml](/Users/xinran/Downloads/dev/mindsync/company/项目注册表.yaml)
为准。

## 1. 设计原则

`墨予镜` 现阶段采用：

- 单仓库 Monorepo
- 单公司工作空间
- 项目级目录内聚

也就是：

- 公司级系统放在 `mindsync`
- 各产品项目逐步收束到 `mindsync/projects/`
- 公司级治理与项目级实现共处一个仓库，但保持目录边界清晰
- Paperclip 在公司层统一调度，在项目层按目录落地

## 4. Git 管理原则

### 4.1 Monorepo 作为唯一主工作区

当前目标：

- 所有长期维护中的项目工作区统一落在 `mindsync/projects/`
- 公司级治理继续留在 `mindsync/company/` 与根目录入口
- 历史独立仓库只作为迁移来源或归档参考，不再作为默认主入口

### 4.2 提交归属规则

改公司系统内容，提交到：

- [mindsync](/Users/xinran/Downloads/dev/mindsync)

改 `一镜一梳` 项目代码和项目文档，提交到：

- [projects/aimandala](/Users/xinran/Downloads/dev/mindsync/projects/aimandala)

改 `怀瑾握瑜` 项目代码和项目文档，提交到：

- [projects/aicareer](/Users/xinran/Downloads/dev/mindsync/projects/aicareer)

改 `内容矩阵` 项目的账号规则、账号矩阵、个人表达基线与账号内容资产，提交到：

- [mindsync/company/projects/内容矩阵](/Users/xinran/Downloads/dev/mindsync/company/projects/内容矩阵)

改 `研究中心` 的研究资产、知识结构与能力底座文档，提交到：

- [projects/research-center](/Users/xinran/Downloads/dev/mindsync/projects/research-center)

### 4.3 共享内容原则

优先共享：

- 规则
- 方法
- 模板
- 研究结论

不优先把项目实现继续放在仓库外部。

### 4.4 所有分支与 worktree 的统一提交纪律

无论当前位于：

- `main`
- 项目开发分支
- 临时实验分支
- 任意本地 `git worktree`

都统一遵守：

1. 本轮改动完成后直接提交
2. 不等待额外口头提醒
3. 不把多个无关主题长期堆在同一工作区等待一起提交
4. 若工作区中同时存在他人改动，只提交本轮责任范围内的文件

## 5. 与 Paperclip 的当前兼容策略

在 Paperclip 中，建议映射为：

- 一个公司：`墨予镜`
- 六个核心项目：
  - `一镜一梳`
  - `怀瑾握瑜`
  - `馨冉求职`
- `内容矩阵`
  - `研究中心`
  - `RelayHub`

其中：

- 产品项目挂接各自的 `mindsync/projects/<project-slug>` workspace
- `内容矩阵` 作为公司侧内容项目，正式入口位于 `company/projects/内容矩阵/`
- `研究中心` 挂接 `mindsync/projects/research-center/`，作为持续研究与知识治理对象

当前不要求为了对象分型而立刻调整 Paperclip 路径。
只要注册表、入口文档和运行时配置保持一致，`product / capability / brand` 可以先共存于现有路径模型中。

补充说明：

- 仓库中的 [company/项目注册表.yaml](/Users/xinran/Downloads/dev/mindsync/company/项目注册表.yaml) 与 [.paperclip.yaml](/Users/xinran/Downloads/dev/mindsync/.paperclip.yaml) 是治理源，不保证和某个本机 Paperclip 实例使用同一套运行时 ID
- Paperclip 本机实例在导入、重建或手工创建项目后，可能生成另一套 `goal/project/workspace` ID
- 因此运行时对账时，应优先按项目名称和 `runtime_directory` 判断是否漂移，而不是假设仓库中的 ID 会直接覆盖实例中的 ID
- 如发现项目工作区路径漂移，可运行 [shared/tools/sync-paperclip-project-workspaces.sh](/Users/xinran/Downloads/dev/mindsync/shared/tools/sync-paperclip-project-workspaces.sh) 进行检查或同步

## 6. 一句话结论

`墨予镜` 现在最适合的形态是：

- `mindsync` 既管公司，也承载项目工作区
- `company/` 管治理与注册表
- `projects/` 当前承载产品工作区，也兼容部分共享能力工作区
- Paperclip 在公司层统一编排，在项目目录内执行
