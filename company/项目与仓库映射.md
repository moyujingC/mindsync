- 公司级系统放在 `mindsync`

- 后续通过 Paperclip 在公司层统一调度

## 4. Git 管理原则

### 4.1 多仓库继续保持

当前不做：

- monorepo 合并
- Git submodule 改造
- 把两个项目仓库并入 `mindsync`

### 4.2 提交归属规则

改公司系统内容，提交到：

- [mindsync](/Users/xinran/Downloads/dev/workspaces/mindsync)

改曼陀罗疗愈产品代码和项目文档，提交到：

- [ai-mandala](/Users/xinran/Downloads/dev/ai-mandala)

改怀瑾握瑜产品代码和项目文档，提交到：

- [ai-career](/Users/xinran/Downloads/dev/ai-career)

### 4.3 共享内容原则

优先共享：

- 规则
- 方法
- 模板
- 研究结论

不优先共享：

- 活跃中的项目实现文件
- 大量通过软链接绑定的变动文档

## 5. 后续接入 Paperclip 的方式

后续在 Paperclip 中，建议映射为：

- 一个公司：`墨予镜`
- 两个核心项目：
  - `一镜一梳`
  - `怀瑾握瑜`

每个项目分别挂接对应仓库作为 workspace。

## 6. 一句话结论

`墨予镜` 现在最适合的形态是：

- `mindsync` 管公司
- `ai-mandala` 管曼陀罗疗愈项目
- `ai-career` 管中年转型项目
- Paperclip 在公司层统一编排，而不是改造为单仓库开发
