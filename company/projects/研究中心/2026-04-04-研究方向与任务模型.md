这份文档定义 `研究中心` 当前的研究范围、任务类型、协作方式和产出要求。

## 0. 总原则

`研究中心` 的研究必须优先围绕公司业务线展开。

这意味着默认优先级应是：

1. 与现有业务线直接相关
2. 与正在孵化的产品方向直接相关
3. 与 `墨予镜` 个人 IP 内容方向直接相关
4. 能增强公司通用方法和 Agent 能力

如果一个主题虽然热门，但和以上主轴都没有明显关系，不应占用 `研究中心` 的主要精力。

## 1. 研究方向

### 1.1 开源项目拆解

研究对象：

- AI 框架
- Agent 框架
- Skill 库
- AI Native 应用
- 值得学习的开发工具链

要回答的问题：

- 它解决什么问题
- 核心能力结构是什么
- 哪些设计值得复用
- 哪些实现模式值得交给架构师继续抽象
- 对你当前产品和服务可能带来什么机会

### 1.2 人与 AI 协作最佳实践

研究对象：

- 大厂公开方法论
- 工程协作实践
- Agent 工作流
- Harness Engineering / SDD / TDD 落地方式
- 多代理协作模式

要回答的问题：

- 他们如何组织人与 AI 的协作边界
- 哪些流程和 artifact 值得引入到 `墨予镜`
- 哪些做法适合一人公司，不适合照搬大团队

### 1.3 源码级材料拆解

研究对象：

- 能帮助理解 AI 工程工作流的源码、泄露材料或公开实现

当前优先材料：

- Claude Code 相关源码材料

重点关注：

- Multi-Agent
- Harness Engineering
- SDD
- TDD
- 工程组织方式

### 1.4 同垂类 AI 产品拆解

研究对象：

- 与当前业务线相近的 AI 产品
- 值得学习的交互流、价值主张与付费设计

要回答的问题：

- 它服务谁
- 它的产品切口是什么
- 它靠什么能力建立差异
- 哪些点说明技术正在驱动新产品形态

### 1.5 同行内容与选题研究

研究对象：

- AI 博主
- 同垂类创作者
- 竞品账号
- 围绕某个选题的代表性内容作品

要回答的问题：

- 他们在这个主题上怎么讲
- 哪些表达角度已经被讲烂了
- 哪些内容受欢迎，但专业含量其实不高
- 哪些角度有参考价值，哪些只是流量包装
- 如果我们要做，应该基于什么专业研究提出自己的观点

这条线的目标不是模仿，而是：

- 借鉴选题和表达策略
- 理解市场认知现状
- 发现内容空位
- 在专业研究基础上形成你自己的判断

## 2. 任务类型

`研究中心` 默认承接以下 5 类任务：

1. 线索收集
   - 发现值得研究的对象，并说明为什么值得看
2. 深度拆解
   - 对单一对象做系统分析
3. 模式抽象
   - 从多个案例中抽取共性做法
4. 知识入库
   - 把结论变成结构化长期资产
5. 协作 handoff
   - 把研究结果转给产品、架构、内容等角色

对于内容相关任务，默认应同时包含两层工作：

1. 对参考内容本身的拆解
2. 对该选题背后专业问题的研究

只有同时完成这两层，才算形成可交给内容侧使用的高质量输入。

## 3. 单个研究任务的最小交付物

每个正式研究任务至少应产出：

1. 研究对象
2. 研究问题
3. 事实摘要
4. 关键拆解
5. 可复用模式
6. 对 `墨予镜` 的启发
7. 哪些内容需要进入知识库
8. 下一步建议交给谁

如果任务与内容选题有关，还应额外产出：

9. 参考内容拆解
10. 我们自己的观点框架
11. 哪些表述可以交给 `Content Lead` 做传播化处理

## 4. 协作方式

默认 owner：

- `Research & Knowledge Lead`

常见协作者：

- `Architect`
  - 当研究对象涉及系统设计、代码结构、框架模式时
- `Product Spec Lead`
  - 当研究结果需要转成产品定义时
- `Business Lead`
  - 当研究涉及商业机会、服务模型和付费逻辑时
- `Content Lead`
  - 当研究结果适合转成内容选题、内容结构和表达资产时

## 5. 入库标准

不是所有研究笔记都应直接进入长期知识库。

默认只有满足以下任一条件的内容，才值得正式入库：

- 可复用
- 可迁移
- 会反复遇到
- 能增强多个 Agent 的能力
- 能帮助产品判断、技术判断或商业判断
- 能持续增强内容选题质量与观点质量

## 6. 当前执行原则

- 先做高价值对象，不追求面面俱到
- 先围绕业务线研究，再扩展到更泛的主题
- 先做拆解和抽象，不做资料收藏夹
- 研究完成后必须决定是否入库
- 每项研究都要明确服务对象：产品、架构、商业、内容或知识库
- 不让研究停留在聊天记录中
- 做内容研究时，不只拆内容形式，还要补足专业问题研究与原创观点
