## 1. 用途

这份文档用于记录 `墨予镜` 个人号从选题苗头到文章准备阶段的判断流程。

它解决的问题是：

- 有了真实感受和观点，但担心内容没有价值；
- 想确认别人是否讲过，又不想输出烂大街观点；
- 容易在写作前继续搜索资料、做深度分析，导致疲惫并影响输出；
- 把个人号常规文章误升级成研究交付。

这份文档不是正式 skill。等流程经过多轮内容实践验证后，再提炼成可复用 skill。

## 2. 基本原则

个人号常规文章，写前只验证三件事：

```text
真实 / 清楚 / 有带走感
```

这三个条件用于判断“能不能开始写”，不用于判断这篇文章是否已经达到研究报告级别。

写前不默认验证：

- 是否全网没人讲过；
- 是否资料完备；
- 是否有完整数据链；
- 是否覆盖所有反例；
- 是否已经形成系统研究结论。

## 3. 3Q 写前验证

### 3.1 真实

检查问题：

- 这是不是创作者真实经历、真实观察、真实困惑或真实判断？
- 能不能说出一个具体场景？
- 是否在把项目材料、AI 推断或更高级的说法伪装成本人立场？

通过标准：

- 能对应到创作者真实体验或已确认判断；
- 能说清这个感受从哪里来；
- 不虚构经历、案例和稳定立场。

不通过时：

- 不进入成稿；
- 先补个人素材、采访问题或观点卡。

### 3.2 清楚

检查问题：

- 这篇到底想说清哪一个判断？
- 能不能用一句话表达核心观点？
- 是否试图同时完成现象、成因、数据、方法和行业分析？

通过标准：

- 一篇文章只解决一个主要问题；
- 核心判断能压缩成一句话；
- 不把常规文章写成综合研究报告。

不通过时：

- 先收成观点卡；
- 不继续搜索资料；
- 不直接扩写。

### 3.3 有带走感

检查问题：

- 读者看完能带走什么？
- 是重新理解一个体验，获得一个判断框架，还是拿走一个小方法？
- 读者会少踩什么坑？

通过标准：

- 能帮助读者命名一种模糊体验；
- 或提供一个可迁移的判断方式；
- 或给出一个低成本可尝试的小方法。

不通过时：

- 补“读者是谁”；
- 补“他为什么会关心”；
- 补“看完后他能改变什么理解或动作”。

## 4. 内容类型判断

通过 3Q 后，再判断选题属于哪类内容。

### 4.1 感受观点型

目标：

- 说清一个真实体验和一个判断。

资料要求：

- 默认不新增搜索；
- 最多引用一个已有资料点作为背景支撑。

适合场景：

- “作为一个重度AI使用者，你有没有更累了？”
- “AI 让我重新开始做很多事，也让我更累了。”

### 4.2 方法复盘型

目标：

- 讲清自己如何调整、如何判断、如何形成闭环。

资料要求：

- 可以不引用外部资料；
- 重点是步骤、边界和复盘。

适合场景：

- “我现在如何判断一个 AI 任务该不该继续做。”
- “为什么我不再把每个选题都升级成研究任务。”

### 4.3 研究分析型

目标：

- 系统拆解概念、成因、证据和方法。

资料要求：

- 需要明确 source；
- 需要区分个人体验、外部资料和推断；
- 需要事实核查或来源标注。

适合场景：

- 行业分析；
- 研究报告；
- 课程材料；
- 涉及心理健康、疗愈建议、医学、金融、法律等高风险内容。

## 5. 新意检测

个人号选题不追求“全网没人讲过”，而追求以下几类新意：

### 5.1 人群更具体

不要只写“AI 用户”，可以具体到：

- 重度 AI 使用者；
- 独立开发者；
- 一人公司；
- AI 内容创作者；
- 重新开始编程的人；
- 同时做产品、内容、研究和疗愈的人。

### 5.2 机制更细

不要只写“信息过载”，可以拆成：

```text
可行性增加 -> 任务扩张 -> 判断负荷上升 -> 收口困难 -> 疲惫累积
```

### 5.3 场景更真实

优先使用已确认的真实场景：

- token 定量，不用完会觉得浪费；
- 快十年没写程序后重新开始编程；
- 自媒体选题容易被升级成研究任务；
- 看到 AI 能做更多事后，主动开启更多任务。

### 5.4 边界更清楚

不要停在泛泛建议，例如“少用 AI”。

更有辨识度的边界包括：

- 不把每个个人号选题都升级成研究交付；
- 不在疲劳时继续让 AI 改主干文档；
- 已有资料足够支撑常规表达时，不新增搜索入口；
- 当下闭环和长期架构要分开判断。

## 6. 研究上限

默认规则：

- 感受观点型：不新增搜索，最多引用一个已有资料点；
- 方法复盘型：不强制引用外部资料；
- 研究分析型：才启动系统搜索、资料整理和事实核查。

需要升级研究的信号：

- 内容要给出专业建议；
- 内容涉及高风险领域；
- 文章主张依赖外部事实；
- 准备做成课程、报告或产品知识；
- 已有读者反馈显示议题值得展开。

不需要升级研究的信号：

- 文章只表达个人真实体验；
- 核心价值在于命名一种感受；
- 已有一份背景资料足够支持；
- 文章目标是启动讨论，而不是完成论证。

## 7. 输出内容卡

每个选题在成稿前，先输出一张内容卡。

模板：

```text
选题：
标题候选：
内容类型：感受观点型 / 方法复盘型 / 研究分析型

真实：
- 真实场景：
- 已确认判断：

清楚：
- 一句话核心观点：
- 本篇只解决：
- 本篇不解决：

有带走感：
- 目标读者：
- 读者带走：

新意：
- 具体人群：
- 更细机制：
- 真实场景：
- 清楚边界：

研究上限：
- 是否新增搜索：
- 可引用已有资料：
- 不补充什么：
```

## 8. 当前可用示例

选题：

```text
作为一个重度AI使用者，你有没有更累了？
```

内容类型：

```text
感受观点型 / 方法复盘型
```

一句话核心观点：

```text
AI 让人更累，不只是因为它输出更多信息，而是因为它让更多原本做不到的事情变得可行，导致任务扩张、判断负荷上升和收口困难。
```

新意：

- 人群：重度 AI 使用者、独立开发者、AI 内容创作者；
- 机制：可行性增加 -> 任务扩张 -> 判断负荷上升 -> 收口困难；
- 场景：token 定量、不用完像浪费；快十年没写程序后重新开始编程；选题被升级成研究任务；
- 边界：常规个人号文章不应默认升级成研究交付。

研究上限：

- 不新增搜索；
- 可引用已有 AI 疲劳报告作为背景；
- 不补完整行业综述、数据链和全部解决方案。

## 9. 后续转 skill 条件

满足以下条件后，可以创建正式 skill：

- 用这个流程处理过至少 3 个选题；
- 每次都能输出可用内容卡；
- 能明确哪些情况该停在观点卡，哪些情况该升级研究；
- 创作者确认这个流程能降低写作前的疲劳和反复搜索冲动。

候选 skill 名：

```text
content-topic-development
```
