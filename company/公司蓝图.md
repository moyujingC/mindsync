这份文档定义 `墨予镜` 的慢变量设计。
它不是“当前全量现实”的记录，也不负责追踪每周变化的项目状态、目录细节或运行时配置。

它只回答四个问题：

- `墨予镜` 是一家什么样的公司
- 为什么要用一人公司 + 多 Agent 的方式运作
- 长期稳定的组织原则和角色哲学是什么
- 什么内容不应该继续维护在这份文档里

## 1. 公司定义

### 1.1 公司名称

墨予镜

### 1.2 核心定位

`墨予镜` 不是单纯的软件开发公司，也不是单纯的内容工作室。

它是一套以研究和知识为底座、以产品与商业设计为驱动、以工程交付为实现、以内容生产为放大器的中文一人公司操作系统。

长期来看，它同时具备以下能力层：

- 产品孵化
- 垂直行业研究
- 知识库建设
- 内容生产与个人 IP 放大
- 软件实现与工程交付
- 商业模式探索与服务设计

### 1.3 组织目标

`墨予镜` 的目标不是先做一个“很多 Agent 的公司”，而是先做一个真正可运行、可沉淀、可复用的中文一人公司系统。

这意味着它必须长期能够支撑：

- 产品设计讨论
- 行业研究与 know-how 积累
- 知识治理
- 内容生产
- 软件架构与开发
- 测试与质量验证
- 商业判断与服务设计

## 2. 组织原则

`墨予镜` 的长期设计由以下原则驱动。

### 2.1 中文优先

默认工作语言为中文。

### 2.2 Docs As System

文档不是附属品，而是公司系统的一部分。
重要结论、hand-off 和约束必须有稳定落点，而不是只存在聊天记录中。

### 2.3 Research First

`墨予镜` 不是“先堆功能、再理解问题”的公司。
研究不是附属工作，而是产品、内容和商业判断的共同底座。

### 2.4 Productize What Matters

不是所有研究都要产品化，也不是所有内容都要服务化。
公司要持续判断：哪些洞察值得沉淀，哪些能力值得产品化，哪些表达值得放大。

### 2.5 Keep The Company Small And Sharp

一人公司最容易死在组织过度设计。
`墨予镜` 的组织设计追求边界清楚、闭环稳定，而不是角色越多越好。

## 3. Operating Model

`墨予镜` 采用的是“一人公司 + 多 Agent 协作”的 operating model。

核心含义是：

- 人类创作者保留最终判断、真实表达和战略取舍
- Agent 承接研究、分析、设计、实现、验证和内容转译
- 公司不是围绕单一产品运转，而是同时管理产品、能力底座和品牌表达

长期稳定的三类对象为：

- `product`
  - 面向外部用户或服务场景的产品项目
- `capability`
  - 为多个项目和多个 Agent 提供共享能力的底座
- `brand`
  - 承接统一对外叙事和个人表达的品牌对象

这三类对象共同构成公司的运行单元，但它们不拥有相同的职责和内容归属方式。

## 4. 角色哲学

`墨予镜` 需要多角色，不是为了模仿传统公司岗位，而是为了让以下边界长期清楚：

- 谁负责商业判断
- 谁负责问题定义和 spec
- 谁负责研究与知识治理
- 谁负责系统设计和实现
- 谁负责质量验证
- 谁负责对外表达和内容转译

当前核心角色包括：

- Idea Clarifier
- CEO / Orchestrator
- Business Lead
- Product Spec Lead
- Research & Knowledge Lead
- UI / UX
- Architect
- Engineer
- Test / QA
- Content Lead

这些角色的“存在理由”是慢变量；角色的具体提示词、具体任务分工和运行时配置是快变量。

## 5. 知识与内容的长期关系

`墨予镜` 的长期优势不来自单点爆款，而来自研究、产品、内容三者之间形成可复用回路。

稳定关系如下：

- 研究提供洞察、方法和判断框架
- 产品把高价值洞察转化为服务、工具和交付
- 内容把研究和产品实践转化为外部表达、信任和影响力

其中：

- 研究中心承担共享能力底座
- 各产品项目承担各自产品语境下的内容与交付
- `墨予镜 IP` 承担跨项目的统一叙事、第一人称表达和品牌放大

## 6. 工作流原则

`墨予镜` 需要稳定工作流，但这份蓝图不维护具体流程细节。

长期不变的原则只有三条：

- 产品、研究、内容都应该形成闭环，而不是只做前半段
- 任何重要工作都应该能回写成长期资产
- 组织设计要服务闭环，而不是让流程变成新的负担

具体 artifact、阶段门和状态规则，统一以专门治理文件为准。

## 8. 一句话结论

`墨予镜` 的核心不是“拥有很多 Agent”，而是把研究、产品、内容、工程和个人表达组织成一个长期可复用的一人公司系统。
