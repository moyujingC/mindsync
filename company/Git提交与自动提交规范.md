# Git 提交与自动提交规范

> 状态：current
> 版本：0.1.0
> owner：CEO / Orchestrator
> last_updated：2026-04-27
> source_of_truth：company/Git提交与自动提交规范.md

这份文档定义 `mindsync` 在本地 IDE 代理协作中的统一 Git 提交纪律，以及仓库内提供的自动提交辅助机制。

## 1. 目标

解决两个问题：

- 改动做完后仍长期滞留在工作区，导致 handoff 不清
- 代理每次都要被用户额外提醒“记得提交”

默认目标是：

- 改完即提交
- 提交范围清晰
- 在任意分支、任意 `git worktree` 下口径一致

## 2. 统一规则

从现在开始，`mindsync` 默认执行以下规则：

1. 只要已经完成一个可描述的最小改动闭环，就应立即提交
2. 该规则适用于所有分支、所有本地 `git worktree`
3. 不把“用户没提醒，所以先不提交”当作允许理由
4. 修改完成但未提交，默认不视为交付完成

## 3. 自动执行口径

这里的“自动执行”分两层：

### 3.1 代理层自动执行

根目录 `AGENTS.md` 与 `CLAUDE.md` 已把“改完即提交”写成默认纪律。

这意味着：

- `Codex`
- `Claude Code`
- 其他会先读取仓库入口说明的 IDE 代理

都不应再等待用户手动提醒才提交。

### 3.2 Git 层辅助执行

仓库提供：

- `.githooks/prepare-commit-msg`
- `shared/tools/install-git-hooks.sh`

用途是：

- 为未手写 commit message 的提交自动生成最小说明
- 把统一 `hooksPath` 安装到仓库级配置

它不是“文件一改就后台秒提”的文件监听器，而是“当代理执行提交动作时，不再因为忘写说明而卡住”。

## 4. 边界与限制

需要明确：

1. 纯 Git hook 无法监听“任意文件一保存就立刻 commit”
2. 因此本仓库当前采用的是“代理默认必须提交 + Git 自动补齐提交说明”的组合方案
3. 若未来要实现真正的后台文件监听自动提交，应另行引入守护进程或系统级 watcher，而不是误称为普通 hook 能力

## 5. 与脏工作区共存的规则

若当前分支或 worktree 已存在其他未提交改动：

1. 只提交本轮负责文件
2. 不替别人清理、重写或收口无关改动
3. 必要时只对明确文件做 `git add <path>`

## 6. 安装与继承

仓库级安装命令：

```bash
shared/tools/install-git-hooks.sh
```

安装后：

- 当前仓库会把 `core.hooksPath` 指向仓库内 `.githooks`
- 共享同一 Git 公共目录的 worktree 会继承该配置

## 7. 完成标准

这条规则生效后，代理在本仓库中的默认表现应是：

- 改动完成
- 立即提交
- 用户无需额外提醒“记得提交”
