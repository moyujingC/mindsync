## 模板说明
本模板基于「怀瑾握瑜」项目可行性研究报告抽象而来，适用于ToC/ToB互联网产品、AI应用产品的立项前可行性分析阶段。

## 模板结构

### 1. 文档头部（必填）
```markdown
# [项目名称]可行性研究报告

> 状态：[草稿/评审中/已归档]
> 来源：[Paperclip 任务编号/项目名称]
> 原始文档键：[对应issue文档键（如有）]
> 落档时间：YYYY-MM-DD
```

### 2. 背景（必填）
- 说明报告产生的背景和来源
- 明确研究的目标和范围
- 说明为什么要做这份研究

**示例：**
```markdown
## 1. 背景
本报告由 Paperclip 任务 `[任务编号]` 产出，原题为「[任务标题]」。
为避免关键结论只停留在运行态 issue 文档中，现将其同步落档到 `mindsync`，作为公司内核中的正式研究资料。
```

### 3. 产品概述（必填）
- 一句话描述产品是什么
- 核心价值主张
- 核心差异点（至少3个，与现有解决方案的本质区别）

**示例结构：**
```markdown
## 2. 产品概述
[产品名称]是一套面向[目标用户]的[产品类型]系统，核心价值是[核心价值]。

### 核心差异点
1. [差异点1]：[具体说明]
2. [差异点2]：[具体说明]
3. [差异点3]：[具体说明]
```

### 4. 用户研究（必填）
#### 4.1 目标用户画像
- 核心用户定义（年龄、特征、痛点）
- 潜在用户范围
- 常见用户痛点

#### 4.2 付费意愿假设（面向付费产品）
- 价格区间预期
- 付费动机分析
- 价格敏感度判断

#### 4.3 市场规模假设
- 总体市场容量
- 目标用户群体规模
- 行业相关数据支撑

**示例结构：**
```markdown
## 3. 用户研究初步结论
### 3.1 目标用户画像
核心用户为[年龄范围]、处于[用户状态]的人群。
- [特征1]
- [特征2]
- [常见痛点]

潜在用户包括：
- [潜在用户1]
- [潜在用户2]

### 3.2 付费意愿假设
- 单次服务预期区间：[价格范围]
- 年度订阅预期区间：[价格范围]
- 主要付费动机：[动机列表]
- 价格敏感度判断：[高/中/低，判断依据]

### 3.3 市场规模假设
- [总体市场数据]
- [目标用户群体占比/规模]
- [行业相关数据支撑]
```

### 5. 竞品分析（必填）
- 直接竞品分析（现有同类产品）
- 间接竞品分析（替代方案）
- 现有解决方案的优缺点

**示例结构：**
```markdown
## 4. 竞品分析
### 4.1 现有同类产品
1. [竞品1]：[优势]，但[劣势]
2. [竞品2]：[优势]，但[劣势]
3. [竞品3]：[优势]，但[劣势]

### 4.2 替代方案
- [替代方案1]：[优势]，但[劣势]
- [替代方案2]：[优势]，但[劣势]
```

### 6. 技术可行性评估（技术产品必填）
#### 6.1 核心技术模块
- 列出核心技术模块
- 评估每个模块的技术难度和可行性

#### 6.2 技术选型建议
- 大模型/技术底座选型
- 核心技术栈建议
- 架构方案选择

#### 6.3 主要技术风险
- 可能的技术难点
- 风险应对思路

**示例结构：**
```markdown
## 5. 技术可行性评估
### 5.1 核心技术模块
1. [模块1]：技术难度[低/中/高]，整体可行性[高/中/低]
2. [模块2]：技术难度[低/中/高]，整体可行性[高/中/低]
3. [模块3]：技术难度[低/中/高]，整体可行性[高/中/低]

### 5.2 技术选型建议
- [技术选型1]：[理由]
- [技术选型2]：[理由]
- [技术选型3]：[理由]

### 5.3 主要技术风险
1. [风险1]：[应对思路]
2. [风险2]：[应对思路]
```

### 7. 商业模式验证（商业化产品必填）
#### 7.1 定价假设
- 不同版本/套餐的定价
- 定价依据

#### 7.2 成本结构估算
- 可变成本估算
- 固定成本估算
- 研发/获客成本估算

#### 7.3 单位经济模型初算
- 平均客单价
- 可变成本/边际利润
- 毛利率
- 盈亏平衡点

#### 7.4 获客渠道
- 核心获客渠道列表
- 渠道优先级排序

**示例结构：**
```markdown
## 6. 商业模式验证
### 6.1 定价假设
1. [版本1]：[价格]
2. [版本2]：[价格]
3. [版本3]：[价格]

### 6.2 成本结构估算
- [成本项1]：约[金额范围]/用户
- [成本项2]：约[金额范围]
- [成本项3]：约[金额范围]/付费用户

### 6.3 单位经济模型初算
- 平均客单价：[金额]
- 可变成本：约[金额]/用户
- 边际利润：约[金额]
- 毛利率：约[百分比]
- 盈亏平衡点：约[用户数量]名付费用户

### 6.4 获客渠道
1. [渠道1]：[说明]
2. [渠道2]：[说明]
3. [渠道3]：[说明]
```

### 8. 总结论（必填）
- 整体可行性判断
- 核心支撑理由（3-4点）

**示例：**
```markdown
## 7. 总结论
报告给出的初步判断是：[项目名称]具备[高/中/低]可行性，核心逻辑[成立/基本成立/不成立]。

支撑理由主要有四点：
1. [理由1]
2. [理由2]
3. [理由3]
4. [理由4]
```

### 9. 仍待验证的关键假设（必填）
- 列出所有需要进一步验证的假设
- 按优先级排序

**示例：**
```markdown
## 8. 仍待验证的关键假设
1. [假设1]
2. [假设2]
3. [假设3]
4. [假设4]
```

### 10. 建议的下一步（必填）
- 明确的行动建议
- 可落地的下一步工作
- 责任方/时间节点（可选）

**示例：**
```markdown
## 9. 建议的下一步
1. [下一步1]：[具体说明]
2. [下一步2]：[具体说明]
3. [下一步3]：[具体说明]
```

## 使用说明
1. 本模板为通用模板，可根据项目类型（纯内容项目/硬件产品/ToB服务等）适当裁剪不需要的章节
2. 所有数据和判断都需要有依据，避免主观臆断
3. 可行性研究完成后，应同步归档到公司知识库，并关联对应Paperclip任务
4. 后续迭代更新应优先在知识库文档中维护，并回链到对应任务

- 原始报告：替换为当前项目对应的研究报告路径
- 对应任务：替换为当前项目对应的 Paperclip 任务链接
