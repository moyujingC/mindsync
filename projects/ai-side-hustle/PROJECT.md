这是 `AI 副业` 的正式项目工作区。目录名为 `ai-side-hustle`。

## 1. 当前阶段

当前阶段是案例收集与机会初筛，目标是建立有来源、可追溯的候选池，而不是立刻批量执行副业。

一个候选方向至少应说明：谁会付费、解决什么问题、如何交付、自动化放在哪里、需要哪些人工复核，以及收入证据是否可核验。

## 2. 目录使用

- `cases/`
  - 用户提交的案例、链接、截图说明和原始文字记录。
  - 每个案例优先建立独立目录，保留 `原文` 或 `OCR原文`，再写分析笔记。
- `specs/`
  - 对通过初筛、准备进入小规模验证的候选方向编写 spec。
- 后续按需建立 `tasks/`、`qa/` 与 `delivery/`，分别记录执行计划、验证结果与交付记录。

## 3. 案例处理规则

1. 先保留来源与原文，来源不明时明确标注。
2. 将案例中的收入、成本、自动化效果视为待验证说法。
3. 记录可复用流程，也记录平台限制、授权需求和失败条件。
4. 不收集或传播不必要的个人隐私、账号凭据或客户机密。
5. 不因单一案例直接决定投入；进入试点前另行编写 spec 与验收口径。

## 4. 初筛维度

案例可按以下维度进行初筛：

- 需求与付费：是否存在具体、可触达的客户问题。
- 交付：结果是否清楚，质量是否可人工复核。
- 自动化：AI 能否承担重复环节，人工是否保留关键判断和最终责任。
- 经济性：启动成本、获客成本、交付耗时和收入证据是否可估算。
- 风险：平台规则、内容权利、数据安全、支付和税务边界是否可接受。

## 5. 当前下一步

用户提交首个案例后，先在 [cases/README.md](./cases/README.md) 的结构下建档；当至少有一个候选方向具备明确用户、交付和验证方式时，再进入试点 spec。
