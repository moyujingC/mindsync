## 1. 教程输入与使用方式

本记录的教程输入来自创作者于 2026-08-23 提供的关卡截图。截图把一个 Agent 从零到可组织协作的过程分为 0-9 关：

| 关卡 | 教程中的动作 | 本项目的使用方式 |
| --- | --- | --- |
| 0 | 看懂全貌、装工具 | 锁定公众号单一试点、检查 Codex/Hermes/飞书 CLI 与数据边界 |
| 1 | 跑通最小 Demo | 用主题卡开始对话，确认观点与结构后生成可审阅草稿 |
| 2 | 选岗位、定边界 | 为每个 Agent 写岗位卡、输入输出合同和禁止动作 |
| 3 | 拆流程、画工作流 | 以 artifact（交付物）而不是对话口头约定进行交接 |
| 4 | 写 Hermes Profile | 为每个 Agent 建独立 Profile、权限和测试记录 |
| 5 | 接 Codex + 飞书 CLI + 生成页面 | 先连模拟表做只读验证，避免形成第二份内容主库 |
| 6 | 测试、修订、写说明、提交 | 形成可复跑的说明、运行记录和 Git 提交 |
| 7-9 | 上下游、接力、服务化 | 只在前序工作流已经真实运行后再进入 |

这是一份项目实践方法记录，不是对教程原始材料的事实核查或正式知识库条目。后续若要将方法升格为通用 Skill，必须基于本项目至少三次运行记录和人工 review（审阅）结论。

本次“关卡 01 最小 Agent”的适配结论是：教程示例要求接任务、调用工具和生成文件，但这些是示例岗位的动作，不是每个岗位的硬要求。`内容访谈与草稿助手` 的最小链路是“脱敏主题卡 -> 对话确认观点与结构 -> 无工具生成草稿 -> 人工审阅 -> 原对话修订”；为了演示而给它开放下载、文件写入或外部发送权限，会破坏本岗位的边界。

## 2. 本次设计判断

用户确认“墨予镜公众号内容生产”是一整条工作流，将由多个 Agent 组成。因此当前不把一个通用 Hermes 当作整条工作流，也不复用已经服务内容情报系统的 Hermes。

采用的运行结构：

```text
一个 Agent 岗位
-> 一个独立 Hermes Profile
-> 一个独立飞书应用机器人
-> 独立会话、权限、日志与凭证
```

第一个岗位选“内容访谈与草稿助手”。它处在流程最前端，在飞书对话中确认“哪些是创作者明确认可的观点”，并把确认后的观点直接写为待人工审阅的草稿。草稿不通过时，创作者在原对话继续讨论意思或观点，Agent 再输出修订版；无需先拆出编辑 Agent。

## 3. 服务器创建记录

### 3.1 创建前检查

目标服务器：腾讯云 release 主机 `42.192.65.145`。

- 已存在 `hermes-content-matrix.service` 与 `hermes-gateway.service`，两者服务已有内容情报系统。
- 既有 Hermes 版本为 `0.19.0`，服务仅监听本机 `127.0.0.1:9119`。
- 既有服务目录为 `/opt/content-matrix-inbox/`，不可改写或复用其飞书应用、会话、技能、记忆与凭证。
- 创建时服务器没有 `feishu-cli` 可执行命令；该 CLI 的安装与飞书授权另行记录。

### 3.2 新 Profile

2026-08-23 创建、2026-08-24 重命名后的 Hermes Profile：

```text
展示名：myjContentAgent
Hermes 运行时 ID：myjcontentagent（Hermes 会自动转为小写）
路径：/opt/content-matrix-inbox/hermes-home/profiles/myjcontentagent
创建方式：hermes profile create moyujingcontent --no-skills --no-alias；随后执行 `hermes profile rename moyujingcontent myjContentAgent`
```

创建时使用 `--no-skills`，所以不会继承旧 Agent 的 Skill；Profile 的 `.env` 为空，Gateway 为 stopped，尚未配置模型 Key 或飞书 App 凭证。

### 3.3 已完成的隔离配置

2026-08-23 完成了以下配置，过程中没有重启或修改既有内容情报服务：

1. 将本项目的 [SOUL.md](../agent-workflow/moyujing-content-interviewer/SOUL.md) 部署到新 Profile。服务器文件权限为 `600`，部署后的文件哈希与仓库版本一致。
2. Hermes 初建 Profile 会放入默认 `SOUL.md`，且共享 Hermes Home 的默认工具配置是开启的；因此不能仅凭“新建 Profile”推断它已经受限。
3. `hermes tools disable` 的默认对象是当前 Hermes Home 的平台配置，直接执行可能影响既有 Agent。发现这一点后已立即恢复共享配置。
4. 改为在新 Profile 自己的 `config.yaml` 中设置：

   ```yaml
   platform_toolsets:
     cli: []
     feishu: []
   ```

复查结果：`myjcontentagent` 的 `cli` 与 `feishu` 两个通道均为零工具；共享 Home 的工具仍为原状态，`hermes-content-matrix.service` 与 `hermes-gateway.service` 均保持运行。

这一步的操作口径应固定为：先指定新 Profile 的 `HERMES_HOME`，再检查或修改其配置；不得在共享 Home 下直接改工具配置。新 Profile 在未配置模型与独立飞书机器人前，不启动 Gateway。

### 3.4 复用创建动作的 Skill

“创建独立 Hermes Agent + 飞书机器人”会在后续岗位中重复，因此已创建本机 Codex Skill：`create-hermes-feishu-agent`。它包含：岗位与输入输出合同检查、Profile 隔离、Profile 级工具配置、最小 Demo、飞书白名单接入和审计记录口径；其中部署脚本默认不配置凭证、不启动 Gateway，也不会修改共享 Home。

### 3.5 待完成配置

## 4. 后续 Skill 提炼卡

未来候选 Skill 名称：`myj-content-drafting`（暂定）。

它可能沉淀：主题卡字段、观点访谈与选项、对话确认识别、结构推荐、草稿修订循环、第一人称边界检查和 handoff 格式。

它不会沉淀：飞书应用凭证、服务器地址、模型 Key、个人未确认观点、客户信息、原始私信或发布权限。

提炼门槛：至少 3 次内容演练、每次都有输入/输出/人工修改记录；至少 1 次失败或边界案例；创作者确认方法可复用；通过后再创建正式 Skill 与测试样本。
