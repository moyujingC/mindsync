# 企业 AI 服务初访助理试点设计

> 状态：draft
> 日期：2026-07-19
> 账号：墨予镜
> 实现方式：Codex
> 知识库：飞书
> 关联记录：[企业 AI 服务初访助理自用试点记录](2026-07-19-企业AI服务初访助理自用试点记录.md)
> 范围：定义公众号初访和企业微信诊断准备的最小流程，不代表已上线或已验证的服务能力。

## 1. 试点目标

让从公众号进入的用户快速区分两类诉求，并在不收集企业敏感资料的前提下，主动添加企业微信：

1. 找服务：希望为自身团队推进 AI 落地、流程梳理、知识库或试点交付。
2. 谈合作：已有 AI 服务、培训或交付项目，希望讨论协作与补位。

企业微信接住用户后，先发送对应的说明资料，再收集诊断前置信息。只有在人工审核资料后，才安排需求诊断。

## 2. 渠道分工与数据边界

```text
公众号初访助理
  -> 确认意图和基本服务范围
  -> 邀请用户自主添加企业微信
企业微信跟进助理 / 人工服务台
  -> 发送资料包
  -> 收集诊断准备信息
  -> 人工审核
  -> 约需求诊断或说明暂不匹配
```

| 环节 | 可以收集 | 不收集 / 不处理 |
| --- | --- | --- |
| 公众号 | 找服务或谈合作的意图；用户自愿留下的概括性问题 | 企业名称、联系人、完整流程、内部文件、报价承诺 |
| 企微资料包 | 用户选择的服务方向；预约所需的最少信息 | 未经确认的敏感内部材料；全量聊天迁移 |
| 诊断前信息表 | 业务背景、一个目标流程、当前卡点、已有基础、预期结果、参与人和时间约束 | 账户密码、个人隐私、无关的客户数据、完整生产数据 |
| 内容洞察 | 用户明确同意后产生的脱敏、聚合需求主题 | 原始聊天、企业身份、联系人、内部资料、可回溯片段 |

公众号和企微不共享完整对话记忆。用户明确同意后，最多交接“意图类型”和“已确认的下一步”。

## 3. 公众号初访助理

### 3.1 开场

```text
你好，我是墨予镜的 AI 初访助理。

这里可以先帮你了解两类事情：
1. 为团队寻找 AI 落地、流程梳理、知识库或试点交付支持；
2. 和正在做 AI 服务、培训或交付的团队讨论合作。

我先帮你找到合适的下一步；具体需求和资料会在企业微信里由本人继续确认。
```

### 3.2 意图问题

```text
这次你更想：
A. 为自己的团队找 AI 服务支持
B. 讨论 AI 服务或项目合作
C. 先了解能做什么
```

处理规则：

- `A`：说明可从一个真实流程开始判断，进入“找服务”导流。
- `B`：说明可讨论需求诊断、方案整理、流程落地和交付支持，进入“谈合作”导流。
- `C`：发送简短范围说明后，允许用户任选 `A` 或 `B`；不在公众号展开需求访谈。

### 3.3 导流话术

找服务：

```text
可以。我们通常先围绕一条真实流程，判断问题、已有基础和适合的小范围试点。

如果你愿意继续，添加企业微信后会先收到一份需求诊断说明和准备表。你填写到方便的程度即可；我会先阅读，再确认是否适合约一次需求诊断。
```

谈合作：

```text
可以。添加企业微信后会先收到一份协作方向说明和简短的合作信息表，方便双方先了解现有项目、需要补位的环节和合作方式。
```

### 3.4 公众号终止条件

公众号助理不进行以下动作：

- 不询问或接收详细企业资料。
- 不给出具体项目方案、报价、交付周期或效果承诺。
- 不承诺一定安排诊断或一定合作。
- 不把用户未授权的对话用于内容生产或需求分析。

## 4. 企业微信资料包与表单

### 4.1 找服务资料包

首条消息应包含：

```text
你好，我是馨冉。收到你的咨询。

我会先阅读你提供的背景和一个具体流程，再判断是否适合进入需求诊断。请先查看《需求诊断说明》，并填写《诊断前信息表》；不需要一开始提供完整内部资料，脱敏样例、流程图或资料目录即可。
```

资料包组成：

1. 《我可以协助的场景与边界》：AI 工作流梳理、知识库 / SOP 整理、试点定义、方案和交付支持；不承诺泛化的转型结果。
2. 《需求诊断说明》：目的、流程、需准备材料、人工审核和约谈规则。
3. 《诊断前信息表》：见 4.2。

### 4.2 找服务诊断前信息表

```text
1. 你所在团队/业务主要做什么？（可概括，不必填写公司名称）
2. 这次最想先改善哪一条具体流程？请从开始到结束简要描述。
3. 这条流程目前最卡在哪里？请举一个近期发生的例子。
4. 现在已经使用哪些工具、资料库、SOP 或人工协作方式？
5. 你希望先看到什么变化？哪些结果不在本次期待内？
6. 参与这件事的人有哪些角色？谁参与判断或决策？
7. 是否有时间节点、预算范围或数据合规要求需要提前说明？
8. 可选：请附脱敏流程图、SOP、资料目录或一个样例。请不要发送账号密码、完整客户数据或无关敏感信息。
9. 你是否同意我仅为本次需求判断阅读以上信息？
   - 同意
   - 暂不同意（可只预约初步沟通）
```

### 4.3 谈合作资料包与信息表

首条消息：

```text
你好，我是馨冉。收到你的合作沟通意向。

为了避免泛泛聊工具，先请你简单说明正在做的服务或项目、目前需要补位的环节和期待的协作方式。我会先阅读，再回复是否适合进一步沟通。
```

合作信息表：

```text
1. 你或团队当前主要提供什么服务？
2. 目前正在推进的项目或客户类型是什么？可概括说明。
3. 希望我补位哪一段：需求诊断、方案整理、流程梳理、知识库 / SOP、试点交付，还是其他？
4. 当前项目处于什么阶段？是否有明确时间节点？
5. 你期待怎样的协作方式和职责划分？
6. 可选：附一页脱敏项目背景或已有方案目录。
7. 你是否同意我仅为本次合作匹配阅读以上信息？
   - 同意
   - 暂不同意（可先做概括沟通）
```

## 5. 企微交接卡

交接卡只记录让人工继续工作所需的最少信息，保留在受控的线索系统中，不写入通用飞书知识库或内容系统。

```text
线索编号：
来源渠道：公众号 / 其他
进入日期：
意图类型：找服务 / 谈合作 / 待确认
用户已确认的概括诉求：
是否已主动添加企微：是 / 否
是否已发送资料包：是 / 否
是否已同意本次资料阅读：是 / 否 / 未确认
已收到的材料类型：无 / 表单 / 脱敏流程图 / 资料目录 / 其他
人工下一步：等待填写 / 阅读材料 / 约诊断 / 说明暂不匹配
内容洞察授权：未询问 / 拒绝 / 同意匿名聚合
```

## 6. 人工审核与异常处理

- 表单未完成：允许先做概括沟通，不催要完整内部资料。
- 信息不足：只追问与一个具体流程有关的最少问题。
- 范围不匹配：说明当前无法承接的原因和可行的下一步，不承诺转介。
- 出现敏感数据：停止在聊天中继续接收，提醒对方删除或改用脱敏材料。
- 用户拒绝资料阅读授权：不得保存或分析其提交的材料，只能进行概括性沟通。

## 7. 首轮测试与验收

首轮只使用自己和模拟企业咨询者，验证：

1. 用户能否在公众号区分“找服务”和“谈合作”。
2. 用户能否理解为什么需先加企微、再填写准备表。
3. 资料包和表单是否只收集了诊断所需的最少信息。
4. 交接卡是否足以让人工继续，而不依赖完整聊天迁移。
5. 是否存在越权承诺、过度收集或信息表达不清的地方。

通过条件：两类模拟用户均能在不提供敏感资料的情况下完成导流，且人工仅凭交接卡和用户主动提交的表单可判断下一步。

## 8. 暂不纳入本试点

- 企业 AI 内训的正式课程、价格、时间表与效果承诺。
- 自动报价、自动方案生成和自动预约确认。
- 真实企业数据接入知识库。
- 用原始聊天或企业资料自动生成公开内容。
