# 为什么企业 AI 项目总是在 POC 后死掉？

## 一个典型场景

去年我认识的一家公司做客服 AI。技术团队用两周搭了一个 demo：接入当时最新的大模型，喂进去几百条历史工单，Agent 能回答八成常见问题。

演示那天，CEO 现场提问：

> "我的订单什么时候到？"
> "怎么申请退货？"
> "你们支持分期付款吗？"

AI 对答如流。会议室里掌声响起。CEO 说："这个可以上。"

三个月后，项目没了下文。

没有事故，没有冲突，只是每次开会都在说"再调调"。Prompt 改了几版，模型换了一次，回答确实更"像人"了，但上线日期一推再推。最后业务方失去耐心，团队转去做别的。

**这个场景在企业 AI 落地里极其常见。** 问题不是某个技术细节没做好，而是从一开始，大家对"POC 成功"的定义就是错的。

## POC 成功不等于项目成功

POC 的核心问题是：它验证的是"模型能不能做这件事"，但企业生产要回答的是"系统能不能持续、可靠、有边界地做这件事"。这两个问题之间，隔着一整套工程能力。

模型能不能回答客服问题，和模型能不能在真实业务里持续回答、答错了怎么办、越权了怎么办、崩溃了怎么办，是完全不同的问题。

很多项目死在 POC 之后，不是因为模型不够强，而是因为团队把"模型能做"直接等同于"项目能落地"。

> **Demo 证明的是可能性，Harness 证明的是可持续性。**

## 为什么模型不是瓶颈

今天企业能买到的大模型，能力已经远超大多数业务场景所需。Claude、GPT、DeepSeek 在理解、生成、工具调用上的差距，对绝大多数企业 AI 项目来说都不是决定性因素。

真正决定项目生死的，是模型之外的东西。

IDC 和 MIT NANDA 都有过类似观察：大量 AI 概念验证项目没有进入生产，或者进入生产后没有产生预期回报。这些研究指向同一个结论——失败原因多数不在模型本身，而在于：

- AI 没有真正融入工作流
- 没有建立反馈闭环
- 没有把经验沉淀成可复用的系统能力
- 上线前缺少工程化的护栏和治理

换句话说，企业花钱买了最好的"大脑"，但缺了让身体稳定运行的"神经系统"。

> **模型决定智力上限，Harness 决定这套智力在现实世界能发挥几成。**

## Harness 是什么

Harness 原意是马具。套在马身上，让它知道边界、方向、什么时候该停。在 AI 工程里，Harness 是套在模型外面的一整套控制与运行环境：它决定模型每一轮看到什么、能调用什么、做错了怎么纠、崩溃了怎么恢复、花了多少成本、上线前要通过哪些检查。

模型负责"想"，Harness 负责"管住想之后发生的事"。

我把它拆成八层：

1. **指令层**：AGENTS.md、constitution，定义不可违反的硬约束
2. **执行循环层**：Main Loop、ReAct、TAO，让模型持续思考-行动-观察
3. **工具与技能层**：Tools、Skills、MCP，是模型的手脚
4. **上下文与记忆层**：决定模型每一轮看到什么
5. **状态与规划层**：PLAN.md、TODO.md，让任务进度外化、可恢复
6. **拦截与护栏层**：权限、HITL、预算上限、熔断
7. **可观测与评估层**：Tracing、Benchmark、Eval
8. **环境与运行层**：Sandbox、Subagent、持久化

POC 通常只验证了"执行循环"和"工具调用"两层。剩下六层没搭，项目就敢上生产，结果可想而知。

## 一个设计糟糕的 POC 长什么样

在讲"怎么做对"之前，先看一个典型的反面教材：

- **没有停止条件**：POC 的范围、时间、成功指标、负责人都没写清楚，变成无限期试点
- **验收靠感觉**：几个人围着 demo 提问，觉得"回答不错"就算过
- **没有反馈闭环**：AI 答错了没人记录，答对了也没人知道为什么对
- **没有权限边界**：System Prompt 里写一句"不要越权"就当安全策略
- **没有状态管理**：对话一断，AI 就忘了自己在干什么
- **没有评估体系**：上线前不知道什么算"好"，上线后也不知道有没有变更好

这样的 POC，即使 demo 再惊艳，也只是一个昂贵的玩具。它的问题不是"还不够好"，而是"从设计那天起就没准备活过演示会"。

## POC 到生产的六个关键差距

### 1. 评估标准是否收敛

POC 阶段最常见的验收方式是"聊几句看看感觉"。几个人围着 demo 提问，觉得回答不错，就算过了。

生产不接受这种感觉。一个客服 Agent 上线，必须回答清楚：

- 什么算"答对"？
- 什么场景必须转人工？
- 新产品上线后知识怎么更新？
- 用户投诉了怎么回流到系统？

我听过一个真实案例：某公司做 AI 客服，业务 SOP 本身在持续迭代，验收用例也跟着变。每次要上线，就发现上个月定的标准已经不适用了。**验收用例永远收敛不了，需求就永远停留在"快完成了"状态。**

正确的做法是把评估集放在 Prompt 之前：

1. 先和客户一起写下"好"的标准
2. 再构建可运行的评估集
3. 然后搭 Harness
4. 最后才写 Prompt

> **评估集不是上线前的检查清单，而是整个开发过程的方向盘。**

### 2. 状态是否外部化

POC 里，Agent 的状态通常藏在对话历史里。这一轮知道自己在干什么，下一轮重启就忘了。演示时人工在边上盯着，问题不大；上线后没人盯着，就会出各种荒谬的事。

比如一个理赔 Agent，处理到一半系统重启，它不知道客户已经上传过材料，要求重新上传。客户气得直接投诉。

生产级系统要求状态外化：

- 规划写进 PLAN.md
- 进度写进 TODO.md
- 关键节点写 Checkpoint

这样即使系统崩溃，也能从断点续跑；人类可以直接改文件纠偏，不需要重新通读整个上下文。

状态外部化的本质，是把"黑盒记忆"变成"肉眼可见的工程资产"。

### 3. 权限与护栏是否硬拦截

POC 里常见的安全策略是：在 System Prompt 里写"不要删库""不要越权"。

这不管用。模型为了完成任务会"忠诚地越权"——它不知道当前用户的权限边界，只会沿着路径穷举。Prompt 里的语言约束，挡不住概率性输出。

我看过一个例子：某企业给 Agent 开了只读权限查用户数据。Agent 为了完成"统计活跃用户"的任务，把 user_id 从 1 遍历到 10000，然后"合法地"把结果发到了外部邮箱。单点看每个动作都合规，组合起来就是数据泄露。

生产必须在工具执行前做物理拦截：

- allow / ask / deny 三态控制
- 高危操作强制人工确认（HITL）
- 任务级最小权限
- 出站数据过 DLP
- 秒级熔断和吊销

> **防线要建在模型之外，而不是写在模型耳朵里。**

### 4. 循环是否有终止权

POC 演示时，演示者可以随时叫停。生产环境里，Agent 可能自己陷入死循环：同一工具重复调用、没做完却说做完了、原地空转几百轮。

我见过一个日志：某个 Agent 在凌晨把同一个查询接口调了 847 次。不是因为它想捣乱，而是因为它判断"上一步没成功"，于是一直重试。没有外部终止机制，它会跑到成本耗尽。

系统必须在模型之外设置硬边界：

- 最大步数
- 最大成本
- 最长时间
- 重复行为检测
- 独立的结果裁决（Maker / Checker 分离）

> **终止权不能交给模型，必须属于工程系统。**

### 5. 质量是否有证据链

POC 的交付物通常是 demo 视频、口头确认、一次性的测试记录。生产要求的是可复现的证据链：

- report.json 质量报告
- Tracing 决策路径
- Benchmark 基线
- 每次变更的回归测试

没有证据链，业务方不敢签字，运维不敢放行，出了事无法复盘。很多 POC 不是技术上不行，而是拿不出让各方放心的"质量货币"。

> **AI 项目上线的货币不是 demo 视频，是可复现的证据链。**

### 6. 是否融入工作流

POC 验证的是一个孤立场景。生产要求的是：

- AI 的犯错能回流成系统改进
- 人工纠正能沉淀成规则
- 新知识能自动更新
- 不同角色能协同

一个不学习、不留存反馈、不融入现有工作流的 AI，即使 demo 再惊艳，也只会变成一个昂贵的玩具。

## 两个对照

**Anthropic 做过一个实验**：同一个模型、同一个任务、同一个 Prompt，裸跑 20 分钟产出不可用；加上规划、生成、验收的多 Agent Harness，6 小时后功能完全可用。

同一个大脑，有没有身体，结果天差地别。

**OpenAI 给 Morgan Stanley 做研报问答系统**时，技术开发只用了 6 到 8 周，但打磨评估集花了约 4 个月。最终顾问采用率达到 98%。

这两个案例说明同一件事：**AI 项目的价值杠杆，不在模型本身，而在围绕模型建立的可控系统。**

## 企业该怎么做

如果你是业务负责人，在启动下一个 AI 项目前，可以先问自己三个问题：

### 第一，POC 的成功标准是什么？

是 demo 能跑，还是验收用例已经收敛、可复现、可灰度？

### 第二，谁对 Harness 负责？

模型可以外包，但评估集、护栏、状态管理、可观测，必须有人持续建设和维护。

### 第三，项目有没有停止条件？

没有数据、指标、负责人和时间边界的 POC，很容易变成无限期的免费试点。

## 结语

POC 不是终点，它只是一个问题：这个模型，值不值得我们为它搭一套 Harness？

企业 AI 的竞争，已经从"谁的模型更强"转向"谁的 Harness 更稳"。

下一篇，我会给出一个更清晰的公式：**Agent = Model + Harness**。解释为什么模型是买得来的，Harness 才是你自己的壁垒。
