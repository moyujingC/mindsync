# 状态外部化——把记忆从黑盒变成肉眼可见的 Markdown

## 观点
与其在内存里维护复杂状态机或上向量库，不如强制 Agent 把规划写进 PLAN.md、进度写进 TODO.md。换来四样东西：绝对透明可观测、零成本人机协同（人直接改文件纠偏）、断电/崩溃后的断点续传、节省 Context 内存。黑盒状态是人类无法介入的根源，文件化状态让 Agent 重启后'瞬间清醒'。

## 来源
Tony Bai，《从 0 开始构建 Agent Harness/13｜记忆沉淀：状态外部化，基于文件系统的持久化记忆与待办管理-…-极客时间.md》

## 边界
适用于长程任务与 Plan Mode；简单查询类任务强制写 PLAN.md 是浪费 Token 的'官僚主义'。

## 反例 / 误用
认为状态外部化=LOW/简陋；课程称这是 OpenClaw 的'神来之笔'。

## 对第一篇的用处
文章'解药'部分的核心一招——POC 项目的状态锁在黑盒里，是它无法被调试、无法被接管、无法跨会话存活的直接原因。
