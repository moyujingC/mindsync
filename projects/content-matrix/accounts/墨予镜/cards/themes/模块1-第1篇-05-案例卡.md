# 主题卡片 5：案例卡

## 核心作用

用真实案例让抽象判断落地。

## 可用的案例

### 案例 1：AI 赋能客服业务失败（Codex 行动营）
- 业务有标准 SOP，但 SOP 随新产品持续迭代
- 验收用例持续变化、无法收敛
- 结果：需求始终无法上线
- 来源：[2026-08-27-codex-验收用例不收敛](../inputs/2026-08-27-codex-验收用例不收敛.md)
- 用处：说明 POC 死亡可以不是因为技术，而是因为验收标准锁不死

### 案例 2：神策广告投放投手 Copilot（FDE 业务落地实战）
- Agent 动真金白银预算
- 第一天就配预算上限、动作白名单、全量日志、回滚
- 投手对 Agent 建议的"拒绝理由"成为训练数据
- 来源：[2026-08-27-fde-上线边界写成清单](../inputs/2026-08-27-fde-上线边界写成清单.md) 相关
- 用处：说明"敢上线"不是因为模型强，而是因为 Harness 全

### 案例 3：Anthropic 对照实验（Agent 驾驭工程之美）
- 同一个模型、任务、提示词，裸跑 20 分钟产出不可用
- 加上多 Agent Harness（规划/生成/验收）6 小时功能完全可用
- 来源：[2026-08-27-harness-一次性到可重复](../inputs/2026-08-27-harness-一次性到可重复.md)
- 用处：最有力的量化对比，说明 Harness 的杠杆效应

### 案例 4：OpenAI × Morgan Stanley（FDE 业务落地实战）
- 技术开发 6-8 周，打磨评估花了约 4 个月
- 顾问采用率最终 98%
- 来源：[2026-08-27-fde-先定义好](../inputs/2026-08-27-fde-先定义好.md)
- 用处：说明评估本身就是开发，不是后置工序

## 对文章的作用

案例不需要全部用。选 2-3 个最有说服力的，穿插在"归因"和"差距"段落中。
