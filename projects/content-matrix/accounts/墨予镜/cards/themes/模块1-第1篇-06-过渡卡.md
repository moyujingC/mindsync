# 主题卡片 6：过渡卡

## 文章结尾要回答的问题

既然 POC 后死掉是因为 Harness 没搭起来，那企业应该怎么办？

## 给读者的三个行动点

1. **重新定义 POC 的成功标准**
   - 不是"demo 能跑"，而是"验收用例收敛、可复现、可灰度"
   - 来源：[2026-08-27-codex-验收标准可复现](../inputs/2026-08-27-codex-验收标准可复现.md)、[2026-08-27-fde-poc自带停止条件](../inputs/2026-08-27-fde-poc自带停止条件.md)

2. **把 Harness 当作交付物，不是附属品**
   - 评估集、状态管理、护栏、可观测，要在写 Prompt 之前就想清楚
   - 来源：[2026-08-27-fde-先定义好](../inputs/2026-08-27-fde-先定义好.md)、[2026-08-27-codex-模糊需求转可验收任务](../inputs/2026-08-27-codex-模糊需求转可验收任务.md)

3. **下一篇预告**
   - 下一篇会给出新公式：Agent = Model + Harness
   - 解释为什么模型是买得来的，Harness 才是你自己的壁垒

## 金句候选

- "POC 不是终点，它只是一个问题：这个模型，值得不值得我们为它搭一套 Harness？"
- "Demo 证明的是可能性，Harness 证明的是可持续性。"
- "企业 AI 的竞争，已经从'谁的模型更强'转向'谁的 Harness 更稳'。"
