# Editing Rounds

## 1. Reader And Purpose Calibration

Goal:

- identify the real reader
- detect whether the draft is drifting toward `同行文`

Use prompt:

```text
先不要改文案。

请先判断这篇文章更像是写给：
1. 同行
2. 泛读者
3. 准客户

然后指出：
- 哪些段落更像在对同行说话
- 哪些段落真正对准了读者的问题
- 如果目标是普通公众号读者，最该删掉或改写的 3 处是什么

不要重写全文，只做判断。
```

## 2. Structure Review

Goal:

- speed up entry
- cut repetition
- tighten the main line

Use prompt:

```text
不要润色。
只从公众号成品编辑的角度看这篇文章，帮我做结构审稿：

- 开头哪里进入太慢
- 哪几段重复了
- 哪几段应该提前
- 哪几段应该删掉
- 哪个位置最适合提前抛出核心观点

输出格式：
1. 建议保留的主线
2. 建议删除的段落
3. 建议调整顺序的段落
4. 一个更适合公众号的结构顺序
```

## 3. Expression De-noising（去 AI 味）

Goal:

- 删掉 AI 套话，而不是删掉判断
- 把空泛的套话换成具体的判断

这一步**必须先读 [ai-de-style.md](ai-de-style.md)**，按里面的 11 种模式 + 硬约束 + 噪声预算来改。不要凭感觉"找 AI 味的句子"，要用清单扫。

Use prompt:

```text
不要补内容，不要拔高，不要扩写。只做去 AI 味和表达降噪。

先读 references/ai-de-style.md，然后逐项扫这篇稿子，按里面的模式清单处理：

内容层：
- 口号式结论（底层逻辑/赋能/抓手/认知升级这类大词）
- 防御型表达（"不是 A 而是 B"式先否定再重构）
- 模板化并列（首先/其次/最后，等长等重）
- 段末拔高总结句（这背后/究其根本/由此可见）

语言层：
- AI 高频词（值得注意的是/综上所述/深入/系统/赋能）
- 无主语被动分析（"该处理体现了"）
- 模糊归因（专家认为/研究表明，无出处）
- "在当下这个时代"式起笔

风格层：
- 破折号/加粗滥用
- 情绪空转（令人震撼/不可想象）
- 节奏单一（句子长度接近）

每一项都给出：原文位置 → 命中的模式 → 改后版本。

改的原则：
- 不增加新观点、新案例
- 只减噪、压缩、换口气、删套话
- 把空泛套话换成具体判断，而不是把判断也删掉
- 遵守硬约束（AI 高频词每段≤2、段末拔高≤1处、模糊归因0处等）
- 遵守噪声预算：每千字留 2-3 处轻微特征，不要全篇改得一模一样
```

## 4. Style Calibration（表达准确）

Goal:

- 让稿子不只"不像 AI 写的"，还要"像你写的"
- 用黄有璨的"表达准确"做上限，不只是去 AI 味做底线

Use prompt:

```text
下面是我要的写作质感，请只按这个方向校准，不要擅自发挥、不要磨成四平八稳：

表达准确（来自黄有璨的风格，我喜欢他这一点）：
- 判断精准，不绕着说；宁可锋利，不磨平
- 分类清楚，让读者感到我脑子里有完整地图
- 抽象结论后面，配一个具体画面或比喻
- 每句话都在推进论点，不浪费篇幅做铺垫
- 结尾把判断权踢回读者，而不是给一个标准答案

基础风格：
- 直接、具体、少废话
- 少空泛判断词，不写给同行炫技
- 不追求面面俱到，更像拆问题，不像讲大道理
- 让读者尽快知道我到底想说什么

请基于上面两点，把这篇文章改成更像我会发出去的版本。
只改表达，不改核心结构和观点。
```

## 5. Title Crafting（标题润色）

Goal:

- 把标题打磨到「像墨予镜、能点进来、不发假」

这一步**必须先读 [title-crafting.md](title-crafting.md)**，按里面的标题 DNA + 模式库 + 质量门来起/改。不要凭感觉"起个标题"，每个标题要能追溯到正文的核心判断。

Use prompt:

```text
不要改正文。只做标题。

先读 references/title-crafting.md，然后：

1. 判断这篇正文的核心判断是什么，接近哪种模式（纠偏否定 / 问题诊断 / 反常识结论 / 场景代入 / 提问踢回）。
2. 围绕核心判断，生成 5-8 个标题变体。
3. 逐个过质量门：先给判断、去 AI 味、不装专家、不发假、平台字数、张力 ≥2 项。
4. 每个标题标注：追溯到哪个模式、为什么适合这篇正文、命中了哪 2 项张力。
5. 收敛出 Top 3，给真实判断，别随便选。

公众号和小红书用不同的字数约束（见 title-crafting.md 第 2 节）。
```

## 6. Pre-publish Check

Goal:

- do a final light check before publishing

Use prompt:

```text
把这篇文章当公众号待发稿，做最后一轮成品检查。

只回答：
- 标题是否合适
- 开头前 3 段是否能留住读者
- 哪个小标题最像报告，不像文章
- 哪 3 句最该再压短
- 哪一段读起来最像同行文章
- 哪一句最像防御型表达，应该改成正面判断
- 哪一句还有 AI 味（口号大词/段末拔高/模糊归因），该删
- 结尾是否自然

不要整篇重写，只给最小修改建议。
```
