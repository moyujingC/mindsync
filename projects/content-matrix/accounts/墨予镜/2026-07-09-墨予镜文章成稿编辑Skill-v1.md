# 墨予镜文章成稿编辑 Skill v1

## 1. 这份 Skill 是干什么的

这不是用来“帮 AI 出草稿”的。

它只解决一件事：

> 把已经写出来的草稿，稳定推进到“像我、能发、适合公众号”的成品。

适用场景：

- 文章主观点已经清楚
- 主要结构已经成型
- 核心例子已经有了
- 现在要优化的是表达风格、阅读节奏、信息密度和成品感

不适用场景：

- 选题还没想清楚
- 观点还在发散
- 内容证据还不够
- 还在“聊着出草稿”的阶段

一句话说，这份 Skill 处理的是：

> 草稿 -> 成品

而不是：

> 空白 -> 草稿

---

## 2. 这一步为什么值得单独做成 Skill

因为这已经不是临场发挥，而是一类高频、重复、边界清楚的任务。

它有固定输入：

- 草稿正文
- 目标读者
- 文章用途
- 当前账号语境
- 风格卡

它也有固定输出：

- 结构问题
- 建议删除
- 表达降噪
- 风格校准稿
- 待发检查

所以它很适合先收成一个轻量 Skill，而不是每次都重新对 AI 说一遍“帮我润色一下”。

---

## 3. 这份 Skill 的核心原则

### 原则 1：编辑，不是重写

这一步的目标不是让 AI 再写一篇。

而是：

- 找问题
- 删重复
- 压缩表达
- 调整节奏
- 校准风格

### 原则 2：先结构，后句子

如果结构没收住，直接润色只会把问题写得更漂亮。

先解决：

- 开头慢不慢
- 主线清不清楚
- 有没有重复段
- 哪些段落该删

再解决句子层的问题。

### 原则 3：先对读者，再对文风

先判断这篇是不是写给对的人，再谈“像不像我”。

如果读者定位已经偏了，风格再对也没用。

### 原则 4：表达优化以减法为主

成稿阶段最常见的问题不是“不够多”，而是“太多”。

优先做：

- 删
- 缩
- 并
- 提前核心句

而不是：

- 扩写
- 拔高
- 补更多例子
- 再解释一层

### 原则 5：AI 负责发现和候选，你负责拍板

AI 在这一步最适合做：

- 找重复
- 找空话
- 找同行腔
- 提供候选改写

你更适合做：

- 选哪种改法
- 哪一句更像你
- 哪些地方必须保留你的判断口气

## 4. 墨予镜风格卡 v1

下面这张卡，是给 AI 做成稿编辑时的固定风格约束。

### 4.1 想要的风格

- 直接
- 具体
- 少废话
- 少空泛判断词
- 不追求面面俱到
- 不写给同行炫技
- 更像拆问题，不像讲大道理
- 尽快进入问题，不长时间铺垫
- 保持判断感，但不要装腔
- 能让普通读者跟得上，不默认对方懂很多概念

### 4.2 不想要的风格

- 太干太专业
- 太像写给同行
- 太像方法论报告
- 太像“AI 在写一篇完整文章”
- 句子太长，段落太满
- 用很多抽象词堆气势
- 为了显得完整而重复解释
- 机械使用“不是 X，而是 Y”式对照句

### 4.3 读者优先级提醒

这类文章优先写给：

- 对 AI 有兴趣，但没有系统工程背景的人
- 能感知问题，但说不清结构的人
- 有真实工作困惑，希望获得判断和视角的人

不优先写给：

- 想看概念炫技的同行
- 想看术语体系的人
- 只为论证你很懂的人

### 4.4 参考风格锚点

目前先参考黄有璨类内容里的六个可迁移方向。

注意：这里不是要“模仿黄有璨”，而是把喜欢的表达方式拆成可执行规则。

#### 个人节点型

参考样本：

- `reference-samples/黄有璨-四十岁生日自述-原文与风格分析.md`

适用场景：

- 个人状态变化
- 阶段性复盘
- 重要节点上的自我确认
- 从个人经验抽出一个判断

可迁移规则：

- 开头先给状态或判断，不长时间铺垫。
- 抽象概念后面马上翻译成人话。
- 个人经历只作为观点证据，不做自我展示。
- 结尾可以上升，但不能突然拔高。
- 学它“把个人经验变成可理解的判断框架”，不要学它“人生节点式的高处抒情”。

#### 趋势判断型

参考样本：

- `reference-samples/黄有璨-全民龙虾热与OPC叙事-原文与风格分析.md`
- `reference-samples/黄有璨-微信AI正在悄然改变游戏规则-原文与风格分析.md`
- `reference-samples/黄有璨-关于微信AI会如何落地的一些猜想-原文与风格分析.md`

适用场景：

- AI 热点
- Agent / Workflow / MCP 这类概念热
- 企业 AI 转型热
- AI 咨询服务热
- 内容创作工具热

可迁移结构：

> 现象 -> 担心 -> 底层问题 -> 错位 -> 建设方向

可迁移规则：

- 先承认趋势重要，再指出讨论讲偏了。
- 把表层热闹和底层问题拆开。
- 反对“红利 / 工具 / 速成”叙事，转向“能力 / 业务 / 长期”叙事。
- 批评之后必须给建设方向。
- 如果话题是平台动作，要继续往下看入口、分发和生态权力关系怎么变。
- 不只讲威胁，也要讲新机会，不然文章容易只剩焦虑感。
- 如果话题是产品猜想，要先讲约束条件和不能碰的雷区，再讲可能的落地路径。
- 阶段推演要有“为什么先做这一步”的解释，不然就会像空想。

可复用句式：

```text
我不是反对 X。
相反，我认为 X 很重要。
只是我担心，现在很多关于 X 的讨论，正在把它讲偏。
真正值得关注的，可能不是 X 本身有多热，而是它背后正在暴露的 Y 问题。
```

#### 阶段判断型

参考样本：

- `reference-samples/黄有璨-一人公司创业三阶段-原文与风格分析.md`

适用场景：

- AI 协作阶段
- 内容创作阶段
- 个人能力成长
- 一人公司 / 个人业务
- 工具使用成熟度

可迁移结构：

> 核心框架 -> 阶段解释 -> 不能跳阶段 -> 行动建议

可迁移规则：

- 先给一个 15 字以内的核心框架。
- 每个阶段都回答：该做什么？不该做什么？搞混会怎样？
- 抽象概念必须翻译成直白动作。
- 至少放一个正例或反例。
- 结尾必须给读者一个自检问题或行动建议。

可复用句式：

```text
很多人卡住，不一定是能力不行。
更可能是：他不知道自己现在处在哪个阶段，也不知道这个阶段最该做什么、最不该做什么。
```

#### 概念拆解型

参考样本：

- `reference-samples/黄有璨-老板们是不是更应该把自己先AI化-原文与风格分析.md`

适用场景：

- 容易混淆的 AI 概念区分
- 个人与组织边界问题
- 工作方式 / 角色变化的本质判断
- “到底是不是一回事”这类问题
- 需要重新定义问题，再给判断的内容

可迁移结构：

> 误区提出 -> 重新定义 -> 本质判断 -> 前置条件 -> 为什么重要 -> 边界修正

可迁移规则：

- 不要急着给结论，先把问题重新定义清楚。
- 遇到容易混淆的概念，先讲边界，再讲观点。
- 不只要说“它是什么”，还要说“它不是什么”。
- 抽象判断后面，最好给一个信号、画面或比喻，帮助读者记住。
- 结尾可以不给唯一答案，但要把判断题清楚交还给读者。

检查重点：

- 有没有只剩观点，没有边界拆解。
- 大词很多，但读者读完还是分不清概念。
- 一直在下判断，却没有给出判断依据。
- 结构像态度表态，不像问题拆解。

可复用句式：

```text
很多人讨论的是同一个词，但其实说的不是同一件事。

我更想先把这个问题拆开：
它和大家平时理解的那个东西，到底是什么关系？哪些地方有关，哪些地方其实不是一回事？
```

#### 招募转化型

参考样本：

- `reference-samples/黄有璨-幸福流工作坊招募-原文与风格分析.md`

适用场景：

- 工作坊招募
- 陪跑营 / 训练营招募
- 顾问服务介绍
- 新产品首轮招募
- 需要先建立价值感，再承接报名或咨询的内容

可迁移结构：

> 理念 -> 状态 -> 痛点 -> 人群筛选 -> 转化承接

可迁移规则：

- 不要一开头就讲产品安排，先讲这件事为什么值得存在。
- 价值不只写成“你能学到什么”，还要写成“你会进入什么状态”。
- 抽象理念后面必须马上接具体痛点，否则容易飘。
- 明确写“什么样的人适合来”，比泛泛欢迎更有转化力。
- 报名方式、模块、价格这些信息，适合放在读者完成自我识别之后。

检查重点：

- 有没有先讲理念，后讲产品。
- 有没有把抽象价值翻译成读者的真实困境。
- 有没有明确筛选人群，而不是谁都在招。
- 有没有把转化承接放得太早，导致读者还没进入状态就被推销。

可复用句式：

```text
我想做的，不只是一个产品。
更准确地说，我想提供的是一种状态、一种场域，或者一种更适合你的做事方式。

如果下面这些描述里，有几条明显说中了你，那这件事大概率就是为你准备的。
```

#### 研究拆解型

参考样本：

- `reference-samples/黄有璨-从超级个体到超级团队-原文与风格分析.md`

适用场景：

- 报告解读
- 播客 / 演讲提炼
- 长文章精读
- 外部研究资料的公众号转写
- 需要把高密度信息改写成可读内容的场景

可迁移结构：

> 来源交代 -> 提炼框架 -> 分层拆解 -> 关键判断 -> 开放问题

可迁移规则：

- 开头先说清：这份材料为什么值得看，你替读者做了什么加工。
- 不要平铺摘要，要先做一轮筛选，告诉读者“哪些最值得带走”。
- 每个要点里都尽量同时放“信息”和“判断”。
- 信息密度越高，越要不断翻译成人话，不然很容易变成资料堆积。
- 结尾可以留讨论口，让读者从“看完”进入“参与”。

检查重点：

- 是不是只剩下摘抄，没有第一轮筛选。
- 编号很多，但读者读完带不走判断。
- 概念很多，但缺少人话翻译。
- 结构像提纲，不像文章。

可复用句式：

```text
我仔细看了这份报告。
如果你没时间通读全文，最值得你先抓住的，可能是下面这几个点。

它们不一定是这份材料里最完整的部分，但我认为是最值得带走、也最值得继续往下想的部分。
```

## 5. 固定编辑工作流

这一步固定分 5 轮，不要一轮里什么都做。

### 第 1 轮：读者与用途校准

目标：

- 先判断这篇是否写给对的人
- 先看内容有没有偏成同行文

这轮只回答：

- 这篇更像写给谁
- 哪些地方像写给同行
- 哪些地方真正对准了准读者的问题

不要在这轮直接重写全文。

### 第 2 轮：结构审稿

目标：

- 调整进入速度
- 去掉重复
- 收主线

这轮重点看：

- 开头是否太慢
- 核心观点是否出现太晚
- 哪些段落重复
- 哪些段落该删
- 顺序要不要调整

### 第 3 轮：表达降噪

目标：

- 去掉解释腔
- 去掉同行腔
- 去掉报告腔

这轮重点做：

- 删空话
- 压缩长句
- 改掉抽象表达
- 减少模板化对照句

### 第 4 轮：风格校准

目标：

- 把文风调成更像“我会发出去的版本”

这轮重点看：

- 判断句是否足够直接
- 语气是否过满
- 节奏是否像人在说话
- 是否还残留“AI 完整文章感”

### 第 5 轮：待发检查

目标：

- 做公众号成品前的最后一轮小检查

这轮只查：

- 标题是否合适
- 开头 3 段是否能留住人
- 小标题是否太学术
- 哪几句还该再压短
- 结尾是否自然

## 6. 每一轮的固定提示词

下面这 5 组提示词，可以直接复制用。

### 6.1 第 1 轮：读者与用途校准

```text
先不要改文案。

请先判断这篇文章更像是写给：
1. 同行
2. 泛读者
3. 准客户

然后指出：
- 哪些段落更像在对同行说话
- 哪些段落真正对准了读者的问题
- 如果目标是普通公众号读者，最该删掉或改写的 3 处是什么

不要重写全文，只做判断。
```

### 6.2 第 2 轮：结构审稿

```text
不要润色。
只从公众号成品编辑的角度看这篇文章，帮我做结构审稿：

- 开头哪里进入太慢
- 哪几段重复了
- 哪几段应该提前
- 哪几段应该删掉
- 哪个位置最适合提前抛出核心观点

输出格式：
1. 建议保留的主线
2. 建议删除的段落
3. 建议调整顺序的段落
4. 一个更适合公众号的结构顺序
```

### 6.3 第 3 轮：表达降噪

```text
不要补内容，不要拔高，不要扩写。
只做表达降噪。

请帮我找出这篇里：
- 最像 AI 写法的句子
- 最像给同行看的句子
- 最空、最抽象、最不接地的句子
- 可以删掉但不影响主线的句子

然后把它们改成：
- 更像人在说话
- 更短
- 更具体
- 更适合公众号读者往下读

原则：
- 不增加新观点
- 不增加新案例
- 只减噪、压缩、改口气
```

### 6.4 第 4 轮：风格校准

```text
下面是我的写作风格卡，请只按这个风格改写，不要擅自发挥：

- 直接
- 具体
- 少废话
- 少空泛判断词
- 不写给同行炫技
- 不追求面面俱到
- 更像拆问题，不像讲大道理
- 让读者尽快知道我到底想说什么

请基于这张风格卡，把这篇文章改成更像我会发出去的版本。
只改表达，不改核心结构和观点。
```

### 6.5 第 5 轮：待发检查

```text
把这篇文章当公众号待发稿，做最后一轮成品检查。

只回答：
- 标题是否合适
- 开头前 3 段是否能留住读者
- 哪个小标题最像报告，不像文章
- 哪 3 句最该再压短
- 哪一段读起来最像同行文章
- 结尾是否自然

不要整篇重写，只给最小修改建议。
```

## 7. 这一步最容易犯的错

### 错误 1：直接说“你帮我润色一下”

问题：

- 目标太泛
- AI 会默认扩写
- 容易变得更满、更标准、更不像你

正确做法：

- 明确这一轮到底是结构、降噪还是风格校准

### 错误 2：还没定读者，就开始改表达

问题：

- 可能越改越像同行文章

正确做法：

- 先做“读者与用途校准”

### 错误 3：一轮里同时做结构、风格、标题、结尾

问题：

- 容易把局部问题改乱

正确做法：

- 一轮只改一类问题

### 错误 4：让 AI 整篇重写

问题：

- 很容易丢掉原文判断感
- 会抹平你的语言习惯

正确做法：

- 让 AI 找问题、给候选
- 你来拍板

### 错误 5：把“成稿编辑”做成继续出内容

问题：

- 本来该收，结果又扩

正确做法：

- 成稿阶段默认做减法

## 8. 最小执行版

如果时间紧，只跑 3 轮也可以：

1. 结构审稿
2. 表达降噪
3. 待发检查

如果文章更重要，再跑完整 5 轮。

## 9. 后续怎么升级成正式 Skill

这版先作为轻量执行手册使用。

建议先连续用在 5 到 10 篇文章上，再看下面几件事是否稳定：

- 哪些提示词一直有效
- 哪些风格要求一直不变
- 哪些问题反复出现
- 哪些地方必须你自己拍板

如果稳定了，再升级成正式 `SKILL.md`，放进：

- 本地个人 skills
- 或 `内容矩阵` 项目下的专用编辑 skill

升级后的正式 Skill 可以再拆成：

- 结构编辑
- 风格编辑
- 待发检查

但现在不需要一开始就做重型系统。

先收稳这份 v1，最重要。

## 10. 使用参考样本的方式

每次编辑前，不要直接说“参考黄有璨风格”。

更好的方式是先判断这篇草稿属于哪类：

- 个人节点型
- 趋势判断型
- 阶段判断型
- 其他类型

然后只调用对应样本里的结构和表达规则。

使用提示词：

```text
请先判断这篇草稿更接近哪种文章类型：
1. 个人节点型
2. 趋势判断型
3. 阶段判断型
4. 其他

如果属于前三类，请只参考对应样本的结构规则，不要模仿原作者腔调。

输出：
- 类型判断
- 该类型最适合使用的结构

```

最终目标不是“写得像谁”，而是：

> 让文章更清楚、更像人、更有判断、更适合 `墨予镜`。
