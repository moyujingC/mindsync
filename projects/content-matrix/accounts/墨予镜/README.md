## 草稿生成阶段写作规则

生成草稿时，默认先正面说判断，不要用防御型表达绕路。

重点规避这类句式：

> 不是 A，也不是 B，而是 C。
> 不在于 A，也不在于 B，真正重要的是 C。

这类句式容易先虚构两个读者未必关心的误解，再进入正题，读起来像在替观点辩护。

更好的写法是直接给出判断：

> 要把它们分清楚，重点看两件事：它们封装了什么复杂度，以及决策权放在哪里。

只有在读者确实存在明确误解、且这个误解会影响理解时，才使用先否定再重构的表达。

## 草稿与成稿：两个文件，分开迭代

一篇内容分两个阶段、存成两个文件：

- **草稿（`-草稿.md`）**：定内容。看重内容信息打磨——表达准确、逻辑顺畅，先把内容想清楚。这一阶段只解决「想清楚没有」，不做润色。
- **成稿（`-成稿.md`）**：定表达。润色通过后另存为成稿，标题以成稿为准。后续微调都在成稿这一篇里迭代，不再回头改草稿。

规则：

- 草稿进入成稿后，草稿原文冻结不动；标题、措辞等表达层决策只落在成稿。
- 成稿顶部用「上游草稿」链接指回草稿原文，方便回溯「内容最初是怎么想的」。
