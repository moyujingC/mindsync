# 博主更新追踪与对标账号采集系统验收基线

## 1. 验收对象

验收对象是第一版 MVP：

`飞书博主账号表 -> 读取启用账号 -> 检查平台更新 -> 新内容写入飞书 -> 状态回写 -> 日志留存`

评论区采集、洞察生成和三平台完整覆盖不属于第一版必过范围。

## 2. 必过用例

### 用例 1：读取启用博主

前置条件：

- 飞书博主账号表中至少有 2 条记录
- 其中 1 条为 `启用`
- 其中 1 条为 `暂停`

期望：

1. 系统只读取启用记录
2. 输出中包含平台、账号 ID、主页链接、检查频率
3. 暂停记录不进入检查队列

### 用例 2：发现新内容并写入

前置条件：

- 平台适配器返回 1 条新内容
- 飞书内容更新表中没有同一内容唯一键

期望：

1. 新内容写入内容更新表
2. 内容唯一键格式稳定
3. 标题、链接、发布时间、采集时间写入成功
4. 博主账号表最近检查时间更新
5. 最近状态为 `正常`

### 用例 3：重复运行不重复写入

前置条件：

- 用例 2 已运行成功
- 再次运行同一检查任务

期望：

1. 内容更新表不新增重复记录
2. 运行日志显示 `skipped_duplicate`
3. 博主最近检查时间仍正常更新

### 用例 4：账号检查失败

前置条件：

- 平台适配器模拟失败

期望：

1. 当前账号状态回写为 `失败`
2. 失败原因可读
3. 其他账号继续执行
4. 任务整体日志包含失败账号和错误类型

### 用例 5：dry-run 不写飞书

前置条件：

- 使用 `--dry-run`
- 平台适配器返回新内容

期望：

1. 命令行输出将要写入的内容
2. 飞书内容更新表不新增记录
3. 博主账号表不被回写

## 3. 边界情况

### 边界 1：缺少平台账号 ID

期望：

- 该账号不进入采集
- 状态回写为 `需人工处理`
- 失败原因说明缺少字段

### 边界 2：平台返回内容缺少发布时间

期望：

- 内容仍可入库
- 发布时间为空或标记为 `待补充`
- 采集时间必须存在

### 边界 3：飞书字段映射缺失

期望：

- 启动阶段直接失败
- 不进入平台采集
- 错误指出缺失字段

### 边界 4：平台限流

期望：

- 记录限流错误
- 不无限重试
- 当前账号标记失败或稍后重试

## 4. 数据质量标准

必须满足：

- 每条内容都有稳定内容唯一键
- 每条内容都有平台、博主、内容链接、采集时间
- 原始内容字段不被分析任务覆盖
- 分析标签和人工判断字段可为空，但不能伪造

## 5. 合规检查

进入评论区采集前，必须单独确认：

1. 当前数据来源是否合法可访问
2. 是否需要登录、授权或人工导出
3. 是否保存了不必要的个人信息
4. 是否有频率限制
5. 是否能关闭评论采集

评论区采集不得作为 MVP 通过条件。

## 6. 不通过条件

出现以下任一情况，MVP 不通过：

1. 重复运行会重复写入同一内容
2. 单个账号失败导致整个任务中断
3. 没有可读运行日志
4. 飞书写入失败但系统显示成功
5. 无法区分新增内容、重复内容和失败内容
6. 未声明平台能力缺失，却在分析中当作完整数据使用

## 7. 验证方式

第一阶段用本地 fixture 验证：

- 模拟启用/暂停博主
- 模拟新增/重复内容
- 模拟平台失败
- 模拟飞书字段缺失

接入真实平台后，再做小样本验证：

- 每个平台先选 1 个公开账号
- 每次检查限制在最近 3-5 条内容
- 对照人工打开页面确认标题、链接、发布时间是否一致
