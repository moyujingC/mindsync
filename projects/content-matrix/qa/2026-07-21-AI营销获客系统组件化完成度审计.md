## 本次真实联调

在不写入飞书或本地台账的条件下执行：

```bash
TIKHUB_API_KEY='[redacted]' npm run research:run -- \
  --template enterprise_ai_service \
  --mode search \
  --platform xiaohongshu \
  --keyword '企业 AI 工作流' \
  --limit 1 \
  --dry-run
```

结果：TikHub 返回 `402`，错误为“check account balance or endpoint entitlement”。这说明当前 Key 未具备该接口的可用余额或套餐权限。由于使用 `--dry-run`，没有写入飞书、研究台账或本地去重库。

## 恢复条件与下一步

1. 在 TikHub 后台确认余额和小红书搜索接口套餐权限。
2. 运行 `npm run preflight:readiness -- --feishu config/feishu.local.json`；账户恢复后用 `--probe --platform xiaohongshu --share-url <公开链接>` 检查详情接口权限。
3. 先以 `--dry-run --limit 1` 重试，确认返回真实响应和调用成本；各平台首个响应用 `capture:tikhub-contract` 保存经审阅的脱敏合同样本。
4. 成功后去掉 `--dry-run`，写入飞书并检查内容、博主、评论和“研究请求”四类记录。
5. 人工确认一个候选，生成草稿、完成真实发布并填写反馈记录。
6. 累积 3-5 轮真实闭环后，再评估每周 Agent Loop。
