## 2026-07-22 只读核验

在当前终端执行 `preflight:readiness`：飞书配置校验通过，但环境中未提供 `TIKHUB_API_KEY`，因此本次不发起新的真实采集。该结果只说明当前终端缺少密钥，不覆盖此前已完成的四平台真实联调记录。

随后执行 `evaluate:agent-loop`：已发布候选数、带下一轮调整的有效闭环数和不同研究请求数均为 `0`。墨予镜草稿、编辑任务包和飞书“已转选题”状态均不计入发布或服务验证；在人工填写真实 `http/https` 发布链接和外部反馈前，不启用 Agent Loop。

同日补齐内容入库的短链接解析 Tool。`research:run` 与 `collect:tikhub` 在详情模式下会先识别已知四平台内容长链接；仅对官方短链或未知路径手动展开跳转，最多 5 次。解析只允许小红书、抖音、公众号和视频号的官方域名，拒绝未知、本机和内网目标；解析为博主页时停止，不创建追踪任务，也不写飞书。该 Tool 仅补全详情采集参数，不替代人工选择研究目标。

同日完成旧 B 站主路径范围复核。源码、npm 命令、Skill 和 README 中没有 B 站、RSSHub 或 yt-dlp 采集入口；旧的日汇总、失败审计和周汇总仅可显式读取历史本地文件，不能发起研究、选题、发布或业务决策。测试夹具已改用抖音等当前支持平台；唯一保留的“B站”文本是平台合同的负向断言，用于证明该平台会被拒绝，而不是恢复支持。

同日修正博主账号写入边界。内容详情和关键词研究不再根据内容作者自动创建“博主账号”记录，避免将单条内容 URL 错写为博主主页并意外启用追踪。只有显式 `creator` 账号拆解请求才可写入博主记录，主页链接必须由调用方以 `creatorHomepageUrl` 提供；内容表仍保留作者名称和账号标识作为来源元数据，不等同于已确认追踪账号。

同日进一步收紧账号拆解的身份合同：`creatorId` 与 `creatorHomepageUrl` 均为必填，飞书“博主账号”的平台 ID 和主页只使用人工确认的输入，不再从返回内容的作者字段推断。即使账号列表为空，也会写入一条“启用 / 手动 / 未命名账号”的已确认追踪记录；可选 `creatorName` 可覆盖内容返回的名称。该边界避免平台返回混入内容作者或空列表时，错误追踪其他账号或丢失人工确认的追踪任务。

同日校正飞书新建表 schema：`博主账号.数据源类型` 的可选值从遗留的 `rss / rss-file` 改为当前实现使用的 `TikHub / 手工`。该修改只影响后续通过 schema 创建的新表；没有自动改写现有飞书表的历史选项或记录。`validate:feishu` 已确认本地飞书配置字段映射仍有效。

同日统一企业 AI 服务的发布路由：无论是否使用研究模板，研究请求、洞察候选、内容简报和新建飞书“适用账号”选项均使用 `墨予镜`；`企业 AI 服务` 继续作为服务方向，不生成独立发布账号或草稿候选。后续变更目标账号时也会保留这一约束。客户项目仍只使用内部项目代号，且不会进入公开草稿链路。历史研究请求不自动改写，需时可使用 `research:target-account` 留痕变更。
