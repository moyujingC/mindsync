# AI营销获客系统阶段 6 P1-4 批量写入报告与状态回写实现记录

本文记录 P1-4，也就是给批量 enrichment 写入补上报告和本地状态回写。

## 1. 这一步解决什么问题

P1-3 已经能批量扫描 `enrichment.json` 并写入飞书候选。

但还缺两个运维信息：

- 本次批量处理了哪些 enrichment
- 每个 enrichment 是写入、重复，还是未启用飞书

没有这两个信息，后面很难排查和重跑。

## 2. 新增能力

这一步给批量命令增加两个参数：

```bash
--report <path>
--mark-processed
```

含义：

- `--report`：写出批量处理报告。
- `--mark-processed`：把每个 enrichment 的处理结果回写到原文件里的 `handoff` 字段。

## 3. 报告格式

报告 schema：

```text
content-matrix/enrichment-write-report/v1
```

报告包含：

- `rootDir`
- `feishuEnabled`
- `enrichmentCount`
- `inputCount`
- `createdCount`
- `duplicateCount`
- `recordIds`
- `items`

每个 item 包含：

- `enrichmentPath`
- `status`
- `candidateCount`
- `createdCount`
- `duplicateCount`
- `recordIds`
- `processedAt`

## 4. 当前状态值

当前 item 状态包括：

- `disabled`：未传飞书配置，只做本地 dry-run。
- `written`：已创建飞书候选。
- `duplicate`：候选已存在，未重复写入。
- `empty`：没有候选。

## 5. 命令怎么跑

本地生成报告，不写飞书：

```bash
node src/cli/write-enrichment-directory-insights.mjs \
  --root-dir fixtures/enrichments.example \
  --report logs/enrichment-writes/example.json
```

真实写飞书并回写本地状态：

```bash
node src/cli/write-enrichment-directory-insights.mjs \
  --root-dir logs/downloads/bilibili \
  --feishu config/feishu.local.json \
  --report logs/enrichment-writes/$(date +%F).json \
  --mark-processed
```

## 6. 为什么 dry-run 状态是 disabled

如果没有传 `--feishu`，系统不会写飞书。

这时报告里的 item 状态必须是：

```text
disabled
```

不能标成 `written`，否则会误导后续运营判断。

## 7. 当前边界

这一步还没做：

- 单个失败文件继续执行
- 失败重试队列
- 飞书写入后反向更新远端状态
- 报告 Markdown 化

## 8. 验证方式

已验证：

```bash

npm run insights:enrichments
```

测试覆盖：

- 报告文件写出
- `markProcessed` 回写 enrichment `handoff`
- 未启用飞书时状态为 `disabled`
