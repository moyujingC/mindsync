# 历史回溯与互动快照实现记录

> 状态：implemented-pending-real-run
> 日期：2026-07-27
> 范围：`influencer-tracker` 的账号历史回溯与互动快照
> 验证：本地自动化测试通过；飞书“互动快照”表已创建并完成字段校验；尚未以真实账号完成一次回溯。

## 已实现

```text
博主记录的采集动作 = 待回溯
-> Worker 解析主页并获取账号内容
-> 默认回溯近 90 天，最多请求 100 条
-> 仅保留发布时间在边界后的内容
-> 内容更新表写入 L1 内容证据
-> 每条内容追加一条互动快照
-> 博主记录回写新增数、重复数、快照数和停止原因
```

- 回溯范围使用“发布时间”判断，不能用采集时间代替。
- 列表页整页内容都早于回溯边界时，Worker 停止继续分页。
- 同一内容后续再次采集，会新增互动快照；不会覆盖旧快照。
- 默认不采评论、不创建研究请求、不触发 L2 文字稿或 L3 评论采集。

## 飞书新增表

已在现有多维表格创建 `互动快照`，保存：

- 快照唯一键、内容唯一键
- 发布时间、快照时间、内容年龄（天）
- 点赞、评论、收藏、转发/分享
- 采集批次、数据源

表 ID 与字段映射仅保存于未纳入版本控制的 `config/feishu.local.json`，不写入仓库或公开文档。

## 真实运行前的人工操作

1. 在“博主账号”找到已确认、启用的目标博主。
2. 将“采集动作”设为 `待回溯`；首次使用默认近 90 天。若要近 60 天，在“采集起始日期”填入 60 天前日期。
3. 运行 Creator Worker。生产 Worker 部署完成前，可由工程端执行命令；后续 Hermes 聊天入口会自动发起确认和回溯。
4. 在“内容更新”按博主、发布时间筛选 L1 样本；在“互动快照”按内容唯一键查看本次快照。
5. 人工挑选需要深入阅读的内容，再申请 L2 或 L3。未挑选内容停留在 L1。
