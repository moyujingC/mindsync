# 评分自动推进内容加工任务实现记录

> 状态：implemented-and-verified
> 日期：2026-07-27
> 范围：`influencer-tracker` 的 L1 评分后自动加工队列

## 目的

将内容双维筛选评分变成受限的自动推进机制，减少在飞书视图中逐条发起 L2 或洞察的操作，同时保留人工对结论、选题和发布的决定权。

```text
内容更新 L1
-> 双维评分
-> 内容加工任务
-> L2 内容提纯 / 选题洞察
-> 飞书洞察与选题
-> 人工审核
```

## 触发规则

| 条件 | 自动动作 | 初始状态 |
| --- | --- | --- |
| 干货信号分 >= 70 | 创建 `L2 内容提纯` | 待处理 |
| 爆款选题分 >= 80 | 创建 `选题洞察` | 待处理 |
| 两项都命中 | 两项都创建 | L2 待处理；洞察等待依赖 |
| 可比样本不足或观察中 | 不创建任务 | 无 |

任务唯一键由“内容唯一键 + 任务类型”构成。重复评分只更新评分字段，不会重复创建相同任务。

## 执行逻辑

- `L2 内容提纯`：重新采集单条公开内容；视频优先用平台字幕，没有字幕时再下载音频并转写。产物路径写回任务行。
- `选题洞察`：读取 L1 元数据，若存在已完成的 L2 产物则一并读取，生成一条带来源内容 ID 的“洞察与选题”候选。
- 洞察任务依赖 L2 时，L2 成功后自动转为待处理；L2 失败后转为“需人工处理”。
- Worker 每分钟只领取优先级最高的一条待处理任务，避免一次触发大量外部采集调用。

## 飞书可见内容

新增“内容加工任务”表，字段为：任务唯一键、内容唯一键、任务类型、触发原因、状态、优先级、目标账号、依赖任务、产物路径、错误摘要、创建时间、更新时间。

人工日常只需要：

1. 查看“内容加工任务”的失败或需人工处理项，决定重试、忽略或手动处理。
2. 查看“洞察与选题”的待处理候选，决定是否转选题。
3. 只有人工确认后的既有通路才能继续生成草稿、发布和记录反馈。

## 明确边界

- 不自动采集评论与回复。
- 不自动创建研究请求。
- 不自动发布、私信、评论、报价或判定成交。
- 不自动把洞察状态改为“已验证”。
