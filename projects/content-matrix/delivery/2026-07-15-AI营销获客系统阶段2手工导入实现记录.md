# AI 营销获客系统阶段 2 手工导入实现记录

本文记录路线图阶段 2 的第一轮实现：

```text
小红书 / 抖音半自动导入 -> 统一内容表
```

## 本轮目标

路线图阶段 2 里，小红书 / 抖音的策略是：

```text
先不硬爬，先支持人工粘贴，再由系统统一标准化和去重。
```

本轮实现的就是这条最小闭环。

## 实现步骤

### 1. 新增 manual-import job

改动位置：

- `projects/content-matrix/tools/influencer-tracker/src/jobs/manual-import.mjs`
- `projects/content-matrix/tools/influencer-tracker/src/cli/manual-import.mjs`

实现方式：

1. 读取人工整理的 JSON。
2. 将每条内容标准化成统一结构：
   - `platform`
   - `creatorName`
   - `contentExternalId`
   - `url`
   - `title`
   - `description`
   - `publishedAt`
   - `contentType`
   - 互动数
3. 为每条内容生成稳定 `uniqueKey`：

```text
平台 + externalId
```

4. 写入前同时检查：
   - 本地 store
   - 飞书 `内容更新` 表已有 `内容唯一键`

5. 只把真正新增的内容写入飞书。

### 2. 新增手工导入样例

改动位置：

- `projects/content-matrix/tools/influencer-tracker/fixtures/manual-import.example.json`

样例包含：

- 1 条小红书样例。
- 1 条抖音样例。

这样可以本地 dry-run，也可以直接验证飞书写入。

### 3. 修复 lark-cli 混合输出解析

改动位置：

- `projects/content-matrix/tools/influencer-tracker/src/feishu/lark-cli-client.mjs`

问题：

- 真实 `lark-cli` 在 stdout 前会输出版本横幅。
- 之前代码直接 `JSON.parse(stdout)`，遇到 `lark-cli v...` 就报错。

修复方式：

- 如果 stdout 不是纯 JSON，就从最后一个 JSON 起始位置截取并解析。

### 4. 兼容真实飞书字段选项

真实排查中发现：

- `内容类型` 支持 `图文`、`视频`、`video` 等选项。
- `标签` 当前在真实表里是单选且没有配置选项。

本轮处理：

- 手工导入把 `视频` 规范成真实表已接受的 `video`。
- 先不写 `标签`，避免因真实表选项未配置而失败。

设计取舍：

- 目标是先打通半自动导入链路，而不是一次性把所有飞书字段设计完。
- 标签字段后续应在飞书 schema 收口阶段统一升级。

## 残留风险

1. 还没有 `backfill-creator` 回溯采集命令。
2. 真实 RSS 扩展仍只验证了 B 站和 fixture，没有做到 3 个真实账号持续检查。
3. 真实表里的 `标签` 仍未收口为适合手工导入的字段。
4. 手工导入目前依赖外部人工整理 JSON，不支持直接从飞书表单导入。

## 下一步建议

下一步优先做：

```text
backfill-creator 命令
```

原因：

- 这是路线图阶段 2 另一个明确交付物。
- 对标账号回溯采集能直接服务市场调研和选题储备。
