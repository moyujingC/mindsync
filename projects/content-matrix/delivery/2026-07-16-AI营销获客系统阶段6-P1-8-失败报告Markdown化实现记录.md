# AI营销获客系统阶段 6 P1-8 失败报告 Markdown 化实现记录

本文记录 P1-8，也就是把 enrichment 写入 JSON 报告转成人工可读的 Markdown 运维报告。

## 1. 这一步解决什么问题

P1-4 到 P1-7 已经能输出 JSON 报告，并记录失败项。

但 JSON 更适合程序读取，不适合每天人工查看。真实运营时需要快速知道：

- 今天处理了多少 enrichment。
- 哪些项失败了。
- 失败原因是什么。
- 下一步应该运行哪条重试命令。

所以这一步新增 Markdown 报告。

## 2. 当前实现

新增导出函数：

```text
buildEnrichmentWriteMarkdownReport(report)
```

批量写入和失败重试都支持新参数：

```bash
--markdown-report logs/enrichment-writes/2026-07-16.md
```

生成内容包括：

- 基础摘要
- 状态汇总
- 失败项列表
- 错误原因
- 建议动作
- 可复制 retry 命令

## 3. CLI 用法

批量写入：

```bash
node src/cli/write-enrichment-directory-insights.mjs \
  --root-dir logs/downloads/bilibili \
  --report logs/enrichment-writes/2026-07-16.json \
  --markdown-report logs/enrichment-writes/2026-07-16.md
```

失败重试：

```bash
node src/cli/retry-failed-enrichment-insights.mjs \
  --report logs/enrichment-writes/2026-07-16.json \
  --retry-report logs/enrichment-writes/2026-07-16-retry.json \
  --markdown-report logs/enrichment-writes/2026-07-16-retry.md
```

## 4. 验证方式

新增测试覆盖：

- 批量写入时能生成 Markdown 报告。
- Markdown 报告包含失败数、失败项、错误原因和 retry 命令。
- 成功报告会显示“无失败项”。

已验证：

```bash
npm test
```

结果：

```text
tests 79
pass 79
fail 0
```

## 5. 当前边界

Markdown 报告是运维视图，不替代 JSON 报告。

JSON 仍是机器可读来源，Markdown 用于人工查看和复制命令。
