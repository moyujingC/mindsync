# AI营销获客系统阶段 6 P1-5 批量失败隔离与重试实现记录

本文记录 P1-5，也就是批量 enrichment 写入时的单文件失败隔离。

## 1. 这一步解决什么问题

P1-4 已经能生成批量写入报告。

但如果目录里有一个坏的 `enrichment.json`，旧逻辑会在读取阶段直接失败，导致整个批次都不能继续。

这在真实运行里风险很高，因为某个文件损坏、写了一半、格式不对，都不应该阻断其他正常内容。

## 2. 当前实现

这一步把批量读取改成安全读取：

```text
find enrichment files
-> safe read each file
-> bad file -> report item failed
-> good files -> continue build candidates
-> write good candidates
```

也就是说：

- 坏文件会被记录
- 好文件继续处理
- 报告里会有失败清单

## 3. 报告变化

批量报告新增：

- `failedCount`

单个 item 新增失败状态：

- `status: failed`
- `error`

失败 item 不会产生候选，也不会写飞书。

## 4. 当前状态值

现在 item 状态包括：

- `disabled`
- `written`
- `duplicate`
- `empty`
- `failed`

## 5. 重试方式

当前还没有单独的 retry 命令，但报告已经给出了失败文件路径：

```json
{
  "status": "failed",
  "enrichmentPath": ".../enrichment.json",
  "error": "..."
}
```

人工修复该文件后，可以重新跑同一个批量命令。

## 6. 验证方式

新增测试覆盖：

- 一个目录里同时有好 enrichment 和坏 enrichment。
- 坏文件进入 `failed`。
- 好文件仍然生成候选并写入。
- 报告 `failedCount` 正确。

已验证：

```bash
npm test
npm run insights:enrichments
```

## 7. 当前边界

还没做：

- 独立 retry CLI
- 根据报告只重跑 failed 文件
- 失败报告 Markdown 版
- 飞书写入阶段的部分失败隔离


也就是读取上一次报告里的 failed 项，只重跑这些文件。
