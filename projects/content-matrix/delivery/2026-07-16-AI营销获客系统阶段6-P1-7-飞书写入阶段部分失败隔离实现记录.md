# AI营销获客系统阶段 6 P1-7 飞书写入阶段部分失败隔离实现记录

本文记录 P1-7，也就是 enrichment 批量写入飞书时的部分失败隔离。

## 1. 这一步解决什么问题

P1-5 解决了坏 `enrichment.json` 阻断整批的问题。

P1-6 解决了失败项只重试的问题。

但还有一个运行风险：所有 enrichment 生成的候选会先合并成一个大批次写飞书。如果飞书接口、字段格式或某条记录异常导致整批失败，旧逻辑无法判断是哪一个 enrichment 触发了问题，也无法让其他 enrichment 继续写入。

## 2. 当前实现

这一步新增“整批优先，失败后降级”的写入策略：

```text
all candidates -> batch write to Feishu
if success:
  build normal report
if failed:
  split candidates by enrichment
  write each enrichment group
  successful group -> written / duplicate / empty
  failed group -> failed with error
```

这样日常成功路径仍然保持一次批量写入；只有失败时才降级为逐个 enrichment 重试。

## 3. 报告变化

当飞书写入阶段某个 enrichment 失败时，该 item 会进入：

```json
{
  "status": "failed",
  "candidateCount": 2,
  "createdCount": 0,
  "duplicateCount": 0,
  "recordIds": [],
  "error": "..."
}
```

返回结果新增：

- `batchWriteFailed`
- `batchWriteError`

`failedCount` 现在统计所有 `status: failed` 的 item，包含：

- JSON 读取失败
- 飞书写入失败

## 4. 为什么不直接全部逐个写入

逐个写入更容易定位问题，但会增加飞书请求次数。

当前选择是：

- 成功路径：继续批量写入，保持效率。
- 失败路径：自动降级，换取定位能力。

这更适合当前 MVP：大多数运行应该成功，失败时才需要更细的排障信息。

## 5. 验证方式

新增测试覆盖：

- 两个 enrichment 同时写入时，模拟整批飞书写入失败。
- 降级后，一个 enrichment 写入成功。
- 另一个 enrichment 继续失败并进入报告 `failed`。
- 返回结果包含 `batchWriteFailed` 和 `batchWriteError`。

已验证：

```bash
npm test
```

结果：

```text
tests 75
pass 75
fail 0
```
