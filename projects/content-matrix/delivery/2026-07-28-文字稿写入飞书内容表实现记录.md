# 文字稿写入飞书内容表实现记录

> 状态：implemented-and-verified

## 调整

服务器 `logs/media-evidence/` 继续保存字幕、原始转写与清理稿，供审计和重跑使用；日常阅读不再要求打开服务器路径。

L2 完成后，系统在飞书“内容更新”的原内容行写入：

- `内容提纯状态`：已完成、已降级或失败。
- `文字稿来源`：平台字幕或语音转写。
- `文字稿`：可直接在多维表格展开阅读的清理稿全文。

```text
L2 内容提纯
-> 本地保留原始证据
-> 清理稿写回“内容更新”原行
-> 飞书直接阅读、筛选和复制
```

## 历史回填

`npm run content:sync-transcripts` 会读取已完成 L2 任务的本地清理稿，并回填到对应飞书内容行。没有清理稿的已降级任务不写空白正文，也不会伪造文字稿。

## 边界

- 飞书表保存清理后的阅读文本，不保存视频、完整 API 响应或原始媒体文件。
- 服务器路径仍是底层工件位置，不作为日常操作入口。
- 当前先使用多维表格长文本字段；若后续出现超长稿、多人批注或结构化编辑需求，再升级为每条内容一份飞书文档，并在表中保存文档链接。
