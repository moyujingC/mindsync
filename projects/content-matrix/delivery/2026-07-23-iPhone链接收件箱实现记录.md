# iPhone 链接收件箱实现记录

## 实现过程

1. 将“随机刷到的链接”从“内容更新”中分离，新增飞书“链接收件箱”和本地 JSON 持久队列。收件记录保存原始/最终链接、平台、类型、状态、重试次数和错误摘要。
2. 复用现有安全短链解析，只允许四个平台官方域名和最多 5 次跳转。内容链接进入待处理；博主页和无法识别链接进入“需人工处理”。
3. 新增 Bearer Token（持有者令牌）保护的 HTTP 收件服务，包含 8 KiB 请求体限制、每分钟固定窗口限流和健康检查。接口只入队，返回 `202 Accepted`，不等待 TikHub。
4. 新增单次 Worker：领取一条记录，调用既有 TikHub 详情与评论采样、飞书内容/评论写入、研究请求与本地简报；成功或失败后回写收件箱。失败须人工显式重试。
5. 新增可选飞书群机器人通知，仅提示已收件、成功或失败，不承担队列职责。
6. 新增 systemd、Nginx、环境变量和 iPhone 背板双击快捷指令说明。转录保留在既有本地媒体 Workflow，不自动下载平台视频。
7. 新增飞书网页直接录入：Worker 会扫描“收件ID”为空且“原始链接”已填的手工行，补全字段并在原行完成整个状态流转。

## 已验证

- 新增收件、去重、主页降级、失败重试、HTTP 鉴权、健康检查和通知隔离测试通过。
- 完整 `npm test` 通过：193 个测试通过，0 个失败。
- 飞书“链接收件箱”已通过 Lark CLI 创建，并用 `validate:feishu` 与 `inspect:feishu` 验证配置和字段映射无错误或警告。
- HTTPS 域名、服务器常驻服务与真实 TikHub 收件联调仍待下一步执行。

## 当前风险与下一步

- `hermes.jingshu.cc` 的 Nginx/TLS 必须先恢复有效 HTTPS，才能让 iPhone 安全调用。
- 服务器需要部署私有环境变量与 `config/feishu.local.json`；这些文件不能提交。
- 首次上线用一条公开测试链接受控验证 TikHub 额度、飞书写入和群通知，再绑定日常背板双击。
