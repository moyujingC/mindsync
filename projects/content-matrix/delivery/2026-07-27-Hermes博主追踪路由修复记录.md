# Hermes 博主追踪路由修复记录

> 状态：implemented-pending-chat-retest
> 日期：2026-07-27
> 触发：飞书聊天中“增加某一个博主”后，Hermes 未按既有系统流程补问主题，而是传入空主题调用命令，并尝试无关的飞书 CLI 排障。

## 原因

release 服务器已部署 `creator-tracking` Skill，但 Hermes 的主角色仍是通用助手。模型能找到项目命令，却没有将 Skill 的两阶段确认规则视为最高优先级，因此绕过了“先补主题”的前置条件。

日志只验证了以下事实：

1. Hermes 调用了现有 `creator:tracking` 命令。
2. 调用传入了空的 `--topics`，被项目校验正确拒绝。
3. 随后尝试了不属于内容情报系统的飞书 CLI 配置操作。

未读取或归档用户聊天正文。

## 修复

- 新增部署用 Hermes 主角色文件：`deploy/hermes/SOUL.md`。
- 将“博主追踪”明确为状态机：缺主题 -> 只提问；主题齐全 -> 准备确认卡；用户回复“确认” -> 写飞书。
- 明确禁止空主题调用、无关 `lark-cli config` 操作、自行创建飞书资源或重新实现系统。
- 同步主角色和更新后的 `creator-tracking` Skill 至 release，并重启 `hermes-gateway.service`。

## 验证

- release 上 `hermes-gateway.service` 状态为 `active`，并重新连接飞书长连接。
- release 主角色文件包含“缺少主题时禁止调用终端命令”。
- release Skill 包含“不要传入空的 `--topics` 参数”。
