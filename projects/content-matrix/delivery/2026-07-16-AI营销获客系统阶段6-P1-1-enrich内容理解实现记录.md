# AI营销获客系统阶段 6 P1-1 enrich 内容理解实现记录

本文记录 `ai-boshu-crawler` 能力迁移进入 P1 后的第一步，也就是把本地采集产物进一步转成结构化内容理解结果。

## 1. 这一步解决什么问题

P0 已经跑通了：

```text
下载
-> 转写
-> 评论入库
-> manifest 统一
```

但这些还只是素材。

要服务“市场需求调研”和“选题”，还需要把素材整理成：

- 服务方向
- 需求信号
- 用户问题
- 洞察摘要
- 选题候选

所以 P1-1 先做一个本地 enrich（内容理解）层。

## 2. 当前实现策略

这一步先做规则版，不接大模型 API（应用程序接口）。

原因：

- 规则版稳定，适合测试。
- 输出可解释，便于人工检查。
- 后续接 LLM（大语言模型）时，可以把它作为 baseline（基线）。

当前输入：

```text
metadata.json
speech-clean.txt
bilibili-comments.example.json
```

当前输出：

```text
enrichment.json
enrich-manifest.json
```

## 3. 新增了什么

新增文件：

- `src/jobs/enrich-content.mjs`
- `src/cli/enrich-content.mjs`
- `tests/enrich-content.test.mjs`

同时新增样例输入：

- `fixtures/bilibili-artifact.example/speech-clean.txt`

并在 `package.json` 增加：

- `npm run enrich:bili`

## 4. 工作流怎么跑

本地样例：

```bash
node src/cli/enrich-content.mjs \
  --artifact-dir fixtures/bilibili-artifact.example \
  --comments fixtures/bilibili-comments.example.json
```

或者：

```bash
npm run enrich:bili
```

## 5. enrichment.json 里有什么

当前结构包括：

- `source`
- `serviceDirections`
- `primaryDirection`
- `demandSignals`
- `userProblems`
- `insights`
- `topicCandidates`
- `evidence`
- `reviewStatus`

其中 `reviewStatus` 默认是：

```text
待人工审核
```

这表示 enrich 只是生成候选判断，不直接替代人工结论。

## 6. 当前规则怎么判断

当前用关键词做初步判断：

- `AI 工作流诊断`
- `AI 文档 / 知识库整理`
- `内容生产系统`
- `企业 AI 落地 / FDE`

评论里的 `demandType` 会被统计成需求信号。

如果评论里出现“怎么、如何、能不能”等问题句，会优先作为 `userProblems`。

## 7. manifest 怎么接入

这一步会写：

```text
enrich-manifest.json
```

并沿用 P0-4 的统一结构：

- `version`
- `job`
- `status`
- `generatedAt`
- `input`
- `output`
- `error`

这样后续 `ops-audit` 可以统计 enrich manifest 覆盖数。

## 8. 当前边界

这一步还不是自动洞察系统。

当前还没做：

- LLM 深度归纳
- 自动写飞书 `洞察与选题`
- 多条内容聚类
- 评论高频主题聚类
- 人工审核后的状态回写

## 9. 对后面的帮助

这一步完成后，后面可以继续做：

1. 把 `enrichment.json` 转成飞书 `洞察与选题` 候选。
2. 接 LLM 做更细的需求归纳。
3. 按账号 / 平台 / 服务方向做多内容聚类。

## 10. 复用建议

以后新增平台或新分析类型，建议继续沿用：

```text
本地 artifact
-> enrichment.json
-> enrich-manifest.json
-> 人工审核
-> 飞书洞察
```

不要一开始就把 AI 判断直接写成最终结论。
