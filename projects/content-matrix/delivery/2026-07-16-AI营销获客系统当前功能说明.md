# AI营销获客系统当前功能说明

这份文档说明当前 `influencer-tracker` 工具已经能做什么，以及它在整套 AI 营销获客系统里处在哪个位置。

工具目录：

```text
projects/content-matrix/tools/influencer-tracker
```

当前系统已经跑通：

```text
博主 / 对标账号
-> 内容更新采集
-> 评论样本采集
-> 本地素材 artifact
-> 内容理解 enrichment
-> 飞书洞察与选题候选
-> brief / draft / 成稿链路
-> 发布反馈回流
```

## 1. 飞书多维表格

当前系统使用飞书多维表格作为运营控制台和数据承接层。

已接入 4 张表：

- `博主账号`
- `内容更新`
- `评论样本`
- `洞察与选题`

当前真实飞书 Base：

```text
AI营销获客系统
https://ocn8icdz3ez3.feishu.cn/base/L2ghbMSJiaJrJKsUNMTcMLxInMb
```

当前本地配置文件：

```text
config/feishu.local.json
```

这个文件包含真实 token 和表 ID，已被 `.gitignore` 排除，不提交到仓库。

## 2. 博主更新追踪

系统可以读取博主清单，检查这些账号有没有新内容。

当前支持：

- 本地 JSON 博主清单
- 飞书 `博主账号` 表
- B 站 RSS 数据源
- 本地 RSS fixture
- 内容去重
- 单个账号失败不阻断其他账号

本地测试：

```bash
npm run check
```

真实飞书测试：

```bash
node src/cli/check-updates.mjs \
  --feishu config/feishu.local.json \
  --creators fixtures/creators.example.json \
  --store logs/content-store.manual-feishu-test.json
```

已验证：

- 第一次真实写入新增 2 条 B 站样例内容。
- 第二次重复运行识别为 2 条重复，不再新增。

## 3. 手工导入小红书 / 抖音

小红书和抖音当前还没有做完整自动爬取，但已经支持半自动导入。

适合场景：

- 手工粘贴小红书链接、标题、正文和互动数
- 手工粘贴抖音链接、标题、正文和互动数
- 先把内容统一进入 `内容更新` 表

命令：

```bash
node src/cli/manual-import.mjs \
  --input fixtures/manual-import.example.json \
  --feishu config/feishu.local.json \
  --store logs/content-store.manual.feishu.json
```

已支持：

- 标准化平台、标题、链接、互动数
- 按 `uniqueKey` 去重
- 写入飞书 `内容更新` 表

## 4. 对标账号回溯采集

系统支持对某个账号做回溯采集，也就是批量拉取历史内容样本。

命令：

```bash
node src/cli/backfill-creator.mjs \
  --feishu config/feishu.local.json \
  --creator-name B站样例账号 \
  --limit 20 \
  --store logs/content-store.backfill.feishu.json
```

支持参数：

- `--creator-id`
- `--creator-name`
- `--limit`
- `--since`

用途：

- 调研对标账号内容结构
- 建立选题样本库
- 后续做评论需求分析

## 5. B 站素材下载

系统可以把 B 站内容从“元数据”升级为本地 artifact。

artifact 指一个内容样本在本地的结构化目录，里面可以放元数据、视频、字幕、评论、转写稿、enrichment 等产物。

命令：

```bash
node src/cli/download-bilibili.mjs \
  --creator-id sample-bilibili-rss \
  --limit 1
```

默认只写元数据，不下载视频。

如果本机安装了 `yt-dlp`，可以启用真实下载：

```bash
node src/cli/download-bilibili.mjs \
  --creator-id sample-bilibili-rss \
  --limit 1 \
  --download-mode yt-dlp
```

当前产物：

- `metadata.json`
- `description.txt`
- `download-manifest.json`
- `video.*`，仅真实下载成功时出现

## 6. 视频转写

系统支持把 artifact 里的视频或字幕转成文本。

命令：

```bash
node src/cli/transcribe-video.mjs \
  --artifact-dir fixtures/bilibili-artifact.example \
  --mode subtitle-only
```

当前逻辑：

- 有字幕时优先清洗字幕
- 没字幕时，`auto` 模式可尝试 `ffmpeg + whisper`

当前产物：

- `speech-raw.txt`
- `speech-clean.txt`
- `transcribe-manifest.json`

## 7. 评论样本入库

系统可以把 B 站评论样本标准化后写入飞书 `评论样本` 表。

命令：

```bash
node src/cli/sync-bilibili-comments.mjs \
  --input fixtures/bilibili-comments.example.json \
  --feishu config/feishu.local.json
```

已支持：

- 评论对象标准化
- 稳定 `commentUniqueKey`
- 按 `评论唯一键` 去重
- 写入需求类型、情绪倾向、是否进入洞察

真实飞书联调已验证：

- 第一次写入 2 条评论。
- 再次运行识别为 2 条重复。
- `需求类型` 字段已调整为多选，可以写入多个需求标签。

## 8. Manifest 统一

下载、转写、评论链路都会写 manifest。

manifest 是每一步运行留下的结构化记录，用来说明：

- 这一步是什么任务
- 输入是什么
- 输出是什么
- 是否成功
- 错误是什么

当前统一字段包括：

- `version`
- `job`
- `status`
- `generatedAt`
- `input`
- `output`
- `error`

用途：

- 排查某个内容处理到哪一步
- 做连续运行审计
- 判断哪些 artifact 已经具备评论、转写、enrichment

## 9. Enrichment 内容理解

enrichment 是当前系统的内容理解层。

它会把一个 artifact 里的内容、转写稿和评论样本，整理成结构化判断。

命令：

```bash
node src/cli/enrich-content.mjs \
  --artifact-dir fixtures/bilibili-artifact.example \
  --comments fixtures/bilibili-comments.example.json
```

当前输出：

- `enrichment.json`
- `enrich-manifest.json`

当前 enrichment 会生成：

- `serviceDirections`
- `demandSignals`
- `userProblems`
- `insights`
- `topicCandidates`

注意：当前是规则版，不调用 LLM（大语言模型）。结果默认是 `待人工审核`，不能直接当成最终市场结论。

## 10. Enrichment 转飞书洞察候选

系统可以把 `enrichment.json` 转成飞书 `洞察与选题` 表里的候选记录。

单文件命令：

```bash
node src/cli/write-enrichment-insights.mjs \
  --enrichment fixtures/enrichment.example.json \
  --feishu config/feishu.local.json
```

当前生成两类候选：

- `用户需求`
- `选题`

去重规则：

```text
来源内容 + 洞察类型
```

真实飞书联调已验证：

- 写入时能正确新建。
- 重复运行时能正确去重。

## 11. 批量 Enrichment 写入

系统可以递归扫描一个目录下所有 `enrichment.json`，批量写入飞书洞察候选。

命令：

```bash
node src/cli/write-enrichment-directory-insights.mjs \
  --root-dir logs/downloads/bilibili \
  --feishu config/feishu.local.json \
  --report logs/enrichment-writes/2026-07-16.json \
  --markdown-report logs/enrichment-writes/2026-07-16.md \
  --mark-processed
```

当前支持：

- 批量扫描
- 批量写入飞书
- JSON 报告
- Markdown 报告
- 本地 `handoff` 状态回写
- 按日期筛选
- 按账号筛选

筛选示例：

```bash
node src/cli/write-enrichment-directory-insights.mjs \
  --root-dir logs/downloads/bilibili \
  --date 2026-07-16 \
  --creator B站样例账号 \
  --feishu config/feishu.local.json \
  --report logs/enrichment-writes/2026-07-16-B站样例账号.json \
  --markdown-report logs/enrichment-writes/2026-07-16-B站样例账号.md \
  --mark-processed
```

真实飞书联调已验证：

- 批量写入能识别重复。
- JSON / Markdown 报告能正常生成。
- 无失败项时 retry 为空。

## 12. 失败隔离与重试

系统已经做了两层失败隔离。

第一层：文件读取失败隔离。

```text
坏 enrichment.json -> failed
好 enrichment.json -> 继续处理
```

第二层：飞书写入失败隔离。

```text
先整批写入
如果整批失败
-> 按 enrichment 分组降级重试
-> 成功项继续写入
-> 失败项进入 report
```

失败重试命令：

```bash
node src/cli/retry-failed-enrichment-insights.mjs \
  --report logs/enrichment-writes/2026-07-16.json \
  --feishu config/feishu.local.json \
  --retry-report logs/enrichment-writes/2026-07-16-retry.json \
  --markdown-report logs/enrichment-writes/2026-07-16-retry.md \
  --mark-processed
```

报告里的状态包括：

- `disabled`
- `written`
- `duplicate`
- `empty`
- `failed`

## 13. 每日运行与摘要

系统支持把日常运行串起来，生成运行报告、选题候选、每日摘要和失败复核。

命令：

```bash
node src/cli/run-daily.mjs \
  --dry-run \
  --creators fixtures/creators.example.json
```

相关能力：

- `run-report`
- `topic-candidates`
- `daily-summary`
- `failure-review`

这些能力用于日常运营复盘：

- 今天检查了哪些账号
- 发现了哪些新内容
- 生成了哪些选题候选
- 哪些账号连续失败

## 14. 选题到内容生产交接

当飞书 `洞察与选题` 表里某条候选经过人工审核后，系统可以继续生成内容生产交接稿。

当前支持：

- 从已审核洞察生成 Markdown brief
- 从 brief 生成 draft seed
- 草稿转存
- 成稿骨架
- 成稿编辑入口
- 发布反馈记录
- 反馈转样本沟通

这部分对应从“选题”到“内容生产”的后半段链路。

## 17. 当前边界

当前还没有完成：

- 小红书自动爬取
- 抖音自动爬取
- B 站评论在线自动抓取
- LLM 驱动的高质量 enrichment
- 评论需求聚类
- Web 控制台
- 定时调度的生产化部署

当前可用策略是：

- B 站优先走 RSS / 下载 / 评论样例链路
- 小红书和抖音先走手工导入
- 飞书作为运营主界面
- Markdown 报告作为每日人工检查入口

## 18. 建议的日常使用顺序

每天可以按这个顺序跑：

```text
1. 检查更新
2. 对有价值内容下载 / 转写 / 导入评论
3. 生成 enrichment
4. 批量写入飞书洞察候选
5. 看 Markdown 报告
6. 修复 failed 项并 retry
7. 在飞书里人工审核洞察
8. 生成 brief / draft
```

当前系统已经能支撑“市场需求调研 -> 选题候选 -> 内容生产交接”的最小闭环。
