# 内容双维筛选评分实现记录

> 状态：implemented-and-verified
> 日期：2026-07-27
> 范围：`influencer-tracker` 的 L1 内容筛选、飞书字段与视图

## 用途

内容回溯会产生较多 L1 内容记录。评分只用于把同一博主、同一平台的内容排出优先阅读顺序，不输出“必爆”“高质量”或市场需求结论。

```text
内容更新（标题、发布时间、当前互动）
-> 按博主 + 平台分组
-> 按内容年龄校正互动数据
-> 爆款选题分 / 干货信号分
-> 飞书候选视图
-> 人工决定进入选题库或申请 L2
```

互动快照不参与这条主链路。未来若要比较同一内容的后续增量，再作为重点内容复查能力启用。

## 两类分数

### 爆款选题分

用于判断内容的题材和表达是否值得进入“爆款选题库”继续研究。

- 80%：点赞、收藏、转发/分享的单位内容年龄相对排名。
- 20%：评论数的单位内容年龄相对排名。
- `>= 80`：`爆款选题库候选`。
- `60-79`：`人工快速查看`。
- `< 60`：`保留 L1`。

### 干货信号分

用于判断是否值得申请 L2 深读、文字稿或内容拆解。

- 55%：收藏的单位内容年龄相对排名。
- 30%：转发/分享的单位内容年龄相对排名。
- 15%：评论的单位内容年龄相对排名。
- `>= 70`：`建议申请 L2`。
- 其余：`保留 L1`。

内容年龄以“评分时间 - 发布时间”计算，最少按 1 天处理。这样不把发布时间更早的累计互动直接当作更强表现。

同一组少于 5 条内容时，系统写入 `观察中`，不计算分数。

## 飞书字段与视图

在“内容更新”新增：

- `筛选状态`：待评分、可评分、观察中。
- `爆款选题分`、`干货信号分`。
- `选题建议`、`深读建议`。
- `评分时间`、`评分说明`。

新增两个视图：

- `爆款选题候选`：筛选“选题建议 = 爆款选题库候选”，按爆款选题分降序。
- `建议深读（L2）`：筛选“深读建议 = 建议申请 L2”，按干货信号分降序。

## 使用方式

服务器或本地在飞书配置可用时执行：

```bash
npm run content:screen
```

先只预览、不写飞书：

```bash
npm run content:screen -- --dry-run
```

日常操作只需打开两个视图：

1. 评分后，系统按阈值自动创建“内容加工任务”；日常无需在两个视图逐条发起 L2 或洞察。
2. 在“内容加工任务”中处理“失败”与“需人工处理”；“完成”的洞察仍需人工审核后才能转选题。
3. 分数是队列筛选提示，不自动创建研究请求、不采评论、不发布，也不将洞察标为“已验证”。
