# AI 营销获客系统阶段 1-3 实现记录

本文记录后续阶段第一轮实现：

```text
飞书去重 + 选题候选写入飞书
```

对应路线图中的：

- 阶段 1：飞书工作台收口。
- 阶段 3：洞察与选题入库。

## 本轮目标

把系统从：

```text
飞书博主账号 -> 内容更新
```

推进到：

```text
飞书博主账号 -> 内容更新 -> 洞察与选题
```

同时解决一个数据可靠性问题：不能只依赖本地 `logs/content-store.feishu.json` 去重。即使本地缓存删除，也应以飞书 `内容更新` 表中的 `内容唯一键` 为准。

## 实现步骤

### 1. 飞书远端去重

改动位置：

- `projects/content-matrix/tools/influencer-tracker/src/jobs/check-updates.mjs`
- `projects/content-matrix/tools/influencer-tracker/src/feishu/client.mjs`

实现方式：

1. 在真实飞书模式下，`checkUpdates` 启动后先读取飞书 `内容更新` 表。
2. 从每条记录中提取 `内容唯一键`，组成 `remoteContentKeys` 集合。
3. 判断新内容时同时检查：
   - 本地 store 是否已有。
   - 飞书远端 `内容唯一键` 是否已有。
4. 只有两边都不存在时，才写入 `内容更新`。
5. 写入成功后，同步更新本地 store 和本次运行内的远端 key 集合，避免同次运行重复。

设计取舍：

- 飞书是主库，本地 store 只做缓存和运行历史。
- `dry-run` 不查飞书远端 key，保持本地样例验证简单。
- 当前读取整张 `内容更新` 表，适合 MVP。后续数据量变大后，应改成按 `内容唯一键` 过滤查询或分页索引。

### 2. 选题候选写入飞书

改动位置：

- `projects/content-matrix/tools/influencer-tracker/src/cli/generate-topic-candidates.mjs`
- `projects/content-matrix/tools/influencer-tracker/src/jobs/write-topic-candidates.mjs`
- `projects/content-matrix/tools/influencer-tracker/src/feishu/client.mjs`

实现方式：

1. 保留原有本地 JSON 输出，不破坏已有 `logs/topic-candidates/` 工作方式。
2. 给 `generate-topic-candidates` 增加 `--feishu` 参数。
3. 如果传入 `--feishu config/feishu.local.json`，则把候选写入飞书 `洞察与选题` 表。
4. 候选字段映射：
   - `topicTitle` -> `洞察标题`
   - `source.contentUniqueKey` -> `来源内容`
   - 固定 `洞察类型 = 选题`
   - 服务方向命中 AI 服务相关项时，`适用账号 = 知行AI服务`
   - `evidenceSummary` -> `证据摘要`
   - `nextAction + userProblem + cta` -> `建议动作`
   - 固定 `状态 = 待处理`

设计取舍：

- 写入飞书后仍保留人工审核状态，不自动进入成稿。
- 选题候选只是线索，不直接当成市场结论。
- 目前不做候选去重，下一步需要用 `来源内容 + 洞察类型` 或独立 `candidateId` 补去重。

### 3. 飞书配置补齐

改动位置：

- `projects/content-matrix/tools/influencer-tracker/src/feishu/config.mjs`
- `projects/content-matrix/tools/influencer-tracker/src/feishu/lark-cli-client.mjs`
- `projects/content-matrix/tools/influencer-tracker/config/feishu.example.json`
- `projects/content-matrix/tools/influencer-tracker/config/feishu.lark-cli.local.example.json`
- 本机运行配置：`projects/content-matrix/tools/influencer-tracker/config/feishu.local.json`

实现方式：

1. 把 `insights` 纳入飞书配置必需表。
2. 补齐 `洞察与选题` 的字段映射。
3. 在 `lark-cli` 批量写入时，为 `insights` 表固定字段顺序。
4. 更新 bootstrap 输出，避免建表脚本只返回 `creators` 和 `contents`。

注意：

- `config/feishu.local.json` 是本机运行配置，已被 `.gitignore` 排除，不提交。
- 仓库只提交 example 配置。

## 当前系统状态

已经跑通：

```text
飞书博主账号
-> 检查更新
-> 飞书内容远端去重
-> 内容更新
-> 运行报告
-> 选题候选
-> 洞察与选题
```

这一步完成后，系统已经不只是采集器，而是有了营销获客工作台的雏形。

## 残留风险

1. `洞察与选题` 目前没有候选级去重，重复使用同一报告写入会重复生成候选。
2. 远端内容去重当前读取整张内容表，数据量大后需要分页和过滤优化。
3. 选题生成仍是规则推断，不是 LLM 深度分析。
4. 真实平台数据源仍主要依赖 B 站 RSS / fixture，小红书和抖音还未接入半自动导入。

## 下一步建议

下一步优先做：

```text
洞察与选题去重 + 已审核选题生成 brief
```

原因：

- 先防止候选表污染。
- 再把人工审核后的选题接到已有草稿 / 成稿链路。
- 这样能继续推进到内容生产闭环，而不是停留在数据收集。
