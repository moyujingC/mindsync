# AI营销获客系统阶段 6 P0-2 转写链路实现记录

本文记录 `ai-boshu-crawler` 能力迁移第二步，也就是：

```text
本地视频 / 字幕
-> 转写稿
-> clean transcript
-> transcribe manifest
```

## 1. 为什么先做这一步

仅有视频文件，对后面的选题和需求分析帮助有限。

真正能进入：

```text
内容理解
-> 高频问题提取
-> 观点归纳
-> 选题生成
```

的是文本层。

所以下载链路后面，最先要接的是转写链路。

## 2. 当前实现策略

这一步采用的是“字幕优先，Whisper 兜底”的策略。

原因很实际：

- 字幕存在时，速度最快，也最稳定。
- Whisper 虽然更通用，但首次运行可能涉及模型下载，测试不够轻。
- 先把工作流骨架搭好，比一开始就追求最强识别更重要。

所以当前逻辑是：

1. 先找 artifact 目录里的字幕文件。
2. 如果找到了，就直接清洗字幕，生成转写稿。
3. 如果没找到字幕，再走 `ffmpeg + whisper`。

## 3. 新增了什么

新增文件：

- `src/jobs/transcribe-video.mjs`
- `src/cli/transcribe-video.mjs`
- `tests/transcribe-video.test.mjs`

同时在 `package.json` 里增加了：

- `npm run transcribe:bili`

## 4. 工作流怎么跑

当前命令入口：

```bash
node src/cli/transcribe-video.mjs --artifact-dir <目录>
```

内部流程：

```text
artifactDir
-> 读取 download-manifest.json
-> 优先找 subtitle.srt / subtitle.vtt / captions.srt / captions.vtt
-> 有字幕：清洗后输出 speech-raw / speech-clean
-> 无字幕：从 videoPath 抽音频
-> whisper 转写
-> 输出 transcribe-manifest.json
```

## 5. 当前产物

每次运行会写出：

- `speech-raw.txt`
- `speech-clean.txt`
- `transcribe-manifest.json`

如果走了 `whisper` 路径，还会多出：

- `audio.m4a`

## 6. 当前支持的模式

### `auto`

默认模式：

- 有字幕就走字幕
- 没字幕就走 whisper

### `subtitle-only`

只允许走字幕：

- 有字幕则成功
- 没字幕则失败

这个模式适合本地稳定测试。

## 7. 测试是怎么做的

这一步没有把测试绑死在真实 `ffmpeg` 和 `whisper` 上，而是通过 mock（模拟）外部命令做验证。

当前测试覆盖：

1. 字幕清洗逻辑。
2. clean transcript 清洗逻辑。
3. 有字幕时，不调用外部命令也能成功产出。
4. 没字幕时，会按顺序调用 `ffmpeg` 和 `whisper`。

## 8. 当前边界

这一步还是 P0 里的最小转写能力，不是完整媒体处理系统。

当前还没做：

- 自动下载字幕。
- 多语言识别策略。
- 长视频切段。
- 转写结果写回飞书 doc（文档）。
- transcript 与选题 enrich 直接打通。

## 9. 对后面的帮助

这一步完成后，后面几个阶段就更顺了：

1. P0-3 评论抓取可以和 transcript 一起形成“内容 + 评论”双文本样本。
2. P0-4 manifest 公共抽象时，可以把下载和转写统一纳入同一套运行记录。
3. P1-1 enrich 可以直接读取 `speech-clean.txt` 做内容理解。

## 10. 以后复用时怎么照搬

如果后面给抖音、小红书也接转写，建议继续沿用这个顺序：

1. 先保证下载产物目录稳定。
2. 先吃字幕，再兜底音频转写。
3. 先写本地 transcript 文件，不急着直接写飞书。
4. 每个阶段都单独写 manifest，方便排障和运维审计。
