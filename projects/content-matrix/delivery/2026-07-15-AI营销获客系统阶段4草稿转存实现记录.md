# AI 营销获客系统阶段 4 草稿转存实现记录

本文记录第四轮后续阶段实现：

```text
draft seed -> 账号草稿目录
```

对应路线图中的阶段 4：内容生产闭环。

## 本轮目标

上一轮已经能从飞书洞察生成 brief 和 draft seed。本轮补上一个显式转存动作：

```text
logs/drafts/*-draft.md -> projects/content-matrix/accounts/<账号名>/*-草稿.md
```

这个动作只把草稿种子转成账号目录下的正式草稿文件，不自动扩写成稿、不配图、不排版、不发布。

## 实现步骤

### 1. 新增 promote-draft job

改动位置：

- `projects/content-matrix/tools/influencer-tracker/src/jobs/promote-draft.mjs`

实现方式：

1. 读取 draft seed Markdown。
2. 解析：
   - 标题。
   - `source_insight_record_id`。
   - 开头草稿。
   - 草稿结构。
   - 证据来源。
   - CTA。
   - 人工审核清单。
3. 按账号目录规则输出：

```text
projects/content-matrix/accounts/<账号名>/<日期>-<标题>-草稿.md
```

4. 输出文件头保留：
   - `状态：草稿`
   - 来源 draft seed 路径
   - `source_insight_record_id`
   - 目标账号

5. 如果同名文件已存在，默认失败，必须显式传 `--overwrite` 才覆盖。

设计取舍：

- 这里不自动选择账号，必须由人工传 `--account`。
- 不自动进入成稿目录，文件名保持 `草稿`。
- 保留来源 ID，方便回溯到飞书洞察。

### 2. 新增 CLI

改动位置：

- `projects/content-matrix/tools/influencer-tracker/src/cli/promote-draft.mjs`
- `projects/content-matrix/tools/influencer-tracker/package.json`

命令：

```bash
node src/cli/promote-draft.mjs \
  --draft logs/drafts/xxx-draft.md \
  --account 墨予镜
```

可选覆盖：

```bash
--overwrite
```

## 当前系统状态

现在系统已经跑通：

```text
飞书博主账号
-> 内容更新
-> 远端去重
-> 运行报告
-> 选题候选
-> 洞察与选题
-> 候选去重
-> 已审核选题
-> Markdown brief
-> 草稿种子
-> 飞书状态回写
-> 账号草稿目录
```

这一步把 AI 营销获客系统接到了内容矩阵的账号生产目录。

## 残留风险

2. 生成的样例草稿来自测试 fixture，不应直接发布。
3. 尚未接入成稿编辑 skill、内容视觉工坊配图和排版。
