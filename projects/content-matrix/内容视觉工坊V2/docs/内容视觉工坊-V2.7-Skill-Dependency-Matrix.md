# 内容视觉工坊 V2.7 Skill Dependency Matrix

## 1. 文档目的

这份文档专门回答三个问题：

1. 每个 `skill` 依赖哪些上游能力
2. 每个 `skill` 的结果被哪些下游能力消费
3. 哪些变化会让现有结果进入 `stale`

这份矩阵是对 [内容视觉工坊-V2.7-Skill-Architecture.md](./内容视觉工坊-V2.7-Skill-Architecture.md) 的补充，不替代主架构文档。

## 3. 当前最重要的三类绑定

这些绑定是内容视觉工坊从“页面原型”走向“AI 编排产品”的关键。

### 3.1 知识卡绑定

- 绑定关系：`cardPlan[i] <-> generated image`
- 当前口径：
  - 优先按 `index + title` 匹配
  - 退一步按 `title` 匹配
- 失效结果：
  - 结果不删除
  - 标记为“需重生成”

这是当前最需要继续强化的一条绑定链。

### 3.2 金句卡绑定

- 绑定关系：
  - `selectedQuoteIndexes`
  - `selectedQuoteTexts`
  - `generatedAtPlanningRevision`
- 失效结果：
  - 旧结果继续展示
  - 标明是上一轮选句结果
  - 不自动覆盖

这条链已经有了基础实现，后面重点是支持多金句批量生成。

### 3.3 正文配图绑定

- 目标绑定关系：`section / inlineImagePlan[i] <-> generated image`
- 当前状态：基础结果已生成，绑定还不够强
- 后续重点：
  - 明确 section id
  - 明确配图对应哪一段
  - 排版页可直接消费

## 4. `stale` 的统一处理规则

所有 `stale` 都遵守同一原则：

1. 不默认删除旧结果
2. 不伪装成当前有效结果
3. 在 UI 上明确标记
4. 提供重新生成或重新渲染入口

按结果类型区分：

### 4.1 规划类结果 `stale`

- 典型对象：
  - `cardPlan`
  - `candidateQuotes`
  - `inlineImagePlan`
- 处理：
  - 直接以最新规划覆盖旧规划
  - 保留需要迁移的选择和绑定摘要

### 4.2 图片类结果 `stale`

- 典型对象：
  - 知识卡图片
  - 金句卡图片
  - 封面候选
  - 正文配图
- 处理：
  - 结果继续可见
  - 绑定失效则标注
  - 用户显式点击后才刷新

### 4.3 排版类结果 `stale`

- 典型对象：
  - 公众号预览
  - 复制 HTML
- 处理：
  - 提示“当前排版基于旧内容/旧图片”
  - 用户重新渲染或重新复制后更新

## 5. 当前实现重点与缺口

### 已经有基础实现的依赖链

1. `article_ingest -> content_planning`
2. `content_planning -> quote_selection`
3. `quote_selection -> quote_card_generation`
4. `content_planning -> knowledge_card_generation`
5. `content_planning -> cover_generation`
6. `content_planning -> inline_illustration_generation`

### 还需要继续做实的依赖链

1. `inline_illustration_generation -> wechat_layout_rendering`
2. `cover_generation -> wechat_layout_rendering`
3. `knowledge_card_generation -> distribution_packaging`
4. `quote_card_generation -> distribution_packaging`
5. `theme_mounting -> all generation skills`

## 6. 开发时的使用方式

每次改一个功能，先查这张表，回答四个问题：

1. 它属于哪个 `skill`
2. 它依赖哪个上游
3. 它产出给哪个下游
4. 什么情况下会变成 `stale`

如果这四个问题答不清，就说明这次改动还停留在“页面模块调整”，还没真正进入 `skill` 级设计。

## 7. 下一步建议

基于当前矩阵，V2.7 最值得先落地的是三件事：

1. 给 `inline_illustration_generation` 建立稳定的 `section` 绑定
2. 给 `cover_generation` 补“当前选中封面”的绑定与消费链
3. 让 `wechat_layout_rendering` 直接读取真实生成结果，而不是只读文章结构

这三件事一做，内容视觉工坊就会明显更像一套可运行的 AI 编排系统，而不是多个独立页面的组合。
