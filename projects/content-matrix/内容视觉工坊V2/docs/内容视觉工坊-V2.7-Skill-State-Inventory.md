# 内容视觉工坊 V2.7 Skill State Inventory

## 1. 文档目的

这份文档回答一个很具体的问题：

`当前前端代码里，真正存在的状态都放在哪里，它们分别属于哪个 skill？`

它不是产品定义文档，也不是页面原型说明，而是：

- 把现有 React 状态对齐到 `skill architecture`
- 找出哪些状态已经是 `skill state`
- 找出哪些状态仍然只是 `page local state`
- 为 V2.7 后续重构提供最小迁移地图

关联文档：

- [内容视觉工坊-V2.7-Skill-Architecture.md](./内容视觉工坊-V2.7-Skill-Architecture.md)
- [内容视觉工坊-V2.7-Skill-Dependency-Matrix.md](./内容视觉工坊-V2.7-Skill-Dependency-Matrix.md)

## 3. Shared State Inventory

这部分已经接近真正的 `skill state`。

### 3.1 `activeTab`

- 容器：`WorkspaceProvider`
- 位置：[workspace.tsx](/Users/xinran/Downloads/dev/mindsync/projects/content-matrix/内容视觉工坊V2/src/app/workspace.tsx)
- 类型：`WorkspaceTab`
- 所属层级：页面导航，不属于具体 `skill`
- 当前消费者：
  - [App.tsx](/Users/xinran/Downloads/dev/mindsync/projects/content-matrix/内容视觉工坊V2/src/app/App.tsx)
  - 工作台控制塔跳转
- 判断：
  - 这是 `navigation state`
  - 不是 `skill state`

### 3.2 `currentArticle`

- 容器：`WorkspaceProvider`
- 类型：`WorkspaceArticle`
- 所属 skill：
  - `article_ingest`
- 当前消费者：
  - `content_planning`
  - `wechat_layout_rendering`
  - `general-image`
- 判断：
  - 这是主共享输入源
  - 已经是合格的 `upstream skill state`

### 3.3 `currentArticleBlocks`

- 容器：`WorkspaceProvider`
- 来源：`currentArticle.body -> buildArticleBlocks()`
- 所属 skill：
  - `article_structuring`
- 当前消费者：
  - `wechat_layout_rendering`
- 判断：
  - 这是派生状态，不需要单独写回
  - 已经有明确上游和下游

### 3.4 `currentArticleMeta`

- 容器：`WorkspaceProvider`
- 来源：`currentArticle.body -> buildArticleMeta()`
- 所属层级：
  - 文章摘要展示
- 判断：
  - 这是 `derived UI meta`
  - 不是核心 `skill state`

### 3.5 `generationRecords`

- 容器：`WorkspaceProvider`
- 类型：`GenerationRecord[]`
- 所属 skill：
  - `knowledge_card_generation`
  - `quote_card_generation`
  - `cover_generation`
  - `inline_illustration_generation`
- 当前问题：
  - 它是一个按 `purposeKey` 聚合的总记录池
  - 但还不是严格分 skill 的独立状态模型
- 判断：
  - 它是当前最接近“生成结果总线”的共享状态
  - 后续可以演进为 `generation result registry`

### 3.6 `planningState`

- 容器：`WorkspaceProvider`
- 类型：`PlanningState | null`
- 所属 skill：
  - `content_planning`
- 输出内容：
  - `cardPlan`
  - `candidateQuotes`
  - `inlineImagePlan`
  - `coverTheme`
  - `strategySummary`
- 判断：
  - 这是目前最完整、最像正式 `skill state` 的一项
  - 但还缺单独显式的 `stale` 标记

### 3.7 `workbenchState`

- 容器：`WorkspaceProvider`
- 类型：`WorkbenchState`
- 组成：
  - `lockedKnowledgeCardIndexes`
  - `knowledgeCardStatuses`
  - `knowledgeCardHistories`
  - `taskState`
  - `quoteGenerationSelection`
  - `importedMarkdownMeta`
  - `replanRevision`
- 所属 skill：
  - 混合型
- 判断：
  - 这是当前最大的“共享工作台运行时状态包”
  - 优点是已经能支撑主链路
  - 问题是多个 skill 还挤在一个容器里

## 4. Workbench Controller State Inventory

这部分大多是工作台编排态，其中有些已经是 skill 内部状态，有些还是 UI 局部态。

### 4.1 输出开关 `outputs`

- 位置：[use-workbench-controller.ts](/Users/xinran/Downloads/dev/mindsync/projects/content-matrix/内容视觉工坊V2/src/app/components/use-workbench-controller.ts)
- 所属层级：
  - 工作台编排参数
- 关联 skill：
  - `knowledge_card_generation`
  - `quote_card_generation`
  - `cover_generation`
  - `inline_illustration_generation`
  - `wechat_layout_rendering`
- 判断：
  - 这是 `orchestration config state`
  - 不是单个 skill 的拥有状态

### 4.2 `splitStrategy / minCards / maxCards`

- 所属 skill：
  - `content_planning`
- 判断：
  - 这是典型的 `planning input state`
  - 后续应该考虑提升为共享态，而不是只留在 controller

### 4.3 `selectedQuotes`

- 所属 skill：
  - `quote_selection`
- 当前容器：
  - controller local state
- 判断：
  - 语义上已经是正式 `skill state`
  - 但物理上还是 `controller local`
  - 后续如果要跨页面使用，应该上移

### 4.4 `regeneratingCardIndex`

- 所属 skill：
  - `knowledge_card_generation`
- 作用：
  - 单卡重生成时的运行中标记
- 判断：
  - 这是 `ephemeral task state`
  - 合理留在 controller

### 4.5 `replaceTargetCardIndex`

- 所属层级：
  - 图片替换交互
- 判断：
  - 纯交互态
  - 不需要上移

### 4.6 `editingCardIndex / editingCardTitle / editingCardSummary`

- 所属 skill：
  - `knowledge_card_generation`
- 更准确地说：
  - 是知识卡编辑对话框的 UI 草稿态
- 判断：
  - 这是 `draft editing state`
  - 不应进入共享状态

### 4.7 `plannedCards / plannedQuotes / plannedInlineImages`

- 来源：
  - `planningState` 派生
- 所属 skill：
  - `content_planning`
- 判断：
  - 这些不是独立状态，而是 controller 为 UI 做的读取投影

### 4.8 `knowledgeGeneration / quoteGeneration / coverGeneration / inlineGeneration`

- 来源：
  - `generationRecords`
- 所属 skill：
  - 四类生成 skill
- 判断：
  - 这些是“从总结果池中切片出来的 skill 视图”
  - 当前很实用，但未来最好变成显式 result selector（结果选择器）

### 4.9 `knowledgeImagesByCard`

- 所属 skill：
  - `knowledge_card_generation`
- 作用：
  - 按卡片索引建立绑定查询
- 判断：
  - 是当前绑定链的运行时索引
  - 很重要，但目前只存在于 controller 派生层

### 4.10 `statusState`

- 来源：
  - `workbenchState.taskState.lastError ?? statusMessage`
- 所属层级：
  - 工作台统一状态展示
- 判断：
  - 这已经是 `orchestration feedback state`
  - 是 V2.6 最关键的整合成果之一

## 7. 按 Skill 反向归类

这部分把“状态容器”翻译回“skill ownership”。

### 7.1 `article_ingest`

当前状态：

- `currentArticle`：shared
- `importedMarkdownMeta`：shared / `workbenchState`
- `inputMode`：page local

判断：

- 主输入已经共享化
- UI 模式还是局部态
- 这层状态结构基本合理

### 7.2 `article_structuring`

当前状态：

- `currentArticleBlocks`：shared derived
- `currentArticleMeta`：shared derived

判断：

- 已经有最小可用的统一出口
- 但还没有显式 `state object`

### 7.3 `content_planning`

当前状态：

- `planningState`：shared
- `splitStrategy / minCards / maxCards`：controller local
- `replanRevision`：shared / `workbenchState`
- `taskState.phase=planning`：shared / `workbenchState`

判断：

- 这个 skill 已经跨过“页面按钮”阶段，进入正式系统态
- 但输入参数和输出结果还分散在两个容器里

### 7.4 `quote_selection`

当前状态：

- `selectedQuotes`：controller local
- `planningState.candidateQuotes`：shared

判断：

- 语义上是 skill
- 存储上还偏工作台私有

### 7.5 `knowledge_card_generation`

当前状态：

- `generationRecords[xhs_card]`：shared
- `knowledgeImagesByCard`：controller derived
- `knowledgeCardStatuses`：shared / `workbenchState`
- `knowledgeCardHistories`：shared / `workbenchState`
- `lockedKnowledgeCardIndexes`：shared / `workbenchState`
- `regeneratingCardIndex`：controller local
- `editing*`：controller local

判断：

- 这是当前状态最丰富、最接近“正式 skill 模块”的一条链
- 后面完全可以独立长成 `knowledgeCardGenerationState`

### 7.6 `quote_card_generation`

当前状态：

- `generationRecords[quote]`：shared
- `quoteGenerationSelection`：shared / `workbenchState`
- `selectedQuotes`：controller local

判断：

- 主绑定已建立
- 还缺的是把“当前选择”和“最后一次生成结果”拆得更显式

### 7.7 `cover_generation`

当前状态：

- `generationRecords[wx_cover]`：shared
- `openCovers`：page local

判断：

- 只有结果池，没有显式“当前选中封面状态”
- 这就是 V2.7 应优先补的一项

### 7.8 `inline_illustration_generation`

当前状态：

- `generationRecords[wx_inline]`：shared
- `plannedInlineImages`：planning derived
- `openIllus`：page local

判断：

- 已有结果和规划
- 但缺稳定的 `section binding`
- 这是下一刀最值得做的点

### 7.9 `theme_mounting`

当前状态：

- 工作台里主要还是摘要展示
- 排版页里有页面自管的 `themeName / activeThemeId`

判断：

- 这是当前最明显“文档上是 skill，代码里还不是”的地方之一

### 7.10 `wechat_layout_rendering`

当前状态：

- `currentArticleBlocks`：shared input
- 页面本地 `statusMessage / isPasting / isCopying`
- 仍然主要由排版页自己维护

判断：

- 这是一个已经存在的能力
- 但仍然没有统一成明确的 `layoutRenderingState`

## 8. 当前状态结构的结论

### 8.1 已经比较像正式 skill state 的部分

1. `currentArticle`
2. `planningState`
3. `generationRecords`
4. `workbenchState.taskState`
5. `knowledgeCardStatuses / Histories`
6. `quoteGenerationSelection`

### 8.2 还停留在页面局部态的部分

1. `selectedQuotes`
2. `splitStrategy / minCards / maxCards`
3. `themeName / activeThemeId`
4. `general-image` 页的整套参数态
5. 工作台的开合态和输入模式态

### 8.3 明确不需要升级成 shared skill state 的部分

1. `openCovers / openIllus / openQuotes`
2. `inputMode`
3. `replaceTargetCardIndex`
4. `editingCardIndex / editingCardTitle / editingCardSummary`
5. `isPasting / isCopying`

这些都属于 UI 交互态，应该继续留在页面或 controller 层。

## 9. V2.7 建议迁移顺序

如果按“先稳状态，再做能力”的原则，建议这样迁：

### 第一步

先不动大结构，只补 `inline_illustration_generation` 的绑定态：

- 新增 `section` 级标识
- 让配图结果不再只靠数组顺序对应

### 第二步

补 `cover_generation` 的选中态：

- 当前封面候选 id
- 当前封面与排版页之间的消费关系

### 第三步

把 `selectedQuotes` 从 controller local 提升为更正式的共享态，前提是它开始被工作台以外的页面消费。

### 第四步

把 `theme_mounting` 从页面散态收成一个正式共享状态对象。

## 10. 一句话总结

当前代码已经有一部分真正的 `skill state`，尤其是：

- `content_planning`
- `knowledge_card_generation`
- 工作台统一任务状态

但还有两类状态没有彻底收口：

1. 仍然只是页面私有的“选择 / 配置 / 展开”状态
2. 文档上已经算 `skill`，代码里还停留在某个页面自己管理的实现

V2.7 的重点不是再加页面，而是继续把这两类状态往 `skill ownership` 上收。
