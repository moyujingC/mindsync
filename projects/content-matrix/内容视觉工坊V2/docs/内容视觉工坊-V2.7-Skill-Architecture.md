# 内容视觉工坊 V2.7 Skill Architecture

## 1. 文档目的

这份文档不描述页面长什么样，而描述产品真正的能力结构。

目标有三个：

1. 明确产品由哪些 `skill` 组成
2. 明确每个 `skill` 的输入、输出、状态和依赖
3. 明确页面只是 `skill` 的承载层，而不是产品本体

适用范围：

- 工作台
- 公众号排版页
- 风格资产页
- 通用出图页
- 同步记录页

## 2. 产品定义

内容视觉工坊不是“一个带多个页面的内容工具”，而是：

`一套面向中文内容创作者的内容拆解、视觉生成与分发编排系统`

它服务的是一条内容生产链：

- 导入文章
- 理解结构
- 拆解观点
- 提炼金句
- 生成知识卡
- 生成配图
- 生成封面
- 渲染排版
- 导出分发

## 4. 通用状态机

所有异步或半异步 `skill` 默认收敛到同一套状态：

- `idle`：尚未具备输入
- `ready`：输入已齐，可以执行
- `running`：执行中
- `partial`：部分成功，结果未完整
- `success`：本轮完成
- `failed`：本轮失败
- `stale`：结果仍存在，但已和当前输入不完全一致

说明：

- `stale` 不是失败
- `stale` 表示“结果可见，但不能默认视为当前有效结果”

## 5. Skill Registry

### 5.1 `article_ingest`

- 目标：把原始文章稳定导入系统
- 输入：标题、正文、Markdown 文件
- 输出：`currentArticle`
- 上游：无
- 下游：
  - `article_structuring`
  - `content_planning`
  - `wechat_layout_rendering`
- 状态：
  - `idle -> ready -> running -> success / failed`
- `stale` 条件：无
- 当前实现：
  - 粘贴正文
  - Markdown 导入
  - 标题提取

### 5.2 `article_structuring`

- 目标：把正文转成结构化内容块
- 输入：`currentArticle.body`
- 输出：`ArticleBlock[]`
- 上游：`article_ingest`
- 下游：
  - `wechat_layout_rendering`
- 状态：
  - `idle -> ready -> running -> success / failed / stale`
- `stale` 条件：
  - 文章正文变化
- 当前实现：
  - 轻量段落 / 引用 / 小节 / 图片占位解析

### 5.3 `content_planning`

- 目标：理解文章并产出拆解规划
- 输入：
  - 文章标题
  - 正文
  - 拆卡策略
  - 张数范围
- 输出：
  - `cardPlan`
  - `candidateQuotes`
  - `inlineImagePlan`
  - `coverTheme`
  - `planningRevision`
- 上游：
  - `article_ingest`
- 下游：
  - `quote_selection`
  - `knowledge_card_generation`
  - `cover_generation`
  - `inline_illustration_generation`
- 状态：
  - `idle -> ready -> running -> success / failed / stale`
- `stale` 条件：
  - 标题变化
  - 正文变化
  - 拆卡策略变化
  - 张数范围变化
- 当前实现：
  - 工作台重新拆解
  - 自动拆卡
  - 候选金句
  - 配图建议
  - 封面主题

### 5.4 `quote_selection`

- 目标：从候选金句中选出传播候选
- 输入：`candidateQuotes`
- 输出：`selectedQuotes`
- 上游：
  - `content_planning`
- 下游：
  - `quote_card_generation`
- 状态：
  - `idle -> ready -> success / stale`
- `stale` 条件：
  - `planningRevision` 变化
  - 新候选中无法匹配旧选项
- 当前实现：
  - 勾选
  - 重拆解后的文本匹配保留

### 5.5 `knowledge_card_generation`

- 目标：为每张知识卡生成对应图片
- 输入：
  - `cardPlan[i]`
  - 风格
  - 尺寸预设
- 输出：
  - 卡片级图片结果
  - 卡片级绑定关系
- 上游：
  - `content_planning`
  - `theme_mounting`
- 下游：
  - `distribution_packaging`
- 状态：
  - `idle -> ready -> running -> partial -> success / failed / stale`
- `stale` 条件：
  - 卡片标题变化
  - 卡片摘要变化
  - `planningRevision` 变化
  - 风格变化
- 当前实现：
  - 按卡单独生成
  - 单卡重生成
  - 替换
  - 回退
  - 标记需重生成

### 5.6 `quote_card_generation`

- 目标：把已选金句转成金句卡
- 输入：
  - `selectedQuotes`
  - 风格
  - 尺寸预设
- 输出：
  - 金句卡图片结果
  - 绑定到的金句文本与索引
- 上游：
  - `quote_selection`
  - `theme_mounting`
- 下游：
  - `distribution_packaging`
- 状态：
  - `idle -> ready -> running -> success / failed / stale`
- `stale` 条件：
  - 选中金句变化
  - `planningRevision` 变化
  - 风格变化
- 当前实现：
  - 真生成
  - 结果绑定
  - 旧结果提示

### 5.7 `cover_generation`

- 目标：生成公众号封面候选
- 输入：

- 输出：

- 状态：

- `stale` 条件：

  - `coverTheme` 变化

### 5.8 `inline_illustration_generation`

### 5.9 `theme_mounting`

- 目标：为当前任务挂载排版和出图风格
- 输入：

  - 卡片模板

- 下游：

  - `quote_card_generation`
  - `cover_generation`
  - `inline_illustration_generation`

- 状态：
  - `idle -> ready -> success / stale`
- `stale` 条件：

### 5.10 `wechat_layout_rendering`

- 目标：将文章和结果渲染成公众号预览与 HTML
- 输入：
  - `ArticleBlock[]`
  - 排版主题
  - 已生成图片结果
- 输出：

  - `article_structuring`

  - `wechat_layout_rendering`

  - `idle -> ready -> running -> success / failed`

### 5.12 `activity_logging`

- 目标：记录关键动作和结果
- 输入：
  - 生成
  - 保存
  - 切换
  - 复制
  - 失败
- 输出：
  - 日志时间线
- 上游：所有主 `skill`
- 下游：无
- 状态：
  - 事件流，不单独走任务状态机

## 7. 状态建模原则

后续状态不要优先按页面组织：

- 不建议：
  - `workbenchPageState`
  - `wechatPageState`
  - `imagePageState`

- 建议：
  - `planningState`
  - `quoteSelectionState`
  - `knowledgeCardGenerationState`
  - `quoteCardGenerationState`
  - `inlineIllustrationGenerationState`
  - `layoutRenderingState`

原则：

1. 页面只消费状态
2. `skill` 才拥有状态
3. 页面跳转不能改变 `skill` 所有权
4. `stale` 必须是一等状态，不能靠文案硬解释

## 9. 评审问题

每次新增功能前，先回答这 5 个问题：

1. 这是新增 `skill`，还是已有 `skill` 的扩展？
2. 这个 `skill` 的输入和输出是什么？
3. 它的 owner 页面是谁？
4. 它的 `stale` 条件是什么？
5. 它是否需要单独状态，而不是塞进某个页面状态里？

## 10. 一句话结论

内容视觉工坊后续迭代，不再以“再做一个页面”为核心单位，而以“增强一个 skill”作为核心单位。
