# 内容方法验证实验闭环规格

## 1. 目的

验证台除了验证采集链路，还要验证一套内容方法是否有效：基于证据筛选、研究和选题转译的内容，是否比凭个人表达欲决定的内容，更接近预设的传播或业务目标。

这不是自动判定内容好坏，也不承诺某篇内容一定带来咨询。系统只记录可比较事实，并要求人工解释下一轮怎么调整。

```text
外部内容证据
-> 人工选择选题来源与假设
-> 成稿、发布
-> 人工填写同一观察窗口的数据与有效反馈
-> 比较不同选题来源和表达方式
-> 决定下一轮研究或选题规则
```

## 2. 数据边界

- `内容更新`：外部内容证据、互动和评分，不记录自己的发布结果。
- `内容实验与反馈`：自己的每次待发布或已发布内容，一篇内容一行。
- 飞书填写发布后的真实数据；不要求或假定平台开放浏览、私信或成交数据接口。
- 有效咨询、资料索取和代表性反馈只能由人工确认填写；系统不从点赞数推断。
- 不同平台、不同发布时间窗口的数据不能直接比较绝对值，先按同平台、同内容形态、相近观察周期查看。

## 3. 最小字段合同

| 字段 | 填写方 | 说明 |
| --- | --- | --- |
| 实验ID | 系统 | 稳定去重键；人工不修改。 |
| 选题标题、账号、内容形态 | 人工 | 发布前建立实验时填写。 |
| 选题来源 | 人工 | 自发表达、爆款结构、用户需求、课题研究或混合。 |
| 选题假设、来源证据 | 人工 | 说明为什么写、参考了哪些内容或洞察。 |
| 目标动作 | 人工 | 本篇优先追求关注、收藏、私信、资料索取或咨询中的一个。 |
| 发布平台、发布链接、发布时间、观察截至 | 人工 | 发布后填写；观察截至应与同组内容保持可比窗口。 |
| 曝光/播放、点赞、收藏、评论、转发、私信 | 人工 | 平台可见的累计事实；没有数据留空，不填零。 |
| 有效反馈、有效咨询 | 人工 | 仅填写可复查的人工事实计数。 |
| 人工结论、下一轮调整 | 人工 | 待观察、保留、调整或无效；写明调整方向。 |

## 4. 使用节奏

1. 写作前创建一行，先明确选题来源、假设和目标动作。
2. 发布后补链接和发布时间。
3. 到预先约定的观察截至时间，再补齐数据与有效反馈。
4. 同一批至少积累 5 篇、且观察窗口接近的内容后，再比较选题来源；不足时只看个案，不形成规则。
5. 每次复盘只修改一个主要变量，例如选题来源、表达角度或 CTA（行动引导），避免无法解释差异。

## 5. 通过标准

- 每条实验可关联其选题假设和来源证据。
- 发布事实与结果由人工回写，不依赖未验证的平台接口。
- 表格可筛选“待发布”“已发布待复盘”和不同选题来源。
- 复盘结论能明确区分事实、解释和下一轮假设。
