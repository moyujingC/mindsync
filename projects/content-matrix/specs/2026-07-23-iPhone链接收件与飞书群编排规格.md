# iPhone 链接收件与飞书群编排规格

## 1. 目标

把手机或飞书网页中随机发现的一条公开内容，可靠地送进现有内容研究流程：

```text
在内容 App 复制链接
-> iPhone 背板双击运行快捷指令 或 飞书网页手工粘贴
-> HTTPS 收件接口 或 Worker 扫描飞书手工行
-> 本地持久队列 + 飞书“链接收件箱”原行
-> Worker（后台处理器）采集内容与评论
-> 研究简报、本地证据与飞书台账
-> 人工确认后再提纯、成稿或发布
```

iPhone 的背板双击不能读取其他 App 当前页面的 URL。因此用户必须先使用内容 App 的“复制链接”，快捷指令再读取剪贴板。

## 2. 范围与边界

首期支持小红书、抖音、公众号、视频号的公开内容链接及其官方短链。服务使用既有短链安全解析、TikHub 采集、飞书内容/评论表、研究请求和本地研究简报。

飞书群用于收件回执和处理结果提示；它不是唯一队列。每一条链接必须先落到本地持久队列和飞书“链接收件箱”，即使第三方采集失败也能查询和重试。飞书网页手工新增行时，只填“原始链接”并留空“收件ID”；Worker 会将该行转入本地队列，并持续回写同一行。

首期不自动下载平台媒体、转写视频或发布内容。现有媒体提纯 Workflow 只处理合法取得的本地音频、视频、字幕或逐字稿；收件 Worker 生成的研究简报保持“待人工确认”。人工确认后，可将视频文件或字幕交给 `media:process`，再进入编辑交接与成稿流程。

## 3. 收件合同

```http
POST /v1/inbox/links
Authorization: Bearer <INBOX_RECEIVER_TOKEN>
Content-Type: application/json

{
  "url": "https://...",
  "source": "iphone-back-tap",
  "mode": "collect"
}
```

接口只接受四个平台的 HTTP/HTTPS 链接。短链最多跟随 5 次跳转，且每一步都限制为受支持的公共平台域名；不访问内网地址或任意第三方跳转目标。

成功时返回 `202 Accepted` 和收件 ID。重复粘贴同一原始或最终链接时，返回既有收件记录，不创建重复队列项。

## 4. 链接收件箱

飞书表和本地队列使用同一语义：

| 字段 | 说明 |
| --- | --- |
| 收件ID | 本地队列与飞书定位键 |
| 原始链接 | 手机剪贴板中的链接 |
| 最终链接 | 短链解析后的链接 |
| 平台 | 小红书、抖音、公众号、视频号 |
| 链接类型 | 内容、博主页或未识别 |
| 收件时间 | 接口接收时间 |
| 来源 | 例如 `iPhone背板双击` |
| 状态 | 待处理、处理中、已完成、失败、需人工处理 |
| 处理结果 | 研究请求 ID 或内容唯一键 |
| 重试次数 | Worker 尝试次数 |
| 错误摘要 | 可操作的简短失败原因，不保存响应正文 |

只允许“内容”链接进入自动详情采集。博主主页和未识别链接保留在收件箱，状态为“需人工处理”，避免误把账号页当作内容详情调用。

## 5. Worker 合同

Worker 每次只领取一条“待处理”记录，先改为“处理中”，再调用既有详情研究 Workflow：

```text
最终内容链接
-> TikHub 内容详情 + 一页评论
-> 内容更新 / 评论样本去重写入飞书
-> 本地研究请求台账与研究简报
-> 回写收件箱为“已完成”
```

任一步失败时，Worker 回写“失败”和错误摘要。失败记录可通过显式重试命令回到“待处理”；不做无限自动重试。收件记录、研究请求 ID、内容唯一键和简报路径形成可追溯链路。

## 6. 安全与运行

- `INBOX_RECEIVER_TOKEN` 只放服务器环境变量，不写入仓库、飞书字段或日志。
- 接口进行 Bearer Token（持有者令牌）校验、请求体大小限制和每分钟固定窗口限流。
- HTTP 服务只做接收和入队，返回前不调用 TikHub，避免手机快捷指令因慢请求失败。
- 部署必须使用有效 HTTPS 证书；不能把 Token 发送到 HTTP 地址。
- 飞书群机器人 Webhook（回调地址）是可选通知适配器。无 Webhook 时，收件、采集和归档仍可正常运行。

## 7. 验收

1. 有效 Bearer Token + 四平台内容链接返回 `202`，本地队列生成一条待处理记录。
2. 无 Token、错误 Token、超限请求、非平台链接和超大请求体被拒绝，且不写队列。
3. 已知短链解析后写入最终链接；重复提交不新增记录。
4. Worker 对内容链接调用现有研究 Workflow，回写研究请求 ID 与完成状态。
5. 博主页链接不调用 TikHub，进入“需人工处理”。
6. Worker 失败时可查询错误并显式重试；完整自动化测试持续通过。
7. iPhone 快捷指令和服务器环境变量在部署说明中可复现配置。
