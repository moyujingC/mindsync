## 1. 试点要解决的问题

墨予镜已经有选题、草稿、成稿、编辑 Skill（技能）、排版 Skill 和发布回流表，但“选题到真实发布再到回流”的连续动作还没有稳定跑通。当前要验证的不是更多工具，而是一组受控 Agent 是否能让这条公众号生产链更容易持续使用。

试点选择 `墨予镜公众号内容生产` 作为唯一业务对象。小红书可在公众号主文完成后人工复用，不纳入首轮 Agent 主链。

## 2. 成功定义

完成一篇公众号内容的最小闭环：

```text
已确认的主题/证据
-> Agent 生成观点访谈与待确认结构
-> 本人补充或确认观点
-> Agent 协助编辑为成稿
-> 人工质量门
-> 排版为公众号草稿
-> 人工检查并手动发布
-> 当天写入发布回流表
```

这里的“智能体组织起来”指各 Agent 的输入、输出和交接规则能被看见、复跑和人工接管；不等于让它们自行发文或自行决定个人观点。

## 3. 固定分工

| 组件 | 试点职责 | 不负责 |
| --- | --- | --- |
| Codex | 搭建项目文件、维护脚本、运行测试、协助迭代 | 代替本人确定第一人称立场或自动发布 |
| Hermes Agent | 后续承接长期会话、受控 Skill 调用和任务编排 | 自主使用终端/浏览器/飞书写入；未确认的外部动作 |
| 飞书 CLI | 后续连接任务状态、发布台账与协作页面 | 保存第二份内容库、自动发送消息或发布 |
| 本人 | 补充观点、确认成稿、发布、填写真实反馈 | 交出个人表达或商业判断的最终决定权 |
| 本地 Markdown | 草稿、成稿、证据和交付物的权威库 | 替代飞书的日常协作视图 |

## 4. 全程边界

- 第一人称内容遵守“先主题和观点卡，再由本人确认”的规则；项目材料不能直接改写成个人立场。
- 不自动发布公众号，不自动发送飞书消息，不自动私信、报价或预约。
- 不向 Hermes、飞书或日志传入客户资料、联系方式、完整私信、模型 Key、飞书 App Secret（应用密钥）或公众号密钥。
- 第一轮不新建采集/情报工具；只使用已有的内容材料和既有编辑、排版能力。
- Hermes 仅可使用独立的无工具/只读 profile（配置档）；不能复用可执行终端、浏览器或文件写入的日常 profile。
- 飞书接入从模拟任务表的只读操作开始。写回必须单独过质量门并由本人确认。

## 5. 关卡路线

| 关卡 | 目标 | 必须产物 | 通过条件 |
| --- | --- | --- | --- |
| 0 | 看懂全貌、安装最小工具 | 开工检查表 | Codex、Hermes、飞书 CLI 可检查；数据边界、唯一试点文章、人工动作明确 |
| 1 | 跑通最小 Demo | 运行记录与边界说明 | 单一 Agent 能把脱敏主题输入变成“观点问题 + 待确认结构”，不外部写入 |
| 2 | 选岗位、定边界 | Agent 岗位卡 | 每个 Agent 有唯一职责、允许输入/输出和禁止动作 |
| 3 | 拆流程、画工作流 | 流程卡与流程图 | 每个交接有明确 artifact（交付物）和人工质量门 |
| 4 | 写 Hermes Profile | Profile 与测试记录 | 无工具/只读 profile 在模拟输入上稳定遵守输出合同 |
| 5 | 接 Codex、飞书 CLI、生成页面 | 项目、飞书测试截图和链接 | 只读读取模拟任务，结果回到同一工作台；不产生第二份主库 |
| 6 | 测试、修订、说明与提交 | Agent 链接、截图、说明书 | 一次内容生产演练完整通过，风险和人工接管点写明 |
| 7（可选） | 判断上下游连接 | 关系判断结果 | 只连接已手动跑通且确有重复交接的节点 |
| 8（可选） | 连接两个 Agent | 接力记录与交接规则 | 能完成一次可回放交接；失败时可人工接管 |
| 9（可选） | 服务化评估 | 企业 AI 服务方案 | 基于真实运行证据，不把内部试点包装成客户案例 |

关卡 1-6 必须按顺序通过；第 7-9 只在前一关有真实运行记录时开始。

## 6. 关卡 0 的范围

### 要完成

1. 确认唯一试点链：以“企业上 AI，先别急着选工具”或下一篇已确认主题为样本，从观点卡到人工发布回流走一遍。
2. 安装并检查 Codex、Hermes、飞书 CLI；不在仓库保存任何凭证。
3. 确认本地 Markdown、飞书工作台、Hermes、Codex 的职责边界。
4. 建立下一关最小 Demo 的输入和预期输出合同。

### 不完成

- 不在关卡 0 建多个 Agent。
- 不接真实飞书表、真实公众号草稿箱或真实模型 API。
- 不改变已有发布脚本或内容生产系统。
- 不因“未来需要协作”预先搭建任务队列、记忆库或定时调度。

## 7. 关卡 1 的预设 Demo 合同

输入是一份不含个人敏感信息的主题卡：读者、已确认的证据/判断、目标动作、不可说边界。输出只能是：

1. 5-7 个需要本人回答的观点问题；
2. 一份待确认文章结构；
3. “证据 / 本人待补充 / 不可直接写”三栏；
4. 不超过 3 个可能的标题方向。

Demo 不能直接输出第一人称成稿，也不能调用飞书、公众号或浏览器写入操作。

## 8. 验收与下一棒

关卡 0 通过后，交给 Engineer / Content Lead 进入关卡 1。若 Hermes 或飞书 CLI 无法安装、模型凭证尚未决定，仍可用 Codex 与本地 Markdown 演练 Demo；但该状态必须写为“本地演练”，不能写为“Hermes + 飞书已接入”。
