# 内容视觉工坊 A+B 产品定义

## 1. 任务级别

- 类型：执行落地
- 范围：局部实验，但会进入正式开发
- 目标：把“文章成稿 -> 配图生成 -> 公众号草稿”收束成第一版内部工具定义

## 2. 用户与场景

### 2.1 用户是谁

- 主用户：`墨予镜` 账号的内容创作者本人
- 次用户：后续可能扩展到其他账号运营者

### 2.2 用户当前卡在哪里

当前内容生产链路仍然是碎的：

1. 文章先在本地写完
2. 再手动整理知识卡片提示词
3. 再去文生图平台逐张出图
4. 再手动下载、筛图、上传到公众号
5. 再手工把正文排版到公众号编辑器

问题不在“不会生成提示词”，而在“从成稿到可发布草稿之间仍有大量重复搬运工作”。

## 3. 本轮要解决的问题

给一篇已经写好的公众号正式稿，系统应能完成两段闭环：

- A. 自动生成公众号可用的排版内容
- B. 自动把图文写入公众号草稿箱

这里的“自动生成”不只包含提示词，还包含直接调文生图 API 出图。

## 4. 本轮不做范围

本轮明确不做以下能力：

- 自动正式发布
- 自动群发
- 定时群发
- 多账号复杂权限系统
- 自由拖拽式富文本编辑器
- 小红书正文排版发布
- 高自由度设计画布

## 5. 产物定义

输入一篇公众号正式稿后，系统输出：

1. 知识卡片图片若干张
2. 公众号封面图 1 张
3. 小红书封面图 1 张
4. 公众号正文排版结果 1 份
5. 公众号草稿箱中的图文草稿 1 篇

## 6. 第一版核心能力

### 6.1 文章输入

支持输入：

- 公众号账号
- 文章标题
- 正文内容
- 图片风格预设
- 品牌主色
- 是否生成知识卡片
- 是否生成公众号封面
- 是否生成小红书封面

### 6.2 内容拆解

系统需先把文章拆成三类中间结果：

- 卡片拆分结果
- 封面图描述结果
- 公众号正文排版结构

这里建议系统内部维护结构化结果，而不是只保留自然语言提示词。

### 6.3 图片生成

系统直接调用文生图 API 生成：

- 知识卡片
- 公众号封面
- 小红书封面

且支持：

- 单张重生成
- 保留本轮生成记录
- 用户手动替换某张图片

### 6.4 公众号排版

系统生成一份兼容公众号编辑器的受控排版结果。

第一版仅支持这些内容块：

- 标题
- 引言
- 小标题
- 正文段落
- 强调句
- 引用块
- 列表
- 分隔块
- 图片块
- 结尾 CTA

### 6.5 草稿同步

系统完成以下动作：

1. 上传正文内用到的图片
2. 上传封面图或摘要封面所需素材
3. 组装公众号图文内容
4. 写入公众号草稿箱
5. 返回草稿创建结果和可追踪状态

## 7. 推荐工作流

1. 用户粘贴正式稿
2. 系统分析文章结构
3. 系统生成卡片方案和封面方案
4. 系统调用图片 API 出图
5. 系统生成公众号排版结构
6. 用户局部重生成或替换图片
7. 用户点击“同步到公众号草稿”
8. 系统上传素材并创建草稿

## 8. UI 信息架构

推荐采用三栏工作台：

### 左栏：文章输入

- 账号选择
- 标题
- 正文
- 风格选择
- 生成选项

### 中栏：生成结果

- 卡片拆解列表
- 封面方案
- 图片缩略图
- 单张重生成操作

### 右栏：排版与草稿

- 公众号排版预览
- 素材上传状态
- 草稿同步状态
- 打开草稿入口

## 9. 方案取舍

### 9.1 为什么不继续做“提示词工具”

只输出提示词，无法消除文生图、下载、上传、排版这些重复操作。对当前用户来说，提示词已经不是主要瓶颈。

### 9.2 为什么先做“草稿箱”而不是“发布”

草稿箱已经能完成大部分效率价值，同时能保留最后一道人工确认，避免误发风险。

### 9.3 为什么不先做复杂 HTML 编辑器

公众号编辑器对样式支持有限。第一版更适合做受控模板，保证同步结果稳定。

## 10. 数据与接口边界

### 10.1 外部接口

- 文生图 API
- 微信公众号素材接口
- 微信公众号草稿箱接口

### 10.2 内部对象

第一版至少需要这几类结构化对象：

- `ArticleInput`
- `CardPlan`
- `CoverPlan`
- `GeneratedImage`
- `LayoutBlock`
- `WechatDraftPayload`

## 11. 风险点

### 11.1 图片风格稳定性

同一篇文章的多张卡片可能风格飘移，需要通过统一风格预设、配色、构图约束来收束。

### 11.2 公众号样式兼容性

本地排版预览与公众号后台实际表现可能有差异，因此必须把排版模板收窄。

### 11.3 草稿接口约束

公众号接口对素材格式、图文字段、摘要、封面等有固定要求，实现前要基于官方接口再次核对。

## 12. 第一版验收标准

满足以下条件即可视为第一版成立：

1. 输入一篇正式稿后，能自动生成至少 1 张知识卡片和 1 张封面图
2. 支持同一篇文章生成 1 篇公众号排版结果
3. 支持把图片和正文写入公众号草稿箱
4. 用户能单独重生成某张图片
5. 用户能看到草稿同步成功或失败的明确状态
