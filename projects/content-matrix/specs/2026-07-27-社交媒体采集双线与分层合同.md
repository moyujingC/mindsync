# 社交媒体采集双线与分层合同

## 1. 目的

采集分为两条独立工作流：`账号追踪` 和 `单条链接采集`。两者不共享触发语义、默认范围或完成条件。

```text
账号追踪：确认追踪对象 -> 定时检查 -> 发现新增内容 -> 一级采集入库
单条链接：发送一个内容链接 -> 按层采集该内容 -> 返回本次采集结果
```

单条内容不是默认研究对象。采集只产生可追溯的社交媒体证据；评论分析、课题研究、选题和需求发现必须另行发起。

## 2. 工作流一：账号追踪

账号追踪用于持续观察一个明确的博主主页。首次建立追踪时，先执行一次有边界的历史回溯，随后才进入定时新增检查。入口是飞书聊天“追踪这个博主 + 主页链接”，由 Hermes 补问主题、目标需求库、回溯范围和检查频率，用户确认后才写入“博主账号”。

```text
飞书聊天主页链接
-> 解析平台和账号 ID
-> 补充主题、需求库、回溯范围、频率
-> 用户确认
-> 创建或更新同一条博主追踪记录
-> 历史回溯 Worker 按发布时间收集近 2 或 3 个月内容的 L1 样本池
-> 人工筛选少数内容进入 L2 或 L3
-> Creator Worker 按频率检查新增内容并执行 L1
```

- 追踪 Worker 只检查已确认、启用且有主题路由的账号。
- 历史回溯与每日追踪默认只执行 L1；二级提纯和三级评论由人工从内容样本池中选择，或由明确任务启用。
- 单条内容链接不能自动升级为追踪账号；用户必须明确说“追踪”。
- 飞书 `record_id` 是手工建档账号的回写身份。短链解析出的账号 ID 只能补全同一行。

### 2.1 历史回溯与人工挑选

首次回溯的默认范围为近 90 天；用户可明确选择近 60 天或按条数上限执行。范围以内容的`发布时间`判断，达到时间边界即停止分页，不因采集日期晚而纳入更早内容。

```text
已确认博主
-> 获取近 60 / 90 天内容列表
-> 每条仅执行 L1 并写入内容证据目录
-> 按发布时间、内容形式、互动快照筛选
-> 人工勾选“申请 L2”或“申请 L3”
-> 系统仅处理被选中的内容
```

这条链路允许在 L1 后结束。未被选中的内容仍是可查询证据，不代表采集不完整或等待自动分析。

## 3. 工作流二：单条链接采集

入口是 Hermes 聊天中粘贴一条公开内容链接；链接收件箱是异步备用入口。系统先解析并去重，再依次执行三个可独立完成的层级。

```text
内容链接
-> 链接解析与去重
-> L1 基本信息
-> L2 内容本体与文字稿
-> L3 评论与回复（仅明确要求时）
-> 回传每层状态、证据链接和失败原因
```

某层失败不回滚已成功的上一层。每层均记录“未请求 / 处理中 / 已完成 / 已降级 / 失败”，使人工可以只重试失败层，而不重复采集全部内容。

## 4. 单条链接三级采集

### L1：基本信息（必做）

目标是建立一条可定位、可去重的内容证据。

| 采集字段 | 说明 |
| --- | --- |
| 内容唯一键、平台、稳定内容 ID、原始链接与最终链接 | 用于去重和回查 |
| 标题、内容形式、作者显示名、发布时间 | 以平台详情返回为准 |
| 点赞、评论、收藏、转发/分享等互动快照 | 平台可获得则记录；记录采集时间 |
| 原始响应工件、TikHub 缓存地址、调用数 | 仅本地日志或工件；不写入飞书敏感字段 |

L1 写入“内容更新”证据目录。已存在内容仍允许刷新互动快照，但不新增内容行。

### L1 的互动快照

互动数据是随时间变化的累计值，不能直接覆盖后当作可比较的历史事实。每次 L1 成功时，除更新“内容更新”中的最新展示值外，还新增一条不可覆盖的互动快照。

| 字段 | 含义 |
| --- | --- |
| 内容唯一键 | 关联内容证据 |
| 发布时间 | 平台返回的内容发布时间 |
| 快照时间 | 本次实际采集互动数据的时间 |
| 点赞、评论、收藏、转发/分享 | 该快照时平台可见的累计数值 |
| 数据可用性 | 平台未返回的指标记为空，不能记为 0 后参与比较 |
| 采集批次 / 运行 ID | 用于追溯本次账号回溯或每日检查 |

`发布时间`回答“内容已经存在多久”，`快照时间`回答“这些互动数在什么时候被看到”，互动数据回答“截至该时点的累计表现”。三者缺一不可。

### L2：内容本体与文字稿（默认执行）

目标是交付人可阅读、可引用的内容文本，并保留来源和降级过程。

| 内容形式 | 顺序 | 交付 |
| --- | --- | --- |
| 纯文字 / 图文正文 | 提取平台正文、简介和可获得的图文描述；图片逐张 OCR（光学字符识别） | 原文片段 + 图片 OCR 文本 + 清理稿 |
| 图片 / 图文 | 下载可访问图片，按图片顺序 OCR；无法下载或识别时保留失败项 | 图片清单、每张 OCR 状态、合并清理稿 |
| 视频 | 优先读取平台提供的字幕或文字稿；无字幕时下载可访问视频、提取音频、ASR（自动语音识别）转写 | 原字幕 / 原始转写 / 清理稿 |
| 音频 | 下载可访问音频后 ASR 转写 | 原始转写 / 清理稿 |

清理稿写入“内容更新”原行的“文字稿”字段，供日常阅读；原字幕、原始转写和本地工件路径保留在服务器。清理稿不能覆盖原字幕或原始转写。

若平台未提供可下载媒体、无字幕且转写依赖不可用，则 L2 标为“已降级”或“失败”，并明确原因；L1 仍为成功。

### L3：评论与回复（按需）

默认不采集。只有以下任一条件成立时执行：

- 用户在聊天中明确说“采评论”“看评论”“评论挖需求”，或指定条数。
- 已确认的加工任务需要评论或回复作为证据。
- 将来的账号追踪规则明确要求评论采样，且人工已确认成本与用途。

| 范围 | 默认值 | 可扩展规则 |
| --- | --- | --- |
| 一级评论 | 请求时最多 20 条、1 页 | 用户显式指定上限和页数 |
| 二级回复 | 平台支持且任务需要时采 | 保留父评论 ID 与回复关系 |
| 评论字段 | 稳定评论 ID、内容唯一键、文本、时间、互动数据 | 不做用户画像、私信或自动需求结论 |

L3 写入“评论样本”证据目录。评论采集完成只表示获得样本，不能自动生成洞察、选题或需求结论。

## 5. 触发语法与回传

聊天入口的最小语法：

```text
<内容链接>
<内容链接> 采评论
<内容链接> 采评论 50 条
<内容链接> 只采基本信息
```

- 未附指令：执行 L1 + L2，不执行 L3。
- `只采基本信息`：仅执行 L1。
- `采评论`：执行 L1 + L2 + L3。
- 无法识别链接、主页链接或私密链接：停止并返回“需人工处理”；主页链接提示使用“追踪这个博主”。

聊天回执只包含标题、平台、内容形式、每层状态、内容证据定位信息、文字稿状态（如有）、评论数量（如有）和可操作的失败摘要。不得在聊天中粘贴全文文字稿或原始响应。

## 6. 飞书字段调整

先在新样本验证，再调整 schema（字段定义）与历史数据。

### 内容更新

新增或明确下列字段：

| 字段 | 含义 |
| --- | --- |
| 基本信息状态 | L1 状态 |
| 内容提纯状态 | L2 状态 |
| 评论采集状态 | L3 状态 |
| 文字稿来源 | 平台正文 / 图片 OCR / 平台字幕 / 语音转写 / 混合 |
| 文字稿 | 清理稿全文；原始工件留在本地 |
| 互动快照时间 | 本次指标采集时间 |
| 采集失败摘要 | 只记录可操作摘要，不含密钥或原始响应 |

### 新增：互动快照

“互动快照”单独建表，而不是在“内容更新”中只保留一个会被覆盖的数值。它是判断内容增长速度、不同发布时间样本是否可比较、以及爆款候选可信度的证据基础。

| 字段 | 含义 |
| --- | --- |
| 快照唯一键 | 内容唯一键 + 快照时间；不可手改 |
| 内容唯一键 | 关联内容更新 |
| 发布时间、快照时间、内容年龄（天） | 用于计算时间窗口 |
| 点赞、评论、收藏、转发/分享 | 本次累计互动值 |
| 采集批次、数据源 | 回查采集来源和运行记录 |

### 新增：内容加工请求

人工从 L1 样本池选择内容后，创建一条“内容加工请求”。它至少包含：内容唯一键、请求层级（L2 / L3）、用途、状态、请求时间和完成时间。该对象避免直接把所有 L1 内容升级到 L2 或 L3。

### 评论样本

新增或明确：`父评论唯一键`、`评论层级`、`回复对象`。它们用于恢复回复关系，不用于用户画像。

## 7. 验收标准

- 单条内容链接在未要求评论时，L1 和 L2 完成或明确降级，且不写入评论样本、不创建研究任务。
- 图文样本的正文和可访问图片 OCR 文本按顺序进入文字稿；单张图片失败不阻塞其余内容。
- 视频样本优先使用平台字幕；没有字幕时才尝试音频转写；原始文本和清理稿均可定位。
- 明确“采评论”后，评论与回复按平台能力入库并与内容唯一键关联；重复运行不重复写入。
- L2 或 L3 失败后可以单层重试；L1 已入库内容不重复新增。
- 账号追踪定时 Worker 不因本规格自动采集所有评论或转写所有历史视频。
- 首次回溯仅纳入发布时间在 60 / 90 天边界内的内容，且每条有 L1 与互动快照记录。
- 人工未选择的 L1 内容不会进入 L2 或 L3；选择后只处理指定内容。
- 同一内容多次采集保留多个互动快照，最新互动数可更新，但历史快照不可覆盖。

## 8. 实施顺序

1. 实现账号首次回溯：按发布时间窗口收集 L1，并创建不可覆盖的互动快照。
2. 实现人工选择的 L2 / L3 内容加工请求与单层重试。
3. 将单条链接默认编排改为 L1 + L2，移除默认评论和研究请求。
4. 接入图片 OCR；先使用本地可控 OCR Tool，缺失运行时要明确降级。
5. 将现有字幕优先 / ASR 转写结果的清理稿写入飞书内容原行。
6. 实现 Hermes 指令解析和回执卡片，再做一条真实平台链接验收。

## 9. 候选爆款判断

系统只能标记“候选爆款”，不能把互动指标直接解释为内容质量、商业价值或可复制结论。

### 9.1 先比较可比样本

同一账号内优先比较内容形式相同、发布时间相近的样本。至少按以下窗口分组：`0-7 天`、`8-30 天`、`31-90 天`、`90 天以上`。发布很久的内容因为累计时间长，不能与刚发布的内容直接按总点赞数比较。

### 9.2 两种信号

| 信号 | 计算 | 前提 |
| --- | --- | --- |
| 同龄表现 | 某条内容在相同内容年龄窗口内的互动指标，相对同账号中位数或分位数的表现 | 至少有 5 条可比 L1 样本 |
| 增长速度 | 两次快照间互动增量 / 间隔天数 | 同一内容至少有 2 次有效快照 |

互动指标不强行合成一个分数。平台缺失收藏、转发等字段时，只使用实际可得指标；不同平台不直接横向排名。

### 9.3 标记规则

- `候选爆款：同龄表现突出`：在可比样本中，至少一项主互动指标进入前 20%，且样本数达到最低要求。
- `候选爆款：仍在增长`：有两次以上快照，近期增长速度高于同龄样本；此标记优先用于新内容。
- `观察中`：样本不足、内容发布时间缺失、互动数据缺失或只采集过一次。
- `非结论`：候选爆款只决定是否值得人工打开、进入 L2 或做表达拆解，不自动生成选题或业务结论。

## 10. 双维度内容筛选评分

评分用于缩小人工阅读范围，不替代判断。每项评分都必须显示样本数、使用的互动指标和缺失指标；样本不足时返回“观察中”，而不是伪造精确分数。

### 10.1 维度一：选题爆发分

**回答的问题**：这个主题或表达角度，是否值得进入“爆款选题库”做进一步研究？

这是 L1 分数，范围 `0-100`。只在同一账号、相同内容形式、相近内容年龄窗口内比较，避免把长期累计互动误判为爆发。

| 信号 | 建议权重 | 含义 |
| --- | --- | --- |
| 可比样本的互动表现 | 60% | 点赞、评论、收藏、转发/分享的相对分位；只使用平台实际提供的指标 |
| 近期增长速度 | 25% | 多次互动快照中的每日增量；只有至少两次快照才计入 |
| 讨论强度 | 15% | 评论数相对同龄样本的表现；表示有讨论，不等于认可或购买意愿 |

决策建议：`80-100` 进入“爆款选题库候选”；`60-79` 人工快速查看标题、形式与评论；低于 `60` 默认保留 L1，不进入选题研究。阈值在积累一个账号至少 20 条样本后再校准。

### 10.2 维度二：干货信号分与干货研究分

**回答的问题**：这条内容是否值得进入 L2，被认真拆解其内容结构、案例、步骤和表达方式？

在 L1 阶段，互动只能给出 `干货信号分`，范围 `0-100`：

| 信号 | 建议权重 | 解释 |
| --- | --- | --- |
| 收藏 / 保存相对表现 | 45% | 用户可能认为内容值得回看；平台无此指标时不以点赞替代 |
| 转发 / 分享相对表现 | 25% | 用户可能认为内容值得带走或转给他人 |
| 高质量讨论信号 | 20% | 评论中出现具体追问、补充、求模板等；需要 L3 样本才可用 |
| 内容完整度代理 | 10% | L1 可见的正文长度、图文页数、视频时长等，仅作弱信号 |

`干货信号分`不等于“内容够干货”。它达到 `70` 时，系统建议“申请 L2”，由你决定是否采集全文、OCR 或文字稿。

完成 L2 后，用 `干货研究分`替代干货信号分，范围同为 `0-100`，由人工或 Agent 按可解释的内容证据评分：

| L2 评分项 | 权重 | 判断标准 |
| --- | --- | --- |
| 具体问题与适用场景 | 25% | 是否说清“谁在什么情况下遇到什么问题” |
| 方法、步骤或案例证据 | 35% | 是否提供可复查的做法、过程、案例或反例 |
| 可复用性 | 25% | 是否能提炼出结构、清单、框架或可测试假设 |
| 表达与信息密度 | 15% | 是否清楚、紧凑，关键条件和边界是否缺失 |

`干货研究分 >= 75` 才进入“内容拆解库候选”。它仍不表示观点正确、方法适合所有人，或可直接复制到墨予镜。

### 10.3 两个分数的协同

| 组合 | 人工动作 |
| --- | --- |
| 高选题爆发分 + 低干货信号分 | 放入爆款选题库候选，研究标题、情绪、表达角度与传播机制；不默认做 L2 |
| 低选题爆发分 + 高干货信号分 | 优先申请 L2，进入内容拆解库候选；适合研究方法、案例和交付细节 |
| 两者都高 | 优先 L2，之后分别进入爆款选题与内容拆解两个候选库 |
| 两者都低或观察中 | 保留 L1 证据；不消耗 L2 / L3 成本 |

评分记录必须保留版本、样本范围、快照截止时间和计算依据。以后根据你实际挑选、发布和复盘的反馈再调整权重，不能用预设分数假装已经验证。
