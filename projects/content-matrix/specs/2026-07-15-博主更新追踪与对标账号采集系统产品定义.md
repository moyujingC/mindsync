# 博主更新追踪与对标账号采集系统产品定义

## 1. 目标

建设一个服务 `内容矩阵` 的内容情报系统。

系统维护一批关注博主，每天定时检查这些博主在抖音、小红书、B站是否发布新内容。发现更新后，采集内容元数据、互动数据和可分析文本，写入飞书多维表格，供选题、账号研究、市场需求分析和评论区需求归纳使用。

系统还支持对一个对标账号做批量回溯采集，用于分析账号定位、选题结构、内容表现和评论区需求。

## 2. 用户与使用场景

### 2.1 使用者

- `内容矩阵` 负责人
- `墨予镜` / `一镜一梳` 等账号运营者
- 后续参与内容调研、市场需求研究和选题共创的 Agent

### 2.2 场景 A：每日博主更新追踪

用户在飞书多维表格中维护关注博主清单。

系统每天定时遍历：

1. 读取启用状态的博主
2. 按平台查询最近内容
3. 判断是否有新发布
4. 新内容入库
5. 更新博主最近检查状态
6. 对高价值内容生成待分析任务

### 2.3 场景 B：对标账号批量采集

用户指定一个账号，系统批量采集该账号历史内容。

第一版优先支持：

- 最近 N 条内容
- 指定时间窗口
- 指定平台账号主页链接或账号 ID

采集结果用于回答：

- 这个账号稳定在讲什么主题
- 哪类选题表现最好
- 评论区有哪些重复问题、需求、抱怨和购买意图
- 哪些选题可以转译到 `墨予镜`、`一镜一梳` 或 `知行AI服务`

## 3. 支持平台

第一版平台范围：

- 抖音
- 小红书
- B站

平台能力不承诺完全一致。每个平台先分成三级能力：

| 能力级别 | 含义 |
| --- | --- |
| L1 元数据 | 内容 ID、标题、链接、发布时间、封面、作者、互动数 |
| L2 正文文本 | 标题、简介、字幕、文案、标签等可分析文本 |
| L3 评论区 | 评论文本、点赞数、回复数、时间、用户昵称或脱敏用户标识 |

第一版验收以 `L1 + 可获得的 L2` 为主。评论区采集作为可插拔能力，必须单独记录来源、权限、频率和失败原因。

## 4. 主库与飞书边界

本系统采用：

- 飞书多维表格：运营主界面和轻量台账主库
- 本地 Markdown：系统设计、表结构说明、采集策略、分析方法和交付记录主库
- 本地运行脚本或服务：采集、去重、同步和分析执行层

飞书适合作为本系统的日常工作台，因为用户需要手工增删博主、筛选内容、标记分析状态和查看结果。

本地仓库保留正式规则和可复用方法，避免采集逻辑、表结构和分析口径只散落在飞书里。

## 5. 飞书多维表格建议结构

### 5.1 表一：博主账号

用途：维护关注对象。

建议字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 博主名称 | 文本 | 人工可读名称 |
| 平台 | 单选 | 抖音 / 小红书 / B站 |
| 平台账号ID | 文本 | 平台侧账号 ID 或唯一标识 |
| 主页链接 | URL | 人工可打开链接 |
| 账号类型 | 多选 | 同行 / 对标 / 需求样本 / 灵感源 / 竞品 |
| 关注目的 | 多选 | 选题 / 市场需求 / 竞品研究 / 表达学习 / 评论洞察 |
| 关联账号 | 多选 | 墨予镜 / 一镜一梳 / 知行AI服务 / 其他 |
| 启用状态 | 单选 | 启用 / 暂停 / 待确认 / 失效 |
| 检查频率 | 单选 | 每日 / 每周 / 手动 |
| 最近检查时间 | 日期时间 | 系统回写 |
| 最近内容时间 | 日期时间 | 系统回写 |
| 最近状态 | 单选 | 正常 / 无更新 / 失败 / 需人工处理 |
| 失败原因 | 文本 | 系统回写 |

### 5.2 表二：内容更新

用途：保存采集到的单条内容。

建议字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 内容唯一键 | 文本 | `平台:内容ID`，用于去重 |
| 平台 | 单选 | 抖音 / 小红书 / B站 |
| 博主 | 关联 | 关联表一 |
| 内容ID | 文本 | 平台侧内容 ID |
| 内容链接 | URL | 可打开链接 |
| 标题 | 文本 | 标题或首句 |
| 正文/简介 | 长文本 | 可获得的正文、简介、字幕摘要 |
| 发布时间 | 日期时间 | 平台发布时间 |
| 采集时间 | 日期时间 | 系统写入时间 |
| 内容类型 | 单选 | 图文 / 视频 / 直播回放 / 其他 |
| 标签 | 多选 | 平台标签或人工标签 |
| 点赞数 | 数字 | 可获得则写入 |
| 评论数 | 数字 | 可获得则写入 |
| 收藏数 | 数字 | 可获得则写入 |
| 转发/分享数 | 数字 | 可获得则写入 |
| 初步主题 | 多选 | AI / 疗愈 / 求职 / 内容运营 / 其他 |
| 分析状态 | 单选 | 待分析 / 已分析 / 忽略 / 需人工复核 |
| 价值判断 | 单选 | 高 / 中 / 低 / 未判断 |
| 可转译方向 | 多选 | 墨予镜选题 / 一镜一梳选题 / AI服务线索 / 市场需求样本 |

### 5.3 表三：评论样本

用途：保存评论区中可用于需求归纳的样本。

建议字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 评论唯一键 | 文本 | `平台:内容ID:评论ID` |
| 内容 | 关联 | 关联表二 |
| 评论文本 | 长文本 | 原始评论文本 |
| 评论时间 | 日期时间 | 可获得则写入 |
| 点赞数 | 数字 | 可获得则写入 |
| 用户标识 | 文本 | 尽量脱敏，不作为真人画像主库 |
| 需求类型 | 多选 | 问题咨询 / 痛点抱怨 / 购买意向 / 反对意见 / 案例补充 |
| 情绪倾向 | 单选 | 正向 / 中性 / 负向 / 未判断 |
| 是否进入洞察 | 单选 | 是 / 否 / 待定 |

### 5.4 表四：洞察与选题

用途：把内容和评论归纳成可执行选题或市场需求判断。

建议字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 洞察标题 | 文本 | 人工可读标题 |
| 来源内容 | 关联 | 可关联多条内容 |
| 来源评论 | 关联 | 可关联多条评论 |
| 洞察类型 | 单选 | 选题 / 用户需求 / 竞品观察 / 表达方式 / 产品线索 |
| 适用账号 | 多选 | 墨予镜 / 一镜一梳 / 知行AI服务 |
| 证据摘要 | 长文本 | 引用事实，不写夸大结论 |
| 建议动作 | 长文本 | 下一步内容、调研或服务动作 |
| 状态 | 单选 | 待处理 / 已转选题 / 已验证 / 暂存 |

## 6. 数据流

```mermaid
flowchart LR
  A["飞书：博主账号表"] --> B["定时任务"]
  B --> C["平台采集适配器"]
  C --> D["内容去重与标准化"]
  D --> E["飞书：内容更新表"]
  E --> F["评论采集任务"]
  F --> G["飞书：评论样本表"]
  E --> H["分析任务"]
  G --> H
  H --> I["飞书：洞察与选题表"]
```

说明：

- 适配器（adapter，平台接入层）负责把不同平台的数据转成统一字段。
- 去重层以平台和内容 ID 为准，避免重复写入。
- 分析任务不直接覆盖原始采集结果，只新增洞察、标签和建议动作。

## 7. MVP 范围

第一版只做一个可跑通的最小闭环：

1. 飞书中维护博主账号表
2. 支持手动触发一次检查
3. 支持定时每日检查
4. 至少先跑通一个平台的 L1 元数据采集
5. 内容更新写入飞书
6. 同一内容不重复写入
7. 每次任务有运行日志
8. 失败账号回写失败状态和原因

第二阶段再扩展：

- 三个平台适配器
- 评论区采集
- 批量回溯采集
- 自动主题聚类
- 需求洞察和选题建议

## 8. 明确不做范围

第一版不做：

- 自动登录托管
- 绕过平台权限或风控的采集
- 大规模无节制爬取
- 自动发布内容
- 自动私信或评论互动
- 把用户个人身份画像作为长期主库
- 对外宣称数据完整覆盖平台全部内容

## 9. 合规与风险边界

本系统必须默认遵守：

- 优先使用平台公开页面、开放接口或用户已授权的数据来源
- 控制频率，避免影响平台服务
- 保存失败原因，不用静默重试掩盖风控问题
- 评论区数据只用于需求归纳，不用于骚扰、定向联系或个人画像
- 飞书中避免保存不必要的敏感个人信息
- 采集来源、采集时间和字段缺失情况必须可追溯

## 10. 验收标准

MVP 通过的最低标准：

1. 能从飞书读取启用博主列表
2. 能检查至少一个平台账号是否有新内容
3. 能把新内容写入内容更新表
4. 重复运行不会重复写入同一内容
5. 失败时能在博主账号表回写状态和失败原因
6. 有可读运行日志
7. 文档中明确当前平台能力级别和缺失字段
