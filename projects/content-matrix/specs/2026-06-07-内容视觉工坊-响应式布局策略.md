# 内容视觉工坊响应式布局策略

## 1. 目标

这份文档只解决一个问题：

第一版虽然以桌面工作台为主，但布局层必须从一开始就具备响应式收缩能力，避免后续为平板和手机返工。

这里的“响应式”不等于“第一版就完整支持手机端创作”。

本项目采用的策略是：

- 桌面优先
- 平板可用
- 手机轻量

## 2. 产品判断

### 2.1 为什么不能只做固定桌面稿

如果当前完全按固定宽度桌面稿实现，后续扩展到平板或手机时，最容易出现以下返工：

1. 三栏布局写死，无法折叠
2. 卡片网格无法收缩
3. 右栏审稿区无法变成抽屉或切换面板
4. 顶部工具栏在窄屏下溢出
5. 各模块最小宽度不合理，导致内容断裂

### 2.2 为什么第一版不直接追求手机完整可用

这个工具的主任务是：

- 上传 Markdown
- 理解文章结构
- 比较多张知识卡片
- 审稿公众号排版
- 同步草稿

这些任务天然更适合大屏。手机更适合查看结果、做简单操作，不适合完整创作。

## 3. 第一版响应式原则

### 3.1 布局层从第一天就响应式

必须做到：

- 主结构使用 `flex` 或 `grid`
- 左中右三栏具备可收缩能力
- 不依赖绝对定位拼主界面
- 不把栏宽完全写死

### 3.2 交互层第一版仍以桌面为主

第一版应优先保证：

- `1440px` 左右桌面最佳体验
- `1280px` 左右桌面稳定可用
- `1024px` 左右窄桌面不崩

### 3.3 手机端只保留轻任务

手机端未来应优先支持：

- 查看生成结果
- 查看草稿同步状态
- 打开草稿
- 重新同步
- 单张图片重生成

不应把手机作为第一版完整创作端。

## 4. 断点策略

建议采用以下断点：

### L：大桌面 `>= 1440px`

- 完整三栏
- 左栏固定输入区
- 中栏主工作区
- 右栏固定审稿区

### M：桌面 `1024px - 1439px`

- 仍保留三栏
- 左右栏收窄
- 中栏优先保留宽度

### S：平板 `768px - 1023px`

- 改为双栏或单主栏模式
- 左栏改为抽屉
- 右栏改为抽屉、sheet（侧滑面板）或 tab（标签切换）
- 中栏保持主视图

### XS：手机 `< 768px`

- 单栏
- 默认进入结果或状态页
- 输入、审稿、同步等作为切换面板

## 5. 三栏收缩策略

### 5.1 左栏

左栏承载：

- Markdown 上传
- 输出开关
- 卡片尺寸
- 风格资产
- 主操作按钮

收缩优先级：

1. 大桌面：固定显示
2. 中桌面：压窄但保留
3. 平板：折叠为抽屉
4. 手机：改为顶部入口或底部 sheet

### 5.2 中栏

中栏承载：

- 内容拆解
- 知识卡片结果
- 封面结果

这是主工作区，应最后收缩。

要求：

- 永远优先保留中栏宽度
- 图片卡片网格必须可从 2 列收缩到 1 列
- 封面区允许从横向并排改为纵向堆叠

### 5.3 右栏

右栏承载：

- 公众号排版预览
- 审稿摘要
- 草稿同步状态

收缩优先级：

1. 大桌面：固定显示
2. 中桌面：压窄但仍保留
3. 平板：切为抽屉或二级 tab
4. 手机：单独结果页或底部入口

## 6. 组件级响应式约束

### 6.1 顶部导航

要求：

- 搜索框可收缩
- 次级导航项在窄屏时允许折叠
- 账号区和系统操作图标优先保留

### 6.2 Markdown 上传卡

要求：

- 小屏时保持信息摘要，不展示过长描述
- 文件名、标题、统计信息应允许换行或截断

### 6.3 风格资产列表

要求：

- 桌面显示完整卡片列表
- 平板可压缩为更矮的列表卡
- 手机可改为横向滚动或单独面板

### 6.4 知识卡片结果卡

要求：

- 桌面 2 列
- 平板 1 列
- 图片比例始终稳定
- 工具条不因文本变化撑开卡片

### 6.5 公众号审稿预览

要求：

- 预览宽度应有上限
- 小屏下应改为独立查看模式
- 审稿摘要和同步状态可拆分为折叠区块

## 7. 实现约束

### 7.1 不要这样写

- 不要把整页写成固定像素布局
- 不要把三栏宽度全部写死
- 不要依赖大量绝对定位摆主结构
- 不要让图片区随文字高度失控

### 7.2 应该这样写

- 用容器级 `flex` / `grid`
- 给左栏、右栏设 `min/max width`
- 给中栏设 `flex: 1` 和合理 `min-width`
- 卡片区使用响应式 grid
- 面板切换提前设计成可抽屉化

## 8. 第一版推荐尺寸口径

### 页面级

- 最佳：`1440px`
- 可接受：`1280px`
- 最低桌面工作宽度：`1024px`

### 栏位级建议

- 左栏：`320px - 360px`
- 中栏：主剩余空间
- 右栏：`420px - 480px`

这些是建议范围，不应写成不可变常量。

## 9. 对当前原型的直接建议

当前这套原型可按以下方式进入实现：

1. 保持桌面三栏为默认态
2. 先把左栏和右栏写成可折叠容器
3. 中栏图片结果区使用响应式网格
4. 右栏预览区支持独立滚动
5. 平板断点下把左栏、右栏切为按钮唤起面板

## 10. 结论

第一版的正确策略不是“只做桌面”，也不是“同时做完整手机端”，而是：

- 现在就把响应式框架搭好
- 现在只把桌面体验打磨完整
- 平板收缩路径提前定好
- 手机端先只保留轻量能力

这能避免后面大规模返工，同时不把第一版范围扩散掉。
