# 内容视觉工坊图片链路与排版链路分工

## 1. 目标

明确一件事：

图片生成链路和公众号排版链路共享同一篇原稿，但不共享同一套处理方式。

## 2. 图片链路

### 输入

- 文章全文文本
- 风格预设
- 图片尺寸与比例

### 处理方式

直接把正文内容交给大模型，由模型完成：

1. 自动判断拆成几张知识卡片
2. 提炼每张卡片的主题
3. 生成每张卡片的图像描述
4. 生成公众号封面和小红书封面描述

### 结论

图片链路 **不依赖 Markdown 解析结果**。

Markdown 文件可以作为原稿载体存在，但图片生成不要求先把 Markdown 转成结构化 AST（抽象语法树）再处理。

## 3. 排版链路

### 输入

- Markdown 原文
- 图片生成结果
- 系统识别出的重点句和插图位

### 处理方式

排版链路需要利用 Markdown 结构：

- 标题层级
- 段落结构
- 列表
- 引用
- 加粗重点

系统在保留原有结构的基础上，再做公众号加工。

## 4. 这个工具真正更强的地方

它不是只把 Markdown 转成公众号样式，也不是只把文章转成图片。

它更强的能力是：

**系统自己知道文生图生成的图片应该放在哪里。**

也就是说，排版链路除了继承 Markdown 结构，还要多做一步：

- 根据文章逻辑决定插图位
- 把生成的知识卡片嵌入合适位置
- 保证图文节奏、段落密度和阅读呼吸感

## 5. 推荐实现分层

### A. 原稿层

- 原文文本
- Markdown 原文

### B. 图片规划层

- 拆图结果
- 卡片主题
- 封面主题
- 图片生成请求

### C. 排版规划层

- Markdown 结构摘要
- 重点句识别
- 插图位编排
- 公众号块级排版结果

### D. 草稿同步层

- 图片素材上传
- HTML 或富文本 payload 组装
- 草稿创建

## 6. 工程约束

后续实现中不要把以下两件事绑死：

1. 不要把 Markdown 解析结果当成图片生成的必经输入
2. 不要把图片位置完全交给人工手动配置

正确做法是：

- 图片生成基于全文语义自动拆图
- 排版链路基于 Markdown 结构做再加工
- 插图位由系统编排，再允许人工微调

## 7. 结论

本项目后续应按两条链路并行实现：

- 图片链路：全文语义 -> 自动拆图 -> 出图
- 排版链路：Markdown 结构 -> 图文编排 -> 草稿同步

这也是内容视觉工坊区别于普通 Markdown 排版工具和普通文生图工具的地方。
