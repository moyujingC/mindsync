# 发布反馈与服务验证组件实现记录

## 实现方式

1. 草稿、编辑包、成稿和反馈模板均保留 `source_insight_record_id`，对应来源研究请求和候选编号。
2. `prepare:feedback` 生成只由人工填写的反馈模板，包含发布事实、互动、服务信号、代表性反馈和反对意见。
3. `feedback:record` 仅在候选已“转选题”且填写有效 HTTP(S) 发布链接时，回写本地台账和研究简报为“已发布”。
4. 传入飞书配置时同步“研究请求”表摘要；未配置时不发起远程写入。
5. 转入 `ai-service-studio` 样本沟通记录仍须显式运行 `promote:feedback`，组件不自动联络、报价或成交。

## 验证

- 专项测试覆盖发布链接门槛、候选状态回写、简报同步、飞书摘要同步和全链路溯源。
- 完整回归：`npm test`，105 passed。
