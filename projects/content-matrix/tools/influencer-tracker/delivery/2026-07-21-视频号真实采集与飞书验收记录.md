# 视频号真实采集与飞书验收记录

## 实现

视频号搜索结果的数字 `hashDocID` 不能直接作为详情对象。有效流程是使用搜索结果的短期 `export_id` 调详情，再从 `objects[]` 取得稳定内容 ID 和 `finder username`。账号列表返回于 `object[]`，评论返回于 `commentInfo[]`。

视频号内容和评论 ID 常超过 JavaScript 安全整数范围。TikHub 客户端会把长整数解析为字符串，确保后续评论请求使用原始 ID。评论唯一键使用真实 `commentId`；研究重复采样时仍会把本轮内容和评论交给洞察层，飞书写入继续按唯一键去重。

## 真实验收

四类轻量脱敏合同（搜索、详情、账号列表、评论）均已捕获，并通过 `validate:tikhub-contracts --platform wechat_channels`。评论接口对一条公开评论数为 199 的内容返回 25 条真实一级评论；受控研究请求采样其中 10 条。

请求 `research-2026-07-21-enterprise-ai-wechat-channels-comments-004` 写入后，飞书 CLI 以字段投影和精确筛选读回：博主账号、内容更新、评论样本、研究请求各 1 条。评论记录使用真实 `commentId` 唯一键，读回点赞数为 56；研究请求状态为“待人工确认”，内容样本数为 1，评论样本数为 10。

首次视频号写入发生在评论 ID 映射修复前，留下 10 条临时序号评论键。后续已写入真实键记录，但旧记录没有自动删除，避免误删人工编辑数据；需人工确认后清理。
