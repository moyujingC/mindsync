# TikHub 多平台内容情报组件实现记录

## 本次改造

原有 B 站 RSSHub、yt-dlp、BV 链接解析、下载、字幕转写、B 站评论和日更 worker 已删除。采集层改为 TikHub 四平台组件：小红书、抖音、公众号、视频号。

新链路：

```text
链接 / 关键词 / 账号标识
-> TikHub Tool
-> 标准化内容和评论
-> Workflow 去重并写入飞书三表
-> 内容提纯与需求归纳
-> 待人工审核的洞察与选题
-> 既有内容发布、反馈和 AI 服务验证链路
```

## 组件架构

| 层级 | 实现 | 职责 |
| --- | --- | --- |
| Tool | `src/platforms/tikhub/client.mjs` | 请求 TikHub、记录调用次数与缓存 URL、处理失败 |
| Tool | `src/platforms/tikhub/normalize.mjs` | 将四平台响应转为统一内容和评论字段 |
| Workflow | `src/jobs/tikhub-collect.mjs` | 详情、关键词、账号采样；内容、博主、评论去重写入飞书 |
| Agent 输入 | `src/jobs/enrich-content.mjs` | 对标准化内容和评论做文本提纯，产出待审核需求洞察与选题 |
| 下游 Workflow | 既有 brief、草稿、发布反馈模块 | 将人工确认的洞察推进为内容与服务验证 |

## 飞书变更

- `博主账号.平台` 和 `内容更新.平台` 新增 `公众号`、`视频号` 选项。
- `博主账号.数据源类型` 新增 `TikHub` 选项。
- 历史 `B站` / `bilibili` 选项仍保留，避免破坏已有历史记录；新代码不再写入这些选项。

## 后续补强：四平台合同样本与分页

- 新增 `fixtures/tikhub-contracts/`，覆盖小红书、抖音、公众号、视频号的列表包装，以及评论游标包装。它们是合同样本，不是生产响应。
- 搜索和账号采样会按总条数跨页；评论保持默认一页，只有显式传入评论页数才跨页。
- 当服务端返回重复或缺失游标时，Workflow 安全停止，并在 `audit.pagination` 输出页数与停止原因。
- 当前 TikHub 账户仍返回 HTTP 402。额度或接口权限恢复后，需用脱敏真实响应替换或补充合同样本，再完成四平台真实联调验收。

## 验证

- `npm test`：68 项通过。
- `node src/cli/validate-config.mjs --feishu config/feishu.local.json`：通过。
- 模拟 TikHub 响应验证了：小红书详情加评论、关键词最多采样指定条数、内容去重、评论去重、博主账号自动补录、飞书平台映射和调用审计。
- 真实 TikHub 最小关键词请求已到达服务端，但返回 HTTP 402。该状态表示当前账号没有可用调用额度或未开通所需接口套餐；代码不再继续重试，以免浪费额度。

## 真实联调前置条件

1. 在 TikHub 后台确认余额和“小红书搜索”接口权限。
2. 在本机或 release 服务器私有环境设置 `TIKHUB_API_KEY`，不写入 Git。
3. 先运行一条 `--dry-run` 小红书详情请求，确认真实响应字段。
4. 再移除 `--dry-run`，验证内容更新、博主账号、评论样本三表各新增一条或多条记录。

## 当前不做

- 不恢复 B 站采集或媒体下载。
- 不在没有真实多轮反馈前启用自动化 Agent Loop。
- 不自动发布、私信、评论或把洞察作为确定市场结论。
