# 研究请求工作流实现记录

## 实现目标

将“链接 / 关键词 / 对标账号”统一为研究请求，而不是以博主日更追踪作为系统入口。一次请求指定研究目的、服务方向、目标账号和采样范围，输出可供人工确认的研究简报。

## 新增能力

- 新增 `src/jobs/research-request.mjs`：编排采集结果、内容提纯、评论证据和候选选题。
- 新增 `src/cli/research-request.mjs` 与 `npm run research:run`：成为日常推荐入口。
- 研究简报写入 `logs/research-briefs/`，包含调用量、缓存 URL、样本数、最多 3 个候选选题、证据等级和人工确认点。
- 清理 `package.json` 中指向已删除日更 worker、旧 fixtures 与旧报告的命令。

## 边界

- Workflow 只负责采集、整理和交接，不自动发布、私信、报价或创建获客结论。
- 候选选题均标记为“待人工审核”；`观察` 仅表示存在内容和至少两条评论证据，不等于市场已验证。
- TikHub Key 仍只从 `TIKHUB_API_KEY` 环境变量读取。

## 验证

- `npm test`：71 项通过。
- 专项测试覆盖：研究简报字段、评论证据、候选选题上限、人工确认状态和请求字段校验。
- 不带 Key 运行 `research:run` 会明确报 `Missing TIKHUB_API_KEY`。
- 已知外部阻塞：真实 TikHub 请求返回 HTTP 402，需在 TikHub 后台确认余额或接口权限后再做真实飞书写入与发布反馈验收。
