# 内容入库规范

## 适用范围

用于小红书、抖音、公众号、视频号的公开内容，以及已获授权的手工摘录。它只负责标准化、去重和归档，不判断内容是否值得研究，也不生成市场结论。

## 必填与可选字段

- 必填：`platform`、`url`、`title`。
- 建议：`creatorName`、`externalId`、`publishedAt`、`description`、`contentType`。
- 评论只在研究目的明确需要时提供；不得把评论正文放入标题或简介字段。
- 清理后的转写稿使用 `refinedTextPath` 引用本地文件，不写入飞书正文。
- 合法取得的本地音频或视频先经 `media:transcribe` 或 `media:process` 生成字幕和清理稿；不得由该组件下载平台媒体、上传原媒体，或将媒体正文写入飞书。
- 中文平台名会规范化为 TikHub 内部 ID；唯一键使用内部 ID，但去重兼容历史中文唯一键。

## 执行规则

1. 先判断来源是否公开、已获授权或已匿名化；不满足时停止入库。
2. 用平台和外部 ID 生成内容唯一键；缺少外部 ID 时使用稳定链接路径。
3. 先运行 `--dry-run` 检查字段、唯一键和候选，再执行写入。
4. 本地去重库和飞书内容表任一已有相同唯一键时，不重复创建记录。
5. 原始 API 响应、转写稿和大段原文只留在本地项目文件；飞书只保存可筛选摘要。

## 隐私与禁止项

- 不录入客户非公开资料、私密链接、可反向识别的个人信息或未经授权的聊天记录。
- 不尝试绕过平台权限、反爬或登录限制。
- 不以“随机发现”为由省略来源链接。

## 当前命令

```bash
# 检查手工内容输入，不写入任何存储
npm run manual:import -- --input fixtures/manual-import.example.json

# 用同一内容输入发起研究请求
npm run research:manual -- --input fixtures/manual-research.example.json --dry-run
```

## 交接输出

输出为标准化内容记录：内容唯一键、来源链接、平台、标题、摘要和必要的本地原文路径。后续是否采评论、提纯或生成洞察由研究请求决定。
