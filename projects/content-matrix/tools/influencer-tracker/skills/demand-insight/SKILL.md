# 需求洞察规范

## 输入与输出

- 输入：标准化内容、可选评论样本、可选本地提纯稿、研究目的和服务方向。
- 输出：用户问题、需求信号、证据摘要、候选选题和下一步动作。
- 输出一律是“待人工审核”的假设，不是客户画像、诊断结论或成交预测。

## 判断口径

- `好奇`：工具、方法或趋势的泛泛提问，没有明确场景或行动意愿。
- `痛点`：描述重复劳动、信息混乱、流程卡点、成本或时间损失，并能指向具体场景。
- `付费信号`：主动询问范围、交付、试点、预算、咨询或愿意提供资料样本；仍需人工确认。
- `反对意见`：对成本、权限、准确性、风险、替代方案或执行难度的担忧，应原样保留。

## 质量要求

1. 每个候选必须保留来源内容唯一键和相关评论唯一键。
2. 不从单条评论推断整体市场规模、购买意愿或疗效。
3. 转写稿只作为原文线索；使用时保留本地路径和有限片段，不把全文写入飞书。
4. 一次研究最多输出 3 个候选，避免把噪声包装成选题池。
5. 一镜一梳相关内容不得输出心理诊断、疗效判断或可识别个体信息。

## 人工确认

候选只能按以下路径推进：`待人工审核 -> 已转选题 -> 已发布`。若要标记“已验证”，必须单独提供可追溯的人工验证依据；转选题不等于已验证。

## 不做

- 不自动把候选写成成稿、服务话术或销售承诺。
- 不删除与假设相反的评论或反对意见。
