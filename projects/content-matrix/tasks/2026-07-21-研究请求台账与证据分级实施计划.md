# 研究请求台账与证据分级实施计划

## 目标

让每一轮研究请求成为可追溯的业务记录，并阻止采集程序把内容或评论自动包装成已验证的市场结论。

## 范围

1. 研究请求运行后，保存本地 JSON 台账和 Markdown 简报。
2. 台账记录请求目标、采集摘要、候选、人工决定、验证依据和更新时间。
3. 证据等级只描述样本强度：`线索`、`观察`。
4. 结论等级只描述洞察判断：自动结果为`假设`；`已验证`必须有人工作为依据。
5. 提供 CLI（命令行）人工确认入口，不自动创建草稿、发布或触达。

## 实施步骤

1. 新增 `ResearchRequestStore`，以 `requestId` 去重保存请求。
2. 研究请求完成后，同时写入 `logs/research-briefs/<requestId>.md` 和 `logs/research-requests.json`。
3. 新增候选状态机：`待人工审核 -> 已转选题 -> 已发布`，任意状态可结束；每次流转必须有决定说明。
4. 新增 `验证` 动作，强制要求 `verificationEvidence`，并只更新结论等级。
5. 确认后重新写入对应简报，保持台账与人工可读简报一致。
6. 通过单测和全量测试验证状态、证据边界与原有组件兼容性。

## 不做

- 不创建飞书“研究请求”表，待字段合同稳定后再接入。
- 不自动生成正式内容、发布、私信、报价或成交。
- 不把两条评论、点赞或模型判断当作“已验证”。
