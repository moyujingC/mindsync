# 内容视觉工坊 A+B 实现计划

## 1. 目标

按最小闭环交付一个内部工作台，完成：

- 文章输入
- 图片生成
- 公众号排版
- 同步公众号草稿

## 2. 里程碑

### M1. 原型与接口边界冻结

- 在 Figma Make 定稿三栏工作台
- 冻结输入字段、生成结果区、草稿同步区
- 明确图片生成 API 和公众号接口字段

交付物：

- 原型稿
- 接口字段表

### M2. 本地工作台跑通

- 建前端工作台
- 支持文章输入
- 支持内容拆解
- 支持展示卡片方案、封面方案、排版预览

交付物：

- 本地可运行工作台

### M3. 图片链路跑通

- 接入文生图 API
- 生成知识卡片
- 生成公众号封面
- 生成小红书封面
- 支持单张重生成

交付物：

- 图片生成链路
- 失败重试机制

### M4. 公众号草稿链路跑通

- 接入素材上传
- 接入草稿创建
- 组装图文 payload
- 显示同步状态

交付物：

- 可写入公众号草稿箱的最小闭环

## 3. 模块拆分

### 3.1 前端工作台

- 文章输入表单
- 生成结果面板
- 排版预览面板
- 草稿同步状态面板

### 3.2 内容编排服务

- 文章结构分析
- 卡片拆分
- 封面摘要提炼
- 公众号排版结构生成

### 3.3 图片生成服务

- 统一图片生成请求
- 风格预设管理
- 重生成逻辑

### 3.4 公众号集成服务

- access token 管理
- 图片素材上传
- 草稿写入
- 错误处理和状态回传

## 4. 推荐执行顺序

1. 先做静态原型
2. 再做假数据工作台
3. 再接内容编排
4. 再接图片生成
5. 最后接公众号草稿

这个顺序可以避免一开始被外部接口阻塞。

## 5. 第一版技术决策建议

### 5.1 排版层

优先使用受控模板和结构化块渲染，不做自由编辑器。

### 5.2 图片层

统一用一个图片服务适配层，避免前端直接绑定某个文生图供应商。

### 5.3 草稿层

先以“创建草稿成功”为主，不把“发布”按钮纳入实现范围。

## 6. 待补技术决策

实现前需要补齐：

1. 前端技术栈
2. 服务端技术栈
3. 图片文件存储位置
4. 公众号授权方式
5. 图片生成失败后的兜底策略

## 7. 残留依赖

- 公众号开发者配置
- 文生图 API key
- Figma 原型确认
- 账号风格预设整理

## 8. 完成定义

满足以下条件才算本阶段完成：

1. 有正式原型
2. 有跑通的本地工作台
3. 有真实生成的图片结果
4. 有真实写入的公众号草稿
5. 有验证记录
