# 抖音四类真实合同联调实施计划

## 目标

利用已有真实搜索结果的分享链接、视频 ID 和博主 `sec_user_id`，验证抖音详情、账号列表和评论端点，修正此前错误的请求方法与参数。

## 实施

1. 读取 TikHub OpenAPI，确认详情、账号列表、评论均使用 GET。
2. 将账号列表改为 `sec_user_id`、`max_cursor`、`count`、`sort_type`，评论改为 `aweme_id`、`cursor`、`count`，首页游标固定传 `0`。
3. 对一条既有视频执行详情、账号和评论 dry-run。
4. 捕获搜索、详情、账号、评论四份轻量脱敏合同，并运行覆盖校验。

## 验收

- 三类请求与 OpenAPI 的方法、参数一致。
- 详情可标准化；账号列表返回内容与游标；评论端点返回成功响应。
- 合同不含视频 ID、账号 ID、昵称、标题、正文、评论原文或 URL 查询参数。
- 当前样本无评论时，不把“端点可用”写成“评论采样已验证”。
