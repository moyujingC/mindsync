这份任务文档用于把 `RelayHub` 的控制台 v1 从信息架构推进到可实施的静态壳阶段。

它只定义第一轮控制台实现该做什么、先做哪些页面，以及哪些能力明确不进入本轮。

## 1. 任务目标

控制台 v1 的第一轮目标是：

- 建立一个面向内部运营的控制台外壳
- 跑通顶层导航和环境优先的信息结构
- 用本地 fixtures 支撑核心页面的静态展示
- 为后续接真实 Relay API、控制台后端和 `eval-sidecar` 留出稳定前端骨架

本轮不是在做：

- 公开产品台
- 真实生产控制面
- 可编辑路由后台
- 可落地执行的策略配置系统

## 2. 当前固定决策

实现过程中必须沿用以下固定决策：

- 控制台 v1 是 `内部运营台`
- 首版前端只做 `壳 + 核心静态页`
- 前端代码未来独立落位在 capability 工作区，不挂到现有产品前端
- 技术路线采用 `React + Vite + TypeScript`
- 构建与未来控制台后端 / Relay API 同栈使用 `Node.js`
- `eval-sidecar` v1 也保持 TypeScript 同栈，但结构上可独立拆分
- 页面数据来自本地 fixtures 与假数据

## 3. 第一阶段要做的页面

第一阶段只做 4 类核心页面：

1. `Dashboard`
2. `Environments`
3. `Providers`
4. `Eval`

这些页面必须是可浏览、可切换、可展示多状态的静态页面，而不是只有标题的占位板。

### 3.1 `Dashboard`

必须至少包含：

- 环境总览卡
- 决策摘要卡
- 风险提示卡
- 运行指标摘要卡
- 最近运行记录卡

### 3.2 `Environments`

必须至少包含：

- 环境卡列表
- 环境详情入口
- 环境详情页 tab 结构的静态壳

### 3.3 `Providers`

必须至少包含：

- provider 列表
- provider 类型与健康状态展示
- provider 详情页四块信息骨架

### 3.4 `Eval`

必须至少包含：

- `Scoreboard`
- `Comparisons`
- `Recommendations`
- `Reports`

四个子页的静态入口与示例内容。

## 4. 第一阶段只保留占位的模块

以下一级模块本轮只保留导航入口和占位页：

- `Routes`
- `Usage`
- `Policies`
- `Runs`
- `Settings`

占位页必须只表达两件事：

- 页面目的
- 未来会承接什么信息

不允许在占位页暗示：

- 真实可编辑策略
- 真实生产开关
- 真实自动切流
- 真实鉴权与多用户能力

## 5. 前端实现骨架

控制台前端未来默认独立放在 capability 下。

推荐后续目录：

- `projects/relayhub/console/`

推荐骨架：

- `console/src/app/`
  - 路由与页面壳
- `console/src/features/`
  - Dashboard / Environments / Providers / Eval
- `console/src/fixtures/`
  - 本地假数据
- `console/src/components/`
  - 共用布局、卡片、表格、状态块

本轮不要求先创建以上代码目录，但后续实现任务应按此骨架推进，避免再次讨论落位。

## 6. 数据与状态要求

本轮页面数据只来自本地 fixtures。

fixtures 至少要覆盖以下 UI 状态：

- 正常
- provider 异常
- 无数据
- 配置越界风险
- 推荐结论已生成

这样实现者才能在没有真实后端的前提下，把最关键的信息状态走通。

## 7. 本轮明确不做

本轮不做：

- 真实 API client
- 真实鉴权
- 真实数据库
- 真实 chart 数据接入
- 真实生产配置编辑
- 真实 provider 测试与调用
- 真实路由保存与发布

## 8. 实施顺序

控制台静态壳建议按下面顺序实现：

1. 顶层布局与导航壳
2. `Dashboard`
3. `Environments`
4. `Providers`
5. `Eval`
6. 占位页
7. 统一状态样式与空态 / 异常态补齐

这样做的原因是：

- 先把“环境优先”的主心智搭起来
- 再实现最影响决策的页面
- 最后才补外围占位结构

## 9. 完成标准

只有同时满足下面条件，才算这份实施任务完成：

- 实施者不需要再决定“第一版先做哪些页面”
- 实施者不需要再决定控制台放在哪个项目下
- 实施者不需要再决定用什么前端技术路线
- 页面范围、占位范围和假数据范围都已明确
- 文档没有把开发版与生产版表达混掉

## 10. 一句话结论

控制台 v1 的第一轮实现，不是“做一个完整后台”，而是先做一个可进入实现的内部运营台静态壳，把环境、provider、评测和决策心智稳定下来。
