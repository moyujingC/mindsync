这份任务文档用于把 `RelayHub` 控制台从“直接读取 fixtures 的静态壳”推进到“只读数据化、可深链浏览的内部运营台”。

它的目标不是接真实 Relay API，而是先把前端数据结构、只读 mock API 和路由状态稳定下来，为后续真实接入铺平路径。

## 1. 任务目标

本轮目标是：

- 把页面从直接 import fixtures 改成通过只读数据访问层取数
- 固化控制台前端所需的最小稳定 view model
- 用 Promise-based mock API 模拟未来的只读数据接口
- 为 `Environments`、`Providers`、`Eval` 补独立 URL 深链
- 明确处理 loading / empty / not-found / mock-error 状态

本轮不是在做：

- 真实后端
- 真实鉴权
- 真实数据库
- 真实控制面
- 真实策略保存或发布

## 2. 当前固定决策

实现过程中必须沿用以下固定决策：

- 控制台仍是 `内部运营台`
- 数据层仍然 `只读`
- mock API 只使用本地 TypeScript 模块实现
- 不引入 JSON server、MSW 或额外 mock 服务端进程
- 深链只覆盖核心模块，不扩展到占位页
- 心理疗愈生产版边界继续写死为“仅国产模型”

## 3. 本轮要做的实现

### 3.1 view model 固化

新增控制台最小稳定类型，至少覆盖：

- environment
- provider
- dashboard decision
- dashboard risk
- run
- eval scoreboard
- comparison
- recommendation
- report

这些类型不直接暴露为真实后端契约，而是前端当前稳定消费层。

### 3.2 mock API

新增 Promise-based 只读 API 层，至少包含：

- `getDashboardOverview()`
- `listEnvironments()`
- `getEnvironment(id)`
- `listProviders(filters)`
- `getProvider(id)`
- `getEvalOverview()`

要求：

- 默认返回本地 mock 数据
- 可模拟 `loading`、`not-found`、`error`
- 不引入真实网络请求

### 3.3 service 层

新增前端数据访问 service，把页面从直接读取 fixtures 改为调用 service。

service 职责：

- 调用 mock API
- 做最小前端映射
- 为页面层返回稳定形态

页面层不再直接 import `fixtures/data.ts`。

### 3.4 URL 深链

新增以下路由形态：

- `/environments/:environmentId/:tab?`
- `/providers/:providerId?`
- `/eval/:tab?`

要求：

- URL 能表达当前上下文
- 刷新后仍能落在正确页面状态
- 未命中资源时展示 not-found，而不是 silently fallback

### 3.5 页面状态补齐

核心页面要显式处理：

- loading
- empty
- not-found
- mock-error

其中：

- `Providers` 至少展示 provider not-found
- `Environments` 至少展示环境 not-found
- `Eval` 至少展示 tab 深链与空态

## 4. 本轮明确不做

本轮不做：

- 真实 fetch client
- API schema 生成
- SSR
- 路由守卫
- 用户体系
- 可编辑策略表单
- 写操作按钮

## 5. 实施顺序

建议按下面顺序推进：

1. 新增 task / qa artifact
2. 提交当前静态壳成果
3. 抽 `models/`
4. 抽 `mocks/` 与 `services/`
5. 改造路由入口
6. 改造 `Dashboard`
7. 改造 `Environments`
8. 改造 `Providers`
9. 改造 `Eval`
10. 跑构建与全文误导风险检查
11. 补验证记录与交付说明

## 6. 完成标准

只有同时满足下面条件，才算本轮完成：

- 页面层不再直接依赖原始 fixtures
- 核心模块已支持只读深链 URL
- loading / empty / not-found / mock-error 状态可见
- `npm run build` 通过
- 生产边界与只读边界未被稀释
- 有新的验证记录或交付说明承接本轮结果

## 7. 一句话结论

本轮不是把控制台变成真实产品台，而是先把它变成“数据入口更稳定、URL 可深链、状态更完整”的只读运营台。
