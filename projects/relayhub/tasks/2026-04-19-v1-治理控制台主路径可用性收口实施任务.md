## 1. 本轮目标

在不改 deployment、runtime seam 和 control-plane 接口的前提下，完成治理控制台主路径的首次使用收口。

## 2. 实施拆解

### 2.1 导航收口

- `/` 继续跳转到 `/models`
- 侧边栏核心模块只强调：
  - `模型库`
  - `任务库`
  - `运行记录`
- `Dashboard` 下调到支持模块
- 支持模块默认弱化或折叠

### 2.2 模型库

- 首屏改成“已可用 / 待补配置”的使用语义
- 列表拆成：
  - `系统预置`
  - `我的模型`
- 表单明确区分：
  - `新增模式`
  - `编辑模式`
- 补最小必填校验
- 把保存、测试连接、停用 / 删除反馈改成可理解的操作语义

### 2.3 任务库

- 首屏改成“先绑定默认模型，再开始积累记录”
- 无激活模型时给出明确提示
- 表单顺序固定为：
  1. 任务名称
  2. 分类
  3. 默认模型
  4. 任务说明
  5. 模型切换说明
- 保存 / 删除反馈改成任务管理语义

### 2.4 运行记录

- 表单顺序固定为：
  1. 任务
  2. 模型
  3. 结果等级
  4. 结果摘要
  5. 可选成本
  6. 可选耗时
  7. 备注
- 补最小必填校验
- 提交成功后：
  - 清空表单
  - 刷新最近运行记录
  - 自动切到对应任务统计
- 任务统计默认优先显示最近有记录的任务

## 3. 明确不做

- 不新增新的前端 public API（公共接口）
- 不新增新的 runtime wrapper（包装层）
- 不新增新的 control-plane 路由
- 不重做 Dashboard 信息架构
- 不改 release 部署

## 4. 验证要求

- 更新路由 / UI 测试，覆盖本轮主要行为变化
- `cd projects/relayhub/console && npm test`
- `cd projects/relayhub/console && npm run build`
- release smoke 只做页面复核，不在本轮继续扩部署任务
