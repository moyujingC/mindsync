## 1. 实施目标

把当前模型库里的“填表 + 点测试”动作收成一条更明确的激活路径，让用户知道：

- 先激活谁
- 缺什么
- 为什么失败
- 成功后下一步去哪里

## 2. 具体工作

### A. 文档与入口同步

- 新增本轮 spec / task / qa / delivery artifact
- 在 `projects/relayhub/PROJECT.md` 补一句，明确当前优先级是模型激活闭环
- 更新 `specs/README.md`、`tasks/README.md`、`qa/README.md`、`delivery/README.md`

### B. control-plane 最小补强

- 扩展 `ModelEntry` 的最近测试语义字段
- 保留现有 `/models/:id/test` 路由
- 为测试结果补清楚的结果码、结果文案和下一步消息
- mock 与 server 逻辑保持一致

### C. 模型库页面收口

- 首屏摘要改成激活导向
- 把“当前状态”和“下一步动作”拆开表达
- 保存后的反馈改成“下一步请测试连接”
- 测试成功后的反馈改成“可去任务库绑定”
- 测试失败时直接展示失败原因
- `purchaseUrl` 进入条目或编辑区可见路径
- API Key 字段明确说明只做服务端脱敏保存

### D. 自动化验证

- 补 `control-plane` 测试：
  - 缺 API Key
  - 非法 Base URL
  - 测试成功
- 补 `console` 测试：
  - 保存后提示下一步测试连接
  - 测试失败原因展示
  - 测试成功提示去任务库绑定
  - `purchaseUrl` 入口可见

## 3. 完成标准

- `/models` 首屏更明确服务模型激活，而不是泛化管理
- 用户可以看懂“保存”和“激活”是两步
- `test-failed` 不再只有模糊失败句子，而是带清楚原因
- release 和本地 mock 的测试语义一致
