## 1. 实施目标

把当前“模型可激活、任务可切换”的基础闭环，继续收口成“用户知道先激活谁、先绑定给谁”的可用状态。

## 2. 具体工作

### A. 类型与数据

- 为 `ModelEntry` 增加轻量预置引导字段
- 同步 mock fixture 和 control-plane seed data
- 把当前预置目录升级成首轮可用的精选候选

### B. 模型库页面

- 把 `系统预置` 改成：
  - `优先激活候选`
  - `更多预置模型`
- 增加适合任务、首选理由、激活提示和成本层级展示
- 测试成功后提示可优先绑定的任务

### C. 任务库页面

- 在任务表格中增加 `推荐候选`
- 按任务 id / 任务分类匹配推荐模型
- 无精确匹配时退回全部已激活模型

### D. 文档与验证

- 新增 spec / task / qa / delivery
- 更新 README 索引
- 跑 console 与 control-plane 自动化验证

## 3. 完成标准

- 用户进入 `/models` 后能看懂先激活哪个预置模型
- 用户进入 `/tasks` 后能看懂该给哪个任务先绑定哪个模型
- 推荐逻辑只做引导，不伪装成正式评测结论
