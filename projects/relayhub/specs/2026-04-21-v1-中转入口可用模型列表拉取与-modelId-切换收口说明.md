# RelayHub v1：中转入口可用模型列表拉取与 `modelId` 切换收口说明

## Summary

本轮解决的是一个已经在线下验证过的真实问题：

- 中转入口的 `baseUrl` 和 `API Key` 可能都没问题
- 但预置默认 `modelId` 不一定是上游当前可用模型
- 结果就是 RelayHub 已经能把请求转发出去，却会卡在上游 `503` 或“无可用通道”

因此本轮收口目标不是继续扩入口数量，而是让用户能在现有预置中转入口上：

1. 先保存 `API Key`
2. 主动拉一次上游可用模型列表
3. 从列表中手动选择当前 `modelId`
4. 再显式测试连接
5. 测试通过后再去任务库绑定或切换

固定决策：

- 只覆盖 `relay-api` / 中转入口主路径
- 新增最小只读接口：`GET /models/:id/catalog`
- 拉到的列表只用于当前编辑会话，不持久化完整目录
- 预置入口继续锁定 `kind` 和 `baseUrl`
- 预置入口的 `modelId` 改为“半锁定”：
  - 不允许自由手填
  - 只允许从刚拉到的可用模型列表中选择
- 保存配置不等于激活；仍需显式点击“测试连接”

## Key Changes

### 1. control-plane 新增最小 catalog 读取能力

- 新增 `GET /models/:id/catalog`
- 只对满足以下条件的条目生效：
  - `source = preset`
  - `kind = relay-api`
  - `catalogFamily = openai-compatible`
  - 已保存 `API Key`
- 服务端请求目标固定为：
  - `<baseUrl>/models`
- 服务端用该入口已保存的 `API Key` 注入：
  - `Authorization: Bearer ...`
- 返回最小结构：
  - `items: Array<{ id: string; label: string; supportedEndpointTypes?: string[] }>`
  - `fetchedAt`
- 不把拉取结果写回 `state.json`

### 2. 错误语义明确化

`GET /models/:id/catalog` 失败时固定给出可操作错误，不返回模糊失败：

- 缺少 `API Key`
  - 提示先补 `API Key`
- 条目不属于当前支持的中转预置入口
  - 提示当前仅支持中转预置入口
- 上游不可达
  - 提示上游暂时不可达
- 上游返回非 `2xx`
  - 保留核心状态码摘要
  - 例如 `503`
- 上游 `/models` 返回结构不合法
  - 明确提示暂时无法识别可用模型列表

### 3. 预置入口锁定规则收口

对系统预置中转入口调整为“半锁定”：

- 继续锁定：
  - `kind`
  - `baseUrl`
- 不再绝对锁定：
  - `modelId`
- 但 `modelId` 的修改来源固定为：
  - 编辑区内刚拉到的上游可用模型列表
- 不开放成自由文本输入

自定义入口继续维持当前行为：

- 可手填 `baseUrl`
- 可手填 `modelId`

### 4. 模型库编辑区交互收口

在 `ModelLibraryPage` 的预置中转入口编辑模式中，新增一段最小交互：

- 按钮：
  - `获取可用模型`
- 拉取前：
  - 显示当前 `modelId`
  - 提示“先获取可用模型，再切当前模型”
- 拉取成功后：
  - 展示一个下拉选择控件
  - 仅列出刚返回的上游可用模型
  - 默认选中当前 `form.modelId`
- 保存后提示固定为：
  - “当前模型已更新，下一步请测试连接确认该入口当前模型是否可用。”

### 5. mock 与真实服务对齐

前端 mock service 和 server control-plane 保持同一语义，避免本地开发与真实行为分叉：

- mock service 也新增 `getModelCatalog(id)`
- 首批覆盖：
  - `AITechFlux`
  - `PPChat`
- `AITechFlux` mock 列表至少包含：
  - `高性能极速模型`
  - `高性能低价模型`
  - `Claude混合版`

## Product Notes

- 本轮解决的是“入口通了，但默认模型未必可用”
- 这不是测评（evaluation，模型测评）结论
- 这也不是推荐系统
- 当前只是让用户更快把一个真实可用模型接进来，再继续后续绑定与切换

## Assumptions

- 本轮只覆盖中转入口，不扩到所有官方国产入口
- 当前优先问题是“模型可用性接入”，不是“模型优劣判断”
- 不引入新的 provider 抽象层
- 不持久化完整上游模型目录
