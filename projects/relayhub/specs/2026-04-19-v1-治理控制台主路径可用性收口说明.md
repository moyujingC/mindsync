## 1. 本轮目标

本轮不再扩 deployment（部署）、runtime seam（运行时装配缝）或 control-plane（控制面）接口。

唯一目标是把当前治理控制台的主路径做成“第一次打开也知道先做什么”的状态。

默认决策固定为：

- 默认入口继续保持 `/models`
- 主路径只优先服务：
  - `模型库`
  - `任务库`
  - `运行记录`
- `Dashboard` 保留页面与路由，但本轮不做重设计
- 支持模块统一弱化，不再和主路径竞争首屏注意力

## 2. 导航与信息架构

当前导航必须明确区分两层：

### 2.1 核心模块

- `模型库`
- `任务库`
- `运行记录`

它们代表当前产品真正需要先走完的最小闭环。

### 2.2 支持模块

- `Dashboard`
- `外部模型源`
- `Environments`
- `Eval`
- `Routes`
- `Usage`
- `Policies`
- `Settings`

这些模块本轮继续保留，但只作为支持信息，不再被表达成第一进入路径。

## 3. Dashboard 本轮定位

`Dashboard` 本轮只做最小一致性处理：

- 保留 `/dashboard` 路由和页面
- 文案降噪
- 导航层级下调
- 视觉上不再像主入口

本轮不回答：

- Dashboard 最终应该承接哪些治理信息
- Dashboard 是否应该成为以后首页
- Dashboard 应该怎样重排模块

这些问题延后到单独的 Dashboard 重设计轮次处理。

## 4. 三张主页面的第一职责

### 4.1 模型库

模型库首屏先回答：

- 哪些模型已经可用
- 哪些模型还待补配置
- 哪些模型需要手动测试连接

模型库不再一上来就把“系统预置”和“自定义模型”混成一张泛表，而应先帮助用户判断当前离“可绑定任务”还差哪一步。

### 4.2 任务库

任务库首屏先回答：

- 当前有没有已激活模型可绑定
- 任务默认模型是否已经设好

任务库的主文案不再讨论复杂路由哲学，而是明确“先绑定默认模型，再开始积累记录”。

### 4.3 运行记录

运行记录页首屏先回答：

- 当前有没有最小记录样本
- 哪个任务最近已经形成可比较数据

录入表单必须遵循：

1. 先选任务
2. 再选模型
3. 再填结果

不让用户自己猜操作顺序。

## 5. 交互与反馈约束

本轮前端必须补足：

- 模型库最小必填校验：
  - 名称
  - Provider
  - Base URL
  - 模型标识
- 运行记录最小必填校验：
  - 任务
  - 模型
  - 结果摘要
- 操作反馈要区分当前动作：
  - 新增模型
  - 保存更新
  - 测试连接
  - 停用 / 删除
  - 新增任务
  - 删除任务
  - 新增运行记录

本轮不新增新的 control-plane 返回结构，只允许前端把现有返回映射成更清楚的界面反馈。

## 6. 与现有 spec 的关系

本说明补充并收束以下既有文档，而不是替代其对象模型：

- `治理控制台下的模型库与任务闭环产品说明`
- `控制台信息架构重排说明`

它负责回答的是：

- 当前第一次进入时，用户先做什么
- 哪些模块应该先看
- 哪些页面需要降低噪音和补反馈

它不负责：

- 重做数据模型
- 重做 Dashboard
- 改 control-plane 契约
- 改 release 部署路径
