这份文档把控制台 IA 草图进一步下沉到页面级，用于让实现者直接开始做静态页面，而不需要再猜首屏卡片、主表格和页面之间的跳转关系。

## 1. Dashboard

### 1.1 页面目标

回答 5 个问题：

- 哪些环境在跑
- 当前最重要的决策结论是什么
- 当前有哪些风险
- 当前系统运行状态如何
- 最近发生了什么

### 1.2 首屏卡片

#### 环境总览卡

每张卡片字段：

- 环境名称
- 环境类型
- provider 数量
- 最近 24 小时请求量
- 成功率
- 当前状态

示例文案：

- `开发版：已接入 6 个 provider，最近 24 小时成功率 96.8%`
- `心理疗愈生产版：仅国产模型，最近 24 小时成功率 99.2%`

#### 决策摘要卡

字段：

- 建议标题
- 建议类型
- 当前推荐对象
- 简短理由
- 更新时间

示例文案：

- `中转站续费建议：优先续费 Provider X，适合 Claude Code 主用上游`
- `国产替代建议：摘要任务建议切到模型 Y，预计成本下降 38%`

#### 风险提示卡

字段：

- 风险标题
- 风险级别
- 风险来源环境
- 简短说明

示例文案：

- `生产边界风险：检测到配置草稿中出现第三方中转占位`
- `观测风险：某 provider 最近 24 小时 usage 透明度不足`

#### 指标摘要卡

字段：

- 总请求数
- 总 token
- 平均延迟
- P95 延迟
- 错误率
- 估算成本

#### 最近运行记录卡

字段：

- run 名称
- run 类型
- 状态
- 运行时间
- 环境

### 1.3 空态 / 异常态

- 无数据：
  - `当前还没有可展示的运行记录，先从开发版 benchmark 开始`
- provider 异常：
  - 风险卡高亮，并在环境卡显示异常标记

### 1.4 页面跳转

- 点击环境卡 -> `Environments` 详情页
- 点击 provider 风险 -> `Providers` 对应详情页
- 点击决策摘要 -> `Eval / Recommendations`
- 点击运行记录 -> `Runs`

## 2. Environments

### 2.1 页面目标

让用户先按环境理解系统，而不是先按模型或 provider 理解系统。

### 2.2 环境卡列表

字段：

- 环境名称
- 环境类型
- 当前用途
- provider 范围摘要
- 当前状态

默认展示 3 张卡：

- `开发版`
- `心理疗愈生产版`
- `评测版`

### 2.3 单环境详情页结构

tabs 结构：

```text
Overview
Providers
Routes
Usage
Policies
Recent Runs
```

### 2.4 开发版详情页

首屏内容：

- 当前目标说明
- 当前接入的第三方中转数
- 当前接入的国产模型数
- 当前推荐主用上游

示例文案：

- `开发版优先服务 Claude Code / Codex，对比第三方中转与国产模型的真实编码代理表现`

### 2.5 生产版详情页

首屏内容：

- 产品名称
- provider 范围说明
- 当前任务类型分流摘要
- 风险提示

必须出现的文案：

- `当前生产版只允许国产模型`

### 2.6 评测版详情页

首屏内容：

- 最近 benchmark 次数
- 最近日报状态
- 最新评分板摘要

## 3. Providers

### 3.1 页面目标

按上游治理视角看 provider，而不是按“模型商店”视角看 provider。

### 3.2 provider 列表字段

- 名称
- 类型
- 可用环境
- 健康状态
- usage 透明度
- 最近错误率
- 最近 P95 延迟
- 当前适用建议

### 3.3 筛选条件

- 按类型筛选
- 按环境筛选
- 按健康状态筛选
- 按透明度筛选

### 3.4 provider 详情页四块结构

#### 基本信息

- 名称
- 类型
- 所属环境
- 简短描述

#### 支持模型

- 模型列表
- 每个模型的当前推荐用途

#### 最近 24 小时运行指标

- 请求量
- 平均延迟
- P95 延迟
- 错误率
- usage 字段完整度

#### 当前适用建议

示例文案：

- `适合作为 Claude Code 主用`
- `适合作为低成本备选`
- `不建议进入生产`

### 3.5 空态 / 异常态

- 无 provider：
  - `当前环境还没有接入 provider`
- usage 不透明：
  - 明确标注 `透明度不足`

## 4. Eval

### 4.1 页面目标

让评测结果可以被独立查看，而不是藏在日志或 provider 页面里。

### 4.2 顶层子页

- `Scoreboard`
- `Comparisons`
- `Recommendations`
- `Reports`

### 4.3 Scoreboard

字段：

- 任务类型
- 模型 / provider
- 质量评分
- 稳定性评分
- 成本效率评分
- 总结结论

默认分区：

- 编码代理任务
- 心理疗愈业务任务

### 4.4 Comparisons

字段：

- 比较对象 A
- 比较对象 B
- 任务类型
- 主要差异
- 当前推荐

示例文案：

- `中转 A 在 Claude Code 流式稳定性上优于中转 B`
- `国产模型 Y 在摘要任务上性价比优于模型 Z`

### 4.5 Recommendations

字段：

- 建议类型
- 当前建议
- 影响范围
- 简短依据
- 更新时间

建议类型至少包含：

- 中转站续费建议
- 任务级国产替代建议

### 4.6 Reports

字段：

- 报告名称
- 报告类型
- 生成时间
- 状态
- 摘要

## 5. 占位模块

这些模块本轮只写页面目的和首屏占位内容。

### 5.1 Routes

页面目的：

- 未来承接模型路由与任务分流视图

首屏占位文案：

- `Routes 将用于展示模型到 provider 的映射，以及任务类型到模型的分流策略。v1 静态壳不含真实编辑能力。`

### 5.2 Usage

页面目的：

- 未来承接 tokens、延迟、错误率和成本的详细视图

首屏占位文案：

- `Usage 将用于展示按环境、provider、任务类型拆分的使用统计。v1 先在 Dashboard 中展示摘要。`

### 5.3 Policies

页面目的：

- 未来承接生产边界、provider 白名单和日志策略

首屏必须出现的文案：

- `心理疗愈生产版默认只允许国产模型`
- `开发版观测策略不得直接复用于生产`

### 5.4 Runs

页面目的：

- 未来承接 benchmark、日报和探活的执行记录

首屏占位文案：

- `Runs 将用于追踪评测 sidecar 的执行记录与失败原因。v1 首页只展示最近运行摘要。`

### 5.5 Settings

页面目的：

- 未来承接只读环境配置与系统信息

首屏占位文案：

- `Settings 仅承接环境信息与系统配置概览。v1 不提供真实编辑能力。`

## 6. 通用页面状态

核心页面至少都要考虑下面这些状态：

- 正常
- 无数据
- provider 异常
- 配置越界风险
- 推荐结论已生成

## 7. 一句话结论

这份线框文档的目的，是让实现者无需再猜“这个控制台首页该放什么、详情页该怎么看、哪些页面先做、哪些页面只占位”，从而可以直接开始搭控制台静态壳。
