## 1. 本轮产品收口

`RelayHub` 当前不再以“只读模型目录试用版”作为主路径。

本轮正式收口为：

- 产品身份仍是治理控制台
- 第一条主路径是“添加模型并激活”
- 在此基础上补齐任务绑定模型与运行记录驱动的基础统计
- 旧的 `/providers` 只读 trial 保留，但降级为支持能力

## 2. 顶层模块优先级

本轮控制台默认优先级固定为：

1. `模型库`
2. `任务库`
3. `运行记录`
4. `Dashboard`
5. `外部模型源（原 /providers trial）`
6. `Environments / Eval / Routes / Usage / Policies / Settings`

旧的 Dashboard-first 叙事不再作为首页心智。

## 3. 第一主路径

用户进入控制台后，默认应完成以下路径：

1. 在模型库看到系统预置的首批 coding plan / 国产模型
2. 为某个条目补 API Key 并保存
3. 手动执行测试连接
4. 看到条目进入“已激活 / 可用”
5. 进入任务库，为某个任务绑定默认模型
6. 在运行记录页录入一次任务样本
7. 查看该任务下不同模型的基础统计

本轮不要求：

- 自动续费判断
- 自动余额识别
- 自动 benchmark
- 外部工具自动回传
- 复杂策略路由

## 4. 核心对象

本轮核心对象固定为：

- `模型预设`
- `模型实例`
- `任务模板`
- `任务运行记录`

模型状态固定为：

- `预置未激活`
- `已配置待测试`
- `测试通过可用`
- `测试失败`
- `已停用`

任务绑定固定为：

- 一个任务默认绑定一个主模型
- 可在控制台内切换
- 切换后只对后续新运行记录生效

## 5. 服务端边界

由于模型配置和 API Key 必须服务端保存，本轮正式新增最小 control plane（控制面）后端。

最小后端职责：

- 模型 CRUD
- API Key 脱敏存储
- 手动测试连接
- 任务 CRUD
- 运行记录 CRUD
- 任务统计汇总

前端职责：

- 管理界面
- 表单和状态展示
- 调用 control plane API

本轮不要求复杂数据库，允许先用服务端文件持久化。

## 6. 与旧 trial 的关系

旧的 OpenAI-compatible `/api/models` 只读链继续保留，但定位改为：

- 外部模型源接入验证能力
- 支持用户理解某个中转或目录里有哪些模型可见
- 不再代表产品主路径

默认 `main.tsx` mock 主入口不在本轮直接切换。
