## 1. 本轮目标

本轮把 RelayHub 从“模型清单 + 任务绑定”进一步收口为：

- 中转 API / 官方模型入口接入控制台
- 用户先保存一个可复用入口
- 再在任务库里切这个入口下当前默认使用的模型

本轮不做：

- 新的 control-plane 路由
- 全局当前模型
- 自动测评
- deployment / runtime seam 调整

## 2. 模型库职责

`/models` 继续作为默认入口，但本页第一任务改为：

- 看有哪些可直接接入的入口
- 通过购买链接完成充值或开通
- 补 Key 并完成测试连接
- 把这个入口变成可用入口

系统预置按“入口”组织，而不是按单个模型名组织。

这里的“入口”包括：

- 国产官方 API 入口
- 第三方中转入口
- 用户自定义中转 API

## 3. 预置入口约束

对系统预置条目固定约束：

- `baseUrl` 锁定
- `modelId` 锁定
- `kind` 锁定
- 允许补 `apiKey`
- 允许保存
- 允许测试连接
- 允许停用

原因是预置条目服务“零配置接入”，不要求用户自己研究 URL 和模型标识。

若用户需要完全自定义 URL / 模型标识，应使用“我的模型”新增自定义入口。

## 4. 任务库职责

`/tasks` 的第一任务固定为：

- 让用户看到每个任务当前默认走哪个入口内模型
- 需要时直接切换该任务当前默认使用的模型

任务绑定的产品语义固定为：

- 绑定的是“入口内默认模型”
- 不是全局当前模型
- 不是外部工具层面的 URL / Key 切换

外部工具只复用同一个入口配置；
具体切到入口下哪个模型，在 RelayHub 内部完成。

## 5. 与运行记录的衔接

`/runs` 继续沿用：

- 任务当前上下文
- 任务默认模型

运行记录页不成为新的模型切换中心，只负责顺手记录：

- 当前任务
- 当前入口下这次实际使用的模型
- 结果摘要与结果等级
