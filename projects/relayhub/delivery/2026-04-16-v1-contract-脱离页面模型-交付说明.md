这份文档用于把 `RelayHub` 控制台当前这轮 contract 脱离页面模型的结果交给下一棒实现者。

## 1. 本轮已交付内容

当前新增内容包括：

- `contracts/` 资源级 payload contract 已独立定义
- `contracts/base.ts` 的 `meta / envelope` 已泛型化，不再依赖页面 `ProviderFilters`
- `mocks/consoleApi.ts` 已切换到 contract 自有的 `ProviderFilterSnapshot`
- `services/consoleData.ts` 已显式承担 contract 到页面 model 的映射职责

## 2. 本轮仍明确不做

当前仍未实现：

- 更接近真实后端 wire format 的命名迁移
- 真实只读 API
- 页面层直接消费 contract 或 `meta`
- mapper 按资源继续拆文件
- 任何真实控制动作

## 3. 当前结构意图

当前控制台前端已经形成更稳定的四层边界：

- `contracts/`
  - 前端只读 raw response 契约
- `mocks/`
  - 本地 mock API response 生成
- `services/`
  - raw helper
  - contract 到页面 model 的解包映射
- `models/`
  - 页面稳定消费模型

这意味着下一棒如果继续做真实 API 对齐，可以优先改 contract 与 raw helper，而不需要先碰页面层。

## 4. 下一阶段建议切入点

下一棒建议按下面顺序继续：

1. 评估 contract 字段命名是否要向未来真实只读 API 靠拢
2. 评估是否把 `consoleData.ts` 的 mapper 按资源拆分
3. 再决定是否开始接真实只读 API

## 5. 一句话结论

当前 `RelayHub` 控制台已经把前端只读 contract 推进到“独立于页面 view model”的状态，下一棒更适合开始做真实只读 API 对齐准备，而不是继续补基础层分层。
