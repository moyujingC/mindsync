这份文档用于把 `RelayHub` 控制台当前这轮 contract 按资源拆分的结果交给下一棒实现者。

## 1. 本轮已交付内容

当前新增内容包括：

- `contracts/base.ts` 承载基础 contract
- `contracts/dashboard.ts / environments.ts / providers.ts / eval.ts`
- `contracts/index.ts` 统一导出入口
- `mocks / services / tests` 已切换到新的资源级 import

## 2. 本轮仍明确不做

当前仍未实现：

- 更接近真实 API 的命名迁移
- 真实只读 API
- 页面层消费 contract/meta
- contract codegen
- 真实控制动作

## 3. 当前结构意图

当前前端契约层已经形成：

- `contracts/base.ts`
  - 通用 envelope / meta
- `contracts/<resource>.ts`
  - 资源级响应契约
- `contracts/index.ts`
  - 聚合出口

这意味着下一棒如果要继续对齐真实只读 API，不需要先回头整理 contract 结构。

## 4. 下一阶段建议切入点

下一棒建议按下面顺序继续：

1. 评估更接近真实 API 的 contract 命名
2. 再决定是否开始接真实只读 API
3. 再评估页面层未来是否需要少量消费 `meta`

## 5. 一句话结论

当前 `RelayHub` 控制台已经把前端只读 contract 层推进到按资源可维护的结构，下一棒更适合开始考虑真实 API 对齐，而不是继续做基础层整理。
