这份文档用于把 `RelayHub` 控制台当前这轮前端只读 contract 层抽离结果交给下一棒实现者。

## 1. 本轮已交付内容

当前新增内容包括：

- `contracts/console.ts` 作为原始响应契约落位
- `models` 回到页面 view model 职责
- `mocks / services` 改为依赖 contract types
- raw helper 与页面 helper 的分层继续保持

## 2. 本轮仍明确不做

当前仍未实现：

- 真实只读 API
- contract codegen
- 页面层直接消费 contract/meta
- 资源级 contract 文件进一步拆分
- 任何真实控制动作

## 3. 当前结构意图

当前控制台前端已经形成更清晰的三层：

- `contracts/`
  - 原始响应契约
- `models/`
  - 页面稳定消费模型
- `services/`
  - raw contract helper + 页面解包 helper

这意味着下一棒如果继续推进真实只读 API 或 resource 级 contract 文件，都不需要先回头拆页面。

## 4. 下一阶段建议切入点

下一棒建议按下面顺序继续：

1. 将 `contracts/console.ts` 按资源继续拆分
2. 再评估是否需要引入更接近真实 API 的 contract 命名
3. 再决定是否开始接真实只读 API

## 5. 一句话结论

当前 `RelayHub` 控制台已经从“有契约语义”推进到“有独立前端只读 contract 层”，下一棒更适合继续做 resource 级 contract 整理，而不是再补基础稳定性。
