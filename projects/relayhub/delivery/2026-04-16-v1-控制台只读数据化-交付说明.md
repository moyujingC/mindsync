这份文档用于把 `RelayHub` 控制台“只读数据化”这一轮结果交给下一棒实现者。

## 1. 本轮已交付内容

当前新增内容包括：

- `console/src/models/console.ts`
- `console/src/mocks/consoleApi.ts`
- `console/src/services/consoleData.ts`
- `console/src/hooks/useAsyncResource.ts`

当前页面层变化包括：

- `Dashboard` 改为通过 service 层加载首页概览
- `Environments` 改为支持 `/:environmentId/:tab`
- `Providers` 改为支持 `/:providerId`
- `Eval` 改为支持 `/:tab`
- 核心页面已支持 loading / empty / not-found / mock-error

## 2. 本轮仍明确不做

当前仍未实现：

- 真实 Relay API
- 真实后端契约
- 真实鉴权
- 真实数据库
- 任何写操作

也就是说，当前交付物仍然是 `只读内部运营台`，不是 `真实控制面`。

## 3. 当前结构意图

当前前端结构已经从“页面直接读 fixtures”调整为：

- `models/`
  - 前端稳定消费类型
- `mocks/`
  - 本地 Promise-based mock API
- `services/`
  - 页面消费的数据访问层
- `hooks/`
  - 通用异步资源状态管理

这意味着后续如果要接真实 API，优先替换的是 `mocks/` 与 `services/`，不是重新改页面心智。

## 4. 下一阶段建议切入点

下一棒建议按下面顺序继续：

1. 将 `Providers` 筛选条件同步到 URL 查询参数
2. 为 `Dashboard` / `Providers` / `Eval` 补路由级自动化测试
3. 抽出 mock 数据到更接近真实契约的 response shape
4. 再决定是否引入真实只读 API

## 5. handoff 提醒

下一棒继续实现时，必须继续保持以下边界：

- 控制台是 `内部运营台`
- 数据层是 `只读`
- 心理疗愈生产版只允许国产模型
- 第三方中转不进入心理疗愈生产用户数据主链路
- 不新增任何真实控制动作

## 6. 一句话结论

当前控制台已经有了更稳定的数据消费层和可深链的核心页面，后续可以继续做“只读接近真实”的演进，而不需要重新拆页面或回退到直接读 fixtures 的实现方式。
