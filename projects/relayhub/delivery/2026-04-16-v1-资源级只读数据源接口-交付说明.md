这份文档用于把 `RelayHub` 控制台当前这轮资源级只读数据源接口抽离结果交给下一棒实现者。

## 1. 本轮已交付内容

当前新增内容包括：

- 统一的 `ConsoleReadonlyDataSource`
- 默认 mock 数据源实现 `mockConsoleDataSource`
- `consoleData.ts` 改为通过数据源接口读取 raw contract
- 数据源层独立测试已补齐

## 2. 本轮仍明确不做

当前仍未实现：

- 真实只读 API
- runtime 数据源切换
- payload 字段向后端 wire format 命名迁移
- 页面层直接消费数据源接口
- 任何真实控制动作

## 3. 当前结构意图

当前控制台前端已经形成更清晰的只读数据链路：

- `mockApi`
  - 当前 mock response 生成
- `mockConsoleDataSource`
  - 当前默认数据源实现
- `consoleData.ts`
  - 通过 datasource 读取 raw contract
  - 通过 adapter 适配 `ReadonlyApiResponse`
  - 通过 mapper 解包页面 view model

这意味着下一棒如果开始准备真实只读 API，只需要新增并接入新的 datasource 实现，而不需要先翻动页面层和 service 对外接口。

## 4. 下一阶段建议切入点

下一棒建议按下面顺序继续：

1. 选择首个真实只读 API 试点资源，优先 `providers` 或 `environments`
2. 为真实 datasource 设计最小切换方式
3. 再决定 mock / real 双实现的共存与验证策略

## 5. 一句话结论

当前 `RelayHub` 控制台已经把 raw contract 读取能力从具体 mock 实现中抽离成统一 datasource 层，下一棒更适合开始做真实只读 API 的首个接入准备。
