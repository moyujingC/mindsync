这份文档记录 `RelayHub` 控制台从静态壳推进到只读数据化后的验证结果。

## 1. 本轮验证范围

本轮验证对象为：

- `projects/relayhub/console/src/models/`
- `projects/relayhub/console/src/mocks/`
- `projects/relayhub/console/src/services/`
- `Dashboard`、`Environments`、`Providers`、`Eval`
- 核心深链路由与状态页

本轮不验证：

- 真实 Relay API
- 真实鉴权
- 真实数据库
- 真实网络请求
- 真实控制操作

## 2. 验证方式

### 2.1 构建验证

- 在 `projects/relayhub/console` 运行 `npm install --cache .npm-cache`
- 运行 `npm run build`

### 2.2 路由核对

人工核对以下深链：

- `/dashboard`
- `/environments/prod-aimandala/policies`
- `/providers/freebridge-sandbox`
- `/eval/recommendations`

### 2.3 状态核对

人工核对以下状态：

- loading
- empty
- not-found
- mock-error

其中 `mock-error` 通过 `?mock=error` 触发。

### 2.4 误导表达搜索

全文搜索以下关键词，确认只在“明确不做”语境中出现：

- `保存策略`
- `立即切流`
- `发布到生产`
- `启用自动路由`
- `编辑生产白名单`
- `立即应用配置`

## 3. 验证结果

### 3.1 数据层抽象

结果：通过

说明：

- 已新增稳定 view model
- 已新增 Promise-based mock API
- 页面层不再直接从原始 fixtures 读取核心展示数据

### 3.2 深链能力

结果：通过

说明：

- `Environments` 已支持 `/:environmentId/:tab`
- `Providers` 已支持 `/:providerId`
- `Eval` 已支持 `/:tab`
- 非法 tab 会进入 not-found 表达，而不是 silently fallback

### 3.3 状态覆盖

结果：通过

说明：

- loading：核心页面异步资源加载时可见
- empty：provider 筛选为空时可见
- not-found：环境 / provider / 非法子页深链可见
- mock-error：`?mock=error` 可触发页面级错误态

### 3.4 边界表达

结果：通过

说明：

- 心理疗愈生产版仍明确写出“只允许国产模型”
- 页面未引入任何真实控制动作
- 占位页仍为只读占位页

## 4. 当前残留风险

1. 当前 service 层仍然是前端本地 mock，不代表未来真实后端字段可以直接复用。
2. `Providers` 的筛选条件仍然保存在页面本地 state，尚未进入 URL 查询参数。
3. 当前没有自动化路由测试，深链仍以人工核对为主。

## 5. 结论

当前控制台已从“直接读取 fixtures 的静态壳”推进到“通过只读数据层取数、支持核心深链和状态表达”的内部运营台，可作为下一阶段接入只读 mock 契约或真实后端只读接口的稳定前端入口。
