## 1. 验证目标

确认模型库主路径已经从“填表技术动作”收口为“激活一个可用模型”的明确路径。

## 2. 自动化验证

### console

- `cd projects/relayhub/console && npm test`
- `cd projects/relayhub/console && npm run build`

至少覆盖：

- `/models` 首屏突出激活路径
- 保存后提示“下一步测试连接”
- 缺少 API Key 时测试失败原因明确
- Base URL 非法时测试失败原因明确
- 测试成功后提示“可去任务库绑定”
- 有 `purchaseUrl` 的预置模型可见购买 / 充值入口

### control-plane

- `cd projects/relayhub/control-plane && npm test`

至少覆盖：

- 缺少 API Key -> `test-failed` + 原因明确
- 非法 Base URL -> `test-failed` + 原因明确
- 测试通过 -> `active` + 成功语义明确
- mock 与 server 结果语义一致

## 3. Release Smoke

验证入口：

- [relayhub.jingshu.cc/models](https://relayhub.jingshu.cc/models)

至少执行两条路径：

### 成功路径

1. 选择一个预置模型
2. 补 API Key
3. 保存配置
4. 测试连接
5. 看到“已激活，可去任务库绑定”

### 失败路径

1. 缺少 API Key 或故意填错 Base URL
2. 触发测试连接
3. 页面显示清楚的失败原因
4. 页面提示下一步修正动作

## 4. 通过标准

- 用户可以区分“已保存配置”和“已激活”
- 页面能明确说明失败原因，不要求用户自己猜
- 激活成功后，下一步自然导向任务绑定
