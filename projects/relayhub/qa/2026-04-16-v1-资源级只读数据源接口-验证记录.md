这份文档记录 `RelayHub` 控制台在抽出资源级只读数据源接口后的验证结果。

## 1. 本轮验证范围

本轮验证对象为：

- `services/consoleDataSource.ts`
- `services/mockConsoleDataSource.ts`
- `services/consoleData.ts` 对数据源接口的复用
- `consoleDataSource.test.ts`
- 现有 `consoleData.test.ts`、`readonlyApiAdapters.test.ts` 与 `routes.test.tsx`

- 运行 `npm test`

## 3. 验证结果

### 3.1 数据源接口层

结果：通过

说明：

- 已新增统一的 `ConsoleReadonlyDataSource`
- 已新增默认 mock 数据源实例与获取函数
- 四类资源均已纳入数据源接口覆盖

### 3.2 service 依赖切换

结果：通过

说明：

- `consoleData.ts` 已不再直接依赖 `mockApi`
- raw helper 改为通过默认数据源读取 `Contract*`
- `ReadonlyApiResponse()` helper 与页面 helper 对外语义保持不变

### 3.3 自动化与构建

结果：通过

说明：

- `npm test` 已通过，共 `45` 条测试全部通过
- 新增 `consoleDataSource.test.ts` 共 `7` 条测试
- `consoleData.test.ts`、`readonlyApiAdapters.test.ts` 与 `routes.test.tsx` 继续通过
- `npm run build` 已通过

### 3.4 边界表达

结果：通过

说明：

- 默认数据源仍固定为 mock 实现
- 未引入真实只读 API
- 未新增任何真实控制动作
- 心理疗愈生产版“只允许国产模型”和只读运营台边界未被改写

## 4. 当前残留风险

1. 当前数据源入口已独立，但仍只有 mock 实现，尚未验证未来真实只读 API 实现与该接口的匹配度。
2. `getConsoleReadonlyDataSource()` 目前固定返回 mock 实例，后续引入真实实现时需要决定切换策略。
3. `Contract*`、`ReadonlyApi*` 与 datasource 层都已独立，后续若继续扩展，可能需要再评估目录归属与长期收敛方案。

## 5. 结论

当前 `RelayHub` 控制台已经把 raw contract 读取能力抽成统一的资源级只读数据源接口，下一棒更适合开始评估真实只读 API 的首个实现与切换策略。
