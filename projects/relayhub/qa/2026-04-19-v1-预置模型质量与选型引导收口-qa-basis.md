## 1. 验证目标

确认模型库和任务库已经从“用户自己猜先做什么”收口为“系统给出最小选型引导”的状态。

## 2. 自动化验证

### console

- `cd projects/relayhub/console && npm test`
- `cd projects/relayhub/console && npm run build`

至少覆盖：

- `/models` 首屏出现“优先激活候选”
- 预置条目显示适合任务、首选理由和激活提示
- 模型测试成功后提示可优先绑定的任务
- `/tasks` 任务行显示推荐候选
- 尚未绑定任务时出现推荐绑定提示
- 若无精确命中，则退回全部已激活模型

### control-plane

- `cd projects/relayhub/control-plane && npm test`

至少覆盖：

- `GET /models` 返回轻量预置引导字段
- mock 与 server 保持同一字段语义

## 3. Release Smoke

验证入口：

- [relayhub.jingshu.cc/models](https://relayhub.jingshu.cc/models)
- [relayhub.jingshu.cc/tasks](https://relayhub.jingshu.cc/tasks)

至少执行两条路径：

### 模型库路径

1. 进入模型库
2. 识别一个优先激活候选
3. 看懂适合任务、首选理由和下一步动作

### 任务库路径

1. 进入任务库
2. 找到一个尚未绑定任务
3. 看懂系统推荐先绑定哪些模型

## 4. 通过标准

- 用户不需要先理解内部技术细节，就能知道先激活谁
- 用户不需要自己猜，就能知道某个任务优先绑哪个模型
- 页面没有把引导表达成正式评测结论或自动最优结论
