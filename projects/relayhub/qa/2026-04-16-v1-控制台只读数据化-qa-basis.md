这份文档定义 `RelayHub` 控制台从静态壳推进到只读数据化后的最小验证口径。

当前阶段仍不验证真实后端，而是验证前端数据层抽象、深链能力和状态覆盖是否达标。

## 1. 目标行为

本轮应满足以下目标行为：

1. 页面层不直接 import 原始 fixtures
2. 核心页面通过只读 service 层取数
3. `Environments`、`Providers`、`Eval` 可通过 URL 深链进入指定上下文
4. 页面显式处理 loading / empty / not-found / mock-error
5. 内部运营台与只读边界表达不被削弱

## 2. 验收标准

### 2.1 数据层抽象

必须满足：

- 存在独立的 view model 类型定义
- 存在 Promise-based mock API
- 页面不再直接从 `fixtures/data.ts` 取核心展示数据

### 2.2 深链能力

必须满足：

- `/environments/prod-aimandala/policies` 能展示生产版 policy 视图
- `/providers/freebridge-sandbox` 能展示 provider 详情上下文
- `/eval/recommendations` 能直接展示推荐子页
- 刷新 URL 后页面状态不丢失

### 2.3 状态覆盖

必须满足：

- loading 状态可见
- empty 状态可见
- not-found 状态可见
- mock-error 状态可见

### 2.4 边界表达

必须满足：

- 心理疗愈生产版仍明确写出“只允许国产模型”
- 页面中不出现真实控制面误导表达
- 占位页仍为只读占位，不新增控制动作

## 3. 明确禁止的误导表达

仍然禁止出现：

- `保存策略`
- `立即切流`
- `发布到生产`
- `启用自动路由`
- `编辑生产白名单`
- `立即应用配置`

## 4. 验证方式

本轮至少执行：

1. `npm run build`
2. 路由级人工验证
3. 全文误导表达搜索
4. 页面状态人工核对

## 5. 通过标准

只有同时满足下面条件，才允许宣布本轮完成：

- 数据层抽象存在
- 深链 URL 可用
- 核心状态覆盖可见
- `npm run build` 通过
- 边界与只读约束未被改写
