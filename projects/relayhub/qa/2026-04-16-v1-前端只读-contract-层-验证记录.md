这份文档记录 `RelayHub` 控制台在抽出前端只读 contract 层后的验证结果。

## 1. 本轮验证范围

本轮验证对象为：

- `contracts/` 目录与原始响应契约
- `models` 与 `contracts` 的职责拆分
- `mocks / services` 对 contract types 的依赖方向
- raw helper 与页面 helper 的行为稳定性

## 2. 验证方式

### 2.1 自动化验证

- 在 `projects/relayhub/console` 运行 `npm install --cache .npm-cache`
- 运行 `npm test`
- 运行 `npm run build`

### 2.2 误导表达搜索

全文搜索：

- `保存策略`
- `立即切流`
- `发布到生产`
- `启用自动路由`
- `编辑生产白名单`
- `立即应用配置`

确认命中仍只出现在“明确不提供 / 不做”的说明语境中。

## 3. 验证结果

### 3.1 contract 分层

结果：通过

说明：

- 已新增 `contracts/console.ts`
- envelope / meta / resource 语义已从页面 model 中拆出
- `mocks` 与 `services` 现在依赖 contract types

### 3.2 行为稳定

结果：通过

说明：

- raw helper 继续返回原始 contract response
- 页面 helper 继续返回原有 view model
- 原有页面与路由测试继续通过

### 3.3 自动化与构建

结果：通过

说明：

- `npm test` 已通过，共 `26` 条测试全部通过
- `consoleData.test.ts` 继续覆盖 raw helper 与页面 helper
- `npm run build` 已通过

### 3.4 边界表达

结果：通过

说明：

- 页面层继续不直接 import `contracts/`
- 未引入任何真实控制动作
- 生产边界与只读边界未被改写

## 4. 当前残留风险

1. 当前 contract 仍是前端只读契约，不代表未来真实 API 会直接复用同名文件或类型。
2. `contracts/` 目前仍集中在单个文件中，后续资源继续增长时可能需要再拆分。
3. 页面层目前仍不消费 contract/meta，因此 contract 的长期稳定性还主要依赖测试约束。

## 5. 结论

当前 `RelayHub` 控制台已经把原始响应契约从页面模型中显式拆出，形成独立前端只读 contract 层，可作为下一阶段继续整理资源级 contract 文件或接近真实只读 API 的稳定基础。
