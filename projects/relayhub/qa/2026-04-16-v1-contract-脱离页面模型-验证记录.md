这份文档记录 `RelayHub` 控制台在将前端只读 contract 从页面模型依赖中解耦后的验证结果。

## 1. 本轮验证范围

本轮验证对象为：

- `contracts/base.ts` 的泛型化 `meta / envelope`
- `contracts/dashboard.ts / environments.ts / providers.ts / eval.ts` 的 payload contract 独立定义
- `mocks/consoleApi.ts` 的 contract `meta.filters` 填充
- `services/consoleData.ts` 的 contract 到页面 model 映射
- `consoleData.test.ts` 的 raw helper 与页面 helper 验证

## 2. 验证方式

### 2.1 自动化验证

- 在 `projects/relayhub/console` 运行 `npm install --cache .npm-cache`
- 运行 `npm test`
- 运行 `npm run build`

### 2.2 误导表达搜索

全文搜索：

- `保存策略`
- `立即切流`
- `发布到生产`
- `启用自动路由`
- `编辑生产白名单`
- `立即应用配置`

确认命中仍只出现在“明确不提供 / 不做”的说明语境中。

## 3. 验证结果

### 3.1 contract 与页面模型边界

结果：通过

说明：

- `contracts/` 已不再直接 import `models/console.ts`
- `ContractMeta` 与通用 envelope 已通过泛型承载可选 `filters`
- `providers` 的筛选快照改为 contract 自有的 `ProviderFilterSnapshot`

### 3.2 service 解包职责

结果：通过

说明：

- raw helper 继续返回 resource-level contract response
- 页面 helper 继续返回原有 view model
- contract 到页面 model 的映射逻辑已集中收束到 `consoleData.ts`

### 3.3 自动化与构建

结果：通过

说明：

- `npm test` 已通过，共 `28` 条测试全部通过
- `consoleData.test.ts` 新增页面 model 映射验证后继续通过
- `routes.test.tsx` 继续通过，页面行为未受影响
- `npm run build` 已通过

### 3.4 边界表达

结果：通过

说明：

- 未引入真实只读 API
- 未新增任何真实控制动作
- 心理疗愈生产版“只允许国产模型”和只读运营台边界未被改写

## 4. 当前残留风险

1. 当前 contract 已独立于页面 model，但字段命名仍沿用前端只读语义，尚未开始与未来真实只读 API 命名对齐。
2. `consoleData.ts` 现在承接了显式映射职责，后续若资源持续增长，可能需要再评估是否按资源拆分 mapper。
3. 当前 contract 稳定性仍主要依赖本地 mock 与单元测试，尚未进入真实 API 对齐验证。

## 5. 结论

当前 `RelayHub` 控制台已经把前端只读 contract 从“独立落位”推进到“独立于页面 view model”，下一棒更适合开始评估更接近未来只读 API 的命名或 raw contract 对齐策略。
