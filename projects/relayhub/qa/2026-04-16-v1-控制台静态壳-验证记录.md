这份文档记录 `RelayHub` 控制台静态壳首轮实现后的验证结果。

它不替代 `qa basis`，而是说明本轮代码实现是否满足已经定义好的页面结构、边界表达和误导风险质量门。

## 1. 本轮验证范围

本轮验证对象为：

- `projects/relayhub/console/`
- 顶层导航与布局壳
- `Dashboard`
- `Environments`
- `Providers`
- `Eval`
- `Routes` / `Usage` / `Policies` / `Runs` / `Settings` 占位页

本轮不验证：

- 真实 Relay API
- 真实鉴权
- 真实数据库
- 真实生产配置编辑
- 真实 benchmark 执行链路

## 2. 验证方式

### 2.1 构建验证

- 在 `projects/relayhub/console` 运行 `npm install`
- 运行 `npm run build`
- 目标是确认 TypeScript 与 Vite 构建通过，静态壳可被正式打包

### 2.2 人工结构校验

按 `qa basis` 逐项检查：

1. 顶层导航是否完整
2. 首页是否先展示环境总览
3. `Environments` 是否是导航枢纽
4. 开发版与生产版是否显式分离
5. `Eval` 是否是一级模块
6. 是否存在会误导为真实控制面的按钮或文案
7. 是否覆盖正常 / 异常 / 无数据 / 越界风险 / 已生成建议五类状态

## 3. 验证结果

### 3.1 导航完整性

结果：通过

说明：

- 顶层导航包含 `Dashboard`、`Environments`、`Providers`、`Routes`、`Usage`、`Eval`、`Policies`、`Runs`、`Settings`
- 4 个核心页面为有内容的静态页
- 5 个占位页均明确表达“页面目的 + 未来承接信息 + v1 不做事项”

### 3.2 环境优先心智

结果：通过

说明：

- `Dashboard` 首屏先展示环境总览卡
- `Environments` 页面以 3 类环境卡作为导航枢纽
- 页面没有把生产版表达成 provider 过滤结果

### 3.3 开发版与生产版边界

结果：通过

说明：

- `dev-relay` 与 `prod-relay/aimandala` 在环境页里显式分离
- 开发版 provider 范围中出现第三方中转，仅出现在开发版语境下
- 心理疗愈生产版明确写出“只允许国产模型”
- 页面没有暗示第三方中转可直接进入心理疗愈生产主链路

### 3.4 Eval 一级模块

结果：通过

说明：

- `Eval` 为一级导航
- 页面独立承接 `Scoreboard`、`Comparisons`、`Recommendations`、`Reports`
- 推荐结论不依附 provider 详情页存在

### 3.5 静态状态覆盖

结果：通过

说明：

- 正常状态：开发版、国产 provider、已生成日报
- provider 异常：`Atlas Relay` 风险状态
- 无数据：`Freebridge Sandbox` 无 24 小时样本、周报空态、生产版 Recent Runs 空态
- 配置越界风险：生产边界风险卡与生产环境风险状态
- 推荐结论已生成：Dashboard 决策摘要与 Eval Recommendations

### 3.6 误导风险检查

结果：通过

说明：

- 页面未出现“保存策略”“立即切流”“发布到生产”“启用自动路由”等误导性操作文案
- 占位页明确声明本轮不提供真实控制或可写操作

## 4. 当前残留风险

1. 当前仅完成静态壳，尚未验证真实 API 数据结构是否能无缝映射到当前 fixtures 形态。
2. `Environments` 的详情页 tabs 目前是本地前端状态，不是独立 URL；若后续要支持深链，需要补路由方案。
3. 当前没有截图回归或自动化 UI 测试，样式回归仍需后续补齐。

## 5. 结论

当前控制台静态壳已满足 v1 `qa basis` 中对结构、边界与误导风险的要求，可作为下一阶段接入真实数据层与控制台后端骨架的稳定前端起点。
