## 1. 背景

`怀瑾握瑜` 已完成项目立项与初步可行性研究，但尚未形成可执行的 MVP 范围定义。

当前需要把“中年转型职业梳理与叙事重建”从方向性判断，转成第一版可交付产品边界。

## 2. 问题定义

目标用户往往拥有复杂、跨阶段、难解释的履历。

他们当前的问题不是“缺一个简历模板”，而是：

- 难以把真实经历梳理成连贯叙事
- 难以解释转型、空档、失败和多角色经历
- 不信任泛化 AI 简历工具会忠实表达自己

## 3. 目标用户

第一版聚焦：

- 35+ 中年转型或再就业人群
- 有复杂履历、空档期、跨行业经历或角色断裂
- 愿意投入时间做深度梳理，而不是只想秒速生成结果

## 4. 用户场景

核心场景：

1. 用户第一次进入系统，希望梳理自己复杂经历。
2. 用户通过对话逐步补全时间线与关键事件。
3. 系统帮助用户形成一版初步职业叙事。
4. 用户对叙事结果进行修正，并沉淀为后续材料的基础资产。

更具体地说，第一版只覆盖一个主路径：

1. 用户带着“我要准备下一轮求职 / 转型表达”的目标进入。
2. 用户先完成基础背景采集。
3. 用户完成一轮引导式职业梳理对话。
4. 系统生成时间线摘要、叙事主线和待补信息。
5. 用户对结果进行确认或修订。
6. 系统输出一份可继续使用的职业资产初稿。

## 5. 本轮目标

第一版 MVP 只验证三件事：

1. 用户是否愿意通过对话完成职业梳理。
2. 系统是否能生成一版让用户认可的职业叙事初稿。
3. 这套流程是否能沉淀成可复用职业资产，而不是一次性输出。

## 6. 本轮不做

- 不做完整简历模板市场
- 不做多平台一键投递
- 不做复杂会员体系
- 不做长期记忆自动学习闭环
- 不做 B 端咨询师工作台
- 不做多个求职材料类型同时生成
- 不做复杂权限系统和团队协作

## 7. 方案说明

MVP 建议围绕一个对话式流程：

1. 用户输入基础背景与当前目标。
2. 系统按阶段追问经历、转折、成果、空档与转型动机。
3. 系统生成：
   - 职业时间线摘要
   - 叙事主线初稿
   - 需要补充的信息清单
4. 用户对结果进行修订确认。

第一版交付物优先为结构化文本，而不是复杂 UI。

第一版建议产出以下 4 类核心结果：

1. `profile`
   - 用户当前目标、目标岗位方向、核心约束
2. `timeline_summary`
   - 按阶段整理的职业经历摘要
3. `narrative_draft`
   - 一版可读的职业叙事主线
4. `follow_up_questions`
   - 当前还需要用户补充的信息

## 8. 用户流程

第一版默认流程分为 5 步：

1. `intake`
   - 输入基础身份、当前目标、主要困扰
2. `exploration`
   - 通过问答梳理关键经历、转折、成果、空档和动机
3. `structuring`
   - 形成时间线摘要和叙事线索
4. `review`
   - 用户修正不准确或不满意的内容
5. `export`
   - 输出一份职业资产初稿

各步输入输出：

- `intake`
  - 输入：用户基础背景
  - 输出：初始 profile
- `exploration`
  - 输入：profile + 用户问答
  - 输出：原始经历材料
- `structuring`
  - 输入：原始经历材料
  - 输出：timeline_summary + narrative_draft + follow_up_questions
- `review`
  - 输入：用户反馈
  - 输出：修订后的 narrative_draft
- `export`
  - 输入：修订确认后的结果
  - 输出：可保存的职业资产初稿

## 9. 成功判定

本轮成功不以“代码量”衡量，而以以下结果衡量：

1. 团队能基于同一份 spec 讨论范围，不再各自理解不同。
2. MVP 主路径足够清楚，可以直接写技术方案和验证清单。
3. 至少能用 2 到 3 个模拟样本走通从 intake 到 export 的纸面流程。

## 10. 关键 trade-off

1. 先做深度梳理，不先追求花哨输出。
2. 先做人工可验证流程，不先做高度自动化。
3. 先验证用户信任和结果质量，不先扩展场景宽度。
4. 先沉淀结构化职业资产，不先追求多种最终材料格式。

## 11. 验收标准

1. 存在一条完整的用户梳理流程定义。
2. 系统能产出时间线摘要与叙事主线两类核心结果。
3. 用户可以对结果进行修正，而不是只能被动接受。
4. 结果能沉淀为后续材料的基础资产。
5. 文档中明确写出输入、输出、主路径和不做范围。

## 12. 默认决策

基于当前阶段的最小实现原则，本轮先采用以下默认决策：

1. 第一版职业资产初稿采用 Markdown 结构化文档输出。
2. 用户修订采用自由文本反馈为主，不做字段级复杂编辑。
3. 首轮验证优先使用仓库内模拟样本，后续再补匿名化真实样本。

第一版 `career_asset` 默认包含以下部分：

1. 当前目标与方向
2. 职业时间线摘要
3. 叙事主线初稿
4. 待补信息与下一步建议

## 14. 核心领域实体字段定义

### 14.1 profile（用户画像）
- `current_goal`：用户当前核心目标（如"准备产品经理岗位转型求职"、"梳理10年工作经历准备内部晋升"）
- `target_role`：目标岗位/方向（自由文本，不做强制枚举）
- `core_constraints`：用户核心约束（如"期望薪资不低于30万"、"不考虑996工作"、"地点限制在长三角"）
- `main_pain_points`：用户当前主要困扰（如"不知道怎么解释2年创业空档期"、"跨行业经历找不到叙事主线"）
- `years_of_experience`：工作年限（数字）
- `industry_backgroud`：过往行业背景（可多个）

### 14.2 timeline_summary（时间线摘要）
按时间倒序排列的阶段列表，每个阶段包含：
- `period`：时间段（如"2020.03 - 2023.12"）
- `company`：公司/组织名称
- `role`：担任角色
- `key_achievements`：核心成果/贡献（3-5条要点）
- `key_challenges`：遇到的关键挑战
- `exit_reason`：离开原因/阶段结束原因
- `growth`：该阶段获得的核心成长

### 14.3 narrative_draft（叙事主线初稿）
- `core_positioning`：用户核心职业定位（1句话总结）
- `core_competencies`：核心能力矩阵（3-5个核心能力，每个配1个实际案例支撑）
- `career_arc`：职业发展脉络（连贯的段落式叙事，解释职业选择的内在逻辑）
- `transition_rationale`：转型动机与合理性说明（如果有转型/空档）
- `unique_value`：独特价值主张（相对于同赛道竞争者的差异化优势）

### 14.4 follow_up_questions（待补信息清单）
- `high_priority`：高优先级需要补充的信息列表（影响叙事完整度的关键信息）
- `medium_priority`：中优先级需要补充的信息列表（优化叙事质量的信息）
- `low_priority`：低优先级需要补充的信息列表（锦上添花的细节信息）
- `suggestions`：后续优化建议

## 15. 对话流程交互规则

### 15.1 基础规则
- 每次提问最多不超过3个问题，避免用户信息过载
- 问题应循序渐进，从基础信息到深层经历，再到动机与反思
- 允许用户随时中断流程，跳转至之前的阶段修改信息
- 允许用户随时要求查看当前已生成的部分结果

### 15.2 追问策略
- 当用户回答模糊时，追问具体案例和数据（如"你提到带领团队完成了重要项目，可以具体说说项目规模和最终成果吗？"）
- 当用户提到空档期、转型、失败经历时，温和追问背后的原因和收获，避免评判性语气
- 当用户提到的成果缺乏上下文时，补充追问背景（如"你当时是在什么情况下主导这个项目的？遇到的最大困难是什么？"）

### 15.3 边界规则
- 不追问与职业梳理无关的个人隐私信息（如婚姻状况、健康状况、宗教信仰等）
- 不替用户做价值判断，不贬低用户过往经历
- 不编造用户没有提到的经历或成果
- 明确告知用户所有信息仅用于生成职业梳理结果，不会用于其他用途

## 16. 敏感数据处理规则

### 16.1 存储规则
- 所有用户职业信息必须加密存储
- 不存储用户的真实姓名、身份证号、具体公司名称等可直接识别个人身份的信息（第一版默认采用匿名化处理，用户可自主选择是否填写真实信息）
- 用户有权随时删除自己的所有数据，删除后不可恢复

### 16.2 访问规则
- 只有用户本人可以访问自己的职业资产
- 系统后台不提供未授权访问用户数据的入口
- 所有数据访问操作都有日志记录

### 16.3 使用规则
- 用户数据仅用于生成该用户的职业梳理结果
- 不会将用户数据用于训练模型或其他用途，除非获得用户明确授权
- 不会向任何第三方泄露用户数据


## 13. 依赖与风险

依赖：

- 后续技术方案明确数据结构、对话流程和存储边界
- QA 文档明确人工验证与未来自动化测试切入点

风险：

- 梳理流程过长导致用户流失
- 叙事结果过度修饰而失真
- 对敏感职业信息的处理边界不清
- 用户给出的原始信息过于碎片，导致第一版难以直接结构化
