# HANDOFF：商业诊断 → 服务设计
## 1. 背景
- 任务背景：以用户为首个超级用户案例，完整跑通"职业梳理→简历生成→投递→反馈→迭代"全链路，验证产品假设并沉淀真实服务经验
- 所属项目：怀瑾握瑜（aicareer）- 职业成长服务平台
- 当前阶段：商业诊断已完成，进入服务设计阶段
## 2. 继承锚点
- 不变的项目锚点：
  - 怀瑾握瑜项目整体定位：为用户提供专业的职业成长服务，打造"AI+人工"的混合服务模式
  - 超级用户案例的核心目标：验证产品假设、沉淀服务经验、打造成功案例
- 本轮任务级别：局部实验（首个超级用户案例，不作为通用产品需求直接上线）
## 3. 本轮已确认结论
1. 商业价值判断：该服务投入产出比极高，非常值得继续推进
   - 低投入：仅需将现有产品能力在真实场景中跑通，无需额外开发大量新功能
   - 高回报：同时获得真实用户反馈、沉淀服务经验、打造成功案例三重价值
   - 低风险：即使服务效果不达预期，也能获得宝贵的失败经验，避免后续更大投入浪费
2. 服务边界明确：
   - 产品负责环节：信息提取、简历生成、内容优化、匹配分析、问题建议、数据记录
   - 人工负责环节：战略判断、亮点挖掘、策略制定、反馈分析、情绪支持
   - 禁止产品化内容：定向内推、简历造假、代面试、offer承诺
3. 优先级与验证指标已定义：
   - 明确了各阶段任务优先级排序
   - 明确了结果指标、过程指标、沉淀指标三类验证指标体系

## 5. 下游任务定义
- 建议交给谁：Product Spec Lead
- 需要产出什么：
  1. 超级用户陪跑服务流程spec（明确每个环节的输入、输出、负责角色、工具使用）
  2. 所需工具/能力清单（明确现有产品能力哪些可以直接使用，哪些需要临时补充）
  3. 交付物定义（明确整个服务过程中需要产出的所有文档、版本、记录的格式和要求）
- 验收标准：
  1. 服务流程完整覆盖"职业梳理→简历生成→投递→反馈→迭代"全链路
  2. 每个环节的责任人和产出清晰，没有模糊地带
  3. 工具/能力清单明确，不存在不可实现的要求
  4. 符合已定义的服务边界和优先级要求
## 6. 范围约束
- 本轮允许变化：
  1. 服务流程的具体步骤设计和顺序调整
  2. 工具/能力的具体选择和组合方式
  3. 交付物的具体格式和模板设计
- 本轮禁止改写：
  1. 已确认的商业价值判断结论
  2. 已定义的服务边界（哪些环节产品做、哪些人工做、哪些不能做）
  3. 已确定的优先级排序和验证指标体系
  4. 项目核心定位和超级用户案例的核心目标
