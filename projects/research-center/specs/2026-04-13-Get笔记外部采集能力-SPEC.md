## 1. 目标

为 `墨予镜` 补齐抖音、小红书、公开网页等外部内容的保存、搜索与召回能力，并把它纳入 `研究中心` 的正式工作流。

自 2026-04-15 起，研究中心正式治理名采用 `external-knowledge-intake`；本文保留的 `Get笔记` 语义，仅代表当前默认底层实现。

## 2. 非目标

- 不把 `Get笔记` 升格为公司正式主知识库
- 不把原始外部笔记内容整批镜像回 `mindsync`
- 不要求所有 agent 默认拥有该 skill

## 3. 标准链路

### 3.1 采集

外部内容先进入 `external-knowledge-intake`，当前默认底层实现为 `Get笔记`：

- `存到笔记 <链接>`
- `记一下：<文本>`
- `保存这张图到笔记`

### 3.2 召回

当需要继续处理时，由 agent 通过 `external-knowledge-intake` 在当前底层实现 `Get笔记` 中搜索或读取：

- `搜一下关于 <主题> 的笔记`
- `找最近收藏的 <平台/主题> 内容`
- `看看这条原文`

### 3.3 沉淀

召回后的内容必须二次转译为 `mindsync` 正式 artifact，例如：

- `research/`
- `specs/`
- `qa/`
- `delivery/`
- `kb/`

默认要求 agent 在输出中明确区分：

- 原始采集内容来自 `external-knowledge-intake` 当前底层实现 `Get笔记`
- 正式结论和交付物写回 `mindsync`

## 4. 角色分工

### 4.1 Research & Knowledge Lead

- 负责通过 `external-knowledge-intake` 完成外部内容采集与研究召回
- 将素材转成研究摘要、事实包、知识候选

### 4.2 Content Lead

- 负责通过 `external-knowledge-intake` 完成内容素材搜集、案例召回、选题池构建
- 不直接把外部素材当成成稿，仍需基于上游研究做转译

### 4.3 Engineer

- 负责本机挂载、Paperclip skill 同步、自动化接入
- 负责后续把召回结果接入脚本或工作流

## 5. 接口与配置

### 5.1 正式 skill

- 研究中心正式治理入口：`projects/research-center/skills/external-knowledge-intake/`

### 5.2 本机技能目录

- 当前默认底层实现：
  - Codex：`~/.codex/skills/getnote`
  - Claude Code：`~/.claude/skills/getnote`

### 5.3 Paperclip company skill

- source：当前仍优先使用 `getnote` skill 目录导入
- 目标 agent：
  - `Research & Knowledge Lead`
  - `Content Lead`
  - `Engineer`

### 5.4 环境变量

- `GETNOTE_API_KEY`
- `GETNOTE_CLIENT_ID`
- `GETNOTE_OWNER_ID`（可选）

若运行环境缺失前两项，agent 必须明确返回配置指引，不允许静默失败。

## 6. 风险与约束

- 当前底层实现 `Get笔记` 依赖外部 API 与会员能力
- 原始笔记属于外部系统，`mindsync` 仅沉淀必要结论与引用
- 隐私内容不应在群聊中直接展开
- 当前 company skill 导入来源使用本机完整目录时，Paperclip 侧识别的 runtime key 可能不是 `getnote`，实现与验证时应以实际同步结果为准

## 7. 验收标准

- `external-knowledge-intake` 已在研究中心正式建立
- Codex 本机可见 `getnote`
- Claude Code 本机可见 `getnote`
- 3 个目标 agent 已配置当前底层 `Get笔记` company skill
- 缺失 `GETNOTE_*` 时有明确报错与引导
- 至少形成一份正式 QA 记录和一份 delivery 记录
