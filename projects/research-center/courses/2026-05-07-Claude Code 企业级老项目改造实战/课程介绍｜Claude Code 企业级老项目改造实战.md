## AI 导学

老项目改造中，AI 常因上下文缺失而“帮倒忙”？关键在于建立可信协作机制。本课聚焦两大核心：一是通过 CLAUDE.md 与 SKILL.md 构建理解层与约束层，让 Claude Code 精准感知项目常识与禁区；二是以 Characterization Test 和分层验证筑牢质量底线，确保 AI 改动不破坏既有行为。三次实战覆盖公司内改造到开源贡献，完整演练从需求拆解、方案设计到 PR 提交的闭环流程，让你在真实存量系统中掌握 AI 时代工程师的核心能力——定方向、设边界、验结果，而非仅写代码。

## 课程介绍

### 为什么做这门课？

这是大多数工程师目前的真实处境：用 AI 编程工具从零搭建一个完整系统我会了，但公司里的项目都是跑了好几年的老系统，在这些项目的实际开发中，AI 编程工具总会改多或改少，也偶尔会改出 Bug，效果没有想象中好。 **这个现象不是因为 Claude Code 不行，而是你缺少体系化思路、用法。**

另一个现象同样普遍：AI 编程工具这两年层出不穷，Claude Code、Cursor、Copilot、CLAUDE.md、SKILL.md、Spec Kit、各种 MCP……很多人都在学，可看了一遍又一遍，感觉每个都懂一点，真开始改老代码还是用不好。 **这个问题不是因为工具太难，而是学工具和用工具之间差了一个真实场景。**

这门课程以企业级老项目改造为主线，会把所有 Claude Code 的工具和方法论放回它应该出现的场景里。在改造任务推进的过程中，用到哪个工具、为什么用、怎么用、用完怎么验证，全部在真实的改造语境里展开。有了 Claude Code 的辅助，效率也会直线提升。

我们会在课程中建立一套完整的质量保障体系，彻底解决你“不敢改造老项目”或“改造质量不稳定”等难题。

1. **保证你改造的下限和质量。** 在经验、熟练度、能力等还不够成熟的时候，课程中的方法论、流程、规范会保证你改造质量的下限，让你的系统不崩，实现小步快走。
2. **让你有一个明确的路径去积累和训练个人经验、熟练度、能力等。** 让你达到无视流程、规范也能把老项目改造好的程度，实现大步领跑。

### 这门课教什么？

- 沿着老项目改造的三种形式展开，收获三次改造实战训练。其中涉及的方法论、提示词、护栏等，全部回归“在存量系统上推进改动”的真实场景。
- 显式建立“工程师 vs Claude Code”的分工边界。写代码大量交给 Claude Code，但方向判断、约束设定、协作沟通由你完成，这是 AI 时代最值钱的工程能力。
- 从公司内到开源外。基于知名开源项目做需求，挑战开源给陌生项目贡献代码，简历上多一个开源 contributor 身份，为履历加分。

### 这门课不教什么？

- 不教架构设计。老项目改造的重点是“在现有架构下推进改动”，因此不会讲怎么把单体拆成微服务、怎么设计高可用架构。
- 不深入特定项目的技术细节。三个实战项目只是演示载体，会讲到它们的核心设计，够你理解改造就行，但不会陷入某个项目的具体技术栈。
- 不教怎么做一个厉害的产品。我们的目标不是做出多精深的作品，是把改造流程走清楚、把方法论落地，从而可以回归到你自己公司的项目里。

### 学完你会得到什么？

- 一套通用的企业级老项目改造方法论，面对任何陌生项目都能套用。
- 一份可复用的 Claude Code 提示词 SOP 文档，课程完结时独立交付。
- 三次真实的企业级项目改造经验，包括一次给开源项目提真实 PR 的外部贡献。
- 一种 AI 时代工程师的高效工作范式，借 Claude Code 提速落地，深耕 AI 无法替代的专业判断力与协作能力。
