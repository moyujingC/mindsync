## 那些经常被问到的问题

问题一：也是我经常被问到的一个问题，在 VibeCoding 过程中， 让 Codex 不断增加功能的时候，会感觉越来越混乱，Agent 似乎迷失在里面，不知道要做个什么东西，怎么办呢？

首先这个问题证明了大家已经不满足于用 Codex 做 demo，而是生产级的产品了。所以，如果你遇到了这个问题，我反而要恭喜你。

那么这个问题到底怎么解决呢？回答略长，且听二姐的小课堂：

经过问询之后，这位同学希望 Codex 复刻某个产品，并在此基础上，增加一些小优化。他的做法是：直接从零开始直接让 Codex 完成。

了解这个情况后，我判断引起这个现象的原因有两个：

一是从零搭建，没有选择成熟框架。框架不牢，后面越搭越重，原来的框架就撑不住了。

二是没有全局的文档维护，也就是没有使用 04 讲里的 Harness Skill 记录项目全貌，导致 Codex 在后面的任务中只见树木不见森林。

基于此，我建议按照以下步骤改进，这也是每次我们要 vibe code 一个完整项目前的准备工作：

![](https://static001.geekbang.org/resource/image/98/d1/98d64da721fa91e16921df67d2ac28d1.png?wh=1672x941)

第一步：先提取出项目中有用的东西。

就是让 AI 总结现在这个项目里面的功能，并且只写从用户角度能完成的功能、业务诉求，总结为 PRD.md 文档。因为在这个项目中，有用的内容是代码背后的业务诉求；而过于脆弱的代码框架是需要抛弃的，可以不总结。

第二步：重新定义需求。

在第一步之后，你会拿到一个 PRD 文档。这时，你需要重新审视这份需求列表，看看它是不是你真正想要的。同时找 5-10 个同类产品，进行竞品分析，就像我在 16 讲案例实战里一样。经过充分的竞品对比之后，你会对需求的把握更清晰，在此基础上完善这份 PRD 文档。

第三步：选择一个开源开发框架 -- 站在巨人的肩膀上。

大多数情况下，Vibe Coding 不需要从零开始，找一个成熟框架是非常重要的。 就像我们在第 4 讲选 SaaS 框架、第 11 讲选 Agent 的前后端框架一样。 在这里，你可以在 GitHub 搜索到 3-5 个框架。然后把框架的代码和上一步生成的 PRD 文档交给 Codex，让 Codex 调研各个框架的匹配程度和优缺点，据此来选择最合适的框架。

第四步：构建 Harness 环境

把选定的框架，PRD 放在一个项目中，让 Codex 使用课程 04 讲的 Harness Skill 构建出这个项目的工作车间环境——参考第 1 讲里，我对 Harness 这个车间环境要素的描述。

第五步：开始 VibeCoding

到此时，才开始按部就班的，遵照刚刚生成的任务列表，逐步完成。

所以你看，AI 目前的水平更侧重执行，而人要驾驭 ta，就需要给它提供明确诉求、完整框架以及可靠的 Harness 环境。这就是生产级项目的制作流程，比起 Demo 级的演示是不是你更有体会了呢。

问题二：如何学习我的课程？

在这门课上线后，我也遇到了很多新朋友想完整地阅读我的第一门《成为 AGI 产品经理》这个专栏，但又担心里面的内容过时了。那么我个人的推荐是这样读：

对于第一门《成为 AGI 产品经理》，你可以先把所有课程内容刷一遍，途中有听不懂的，先记下来，跳过去继续往前看。看完之后再检查你当初记下的问题。如果不理解，可以借助 AI 帮忙理解。这一门课程不需要跟着实战，因为实战所用的工具已经过时了，但我仍然推荐大家阅读全文，因为实战里穿插底层原理是没变的。

![](https://static001.geekbang.org/resource/image/0e/58/0ed7a445ee534d90c9963f1ab3a37e58.png?wh=1672x941)

对于新的这门《AGI 产品经理全栈指南》：我推荐你刷两遍。第一遍只阅读内容，不动手实践；第二遍可以跟着实战起来，你可以先挑自己感兴趣的，难度较低的案例开始，比如第二章、第 15 讲、第 16 讲的案例。当然你也可以只参考方法，而把其中的案例变换成你想要做的业务。做完 1-2 个小项目后，就可以开始做第 11-14 讲的 Agent 案例了。实战之后，相信你有更深刻的理解，做出自己的 AI 产品，然后参考第五章的内容做商业化尝试。

问题三：什么样的产品才能赚钱？

我的回答是：一个产品能否赚钱，主要依赖于用户是否需要它。请大家铭记：Vibe Coding 改变的只是开发产品的速度，而不改变需求发现的正确率。

![](https://static001.geekbang.org/resource/image/2a/f8/2a3e6548886cc8fdc1489072cd9831f8.png?wh=1672x941)

学完怎么开发产品后，你会发现：50% 的精力都是在寻找正确的需求。这一步走对了，后面 50% 的做产品、卖产品会更加顺手。 找需求可以参考第 02 讲、17 讲，相信能激发你不断想出对用户真正有用的产品。

在回答完这三个问题后，我也要感谢大家，正是大家的这些问题才让我在最初的迷茫中对课程的设计越来越清晰。

## 课程背后的设计思路

最开始收到蚂蚁集团的诉求时，我设计了一个过渡章节：那就是传统产品经理应该如何用 AI 写 PRD，如何做客户访谈，如何写竞品分析。

但在构思的过程中，我发现自己已经完全脱离了原来的软件开发流程，也就是传统 PRD 是为开发者写的，而 AI 的 PRD 应该是为 Coding Agent 写的。

所以，最好的 PRD 创作方式就是做 demo ，并融合在为产品构建 harness 工作环境的过程里。所以我在第二章展现了完全 AI native 式软件生产流程。事实证明，在两个月后，也就是课程全部写完的此刻， 这种工作方式正在被大家接纳。

从这一点出发，我把这门课定义为讲授更加前沿、而不是已经成熟的 AI 产品构建方法。因为 AI 时代的变化太快，跟随成熟的方案，意味着你可能已经落后了。

所以，你会看到：我们不止是在分享怎么用 Codex 做出产品，我们还会讲如何构建出类似 Codex 这样的 Agent 产品。比如：用 Hermes 这种开源框架大胆地改造 SaaS 产品，本质上就是在构建一个股票分析版的 Codex。

你还会看到：当大部分人在讲如何用 Codex+Obsidian 构建个人知识库的时候，我们已经在尝试把 LLM Wiki 应用在自己开发的 Agent 当中了。

除了前沿之外，我的另一个小心思是：怎么让大家的产品开始赚钱呢？

在职场，我从未关心过这件事，理所当然地以为那是销售的事情。但也因此，商业化成为我裸辞之后需要突破的最大瓶颈。我经常想，如果我在职场就提前考虑好这个问题，那我的第一个产品是不是就会更加面向付费需求，避开竞争激烈的红海来做呢？

所以，即使今天的你依然在职场，不需要为产品营业额背指标，我也强烈推荐你早日触发自己商业觉醒。

![](https://static001.geekbang.org/resource/image/50/60/500d9c555cb8e6ef6b3af2a23bb8bf60.png?wh=1672x941)

可以说，上面的两个构思也是这门课区别于其他课程最大的两个不同之处，即：

以更前沿的 AI 产品构建方法，使用 Codex 构建出像 Codex 那样的 Agent。

以更有预见性的商业思考，让你的 AI 产品早日走上致富之路。

有了这种前沿尝试，我相信你不再会因为 AI 产生的各种变化而恐惧，而是主动迎接。也只有在变化中，才会有更多机会。我也希望这门课，在我们课程社群的陪伴下，成为一个持续的有生命力的产品，伴随着大家始终走在 AI building 时代的前面！

最后，让我套用上一个专栏里的四句话，祝愿每一位学习这门课程的朋友：

![](https://static001.geekbang.org/resource/image/57/c7/575e79a7df8ffb6027ce7c57365562c7.png?wh=1672x941)

在不确定中看到机遇，

在探索中找到方向，

在挑战里获得成长，

在实践里创造财富！

这次，我们不要江湖再见，我们一直在微信群里陪伴！

——产品二姐
