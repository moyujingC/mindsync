## 亲手感受“原来上线可以这么简单”

还记得上一讲我们在 V0.App 里做的 demo 吗？现在打开它，看右上角——有一个 Publish 按钮。点下去。

![](https://static001.geekbang.org/resource/image/12/b5/1270yye2fc5d7dc1c95178645c4538b5.png?wh=1196x667)

30 秒之后，你会得到一个真实的 URL，它长这样：https://v0-event-material-generator.vercel.App/，它的域名是：.vercel.App。

有了这个域名，就意味着你的产品此刻运行在 Vercel.App 对应的服务器上，相当于你把服务托管给 Vercel —— 你不需要自己买服务器、不需要管硬件，只管写代码就好。你还可以把这个链接发给用户直接使用，比发视频的方式更加直接了。

这里需要说明一下：V0.App 就是 Vercel 在 2023 年发布的代码生成工具。Vercel 是著名前端框架 Next.js 的发起者，在 AI 革命之前，它就是一家云平台公司，为开发者提供代码托管、自动部署的服务。在 AI 革命之后，它上线了 V0.App（原来叫 v0.App），让开发者能通过自然语言直接开发应用，打通了应用开发、部署上线的全流程。

V0.App 几乎是全球最快能让你完成产品创建、上线的应用，因此受到众多用户的喜爱。到 2024 年，Vercel 平台上托管的应用超过 350 万个，每月处理的部署请求超过 10 亿次，全球超过 100 万名开发者把它作为首选部署平台，其中很大一部分是产品经理。

Jackie Bavaro，前 Google、Airbnb 的产品经理曾经公开了自己用 Vercel 独立构建了一款尤克里里 App 的全程记录：从想法到可交互原型花了 6 分钟；发现 Bug 到 AI 修复用了 1 分钟；完成“听音识别”功能用了 2 分钟。

这些时长虽然夸张，但她的结论不容忽视，那就是：“成本结构完全改变了。PM 不应该再预先削减需求范围，可以直接尝试。”

这与我在上一节说的观点是一致的，即“产品的成本被 AI 无限降低，所以论证 idea 本身，就是把产品 Demo 做出来，在用户使用中逐渐明确需求。”

那么，Vercel 背后到底做了什么，让部署上线如此简单呢？了解背后的过程也就是了解工业生产级的部署过程。

## 按下 Vercel 的 publish 按钮后会发生什么？

我们假设软件产品是一台印刷机，那么开发工程师的工作就是把机器做出来，而 DevOps 运维工程师的工作就是：

能让印刷机搬运到一个厂房，通上电能稳定运行；这个“厂房”就是能运行并存储代码的服务器。你可以租阿里云、AWS 的云服务器 ECS，它本质上就是一台性能更强、永远联网、不会关机的电脑。

把印刷记录以及印刷出来的成品很好地存储、管理起来。也就是在服务器上划出一块区域，并按照你的想法，构建出数据库，以便用户随时来登录、查询。

整个过程分七步：

第一步：进入工厂—— SSH 连接服务器

首先从阿里云或亚马逊购买云服务器 ECS，相当于你自己租了一个厂房。在这些云厂商的平台上，你需要生成一把打开服务器的钥匙，放在自己本地电脑上。拿着这把钥匙，你就可以在你的电脑上，打开服务器的大门，进入服务器操作了。至于如何配这把钥匙，可以在各个云厂商官网查到。比如阿里云的配置方式在 这里 可以看到。

这里的核心指令是：

ssh -p 22 root@YOUR\_SERVER\_IP

这里要注意：在不同操作系统的指令略有不同，以下所有指令仅供理解，使用之前你可以让 AI 根据你自己的情况确认后再运行。

进去之后，你就可以操作那台“云端电脑”了，只是操作的方式需要通过命令行来执行。这里要做的第一件事就是把代码复制到服务器上。

第二步：搬运印刷机——也就是把代码复制到服务器

我们通常不会把电脑里的代码直接“传”到服务器，而是借助 GitHub 这样的代码管理工具作为中转站。代码先推到 GitHub（git push），服务器再从 GitHub 把代码拉下来（git pull）。这样做的好处是：每一次改动都有历史记录，新版本出了问题可以迅速回退到以前的版本。

在服务器上运行的搬运指令核心就是这两条：

git clone https://github.com/your-org/your-App.git

git pull origin main

第三步：做好基建——安装印刷机运转需要的水电

代码本身只是印刷机，要运行还需要安装很多依赖库（比如水、电等），这就像你最开始在本机运行一样，核心指令是：

npm install

第四步：建好仓库保存往来用户信息以及印刷成品

我们所说的数据库就是这个“仓库”，专门存放用户信息、操作记录和 AI 生成的结果。

搭建数据库的核心指令比较多，你直接看示例代码，在具体做的时候，让 AI 帮你生成即可。

sudo apt install -y postgresql postgresql-contrib

sudo systemctl start postgresql && sudo systemctl enable postgresql

sudo -u postgres psql <<EOF

CREATE USER myApp\_user WITH PASSWORD '你的强密码';

CREATE DATABASE myApp\_prod OWNER myApp\_user;

GRANT ALL PRIVILEGES ON DATABASE myApp\_prod TO myApp\_user;

EOF

其实这一步在 V0.App 的代码生成过程中已经完成了，但是如果你要进行数据库的迁移或者从零创建，依然要完成这一步。

第五步：让厂房、印刷机、仓库彼此相认——设好环境变量

数据库地址、API Key 这些“原材料供应商的联系方式”不能写在你提交的代码里，而要在工厂里单独配置，这时候会使用到一些命令行来读写服务器上的环境变量，比如下面两个命令就是写入数据库密码和大模型服务的 API key。这些命令都可以让 AI 告诉你来完成。

export DATABASE\_URL="postgres://user:password@host/dbname"

export ANTHROPIC\_API\_KEY="sk-ant-..."

第六步：开机运转——启动服务

这就像你在本地运行一样，看看能不能在服务器上运转起来。

npm run build

npm start

第七步：挂上厂牌——配置域名，让客户找到你

机器跑起来了，最后需要把你的域名（如 myApp.com）指向这台服务器的 IP，让大家通过域名就能找到你。你可以在阿里云、godaddy、namecheap 等域名平台购买域名，按照他们的操作来执行即可。

这就是一次部署上线的全貌。你在 Vercel 里点一下 Publish，本质上就是把这七步并做了一个按钮。

虽然 Vercel 这种方式部署起来非常简单，但对于一定规模的 App 来说使用会有限制，以下情况不适合使用 Vercel，比如你需要支持实时长时间聊天、直播、游戏实时同步等功能，Vercel 目前是不支持的；如果需要这些能力，你得集成其他三方服务来完成。

又比如你的应用可能需要执行长时间任务，Vercel 最长支持 13 分钟的任务，举个例子如果你的产品需要让 AI 生成一个长视频，超过 13 分钟就会被强制打断。

另外我个人感受 Vercel 收费相对云厂商来说，是偏贵的。

总结来说：Vercel 是最好的起点，但不是终点。

那么，当 Vercel 不能满足你的需求时，就该换一条路了——自己租一台服务器，自己管。

在之前的七步操作中，你已经了解了大概的部署步骤，有了这个基础之后，你就可以借助 AI Coding 工具，加上专业的运维 Skill 和数据库管理 Skill，完成以上七步。接下来我们就看看如何让 Coding Agent 完成这七步。

需要提醒的是：对于重要的生产级别的应用，大家一定要找专业的运维工程师确认，保障安全。

## 工业级部署：携 Skill 以令“Agent”

其实上述的七个步骤让 AI 完成最简单的方法就是：让 Agent 基于一个优秀的 Skill 把这些步骤写进一个脚本文件，之后每次部署，运行这一个文件就够了。借此机会我也分享一下如何鉴别好的 Skill，以及怎么利用好 Skill。

首先，网上有大量的 Skill 平台，我在这里推荐两个：

一是：skills.sh，这个平台会自动扫描 GitHub 上公开发布的 Skill，只要满足一定条件就可以被展示。

二是：Anthropic 官方的 Skill 库 。

其次，甄别 Skill 最好的方法是直接安装，然后问 Claude Code/Codex，这个 Skill 可以做什么，看看它是否能满足你的诉求。如果不满足，在对应的目录下删除即可。

这节课，我们要完成代码部署和数据库创建，我会使用两个 Skill：

一是 devops-engineer skill ，在 GitHub 上有 9 千 Star，主要协助完成部署上线。

二是 supabase-postgres-best-practices skill ，主要完成数据库相关的任务。

下载安装之后，直接告诉 AI Coding 工具：

使用 devops-engineer skill，帮我创建一个部署脚本，让我以后运行这个脚本就能完成部署上线，途中遇到需要我提供的任何东西，请你告诉我。

还要完成数据库的初始化，创建数据库的时候，使用 supabase-postgres-best-practices skill 构建，并生成一个数据库初始化的脚本。

在你已经理解部署流程之后，顺着这个方向，就可以完成所有的部署、数据库搭建工作。

比如我自己项目的前端脚本长这样，你可以使用 AI 来读这段脚本的含义来理解。

set -e

PORT=22

SSH\_URL=root@< ip >

\# 连接服务器解压文件

\# ssh -p 22 root@< ip > "cd /www/server/x007/x007-web && rm -rf dist/ && unzip -o dist.zip && rm -rf dist.zip"

ssh -p $PORT $SSH\_URL "set -e; cd /App/book-skill/frontend; git clean -f public/favicon/; git pull; npm install; npm run export; cp nginx.conf /www/server/panel/vhost/nginx/html\_book2skills.com.conf && nginx -t && nginx -s reload"

## 日常运维：逐步自己搞定

到这里，我从一个产品经理的角度介绍了部署、上线的概念和思路。

无论你是通过哪种方式完成的，上线之后都需要持续更新、维护。你可以继续借助这两个 Skill 完成，在这里我也列出一些常用的指令，让你做到心中有数。

代码更新上线

git add.

git commit -m "fix: 修复登录按钮问题"

git push origin main

建新数据库（新功能需要新表时）

psql -U postgres

CREATE DATABASE myApp\_prod;

## 总结

最后，我们来总结一下整个章节所讲的内容。

而这一讲，我们让它可以面向公众使用。

三讲合在一起，就是一个产品从 idea 到真正上线的完整路径。走完之后，你就迈出了走向独立 AI 产品 builder 的第一步：学会使用 AI Coding 工具，构建端到端的应用，但这不足以让你构建出好的产品。
