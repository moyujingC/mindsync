你好，我是产品二姐。

如上一讲所说，接下来两节课，是个人开发者可以轻量上手的两个尝试。和企业相比，个人开发者能撬动的物力、人力资源有限，而且从需求发现到最后的宣传推广全部由 1-2 人负责。因此，如果你是刚刚起步的个人开发者，我建议你的产品，除了有用能解决痛点之外，还要满足以下三个条件中的两个条件：

赛道选择方面： 选一个新且会长期存在的赛道。这里的新不是说别人没做过，而是大部分人才刚刚入场，还没有形成稳定格局。

产品设计方面：只需要提供很短链路，就能让用户感受到效果。比如 AI 生图这个领域，个人开发者可以做个人写真照的生成，因为用户可以很快看到效果；但做电商商品详情的生图就不一定合适了，因为商家想要看到的效果是这个图片能给他带来收入，而商品生图只是电商商家运营过程中的一个小环节，商家单凭几张商品图是不能看出效果的。

产品运营方面：产品本身要能自运营。不需要倾注很大的运营成本。

今天和你分享的案例就是从以上三点出发来做的，也是我自己的产品 book2skills ——一个把书籍转化为 Agent Skill 的内容平台。

![](https://static001.geekbang.org/infoq/2f/2f58334c22daf975b94eaa176014e10c.png)

我用两天时间开发完成最初的版本后，在过去的三个月内，几乎零运营的情况下，流量在慢慢增长。而且，在我的规划中，它只完成了第一步，在把网站“养”一段时间后，我会在现在的版本基础上做升级。尽管目前 book2skills 还不能称为一个成功的产品，但其背后的故事却代表了典型的独立开发者的思维，并且非常适合第一次独立开发的同学体验。

![](https://static001.geekbang.org/infoq/f0/f0a074537fe1db9be7cd52c86ec77981.png)

接下来的内容会涵盖以下三个步骤：

从独立开发者角度，为什么要选择做这个产品，以及背后的产品定位决策。

book2skills 是如何实现的，尤其是其中的 skill 是如何通过编排 skill 提炼出来的，这种编排 skill 的方法在后续章节中也会用在营销内容生产上，是一种通用的方法。

book2skills 是如何做到自运营的。

学完这节课，你能初步体会独立开发者为自己做产品，和在职场为公司做产品相比有哪些不同。如果你有意向独立构建自己的产品，那么不妨带着这个思路，从这节课开始，去寻找类似的机会。

## 为什么做 book2skills？

book2skills 的想法源自一篇阅读量 2.5 万的公众号文章： pdf2app：把书变成可以玩儿的 APP ，文章受到的关注度也很高，文章中提到前半段是 pdf2skills，就是把 pdf 里的内容转换成 skills，可以让 Agent 使用，于是我萌发了把它产品化的想法。

但最终决定做这个项目，是考虑了以下几个因素：

Agent Skill 这个概念属于新赛道，处于快速成长期，且会长期伴随 Agent。

在我看来，Skills 某种程度上是 Anthropic 继 MCP 后提出的另一个标准，它不止是提示词，而是提示词 + 工具使用的融合，比如你可以在 Skill 里定义脚本，在 skill.md 里写入对工具使用的习惯和原则等等，而且它比 workflow 更加灵活。所以我判断它会长期存在，而不是短期热点。

现在回头再看 Agent skill 这个关键词在谷歌趋势中的热度，就会发现在当时已经很热的基础上，它的热度依然经历了很长时间的上升，证明了我的判断。

![](https://static001.geekbang.org/infoq/43/431bc8ebcafebb5591d1f1a09c68cf0f.png)

所以，除了选择刚刚起步的赛道之外，你还要有预判趋势的能力。在后面第五章，我会详细和你分享判断趋势与热度的方法。这里不作详述。

2\. 书籍是提取 Skill 的天然材料。

我们知道，Skill 是赋予 Agent 某种技能，书籍自古以来就是沉淀技能的最佳载体。特别是类似教你看财报、做营销等方法论的书籍，本身结构清晰、步骤明确，且经过出版社打磨，比其他类型的文档更适合被提炼成 Skill。而且在人类历史上，有非常多经久不衰的书籍，并不会随着时间流逝和技术进步被淹没。

3\. 书籍 × 行业，可以形成 SEO/GEO 关键词矩阵。

SEO（搜索引擎优化）对个人开发者来说，是最便宜的流量获取来源，如果网站的内容好，拿到 Google 搜索的首页排名，意味着每天都能免费吸引大量的用户进入你的网站。当然 SEO 并非易事，我们在第五章会详细讲述。

如果我不考虑 SEO，很可能会把 book2skills 做成一个工具：用户上传一本书，然后拿到一组 skill。这样做会有两个问题：

一是开发工作量会十倍增大：比如你要兼容上传文档的各种格式；为了保证 Skill 生成的质量，需要调用 Claude-agent-SDK 这类顶级 Agent；要有专门的云存储来保存用户上传的文档；提供 Skill 的转化任务管理等等。

二是你在推广的时候，大概会说：“这是一个能把任何书籍转换成 Skill 的工具”，那么你可以被搜索到的关键词就只有“book to agent skill”“agent skill”“convert book to skill”。作为一个要长期运营的网站，关键词不够丰富，不能形成矩阵效应。

而从 SEO 的视角看，我们需要把书名、行业都当做关键词。比如我会在《一本书读懂财报》的 Skill 页面，去贴合以下关键词或者问题：

《一本书读懂财报》有用吗？

如何用《一本书读懂财报》的方法解读 xxx 公司

《一本书读懂财报》里帮我判断是否有财务造假？

....

假设每本书可以衍生出 10 个问题，那么 N 本书的 Skill，就可以有 10 ✖️ N 个关键词或者问答。从行业来看，我们可以做书籍合集：比如个人理财的 10 本最佳书籍，用户增长的 10 本最佳书籍等。甚至我们也可以去切某些名人，比如巴菲特写的书籍，我可以切 “用巴菲特的方法投资”的主题。

这样，书籍 ✖️ 行业 ✖️ 名人，可以让你的产品具备强大的自运营效果，随着时间的积累，会自我增长起来。

所以最终，我把这个产品定位为 Skill 内容平台，而不是一个工具。这种流量驱动产品的思维，和用户驱动产品的思维，是两种完全不同的思路，虽然二者用到的技术是一样的，但换一个视角思考，你会构建完全不同的产品。

4\. Skill 库可以长出更大的东西。

最后一个因素再回来看商业成长性。个人开发者的商业变现主要有广告、订阅收费两种。

对于 book2skills 来说，随着 Skills 的积累和开源 Agent 框架的成熟，我们可以在 Skill 库上长出垂直行业的 Agent 应用，最终形成“Agent 应用 × 书籍 × 行业”的矩阵。一方面，它可以为行业 Agent 做广告，另一方面可以通过基于 Skill 生长出来的 Agent 做订阅收费。这是一件可以做很久的事。

综合以上四点，我们看到，个人开发者从最开始就要考虑产品的成长性、开发成本、运营成本等因素，从小切口进入，把 book2skills 定位为内容平台，而不是工具。确定这件事可做之后，接下来最重要的就是内容生产，在这里找到一个通用的方法，从书中提炼出 Skill。

## Skill 是怎么从书里“提炼”出来的

在这里我会使用 Claude Code 完成这件事情，也借此机会和你介绍，如何通过组合 Skills 构建工作流。因为我们是通过编排 Skill 而提炼出 book-skill，为了避免混淆，接下来的内容中，用 Skill 代表 Claude Code 中使用 Skill，用 book-skill 代表从书中提炼出来的技能。

首先我想以《一本书读懂财报》的 book-skill 为例，看看效果，也就是在同样的提示词下，使用 Skill 和不使用 Skill 的差别。示例中使用的是对腾讯控股的分析，因为内容太长，我放在这一讲的附录里。我对比了 10 份财报分析，并发给身边的二级投资基金经理，都得到明确的肯定。

接下来你可以看看《一本书读懂财报》的目录与 book-skill 的内容，并按照我的思路详细对比，体会一下其中的联系，然后我再和你分享我是如何生成这个 book-skill 的。

我们看到这本书目录的一级标题形成了书籍整体脉络：作者首先介绍了资产负债表、利润表、现金流量表，俗称财务三张表；其次讲了活用三张表；然后讲了影响财务的关键因素是行业；最后综合讲述了，从财务角度看，好公司的标准以及风险控制。

目录：

![](https://static001.geekbang.org/infoq/32/32dcb36023f8b3c72c74eb3fd7585123.png)

此时你可以假设，如果你看了这本书之后，你期待得到什么样的技能呢，我认为就是会看三张表，能发现其中的漏洞，能根据影响因素综合评价公司好坏，以及背后的风险。

按照这个思路，我们再来看最终生成的 Skill。

![](https://static001.geekbang.org/infoq/1c/1c6aa381f8e183e2f7b9695213c96964.png)

首先这个 Skill 是总分结构，有一个主 book-skill，有若干个子 book-skill，用 m1-m6 表示，分别代表不同章节里体现的技能；主 book-skill 是一个调度器，并不做具体的工作，而是会根据用户的问题，构建出不同的子 book-skil l 组合，比如用户问的是综合评估，那么就是把 m1-m6 这 6 个 subskill 都走一遍，如果用户只问和利润相关的问题，那就只调用对应 m3- 利润质量验证。

那么这样的 book-skill 是如何生成的呢，我也依次做了三种尝试，才确定了最终方法。

第一次尝试——整本直出。直接发送书籍给 Claude code，输入提示词“使用 /skill-creator 把这本书里的内容提取为 Skill”，这里的 /skill-creator 是 Anthropic 发布的元 Skill，也就是生成 Skill 的 Skill，元 Skill 是创建 Skill 的基础，关于元 Skill 你可以参考 anthropic 的官方内容 ，这里不做详述。但是这种方法生成的 book-skill 过于宏观。在仔细阅读书籍内容之后，发现很多精华细节都被漏掉了。

第二次尝试——按章节出。逐步把每个章节发给 Claude Code，每章生成一个 book-skill，但发现 Skill 过于松散，打破了章节原有的联系。

第三次尝试——渐进式披露法。受“渐进式披露”思想的影响，第一步首先让 Claude Code 为每一个章节写一段较为详细的综述，包含了章节内容，提到的方法、引用案例（如下图）。

![](https://static001.geekbang.org/infoq/a5/a5d825e1846c0624acc534a92bf209fb.png)

接下来从这份摘要出发，让 Claude Code 决定把书拆成几个独立的子 book-skill，并且从用户出发，感受哪些模块可以进行组合完成用户问题，构建出上述的主 book-skill，也就是那个并不做具体工作的总调度器。最后，让 Claude Code 再生成每个子 book-skill 的详细内容，生成子 book-skill 的时候，就是要求 Claude Code 严格阅读并引用原始文章案例。

第三阶段后，我们生产的 book-skill 就是既有整体，又有细节的，相对完整体现书籍技能的 Skill。你看，渐进式披露这种思想在 AI 工程中可以用在非常多的场景中，希望你能再次体会到这一点。

当这个核心的生产 book-skill 的 Skill 工作流完成后，我还配套了读书 Skill，发布到网站的 Skill，组成了以下 Skill 工作流，我只要输入一本书，就能让 Claude Code 全部完成 book-skill 生产和发布过程，这个流程是：

读书——read-book-skill。 把 pdf 书籍转换成原文全文.md ， 并提取章节摘要.md 。

生成——book-skill-creator。在 skill-creator 的基础上，读取摘要生成主 book-skill 和子 book-skill。

发布 GitHub——write-skill-repo。把 Skill 发布到 开源仓库

发布到网页——write-skills-page-content。把 Skill 发布到 book2skills 网站 。

![](https://static001.geekbang.org/editor-compose/resourceimage/compose/b1/05/b19155d26c4c1f1adf36c274d4ad6205.png)

在这里，我们看到用 Skill 组合为工作流，并用于内容生产比原来使用 Coze 等搭建工作流会更加灵活。不过这并不意味着 Skill 能取代工作流。Skill 使用依赖于两个条件：

一是使用 Skill 的 Agent 要很强大，比如类似 Codex、Claude Code；

二是模型也要强大，最好高于或和 sonnet 4.6 水平相当的模型。

就像我们在 04 讲提到的，Skill 是一个灵活技能，workflow 是一个严谨的操作手册，只有“老医生 Agent”能用得了技能，而“新手 Agent”只能使用 workflow。那么，如果你在企业自己开发的 Agent 中使用 Skill，要同时提升 Agent 本身的能力，而不止是优化 Skill。

完成这个 Skill 组成的工作流之后，book2skill 这个平台就初步搭建起来了。接下来我们看这类小产品如何实现内容的自运营。

## 让产品自运营：内链增强

作为内容平台，我们需要让每一个 Skill 都成为可被索引、可被发现、彼此关联的节点，这样用户发现一个 Skill 后，还能吸引 ta 看其他的 Skill，比如《一本书读懂财报》的 Skill 的用户，对《怎样选择成长股》也会感兴趣。这部分叫内链建设，我们会在第五章商业化详细讲述，这里你只需要知道链接能促进用户点击即可。

为了达到目的，我们初步把 book2skills 的内链建设落在两个点上。

一是用 Collections 承载行业维度

书籍 × 行业 × Skill 的矩阵，行业这个维度在前端通过 Collections 来体现。

Collections 是按行业组织的 Skill 合集，比如“财务分析”“投资决策”“市场营销”“个人成长”。每个 Collection 下是这个行业里所有相关书籍提炼出的 Skill。每个 Collection 是一个独立的落地页，有自己的 URL、标题和内容，覆盖“\[行业\] Agent Skill”这一类关键词。当书籍和行业的组合越来越多，Collection 页面自然积累，搜索覆盖面随之扩大。

![](https://static001.geekbang.org/infoq/8d/8d1a7306c223ce428d40430529619574.png)

二是 Skill 详情页加相关 Skill 内链

每个 Skill 有独立的详情页，页面末尾展示“相关 Skill”——来自同一行业或处理相似问题的其他 Skill。

![](https://static001.geekbang.org/infoq/3c/3cd44b850157fea2fe2b0ba4494e6dca.png)

在后续 book2skills 的建设中，还可以增加垂直行业 Agent 的这个设计。长远看，book2skills 还留给我很大很大的提升空间。

到这里，我的这个小案例就讲完了，不知道你是否体会到从“小切口”扩展到“大世界”的个人开发者创作思路呢，如果有的话，你可以思考作为个体，有哪个小切口进入，长期做下去，会产生矩阵式的乘法效应和复利效应的产品呢？

## 总结

最后，我们来总结一下。

这节课从一个公众号文章的洞察出发，完整走了一遍 book2skills 的产品思路，也是适合个人开发者上手的一类小产品。

首先，对于个人开发者，要做一个产品，不只是“需求存在”，还要是新赛道、长存在、有自运营支撑，这几点都是你需要考虑的因素。

其次，在 book2skill 这个实战中，我们完成了一个内容生成工作流。在这里我和你分享了使用 Skill 编排工作流的方法，并且再次用到了渐进式披露的思想。你可以合理地将这个方法和思想用在你目前的工作流调整中，比如在第五章的商业化中，我同样会用这个方法为 AlphaWiseWin 生成营销内容。

最后我们通过行业专属页、相关 Skill 的内链，增强了 book2skills 的产品自运营能力，把个人开发者从运营中解放出来，避免有限人力资源的浪费。二者其实都只是 SEO 的技巧之一，我们同样会在下一章系统讲述与 SEO/GEO 相关的所有内容。

不知道今天这样一个小产品对你产生了哪些启发呢？下一节课，我们会继续带来另外一个适合个人开发者的案例。

## 课后题

这节课我们套用今天的三个判断标准做出了适合个人开发者的产品。

①新赛道但长期存在，②用户能快速感受到效果，③产品本身能自运营

它会不会有什么乘法效应？
