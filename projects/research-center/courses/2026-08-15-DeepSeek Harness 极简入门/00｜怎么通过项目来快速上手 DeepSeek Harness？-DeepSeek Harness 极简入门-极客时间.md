DeepSeek Harness 第一次打开时，很容易让人产生两种错觉。

一种错觉是：这不就是另一个 AI 编程聊天框吗？选个模型，输入一句话，等它写代码。另一种错觉正好相反：插件、Provider、Agent 预设、Cordis……这么多新名词摆在一起，似乎不先把文档看完，就不配开始使用。

我觉得这两种理解都不太准确。

DeepSeek Harness 的确可以像编码助手一样使用，但它真正有意思的地方，不只是“模型会不会写代码”，而是你可以决定 Agent 按什么模式工作、哪些插件应该用在这次任务里。换句话说，模型只是其中的一层。终端、网页搜索、权限控制，乃至驱动 Agent 不断调用工具的循环，都可以作为插件被组合和替换。

这也是官方反复强调“一切皆插件”的原因。

不过，如果从插件架构开始讲，这套教程很快就会变成说明书。所以我打算换一种方式：我们先完成一个真实任务，再回过头看每个模块在任务里做了什么。

## 我们会维护一个小项目

这套教程会围绕一个叫 Task Lens 的小项目展开。它是一个零依赖的 Node.js 命令行工具，从 JSON 文件中读取任务，输出简单的状态汇总。

我们不会提前下载代码，而是让 DeepSeek Harness 自己把它创建出来。这样做的好处是，通过第一次操作就能看到 Harness 与普通聊天产品的差别。

后面的几篇文章会不断使用这个项目：

更换各种 Provider（提供方）和模型，比较同一个任务的表现；

用标准模式、PTC 模式、极简模式和创造模式四种 Agent 预设处理不同类型的工作；

用创造模式做一个可重复使用的“项目维护助手”；

调整终端、Agent Loop 和网页搜索配置；

体验 skill、plan、subagent、sandbox、session 等代表性插件；

最后让自定义 Agent 独立完成一次项目升级。

Task Lens 本身并不重要。它只是一个足够小、又包含代码、数据、测试和文档的练习场。以后换成自己的项目，操作思路是一样的。

## 读这套教程需要准备什么

你需要一台能运行 Node.js 的电脑，以及一个可用的模型 API Key。最顺手的组合当然是 DeepSeek API Key，不过模型配置那一篇也会介绍内置 Provider 和自定义 Provider。

正式开始前，建议准备好：

Node.js（如果 Node 版本过低，推荐使用 nvm 安装 Node 22）；

DeepSeek API Key，或其他模型服务提供商的 API Key，例如模力工厂提供的模型服务 （戳此了解详情） ；

一个专门用于练习的空白文件目录；

Git，可选但强烈建议使用；

大约九十分钟不被打断的时间。

## 三条安全约定

Agent 能读写文件、运行命令，也可能访问网络。它比普通聊天机器人更能干，也更需要边界。整套教程默认遵守以下三条约定。

第一，只在练习目录里操作。不要为了省事，把个人主目录、整个“文档”目录或装满公司资料的仓库直接交给 Agent。

第二，API Key 只填在模型设置或受信任的环境变量里，不写进提示词、README 或项目配置。

第三，看到审批请求时先读内容。尤其是安装依赖、删除文件、访问工作区之外路径和联网操作。审批按钮不是“继续生成”，而是你在授权一个真实动作。

如果练习项目使用 Git，我习惯在每个重要步骤前提交一次。这样即使 Agent 的修改方向不对，也能清楚地比较和恢复，而不是靠记忆猜它改过什么。

## 版本差异怎么处理

DeepSeek Harness 目前仍是开发者预览版，核心插件和界面都在快速迭代。你看到的按钮名称、模型列表或默认值，可能和教程中的截图略有不同，这一点需要注意。

## 怎么读最合适

我建议一边读一边做，不要先把七篇文章全部看完后才开始操作。

前两篇文章会带你完成启动、示例项目和模型配置；第三篇我们开始比较 Agent 预设的几种不同模式；第四篇我会带你创建自定义预设；第五篇则会集中处理插件；最后一篇会有一个综合任务。如果某个 Provider 或插件你暂时用不到，可以先读懂它解决什么问题，以后要用到的时候再配置就可以了。

学完之后，最重要的不是记住所有字段，而是形成一个配置顺序：

先看任务需要什么，再选模型，再选工作方式，最后只装入必要的插件能力。
