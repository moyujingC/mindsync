# L03｜把模糊需求变成可验收 Spec

> 来源：`PPT/L03-PPT.pdf`（29 页，已提取文字）；`PPT/L03-辅导资料｜…pdf` 为截图型查询手册，未 OCR。
> 仓库讲义：`CodexFDE/docs/courses/L03/`。

## 一句话

把「增加库存导出功能」这类模糊诉求，写成有来源、有边界、有验收的确认版 Spec（六段合同），并把最小解析器接入工作台入口。

## 为什么不能直接交接

需求缺口径：数量公式、明细粒度、排序、空集行为、写失败行为，都没定。案例：表头只写「库存数量 8」，运营会误读成还能接单 8 件。

**库存三列口径（核心案例）**：`on_hand` 账面在库 8 ／ `reserved` 预占未出库 3 ／ `available` 可用量 5（= 8 − 3）。三列同时保留，运营据可用量判断，其他列供核对；在库 8 是账面基准，实物另行清点。

## 六段 Spec 模板

来源（为什么做）/ 目标（做成什么）/ 非目标（这次不做）/ 约束（守哪些边界）/ 验收用例（怎样检查）/ 完成定义（何时算完成）。

方法：六步判断 + 反例修订（v1 → 反例 → v2 → 修订理由 + 实际确认状态）。**初稿随调查修订；进入执行前，合同版本必须与审查确认后的需求一致。**

## 解析器接入工作台

- 入口：`python -X utf8 -m workbench.cli spec <文件路径>` → 调 `load_spec(path)` → 个人 `parse_spec(text)`。
- 完整输入：退出码 0，六字段 JSON 与原文一致；缺「非目标」的副本：退出码 1，`ValueError: Spec 缺少必要章节：非目标`。
- 检查：两次运行前后输入文件均未被改变；stderr 省略调用栈保留末行。

## 三种检查分离（本讲最重要的框架）

1. **写全了吗**（L03 解析器）：六段齐全吗？→ 结构可被程序读取。
2. **说对了吗**（L03 人负责、Codex 辅助）：在库 8、预占 3，可用量应为 5？运营需要这个口径吗？→ 需求经审查与实际确认。
3. **做到了吗**（L04 复验者与审核者）：真运行导出，CSV 是否得到 5？导出前后库存是否不变？→ 实际实现经复验与人审。

文件写全 ≠ 需求想清楚；需求确认 ≠ 程序做对。

## 交接材料清单

业务决定（8/3/5 含义、粒度、排序、空集、失败行为）／版本与人审（v1、反例、v2、修订理由、确认状态）／模板与方法（同一模板生成库存稿与采购稿）／解析器接入（调用路径 + 接入 Diff + 完整/缺项输入与退出码）／未决事项（谁接着确认什么）。没有同伴反馈就如实标「待互评」。

## 迁移思考：换成采购申请导出

可复用：六步判断方法、六段结构、已验证的解析能力。必须重问：「未完成」含哪些状态、谁使用、字段与权限、排序、空集。**库存公式与仓位规则不直接迁移。**

## 课后三问

1. 六段齐全但可用量公式错误，解析器为什么仍可能通过？谁负责退回？（结构 ≠ 业务正确，人负责）
2. 换采购申请导出，哪些方法可复用？哪些口径必须重新确认？
3. 下一位执行者不看聊天记录，仅凭确认版能否开始？缺什么？
