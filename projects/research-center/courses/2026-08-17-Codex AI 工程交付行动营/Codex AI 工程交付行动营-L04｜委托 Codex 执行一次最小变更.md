## 一句话

自举换挡：先亲手补齐并**独立验收**工作台 V0（Ticket A），再由 V0 读取 L03 确认版 Spec 组织 Codex 交付库存导出（Ticket B）。

## Ticket A：先用两条路径验收 V0

- **正常路径**：导出 CSV 成功、只改授权文件 → V0 核对 Diff 通过 → 继续业务检查 → 等人审。**不能误拦。**
- **越界路径**：CSV 也成功，但额外改了 README → V0 核对 Diff 发现越界 → 停止交付并返工。**必须拦住。**

## 任务说明本身就是 Spec

用六段写 V0 建设任务。缺「完成定义」时：解析器报「缺少章节：完成定义」、退出码 1、**执行器不启动**。修正任务说明后重新提交，不能删校验规则放行进不完整输入。

## 执行边界与三步验收

- 边界：授权导出模块和测试，不代表可以顺手改订单状态机。
- 退出码 0 只说明进程正常结束，不代表改动合格。三步核对**同一份实际改动**，前一步通过才进下一步：
  1. 执行是否正常结束（退出码、超时、异常）
  2. 实际改动是否符合 Spec（Diff 对照 + 最小 Eval）
  3. 具名审核者是否接受这个版本
- 越界判断表：改 `export.py` 是 → 继续；新增 `test_export.py` 是 → 核对断言；改 README 否 → 列出越界退回；新增 `.env` 否 → 阻止提交保护凭据。

## 数据复验（Ticket B 的验收核心）

**只读验收**：导出只生成文件，不应改库存账。导出前保存状态 → 执行（分别测成功与写失败）→ 导出后逐条比较。
- 教学反例：总量相等（8+12 = 7+13 = 20）仍要返工——逐仓比较东仓少 1、西仓多 1。CSV 内容正确不能抵消库存账被改。

**中途失败保护**：inventory.csv 已是可用旧报表，写到一半出错时——
- 原本有旧文件：目标文件与旧内容**逐字节相同**（程序可能先清空再写失败）。
- 原本没有目标文件：不留下可被当成完整报表的半成品。
- 库存记录与流水：与失败前逐条比较不变。
- 为什么要故意中途失败：「目录不存在」只验证开始前路径错误，发现不了旧文件被截断。

## 返工定位：先分 A/B，再决定修谁

- 控制有效、业务结果不符 → 修 B（在 B 批准范围内修，复验新候选，交审核者）。
- 控制失效（越界被放行）或控制源码版本已变 → 先回 A：暂停 B，修复控制或复验新版本，A 重新被独立接受后再继续 B。
- 两类问题同时存在**先处理 A**：控制不可信时修业务仍可能越界或丢失败证据。
- 先保存原始 Diff、错误 CSV、检查报告；未定位原因先调查，不能凭"测试红了"就判定 A 或 B。

## skill 复用与 L05 预告

- `controlled-delivery-handoff` skill：建设 V0 / 复验 A / 交付 B / 迁移采购导出四个阶段给不同材料；**文件存在 ≠ 已复用**，要记录后续实际结果。
- L05 预告（教学反例）：导出程序把「可用量」写成「在库量」，测试也把预期写成「在库量」→ 测试全绿。**先设计失败，再编写 Eval**——用重复入库反例验证检查的辨别能力。
