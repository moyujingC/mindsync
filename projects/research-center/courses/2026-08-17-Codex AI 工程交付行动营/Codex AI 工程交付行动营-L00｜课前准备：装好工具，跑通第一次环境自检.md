## 欢迎：我们先从一件你想做成的小事开始

欢迎来到 Codex AI 工程交付行动营。

也许你试过让 AI 帮忙写程序，但遇到报错后不知道该怎么办。这门课从这样的起点出发：你有一个需要解决的问题，Codex 可以帮你调查、实现和运行，但你需要逐渐学会判断它做的事情是否符合要求。

想象一下，你希望每天把订单整理成一份清单。你告诉 AI “帮我做一个导出功能”，它很快回复“已经完成”。这时还有几个实际问题：导出的是什么数据？空订单会怎样？文件保存在哪里？下次还能运行吗？它有没有顺手改动其他东西？我们会在课程里把这些问题变成可以检查的步骤。

**你将先用 Codex 搭建个人 AI 研发工作台，再通过这个工作台持续开发电商客户产品 FlowERP。** 最后带走的成果包括能继续使用的工作台、逐步增长的 FlowERP，以及你自己组织交付和作出判断的记录。

这份文档是开课前给你独立阅读、动手准备的预习资料。今天先认识学习路线、装好工具、完成几个小练习。工作台的建设从 L01 开始，FlowERP 的首次接入与交付在 L04。

### 这门课与你有什么关系

你不需要先成为程序员才能开始准备。你需要愿意把一个模糊想法说清楚，按步骤尝试，保存真实结果，并在不确定时提出问题。遇到代码，我们会先说明它完成什么、怎样观察结果，再解释当前需要理解的部分。

四周课程也不会自动让每个人掌握所有编程知识。随着任务推进，你会补学必要的文件、命令、代码和业务概念。你能否跟上，取决于动手与反馈，不能只用视频是否看完来判断。已经有开发经验的同学可以减少学习提示，但仍要完成判断和复验。

### 先分清三个名字

| 名字 | 你可以怎样理解 | 课程里由谁来建设、使用 |
| --- | --- | --- |
| Codex | 与你一起工作的 AI 开发伙伴，可以理解项目并使用工具 | 你提出目标、检查计划和结果，Codex 协助调查与实现 |
| 个人 AI 研发工作台 | 组织研发工作的地方，记录需求、任务、修改、检查和审核 | 你先与 Codex 一起搭建，随后用它组织交付 |
| FlowERP | 电商客户使用的软件，逐步管理进货、销售、库存和财务 | 你通过工作台与 Codex 协作开发，用真实业务结果检验工作台 |

例如，同一张入库单收到两次，库存应只增加一次。以后我们会通过这样的业务问题学习怎样写清要求、检查错误、修复和签收。现在只需理解这个现象，不必提前学习数据库或财务知识。

### 四周里，你会看到什么变化

| 阶段 | 你逐渐能做的事 | 看得见的成果 |
| --- | --- | --- |
| 第一周，L01～L04 | 说清范围，让 Codex 在边界内工作，并保存检查记录 | 最小工作台；L04 第一次交付库存导出 |
| 第二周，L05～L08 | 用正常与失败例子检查结果，在本机与远端重复检查 | 幂等入库、库存口径、订单创建与原子预占逐步完善 |
| 第三周，L09～L12 | 安排返工与分工，知道何时停止、何时交给人审核 | 订单取消与状态修复、采购申请及审批后入库 |
| 第四周，L13～L16 | 使用界面、处理反馈，让他人也能启动和检查交付 | 可操作的工作台与 FlowERP，完成一个现场新需求 |

这里的“幂等入库”就是同一笔入库重复提交仍只生效一次；“原子预占”先理解为一张订单要占的库存要么全部成功，要么不占，不能只占一半。其他术语会在相应课次用实例解释，无需提前背诵。

### 你和 Codex 分别负责什么

Codex 可以给出建议和实现，也可能误解你的要求。你不必在第一天就看懂每一行代码，但需要逐渐守住四个检查点：这次要做什么、允许改哪里、结果怎样检查、现在是否有足够证据接受。

当一条命令失败时，先记录实际发生了什么，再决定下一步。让 Codex 解释错误或提供一个提示，比反复说“再修一下”更有助于你理解问题。不要让它代写你没有做过的步骤，也不要把自己的不确定删掉。

### 每讲怎样学，怎样知道自己学会了

1. **课前看问题** ：读一个具体场景，先写下你目前的判断；陌生词先看例子。
2. **课中分段看示范** ：遇到暂停点，预测结果或解释一处变化，再继续看。
3. **课后动手** ：在本讲指定工作区完成小任务，保存失败、修改和再次检查的结果。
4. **请别人复验** ：让同学或老师依据记录定位同一件事，得到可比较的结论。
5. **自己答一道变化题** ：暂时不让 AI 代答，说明为什么可以接受、为什么要退回，或还缺什么证据。

“程序运行成功”和“我能解释它为什么符合要求”分别检查。你不用脱离 Codex 重写整个系统，但需要能用自己的话解释关键决定。

线上每讲约 30 分钟，完整动手会花更长时间。先预留一段不被打断的练习时间，卡住时记录进度，分次完成。

## 二、必须安装的工具

先打开终端：Windows 在开始菜单搜索并打开 “PowerShell”；macOS 按 Command + 空格，搜索 “Terminal／终端” 并打开。看到可输入文字的一行后再执行命令，不需要管理员模式。以后也可以使用 VS Code 的“终端 → 新建终端”。

### 1\. Python 3.11

只做自己系统的一条路线。如果已有 `Python 3.11.x` 且验证命令可运行，跳过安装。

**Windows：官方安装管理器路线**

- 打开 [Python 官方 Windows 使用说明](https://docs.python.org/3/using/windows.html) ，从文档指向的 python.org 或 Microsoft Store 安装 **Python Install Manager** 。
- 关闭并重新打开 PowerShell，输入下面命令。 `pymanager` 管理安装， `py -3.11` 明确选择课堂版本。

复制代码

```powershell
pymanager install 3.11

py -3.11 --version

py -3.11 -m pip --version
```

第一行需要联网下载，请等它结束再继续。第二行应以 `Python 3.11` 开头，第三行应显示 pip 版本和位置。若 `pymanager` 找不到，先确认安装管理器已安装并重开终端；旧版 `py` 启动器本身不代表安装管理器已安装。不要卸载正在用于其他项目的 Python。

**macOS：官方图形安装器路线**

1. 打开 [Python 3.11.9 官方发布页](https://www.python.org/downloads/release/python-3119/) ，在 Files 中选择 **macOS 64-bit universal2 installer** ，下载 `.pkg` 。不要下载 Source tarball 源码包。
2. 打开 `.pkg` ，按安装器提示完成；重新打开 Terminal。
3. 输入下面命令验证：

复制代码

```bash
python3.11 --version

python3.11 -m pip --version
```

应看到 `Python 3.11` 开头的版本和 pip 信息。若 `python3.11` 找不到，先确认 `.pkg` 安装成功并重开终端，保留错误后求助。

**版本说明** ：3.11.9 提供传统图形安装器，后续 3.11 安全修复版本的分发方式不同；它不是最新安全版本。上述路线用于课程本地练习，不作为生产部署版本建议。记录实际安装的完整版本；如果是用学校设备，有补丁要求时先找管理员采用符合要求的 3.11.x，不自行编译或绕过管理。

**检查点 A-1** ：版本与 pip 都有结果再继续。只弹出商店、只下载了安装文件，均不代表安装完成。

### 4\. Codex

本课程中的 Codex 是 AI 开发伙伴，不是 FlowERP 的一部分，也不是我们自行训练的大模型。它将帮助你读取仓库、提出计划、修改代码和运行命令，但你仍负责范围、权限、Diff 审查和最终验收。

本课程需准备两种入口：

1. **桌面入口** ：从 [官方桌面入口](https://learn.chatgpt.com/docs/app) 安装应用并登录 ChatGPT 账号；第四节下载仓库后，再在第八节打开课程目录并实际对话。
2. **命令入口** ：打开 [Codex CLI 官方安装页](https://learn.chatgpt.com/zh-Hans/docs/codex/cli) ，选择自己操作系统对应的安装标签，按该页当前方法安装。现在先在终端运行 `codex --version` ；第四节下载课程仓库后，第八节再进入该目录启动对话。

先选一种 CLI 安装方式即可，装桌面应用不等于终端已经能识别 `codex` 。官方 CLI 提供独立安装入口；本课无需为了前端开发提前安装 Node.js。若选择 npm 安装方式，才需要该方式的依赖。

### 练习 3：失败不一定是电脑坏了

$LASTEXITCODE

**对照解释** ：本练习修正了计算，保留同一检查要求，用来认识“先失败、修正后通过”。它仍只是算术示例，不是实际库存业务修复，也不能作为 L01 构造证据。如果连 `.venv` 的 Python 都找不到，那是环境问题，和断言失败需要分别处理。

用下面的清单逐项检查。完成时可以查文档或接受提示，但最后必须亲自操作、保存实际结果，并能解释关键现象。

- **准备完成** ：环境可用，练习完成且能说明结果，引用已核验，记录齐全。
- **需要辅导** ：工具能用，但部分操作或解释仍未完成；提交现有记录，请老师安排补练。
- **环境受阻** ：安装、网络或登录阻止继续；提交错误记录，进入环境答疑。

三种状态都可以如实提交；“允许提交”不等于“全部通过”。是否需要先补学再进入 L01 动手，由老师依据具体卡点安排。

**检查清单：**

- Python 3.11.x 可以运行，且课程命令使用仓库内 `.venv`
- Git 可以运行并已设置自己的姓名与邮箱
- VS Code 能打开课程工作区并选择 `.venv`
- Codex 桌面入口可以登录， `codex --version` 可以运行，并且完成本讲只读对话
- 仓库成功克隆， `git status` 能识别
- Python 能导入 `sqlite3` ，并打印 `imports-ok`
- `python -m workbench.cli --help` 可以运行
- 没有把 `serve` 、 `demo` 、 `course-status` 或全量测试当作预习通过证据
- 完成一次 Codex 只读提问，并人工核对至少两个文件
- 能找到目录、解释小程序输出，区分断言失败与环境错误，并完成第九节四个练习
- 自检文档放在 `lesson-00-submission/` ，如实保留失败和未解决问题，没有提交敏感信息

预习不以“所有命令一次成功”为评分标准。真实失败、错误信息和解决过程都是准备证明；无法解决时，带着完整命令、输出和系统信息，参加开营前环境诊断，或者向讲师寻求帮助。

## 十二、常见问题：先找与你相同的现象

| 现象 | 先检查什么 | 下一步 |
| --- | --- | --- |
| `pymanager` 找不到 | 是否装了 Python Install Manager，并重开 PowerShell | 查第二节；不要把旧 `py` 启动器当管理器 |
| `py -3.11` 或 `python3.11` 找不到 | 是否真正装了 3.11，而不只是下载文件 | 保存安装结果，按对应系统路线核对 |
| `.venv` 下的 Python 找不到 | 当前目录是否包含 `pyproject.toml` 和 `.venv` | 回到课程根目录；尚未创建则完成第五节 |
| `pip install -e .` 报“not a Python project” | 命令最后的点和当前目录是否正确 | 在有 `pyproject.toml` 的目录重新尝试 |
| 包导入报 `ModuleNotFoundError` | 刚才安装和现在运行是否用了同一个 `.venv` | 对照实际解释器路径，不改成全局安装 |
| 克隆提示目录已存在 | 是否已经下载过；现有目录里有无作业 | 用文件管理器和 `git status` 检查，不删除重来 |
| `not a git repository` | 是否仍在 `work` 父目录，或下载的是 ZIP | 进入真正的 `CodexFDE` 仓库；不运行 `git init` 冒充克隆 |
| `code` 找不到 | 是否重开终端、VS Code 能否从图标打开 | 可先记“关于”版本，PATH 方法见第二节 |
| `git` 或 `codex` 找不到 | 工具是否装好并重开终端 | Windows 查 `where.exe git` ／ `where.exe codex` ；macOS 查 `which git` ／ `which codex` |
| PowerShell 显示 `>>` 不执行 | 是否漏了引号、误复制了多行或提示符 | 按 Ctrl+C 取消当前未完成输入，重新复制一条完整命令 |
| macOS 显示 `quote>` 或 `dquote>` | 引号是否不成对 | 按 Control+C 取消未完成输入，重新复制完整一行 |
| `AssertionError` | 是否正在做练习 3 的故意失败步骤 | 按练习保存证据，不重装 Python |
| 网络超时、登录失败或额度不足 | 保留明确错误，区分下载失败与账号限制 | 按第十三节求助，不反复重装或换不明账号 |

电脑受管理、下载受限或需要离线材料时，联系讲师确认可用方案。这里不要求修改整机执行策略、关闭安全软件或使用不明安装源。

**中文显示异常** ： `-X utf8` 只作用于 Python 的编码处理，不能修复所有工具与终端显示问题。保存原命令及现象，不改整机区域设置来碰运气。

**课程目录在网盘中** ：优先使用不自动同步的本地目录，避免锁定和同步冲突。确需换目录时保留原作业与失败记录，再重新克隆，不直接删除原目录。中文路径不一定有错，短路径只是为了减少排错因素。
