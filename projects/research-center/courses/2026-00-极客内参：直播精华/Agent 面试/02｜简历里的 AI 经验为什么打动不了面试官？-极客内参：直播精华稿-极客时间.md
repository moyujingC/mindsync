## 开场：四个问题，游戏规则变了

大家好，我是 Robert。今天这场分享，我想先跟大家聊四个问题，这四个问题就装在每一个程序员心里。

第一个问题：简历上写“熟练使用 AI”，现在人人都这么写，写了约等于没写。面试官看一眼就过去了，没有任何记忆点。

第二个问题：我明明用了 AI，怎么面试官问几个细节，我就露馅了？工具你用得再溜，一问到底层逻辑就卡壳。

第三个问题：AI 帮我写的代码，算不算我的能力？讲多了心虚，讲少了吃亏。这中间的度到底怎么把握？

第四个问题：平时零散用 AI，攒不成一个像样的项目故事。到了面试桌上，没有完整叙事，没有真实项目背书。

![](https://static001.geekbang.org/resource/image/49/da/49eda05ca9cddf26d51d818d474e2eda.png)

这四个问题背后其实是一件事：游戏规则变了，很多人还在用旧打法。 过去一年里 AI 工具的普及速度，大家都有体感。但在面试桌上，真正拉开差距的，不是谁用的工具更高级，而是谁能在 AI 之上展现出自己的判断力和系统理解。

整场分享的主线就一句话：面试官考察的东西，正在从“你会不会执行”变成“你有没有判断”。

执行这件事，AI 能替你做。判断这件事，AI 不能。这条线会贯穿今天全场：考察点变化、简历怎么写、追问逻辑、你该准备什么，都是它的延伸。

## 面试官到底在考什么

### 从"执行"到"判断"的底层转移

先说背景。这不是一个小趋势，是真金白银的市场变化。

智联招聘 2025 年 Q1 的数据显示，AI 领域的求职人数同比增幅达到了 200%。麦肯锡预测到 2030 年中国 AI 人才缺口将达到 400 万。AI 工程师岗位的求职热度增幅更是高达 69.6%。

![](https://static001.geekbang.org/resource/image/e8/e2/e895f13cdf7f1909d2b327b109768fe2.png)

但这里有一个特别关键的点：缺口不在算法研究，在工程落地。麦肯锡那 400 万缺口，大量分布在 AI 工程化、系统集成环节, 也就是“把 AI 做成能上线的系统”这件事。这恰恰是有工程功底的人的机会。

那面试官到底在考什么？哪里变了？

过去考的是执行：手写算法、数据结构、背 API、语法细节、从零实现某个功能、比谁写得快写得多。现在考的是判断：AI 给的对不对、能不能快速定位问题、权衡与技术选型的理由、能不能对结果负责。

![](https://static001.geekbang.org/resource/image/81/c3/815b9fbf9c025630048e456b24bd91c3.png)

变的是重心：从“生产代码”上移到“判断代码”。默认你会用 AI，考的是 AI 之上的东西。

但有些东西从没变，甚至更重要了。计算机基础，比如操作系统、网络、数据库，不会因为 AI 而过时。系统理解，知道一个系统怎么跑起来、瓶颈在哪。Debug 能力，定位问题的能力，是 AI 时代最硬的通货。把问题讲清楚，能讲清判断和权衡，比会用工具值钱得多。工具变了，内功没变。AI 只会放大“有内功”和“没内功”的人之间的差距。

这里有一个特别硬的证据，来自 Anthropic 的一个随机对照实验。他们让 52 名工程师学同一个新库，一组用 AI 辅助、一组手写，然后做同样的测试。结果是：用 AI 组平均分 50 分，手写组 67 分。差距最大的题型，正是 Debugging。

![](https://static001.geekbang.org/resource/image/82/6e/823dc3f92360d5547bb28e726958f46e.png)

“判断代码错没错、为什么错”这个能力，最容易因为依赖 AI 而萎缩。而面试官追问细节、让你现场找 bug，本质就是在复现这个实验：验证你是真懂，还是 AI 帮你写的。

### "熟练使用 AI"为什么正在失效

为什么“熟练使用 AI”这个表述正在失效？因为两种操作几乎一模一样，结果天差地别。

第一种是 AI 代劳型：让 AI 写完，拿了就走，不回头理解。完成最快、几乎不犯错，但什么都没掌握，这叫掏空了自己。第二种是先生成后理解型：让 AI 写完，回头追问：为什么这么写？改成 X 会怎样？用 AI 检查了自己的理解。这叫保住了能力。

![](https://static001.geekbang.org/resource/image/54/14/5403a68c4fa5dbcbf43b25d482b38b14.png)

“熟练使用 AI”之所以失效，是因为它证明不了你是哪一种。面试官看到的只是一个结果，但背后两种截然不同的能力路径，他需要用追问来区分。我再给大家讲两个真实面经，大家就明白了。

案例一：字节三面，一道意料之外的题。面试官问：“你日常开发用 Claude Code 还是 Copilot？为什么选它？”这道题不是考算法，不是考系统设计，考的是你的工具选择背后有没有判断。如果你答不出“为什么选”，说明你只是随手在用，没有对工具做过判断和比较。这种题在 2026 年已经是面试标配了，面试官用它快速区分“随手用”和“有判断地用”。

![](https://static001.geekbang.org/resource/image/c1/5d/c1d1b043b9b9c2ed6d86f5746733a75d.png)

案例二：一个“只会调 API”的人怎么当场哑口。候选人简历写：调用过大模型 API，做过 RAG 服务。面试官三连问：你的 RAG 服务每秒能处理多少请求？检索速度怎么提上去？要是向量数据库崩了，你怎么应对？结果连最基础的兜底都答不上。简历只写“调用过 API”，直接被刷。

![](https://static001.geekbang.org/resource/image/f5/10/f5096173a4931714135f7f3bf49d2510.png)

公司招的不是“会调接口的人”，是“能解决问题、能对可用性负责的人”。

## 追问的本质：一场可验证性测试

所以面试官到底在验证什么？我用一句话总结：追问的本质是一场“可验证性测试”。

能被你当场解释、推演、debug 的，是你的真能力。只能背出结论、一深问就崩的，是 AI 的能力，借你的嘴说出来。追问不是刁难，是在剥离“AI 的功劳”和“你的功劳”。

面试官是怎么一层一层往下逼的？我把它拆解成三层结构。第一层，是什么：你做了什么？大部分人都过得了。这一步是确认基本事实，你只要真的做过项目，就能答出来。第二层，为什么：为什么这么选？权衡了什么？这时候“AI 代劳型”的人开始卡壳。这一层开始考察你的判断过程，不是结果，是你做决策时的思考路径。第三层，如果变了会怎样：改需求、加十倍压力、出故障，这只有真懂系统的人答得上。这一层是在极限条件下检验你的系统理解深度。

![](https://static001.geekbang.org/resource/image/cd/7a/cd36e83f8251eb2d54bb2e73ac3e477a.png)

面试官就是靠这三层，把你的理解深度探到底。

那好的回答长什么样？我给大家看一个真实拿到 offer 的案例。做知识库问答，一开始用 CoT（Chain of Thought），复杂问题分解不好；换成 ReAct，让模型边想边调工具检索，准确率提升了 15%。ToT（Tree of Thought）我也试过，效果好但 token 消耗三倍，线上成本扛不住，最后只在离线深度推理时用。

![](https://static001.geekbang.org/resource/image/48/86/48ab718d3e16a3b220ba12724cf9ef86.png)

为什么这个回答能拿 offer？两点。第一，说清了 trade-off：效果提升多少、成本增加多少，都有数字。第二，说清了为什么这么选：这比背一堆概念，强一百倍。这个回答的核心逻辑就是：不只是在说“我用了什么”，而是在说“我为什么这么选、我验证了什么、我对结果负了什么责”。

说到这，我想直接给大家一个可套用的表达公式，别写“熟练使用 Claude Code”，用这个结构讲：第一步，我用 AI 做了什么——这是执行层。第二步，我做了哪些判断——选型、权衡、否决了什么。第三步，我怎么验证它是对的——测试、review、发现并修了什么。第四步，结果和我的责任——我为这个结果负什么责。

![](https://static001.geekbang.org/resource/image/9f/8f/9f4f8b20b350c88783e91a1afbba3c8f.png)

公式的核心：把你的“判断”和“负责”讲出来，而不是把“会用工具”讲出来。我再给大家对比同一套经历的两种讲法，大家立刻就明白差距在哪。

差一点的讲法：“我用 Claude Code 写了一个高并发订单服务。”这只证明了：会用工具。

好的讲法：“核心逻辑我让 AI 生成，但并发模型是我定的；AI 第一版用了乐观锁，我判断在这个写多读少的场景会大量冲突，改成了分段锁；上线前我压测，发现一个连接泄漏，定位是连接池没复用。”这些证明了：判断力加验证力加对结果负责。

这就是面试官想听到的。不是你的工具用了什么，而是你的脑子做了什么。

## 大厂要什么，不同背景怎么转

### Agent 技能树与人才结构

接下来我们看看大厂到底在招什么样的人。我扒了数百份招聘 JD，做了横切分析。四家公司——DeepSeek、字节跳动、蚂蚁、美团的岗位指向同一件事：要的是“能把 Agent 做落地”的人，不是“只会调接口”的人。

DeepSeek 专设了“Agent Harness”团队，对标 Claude Code，大规模抢人。字节做多智能体框架研发，Agent 在审核系统的落地与创新。蚂蚁招 PaaS 智能体平台研发专家，要求多 Agent 编排。美团招大模型应用后端工程师，要求 Agent 测评标准输出经验。

那 Agent 工程师到底需要什么样的人？我把一份 DeepSeek 的 JD 拆到底：重度用 Claude Code 或 Cursor，且懂其内部机制；能搭 Agent 运行时、容器服务、轨迹回放与调试；Docker、K8s、CI/CD、Git 是明确硬要求，不是加分；理解 Context Window 与 Token 机制；MCP、Tool Use、Function Calling 是加分项。翻译成一句话：它要的不是“会用 AI 的人”，是“能把 AI 做成可靠系统、能对结果负责的人”。

这里还有一个特别重要的认知：“Agent 工程师”不是一个岗，是一类岗。覆盖应用开发、Infra 平台、算法、评测、产品 PM、多模态六大方向。LangChain 仍是第一框架，但 LangGraph 加 MCP 已是生产标配，89% 的团队做 Observability。堆一排框架名是 HR 抄模板的表现，简历别堆框架，要堆“为什么选这个框架”的判断。

2026 年 Agent 岗真正要点的技能树我给大家梳理了四个层次：

工程底座：Docker、K8s、CI/CD、Git 工作流，几乎每份工程岗 JD 的地基；

Agent 核心机制：ReAct 循环、Function Calling、Tool Use、MCP（生产标配）、上下文与 Token、记忆管理；

系统能力：API 设计 REST/gRPC、微服务、消息队列、向量库、高并发与成本控制，这些后端可以直接复用；

可观测与评估：89% 生产团队做 Observability、LLM-as-a-Judge 评测体系。

![](https://static001.geekbang.org/resource/image/d6/0a/d6615ee0f7827428483b9801ca08f10a.png)

框架名是“术”，会不断变换，但把 Agent 做成可靠系统的能力是“道”，不会过时。

再看人才结构。现在呈现一个明显的两极分化：纯算法岗，卷学历、卷论文，离业务落地远，门槛越来越高。纯后端岗，竞争白热化，薪资增长乏力，初级可替代性强。中间那个“既懂工程落地、又懂 AI”的复合型 AI 应用工程师，是最大缺口，也是 2026 企业争抢的核心，这是转型的黄金窗口。

### 不同背景的转型优势与避坑

后端开发者的经验不是包袱，是护城河。大模型服务本质就是一类新型分布式系统。例如 Agent 服务的负载波动、峰值请求，这是高并发微服务，你最懂。推理成本控制等于有限资源下性能最大化，这是成本控制，你的老本行。服务宕机怎么保 99.9%，这是高可用降级熔断，正是企业付费的核心。再比如一个面试真题：“大模型服务宕机怎么保 99.9%？调用暴涨 10 倍怎么控成本？”这是“API Caller”和“AI 架构师”的分水岭，也正是后端最擅长的。

![](https://static001.geekbang.org/resource/image/12/7a/12889667f2bb66581e32eae839e0f87a.png)

前端开发者也有独特优势。前端积累的状态管理，对应 Agent 的状态机和记忆管理。异步和流处理，对应 Agent 的流式输出和工具调用。接口与 Schema 设计，对应 Agent 的 Function Calling 和结构化输出。用户流程规划，对应 Agent 的任务规划和多步执行。Agent 最缺的不是“会聊天”，是“交互加流程加可靠性”这些工程能力，前端很有优势。

![](https://static001.geekbang.org/resource/image/c7/a3/c7796fa93c3426cb1b53293e5871e0a3.png)

转型路上有三个坑，我特别想提醒大家避开。

第一个坑：死磕底层算法。一上来啃 PyTorch、反向传播、GPU 集群，那是研究员的活，做 AI 应用根本用不上。就像用 MySQL 不必懂 B+ 树。

第二个坑：只刷教程不做实战。收藏几十 G 资料，却连一个 RAG 知识库都搭不出来。企业要“能落地”，不要“会背理论”。

第三个坑：简历只写“调用过 API”。最常见的坑，直接被刷。公司要的是能设计反馈机制、能监控恢复、能对结果负责的人。

![](https://static001.geekbang.org/resource/image/55/1c/55ae9f76c588b901f1b17a4c5822c01c.png)

## 从现在开始：行动清单与长期沉淀

讲了这么多，落到行动上，2026 年从今天开始要做五件事。

第一，把 AI 当老师，不当代笔。生成完，回头追问“为什么”。

第二，刻意保留卡壳。先自己啃一会儿，再问 AI。AI 最危险的地方不是写错，是太顺。它把“卡壳”这件事抹平了，于是也顺手抹掉了藏在卡壳里的成长。手写组遇到了更多错误，而正是通过独立解决这些错误，他们练出了 debug 能力。

![](https://static001.geekbang.org/resource/image/fc/2a/fc85ec0f335e857b4cyy8c3d3dec8c2a.png)

第三，每个项目都能讲得出“我的判断在哪”。

第四，往深水区扎根。系统设计、分布式、debug、合规安全。

第五，攒一个能扛住“三层追问”的真实项目。

![](https://static001.geekbang.org/resource/image/c7/55/c701ced43618bf97528f2e8a80dfce55.png)

长期来看，什么才是 AI 替不走的？不是“你会不会用 AI”，是“你能不能对结果负责”。AI 把执行做到趋近免费，判断反而成了唯一稀缺的东西。面试桌上真正拿得出手的，不是“我会用 AI”，是“我在用 AI 的时候，没有掏空自己”。

![](https://static001.geekbang.org/resource/image/25/4a/250d6e33bd01c0562f4cdef023ff974a.png)

工具会过时，判断会留下。今天这一个小时，我希望给你的不只是面试技巧，是未来很多年都拿得出手的东西。
