### 通用开放 Agent 与企业执行型 Agent 的本质差异

通用开放 Agent（如旅行规划、文案生成）以内容生成为主，工具之间松编排，上一步结果可作为文本传递给下一步，错误代价主要是内容质量下降。而企业执行型 Agent 涉及异构 API 的序贯编排、参数的严格绑定、重业务流程交付（如算薪、发薪）。多步入参与出参必须准确传递，参数一旦出错，交付失败甚至造成误操作，回滚代价巨大。

![](https://static001.geekbang.org/resource/image/51/af/515436d1338e22f1481bd01b2340d5af.jpg?wh=4000x2083)

### MCP 在企业级场景的边界

企业执行型场景仅靠 MCP 无法满足。以报销流程为例：创建申请 → 上传发票 → 提交审批 → 查询结果，顺序与入参不可乱。人工操作时，每个按钮的参数由程序固定，上传发票时自然带着刚创建的申请 ID。但 Agent 自动化时，调用哪个工具、准备什么参数都由大语言模型生成，参数漂移是常态。MCP 标准化的是“连接方式”，并不保证大语言模型生成参数的精准程度。这不是 MCP 的缺陷，而是协议定位与场景需求的匹配问题。

![](https://static001.geekbang.org/resource/image/aa/bf/aayy1c649f7bd7aa56bbcec878da1bbf.jpg?wh=4000x2250)

因此，团队最终采用了 规划执行（Plan-and-Execute）加 Minimal Tool Set 的组合：在内容生成环节使用 MCP 松编排，在严绑定动作上使用确定性绑定与护栏。这一判断本身就是设计模式思维的具体体现。

### Part 3 控制面与叙事面分离 / 链式推理与 ReAct 实践改造

梁博团队将用户意图收敛为枚举结构——早期是 chat、analyze、resolve，后演进为 task、information、produce、chat——并创造性地提出了控制面与叙事面相分离的架构。控制平面负责驱动 Agent 的下一步逻辑，叙事平面提供后续推理所需的内容。当意图解析失败时，统一打回未知状态，由下游兜底逻辑处理。这一设计确保了模糊的自然语言意图能够收敛成可控、明确的数据结构，从而驱动下游的确定性逻辑。

在链式推理环节，团队要求每次推理同时产出两种信号：叙事层面的自然语言（供后续推理、规划、对话合成）和控制层面的结构化输出（驱动下游行动）。每次只产出下一步，明确指明可调用的逻辑，不必一次性规划全部。这种“给人看的思考”与“给程序消费的控制信号”的分离，使得系统既具备可解释性，又具备确定性。

在 ReAct 模式实践中，团队将每轮的 Thought、Action、Observation 作为一个 block 追加到 Scratchpad（草稿纸）看板，后续步骤通过阅读草稿纸上的 block chains 沿已完成事项继续推理。当任务脉络清晰后，控制权交还给编排器，切换到规划执行模式。这一“草稿纸”概念是团队在生产实践中的原创贡献，可以被视为双轴框架的一个扩展组件。

### 规划执行与 Human-in-the-Loop

对于严格顺序、存在依赖关系的任务，ReAct 容易出现跨步或漏步。团队因此引入了规划执行模式：由大语言模型一次性产出完整的步骤计划（任务 DAG），再由调度器按依赖逐步落地。核心组件包括规划器、执行器、验收器以及任务状态机。执行阶段尽量不再让大语言模型逐步重选路径，只在必要时触发重新规划。

在落地规划执行模式后，Human-in-the-Loop 的实现水到渠成。团队利用已有的任务 DAG、状态机、调度器、执行器，对敏感或高风险操作（如批量发薪、调薪基数）设置阻塞点，等待人工审批后恢复执行。哪些操作需要人审，通过声明式配置完成。

### 分层记忆体系：L1、L2 与 L3

梁博团队设计了三级分层记忆体系。L1 当前意识流是模型在当前时刻该看到的最小必要集，即当前推理与回复的直接输入。L2 里程碑日志记录“做到哪、刚完成什么”的结构化叙事，持久化到数据库。L3 经验教训在成功或失败时蒸馏出经验，通过向量语义索引存储，并可存放指向 L2 原始事实的 ID。

由于 L3 召回成本较高，团队只在链式推理首次、ReAct 首次、任务规划时这三个“关键边界”进行召回——因为第一步如果对了，后续步骤正确的概率会大幅提升。这一分层记忆体系直接映射了 CoALA 认知架构中的 working memory、episodic memory 和 semantic memory，同时也是 MemGPT“虚拟上下文管理”思想的最小可用实现。

### 双轴框架的实践映射与 Agent 学习经验

黄佳老师展示了双轴框架如何指导东方屹腾的架构落地。纵轴七个认知功能与横轴六个执行拓扑的组合，几乎覆盖了所有设计模式。例如：链式推理归属“推理 × 链式”，ReAct 归属“行动 × 循环”，Plan-and-Execute 归属“行动 × 链式”，Human-in-the-Loop 归属“治理 × 编排”，分层记忆归属“记忆 × 层级”。

![](https://static001.geekbang.org/resource/image/56/b0/56acc3f1133af9e753cyyf90e5b310b0.jpg?wh=4000x2250) ![](https://static001.geekbang.org/resource/image/5b/59/5bcc0ef0355a28f98a8da913b475b659.jpg?wh=4796x2876)

黄佳老师特别强调，这张图谱不是终点，而是起点。每一个空白格子都等待着社区在实践中填充。例如梁博团队提出的“草稿纸”模式，就可以被命名并发表，成为双轴框架下的一个扩展组件。他呼吁中国工程师不要再满足于追随者角色，而应该定义属于自己的技术体系，积累生产实践，诞生更多原创性的技术成果。

针对学习者如何分配时间的问题，黄佳老师给出了明确的建议：先看最新的内容。不必纠结于早期的机器学习或 LangChain 课程，优先学习 Claude Code 工程化、Agent 设计模式之美等最新专栏，理解双轴框架和 Harness 工程化思想，再回头补充那些“边角料”知识。他总结道，知识会过时，但元认知不会——设计模式的底层思想 20 年也不会过时。

架构设计的本质是在不确定性下进行有界资源的分配。模型负责生成可能性，治理框架负责管控资源预算。没有治理，就没有可靠的 Agent。在技术飞速迭代的当下，最需要的是能够穿透变化、抓住本质的思维地图——而这正是设计模式的价值所在。

## QA 对谈精华内容

## 一、AI 时代的能力重构：硬技能与软技能

黄佳老师指出，当前 AI 行业正从“模型层固化”转向“应用层爆发”，企业对 AI 应用开发能力的需求急剧上升。一个值得关注的新岗位角色是 FDE，即能够将 AI 引入业务系统并完成端到端落地的综合性工程师。企业需要的不是“为了 AI 而 AI”的演示原型，而是能够真正让业务流程更顺畅、让系统在 AI 时代更具竞争力的解决方案。

黄佳老师将当下 AI 岗位所需的关键能力拆解为硬技能与软技能两个维度。

硬技能方面，首要的是 AI 应用开发与落地能力。过去工程师们热衷于学习 Transformer 底层原理，但如今模型层已趋于成熟，千行百业的业务系统接入 AI 才是真正的战场。其次是企业级系统架构能力——Agent 时代的到来并未让架构师角色失效，反而因其系统更全面、更复杂，对架构能力的要求更高。工程师需要深入理解数据结构、设计模式等底层基础。第三是数据工程与知识工程能力，从 RAG 到知识图谱再到本体论，这些技术必须与具体行业相结合，否则企业应用落地无从谈起。

软技能方面，“穿透迷雾看本质”的能力最为关键。工程师需要具备与时俱进的学习能力，知道该学什么、不该学什么，而不是在技术变革中焦虑抱怨。AI 实际上降低了知识获取的门槛——过去被视为“秘密”的架构经验，现在可以通过 AI 获得基本指引，再逐步深入钻研。这种拥抱变化而非被动焦虑的心态，才是在这个时代存活下来的根本。

## 二、传统设计模式并未失效，而是作用域发生改变

针对许多工程师的困惑，传统软件工程中的设计模式在 Agent 时代是否还有用——黄佳老师引用了一位用户的精辟观点进行澄清。这位读者指出，旧模式并未失效，只是其作用域发生了改变。传统设计模式在面向对象的程序级架构设计中依然有效，Agent 时代的系统内部仍然存在大量传统的分布式系统、微服务架构的设计。Agent 只是为这个复杂系统增加了一个新的变量，我们需要在旧有模式基础上进行扩充和增强，而不是全盘否定。

黄佳老师坦言，他曾一度宣称“旧模式崩盘”，因为系统不再具备完全的确定性，Agent 带来了不确定性。但读者提醒他：旧模式的作用域变了，但并未消失。这一纠偏让他更清晰地认识到，AI Agent 时代需要一套属于自身的全新软件工程方法论，而这套方法论应当是对过去二三十年积累的架构知识的扩展，而非推倒重来。

正是基于这一认识，黄佳老师在过去半年多的时间里系统阅读了大量经典架构著作，包括设计模式、操作系统、微服务设计等，最终提出了双轴框架——以“认知功能”为纵轴、“执行拓扑”为横轴，将七个认知功能（感知、记忆、推理、行动、反思、协作、治理）与六个执行拓扑（链式、路由、并行、编排、层级、循环）正交组合。这一框架目前已成为该领域较为体系化的理论成果。

## 三、双轴框架的诞生：从中文书到国际出版

黄佳老师详细回顾了双轴框架的诞生过程，这一过程本身也是一次“从实践到理论再回到实践”的迭代。2025 年下半年，他意识到时代已经发生深刻变化，于是用半年时间“闭关”，系统阅读经典著作。在此基础上，他完成了中文版《Agent 设计模式》。出版后，黄佳老师仍然在持续思考与精进。

随后，他将这本书翻译成英文，向 O‘Reilly 和曼宁出版社投稿。曼宁出版社的副社长表示感兴趣并约他开会。在准备会议的一周内，他收到了大量来自工程师读者的反馈，同时结合自己在 Claude Code 工程化课程中的实践，突然意识到这些分散的模式背后应该有一张统一的地图。

就在会议召开的前一天晚上，双轴框架诞生了。他将这个新框架展示给曼宁出版社，对方感到非常震惊，随即迅速敲定了合同。黄佳老师感慨，压力有时不是坏事——正是因为要走向国际舞台、接受全球工程师的检验，他才逼自己在一个星期内完成了从分散模式到统一框架的跃升。

这本英文著作《Designing AI Agents》经过全球 20 多位来自 Google、Microsoft、OpenAI 等大厂的资深专家评审，获得了 4.5 分的高分，目前已进入曼宁的“trending titles”榜单。黄佳老师特别提到，这一过程中他内心有一个强烈的动力：为什么所有的模式都是外国人命名的？为什么中国工程师不能定义自己的框架？这种“不服”的劲头，驱动他完成了从追随者到定义者的转变。

## 四、生产级 Agent 的关键考量：Token、可观测性与治理

针对“如何打造生产级别、聪明且可靠的智能体”这一核心问题，黄佳老师指出，魔鬼都在工程细节中。设计模式之美专栏中，每个模式都着重强调了以下几个生产级考量。

Token 预算控制。在演示阶段，Token 消耗或许不是问题，但进入生产级别后，必须知道如何控制 Token 数量，这跟设计选择强相关。不同的模式会带来数量级的成本差异。

可观测性。黄佳老师引用自己的一句描述——“一行过后即留痕”——生产级 Agent 必须能够追踪每一步的执行轨迹。消耗了多少 Token、压缩了什么内容、压缩前的状态是什么、保存在哪里，这些都需要有清晰的观测手段。没有可观测性，连错误原因都无从定位。

治理。当 Agent 出错时如何回滚？如何限制其权限范围？该做到哪、不该做到哪？这些都是生产级系统必须解决的问题。治理作为一个独立的模式，在双轴框架中占据重要位置。黄佳老师甚至提出一个核心观点：没有治理，就没有好的 Agent。

黄佳老师用一个生动的比喻来说明治理的必要性。如果给 Agent 完全的自由，它就是一匹脱缰的野马。就像他对自己七岁儿子的管理：规定每天最多看两小时电视，孩子反而在“约束”下爆发出更多智慧——协商每次 20 分钟、用做家务换取额外时间。约束催生可控的自由，这正是治理的意义所在。

更多精彩内容，欢迎试读黄佳老师的 《Agent 设计模式之美》 ，与上千位 Agent 工程师共同探讨 Agent 通用范式与工程落地。
