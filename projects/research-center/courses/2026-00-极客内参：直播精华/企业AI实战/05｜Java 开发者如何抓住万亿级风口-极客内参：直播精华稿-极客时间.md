## AI Agent 黄金时代

哈喽，大家好，我是张嘉熙。今天很高兴能有机会在极客时间和大家一起参与这个直播。我是一名有 10 年以上 Java 开发经验的老 Java 程序员，曾经在创业公司、大厂、外企都待过。

今天的主题是：Java 开发者如何抓住万亿级风口。这个数字来自 Marketssandmarkets 的一份人工智能报告，报告中提到，2030 年人工智能对经济发展的贡献可以达到万亿级。我们最近也在极客时间上新了一门课程—— 《Java Agent，从 Demo 到生产级实践》 ，本次直播可以当做这门课的预热。

现在是大语言模型的黄金时代，当前最火的赛道就是 AI Agent。根据 Markets and Markets 的预测，2030 年 AI Agent 的全球市场规模可达 526 亿美元，行业复合年增长率（CAGR）达到 46%。

从产业角度看，可以用“供需两侧的共振”来形容。模型侧，DeepSeek 发布了 V4 版本，OpenAI 有 GPT-5，Anthropic 发布了 Claude 4，这些全球旗舰模型都将 Agent 作为核心能力进行了重构与强化。需求侧，AI Agent 应用形态已经发生根本转变：前两年 80% 以上是简单的聊天机器人，现在已经转化为流程化、自动化的 Agent 应用，复杂场景下的长链路推理、多 Agent 协作变得越来越复杂。

所以，现在就是 AI Agent 的黄金时代。

## Java vs Python：工程化能力的降维打击

在这个时代，主流编程语言确实是 Python。作为一个老 Java，我不由得思考：Java 将扮演怎样的角色？是被边缘化，还是迎来新的春天？

Python 的优势：快速原型开发、丰富的 AI 算法库、全球最活跃的 AI 开发者社区。而 Java 在当前 AI 浪潮中讨论声量较小，有人觉得 Java 笨重，甚至说是“上古时代的语言”。

但事实真的如此吗？从工程化角度来讲，Java 有非常明显的优势，我甚至用“降维打击”来形容。

我们做一个正面 PK：Python 阵营选 LangChain，JVM/Java 阵营选 Spring AI。

Python 这边：

开发范式：非常灵活，但类型系统偏弱，动态类型，没有编译器的约束。

工程化能力：相对较弱，集成零散工具和库维护成本高。

企业集成：与主流 Java 企业体系天然割裂，集成成本高昂。国内外 90% 以上的企业级应用都是基于 Java 构建的，已经运行了几年甚至几十年。

生产稳定性：完全基于 Python 的企业级应用很少，高并发场景下稳定性面临巨大挑战，内存泄漏问题时有发生。

Spring AI / JVM 这边：

开发范式：严谨规范，静态类型系统，继承 Spring 生态的高标准，架构设计、可读性、可维护性、测试性都有很高要求。

工程化能力：天然继承 Spring 生态几十年沉淀下来的成熟企业级工具链。

企业集成：本身就是 Java 技术栈，可以直接复用核心业务逻辑和资产，零门槛集成。

生产稳定性：跑在 JVM 上，大厂对 JVM 高并发、高可用场景有丰富的调优和测试体系。

结论：当 AI 应用从 Demo 验证走向承载企业核心业务时，Java 的工程能力对 Python 形成降维打击。

## Java 的核心优势

Java 不只是一门语言，背后是一套非常成熟的工程体系。

1\. 强类型的安全保障

Python 传递数据时常用 dict，里面某个字段的 value 是什么类型你不知道，存在巨大的类型风险。而 JVM 语言（Java、Kotlin 等）都是强类型，在类型系统上下了专门功夫，安全保障是业界顶级的设计。

2\. 事务管理

企业级开发中事务管理必不可少。比如电商下单、减库存、付款扣费，需要强事务保障原子性和回滚能力。Spring Java 这套体系非常成熟，只需要加一两行注解，ACID 特性就能得到完美保障。

3\. 并发与多线程能力

Java 在设计之初就把多线程能力放在不亚于类型系统的重要位置，并且还在不断增强。Java 21 及更高版本提供了更多并发编程支持。Java 天生为处理大规模高并发场景而设计，Agent 部署到生产环境同样面临并发和大流量挑战，Java 的并发能力提供了稳固的地基。

4\. 企业级生态

从诞生之初，Java 就快速进入企业级开发。Spring Data 提供数据处理的统一抽象，Spring Cloud 提供云环境下的微服务、网关、配置中心支持，还有对 Kafka、Redis 等中间件的专门支持。所有你能想到的企业级中间件，在 Spring 生态里都能找到对应的 Starter。Python 目前还达不到这样丰富的企业级生态。

## 技术选型策略

技术选型不是非黑即白，Python 和 Java 各有适用的阶段和场景。

Python：适合快速验证想法。有大量深度学习、机器学习的库，几十行代码就能快速验证一个 Agent 项目的价值。比如 CrewAI 框架。

JVM/Java：适合生产端和企业级应用。保证业务稳定性，承载核心业务，处理敏感数据。长期价值体现在易维护、可扩展，与既有系统深度融合。

决策路径：

探索期：用 Python 快速开发原型，验证 Agent 场景价值。

落地期：用 Java/Kotlin 等 JVM 语言重构核心逻辑，实现企业级生产部署。要考虑稳定性、可维护性、与既有系统的融合能力。

## Java Agent 生态环境

### Spring AI

Spring 官方出品，遵循约定优于配置、面向接口编程的设计哲学。支持 YAML 配置文件、注解方式快速配置。建立统一的抽象层，比如 Chat Model、Embedding Model 等接口，屏蔽不同 AI 服务商的底层差异。与 Spring Boot、Spring Cloud、Spring Security 无缝集成。生产就绪能力（错误重试、指标监控）100% 继承自 Spring 生态。如果你已经是 Spring Boot 开发者，可以很平滑地将大模型能力融入现有业务系统。

### LangChain4j

LangChain 的 Java 版。理念与 Python 原版几乎一模一样，只是实现语言不同。

### Spring AI 阿里巴巴

阿里基于 Spring AI，结合自己的通义系列模型和阿里云生态做的深度拓展。如果你公司的项目部署在阿里云上，使用阿里的大模型，这套框架开发门槛非常低，集成非常容易。这也体现了一个趋势：大厂正在将 AI Agent 能力与现有基础设施体系进行深度融合，解决落地难题。

### Embabel Agent

这是我们课程的主角。一个针对 JVM 语言开发者的 AI Agent 框架，不局限于 Java，Kotlin 等语言也可以使用。

虽然名气目前不如 Python 生态的 CrewAI、LangChain、LangGraph 等，但它的作者是 Ron Johnson——Spring 之父。光听这个名字，就可以增加一份信任。

设计理念：

工程优先：把企业级工程能力置于首位，确保 Agent 在生产环境下的稳定性、安全性和长期可维护性。从纯工程化角度讲，Embabel 是做得最好的框架。

与 Spring 生态紧密联系：虽然不是 Spring 官方项目，但设计、实现完全符合 Spring 生态要求，可以说是“胜似 Spring 项目”。

约束与智能的平衡：很多 Agent 框架完全依赖大语言模型进行规划，但大模型有概率性和不确定性。Embabel 在这方面做了非常好的折中。它提出了 GOAP 算法，这在所有 Python Agent 框架里都没有，是 Ron Johnson 独创的。

Ron Johnson 的一句话：“Agent 的未来不在于 Agent 多么像人，而在于它怎么样能更好地融入我们现有的企业软件体系。” 他是一个非常务实、真正从工程角度思考的人。

我们的课程不教玩具，只教能落地、敢上线的实战技能。

## 答疑环节

Q：阿里的 Java Agent 开发是不是也比较猛？

是的。阿里的企业战略很大程度上已经 All in AI，基础模型、Claude 对 Agent 的支持、Agent 框架开发都投入了极大资源。像淘宝这样的平台，背后已经有大量 Agent 在运行。

Q：这个项目是智能体平台还是单个 Agent？

从 Demo 到生产级实践，会讲到最简单的 Demo，逐渐深入到核心能力和核心模型，最后提供一个完整的生产级项目，包括多智能体协作，可以理解为是一个智能体平台。

Q：深度集成业务系统是什么意思？举个例子？

比如你们已经有一个电商平台，背后有订单服务、付款服务等十几个微服务。在 Agent 时代，你想把大模型能力集成进去，既要保持原有业务能力，又要引入 Agent 能力。可以用 Agent 获取数据库中的订单数据，利用 AI 放大价值。从单点小功能的 AI 化，到整个业务系统的 AI 化，这就是深度集成。

Q：Java 怎么做 React 规划？

Embabel 支持。框架里有规划器的概念，支持利用大语言模型的能力做规划，这是课程核心篇靠后的内容。

Q：把大模型做到核心业务时，遇到过什么真实踩坑经验？

合规方面是典型问题。上线一个业务能力时，需要解释清楚它为什么会产生这样的效果。我们之前用 Python 的 LangChain 和 Google ADK，大模型返回的结果有时不可控，难以解释。这也是我最终从 Python Agent 转向 Embabel 的原因之一——可解释性。很多 Python Agent 在这方面比较糟糕。

Q：集成业务系统是不是像千问 APP 点奶茶这种功能？

范围更大，不要局限在电商下单。举个例子：我们做过一个功能，用户需要输入一种类似 DSL 的表达式语言，对用户来说很难。我们就集成 Agent 能力，让大模型根据用户的自然语言输入，帮用户生成这个 DSL。Agent 的应用空间无限广阔，所有地方都有可能获得 AI 赋能。

Q：适合学生吗？

适合。不管是不是学生，都可以学习。如果想快速实现创意想法、做原型探索，可以用 Python 的 CrewAI。但如果毕业后想进入企业，实现真实业务场景下的复杂需求，就需要工程化能力，接触 Java Agent 是非常好的选择。

Q：Java 开发者会被替代吗？

我作为一个 Java 开发者，充满信心。不用急着转型，可以学习 Java Agent 框架如 Spring AI、Embabel，增强自己在 AI 时代的竞争力。Python 的 Agent 框架也有独到之处，可以学习，但不意味着要放弃 Java。到今天为止，Java 仍然是企业级开发、能够真正部署到线上的首选。如果缺少信心，欢迎来看我们的课程，相信会增强你的信心。
