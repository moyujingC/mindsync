Pydantic Schema <img src="https://cdn.nlark.com/yuque/0/2026/png/28539630/1783396370041-462884cf-db8a-48a5-9af3-c05ca5b9e863.png" width="1672" title="null" crop="0,0,1,1" id="MkWEZ" class="ne-image"> 结构化输出 Schema 图：这张图左侧画 Pydantic `BaseModel`，列出字段、类型、默认值、`Field(description=...)` 和枚举约束；箭头指向模型可见的 schema；右侧画 `structured_response`，强调程序读取的是通过校验后的对象或字典。 以电商咨询信息抽取为例： ```python from typing import Literal from pydantic import BaseModel, Field class PurchaseIntent(BaseModel): category: str = Field(description="用户想购买的商品品类") budget_yuan: int | None = Field(default=None, description="预算金额，单位元") usage: str | None = Field(default=None, description="使用场景") urgency: Literal["unknown", "normal", "urgent"] = Field( default="unknown", description="是否急用", ) gift: bool = Field(default=False, description="是否作为礼物") ``` 字段名、类型和描述都会影响模型输出。不要用 `x`、`info` 这种含糊字段名。 --- ## 4. ProviderStrategy 和 ToolStrategy LangChain 官方文档把结构化输出策略分成两类： | 策略 | 含义 | 适合场景 | | --- | --- | --- | | ProviderStrategy | 使用模型提供商原生结构化输出能力 | 模型原生支持 JSON schema 或类似能力 | | ToolStrategy | 使用工具调用机制得到结构化输出 | 模型支持 tool calling，但没有原生结构化输出 | 如果你直接把 schema 传给 `response_format`，LangChain 会根据模型能力选择合适策略。 基础阶段不必死记内部细节，但要知道： ```latex 结构化输出不等于普通 prompt 里要求“请返回 JSON”。 LangChain 会用模型供应商能力或工具调用机制来提高可靠性。 ``` --- ## 5. 可运行 Demo：抽取购买意图 前提： + 已配置 `AGENT_OPENAI_API_KEY` + 已配置 `AGENT_OPENAI_BASE_URL` + 已配置 `AGENT_OPENAI_MODEL` ```python import os from typing import Literal from pydantic import BaseModel, Field from langchain.agents import create_agent from langchain_openai import ChatOpenAI class PurchaseIntent(BaseModel): category: str = Field(description="用户想购买的商品品类") budget_yuan: int | None = Field(default=None, description="预算金额，单位元") usage: str | None = Field(default=None, description="使用场景") urgency: Literal["unknown", "normal", "urgent"] = Field( default="unknown", description="是否急用", ) gift: bool = Field(default=False, description="是否作为礼物") model = ChatOpenAI( model=os.environ["AGENT_OPENAI_MODEL"], api_key=os.environ["AGENT_OPENAI_API_KEY"], base_url=os.environ["AGENT_OPENAI_BASE_URL"], temperature=0, ) agent = create_agent( model=model, tools=[], response_format=PurchaseIntent, system_prompt="你负责从电商客户咨询中抽取购买意图。只抽取用户明确表达的信息。", ) result = agent.invoke({ "messages": [ { "role": "user", "content": "我想买一个 500 元以内的蓝牙耳机，明天出差要用，最好适合送同事。", } ] }) print(result["structured_response"]) ``` 观察点： + `category` 是否抽成“蓝牙耳机”。 + `budget_yuan` 是否是数字 `500`。 + `urgency` 是否是 `urgent`。 + `gift` 是否为 `True`。 + 没有明确表达的信息是否保持默认值或 `None`。 --- ## 6. JSON Schema 也可以做结构化输出 除了 Pydantic，LangChain 也支持 JSON Schema、TypedDict、dataclass 等形式。 JSON Schema 适合跨语言或前后端共享结构： ```python purchase_intent_schema = { "type": "object", "properties": { "category": {"type": "string", "description": "用户想购买的商品品类"}, "budget_yuan": {"type": ["integer", "null"], "description": "预算金额，单位元"}, "gift": {"type": "boolean", "description": "是否作为礼物"}, }, "required": ["category", "gift"], } ``` 基础阶段优先推荐 Pydantic，因为 Python 代码里更清晰，也容易和类型提示结合。 --- ## 7. 错误处理：结构化输出也会失败 <img src="https://cdn.nlark.com/yuque/0/2026/png/28539630/1783396371154-5c0b5038-e071-4648-872e-24b507a46dd0.png" title="null" crop="0,0,1,1" id="L6oA6" class="ne-image"> 结构化输出错误处理图：这张图从 `model output` 分成两条路径：符合 schema 进入 `structured_response`；不符合 schema 进入 `schema validation error`。错误路径再分成“自动反馈给模型重试”“返回错误给调用方”“降级到人工处理”。图中要强调结构化输出提升可靠性，但不是绝对不会失败。 常见失败包括： + 模型输出多个结构化对象，但你只需要一个。 + 字段类型不符合 schema。 + 枚举值超出允许范围。 + 必填字段缺失。 + 用户输入本身缺少可抽取信息。 不要把结构化输出当作数据库约束的替代品。进入业务系统前仍然要做业务校验。 --- ## 8. 常见错误 ### 错误一：字段描述太少 ```python class Intent(BaseModel): x: str y: int ``` 模型很难知道 `x` 和 `y` 代表什么。 ### 错误二：把推断当事实 用户说“送同事”，可以抽取 `gift=True`。但用户没说预算，就不要凭空填 `999`。 ### 错误三：结构化输出直接驱动高风险动作 即使模型抽取出 `refund_requested=True`，也不代表可以自动退款。抽取结果只是输入，后续还要经过规则、权限和审批。 --- ## 9. 本节知识框架总结 ```latex 结构化输出 -> 用 schema 约束模型输出 -> Pydantic / JSON Schema / TypedDict / dataclass -> create_agent(response_format=...) -> ProviderStrategy / ToolStrategy -> 结果读取 structured_response -> 错误包括多输出、类型不符、校验失败 -> 业务系统仍需二次校验 ``` ## 10. 本节小结 你需要记住： 1. 自然语言适合人读，结构化输出适合程序处理。 2. schema 的字段名、类型和描述会影响输出质量。 3. `response_format` 可以让 agent 返回 `structured_response`。 4. 结构化输出比“请返回 JSON”可靠，但仍要处理失败。 5. 抽取结果不能直接等同于业务动作。 课后练习： 1. 为售后咨询定义一个 `AfterSaleIntent` schema。 2. 字段包含订单号、问题类型、是否质量问题、用户诉求。 3. 用三句话测试结构化抽取。 4. 故意输入缺少订单号的问题，观察结构化结果如何表达未知信息。
