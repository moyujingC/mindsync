LangSmith 数据结构 LangSmith observability 文档中的核心概念： | 概念 | 含义 | | --- | --- | | Project | 一组应用 trace 的容器 | | Trace | 一次操作的完整执行轨迹 | | Run | trace 内的单个步骤，如模型、工具、链、节点 | | Thread | 多轮会话中多个 trace 的关联 | <img src="https://cdn.nlark.com/yuque/0/2026/png/28539630/1783396398490-a46665c6-1da9-46c9-acbf-fd81b8747407.png" width="1672" title="null" crop="0,0,1,1" id="b1LI6" class="ne-image"> Trace Run Thread 关系图：这张图画 Project 包含多条 Trace；每条 Trace 包含多个 Run；多个 Trace 通过同一个 thread_id 连接成 Thread。每个 Run 旁标注输入、输出、耗时、token、错误。图中要强调一轮对话通常是一条 trace，多轮对话通过 thread 关联。 --- ## 3. Trace 能帮助排查什么 电商客服中常见排查问题： + 模型是否调用了订单工具。 + 工具参数是否填错订单号。 + 检索到的政策是否过期。 + 最终回答是否引用了资料。 + 哪个步骤耗时最高。 + 错误是否来自模型、工具还是外部服务。 Trace 让你从“猜测问题”变成“定位问题”。 --- ## 4. Tags 和 Metadata 你可以给 trace 添加标签和元数据： ```latex tags: ["customer-service", "after-sale"] metadata: channel: "web" tenant_id: "shop_001" scenario: "refund" ``` 用途： + 按渠道筛选。 + 按场景统计错误率。 + 按版本对比效果。 + 把同一用户会话关联成 thread。 注意：metadata 不要放敏感个人信息。 --- ## 5. Trace 不是普通日志 普通日志通常是时间顺序文本。Trace 是结构化执行树。 它能看到： + 父子 run 关系。 + 模型输入输出。 + 工具参数和结果。 + token 和成本。 + 延迟和错误。 + 线程和会话关系。 但 trace 也有隐私风险。系统提示词、用户隐私、订单地址等都要按策略脱敏或避免记录。 --- ## 6. 最小配置口径 常见环境变量： ```bash export LANGSMITH_TRACING=true export LANGSMITH_API_KEY=... export LANGSMITH_PROJECT=ecommerce-agent-course ``` 基础课不要求你现在接入真实 LangSmith，但要建立意识： ```latex 没有 trace 的 Agent 很难进入稳定迭代。 ``` --- ## 7. 常见错误 ### 错误一：只看最终回答 Agent 错误常常发生在中间步骤。 ### 错误二：trace 里保留过多敏感信息 可观测性不能突破隐私边界。 ### 错误三：没有版本信息 prompt、工具、知识库版本不记录，就很难比较改动前后的效果。 --- ## 8. 本节知识框架总结 ```latex 可观测性 -> Project / Trace / Run / Thread -> 记录模型、工具、检索、节点 -> tags / metadata / feedback -> 用于调试、分析、评估 -> 需要隐私和脱敏策略 ``` ## 9. 本节小结 你需要记住： 1. Trace 是 Agent 调试的基础设施。 2. Run 记录每个步骤，Trace 记录完整执行。 3. Thread 把多轮会话关联起来。 4. metadata 和 tags 支持筛选和分析。 5. 可观测性必须同时考虑隐私。 课后练习： 1. 设计一次订单查询 trace 应该包含哪些 run。 2. 为售后场景设计 tags 和 metadata。 3. 列出 trace 中需要脱敏的信息。 4. 根据一个错误回答，写出你会先检查哪些 run。
