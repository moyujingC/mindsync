# 文档切片与元数据：让知识库既能搜到，也能追溯

## 1. 为什么要切片 一份售后政策可能有几千字，里面同时包含：
- 7 天无理由退货。
- 质量问题换修。
- 特殊商品例外。
- 发票和赠品处理。
- 运费承担规则。
用户只问：

```latex
耳机签收 8 天还能退吗？
```

如果整篇政策都给模型，信息太多；如果只检索到相关小段，回答更聚焦。
切片的目标是：

```latex
让每个可检索单元足够小，便于召回；又足够完整，便于理解。
```

---

## 2. Document 的两个核心字段 LangChain `Document` 抽象通常包含：

| 字段 | 作用 |
| --- | --- |
| `page_content` | 文档正文 |
| `metadata` | 来源、标题、章节、版本、更新时间等附加信息 | 示例：

```python
from langchain_core.documents import Document doc = Document( page_content="普通数码配件支持签收后 7 天无理由退货，特殊商品除外。", metadata={ "source": "after_sale_policy.md", "section": "无理由退货", "version": "2026-05", "updated_at": "2026-05-01", }, )
```

`page_content` 给模型读，`metadata` 给系统追溯、过滤和展示。

## 3. chunk size 和 overlap

<img src="https://cdn.nlark.com/yuque/0/2026/png/28539630/1783396377282-06900a14-118e-48e4-b4ef-109f7bb314e5.png" width="1672" title="null" crop="0,0,1,1" id="dzddL" class="ne-image">

chunk size overlap 图：这张图画一条长文档文本，被切成多个连续 chunk。每个 chunk 有固定长度，chunk 之间有一小段重叠区域。标注 chunk size 决定单片长度，overlap 用来保留跨边界语义，例如一个规则的条件在上一段、结论在下一段。
`chunk_size` 控制每段多长，`chunk_overlap` 控制相邻切片重叠多少。
切片过大：
- 检索不精准。
- 无关内容太多。
- 容易超过上下文预算。
切片过小：
- 语义不完整。
- 条件和结论被拆开。
- 模型拿到片段后仍然无法回答。
售后政策通常可以按标题和自然段切，再用 overlap 保留上下文。

---

## 4. 推荐的元数据字段 电商知识库至少考虑：

| 字段 | 作用 |
| --- | --- |
| `source` | 原始文件或系统来源 |
| `doc_id` | 文档唯一标识 |
| `section` | 章节标题 |
| `version` | 政策版本 |
| `updated_at` | 更新时间 |
| `category` | 商品、售后、发票、物流等分类 |
| `effective_from` | 生效日期 |
| `channel` | 适用渠道 | 元数据不是越多越好，但来源、版本、更新时间通常不能省。

---

## 5. 可运行 Demo：生成带来源的 chunk

```python
from langchain_core.documents import Document from langchain_text_splitters import RecursiveCharacterTextSplitter raw_doc = Document( page_content=( "无理由退货：普通数码配件支持签收后 7 天无理由退货，特殊商品除外。\n" "质量问题：如商品存在质量问题，需提交售后检测，检测通过后可维修、换货或退款。\n" "运费规则：非质量问题退货运费由用户承担，质量问题退货运费由商家承担。" ), metadata={ "source": "after_sale_policy.md", "version": "2026-05", "category": "after_sale", }, ) splitter = RecursiveCharacterTextSplitter( chunk_size=60, chunk_overlap=10, ) chunks = splitter.split_documents([raw_doc]) for index, chunk in enumerate(chunks): chunk.metadata["chunk_index"] = index print(chunk.page_content) print(chunk.metadata)
```

观察点：
- 每个 chunk 都保留了原始 metadata。
- 可以额外加入 `chunk_index`。
- chunk 不应该丢失来源和版本。

---

## 6. 常见错误

### 错误一：丢失来源 如果 chunk 只有文本，没有 `source` 和 `version`，后续无法解释答案依据。

### 错误二：机械按固定字数切所有文档 商品参数、FAQ、政策条款结构不同，切片策略也应该不同。

### 错误三：旧版本和新版本混在一起 政策更新后，要能通过 version 或 effective date 控制召回。

---

## 7. 本节知识框架总结

```latex
文档切片 -> Document(page_content, metadata) -> chunk_size 控制长度 -> chunk_overlap 保留边界语义 -> metadata 支持来源、过滤、引用、更新 -> 切片策略要适配文档结构
```

## 8. 本节小结 你需要记住：
1. RAG 质量很大程度取决于切片质量。
2. chunk 要足够小以便检索，足够完整以便理解。
3. metadata 是引用、过滤和排错的基础。
4. 电商政策知识库必须保留来源、版本和更新时间。

4. 设计一个只检索当前渠道政策的 metadata filter。
