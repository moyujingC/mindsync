### 66. 一分钟项目介绍怎么说？ 我做的是一个面向生产实践的小哲电商客服 / 售后 Agent 项目。整体是 前端工作台、FastAPI Agent 后端和 Spring Boot 电商业务后端三端结构。Agent 不直接编造订单、物流、库存和售后状态，而是通过 Tool 查询实时业务事实；售后政策、FAQ 和商品知识通过 RAG 提供引用依据；未发货退款、签收后退货这类高风险流程使用 LangGraph 显式编排，并通过 HITL 做人工确认和受控恢复。项目还用 Hooks、Trace、Evaluation 和 cost_summary 观察脱敏、降级、回归和成本边界。当前项目没有接真实支付退款和企业内部系统，真实上线时需要替换鉴权、审批、审计、监控和知识运营流程。 ### 67. 简历里怎么描述这个项目？ 可以写：基于 FastAPI、LangChain / LangGraph、React 和 Spring Boot 构建小哲电商客服 / 售后 Agent 项目。系统通过 Tool Calling 查询订单、物流、商品、库存等实时业务事实，通过 RAG 管理售后政策、FAQ 和商品知识，通过 Memory、Runtime Context 与 Context Builder 支持多轮指代、身份边界、上下文裁剪和脱敏；对退款、退货等高风险流程使用 LangGraph 编排，并通过 HITL 支持人工批准、拒绝和恢复。配套 Trace、Evaluation、Hooks 和成本摘要，用于工具治理、行为可观测、回归验证和成本分析。 ### 68. 面试官问“你这个项目和套壳聊天机器人有什么区别”怎么答？ 我会从三点回答。第一，事实来源不同：聊天机器人主要靠模型回答，项目里实时订单物流走 Tool，稳定政策走 RAG。第二，风险控制不同：退款退货不是普通聊天，而是 LangGraph + HITL 的受控流程。第三，验证方式不同：项目不只看最终回答，还看 citations、tool_calls、session_state、trace 和 eval case。 ### 69. 面试官问“为什么不用一个超长 Prompt 解决所有规则”怎么答？ 超长 Prompt 早期能救火，但生产上不可维护。规则变化会导致版本难控，token 成本高，模型注意力会被无关规则稀释，冲突规则也难追溯。更合理的分工是 Prompt 管角色和边界，RAG 管稳定知识，Tool 管实时事实，Workflow 管高风险流程。 ### 70. 面试官问“怎么防止幻觉”怎么答？ 我不会只说“让模型不要编”。项目里用分层机制防幻觉：稳定知识要求 RAG citations，实时事实必须 Tool 查询，低置信检索要兜底或转人工，高风险动作进入 Workflow / HITL，最终用 Eval case 检查是否漏引用、漏工具或越权承诺。 ### 71. 面试官问“怎么保证用户不能越权查订单”怎么答？ 工具查询使用 Runtime Context 里的可信 user_id、role 和权限字段，不使用用户自然语言里的身份声明。用户说“我是某某”只能作为待验证输入，不能覆盖系统上下文。业务后端也要做权限校验，Agent 层的 Prompt 只是辅助边界，不替代鉴权。 ### 72. 面试官问“为什么高风险流程不交给模型自己判断”怎么答？ 因为退款、退货、补偿涉及资金、库存、财务和用户权益。模型适合理解用户意图和整理材料，但不应拥有最终审批权。项目里用 LangGraph 固定流程，用 HITL 让人工确认，用 checkpoint 和幂等保证恢复时不重复提交。 ### 73. 面试官问“你怎么定位线上一次错误回答”怎么答？ 先看 trace：路由是否正确、RAG 是否命中正确引用、Tool 是否调用成功、Context Builder 是否混入旧事实、Workflow 是否走到正确节点、安全和降级是否触发。再看 eval 是否已有类似 case。如果没有，就把这次失败归因后补成 regression case，而不是只改一句 Prompt。 ### 74. 面试官问“RAG 参数怎么调”怎么答？ 先定义评测集和指标，再调 chunk size、overlap、metadata、top_k、score threshold、query rewrite、rerank 和 hybrid 策略。不能只看命中率，要看回答是否引用正确、是否拒绝无依据问题、是否延迟和成本可接受。 ### 75. 面试官问“Tool 和 RAG 都能查资料，怎么选”怎么答？ 看事实类型。实时、用户相关、权限相关、状态会变化的事实走 Tool，例如订单、物流、库存、余额；稳定文本知识走 RAG，例如售后政策、FAQ、活动规则和商品说明。混合问题可以先 Tool 查事实，再 RAG 查规则，最后由模型组织回答。 ### 76. 面试官问“Agent 失败时怎么降级”怎么答？ 按失败类型降级。模型失败可以切备用模型或返回稍后再试；工具超时可以提示当前无法查询并转人工；RAG 低置信不能硬答；权限失败要拒绝；高风险动作要暂停审批。降级回答要用户可理解，同时隐藏内部异常、堆栈、密钥和敏感字段。 ### 77. 面试官问“你项目里最有工程价值的部分是什么”怎么答？ 我会说最有价值的不是某一个模型调用，而是把 Agent 拆成可治理链路：路由决定路径，RAG 和 Tool 分别管理知识与实时事实，Workflow 和 HITL 管高风险动作，Context Builder 管上下文污染，Trace 和 Eval 证明系统按边界运行，成本摘要帮助做路径分层。 ### 78. 面试官问“如果要真实上线，你还差什么”怎么答？ 这个项目真实上线还需要接入企业系统和运维治理：统一鉴权、租户隔离、RBAC、订单物流售后正式接口、真实审批组织流、审计日志、监控告警、限流缓存、知识发布审核、人工质检、线上评测、A/B 和成本平台。它证明的是生产形态和关键机制，不等于已经替换企业客服系统。
