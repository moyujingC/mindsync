# 常见学习路线

回答课程导读问题时，先结合 `course_compact_map.md` 使用本文。面向学习者的云效/Codeup 公开代码仓有意不包含完整课程 Markdown；因此应从精炼课程地图和本地代码/材料回答，不要求学习者提供课程正文目录。

如果学习者问“这一课和上一课相比新增什么”“第 X 课改了哪些能力”，优先读取 `lesson_delta_map.json`，再结合 `lesson_delta.py` 输出的本地代码差异。

## 具体知识点映射

如果学习者问的是一个具体机制，不要只给宽泛能力范围；先把它定位到最接近的课次，再简要说明原因。

建议回答形态：先说“这个知识点主要看……”或“这个点不是整条能力线，主要落在……”。只有必要时再列前置课和延伸课。

- Prompt 角色边界 / SystemMessage 与 HumanMessage 边界：基础课 05，故事课 05。
- Prompt 分区管理 / Prompt 片段化 / Prompt Template / Prompt Registry / selected fragments：故事课 06 是主课；基础课 05 是角色和边界 Prompt 的前置。
- Prompt 成本或 Prompt 片段成本治理：故事课 07 看早期 token 成本压力；故事课 40 和 41 看成本摘要和路径级成本治理。
- Runtime Context / 当前用户身份 / 用户自称不能覆盖系统事实：基础课 19，故事课 33。
- Context Builder / 历史消息、工具结果、RAG 片段分层组织：基础课 06 和 30，故事课 34。
- 上下文压缩 / 长上下文遗忘：故事课 35；基础课 30 可作为 compaction 概念前置。
- 上下文安全管理 / 上下文污染 / 外部文本隔离 / Prompt Injection 防护：故事课 36 是主课。如果问题同时涉及 Runtime Context、Context Builder 或压缩，再串起故事课 33-35。基础概念可按角度补充基础课 06、19、30、31。
- Tool 结果进入上下文前的安全摘要 / Observation / 脱敏压缩 / 工具结果怎么回到上下文 / 工具结果如何治理回上下文 / 工具输出进入上下文：故事课 20。若学习者问“怎么看代码”或“代码在哪看”，按“机制到代码”的方式回答：先说明机制，再指向故事课 20 的本地代码路径。

## RAG 路线

- 基础侧：为什么需要 RAG、文档切片、metadata、引用、低置信边界。
- 故事课：08-16。
- 关键桥接：基础课解释 `Document -> chunk -> embedding -> retriever`；故事课解释小哲电商为什么不能继续把 SOP 全塞进 Prompt，以及检索质量如何从朴素向量检索逐步成长到重排、混合检索和缓存。

## Tool Calling 路线

- 基础侧：messages、tool schema、ToolRuntime/ToolNode、工具参数和错误。
- 可先提的基础课：09 Tool Calling 基础、10 工具参数返回值与错误处理、11 ToolRuntime/ToolNode 与 LangGraph 工具节点。
- 故事课：17-24。
- 可先提的故事课：17 订单物流事实查询、18 工具箱与参数/身份边界、19 缺少订单号时先澄清、20 工具结果观察与摘要、21 工具/模型故障降级、22 Tool + RAG 商品回答、23 工具治理、24 MCP/跨 Agent 工具边界。
- 关键桥接：基础课解释模型如何请求工具；故事课解释订单、物流、商品库存等事实必须来自确定性业务系统，不能靠 RAG 或模型记忆猜。
- 回答“哪一课讲 Tool”时，可先说：“Tool 不止一节课，它在故事课 17-24 形成一组能力线；如果只想先入门，先看基础课 09-11，故事课可以从第 17 课进入。”然后列课次和标题。除非学习者明确要求启动某课，否则不要生成运行卡片。

## Workflow 和 HITL 路线

- 基础侧：LangGraph state、nodes/edges、persistence、interrupt、human-in-the-loop。
- 故事课：26-31 和 43。
- 关键桥接：基础课解释图控制和恢复机制；故事课解释退款/退货这类高风险动作必须停在政策和人工审批边界。

## Memory、Runtime Context、上下文工程路线

- 基础侧：短期记忆、长期记忆隐私、Runtime Context、上下文工程。
- 故事课：32-36。
- 关键桥接：基础课区分 state、runtime context 和 model context；故事课说明用户自称身份不能覆盖可信运行时事实。

## Trace、Evaluation、Cost 路线

- 基础侧：可观测性/Trace、Evaluation/测试、错误处理。
- 故事课：37-40，再接 41-45。
- 关键桥接：基础课解释为什么系统需要证据；故事课用调试台里的 Trace/Eval/Cost 信号证明 Agent 是否按边界工作。

## 生产交付和项目表达路线

- 故事课：41-46。
- 重点：最终总演习、Tool/RAG/HITL/安全场景、生产边界、增强路线图，以及如何表达项目但不夸大为完整企业系统。

## 第 41 课综合运行时

- 普通商品、订单、FAQ 和活动问题以模型路由为主；退款、退货、安全、退款状态和降级保留确定性规则护栏。回答“是否写死”时，应区分模型能力与必须稳定的业务控制。
- RAG 默认使用真实 OpenAI-compatible Embedding；`AGENT_COURSE_OFFLINE_RAG=1` 只用于学习者明确要求的离线模式，调试台应公开 embedding 模式。
- 商品与活动联合问题先用 Tool 查询当前 SKU 的价格、活动价和库存，再用 RAG 补充平台通用规则；未被 Tool 或结算事实确认时，不得说通用规则一定适用于该商品。
- FAQ 缓存保存的是首次模型基于证据生成的最终答案；显式离线模式才缓存确定性兜底话术。
- 第 44 课 `SERVICE_TIMEOUT` 是故障注入预设，不是实际物流接口故障证明。

## 快速学习路径

- 30 分钟快速看全貌：先读精炼课程地图，再看第 41 课代码 README 和第 45 课材料 README。
- 2 小时聚焦 RAG：故事课 08、10、11、12、15、16，再补基础 RAG 课。
- 2 小时聚焦高风险退款：故事课 26-31 和 43，再补基础 LangGraph/HITL。
- 面试表达重点：故事课 17-24、26-31、37-41、45-46。
