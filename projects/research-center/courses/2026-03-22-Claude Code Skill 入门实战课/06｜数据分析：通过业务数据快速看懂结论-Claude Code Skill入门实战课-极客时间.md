本节摘要

各位同学大家好，欢迎来到 Claude Code Skill 系列课程。

想必这种痛苦你一定经历过：老板周一早上给你发一个 Excel，里面是上个月的销售数据——15000 行，25 列。他说："周三例会要用，帮我分析一下流失用户的特征。"然后……你就开始了地狱之旅。

- 第一步：花半小时搞清楚每一列是什么意思
- 第二步：处理缺失值和异常数据（年龄 200 岁？）
- 第三步：写 Python 脚本做统计分析
- 第四步：画图表（到底该用折线图还是柱状图？）
- 第五步：写报告（“本月销售额 100 万”……所以呢？）

三天后，你终于交出一份报告。老板看了三分钟，只记住了三行结论。

## 传统数据分析的痛点

传统数据分析的痛点，我总结了五个字： **理解难、清洗累、门槛高、选图烦、结论浅。**

更要命的是——你要会 Python、会 Pandas、会统计学，还得懂业务逻辑。这不是一个人的工作，这是三个岗位的活儿！而且最可怕的是： **这些工作高度标准化，但每次都要手动执行。**

像个机器人一样，日复一日地重复。

## 解决方案：数据分析 Skill 的核心价值

所以，数据分析 Skill 要解决的就是这个问题。

**把数据分析的标准化流程自动化。**

你可以把它理解为一个 **“数据分析师助手”** ——你说：“分析这份数据，找出流失用户的特征。”

它自动完成数据清洗、统计分析、图表制作、报告撰写——全套流程。

看这张对比表：

| 工作环节 | 传统方式 | 使用 Skill |
| --- | --- | --- |
| 数据清洗 | 2-4 小时 | 自动完成 |
| 统计分析 | 1-2 小时 | 自动完成 |
| 图表制作 | 1-2 小时 | 自动完成 |
| 报告撰写 | 2-3 小时 | 自动生成 |

**三天的工作，10 分钟搞定。**

而且输出的不是纯文字报告，是 **带交互式图表的 HTML 页面** ——可以直接在浏览器里打开，也可以一键部署分享给团队。

## 核心方法论——七步分析法

我设计的提示词采用了 **「七步数据分析法」** ——这是一套完整的数据分析方法论，在三个关键节点设置了交互确认。

复制代码

```
输入 → 业务理解 → 数据初探 → 清洗策略 → 探索性分析 → 深度分析 → 洞察输出 → 报告交付

  ↓       ↓           ↓          ↓          ↓           ↓          ↓         ↓

必须   交互点 1      质量门     交互点 2     自动执行    自动执行    自动执行   交互点 3
```

让我逐一拆解每一步。

### Step 1：明确业务背景

这是整个分析的 **方向盘** 。很多人做数据分析最大的问题是——拿到数据就开始跑统计，根本没想过"我为什么要分析这些数据"。所以我在提示词里加了一句死命令：

> **“没有业务目标的数据分析只是在做无用功。”**

这就像你去医院——医生不会一上来就给你开药，他会先问：“哪里不舒服？什么时候开始的？” **问诊，比开药更重要。**

Skill 会先问你：

- 这份数据是谁给的？
- 要解决什么业务问题？
- 预期得出什么结论？

只有目标明确了，后面的分析才有方向。

### Step 2：数据初探概览

第二步是给数据拍一张 **“体检报告”** 。

Skill 会自动检查：

- 有多少行多少列
- 有没有缺失值、重复行
- 数据类型是否合理
- 有没有明显的异常值

这里有个质量评分机制：

复制代码

```
评分 = 100 分 - (缺失值扣分 + 重复值扣分 + 类型不匹配扣分)
```
- **≥ 80 分** ：数据质量良好，直接继续
- **60-79 分** ：存在问题，提示后可继续
- **< 60 分** ：数据质量差，警告并建议先清洗

这就像食品安全检测——原材料不新鲜，做出来的菜再好吃也有问题。

### Step 3：数据清洗预处理

**这是整个 Skill 中最关键的一步！** 行业里有句名言：“Garbage In, Garbage Out”——脏数据会导致错误的结论。

Skill 会自动发现四种常见的脏数据：

复制代码

```markdown
发现以下数据质量问题：

 

1. 【缺失值】'Age' 列有 20% 缺失

   建议策略：

   - A. 删除含缺失值的行（损失 20% 数据）

   - B. 用中位数填充（年龄 =35）

   - C. 用分组均值填充（按性别分组）

 

2. 【异常值】'Price' 列存在负值（3 条记录）

   建议策略：

   - A. 删除异常记录

   - B. 设为 0 或最小值

 

3. 【格式问题】'Date' 列格式不统一

   建议策略：统一转为 YYYY-MM-DD
```

你可以逐项选择策略，也可以直接输入"recommended"使用推荐策略。甚至可以输入"auto"让 AI 全权处理。清洗完成后，Skill 会输出一份清洗日志：

复制代码

```
✓ 缺失值处理完成：Age 列已填充

✓ 异常值处理完成：3 条负值记录已删除

✓ 格式统一完成：Date 列已标准化

✓ 最终数据：14,997 行 × 25 列（清洗前 15,000 行）
```

这一步在传统流程中占 60% 到 80% 的工作量，但 Skill 可以在几秒内自动完成。

### Step 4-5：探索性分析与深度分析

在清洗干净的数据上，Skill 会做三件事：

**第一，描述性统计** ——了解数据的整体分布。

**第二，单变量分析** ——每个维度自己的分布情况。

**第三，多变量分析** ——不同维度之间的关系。

然后根据业务问题自动选择分析方法：

| 业务问题类型 | 推荐分析方法 |
| --- | --- |
| 趋势变化 | 时间序列分析、移动平均 |
| 归因分析 | 分组对比、贡献度拆解 |
| 用户行为 | 漏斗分析、留存分析 |
| 客户价值 | RFM 模型、分层聚类 |

这就像中医看病——望闻问切，四诊合参，才能找到病根。

### Step 6-7：洞察输出与报告交付

最后一步，将冷冰冰的数字转化为业务人员能听懂的故事和建议。

我采用了 **What → So What → Now What** 三段式结构：

复制代码

```
核心发现（What）—— 数据事实

业务洞察（So What）—— 为什么会这样？

行动建议（Now What）—— 应该做什么？
```

千万别只说“A 渠道转化率 5%，B 渠道 2%”！要说： **“A 渠道效率是 B 的 2.5 倍，建议将下个月营销预算向 A 渠道倾斜 30%”** 。

最后，Skill 会让你选择输出格式：

1. 【快速报告】Markdown 文档 + 图表（PNG）
2. 【交互报告】单页 HTML（可在浏览器打开，含交互图表）
3. 【完整 Dashboard】多页前端应用（Tailwind + Chart.js）

## 实战演示——真实案例

现在到了最激动人心的环节——实际运行这个 Skill。我们使用 **RavenStack 数据集** 来演示——这是一个虚构的 SaaS 平台的业务数据。

包含 15000 行用户数据，25 个维度：

- 用户画像
- 订阅生命周期
- 产品交互日志
- 客服工单
- 流失事件

### 执行过程

**第一步：创建 Skill**

使用 skill-creator，执行提示词，创建名为"data-analysis"的 Skill。

**第二步：导入数据并明确目标**

我输入的需求是：

> “分析这份数据，找出流失用户的特征，以及哪些因素与流失最相关。”

**第三步：业务理解确认**

Skill 生成分析计划：

复制代码

```
核心问题：识别流失用户特征，找出流失的关键驱动因素

关键指标：流失率、用户活跃度、订阅时长、客服工单数

分析维度：用户画像、订阅类型、使用频率、客服满意度

预期产出：流失用户画像 + 流失驱动因素分析 + 留存建议
```

确认计划无误，继续。

**第四步：数据初探与质量检查**

Skill 自动加载数据：

复制代码

```
📊 数据规模：15,000 行 × 25 列

💾 内存占用：4.2 MB

✅ 数据质量评分：82/100
```

评分 82 分，质量良好，可以继续分析。

**第五步：数据清洗**

Skill 发现少量缺失值和格式问题，我选择"recommended"使用推荐策略。几秒后，清洗完成。

**第六步：探索性分析与深度分析**

Skill 自动执行：

- RFM 用户分层
- 流失归因分析
- 留存趋势分析

**第七步：生成报告**

我选择"交互报告"格式。

### 执行结果

10 分钟后，我们得到了一份包含以下内容的专业分析报告：

1. **用户流失画像** ——流失用户 vs 留存用户的关键特征对比
2. **流失驱动因素** ——哪些变量与流失相关性最高
3. **留存趋势图** ——不同时间节点用户留存率的变化曲线
4. **行动建议** ——基于数据给出的具体留存优化建议

整个过程从上传数据到生成报告，只需要 **10 分钟左右** 。而人工完成同样的分析可能需要 **3-5 天** 。 **这就是自动化的力量！**

## 第四部分：避坑指南——千万别这么用

任何工具都有边界，用错了会翻车。

### 五大典型错误场景

#### 坑 1：数据质量决定分析质量

**【避坑指南】**  
千万记住：如果原始数据本身就是错的，再好的分析框架也救不了你。  
**【解决方案】**  
在 Step 2 数据初探阶段，花足够的时间检查数据质量。

特别关注缺失值比例超过 30% 的列——这些列的分析结论可能不可靠。

#### 坑 2：分析目标不清晰

**【避坑指南】**  
如果你自己都不知道想从数据中得到什么，AI 也不可能帮你找到答案。  
**【解决方案】**  
在使用 Skill 之前，先想清楚这份数据要解决什么业务问题。如果不确定，可以让 Skill 先做数据概览（使用 `--quick` 模式）。

#### 坑 3：图表选择不当

**【避坑指南】**  
用错图表类型会导致信息传达效率极低。比如用饼图展示 20 个品类的占比，根本看不清。  
**【解决方案】**  
严格遵守图表选择指南：

- 趋势变化 → 折线图
- 占比关系 → 饼图 / 环形图
- 对比关系 → 柱状图 / 条形图
- 相关性 → 散点图

**数据维度超过 7 个时，优先使用柱状图而不是饼图。**

#### 坑 4：结论缺乏业务洞察

**【避坑指南】**  
AI 可能会输出"本月销售额为 100 万，环比增长 10%"这种纯描述性结论。这没有业务价值！  
**【解决方案】**  
如果结论不够深入，可以手动追问：“这个数据变化背后的原因可能是什么？”

#### 坑 5：大数据量处理

**【避坑指南】**  
当数据超过 10 万行时，Skill 会自动提示你选择处理方式：

- **策略 1** ：随机抽样 10% 进行分析
- **策略 2** ：按维度聚合后再分析
- **策略 3** ：处理全量数据（耗时较长）

不要一上来就选策略 3，除非你真的需要全量分析。

### 与 L3 需求挖掘 Skill 的区别

你可能会问：L3 不也是处理 CSV 数据吗？它和 L6 有什么区别？

| 维度 | L3 需求挖掘 | L6 数据分析 |
| --- | --- | --- |
| 数据类型 | 非结构化文本（用户评论） | 结构化数值数据 |
| 核心方法 | NLP + 语义聚类 | 统计学 + 可视化 |
| 输出物 | 聚类报告 + 路线图 | 分析报告 + 图表页面 |

**L3 是从文字中找需求，L6 是从数字中找规律。**

**组合一：数据驱动产品迭代**

复制代码
