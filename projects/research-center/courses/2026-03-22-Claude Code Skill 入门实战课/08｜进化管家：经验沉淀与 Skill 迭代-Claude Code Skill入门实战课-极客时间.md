本节摘要

各位同学大家好，欢迎回到我们 Claude Code Skill 系列课程。

前几节课，我们学了怎么创建各种各样好用的 Skill：产品逆向分析、需求挖掘、会议纪要……每一个都能帮你大幅提升工作效率。

不知道大家有没有发现这样一个问题，创建好的 Agent Skill，用着用着就会发现，有些地方不太符合自己的需求。然后每次都在重复纠正同样的问题，并且 AI 却好像永远记不住。

这节课，我要教大家的，就是彻底解决这个问题，打造一个会自动进化的 Skill。

什么意思呢？简单说就是：你在使用 AI 的过程中不断纠正它，等你觉得差不多了，只需要一句话，这个 Skill 就能从你们的对话中自动提取经验，生成一个优化后的新版本。  
下次直接用新版本，所有纠正全部生效，越用越懂你。

## 需求场景

在正式开讲之前，我先和大家描述这么一个场景：

> 你花了好几天精心编写了一个 Skill 提示词，满心欢喜地拿去用。  
> 结果第一次跑出来，格式不对。你告诉它，改成表格，它改了。  
> 第二次跑，逻辑有漏洞。你又纠正它，这里要先判断再输出，它又改了。  
> 第三次跑，风格太啰嗦。你再说，精简一点。  
> 就这样来来回回了 十几轮对话，终于得到了一个还算满意的结果。  
> 但最崩溃的是什么？下次再用的时候，AI 又忘得一干二净了。  
> 你得重新从头解释一遍：先这样、再那样、不要这样、必须那样……

为什么会产生这样的问题？

因为 Agent Skill 是写完就定型的了，它不具备随着使用过程自我迭代的能力。

那如果没有今天这个工具，你会面临什么呢？

1. 每次调优都要重复劳动。同样的话你得说好多遍，浪费时间。
2. 经验无法沉淀。你脑子里的调优经验，全靠记忆，过两天可能就忘了。

但有了这个自动进化 Skill 呢？每一次纠正都不是浪费，而是投资。 你的 Skill 会在使用过程中一次次进化中，变得越来越懂你。

## 实现步骤

好，相信通过刚刚的介绍，大家已经对这个自动进化 Skill 充满了好奇。接下来，我就来与大家分享一下它是如何实现的。

这个 Agent Skill 的执行过程一共可以划分为 4 个阶段：分别是「审计 - 裁决 - 整合 - 复盘」

### Step 1：语料复盘

进化流程的第一步是「语料复盘」，也是整个流程的关键起点。

用户往往无法一次性说清所有需求，大量关键信息都隐藏在多轮对话细节中。比如第 3 轮说的“标题要加粗”，是风格要求；第 7 轮“不要用 emoji”，是负面约束；第 12 轮“数据来源写最前面”，则是逻辑澄清。

这些零散的纠正，要是不进行结构化提取，很容易遗漏、记混，进而影响后续执行。

所以我设计了一个包含四个核心维度的提取表格，专门用来整理这些零散要求。

除此之外，还告诉 AI，提取的每一条约束，都必须引用用户原话作为依据，避免主观猜测，确保需求准确。

### Step 2：冲突裁决

第二步是“冲突裁决”。在多轮对话里，用户需求经常会变，甚至前后矛盾，这一步就是为了确定“到底听哪一句”。

裁决规则有四条：

1. 近时性原则。简单说，就是“听最新的”。第 15 轮提出的修正，优先级一定高于第 2 轮的初始需求。因为最新的反馈通常代表了你看到结果后的实时想法。
2. 具体化原则。具体指令大过通用指令。如果全局要求“精简”，但你额外补了一句“代码要详细”，那么系统会保持整体精简，唯独对代码进行详细拆解。
3. 场景解耦。如果两个需求分不出高下，就用逻辑分支来兼容。比如：如果是给小白看，就详细解释；如果是给专家看，就直接给结论。让系统根据上下文自动切换模式。
4. 冲突确认。这是最后的安全阀。如果系统实在判断不了，它不会瞎猜，而是会主动问你一句，由你来明确哪个指令优先。

### Step 3：整合优化

第三步：整合优化。这是从准备素材转向产出 Skill v2.0 的关键环节。

原则一：优先级排序 核心需求排第一，负面约束紧随其后。逻辑在于，“不能做什么”往往比“要做什么”更关键。负面约束一旦被违反，整个输出就会直接失效，所以必须给予极高的权重。

原则二：逻辑清洗 删除所有被后期指令覆盖的旧规则。例如，如果要求已从“表格”改为“列表”，旧的表格指令必须清除干净，防止模型在冲突的规则中产生执行偏差。

原则三：指令化表述 放弃建议性语言，改用强命令。

- 用“必须”取代“可以考虑”
- 用“始终”取代“尽量”
- 用“严禁”取代“最好不要”
- 用“仅允许”取代“或许可以”

措辞的强硬程度与模型的执行准确率直接正相关。

### Step 4：进化复盘

最后一步叫「进化复盘」。这一步只要求做一件事：用一句话概括本次进化的价值。

模板是这样的：  
“本次进化解决了某个具体痛点，通过新增某些约束，实现了输出质量或效率的提升。”

这句话的作用是什么呢？

1. 给用户明确的交付感知。让你知道这次进化到底值不值。
2. 形成进化日志。多次迭代后，你可以回溯每次改进的具体内容。
3. 辅助决策。如果某次进化的价值描述很模糊，说明这次对话中可能没有足够有价值的纠正。

## 实操环节

好，理论讲完了，接下来就让我们来开始进行实际演示操作。

我已经提前准备好了周报生成器 Skill 和自动进化 Skill。我们先来看一下默认生成的效果，再来一步步优化它。

在使用这个自动进化 Skill 的过程中，有几个注意事项是需要我们提前了解的：

1. 大模型有上下文窗口的限制。如果你的对话超过了几十轮，早期的一些纠正可能会被遗忘。所以不要优化需求等到最后再一次性处理。
2. 在进行描述需求时，应可能减少前后需求不一致的情况。
3. 如果发现进化后的 Skill 生成结果反而变得更差了，此时需要手动检查一下 SKILL.MD 文件，人工确认一下是否引入了一些非预期的规则内容，如果有，手动操作删除即可

好了，让我们回顾一下今天学到的核心内容。

我们通过创建自动进化 Skill，解决了 Agent Skill 创建完就定型了，没法跟着使用过程自我迭代的问题，最终实现了 Skill 越用越聪明的效果。
