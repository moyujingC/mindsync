第 5 讲我们划清了“研究不等于实盘执行”的安全边界。这节课开始，我们进入数据证据层：在讨论任何信号、摘要或报告之前，先确认输入数据本身能证明什么。

行情、资金、链上和情绪数据都可能描述“市场”，但它们记录的不是同一类事实。行情多来自交易所成交结果；资金数据提供流向或市值线索；链上数据受区块确认和索引口径影响；情绪数据往往来自指数、文本或模型候选。把它们直接拼成一个“当前市场状态”，报告会显得完整，却可能已经混入时间错配、来源延迟和口径偷换。

本讲的目标不是判断市场方向，而是交付一张可复查的市场数据地图：每类数据从哪里来、记录哪个时间、字段口径是什么、能回答什么、不能回答什么。学习完后，你应能把行情、资金、链上和情绪数据分别写成来源卡，并判断哪些材料可以合并解释，哪些只能分别展示。

## 1\. 区分四类市场数据

第 4 讲区分价格、收益率、量化信号、持仓仓位、权益曲线五层指标体系；第 5 讲划定研究输出不可直接转化为实盘指令。本节补充底层数据的证据约束边界，解决多源数据混用导致的逻辑误判。

### 1.1 典型数据误用反例

行业高频错误推导逻辑：BTC 现货行情价格下行、链上活跃地址数量抬升、恐惧贪婪指数落入恐慌区间，由此得出结论——市场正在恐慌性增持。该推导存在三重证据偷换：

行情数据为分钟级实时成交快照，链上交易存在区块确认延迟，二者观测窗口天然错位。

情绪指数更新周期、采样人群与交易所成交数据无时间同步机制。

价格、链上地址活跃度、市场情绪三类指标无法直接推导用户真实增持行为。

因此本讲优先划定四类数据各自的有效证据范围，表 6-1 为第二章全流程实操基准规范。

| 数据类型 | 主要回答 | 常见字段 | 不能直接证明 |
| --- | --- | --- | --- |
| 行情数据 | 价格、成交量、涨跌幅 | last、close、volValue、changeRate | 资金真实流向或未来收益 |
| 资金数据 | 资金分布、流入流出线索 | tradeType、市值、流通量、资金相关字段 | 实盘执行指令或策略有效 |
| 链上数据 | 链上活动、地址或交易行为 | 交易数、活跃地址、链上事件 | 交易所订单簿即时状态 |
| 情绪数据 | 市场叙事、风险偏好、候选机会 | 恐惧贪婪、热度、AI picks | 真实订单或确定预测 |

### 1.2 四层数据证据校验门

所有原始数据进入指标计算、大模型摘要生成流程前，必须依次通过四层校验门。只有四道门都能留下证据，才允许进入指标计算或 LLM 摘要；任一门失败，禁止流入下游分析链路，只能退回来源卡，重新核验。

来源校验门：核验数据原始采集渠道合法性、数据分层（离线样本 / 快照 / 实时源）。

时序校验门：区分观测时间、快照存储时间、复核系统时间，校验时序延迟阈值。

字段口径门：核验指标统计规则、单位、筛选逻辑统一。

用途边界门：核验待解答问题未超出该类数据的证据范围。

这些命令只能说明路径存在，不能证明数据适合交易，也不能证明某个信号应被执行。如果其中某一项返回 False，应先补路径或修正文中引用，不能把缺失路径写成“预计可通过”。

命令之外，还应做一次只读走查。打开 data/dashboard/manifest.json 时，先看 datasets 下每个数据集的 origin、updated\_at、complete 和 path。origin 说明数据来自 fixture、live、test 还是其他层；updated\_at 说明保存时间；complete 说明完整性检查是否通过；path 说明可追溯文件在哪里。四个字段缺一项，都不应直接进入“市场正在如何”的结论。

src/dashboard/api.py 的价值在于，把不同数据源组织成统一接口，但统一接口也会制造一种错觉：既然 API 返回了同一种 JSON，就好像所有字段属于同一个时间点。复核时要反过来警惕这种整齐感。

一个合格的 API 输出不仅要有值，还要保留来源、失败状态和 fallback 过程。否则 LLM 或页面会把“为了可用性而降级的结果”误解成“高质量的实时事实”。这也是行业里的常见痛点：很多量化 AI 分析工具默认只展示结论字段，没有原生数据溯源字段，后续复核时很难判断结论来自实时源、快照源还是离线样本。

## 3\. 写出可复查的来源卡

明确仓库溯源路径后，我们来写四类数据标准化来源卡。来源卡是指标计算、LLM 摘要、前端展示的准入门槛，不属于补充附录，是量化研究的标准化证据合同。

### 3.1 来源卡统一字段模板

表 6-3 给出我们的来源卡模板。它刻意把“能回答什么”和“不能回答什么”放在同一张表里，是为了防止只记录有利证据。

| 字段 | 合格写法 | 不合格写法 |
| --- | --- | --- |
| 数据域 | 行情、资金、链上或情绪 | “市场数据”一笔带过 |
| 来源 | fixture、snapshot、live 或明确上游 | “系统返回” |
| 保存时间 | 使用 updated\_at、文件时间或快照 ID | 只写“最新” |
| 关键字段 | 列出本次实际使用的字段 | 只贴完整 JSON |
| 可回答问题 | 说明该数据支持哪类判断 | 直接写成结论 |
| 不能回答问题 | 写明不能外推的范围 | 空白或“无” |
| 失败处理 | 缺字段、错时间或不完整时如何停止 | 失败后继续解释 |

四张卡都完整后，数据才有资格进入指标计算或 LLM 摘要。来源卡完成后，至少做一次交叉检查：比较同一资产在行情数据和情绪数据中的时间戳。如果时间窗口不同，正文只能写“两个来源分别显示……”，不能写“当前市场同时出现……”。

这一点尤其影响 LLM 摘要。模型很擅长把分散字段写成流畅段落，例如“价格下跌、链上活跃、情绪恐慌，显示市场承压”。如果没有来源卡，复核者很难看出这句话是否混用了不同时间窗口。

更稳妥的写法是：“行情 fixture 显示某一保存时间下的价格变化；情绪样本来自另一保存时间，只能作为独立线索，不能证明同一时点因果关系。”这句话不如前一句直观，但更符合研究证据。

我们的来源卡也要保留冲突。行情偏弱、链上偏强、情绪偏乐观，并不意味着系统出错，它可能意味着数据观察的是不同维度，也可能意味着其中一个来源有延迟或噪声。研究者应先保留冲突，再决定是否继续采集、降级解释或停止判断。把冲突强行改写成单一方向，是数据研究中最隐蔽的过度承诺。

### 3.2 四类数据地图示例

以 BTC 标的为例，标准化构建市场数据地图分为四步执行：

定位元数据：读取manifest.json内market\_tickers、token\_fund、onchain、ai\_picks数据集，逐条记录 origin、updated\_at、complete、path 字段；区分快照层、离线样本层，分层数据不可合并视为同一实时面板。

提取核心字段：每类数据仅提取本次分析所需关键字段，完整原始 JSON 仅作归档素材，不写入来源卡。

行情：symbol、last、close、changeRate、volValue。

资金：marketCap、circulatingSupply、资金流入指标、更新时间戳。

链上：区块事件时间、公链标识、地址统计口径。

情绪：采集来源、AI 评分逻辑、模型输出时间戳。

定义可解答边界：仅客观陈述数据记录的客观事实，不推导交易结论。

明确不可外推范围：逐条写明指标无法证明的逻辑，覆盖因果、收益、实盘指令三类常见越界推导。

这个案例的交付物不是一段漂亮总结，而是一份别人能复查的记录。交接复核者拿到记录后，应能找到原始文件、确认保存时间、复算一个简单收益或覆盖率，并指出哪些句子只能算解释、哪些句子已经越过数据边界。如果做不到，说明记录还停留在作者视角，没有变成可交接证据。

把这个示例迁移到真实仓库时，要检查现有路径是否已经表达同样的合同：catalog.py 是否能说明数据不完整的原因，manifest.json 是否保留保存时间，API 是否把 fallback 结果标明为离线或快照，页面是否避免把候选信号写成实盘执行指令。只要这些问题回答不清，数据地图就还没有完成。

最小测试清单包括三类：

单元测试：缺少 source、observed\_at 或合法价格时，样本必须被拒绝；manifest 来源卡必须保留 cannot\_answer。

数据完整性测试：market\_candles、market\_tickers、onchain 等 fixture 或 snapshot 必须通过 is\_complete()，失败原因要能从 completeness\_detail() 读到。

文档评审测试：报告不得把不同时间窗口的数据写成同一时点事实，也不得把来源不明的字段交给 LLM 补写。

## 4\. 复核跨来源数据口径

数据来源卡不是表格填空。它必须能支撑最小复算、偏差识别和人工复核，否则就只是把不确定性换了一种格式保存。

### 4.1 固定三个复核口径

严谨数据分析流程遵循「固定变量定义→划定样本范围→核算统计指标」顺序，规避两类典型错误：公式逻辑自洽但变量统计口径不一致；样本表面完整但存在未记录数据筛选规则。

#### 4.1.1 全局变量命名规范

时间类变量：小写字母搭配语义下标， 为数据观测时间， 为复核 UTC 时间。

阈值约束类变量：大写字母， 为允许最大时序延迟。

计数类变量：n 搭配语义下标， 为有效样本记录数量。

数学变量与工程代码标识符一一映射：， 取系统当前 UTC 时间戳，。 关键区分：updated\_at 仅代表快照落地存储时间，无上游声明时不可等同于市场事件观测时间。

#### 4.1.2 三大核心数据质量指标

##### ① 数据覆盖率

定义 ：t 观测时刻，同一标的、统一报价货币、统一采样周期的收盘价 close；last、估算撮合价格不可与 close 无差别混用。资金、情绪衍生评分的权重、阈值、缺失处置规则必须完整归档；缺失字段禁止默认填充数值 0，0 为有效统计值，不可混淆未知状态。

#### 4.1.4 样本与成本口径说明

本讲教学中的离线样本、快照仅用于流程复现，不还原真实交易场景：不包含滑点、手续费、订单簿深度、资金费率建模；若分析不涉及成交测算，需明确标注「本分析未建模交易成本」，不可简化为交易成本等于 0。 快照存储时间 updated\_at 与每条记录内部事件观测时间强制分开标注；归档快照路径仅证明系统存储记录，无法证明上游数据源同步采集。本讲的时序、口径校验体系，为第 7 讲快照流程、第 12 讲 LLM 上下文构造、第 15 讲大模型信号评测提供底层约束，基础校验越严谨，下游自动化流程越难放大数据缺陷。

### 4.2 偏差控制与人工复核

自动化校验可拦截字段缺失、格式异常、基础完整性缺陷，但无法识别语义口径偷换、时序逻辑错位等人为偏差，必须配套人工复核机制。

#### 4.2.1 四类高频时序偏差与反例

时区错配偏差：多数据源混用 UTC、本地时区、毫秒时间戳，仅补充统一时区转换方可对比窗口；未标准化时区会制造数小时虚假时序重合。

from datetime import datetime, timezone

from zoneinfo import ZoneInfo

utc\_saved\_at = datetime.fromisoformat("2026-06-21T16:33:21+00:00")

local\_observed\_at = datetime.fromisoformat("2026-06-22 00:33:21")

wrong\_observed\_at = local\_observed\_at.replace(tzinfo=timezone.utc)

right\_observed\_at = local\_observed\_at.replace(

tzinfo=ZoneInfo("Asia/Shanghai")

).astimezone(timezone.utc)

assert wrong\_observed\_at!= utc\_saved\_at

assert right\_observed\_at == utc\_saved\_at

数据源延迟偏差：前端面板标注 “最新数据”，底层实际为离线样本、历史快照、兜底降级数据，无元数据标记则完全掩盖延迟缺陷。

缺失值过度填充偏差：线性插值、历史回填让图表视觉连续，但掩盖原始数据空白，扭曲真实市场观测状态。

历史快照覆盖偏差：旧快照被自动覆盖，丧失复盘原始观测数据的能力，研究结论不可复现。

人为构造行情、情绪数据时序无交集样本，调用分析链路生成市场汇总结论；合规系统必须自动降级，仅分开描述两类独立线索，禁止输出同步市场判断。图 6-5 展示这个失败样本。它的重点是让你看到：时间错配不是措辞问题，而是证据结构问题。

#### 4.2.2 人工复核与三级发布判定标准

完成全流程数据校验后，必须执行至少一项人工数值复核，复核记录归档要素：原始输入样本、代入校验公式、程序输出结果、结论边界约束。

复核可选方向：

行情收益率复核：读取同文件连续两条 close，统一标的与报价货币，代入收益率公式 。

元数据复核：核验 manifest.json 数据集 origin 分层、complete 校验函数支撑、原始文件物理路径存在。

API 接口复核：追溯 api.py 对应函数，区分实时上游、归档快照、离线样本三类兜底逻辑。

人工复核核心目的：验证自动化校验规则匹配研究语义，程序仅能校验格式，无法判断指标是否适配研究问题；大模型仅能解读字段字面含义，无权忽略数据缺失、时序冲突缺陷。

基于复核结果划分三级发布判定，完整写入研究档案：

直接通过：四类来源卡完整归档、所有关键字段可溯源、时序错配测试可触发降级逻辑、未将样本事实等价为实盘指令；仅代表数据证据合规，不代表市场预测有效。

修改后复测：仓库路径完整，但存在字段无来源、时序口径模糊、校验规则仅文档标注未代码落地，补充修正后二次校验。

直接拒绝：数据源无法追溯、历史快照覆盖丢失、LLM 自动补全缺失字段、面板将候选信号标注为实盘指令；及时拦截可避免下游回测、策略开发基于污染数据。

## 总结

本讲完整搭建市场数据地图标准化交付体系，核心要求：解读数据前完整核验来源、观测时序、统计口径、采集延迟、适用边界、异常处置六大维度。

区分三层不可混淆的表述层级：

客观事实：BTC-USDT 离线样本快照内 last 字段为指定数值。

计算推导结论：该观测窗口内标的收盘价相对前一周期下行。

越界交易指令：当前时点适合开仓交易（超出本讲数据证据边界，禁止输出）。

我们的核心学习目标，并非记忆四类数据名称，而是建立标准化校验思维：任何数据进入分析链路前，固定核验五问：数据采集渠道是什么？记录的市场观测时间？字段统计口径如何定义？能够支撑哪些客观判断？数据异常时系统如何终止下游流程？完成五重校验，原始素材方可转化为可采信研究证据。
