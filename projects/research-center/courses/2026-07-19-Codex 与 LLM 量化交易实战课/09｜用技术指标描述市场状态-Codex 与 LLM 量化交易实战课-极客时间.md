看到一张价格走势图时，很多初学者会下意识问：“接下来会涨还是会跌？”技术指标最容易被误用的地方，正是把“现在看到了什么”直接写成“接下来一定会怎样”。

这节课我们先不讨论买入、卖出，也不讨论完整策略，而是完成一件基础工作：把价格样本里的状态说清楚。例如，收盘价在均线之上，说明价格高于过去一段时间的平均水平；RSI 偏高，说明近期上涨力量较强；价格接近布林带上轨，说明它处在近期波动区间的偏高位置。这些都只是观察结果，不是交易结论。

本讲的最终交付物是一张指标计算与解释卡。这张卡记录输入数据窗口、指标公式口径、指标读数、指标冲突、可采用的解释方式和应避免的越界表达。第 10 讲我们会把这些读数写入可追溯的市场研究报告；第 16 讲会把状态描述转化为可测试的策略规则；第 18 讲会把规则放入事件驱动回测。后续每一次引用指标，都要先回到这张卡，确认判断有数据来源。

## 1\. 边界核心定义

技术指标进入研究报告前，先要划清语言边界。本节先区分状态描述、策略规则和交易动作，再把常用指标限定在各自能描述的维度内。

### 1.1 状态、规则与动作

本讲统一使用三层术语。表 9-1 说明三层术语各自回答的问题，以及本讲允许和不允许的表达边界。

| 层级 | 回答的问题 | 本讲允许的写法 | 本讲不允许的写法 |
| --- | --- | --- | --- |
| 状态描述 | 固定样本当前呈现什么特征 | close < SMA20，RSI14 偏弱，ATR14 占比上升 | 应当买入、应当卖出 |
| 策略规则 | 何时触发入场、离场或观望 | 第 16 讲会定义可测试规则，例如 close <= lower -> long\_candidate | 在本讲直接生成订单方向 |
| 交易动作 | 是否下单、下多少、怎样风控 | 第 22 讲会结合仓位、止损和风险预算讨论执行边界 | 把指标读数写成仓位建议 |

表 9-1　三层术语与职责边界

技术指标是历史数据的压缩描述。SMA20 描述价格相对平滑基准的位置，RSI14 描述近期涨跌动量，布林带描述价格相对波动通道的位置，ATR14 描述真实波幅尺度。它们可以提示你继续观察哪些维度，但不能独立回答未来方向、收益概率、仓位大小或风险是否可控。

一个合规示例可以这样写：RSI14=78、bbPctB=91.5、atrPct=2.4% 同时出现时，解释卡记录为“动量偏热、价格接近布林带上沿、波动尺度需要复核”。若系统同时给出 actionLabel，该字段只表示可视化聚合标签，没有统计胜率含义；是否进入策略规则，还要另行验证。

专业术语注释

SMA20：20 周期简单移动平均线

RSI14：14 周期相对强弱指标

bbPctB：布林带百分位（布林带位置指标）

atrPct：ATR 相对波动百分比

actionLabel：交易动作标签

解释卡记录：行情信号注释日志

ART4：14 周期平均真实波幅

## 3\. 指标复算与验证规范

指标解释先验证输入，再验证公式，最后验证语言。输入不足、公式不可复算或解释越界，任一项失败，都不能进入研究观测记录。

## 4\. 代码实现与校验

本节集中说明代码入口和最小可运行示例。指标函数由 src/ta/core.py 实现，并通过 src/dashboard/indicators.py 对外暴露；K 线状态分析由 src/dashboard/kline\_analysis.py 的 analyze\_candles、kline\_verdict 和 run\_kline\_analysis 组织。

下面先看分析函数怎样处理窗口不足，再用固定样本脚本生成解释卡，最后用测试命令和边界校验函数确认输出没有越过研究观察范围。

### 4.1 分析入口

analyze\_candles 是本讲进入指标计算的主入口。它接收已经标准化的 K 线序列，而不是交易所原始数组。进入函数前，时间顺序、字段转换和缺失处理应已在第 8 讲完成。

这个函数至少需要 20 根 K 线。它会抽取开盘价、最高价、最低价、收盘价和成交量，计算 SMA20、SMA60、RSI14、布林带、ATR14、20 根支撑阻力、量比、区间位置和行情状态。窗口不足时返回 None，这比补造一个看似完整的指标值更可靠。

本讲样本只有 35 根 K 线，足够计算 SMA20，但不足以计算 SMA60，正好保留了窗口不足的边界案例。解释卡应如实写出 SMA60=None，而不是用短窗口指标替代长期趋势读数。

### 4.4 边界校验函数

代码 9-4 给出可复用边界校验函数，用于拦截缺字段、明显越界措辞和数值异常。数值异常包括：rsi14 不在 0 到 100 之间，atr14 为负数，atrPct 为负数，bbPctB 不是数值，或 close 小于等于 0。

def validate\_indicator\_card(card: dict) -> list\[str\]:

issues: list\[str\] = \[\]

required = ("input", "readings", "allowed", "forbidden")

for key in required:

if key not in card:

issues.append(f"missing field: {key}")

allowed = str(card.get("allowed", ""))

for term in FORBIDDEN\_TERMS:

if term in allowed:

issues.append(f"allowed text crosses boundary: {term}")

readings = card.get("readings") or {}

if readings.get("sma20") is None:

issues.append("SMA20 is unavailable; explain insufficient window before publishing")

close = readings.get("close")

rsi14 = readings.get("rsi14")

atr14 = readings.get("atr14")

atr\_pct = readings.get("atrPct")

bb\_pct\_b = readings.get("bbPctB")

if close is not None and close <= 0:

issues.append("close must be positive")

if rsi14 is not None and not 0 <= rsi14 <= 100:

issues.append("RSI14 must be between 0 and 100")

if atr14 is not None and atr14 < 0:

issues.append("ATR14 cannot be negative")

if atr\_pct is not None and atr\_pct < 0:

issues.append("atrPct cannot be negative")

if bb\_pct\_b is not None and not isinstance(bb\_pct\_b, (int, float)):

issues.append("bbPctB must be numeric when present")

return issues

## 5\. 指标冲突与解释卡案例

指标冲突不是异常，而是需要记录的研究事实。同一段样本可能同时出现价格低于 SMA20、RSI14 接近低位、布林带宽度扩大、ATR14 占比上升。它们分别描述趋势、动量、通道位置和波动尺度，不需要被压成一个方向。

本节用两个解释卡案例展示这种写法：先看固定样本如何形成合规描述，再看冲突样本如何保留不一致信息，最后用参数窥探反例说明研究流程风险。
