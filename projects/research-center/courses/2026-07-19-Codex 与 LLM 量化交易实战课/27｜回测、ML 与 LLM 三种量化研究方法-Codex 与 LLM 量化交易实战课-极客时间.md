第 26 讲我们已经把回测页和风险页做成可复核页面。这节课继续往下走：页面能展示结果，不等于研究方法已经成立。量化研究真正要回答的是，候选信号能不能穿过样本、成本、时间切分和风险证据的检验。

规则、机器学习和 LLM 都能提出候选，但它们的证明方式不同。规则回测要说明账户路径，机器学习要先验证排序能力，LLM 只能提出受约束的假设和解释已有证据。三者最后都要落到同一套回测纪律里。

本讲的边界很清楚：回测不是寻找“最好看的收益曲线”，而是建立一套能重跑、能解释、能降级的研究纪律。我会带你先看方法分工，再进入回测引擎、实战复核、ML / LLM 候选验证，最后把这些证据交给 Codex 做窄范围复核。

## 1\. 三种方法的研究契约

量化研究容易被一句话带偏：“模型发现一个信号，回测效果不错，所以策略可用。”这句话跳过了三个问题：信号有没有偷看未来，交易规则是否能执行，结果能否经受成本、样本外和过拟合检查。表 27-1 先把三种方法的分工理清楚，避免后面把候选、解释和交易证据混在一起。

本讲使用固定教学样本 WEB3-DEMO/USDT。规则回测来自 backtest.rolling.service，ML 和 LLM 候选来自 factor\_mining.service，图表由 scripts/generate\_chapter27\_figures.py 生成。样本不代表真实市场，只负责让三种方法在同一批数据上可比。

| 方法 | 本讲判断什么 | 仓库入口 | 不能直接证明 |
| --- | --- | --- | --- |
| 规则回测 | 明确规则在固定样本中怎样交易 | backtest.rolling.service.execute\_backtest | 规则未来仍然有效 |
| ML 因子 | 历史特征是否对未来收益有排序能力 | factor\_mining.service.run\_factor\_mining(mode="ml") | 因子可以直接实盘交易 |
| LLM 辅助 | 模型能否提出受约束候选或解释信号 | run\_factor\_mining(mode="llm")、dashboard.llm\_signal | 模型文字等于交易证据 |

表 27-1　三种量化研究方法的分工

关键名词解释：

ML 是 Machine Learning，也就是机器学习。在本讲里，它先验证特征对未来收益的排序关系，再讨论能否转成交易。

LLM 是 Large Language Model，也就是大语言模型。它只负责候选生成、结构化解释和报告整理，不能跳过回测。

DSR 是 Deflated Sharpe Ratio，可理解为“折减后的 Sharpe”，用来提醒你：多次试验以后，漂亮 Sharpe 可能只是选择偏差。

PBO 是 Probability of Backtest Overfitting，用来估计回测结果来自过拟合的概率。

CPCV 是 Combinatorial Purged Cross-Validation，是组合式交叉验证，用来观察多条训练 / 测试路径是否一致。

我们会采用四道门来判断所有结果：

数据门：样本时间、字段、标签和可见信息要说清楚。

交易门：信号如何变成仓位，成交、费用和滑点如何进入账户路径。

统计门：单次收益要接受窗口、样本外、DSR、PBO 和 CPCV 的复核。

解释门：LLM 或报告文字只能解释已经存在的证据，不能替代证据。

这四道门是后面所有图、表、代码和 Codex 委托的共同口径。任何单次好结果，都不能抵消样本外、过拟合、成本或风控证据。

## 2\. 回测引擎：从数据到账户路径

规则回测的优点是可解释。策略什么时候入场、什么时候出场，赚亏来自哪段价格，都能追到交易记录。它的弱点也明显：单次收益很容易被参数、窗口和成本假设影响。正式研究时不能只交付一条收益曲线，还要交代这条曲线是怎样被引擎生成的。

### 2.1 策略契约

实际交付里最容易漏掉的是“回测合同”。一条收益曲线至少要配五个字段：样本范围、信号规则、成交假设、成本口径和风险出口。没有样本范围，结果不能复现；没有信号规则，收益不能解释；没有成交和成本，曲线会偏乐观；没有风险出口，你无法知道策略失败时怎样停下来。表 27-2 把这些字段放回到回测引擎的组件里。

| 回测组件 | 它回答的问题 | 本仓库对应证据 |
| --- | --- | --- |
| 数据处理 | 这根 K 线在当时是否可见 | load\_candles、固定样本、limit |
| 信号生成 | 规则在当前信息下想做什么 | strategy\_name、candle\_signals |
| 组合与仓位 | 信号如何变成风险暴露 | equity\_curve、position、risk hook |
| 成交模拟 | 订单以什么价格和成本成交 | cost\_preset、commission、slippage |
| 绩效与审计 | 路径是否经得起复核 | return、drawdown、WFO、PBO、CPCV |

表 27-2　回测引擎的最小组件合同

这张表比单独一条收益曲线重要。收益曲线只能说明账户路径长什么样；组件合同能说明这条路径是怎么来的。复核回测时，应先问“哪一个组件最可能让结果失真”：数据可能偷看未来，信号可能过度拟合，仓位可能隐含满仓假设，成交可能低估滑点，绩效可能只挑了好窗口。

图 27-1 把回测引擎画成从数据到账户路径的事件链。每个中间环节都可能改变结果：信号滞后方式会改变入场，成交模型会改变价格，成本模型会改变收益，风险模块会改变仓位。

### 2.2 常用回测范式

回测实现通常有两种风格。向量化回测把信号、仓位和收益写成数组运算，速度快，适合因子初筛和大量参数扫描；事件驱动回测按时间推进事件队列，更接近真实交易流程，适合验证订单、成交、资金、风控和多资产组合。本专栏的教学实现偏事件驱动：先接收 K 线，再生成信号，再更新组合与权益。

常用回测不是一种算法，而是一组验证范式。不同范式回答的问题不同，不能混成“跑回测”三个字。表 27-3 用同一口径对照这些范式：每一种范式回答什么问题、容易犯什么错、在仓库里从哪里复核。

| 回测范式 | 适合回答的问题 | 常见陷阱 | 本仓库位置 |
| --- | --- | --- | --- |
| 历史回放 | 规则在固定历史样本上怎样交易 | 把样本内路径误读成未来能力 | execute\_backtest |
| 向量化回测 | 因子或参数能否快速初筛 | 容易隐藏成交顺序和持仓约束 | factor\_mining.evaluate |
| 事件驱动回测 | 信号、订单、成交、风控怎样串起来 | 实现复杂，速度较慢 | backtest.rolling.engine |
| 滚动窗口 | 不同时间段表现是否一致 | 窗口切分过少会误判稳定性 | compare\_windows |
| Walk-Forward | 训练段选参后，下一段样本外表现怎样 | 边测试边调参会污染样本外 | run\_walk\_forward |
| Purged / CPCV | 标签看未来时，多条训练测试路径是否稳健 | 不处理重叠标签会泄漏信息 | run\_cpcv\_service |
| 蒙特卡洛 / 重采样 | 交易顺序或扰动后，路径是否仍可承受 | 模拟分布假设会影响结论 | run\_robustness\_audit |
| 成本压力测试 | 手续费、滑点、资金费率变差后是否还成立 | 低估成本会制造虚假优势 | cost\_preset |

表 27-3　常用回测范式与本讲判断问题

这些范式之间有顺序。历史回放先回答“规则能不能跑通”；向量化回测适合做候选初筛；事件驱动回测负责把候选放进账户和成交流程；滚动窗口和 Walk-Forward 检查时间稳定性；CPCV 和蒙特卡洛类方法检查路径是否脆弱；成本压力测试检查优势是否只是被低成本假设撑起来。

把这些范式落成可执行算法，可以按以下路径理解：

基准回放算法：固定样本和初始资金，生成买入持有或空仓基准，给复杂策略一个最低参照。

向量化信号回测算法：把价格变成收益，把规则或因子变成信号，再把信号滞后一格变成仓位，避免当根 K 线偷看未来。

事件驱动回测算法：行情事件进入策略，策略产生信号事件，组合模块转成订单事件，撮合模块生成成交事件，账户模块更新现金、仓位和权益。

订单撮合算法：区分市价单、限价单、止损单和止盈单，并检查当根 K 线的 high / low 是否触及价格。

成本与冲击算法：加入手续费、滑点、买卖价差、资金费率、容量限制和冲击成本，检查优势是否被低成本假设撑起来。

仓位与再平衡算法：把信号转成固定资金比例、目标权重、波动率缩放或风险平价等风险暴露。

滚动窗口算法：把样本切成多个连续窗口，暴露规则在哪些时间段失效。

Walk-Forward 算法：在训练段选择参数，只把选好的参数拿到下一段样本外测试。

Purged / CPCV 算法：移除标签窗口重叠带来的信息泄漏，用多条训练 / 测试路径观察稳定性。

蒙特卡洛与扰动算法：打乱交易顺序、抽样交易结果、改变滑点或随机丢失部分信号，检查路径脆弱性。

纸上交易：把策略逻辑放到实时或准实时数据中执行，只记录交易进出和盈亏，不使用真实资金。

情景分析算法：假设成本翻倍、波动率上升、流动性下降或资金费率恶化，检查坏场景下是否越过风险边界。

这些算法还要配一层归因。收益可以拆成市场基准、择时、选币或选股、仓位、成本和残差；回撤可以拆成价格回撤、仓位放大、连续亏损和风控失败。没有归因，回测只告诉我们“发生了什么”；有归因，回测才开始解释“为什么发生”。

### 2.3 审计问题清单

严肃回测至少要回答一组基础问题。它们不是形式化清单，而是我们保护自己不被漂亮曲线带偏的操作顺序。

样本从哪来，是否固定，是否包含当时不可见的信息？

K 线、资金费率、成交量和快照时间是否对齐？

信号是在当前 K 线收盘后生成，还是偷看了下一根？

入场价、出场价、止损价和止盈价按什么规则确定？

仓位是固定金额、固定比例，还是按波动率调整？

手续费、滑点、资金费率和最小交易单位是否进入权益？

是否允许做空、杠杆、同一时点多笔订单或部分成交？

风险规则在下单前拦截，还是回测后才评价？

收益曲线是否能追到逐笔交易和每次仓位变化？

指标是否同时覆盖收益、回撤、波动、换手和暴露时间？

参数是否只在训练段选择，测试段是否完全隔离？

失败窗口、被拒订单和亏损交易是否保留在报告里？

年化收益、Sharpe、Sortino、Calmar、最大回撤和胜率都是结果指标；交易次数、换手、暴露时间、平均持仓周期和回撤持续时间是路径指标；成本、滑点、容量和拒单原因是现实指标。三类指标要一起看。只看第一类，回测会变成结果展示；三类都看，回测才接近研究证据。

## 3\. 规则回测实战：路径、成本与稳健性

下面我们把前面的合同落到仓库里的 ma\_crossover 样例。重点不是证明均线策略好坏，而是演示一条规则怎样从单次回测走向路径诊断、成本压力、窗口复核和参数敏感性。

### 3.2 路径诊断与证据判定

最终收益只是入口，路径质量才是正文。交易只有 4 笔时，单笔盈亏会强烈影响结论；窗口 0/3 为正时，说明结果对切分方式敏感；PBO 偏高时，说明选择过程本身可能已经把结果推向乐观。把这些证据合在一起，动作应当降级为“停止放行或修订后复测”。

### 3.3 成本、窗口与参数敏感性

## 4\. ML 与 LLM 候选：从排序到交易证据

规则回测回答“明确规则怎样交易”。ML 和 LLM 则更容易出现在候选生成层：一个从历史特征里学习排序关系，一个从文本和上下文里提出结构化假设。两者都不能绕过交易验证。

### 4.1 ML 因子验证

ML 在本讲先回答一个窄问题：一组历史特征能否对未来收益形成排序。IC 是信息系数，用来衡量因子分数与未来收益的相关性；IR 是信息比率，在这里帮助判断这种相关性是否稳定。它们证明的是“排序关系”，不是“交易策略已经成立”。

金融 ML 和普通分类任务的差异在时间。标签往往来自未来收益，相邻样本又可能共享一段未来信息。普通随机交叉验证会把未来线索带回训练集，所以本讲采用更保守的判断链：先按时间切分看训练 / 测试 IC，再把候选因子接入交易回测，最后用成本、窗口和试验账本复核。

代码 27-2 展示这个判断链的最小入口：先生成 ML 候选因子，再把候选里的 backtest\_spec 接入交易回测。

from factor\_mining.service import run\_factor\_mining, run\_mined\_factor\_backtest

mined = run\_factor\_mining(

mode="ml",

symbol="WEB3-DEMO/USDT",

limit=120,

horizon=1,

)

payload = run\_mined\_factor\_backtest(

backtest\_spec=mined\["leader"\]\["backtest\_spec"\],

symbol="WEB3-DEMO/USDT",

limit=120,

)

代码 27-2　ML 因子验证与回测入口

当前 ML 候选公式显示为 0.0116\*overnight\_gap，实际 backtest\_spec 还包含 overnight\_gap、ret\_1、ema13\_55\_spread 和 close\_sma60 等权重。训练 IC 为 0.746946，测试 IC 为 0.655742，过拟合缺口 0.091204；测试 IR 为 6.361409，命中率 0.685714，分层收益差 0.052055。转成 mined\_factor 回测后，当前结果是：收益 144.01%，最大回撤 3.85%，Sharpe 15.33，交易 31 笔。

这个结果比规则样例强很多，但它触发的是继续复核，而不是直接放行。漂亮样本内结果更需要解释来源：如果训练 IC 和测试 IC 都高，但交易次数很少，要先怀疑样本偶然性；如果回测收益高但换手高，要先提高成本和滑点假设；如果多次搜索后才找到这个因子，要把试验次数写进账本。

### 4.2 LLM 候选验证

LLM 在量化研究里适合做三件事：读取上下文，提出结构化候选，解释已有证据。它不适合凭自然语言越过验证。OpenAI 的 Structured Outputs 强调模型输出应遵守 JSON Schema；放到本讲，就是信号枚举、字段名、权重和 fallback 状态都要受约束。

业界论文常把研究过程拆成数据输入、记忆、角色协作、交易员和风险管理。这个结构很有启发，但不能直接搬收益结论。本讲把这些研究翻译成一条更窄的规则：LLM 可以进入候选层，不能跳过候选验证层。

代码 27-3 用同样的复核方式处理 LLM 候选。它先记录候选来源和结构化字段，再把候选转成可复算的回测输入。

from factor\_mining.service import run\_factor\_mining, run\_mined\_factor\_backtest

llm = run\_factor\_mining(

mode="llm",

symbol="WEB3-DEMO/USDT",

limit=120,

horizon=1,

)

payload = run\_mined\_factor\_backtest(

backtest\_spec=llm\["leader"\]\["backtest\_spec"\],

symbol="WEB3-DEMO/USDT",

limit=120,

)

代码 27-3　LLM 候选因子验证与回测入口

当前本地运行使用 proposal\_source=fallback\_templates，不是外部模型实时生成。候选公式为 1.0000\*ret\_5\_reversal，权重还包含 reversal\_volume=0.7、rsi\_centered=-0.4。训练 IC 为 0.115774，测试 IC 为 0.302241，测试 IR 为 0.827521，命中率 0.571429，分层收益差 0.030966。转成回测后，当前结果是：收益 -25.34%，最大回撤 32.96%，Sharpe -4.66，交易 19 笔。

这个结果并不说明“LLM 方法没用”，只说明当前候选没有通过交易验证。LLM 输出要过三道闸：结构闸，字段必须来自白名单；来源闸，要区分真实模型、规则 fallback 和模板候选；交易闸，候选要转成可复算的规则或因子，再接受同样的成本、回撤和样本外检查。

## 5\. Codex 实战委托与验证入口

Codex 适合做证据复核，不适合替研究者下结论。委托时要把范围、输入、输出证据、失败分支和禁止越界写清楚。下面我们把一个模糊请求拆成可照做的多轮工作流。

### 5.1 从模糊请求拆成多轮任务

模糊请求通常长这样：“帮我看看哪个策略最好。”这句话会诱导工具去追求收益排名。本讲推荐拆成三轮：

第一轮限定输入：只使用 WEB3-DEMO/USDT、limit=120、cost\_preset=teaching、horizon=1，不新增数据源。

第二轮限定证据：分别重跑规则、ML、LLM 候选，输出收益、回撤、交易数、窗口、WFO、DSR、PBO、CPCV 和候选来源。

第三轮限定动作：结论只能写“继续复核”“降级观察”或“停止当前候选”，不能写投资建议、仓位建议或“找到最佳策略”。

这样的拆法能防止两类越界：一是把 LLM 文字当交易证据，二是把单次回测当策略结论。Codex 的价值是读代码、跑命令、整理证据和指出失败分支，人的责任仍然是根据证据决定是否扩大样本或进入下一轮实验。

### 5.2 可复用委托语

代码 27-4 是一段可以直接用于本讲复核的委托语。它保留工具价值，同时把边界压得足够窄。

请重跑第 27 讲的方法对照实验，只检查研究证据，不给投资建议。

输入：WEB3-DEMO/USDT、limit=120、cost\_preset=teaching、horizon=1。

范围：

1\. 规则回测：记录收益、回撤、交易数、窗口、WFO、DSR、PBO、CPCV。

2\. ML 方法：记录训练 / 测试 IC、IR、分层收益差、backtest\_spec 和回测结果。

3\. LLM 方法：记录 proposal\_source、fallback 状态、候选字段、验证指标和回测结果。

输出：一张动作表，结论只能是继续复核、降级观察或停止当前候选。

禁止：写投资建议、建议仓位、声称未运行命令已经通过。

代码 27-4　面向证据复核的 Codex 委托语

如果 Codex 报告命令失败，下一轮委托就不要让它改策略参数，而要让它先定位失败分支：是测试入口不存在、样本路径不存在、字段对不上，还是回测服务返回结构改变。只有失败分支清楚，后续修改才不会把研究结论和工程修复混在一起。

## 总结

这节课我们把三种方法放进同一套判断纪律。规则回测提供可复算路径，但不能只看单次收益；ML 方法先验证排序，再进入交易回测；LLM 方法可以提出候选和解释证据，但证据本身仍来自结构化字段、回测和风险门禁。

当前教学样例的降级逻辑很明确：ma\_crossover 不通过稳健性门禁；ML 候选支持继续复核，但还不能放行；LLM fallback 候选转成交易后失败，应停止当前候选。三者共同证明的不是“找到好策略”，而是本专栏已经建立了一套能讲清、能重跑、能降级的量化研究方法。

学完这节课后，你要形成三个习惯：看到收益先追路径，看到好结果先查样本外和试验次数，看到 LLM 解释先问它能不能落成结构化候选和可复算回测。
