## 1\. 数据清洗的目标与边界

初次清洗数据时，目标很容易被误解为“让表格没有空值、图表能画出来、模型能读进去”。量化研究中的清洗，不以视觉连续为目标，而以输入可解释为目标。

举个例子，假设一条资金数据缺少 netInflow24h。如果展示端为了连续呈现，把缺失值自动填成 0，图表确实不会断，但会让人以为“资金净流入为 0”。真实含义可能是“上游没有返回该字段”。0 是事实，缺失是未知，二者不能互换。

因此，本讲采用一个基本原则：能解释的转换才做，不能解释的缺口记录为缺失。

src/dashboard/normalize.py 中的 \_to\_float 就体现了这个原则。它尝试把基础字符串数值转成浮点数，如果遇到空值、类型错误或不可转换字符串，就返回 None。代码 8-1 给出这个最小转换函数。

def \_to\_float(value: Any) -> float | None:

try:

if value in (None, ""):

return None

return float(value)

except (TypeError, ValueError):

return None

代码 8-1　业务源码：\_to\_float 基础数值转换函数

这个函数只做基础类型校验："19.12" 可以进入数值计算，""、None、"N/A" 不会被硬编成 0。千分位、百分号等业务格式，不在 \_to\_float 中处理。应由上层标准化函数，先写清单位和预处理规则，再决定是否转换。外部数据工具也采用类似思路，例如 pandas 可以把无法转换的值降为缺失：

import pandas as pd

pd.to\_numeric(series, errors="coerce")

这类写法的含义是“无法解释的输入降为缺失”，不是“无法解释的输入变成 0”。

表 8-1 给出常见数值输入的处理口径。它的重点不是列举所有污染输入，而是把“可解释数值、缺失占位、业务格式文本、真实 0”区分开。

| 原始值 | 字段语义 | 推荐处理 | 可进入计算 | 复核说明 |
| --- | --- | --- | --- | --- |
| "102.5" | 收盘价字符串 | 转为 102.5 | 是 | 可解释数值 |
| "" | 空字符串 | 保留为 None | 否 | 上游未返回，不等于 0 |
| "N/A" | 非数值占位 | 保留为 None | 否 | 必须记录不可转换 |
| "3.2%" | 百分比文本 | 明确去掉 % 后再转 | 视规则而定 | 需要说明单位是百分数还是比例 |
| "1,024" | 带千分位 | 清理逗号后再转 | 视规则而定 | 需要记录清理规则 |
| 0 | 数值 0 | 保留为 0 | 视字段而定 | 成交量可为 0，价格通常不可为 0 |

表 8-1　数值字段转换审计示例

这张表区分的是可解释数值、缺失占位、业务格式文本和真实 0。0 对成交量可能合法，对收盘价通常无效；"3.2%" 可以转成 3.2，也可能应该转成 0.032，取决于字段单位。

百分号和千分位可以用上层规则显式处理：

raw = str(value).replace(",", "")

number = float(raw\[:-1\]) / 100 if raw.endswith("%") else float(raw)

这段伪代码只说明规则位置，不要求所有字段都这样转换。价格、比例、成交量和资金流要分别定义单位。

## 2\. 数据契约与转换规则

清洗数据之前，先定义数据契约。数据契约是输入字段的最小约定，说明字段从哪里来、类型是什么、缺失如何处理、范围是否合理、重复和乱序如何发现。没有契约的清洗，很容易变成事后修补。第 7 讲出现过的 Manifest 可以理解为数据清单，负责记录数据集、路径、来源和更新时间；快照则是把某一次实际输入固定下来，供后续复查。

本讲统一使用三层放行口径：

展示层只负责可读呈现，允许标注缺失。

指标层负责公式复算，关键字段缺失时应阻断或切断窗口。

回测层最严格，任何可能改变买卖点、收益或回撤的输入都不应放行。

后文均沿用这组三层术语。表 8-2 集中定义本讲使用的时间字段，避免秒 / 毫秒、观测时间和展示日期混用。

| 术语 | 含义 | 使用边界 |
| --- | --- | --- |
| openTime | 外部 K 线所属时间桶 | 可参与唯一键，需确认单位 |
| tsSec | 标准化后的秒级 UTC 时间戳 | 指标和回测优先使用 |
| observed\_at | 系统观察到记录的时间 | 用于判断数据可见性 |
| updated\_at | 快照文件落盘或更新的时间 | 用于复查样本版本 |
| date | 展示用日期字符串 | 不单独作为唯一键 |

进入来源卡片或跨来源比较时，还要有 source 或等价来源记录。

| 检查维度 | 口径 | 有效证据 | 风险信号 |
| --- | --- | --- | --- |

| 时间顺序 | 时间序列有可复核排序规则 | 原始顺序或排序逻辑有记录 | 乱序后直接计算收益 |

| 完整性 | 关键字段缺失时降级或拒绝 | complete 与 reason 可追踪 | 缺字段仍通过 |

技术指标、自动化摘要和回测都依赖输入字段。如果字段已经被不透明地填补，后面的结论再严谨，也只是在污染数据上精细计算。落到配套项目里，最小检查问题包括：

完整性：tsSec、close、source、observed\_at 是否存在，缺失后进入哪一层。

有效性：价格是否大于 0，比例是否在合理区间，字符串能否按规则转换。

唯一性：是否用 exchange + symbol + interval + openTime 判断同一根 K 线，而不是只看日期。

一致性：秒 / 毫秒、UTC / 本地时间、交易所来源是否混用。

及时性：当前 K 线是否已经收盘，样本是否在决策时可见。

可追溯性：输出字段是否能回到输入路径、转换函数和污染样本。

数据契约还要说明哪些转换只服务展示层。例如给智能候选 ai\_picks 增加标题 title 和摘要 summary，可以帮助阅读，但不是新的市场事实；把资金流字段整理成 netInflow24h，可以统一展示口径，但仍要记录原始字段。无法定位来源的字段只能作为展示文本。

部分清洗动作在工程上成本很低，例如缺值填 0、重复取最后一条、乱序自动排序、非法百分比直接丢弃。它们都可能让程序更容易跑通，却会改变研究问题。因此，处理前应先判断：填补是否改变均值，去重是否丢掉交易时点，排序是否掩盖数据源错误，丢弃是否改变样本窗口。

时间字段尤其不能混用。一个 2026-06-24 10:00 的 1 小时 K 线，可能在 10:01 仍未收盘，也可能在 11:00 后才完整；如果把 10:01 的未收盘值拿去回测，就等于把盘中临时状态当成历史定稿。秒和毫秒也要分清：1719201600 是秒级时间戳，1719201600000 是毫秒级时间戳；对配套项目来说，normalize\_candle 输出的 tsSec 是秒级 UTC 时间戳，date 只是展示用日期，不应该单独作为唯一键。

### 3.1 标准化函数

normalize\_ai\_picks 会遍历 chance、funds、risk 三类条目，为缺少标题和摘要的候选补出展示字段。它补的是展示字段，不是补造市场事实。比如 percentChange24h 可转换时进入摘要；不可转换时就不写这段，而不是编一个涨跌幅。

normalize\_token\_fund 会从资金、情绪和市值比例相关字段中，整理展示所需的结构。它会尝试提取 netInflow24h、sentiment.score 和 fundMarketCapRatio.ratio，但这些转换都有来源字段。若来源字段不存在，结果仍保留缺失，而不是假装数据完整。

K 线数据也有对应的标准化入口。src/dashboard/market.py 中的 normalize\_candle 把交易所返回的一行数组转换成有名称的字段：tsSec、date、open、close、high、low 和 volume。如果行长度不足或字段无法转换，就返回 None，不让坏行进入后续曲线。代码 8-2 给出 K 线行标准化入口。

def normalize\_candle(row: list\[Any\]) -> dict\[str, Any\] | None:

if not row or len(row) < 6:

return None

try:

ts\_sec = int(float(row\[0\]))

return {

"tsSec": ts\_sec,

"date": \_ts\_to\_date(ts\_sec),

"open": float(row\[1\]),

"close": float(row\[2\]),

"high": float(row\[3\]),

"low": float(row\[4\]),

"volume": float(row\[5\]),

}

except (IndexError, ValueError, TypeError):

return None

代码 8-2　业务源码：normalize\_candle 外部 K 线行标准化入口

这段代码的重点不是“能画 K 线”，而是先把字段身份固定下来。进入第 9 讲的技术指标前，指标函数只应该看到已经有日期和收盘价的记录，而不是交易所原始数组。

### 3.2 完整性和来源校验

src/dashboard/catalog.py 的 completeness\_detail 判断数据是否足以进入后续流程。标准化让字段更一致，完整性检查决定数据能否继续进入指标层或回测层。

src/dashboard/source\_card.py 还提供了一个市场行校验函数：validate\_market\_row。它检查一行市场数据是否有来源 source、观察时间 observed\_at 和正数收盘价 close。这对应本讲的三项底线：知道数据从哪里来、知道数据是哪一刻的、价格字段可用于计算。代码 8-3 展示这个市场行校验函数。

## 4\. 污染样本与拒绝验证

本讲实践不是只跑一个成功样本，而是主动构造污染输入。只有系统能说明哪些输入被接受、哪些输入被降级、哪些输入被拒绝，数据质量报告才有价值。

### 4.1 污染样本设计

表 8-4 给出本讲建议注入的六类污染。每一类都对应真实研究中的常见问题。

| 污染类型 | 示例 | 预期处理 | 风险处理 |
| --- | --- | --- | --- |
| 重复时间戳 | 同一资产同一时间两条价格 | 保留规则或拒绝原因明确 | 静默覆盖 |
| 逆序记录 | 后一天排在前一天之前 | 排序规则可复查 | 直接计算收益 |
| 缺失字段 | close、source 或时间为空 | 降级或拒绝 | 自动填 0 |
| 字符串数值 | "19.12"、""、"N/A" | 可转则转，不可转为 None | 全部当作有效数值 |
| 价格越界 | 负数价格、极端跳变或异常天价 | 标记异常并进入复核 | 直接进入指标或回测 |
| 时间漂移 | 本地时间替代 UTC，或时区字段缺失 | 标记时区口径，重建时间戳 | 直接按字符串排序 |

表 8-4　时间序列污染样本与预期处理

质量验证不能只覆盖成功样本，还要证明系统会在错误输入前停下来。实践时复制一份小样本，先记录预期行为，再运行测试或手工调用标准化函数，避免看见结果后倒推解释。

下面，我们把污染样本写得更具体。假设固定样本里有 3 根 1 小时 K 线：

\[

{"openTime": 1719201600, "close": "64200.5", "volume": "12.4"},

{"openTime": 1719205200, "close": "64310.0", "volume": "9.8"},

{"openTime": 1719208800, "close": "N/A", "volume": "0"}

\]

这组样本里，第三根 K 线不是“价格为 0”，而是“收盘价不可转换”。展示最近行情时，可以标成“缺失”或“待复核”；计算 3 根 K 线收益率时应阻断窗口，因为收益率需要上一根和当前 close 都有效。成交量 0 也要依赖来源文档或采集日志解释，不能自动推导为“交易所无成交”。

重复时间戳也要分情况处理。若两条记录完全相同，质量报告可以写“完全重复，保留第一条，删除 1 条重复”；若同一 exchange + symbol + interval + openTime 下出现两个不同收盘价，就不能静默取最后一条。表 8-5 给出重复和缺口的处理示例。

| 场景 | 样本现象 | 展示层 | 指标层 | 回测层 |
| --- | --- | --- | --- | --- |
| 完全重复 K 线 | 两行所有字段一致 | 可显示去重后结果 | 记录后可用 | 记录后可用 |
| 冲突重复 K 线 | 同一 open time，不同 close | 标红待复核 | 拒绝 | 拒绝 |
| 中间缺一根 K 线 | 10:00 后直接到 12:00 | 显示缺口 | 视指标而定 | 切断窗口或拒绝 |
| 当前未收盘 K 线 | 11:00 K 线在 11:03 采集 | 可展示实时状态 | 不进入指标 | 不进入回测 |
| 跨交易所同时间 | Binance 和 KuCoin 同时有 BTC-USDT | 分来源展示 | 不算重复 | 按策略数据源选择 |

表 8-5　重复时间戳、缺口与未收盘 K 线处理示例

唯一键不能只写 date。对 K 线来说，更稳妥的唯一键是 exchange + symbol + interval + openTime。同一天的日线和小时线不是同一条记录；同一时间的不同交易所价格也不是重复记录。

资金和情绪字段也要写清来源。normalize\_token\_fund 可能把 bullishRatio=0.61 转成 sentiment.score=61.0，这个转换适合展示“看多占比”，但不能直接解释为“买入评分 61”。netInflow24h 若有多个候选来源，也要在质量报告里记录优先级。表 8-6 给出一条写法。

### 4.2 数据质量报告模板

表 8-7 是本讲交付物模板。它把清洗动作和结论边界放在一起，防止“清洗完成”变成一句空话。

| 字段 | 示例内容 | 风险信号 |
| --- | --- | --- |
| 输入版本 | 固定样本、快照或临时污染样本路径 | 只有“当前数据” |
| 转换规则 | 哪些字段转为浮点数，失败如何处理 | 只有“统一格式” |
| 缺失处理 | 缺失保留、降级或拒绝 | 缺失自动填 0 |
| 异常处理 | 重复、逆序、越界如何处理 | 只有“异常已修复” |
| 测试结果 | 命令、退出码、失败信息 | 只有“应该能通过” |
| 结论边界 | 可进入展示、不可进入回测或需复测 | 只有“数据可用” |

这份报告要能被独立复核。复核者不依赖外部口头说明，也能找到输入文件、理解转换规则、复现一个污染样本，并说明为什么某个字段被保留为缺失。

### 4.3 标准化记录示例

以 normalize\_token\_fund 为例，复核流程可以压缩为四步：

读取原始样本：用 load\_offline("token\_fund") 保存 fund、fundMarketCapRatio 和 sentiment 三组字段。

运行转换函数：记录 fund.netInflow24h、sentiment.score 和 fundMarketCapRatio.ratio。

追溯来源字段：确认 netInflow24h、sentiment.score、ratio 分别来自哪一个原始字段或候选字段。

构造污染样本：删除资金行或把 bullishRatio 改为 "N/A"，确认函数记录缺失，而不是生成推测值。

再看 normalize\_ai\_picks。它对 chance、funds 和 risk 三类条目，采用同一套展示补全逻辑，但三类频道不能合并成一个交易方向。标题和摘要统一只是为了阅读体验，不代表它们可以替代原始市场证据。

交接复核时，可以反向走一遍：先从展示字段找到接口输出，再从接口输出找到标准化函数，再从标准化函数找到原始字段。无法回到原始字段的内容，只能算展示文本，不能进入研究结论。质量报告还要记录未采用的清洗方案，例如没有用均值填补缺失、没有把非法百分比强制转成 0、没有在删除所有异常点后直接重算收益。

### 5.2 偏差控制与人工复核

本讲最容易出现的偏差，是为了图表连续而自动填补所有缺失值。另一个常见偏差，是把字符串百分比、空字符串和 0 混为一类。它们在展示端都可能显示成数字，但研究含义完全不同。

完成本讲后，至少手工复核一项标准化结果。你可以选择 normalize\_ai\_picks 生成的 title 和 summary，确认每个片段都来自原始字段；也可以选择 normalize\_token\_fund 的 netInflow24h，追到 spotGoodsList 或 fundMarketCapRatio 的来源字段。复核记录只保留四项：原始字段、转换规则、标准化输出和结论边界。

交付复核同样分三类：

第一类是“通过”：关键字段来源有记录，非法值不会被编造成 0，污染样本能触发降级或阻断。

第二类是“修改后复测”：展示字段基本可用，但缺失处理、异常范围或测试覆盖还不清楚。

第三类是“退回复核”：清洗过程会改变研究含义，例如自动填补所有缺失、静默去重、删除异常值却不更新样本窗口。

自动化摘要和展示端也要遵守复核结论。摘要可以把标准化字段转为自然语言，但不应根据上下文推测数值；字段缺失时，展示端应显示“缺失”“未返回”或“待复核”，不要为了美观显示 0 或空白占位。

从清洗进入指标前，还要做一次门禁判断：展示层可以容忍部分字段缺失；指标层要求关键字段可复算；回测层还要确认错误输入不会改变买卖点、收益和回撤。同一份标准化数据可以允许展示，但仍然不允许回测。

## 总结

这节课我们把时间序列数据质量与标准化验证，收束为一份数据质量报告。报告不只说明程序能跑，还要说明字段从哪里来、怎样转换、缺失如何保留、污染样本如何处理，以及哪些结果只能展示、不能进入指标或回测。

清洗完成不代表数据已经可靠。它只代表当前输入在明确规则下被整理成了可解释形状。真正的交付判断仍要看字段来源、时间顺序、缺失处理和用途边界是否能被独立复核。

这节课我们不展开资产池构建，但质量报告应记录样本池口径：样本是“当前可见资产”，还是“按历史时点可见资产”。如果回测只使用今天仍存在、仍有数据的资产，就会漏掉历史上已经下架、停牌或失效的样本，从而抬高历史表现。这个问题会在第 20 讲讨论过拟合和数据窥探时继续展开。

![](https://static001.geekbang.org/resource/image/5c/5c/5cf140e1de1ddc9a0296b81762dea45c.jpeg)

下一讲我们将用技术指标描述市场状态。它会继承本讲留下的输入、代码和复核记录，把验证范围从“字段能否解释”推进到“指标是否具备解释资格”。如果标准化阶段没有保留字段来源、时间顺序和缺失状态，技术指标会把数据质量问题放大为市场解释问题。
