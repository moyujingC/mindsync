## 课程介绍

### 为什么做这门课

过去三年，作者高强度投入一个分布式基础软件的开源项目，从架构设计到代码实现几乎全部人肉完成。2025 年开始，随着 Claude Code 的成熟，工作模式发生根本变化——从质疑、怀疑，到信任、融合。这个过程验证了一件事：编程的模式已经变了。以前考验的是实现一个需求的能力，现在考验的是定义需求、拆解需求、然后高效交付的能力。

这个变化对程序员要求更高了。你需要理解业务、定义边界、设计架构、拆解任务，然后指挥 AI 高效执行，在它做不好的地方补位。你变成了产品经理 + 架构师 + 研发的集合体，AI 是你的执行团队。

但大多数人还停留在把 AI 当代码补全工具的阶段。这门课要解决的，就是如何真正用好 Claude Code，让它成为能力的放大器，达到一个人顶一个团队的效果。

### 这门课教什么

核心命题：一个工程师，拿到一个复杂系统的需求，只有 Claude Code 作为搭档，如何从零把它完整交付出来？不是写几个函数、生成几个页面，而是从产品定义、架构设计、核心开发、测试验证到本地部署的完整链路。

为了让这件事足够真实，我们选了一个所有关注 AI 的开发者都熟悉的项目作为载体：用 Claude Code 从零构建一个简版 Dify，我们叫它 Hify。Spring Boot + Vue 技术栈，模块化单体架构，支持多模型管理、Agent 配置、对话引擎（流式响应）、MCP 工具接入，Docker Compose 一键部署，面向团队内部小规模使用。

但 Hify 只是载体。这门课真正教的是一套完整的方法论——Claude Code 全链路开发框架。

这套框架包含两种协作模式：

- 执行模式：你想清楚了，让 Claude Code 做，你验收。
- 咨询模式：你还没想清楚，先让 Claude Code 帮你梳理“这一步应该考虑什么”，你判断取舍后再让它执行。越是项目早期，咨询模式越有价值。

框架还包含一系列可以直接套用的具体方法论：

- 规范驱动开发（SDD）让 AI 永远在你定义的轨道上运行，不自由发挥。
- 三问裁剪法帮你快速确定产品边界——做什么、不做什么、做到什么程度。
- 三步检查法帮你高效审查 AI 输出——先查意图、再查质量、最后查边界。

这些方法论不只适用于 Hify，换成任何项目都能用。

### 怎么学

整个课程按工程开发顺序展开：

1. 建立认知框架：你和 Claude Code 的关系是什么，执行模式和咨询模式分别怎么用
2. 顶层设计：产品定义、架构设计、规范体系
3. 搭建工程骨架：后端、前端、基础组件全部就位
4. 逐个交付核心功能：模型管理、Agent 配置、对话引擎、MCP 接入、前端控制台
5. 测试、部署与复盘：联调验证、Docker 部署、AI 贡献率量化回顾

每一步都展示 Claude Code 是怎么参与的。不只是写代码——产品定义时它帮你梳理功能全景，架构设计时它帮你做方案对比，基础组件阶段它帮你发现遗漏。

每节课以图文为主体，讲清楚方法论和思考过程。每个篇章结束后，配一个完整的演示视频，展示真实操作过程。图文让你理解方法，视频让你看到现场。

提示：课程以 Claude Code 为核心教学工具。建议优先使用 Claude Code 跟随实践，学习体验更佳。如果没有开通，也可选用其他 AI 编程工具——方法论是通用的，实现效果有差异而已。
