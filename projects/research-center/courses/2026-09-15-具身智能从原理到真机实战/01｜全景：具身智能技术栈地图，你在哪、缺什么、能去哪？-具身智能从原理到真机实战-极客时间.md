你好，我是 Leo，欢迎你和我学习具身智能开发。

这节课我想先把你放到一张真实的工作台前。桌上是一台 SO-101，旁边放着相机、用来遥操作的 Leader（主）臂和一只准备被抓起的杯子。屏幕上同时开着采集、训练、日志和视频回放四个窗口。

你可能已经会 LangGraph、模型微调和 Agent Eval，但面对这张桌子，问题会马上变得具体：相机画面如何和关节动作对齐？模型输出的数组怎样变成安全动作？一次成功究竟该信视频，还是信评测表？

这节课的任务，就是先把整张具身智能技术栈地图铺开。学完以后，你应该知道自己已经会什么，第一条真机闭环还缺哪几块，以及转型路径有哪些。

## 先说一件事：会 AI，不等于会具身 AI

做了这么多年软件、这两年一直扎在大模型 Agent 里，决定转具身智能之前，我先给自己做了个评估：搭过企业级智能体平台，用 LangGraph 编排过多个业务 Agent，Lead Agent 拆任务、子 Agent 对接各路系统，全链路跑通过；也做过 Qwen-VL 微调，从数据标注到上线部署走过一整遍。心里想的是，这些底子应该够用了。

拿到真机的第一周就被打回原形：电机过载，主从臂标定空间对不上，录了十几条遥操作数据，质检完大部分作废。后来复盘才明白，问题不是算法功底不够，是我对具身智能的技术栈根本没有一张地图——哪些模块和熟悉的软件 Agent 是相通的，可以直接搬过来用；哪些是全新的，得从零学。当时完全没数，只能一头扎进去自己撞。

这张地图，现在摊开看一遍。

## 具身智能的技术栈全景：五层拆解

先把系统分成五个观察角度。它们不是每次推理依次调用的五个步骤：数据支撑训练与评测，感知和执行反复交互，规划器也未必每个控制周期都参与。

![](https://static001.geekbang.org/editor-compose/resourceimage/compose/b9/1a/b9b3c40fcadb198121a4f4cf22ca4d1a.png)

具身智能技术栈全景：五层分工与关键问题

这五层里，有一层你可能已经很熟悉：大模型规划层。如果做过 LLM Agent，“拆任务、调技能、判断下一步干什么”的经验可以迁移。到了机器人系统里，规划层负责决定先抓哪个物体、再放到哪里，并调用已经定义好的抓取或放置技能；连续动作则交给策略和控制器。第一条固定抓放基线甚至可以不接规划器：先让策略在指定场景完成一个任务，再考虑语言调度。

另外三层你会更陌生：策略执行层、硬件控制层、仿真与数据层，这门课的重心也在这里。感知层夹在中间，不算全新概念，但连续、带噪声的图像流，与软件 Agent 常见的文本和结构化工具结果差异很大，后面会穿插在其他几层里讲。

这几层为什么不能照搬软件 Agent 的做法？差别首先落在“动作会改写下一帧输入”。夹爪碰偏纸杯，杯子的位置已经变了，即使重新摆回去，也很难精确恢复碰撞前的速度、遮挡和关节状态。与此同时，机械臂每秒要接收多次控制指令，相机受光照、遮挡和视角影响，电机还有过载与关节超限风险。软件系统也有噪声、延迟和权限问题，但物理闭环把这些问题压进了同一条实时动作链。

| 维度 | 屏幕 Agent | 具身 Agent |
| --- | --- | --- |
| 输入 | 文本、页面、日志与工具返回 | 图像、关节状态与任务条件组成的连续观测 |
| 控制 | 离散工具调用，常以秒级响应 | 连续动作或动作块，常以固定频率执行 |
| 节奏 | 许多操作可重试或回滚 | 动作会立刻改变环境和下一次观测 |
| 不确定性 | 接口失败、脏数据、模型误读 | 还要叠加遮挡、标定误差、摩擦与负载 |
| 容错 | 可借助事务、幂等和重试恢复 | 要靠限幅、停止、恢复策略与人工接管 |
| 安全 | 主要守权限、隐私与数据边界 | 还要守人员、设备和工作空间边界 |
| 框架 | LangChain / LangGraph | LeRobot + 策略模型 |

经常有人问：能不能直接用通用大模型控制机械臂？

答案是“不能”。通用大模型适合负责“拿哪个杯子、放到哪里、失败后该调哪个技能”，却不应直接承担几十赫兹的关节控制。连续动作对时延、稳定性和边界更敏感，需要专门的策略与底层控制器。因此，课程后面会把大模型放在规划层，把 ACT 或 VLA 放在策略层，再用限幅、停止和接管守住执行层。

还记得开篇词里的 29/30 吗？假设 30 次评测成功 29 次，点估计就是 96.7%。它并不说明下一次任务也有同样的把握，更不能拿来证明 ACT 比 PPO 强。算法比较还需要相同任务、明确的训练预算与逐次试验记录。第 03、12 和 15 讲会依次拆清算法选择、训练排查与统计可信度；没有原始记录的数字，只用来练习计算，不当作课程实测成绩。

## 这门课在全景里的位置：覆盖什么，不覆盖什么

课程分为五个模块，用一套 SO-101 Leader / Follower 和 LeRobot 贯穿。重心放在策略执行、硬件控制、仿真与数据这三层。LeRobot 把采集、数据集、训练和真机执行放进一套可组合的接口中；它有些像机器人学习里的 Transformers，但还要多管一条从相机、时间戳到电机指令的实时链路：

原理底座篇 → 策略执行层的判断逻辑：模仿学习、强化学习、VLA 三大范式怎么选，为什么单帧行为克隆进入长时闭环后容易失稳。

数据平台篇 → 仿真 & 数据层的工程细节：采集纪律、LeRobot v3.0 数据标准、质检与数据飞轮。

LeRobot 框架实践篇 → 策略执行层的落地：从 overfit 一个 batch 到一份可信的 ACT 成功率报告，再到 SmolVLA LoRA 微调。

真机机械臂篇 → 硬件控制层：SO-101 的标定、安全边界、真机闭环与失败诊断。

工程交付篇 → 把前面几层串起来，练习有限规划、技能接口与运行审计，再按实际接入和验证范围交付项目；离线检查通过不等于完整系统已能安全运行。

![](https://static001.geekbang.org/editor-compose/resourceimage/compose/b1/20/b19357a2b975ad6c9c7cef6fccf97c20.png)

课程知识地图

这门课不覆盖、需要你自己后续补的部分：

要不要先学 ROS2？本课的 SO-101 路径可以直接使用 LeRobot 的设备接口，不需要先学完 ROS2。以后接入采用 ROS2 的机器人或团队系统时，再围绕消息、坐标变换和设备桥接补课。先看目标项目用了什么，不把另一整套框架当作入门门槛。

要不要直接上人形？先看你想验证什么。如果是学习示范数据怎样变成抓取动作，一套桌面臂就能暴露相机、动作语义、时序和评测问题。人形还会引入平衡、全身协调和更复杂的安全约束。先把桌面任务做清楚，以后扩展平台时才知道哪些方法能迁移、哪些假设必须重做。

大规模生产部署（多机队列管理、云端调度）也不在这门课范围内，属于作品集之后的下一步，结束语里会给一些方向性建议。

## 从 LLM Agent 到具身智能，你能走哪几条路

现在值得学，不只是因为某个机器人视频很热闹。行业正在把图像、语言和动作放进同一条学习链路：小型开源模型，如 SmolVLA 已经能在 SO-101 上做任务适配；更大的系统则开始处理跨本体数据、长时程家庭任务和合成数据。这些热点最终都会回到同几件事：数据能不能对齐，动作能不能执行，失败能不能重现。这正是个人开发者可以先在桌面臂上练扎实的部分。

落到职业能力上，不同背景的工程师可以从不同入口切进来：

LLM / Agent 工程师 → 具身策略工程师：工具调用、Prompt 工程、评测流程的底子已经有了，缺的是“怎么让模型真正控制一条机械臂”。策略执行层和硬件控制层，是要补的两块，也是这门课的重心。

后端 / 算法工程师 → 具身开发转型：不必等到 ROS2 和复杂仿真全部学完再开始。先在一套桌面臂上跑通采集、训练和评测，产出有数据和失败记录的作品集。

数据 / 平台工程师 → 具身数据工程：具身数据不是再搭一个标注平台，采集纪律、v3.0 数据标准、质检和飞轮工程，各有各的门道，数据平台篇专门讲这条线。

对照一下自己现在的位置：

会 Prompt 工程、多智能体编排 → 对应“大模型规划层”，可以直接复用。

做过模型微调、数据标注 → 对应“策略执行层”和“仿真 & 数据层”的部分基础，缺的是机器人数据的特殊规则。

没碰过硬件、没接触过连续控制 → 最大的盲区，也是“真机机械臂篇”重点要补的部分。

根据不同基础，可以看看这三条路哪条更适合你。

### 现在就做：给自己留一张起点卡

花十分钟新建一个 embodied-start.md，按真实情况填写下面四行：

我已经能独立完成：例如 Agent 编排、PyTorch 训练、数据平台

我目前完全陌生：例如电机标定、动作空间、闭环评测

我的第一台目标设备：SO-101 / 其他机械臂 / 暂时只做仿真

我的第一个有限任务：例如把一个已知木块放进固定托盘

然后尝试给任务补上验收条件。例如：“木块从左、中、右三个标记位置出发，20 秒内进入托盘并保持 2 秒；人工接管记为非自主成功，所有尝试都保留。”这里的时间只是起点示例，要按你的任务确定并在评测前冻结。这张卡会在第 15 讲变成评测协议，在第 23 讲变成作品集主张。

再做一个不用机器人就能开始的小练习：打开课程的一段抓放视频，在“夹爪开始闭合”处暂停，分别写下画面能回答和不能回答的问题。你能看见夹爪与木块的大致位置，却通常看不出关节目标的单位、命令发送时间，也不知道是否有人接管。前者留在观察记录中，后者分别去找动作配置、时间戳和操作日志。找不到就记“未知”。这就是后面排查失败的起点，不必等学完所有模型才开始练习。

## 学完这门课，你能达到什么水平

光说“跑通过 SmolVLA 的 demo”还不够。下面三件事可以作为练习后的自查目标，每项都要能打开自己的记录说明：

理解模仿学习、强化学习、VLA 三大范式在具身场景下的实际差异，遇到新任务知道该选哪个，而不是凭感觉。

能独立完成 ACT / SmolVLA LoRA 的训练与真机评测，知道离线 loss 低不等于真机好，会用闭环成功率而不是离线指标判断策略优劣。

能说明语言规划、策略与执行保护怎样连接，逐项验证已接入的部分；看板上的每个结果都能追到试验记录，尚未实现的接口不当作已有能力。

最后留下的不是一句“我了解具身智能”，而是一个可以打开检查的项目：架构图说清职责边界，逐次 trial 表给出成功率分母，三分钟演示把正常流程、失败与接管放在同一条证据链里，GitHub 仓库则提供复跑入口。面试或项目评审追问时，你能从结论一路打开到数据、配置和失败记录。

## 这是起点，不是终点

具身智能这个领域还在向前发展，这门课程可以带你走完“感知 - 策略 - 执行”这条最基础的闭环，之后你还可以朝这些方向迈进：

VLA 基础模型的进展：SmolVLA 让桌面臂开发者能够练习完整微调链路；π0.5 展示了机器人进入此前未见过的家庭环境，连续执行 10～15 分钟多阶段整理任务的研究方向；Isaac GR00T 则把跨本体数据、合成数据和人形机器人后训练放到同一套工作流中。

Sim2Real（把仿真里训好的策略，迁移到真实机器人上还能用）的工程化：域随机化、更鲁棒的部署策略。

从单任务桌面抓取，扩展到多任务、更复杂的操作场景。

这些方向的设备、数据和算力，距离个人桌面实验还有一段距离，但它们没有改变基础工程问题。能在 SO-101 上把一条轨迹说清楚、把一次失败复现出来，比只能复述最新模型名字更有价值。

延伸阅读： SmolVLA 、 π0.5 、 Isaac GR00T 。

## 小结

开篇词讲的是我从软件 Agent 走向机械臂的亲身经历；这一讲把视角拉远，给你一张完整的技术栈地图。先别急着给自己贴“适合”或“不适合”的标签，看看现有能力能迁移到哪一层、第一块短板又在哪里。

现在不妨在五层中各标出一项：你已经能迁移的能力、最需要补的能力，以及最适合立刻动手的入口。这样判断这条方向是否适合自己，会比只看岗位名称更具体。

下一讲，我们会从软件 Agent 最熟悉的执行循环出发，逐项比较信息世界与物理闭环。等我们把观测、动作、实时性和安全边界弄清楚以后，第 03 讲再谈模仿学习、强化学习与 VLA 的选择。
