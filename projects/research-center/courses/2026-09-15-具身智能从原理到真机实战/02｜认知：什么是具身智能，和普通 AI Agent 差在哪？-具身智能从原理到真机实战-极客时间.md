你好，我是 Leo，欢迎你和我学习具身智能开发。

假设你已经很熟悉 AI Coding Agent。你给它一句话：“修复登录接口偶发的 500 错误。”它会读代码、查日志、修改文件、运行测试；如果测试失败，就根据报错继续改。整个过程可以概括成一个你非常熟悉的循环：

观察环境 → 做出判断 → 执行动作 → 读取结果 → 继续判断

现在，把任务换成：“拿起桌上的纸杯，放进左边的收纳盒。”看起来仍然是同一个 Agent 循环：摄像头负责“观察”，模型负责“判断”，机械臂负责“执行”。既然大模型已经会看图、会规划、会调用工具，我们是不是只要把机械臂封装成几个 Tool，就能得到一个具身智能体？

这正是很多软件工程师进入具身智能时最自然、也最容易低估问题的一步。

纸杯只偏了 3 厘米，机械臂为什么就抓空了？模型已经判断出“应该向左移动”，为什么电机不能直接执行这句话？为什么一个 Coding Agent 可以思考十几秒，机械臂却可能在这十几秒里撞上桌面？

这节课我们就从这个纸杯开始。给 AI Agent 接上一双机械手只是表面变化；更深的变化在于，智能进入了一个有噪声、持续变化、动作会留下真实后果的物理闭环。

![](https://static001.geekbang.org/editor-compose/resourceimage/compose/f7/56/f7747ac37309201a43c913cbc50be256.png)

## 一个看起来合理、实际上问题很多的方案

如果沿用开发 AI Agent 的经验，我们很容易设计出这样的系统：

摄像头拍一张桌面照片；

读取机械臂当前的关节角度；

把图像和关节角度发给多模态大模型；

让模型返回下一步动作，例如“夹爪向左移动 2 厘米”；

执行动作，重新拍照，再循环一次。

它和 Tool Calling 很像：输入上下文，选择动作，执行工具，再把执行结果放回上下文。

这个方案并非完全不能工作。它甚至可能在精心布置的演示里成功几次。但当光线变了、杯子被遮住一部分、桌面有轻微反光，或者模型响应突然慢了两秒，问题就会接连出现。

原因不在于“大模型还不够聪明”，而在于物理世界给 Agent 增加了四类软件世界里不那么显眼的约束。

## 从看见纸杯到夹住它，中间还缺什么？

### 看见的位置，未必就是杯子的真实位置

Coding Agent 读取一个文件时，文件里的第 42 行就是第 42 行。只要文件没有被修改，两次读取通常会得到相同的内容。它可以精确搜索函数名，可以对比 Git diff，也可以把确定的文本放进缓存。

机器人无法直接读取物理世界本身，只能得到传感器采集的一次观测（observation）。

同一个纸杯，在摄像头里可能因为光线、阴影、反光、遮挡和相机噪声呈现出不同的像素；机械臂的编码器能告诉你关节转了多少，却不能直接告诉你夹爪是否已经把杯子夹稳；杯子看似没有移动，也可能在接触瞬间发生了轻微滑动。

这意味着两个重要变化：

输入不再是精确、完整的状态，而是对真实状态的不完整估计；

“看起来一样”不等于“对机器人来说就是同一个状态”。

举个常见例子：训练数据里的杯子总在桌面中央，模型可能学会了一条看似有效的捷径——机械臂先移动到某个固定位置，再闭合夹爪。测试时只把杯子向右挪 5 厘米，它就抓空了。

模型没有突然变笨。它学到的可能只是训练环境里的位置偏差，并未建立“杯子位置变化时，动作也要跟着调整”的关系。

所以，“让模型看见”只完成了输入接线。策略还要从不完美的观测中提取与动作有关的信息，并借下一次观测持续修正判断。

### 发出“抓取”指令之后，谁来完成这段动作？

对普通 AI Agent 来说，一个动作往往是离散的：

调用搜索工具；

读取一个文件；

执行一条测试命令；

向数据库写入一条记录。

工具名、参数和返回值都可以被清楚地定义。只要 JSON 合法、权限正确，工具就能开始工作。

但“拿起纸杯”并不是一个瞬间完成的函数调用。它至少包含：

靠近纸杯 → 调整夹爪姿态 → 对准抓取位置 → 张开夹爪 → 前进 → 闭合 → 判断是否夹稳 → 抬起

每一步都包含多个关节在一段时间内的连续运动，无法压缩成一次简单的“成功或失败”。前一时刻的速度、位置和接触状态，会影响后一时刻应该做什么。

即使模型返回了一组格式正确的关节位置，也不代表这组位置适合立刻执行。例如，上一条指令还让夹爪停在桌面上方，下一条却要求它大幅向下移动。六个数字都在允许范围内，连接这两个姿态的运动仍可能撞到桌面。

这就是具身智能里“动作”的关键区别：

普通 Agent 常常在选择“调用哪个工具”；机器人还必须学会“身体在接下来的一小段时间里怎样运动”。

课程里把“根据眼前画面和机械臂姿态，预测接下来怎么动”的模型叫作策略模型（policy）。你可以先把它看成一个函数：输入相机画面和关节位置，输出下一步或接下来几步的动作。至于“现在该抓取还是放置”，可以由上层程序决定，也可以作为任务条件提供给策略。

后面会用到的 ACT，一次预测一小段动作序列。执行一部分之后，系统再用新画面预测下一段，这叫动作分块（Action Chunking）。这一讲先记住它负责哪段工作，第 04、05 讲再解释这样预测为什么有用。

### 模型还在思考，机械臂怎么办？

Coding Agent 思考 5 秒还是 15 秒，主要影响的是用户等待时间。只要代码仓库没有同时被别人修改，它面对的环境大体还停留在原处。

机器人没有这个条件。

夹爪碰到杯子的瞬间，杯子可能继续滑动；传送带上的物体不会因为模型还在推理就停下来。模型暂时没有返回新动作时，设备是保持当前位置、继续旧动作，还是停止，必须事先约定。这取决于具体控制方式，不能指望“接口没有返回”自然等于安全停止。

大语言模型擅长理解目标、分解任务和处理异常，但它的推理延迟通常比底层运动控制慢得多，而且会随输入长度和模型负载波动。因此，可靠的具身系统通常采用分层运行：

任务规划层：理解“把纸杯收进盒子”这样的目标，决定先做什么、后做什么；

技能或策略层：根据图像和机器人状态，生成抓取、放置等短时间动作；

控制与安全层：以更稳定的频率执行电机控制、限制速度与关节范围，并处理急停。

你可以把它理解成软件架构里的“慢思考 + 快执行”：大模型负责秒级的规划，策略模型负责更快的感知 - 动作闭环，底层控制器负责稳定执行和兜底。

所以，“ChatGPT 能不能控制机械臂”并不是一个简单的是非题。它当然可以理解任务、调用已经封装好的机器人技能，甚至根据现场情况重新规划；但让通用大模型逐帧输出原始电机指令，通常既不经济，也不稳定，更不安全。

### 抓空以后，下一次尝试从哪里开始？

AI Coding Agent 改错了代码，可以撤销 diff；命令执行失败，可以修正参数后重试；测试环境被弄乱了，还可以重新启动容器。

机械臂抓错一次，现场状态已经改变：

杯子可能倒了，液体可能洒出；

目标物可能被推到了摄像头看不见的位置；

夹爪可能把柔软物体压坏；

机械臂可能碰到人、桌面或另一台设备。

物理动作并非都绝对不可逆，但它们通常没有软件世界里那种低成本、完全一致的回滚。失败之后，机器人面对的是一个新的环境，而不是原任务的原始快照。

因此，具身系统不能只设计“成功路径”，还要同时设计：

安全边界：关节、速度、力矩和工作空间限制；

失败检测：是否抓空、滑落、遮挡或发生碰撞；

恢复策略：失败后退回哪里，是否重新观察，何时需要人工介入；

环境重置：训练和评测时，怎样让下一次尝试从可比较的状态开始。

在软件 Agent 里，Guardrail 往往是在工具调用前做权限和参数检查；在机器人里，安全约束必须贯穿规划、策略、控制和硬件急停整个链路。

## 到底什么是具身智能？

了解完这四处差异，我们可以给出一个更有用的定义：

具身智能，是智能体借助身体，在有噪声、持续变化的物理环境中，通过“感知 - 动作 - 再感知”的闭环不断修正行为，并最终完成任务的能力。

这个定义里有三个关键词：

第一是身体。身体不只是模型的输出设备。机械臂的关节结构、夹爪形状、相机位置和运动范围，都决定了模型能感知什么、能采取什么动作。换一副身体，同一个任务的解法也可能完全不同。

第二是闭环。机器人不能只看一眼，然后盲目执行到底。它做出的每个动作都会改变环境，而变化后的环境又会成为下一次决策的输入：

看到杯子 → 靠近 → 再看一次 → 修正偏差 → 接触杯子 → 再判断是否夹稳 → 抬起

第三是真实后果。机器人输出会直接改变物理世界，无法只当作一段建议来审阅。因此，成功率、稳定性、安全性和恢复能力，都是系统能力的一部分。

### 用旧画面答题，与自己动手完成任务，差在哪里？

这里先区分两种测试。第一种是拿一段已经录好的演示，逐帧问模型“这时应该怎么动”，再把答案与人的动作比较。模型答错了，录像里的下一帧也不会改变。第二种是把预测动作发给机械臂，再拿动作执行后的新画面继续预测。这时，上一步的答案会改变下一道题。这就是闭环测试。

假设模型只在训练数据里见过“夹爪正对杯子”的画面。真机运行时，第一步动作偏了 1 厘米，下一帧就进入了一个训练数据里很少出现的状态；模型基于这个陌生状态又做出一个略有偏差的动作，误差继续放大，最后彻底抓空。

单独检查每一步，预测都可能“差得不多”；把这些小误差放进闭环，它们却会不断累积。这类现象通常与分布偏移有关：训练样本来自人类示范或离线数据，运行时的状态却由策略此前的动作一步步造成。

这也解释了为什么机器人不能只看离线损失或单帧预测是否准确。最终必须让它完整运行多次，统计任务成功率，并记录它在什么位置、以什么方式失败。

对 Coding Agent 来说，单元测试和静态评测已经能覆盖大量问题；对机器人来说，真实或高质量仿真中的 rollout（完整执行一次任务） 才是不可替代的验收环节。

## 你已有的 Agent 经验，哪些仍然有用？

好消息是，你不需要把过去的知识全部推倒重来。软件 Agent 和具身智能共享同一条主线：围绕目标，获取环境信息，选择行动，并用反馈修正下一步。

许多概念可以直接迁移，只是落到物理世界后需要升级：

Agent 的任务分解，可以迁移为机器人的高层任务规划；

Tool Calling，可以迁移为可复用的抓取、放置、开门等技能库；

Guardrail，可以迁移为速度、力矩、工作空间和碰撞限制；

Trace，可以迁移为包含图像、关节状态和动作的完整 episode；

Eval，可以迁移为多次真机 rollout、成功率统计和失败类型分析。

接下来要补的，恰好是软件 Agent 很少要求的那部分能力：

如何采集时间对齐的机器人数据；

如何让模型学习连续动作；

如何处理延迟、控制频率和误差累积；

如何在仿真和真机里做闭环评测；

如何把规划模型、策略模型、控制器和安全机制组合成一个系统。

### 把这些经验接回纸杯任务

![](https://static001.geekbang.org/editor-compose/resourceimage/compose/65/9b/6529f024aa183e0973b97318beebbd9b.png)

上图把这条闭环画了出来：用户目标先变成任务计划，策略再根据当前观测预测一小段动作，控制与安全层负责执行；动作改变现场后，新观测会触发下一轮预测、重新规划或失败恢复。

大模型仍然有价值，只是角色从“每一帧该怎么转电机”的直接控制者，转为理解目标、组织技能和处理长程任务的规划者。闭环策略把视觉变成身体动作，底层控制器和安全机制则约束动作怎样执行。

这就是普通 AI Agent 与具身智能最核心的分界线：

普通 Agent 主要在信息世界里选择和调用动作；具身智能必须让身体在真实世界里连续行动，并承担动作带来的后果。

## 动手写第一份“物理 Tool Schema”

如果你习惯先写 Tool Schema，现在就把这个习惯迁移过来。先不连接机械臂，为纸杯任务写一份最小合同：

{

"task": "把纸杯放进左侧收纳盒",

"observation": {

"cameras": \["front", "wrist"\],

"state": \["shoulder\_pan", "shoulder\_lift", "elbow\_flex", "wrist\_flex", "wrist\_roll", "gripper"\]

},

"action": {

"representation": "absolute\_joint\_position",

"rate\_hz": 30,

"dimensions": 6

},

"stop": \["joint\_limit", "stale\_observation", "operator\_estop"\],

"success": "20 秒内杯子完全进入盒内，夹爪释放"

}

先读其中最关键的三个字段：

absolute\_joint\_position 表示每次给出六个关节各自要到达的位置；

dimensions: 6 表示每条动作有六个数；

rate\_hz: 30 表示计划每秒发送 30 条动作，约每 33 毫秒一条。

这是本练习的设计值，实际设备能否稳定达到，要在运行时测量。

注意，这份 JSON 是你写给自己的接口草稿，不是 LeRobot 可以直接加载的配置。现在请在旁边写下三个尚未解决的问题：六个数用什么单位？相机名字怎样对应实际画面？多久没有新画面就该停止？再给成功条件补一个反例：“杯子卡在盒沿上，即使夹爪已松开，也判失败。”做到这里，你已经把一句模糊需求，变成了几项可以检查的约定。后面的数据、训练和安全章节会逐项补全它。

## 小结：先不要急着问“该选哪个模型”

进入具身智能后，你很容易先问：用 VLA、ACT，还是强化学习？哪个模型参数更多？哪个榜单成绩更高？但在选模型之前，更重要的是先建立下面这套判断框架：

模型拿到的观测，是否足以判断当前任务状态？

它输出的是高层技能、短动作序列，还是底层控制量？

整条链路的延迟和运行频率，是否满足任务要求？

动作失败后，系统如何检测、恢复和重置？

评测的是离线预测，还是完整闭环中的真实成功率？

这五个问题没有答案时，再强的模型也可能只留下漂亮演示。逐一解决之后，一台普通机械臂才有了可感知、可行动、可纠错、可验收的智能体闭环。

下节课继续解决中间那一层：我们已经知道策略的输入和输出，可它怎样学会这些动作？还是这个纸杯任务，我们分别试着“示范给它看”“让它按得分试错”和“用语言指定目标”，看看三种起点各需要哪些条件，再选出第一条值得动手的路线。

## 思考题

如果策略模型在机械臂运动途中迟迟没有返回新动作，你会让设备“保持当前位置”“继续上一段动作”还是“立即停止”？请选一种，并写出它适用的前提和可能带来的风险。
