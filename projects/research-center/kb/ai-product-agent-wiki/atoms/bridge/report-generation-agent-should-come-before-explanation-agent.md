# 报告生成 Agent 应先于解释 Agent

## 断言

一镜一梳更自然的 Agent 顺序是先把 Lite / Pro 报告生成变成 Agent，再加报告解释 Agent。

## 类型

- decision

## 适用范围

- bridge

## 来源

- [[../../wiki/bridge/mandala-report-agent-path]]

## 备注

- 先解决报告生成里的证据组织、stage 顺序、来源绑定和质检，再做解释层更稳妥。
- 解释 Agent 应该建立在稳定的报告产物、trace 和 guardrails 之上。
