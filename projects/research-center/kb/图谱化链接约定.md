# KB 图谱化链接约定

> 状态：draft
> 版本：0.1.0
> owner：Research & Knowledge Lead
> last_updated：2026-05-11
> source_of_truth：projects/research-center/kb/图谱化链接约定.md

本约定遵循 Karpathy（卡帕西）一类 `llm-wiki` 的轻量思路：先让 Markdown 页面稳定互链，再让图谱自然长出来。

## 核心原则

1. Markdown 是唯一真实源。
2. 重要概念优先做成独立页面，而不是只留在正文里。
3. `source -> atoms -> wiki` 仍然是主链路，图谱化只是增强，不替代这条链路。
4. 不急着引入重型图数据库、RDF 或复杂 typed edges（带类型关系边）。

## 页面分工

- `sources/`
  - 记录原始材料。
  - 负责说明“这份材料讲了什么”。
- `atoms/`
  - 沉淀单条、可检查、可复用的判断。
  - 负责说明“我确认了什么判断”。
- `wiki/`
  - 承接概念页、方法页、主题页。
  - 负责说明“这个概念是什么、和什么有关、当前如何理解”。

## 什么词要做成页面

满足以下任一条件时，优先建独立页面：

1. 会在多个 source / atom / wiki 中反复出现。
2. 不是纯标签，而是有理解成本。
3. 会和其他概念形成稳定关系。
4. 值得后续进入公司级知识库。

## 链接写法

为了兼容未来的 wiki graph（图谱视图）与当前 GitHub 阅读，默认使用“双写法”：

- `[[Agent]] Agent`
- `[[MCP]] MCP`

规则：

1. 在一篇文档里，首次出现的重要概念优先加链接。
2. 后续重复出现时，不强制每次都加。
3. `source` 不要满屏链接，只链接关键概念。
4. `atom` 和 `wiki` 可以更积极地互链。

## 命名约定

- 概念页默认放在 `wiki/ai/` 或 `wiki/healing/`。
- 文件名优先用行业里更稳定的主称呼，例如 `Agent.md`、`MCP.md`。
- 标题可以保留中英混合解释，例如 `# Agent（智能体）`。

不同页面不要共用同一套命名规则：

- `sources/`
  - 默认使用 `YYYY-MM-DD-作者-标题.md`
  - source 是具体材料记录，保留日期有利于排序、去重和回溯
- `atoms/`
  - 默认不带日期
  - 优先使用“判断主语-核心判断”的稳定命名
- `wiki/` 概念页
  - 默认不带日期
  - 文件名直接使用稳定概念名，例如 `Agent.md`、`MCP.md`
- `wiki/` 人物页 / 公司页 / 产品页
  - 默认不带日期
  - 文件名直接使用稳定实体名，例如 `Teddy-Riker.md`、`Ramp.md`

## 页面层级建议

为了避免文件规模过快膨胀，默认区分两类 wiki 页面：

- 核心概念页
  - 高频复用
  - 有解释成本
  - 会成为多个页面的链接中心
  - 这类页面值得长期保留并持续增长
- 语境实体页
  - 主要用于解释“这个人 / 公司 / 产品在当前来源里是谁”
  - 当前信息量很小时可以先保留最小页面
  - 如果后续没有重复出现，可以并回 source 或主题页，不强制长期独立存在

一个词默认满足以下 3 条中的至少 2 条，才建议升格为核心概念页：

1. 会跨多个 source / atom / wiki 重复出现
2. 本身有解释成本
3. 会成为其他页面的稳定链接中心

知识如何按寿命分层，见 [知识半衰期分层约定](./知识半衰期分层约定.md)。

## 第一阶段做法

当前阶段先做：

1. 为高频专有名词建概念页。
2. 在 source 的术语表和正文首次出现处补关键链接。
3. 在概念页里回链相关 source。

暂时不做：

1. 自动生成全局 graph。
2. 复杂关系类型标注。
3. 单独的术语数据库或 JSON 索引。
