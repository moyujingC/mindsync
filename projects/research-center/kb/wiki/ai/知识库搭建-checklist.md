# 知识库搭建 checklist（检查清单）

> 状态：draft
> 版本：0.1.0
> owner：Research & Knowledge Lead
> last_updated：2026-05-12
> source_of_truth：projects/research-center/kb/wiki/ai/知识库搭建-checklist.md

## 使用方式

这份 checklist 用于从 0 到 1 搭建知识库，或审查一个已有知识库是否具备长期维护能力。

每一项可以标记为：

- `未开始`
- `已定义`
- `已落地`
- `需复核`

## 1. 边界与入口

- [ ] 已明确知识库服务对象：个人 / 团队 / 项目 / 客户 / AI agent（智能代理）。
- [ ] 已明确知识库主题边界：哪些内容应该进入，哪些内容不进入。
- [ ] 已明确知识库所在位置：目录、工具、空间或仓库路径。
- [ ] 已设置稳定首页入口，并能从常用工作路径访问。
- [ ] 首页能说明当前知识库的用途、结构和主要入口。
- [ ] 已区分 source（来源）、atom（原子知识）和 wiki（结构化知识）等不同层级。

## 2. 权限与责任

- [ ] 已明确全局 owner（负责人）。
- [ ] 已明确谁可以新增内容。
- [ ] 已明确谁可以修改正式 wiki 页面。
- [ ] 已明确谁负责审核或复核重要页面。
- [ ] 重要页面已绑定页面级 owner。
- [ ] 已定义 owner 离开、角色变化或长期不维护时的交接方式。

## 3. 内容结构

- [ ] 已定义 source 模板。
- [ ] 已定义 atom 模板。
- [ ] 已定义 wiki 模板。
- [ ] 模板包含来源、可信状态、适用场景和边界字段。
- [ ] 已定义文件命名规则。
- [ ] 已定义页面状态：draft（草稿）、current（当前有效）、deprecated（已废弃）等。
- [ ] 已定义从 source 到 atom，再到 wiki 的最小流转规则。

## 4. 标签、目录与搜索

- [ ] 已定义稳定目录结构。
- [ ] 已定义标签维度，例如主题、对象、状态、用途、项目。
- [ ] 已避免只依赖树状目录查找内容。
- [ ] 高频主题能通过首页或导航快速进入。
- [ ] 页面标题包含用户可能搜索的关键词。
- [ ] 重要概念已通过内部链接互相连接。
- [ ] 已确认搜索能覆盖标题、正文和关键标签。

## 5. 内容发现机制

- [ ] 已定义新内容从哪里来。
- [ ] 高频问题能从客服、销售、交付、研发或项目记录中进入候选池。
- [ ] 重复出现的私聊答案、群聊解释和排障记录有机制进入 source。
- [ ] 已定义哪些问题值得提炼成 atom。
- [ ] 已定义哪些 atoms 值得编译成 wiki。
- [ ] 已定义低价值、过期或一次性材料的处理方式。

## 6. 更新与复核

- [ ] 已定义重要页面的复核周期。
- [ ] 页面包含 `last_updated` 或等价更新时间字段。
- [ ] 页面包含可信状态或验证状态。
- [ ] 已定义内容过期时的处理方式。
- [ ] 已定义冲突内容如何合并或裁决。
- [ ] 已定义废弃页面如何标记和保留。
- [ ] 已定期检查无人负责、长期未更新或高频访问但低可信的页面。

## 7. 面向 AI 的可读性

- [ ] 页面标题层级清晰，优先使用 H1 -> H2 -> H3。
- [ ] 关键术语首次出现时有解释。
- [ ] 同一概念使用稳定命名。
- [ ] 页面尽量自包含，避免必须依赖大量外部语境才能理解。
- [ ] 段落简短，列表结构清晰，减少大段混杂内容。
- [ ] 重要页面包含内部链接，帮助 AI 理解概念关系。
- [ ] 页面包含元数据，例如状态、owner、更新时间、来源路径。
- [ ] 面向 AI agent 或 RAG（检索增强生成）时，已确认知识库内容比 prompt（提示词）更优先治理。

## 8. 验收标准

一个知识库第一版可以进入使用，至少应满足：

- [ ] 有稳定入口。
- [ ] 有清楚边界。
- [ ] 有 1 个全局 owner。
- [ ] 有 source、atom、wiki 的基础模板或等价结构。
- [ ] 有最小命名规则。
- [ ] 有至少 3 条可追溯 source。
- [ ] 有至少 3 条从 source 提炼出来的 atoms。
- [ ] 有至少 1 篇由 atoms 编译成的 wiki。
- [ ] 重要页面能回指来源。
- [ ] 用户能通过目录、标签或搜索找到核心内容。
