# Content Visual Workflow

## 目标

把一篇中文长文转成可分发的内容资产，用于公众号、小红书等渠道首发。

这个 skill 关注内容生产工作流本身，不负责具体页面样式，也不替代某个单独的出图命令。

## 适用范围

在以下场景使用：

- 需要把长文转成公众号和小红书可发布资产
- 需要先做内容拆解，再做视觉生成
- 需要评估工作台是否已经达到首发可用
- 需要判断哪些动作应进入主链路，哪些动作保留人工复核

以下场景不适用：

- 单纯前端样式微调
- 某个组件的局部重构
- 与内容分发无关的通用图片生成

## 核心原则

1. 先内容结构，后视觉生成。
2. 一篇长文通常要拆成多类资产，不要混成一种“图片输出”。
3. 知识卡和金句卡是两条不同链路：
   - 知识卡承载信息拆解
   - 金句卡承载传播句子
4. 正文配图服务阅读节奏，不替代正文表达。
5. 首发阶段默认人工复核，生成成功不等于可直接发布。

## 工作流

### 1. 输入文章

输入可以来自：

- 手动粘贴正文
- Markdown 文件导入
- 已有文章草稿

最低要求：

- 标题
- 正文
- 可用于结构拆解的段落文本

### 2. 提取文章结构

先把正文转成基础结构，再进入出图。

至少识别：

- 标题
- 段落
- 引用
- 小节
- 图片占位

### 3. 拆知识卡

知识卡数量由模型按文章结构判断，不由用户先指定固定张数。

建议约束方式：

- 拆卡策略：偏少 / 自动 / 偏多
- 数量范围：例如最少 2 张、最多 6 张

每张知识卡至少包含：

- `index`
- `title`
- `summary`

### 4. 提取候选金句

候选金句来自原文，不能脱离原文语义。

筛选标准：

- 能独立传播
- 不依赖大段上下文
- 有记忆点
- 不只是正确，也适合传播

系统应支持：

- 多条候选
- 人工勾选
- 重新选择后再生成金句卡

### 5. 规划正文配图

正文配图按阅读节奏规划，不按小节数量机械分配。

每张配图至少回答：

- 对应哪一节
- 作用是什么
- 视觉方向是什么
- 为什么放在这里

### 6. 规划封面

封面服务文章入口，不负责完整表达全文。

优先考虑：

- 文章总主题
- 点击入口气质
- 品牌统一感
- 渠道适配

### 7. 按用途生成视觉资产

图片生成顺序固定为：

1. 用途
2. 预设尺寸
3. 宽高
4. 风格
5. 提示词

不要直接让用户面对零散像素值。

### 8. 回写结果并建立绑定

生成结果不能只存“有几张图”，至少要建立这些绑定：

- 知识卡图片 <-> 对应知识卡
- 金句卡结果 <-> 所选金句
- 正文配图 <-> 对应小节
- 封面结果 <-> 当前封面候选

没有绑定关系，结果区只是素材堆，不是工作流。

### 9. 输出发布材料

最终目标是可发布材料，而不是系统内预览：

- 公众号正文
- 小红书知识卡组
- 金句卡
- 封面图
- 正文配图

## 可协作的外部 Skill

如果当前环境已经安装了以下外部 skill，可以按生产环节调用；未安装时，只参考其能力边界，不要假装已经可用。

### 选题与角度诊断

- `dbskill`：用于 Hook、标题、内容角度和同类爆款结构诊断。
- 使用位置：文章立项前，或文章写完但标题、切口不稳时。
- 注意：它不替代作者判断，只给选题角度和传播入口做诊断。

### 资料、提纲与长文写作

- `content-research-writer`：用于资料整理、提纲、引用和长文初稿。
- `NotebookLM Claude Code Skill`：用于基于个人资料库、课程资料、访谈记录、行业文档写作。
- `khazix-skills`：用于深度研究型内容和长报告。
- 使用位置：文章进入成稿前，尤其适合资料驱动型长文。
- 注意：对于个人体验类文章，不应过度引入研究流，避免把随笔升级成研究项目。

### 中文表达优化

- `Humanizer-zh`：用于减少模板感、空话、过度排比和 AI 腔。
- 使用位置：文章成稿后、发布前。
- 注意：只做表达打磨，不改文章核心立场；不要把真实个人语气磨平。

### 正文配图

- `ian-xiaohei-illustrations`：用于把观点、流程、情绪或隐喻转成统一风格正文配图。
- 使用位置：正文配图规划完成后。
- 注意：正文配图服务阅读节奏，不等同于小红书知识卡。

### 拆卡、封面与分发包装

- `guizang-social-card-skill`：用于小红书图文卡片、公众号封面、社交平台缩略图。
- `baoyu-skills`：用于封面、信息图、结构图、观点可视化等视觉表达参考。
- `guizang-ppt-skill`：用于把文章观点、课程大纲、分享稿转成演示稿。
- `html-anything`：用于把 Markdown 转成 HTML 页面、海报页、杂志风页面。
- 使用位置：文章结构和视觉资产规划已经明确之后。
- 注意：这些 skill 解决分发包装，不负责判断文章主张是否成立。

## 推荐编排

首发生产时优先按这条链路执行：

1. `content-visual-workflow` 判断内容结构和资产类型
2. `dbskill` 诊断标题、Hook 和传播角度
3. `Humanizer-zh` 打磨中文表达
4. `guizang-social-card-skill` 生成小红书卡片和公众号封面
5. `ian-xiaohei-illustrations` 补正文配图

如果文章依赖大量外部资料，再把 `content-research-writer` 或 `NotebookLM Claude Code Skill` 放到第 1 步之前。

## 资产类型要求

### 知识卡片

- 标题清楚
- 摘要简短
- 单卡表达一个相对独立的观点
- 支持单卡重生成和单卡替换

### 金句卡

- 必须绑定已选金句
- 无选择时不能默认生成
- 更换已选金句后，旧结果必须明确标记为旧绑定结果

### 公众号封面

- 服务品牌气质
- 不过度营销化
- 不承担全文信息表达

### 正文配图

- 服务阅读节奏
- 适合插入正文
- 与当前小节主题有关联

### 公众号正文排版

- 结构来自当前文章
- 标题、引用、段落、图片位置有明确映射
- 复制后的还原度需要人工验证

## 人工复核规则

以下情况必须人工复核：

- 知识卡标题偏离原文主张
- 金句抽离后不成立
- 金句过于口号化
- 配图和段落逻辑不匹配
- 封面过重、过度营销、像素材站模板
- 排版复制后样式不稳定
- 小红书卡片可看但不具备发布质感

## 产品侧判断

如果把这个 workflow 做成工作台，优先保证：

1. 当前文章是全局共享对象
2. 拆解结果、金句、图片结果之间有明确绑定
3. 用户能看懂当前结果来自哪一轮拆解
4. 单卡失败、单卡重生成不会打乱整页状态
5. 工作台是主链路，不要求用户频繁切页

## 发布阶段判断

当前更适合：

- 创作者本人使用
- 边生产边校正工作流
- 验证哪部分值得自动化

当前不适合：

- 无人值守批量发布
- 稳定生产后台
- 多人协作正式运营

灰度顺序建议：

1. 先支持单篇内容闭环
2. 再支持连续 3 篇内容
3. 默认人工审核发布

## 边界

这个 skill 负责内容生产逻辑和工作流判断。

它不负责：

- 某个前端文件怎么改
- 某个按钮的最终视觉样式
- 某个 API 的技术实现细节
- 与内容分发无关的纯研究任务
