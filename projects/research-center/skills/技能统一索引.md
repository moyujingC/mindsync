## 3. 按问题查找

### 3.1 任务刚进来，不知道该给谁

- 用 `task-routing`
- 如果任务明确是“参考材料摄取”，优先用 `reference-intake-routing`

### 3.1A 链接是视频/媒体内容，先要把它变成可处理输入

- 先用 `media-link-intake`
- 若已拿到媒体文件或音频，再用 `media-transcribe`
- 若媒体内容本身难以本地抓取，优先用 `external-knowledge-intake` 先完成外部采集与保存

### 3.2 不确定当前能不能进入下一阶段

- 用 `artifact-readiness-check`

### 3.3 已经有结论，但不知道怎么交给下一角色

- 用 `handoff-packaging`
- 如果上游是研究结论，也可用 `insight-handoff`

### 3.4 研究还没收束成正式任务

- 用 `research-brief`

### 3.5 研究做完了，想入库

- 用 `knowledge-ingest`

### 3.5C 草案里有事实主张，想先确认能不能放行

- 用 `fact-check-gate`

### 3.5A 研究材料很多，但还没形成综合结论

- 用 `research-synthesis`

### 3.5B 有参考材料，想提炼观点、框架和方法

- 用 `insight-extraction`
- 若参考材料来自抖音、小红书、网页收藏，优先先用 `external-knowledge-intake` 召回

### 3.6 需要做产品定义

- 用 `product-framing-spec`

### 3.7 需要做商业判断

- 用 `business-diagnosis`

### 3.8 需要进入架构定义

- 用 `architecture-boundary-plan`

### 3.8A 需要把控制台前端做稳、做清楚、做成正式后台

- 用 `ui-ux-console-design`

### 3.9 需要做验收或质量门

- 用 `qa-gate-review`

### 3.9A 需要做仓库文档健康检查或治理执行

- 用 `doc-governance`

### 3.10 需要把真实素材转成内容输入

- 用 `content-grounded-transform`
- 上游真实素材若仍在外部平台，先用 `external-knowledge-intake`

### 3.10A 需要拆解表达方式、结构和语气

- 用 `expression-extraction`

### 3.11 需要把创作者 review 结果写回系统记忆

- 用 `review-feedback-to-memory`

### 3.12 需要定期整理知识库与偏好记忆

- 用 `knowledge-relink-maintenance`

### 3.13 文档系统有问题（冗余/重复/矛盾/状态混乱）

- 用 `doc-governance`
- 典型场景：
  - 文档改着改着越来越冗余
  - 多个文件说同一件事，不知道信哪个
  - 发现内容矛盾的文档
  - 定期做文档健康检查

## 4. 后续自动发现建议

如果后续要做轻量自动发现，建议优先读取：

1. 本索引文档
2. `skills/*/SKILL.md` frontmatter
3. `技能清单与角色映射.md`

自动发现时至少应支持：

- 按角色筛选
- 按关键词筛选
- 按工作流阶段筛选
- 区分 repo 内 skill 与第三方外部 skill
