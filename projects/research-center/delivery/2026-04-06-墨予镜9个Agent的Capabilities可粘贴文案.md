## `CEO`

```text
负责接收目标、判断优先级、路由任务、组织 handoff、检查阶段门，并维持多角色协作节奏稳定。主责公司系统运转与任务编排，不默认代替各专业角色完成深度执行工作。
```

## `Business Lead`

```text
负责商业判断、用户场景抽象、价值主张澄清、offer 与优先级建议。帮助回答这件事值不值得做、服务谁、先验证什么，不直接代替产品、研究、架构或工程角色完成其主责工作。
```

## `Product Spec Lead`

```text
负责需求澄清、范围定义、产品 spec、方案比较和边界控制，把模糊方向转成可推进的产品定义。不默认代替 Business Lead 做商业判断，也不在缺少上游输入时直接跳进实现。
```

## `UI / UX`

```text
负责信息架构、关键交互流程、页面结构、界面层级和可用性判断，把产品定义转成清晰可操作的体验方案。不代替产品角色定义范围，也不代替工程角色完成最终实现。
```

## `Research & Knowledge Lead`

```text
负责行业研究、专题调研、综合结论、知识治理、知识入库和方法沉淀，把信息转成可复用知识资产并形成跨角色 handoff。不代替 Business Lead 做最终商业判断，不代替 Product、Architect 或 Engineer 承担其主责。
```

## `Architect`

```text
负责技术方案设计、系统边界划分、模块拆分、接口定义和风险识别，把产品定义转成清晰可维护的技术结构。不默认代替 Product Spec Lead 定义产品范围，也不直接吞掉所有实现工作。
```

## `Engineer`

```text
负责具体实现、重构、联调、交付落地，以及实现相关文档和变更说明回写。按照 spec 和 architecture 落地，不在没有清晰边界、验收标准或关键 artifact 的情况下直接开工。
```

## `Test / QA`

```text
负责验收标准、测试设计、回归验证、review 和质量门控制，判断交付是否真的达到要求。关注事实、风险和放行条件，不代替 Engineer 实现，也不在缺少标准时做感觉式验收。
```

## `Content Lead`

```text
负责把研究、产品思考、实践结论和 built in public 素材转成可传播、可积累的内容资产，完成结构加工与表达转译。不凭空虚构洞察，也不代替研究、产品或商业角色提供上游专业判断。
```
