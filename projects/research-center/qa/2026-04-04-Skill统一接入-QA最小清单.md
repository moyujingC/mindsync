# Skill 统一接入 QA 最小清单

这份文档用于定义 skill 统一接入前后的最小 QA 检查项。

## 1. 结构检查

- 每个关键 skill 是否存在 `SKILL.md`
- 关键 skill 是否有模板或 checklist
- 统一索引是否能定位到每个 skill 的真实路径

## 2. 角色接入检查

- 对应角色 `AGENTS.md` 是否已引用应使用的核心 skill
- 角色引用路径是否有效
- 角色 prompt 是否只保留入口，而没有复制 skill 正文

## 3. 试跑验证检查

- 每条主链是否至少有一份试跑记录
- 试跑记录是否能反查到真实 artifact
- 是否能区分：
  - 已有真实试跑的 skill
  - 仅有说明但未试跑的 skill

## 4. 阶段门检查

- spec 是否明确做什么 / 不做什么
- architecture 是否明确模块边界、风险和 handoff
- implementation-plan 是否明确 owner 和产物
- QA 结论是否明确：
  - 通过 / 有条件通过 / 不通过

## 5. 放行规则

- 以下情况可判为“有条件通过”：
  - 路径和角色接入一致，但案例覆盖不完整
  - artifact 完整，但 QA checklist 尚在补齐
- 以下情况应判为“不通过”：
  - skill 引用路径失效
  - 关键阶段缺正式 artifact
  - 试跑记录无法回链到真实产物

## 6. 一句话结论

统一接入的 QA 最小目标，不是证明 skill 完美，而是证明它们已经具备结构完整、路径有效、可被真实任务验证的最低条件。
