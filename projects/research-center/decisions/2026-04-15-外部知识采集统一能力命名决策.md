# 外部知识采集统一能力命名决策

> 阶段：architecture

## 1. 决策

从 2026-04-15 起，`Get笔记` 相关正式治理入口统一命名为 `external-knowledge-intake`，中文定位为“外部知识采集”。

当前采用双层结构：

- 上层正式 skill：`external-knowledge-intake`
- 底层默认工具实现：`getnote`

## 2. 为什么这样做

`Get笔记` 是一个具体工具名，不适合长期承担研究中心正式能力命名。

当前真正需要稳定下来的不是品牌名，而是以下业务能力边界：

- 外部内容采集
- 外部素材召回
- 外部素材基础管理
- 原文回看与追溯
- 下游 source pack 供给

若继续直接把正式能力写成 `Get笔记`，会带来两个问题：

- 公司治理文档会和某个供应商强绑定
- 未来若更换底层工具，角色入口和治理口径都要重写

## 3. 边界

`external-knowledge-intake` 负责：

- 定义什么时候需要进入外部采集层
- 定义输入、输出、handoff 和质量门
- 约束外部素材如何进入研究中心正式工作流

`getnote` 继续负责：

- 具体 API
- 笔记保存
- 搜索召回
- 标签和知识库管理
- 相关环境变量配置

默认不把 `external-knowledge-intake` 或 `getnote` 视为公司正式主知识库。

## 4. 兼容策略

- 不删除现有 `getnote` skill
- 不立即改 `shared/tools/getnote-setup.sh`
- 现有 Paperclip 恢复链仍按 `getnote` 来源工作
- 研究中心文档、角色入口和治理口径先统一切到 `external-knowledge-intake`

## 5. 一句话结论

以后正式对外说的是“外部知识采集”能力，当前默认底层实现仍然是 `Get笔记`。
