## 一、整体工程概览

- 代码规模：~1,900 个文件，512,000+ 行 TypeScript 代码

## 二、核心工作流

### 1. 启动流程
```
bun run dev → package.json scripts.dev → src/entrypoints/cli.tsx
→ 快速路径检查（按开销从低到高，早返回早优化）
→ 动态 import 延迟加载重型模块
→ main.tsx:main() → 40+ CLI 参数解析 → 预加载并行执行（MDM检查、keychain预取等）
→ launchRepl() → replLauncher.tsx → <App><REPL /></App> 渲染到终端
```

### 2. 对话循环
```
用户输入 → REPL.onSubmit → handlePromptSubmit → onQueryImpl
→ query() AsyncGenerator 入口 → queryLoop() while(true) 主循环
→ 消息预处理（自动压缩、边界处理）
→ deps.callModel() → claude.ts queryModel()
→ anthropic.beta.messages.stream() 流式API调用
→ StreamingToolExecutor 并行执行工具调用
→ 工具结果追加到消息列表 → 继续循环
→ 无工具调用时返回最终结果给用户
```

### 3. 工具调用流
```
模型返回 tool_use 内容块 → 工具名称匹配 → 权限检查
→ 工具执行（同步/异步）→ 结果格式化
→ 追加到消息历史 → 重新进入查询循环
```

## 三、关键设计模式总结

| 模式 | 位置 | 说明 |
|------|------|------|
| 快速路径优化 | cli.tsx | 按开销从低到高逐级检查，减少不必要的模块加载 |
| 动态import延迟加载 | cli.tsx / main.tsx | `await import()` 拆分模块，优化启动时间 |
| Feature Flag | 全局 | `feature()` 函数控制功能开关，死代码自动消除 |
| React/Ink 终端UI | UI层 | 用React组件模型开发终端交互界面 |
| AsyncGenerator 事件流 | query.ts → claude.ts | `yield*` 透传流式事件，形成管道架构 |
| 不可变状态机 | query.ts queryLoop | 循环间通过不可变State + transition传递状态 |
| 流式并行工具执行 | query.ts | API返回过程中并行执行工具，降低延迟 |
| Withheld 消息模式 | query.ts | 暂扣可恢复错误，恢复成功则用户无感知 |
| 自动重试+降级 | claude.ts | 429/500/529错误自动重试，失败则模型降级 |
| Prompt Caching | claude.ts | 缓存系统提示和历史消息，减少token消耗 |
| 工作树隔离 | AgentTool | 子Agent运行在临时git工作树，不污染主工作区 |

## 四、Multi-Agent 协作机制

### 1. AgentTool 核心能力
- 支持多种Agent类型：general-purpose、statusline-setup、Explore、Plan等
- 运行模式：前台阻塞/后台异步
- 隔离能力：git worktree 隔离工作区，避免相互影响
- 通信能力：支持通过SendMessage向命名Agent发送消息
- 权限控制：子Agent可继承或独立设置权限模式（如plan模式需要审批）

### 2. 调度机制
- 每个会话一个QueryEngine实例
- 子Agent拥有独立的会话上下文和工具集
- 协调器模式支持多Agent任务分配和结果汇总
- 后台Agent任务自动通知进度和完成状态

### 3. 资源隔离
- 工作目录隔离：子Agent可指定独立cwd或使用临时worktree
- 权限隔离：子Agent权限独立于父Agent
- 状态隔离：子Agent拥有独立的消息历史和状态
