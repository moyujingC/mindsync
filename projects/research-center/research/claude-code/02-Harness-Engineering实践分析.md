# Claude Code Harness Engineering 实践分析

> 版本：0.1.0
> 日期：2026-04-04
> 研究人员：Research & Knowledge Lead

## 一、Harness Engineering 核心理解

Harness Engineering（线束工程）是指构建一套标准化的、可复用的"操作线束"，将复杂的操作封装成安全、可控、可审计的工具和工作流，让AI能够在明确的边界内可靠地执行任务。

## 二、Claude Code 中的核心实践

### 1. 工具系统线束化

#### 工具定义标准
```typescript
interface Tool {
  name: string;
  description: string;
  inputSchema: ZodSchema; // 严格的输入校验
  call: (params: ToolParams) => Promise<ToolResult>;
}
```
- 每个工具都有明确的功能边界和输入输出契约
- 使用Zod做严格的参数校验，拒绝非法输入
- 工具实现与调度层完全解耦

#### 工具安全防护
- **权限分级**：每个工具都有明确的权限要求，用户可细粒度控制
- **操作审计**：所有工具调用都会被记录到会话历史
- **危险操作确认**：破坏性操作（如文件删除、git reset）需要用户二次确认
- **Dry Run 支持**：高危工具支持预览操作结果，避免误操作

### 2. 执行环境线束化

#### 工作区隔离
- 子Agent默认运行在临时git worktree，不污染主工作区
- 支持指定独立cwd，限制文件操作范围
- 工作树自动清理机制，任务完成后可选择保留或删除

#### Shell 执行防护
- Bash工具内置白名单过滤，禁止危险命令
- 命令执行超时机制，避免长时间阻塞
- 输出大小限制，防止大量输出撑爆上下文
- 后台任务独立管理，支持中断和状态查询

### 3. 工作流线束化

#### 标准化任务模板
- 研究任务模板
- 内容选题模板
- 开发任务模板
- 所有任务都有统一的元数据结构（状态、版本、owner、来源等）

#### 流程强制校验
- 计划模式：实现功能前必须先输出计划，用户审批后才能执行
- 设计规格确认：实现前必须验证设计规格是最新批准版本
- 服务器启动验证：启动服务后必须通过health检查才能报告成功
- 内容质量校验：内容发布前必须经过质量标准检查

### 4. 上下文线束化

#### 上下文自动注入
- Git状态自动注入：当前分支、修改文件、最近提交等
- CLAUDE.md 自动加载：从全局到项目级的规则自动合并
- 环境信息注入：平台、日期、工作目录等
- 内存文件注入：跨会话记忆自动加载

#### 上下文压缩策略
- 自动压缩历史消息，保持上下文窗口高效利用
- 边界检测机制，避免重要信息被压缩
- 长文件分块读取，避免一次性加载过大内容

## 三、Harness Engineering 带来的价值

### 1. 可靠性提升
- 标准化工具减少了AI的" improvisation（即兴发挥）"
- 严格的输入校验降低了错误率
- 隔离机制避免了操作污染

### 2. 安全性提升
- 权限系统防止越权操作
- 审计日志支持问题回溯
- 二次确认机制降低人为失误

### 3. 效率提升
- 封装好的工具链减少重复劳动
- 标准化流程降低沟通成本
- 自动上下文注入减少用户输入负担

### 4. 可扩展性提升
- 工具注册表支持动态扩展新能力
- 技能系统支持自定义工作流
- 插件系统支持第三方能力接入
