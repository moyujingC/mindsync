# 05 部署上线：让产品面向用户开放
你好，我是产品二姐。
上一讲，我们把 Demo 嵌进了 SaaS 框架，用 Harness Engineering 让 Agent 能跑长任务，但做出来的东西只有你自己能看到，并不能发公开的网址给用户使用。这一讲，我们把产品推上线，直接面向用户使用。

以前，这是运维工程师的事情。今天在 AI 的协助下，作为一名产品经理，你也可以自己走完发布流程，这就是 AI 革命的冲击：**让产品经理成为了一名全栈 AI builder**。
我会循序渐进带你完成三件事：
先让你亲手感受“原来上线可以这么简单”。
拆解“简单”背后的机制，从产品经理角度理解运维本身。
聊聊稍微复杂的、工业生产级别的部署上线步骤。

学完这一切，你就可以独立走完从 idea 到产品发布的完整过程。

如果你想要成为一名独立产品人、一人公司、独立开发者、创业者，这是一个基本技能。如果你仍然服务于一个团队，可以推动 AI 在运维中的应用，缩短产品的上线时长等。
## 亲手感受“原来上线可以这么简单”
还记得上一讲我们在 V0.App 里做的 demo 吗？现在打开它，看右上角——有一个 Publish 按钮。点下去。
30 秒之后，你会得到一个真实的 URL，它长这样：https://v0-event-material-generator.vercel.App/，它的域名是：.vercel.App。
有了这个域名，就意味着你的产品此刻运行在 Vercel.App 对应的服务器上，相当于你把服务托管给 Vercel —— 你不需要自己买服务器、不需要管硬件，只管写代码就好。你还可以把这个链接发给用户直接使用，比发视频的方式更加直接了。

这里需要说明一下：V0.App 就是 Vercel 在 2023 年发布的代码生成工具。Vercel 是著名前端框架 Next.js 的发起者，在 AI 革命之前，它就是一家云平台公司，为开发者提供代码托管、自动部署的服务。在 AI 革命之后，它上线了 V0.App（原来叫 v0.App），让开发者能通过自然语言直接开发应用，打通了应用开发、部署上线的全流程。
V0.App 几乎是全球最快能让你完成产品创建、上线的应用，因此受到众多用户的喜爱。到 2024 年，Vercel 平台上托管的应用超过 350 万个，每月处理的部署请求超过 10 亿次，全球超过 100 万名开发者把它作为首选部署平台，其中很大一部分是产品经理。
Jackie Bavaro，前 Google、Airbnb 的产品经理曾经公开了自己用 Vercel 独立构建了一款尤克里里 App 的全程记录：从想法到可交互原型花了 6 分钟；发现 Bug 到 AI 修复用了 1 分钟；完成“听音识别”功能用了 2 分钟。
这些时长虽然夸张，但她的结论不容忽视，那就是：“成本结构完全改变了。PM 不应该再预先削减需求范围，可以直接尝试。”
这与我在上一节说的观点是一致的，即“产品的成本被 AI 无限降低，所以论证 idea 本身，就是把产品 Demo 做出来，在用户使用中逐渐明确需求。”
那么，Vercel 背后到底做了什么，让部署上线如此简单呢？了解背后的过程也就是了解工业生产级的部署过程。
按下 Vercel 的 publish 按钮后会发生什么？
我们假设软件产品是一台印刷机，那么开发工程师的工作就是把机器做出来，而 DevOps 运维工程师的工作就是：
能让印刷机搬运到一个厂房，通上电能稳定运行；这个“厂房”就是能运行并存储代码的服务器。你可以租阿里云、AWS 的云服务器 ECS，它本质上就是一台性能更强、永远联网、不会关机的电脑。
把印刷记录以及印刷出来的成品很好地存储、管理起来。也就是在服务器上划出一块区域，并按照你的想法，构建出数据库，以便用户随时来登录、查询。
整个过程分七步：
第一步：进入工厂—— SSH 连接服务器
首先从阿里云或亚马逊购买云服务器 ECS，相当于你自己租了一个厂房。在这些云厂商的平台上，你需要生成一把打开服务器的钥匙，放在自己本地电脑上。拿着这把钥匙，你就可以在你的电脑上，打开服务器的大门，进入服务器操作了。至于如何配这把钥匙，可以在各个云厂商官网查到。比如阿里云的配置方式在这里可以看到。
这里的核心指令是：
ssh -p 22 root@YOUR_SERVER_IP
# -i 指定你的私钥文件；root 是用户名；后面跟服务器的公网 IP ；
这里要注意：在不同操作系统的指令略有不同，以下所有指令仅供理解，使用之前你可以让 AI 根据你自己的情况确认后再运行。
进去之后，你就可以操作那台“云端电脑”了，只是操作的方式需要通过命令行来执行。这里要做的第一件事就是把代码复制到服务器上。
第二步：搬运印刷机——也就是把代码复制到服务器
我们通常不会把电脑里的代码直接“传”到服务器，而是借助 GitHub 这样的代码管理工具作为中转站。代码先推到 GitHub（git push），服务器再从 GitHub 把代码拉下来（git pull）。这样做的好处是：每一次改动都有历史记录，新版本出了问题可以迅速回退到以前的版本。
在服务器上运行的搬运指令核心就是这两条：
git clone https://github.com/your-org/your-App.git   # 首次：把印刷机搬进工厂
git pull origin main                                   # 之后每次更新：换成最新型号的机器
第三步：做好基建——安装印刷机运转需要的水电
代码本身只是印刷机，要运行还需要安装很多依赖库（比如水、电等），这就像你最开始在本机运行一样，核心指令是：
npm install          # Node.js 项目安装依赖
第四步：建好仓库保存往来用户信息以及印刷成品
我们所说的数据库就是这个“仓库”，专门存放用户信息、操作记录和 AI 生成的结果。
搭建数据库的核心指令比较多，你直接看示例代码，在具体做的时候，让 AI 帮你生成即可。
# 安装数据库，这里我们以最常见的 PostgreSQL 为例
sudo apt install -y postgresql postgresql-contrib
# 启动并设为开机自启
sudo systemctl start postgresql && sudo systemctl enable postgresql
# 创建专属数据库和用户（不用 root，安全起见）
sudo -u postgres psql <<EOF
CREATE USER myApp_user WITH PASSWORD '你的强密码';
CREATE DATABASE myApp_prod OWNER myApp_user;
GRANT ALL PRIVILEGES ON DATABASE myApp_prod TO myApp_user;
EOF
其实这一步在 V0.App 的代码生成过程中已经完成了，但是如果你要进行数据库的迁移或者从零创建，依然要完成这一步。
第五步：让厂房、印刷机、仓库彼此相认——设好环境变量
数据库地址、API Key 这些“原材料供应商的联系方式”不能写在你提交的代码里，而要在工厂里单独配置，这时候会使用到一些命令行来读写服务器上的环境变量，比如下面两个命令就是写入数据库密码和大模型服务的 API key。这些命令都可以让 AI 告诉你来完成。
export DATABASE_URL="postgres://user:password@host/dbname"
export ANTHROPIC_API_KEY="sk-ant-..."
第六步：开机运转——启动服务
这就像你在本地运行一样，看看能不能在服务器上运转起来。
npm run build        # 先把设计图编译成可以运转的机器
npm start            # 开机，开始接单
第七步：挂上厂牌——配置域名，让客户找到你
机器跑起来了，最后需要把你的域名（如 myApp.com）指向这台服务器的 IP，让大家通过域名就能找到你。你可以在阿里云、godaddy、namecheap 等域名平台购买域名，按照他们的操作来执行即可。
这就是一次部署上线的全貌。你在 Vercel 里点一下 Publish，本质上就是把这七步并做了一个按钮。
虽然 Vercel 这种方式部署起来非常简单，但对于一定规模的 App 来说使用会有限制，以下情况不适合使用 Vercel，比如你需要支持实时长时间聊天、直播、游戏实时同步等功能，Vercel 目前是不支持的；如果需要这些能力，你得集成其他三方服务来完成。
又比如你的应用可能需要执行长时间任务，Vercel 最长支持 13 分钟的任务，举个例子如果你的产品需要让 AI 生成一个长视频，超过 13 分钟就会被强制打断。
另外我个人感受 Vercel 收费相对云厂商来说，是偏贵的。
总结来说：Vercel 是最好的起点，但不是终点。
那么，当 Vercel 不能满足你的需求时，就该换一条路了——自己租一台服务器，自己管。
在之前的七步操作中，你已经了解了大概的部署步骤，有了这个基础之后，你就可以借助 AI Coding 工具，加上专业的运维 Skill 和数据库管理 Skill，完成以上七步。接下来我们就看看如何让 Coding Agent 完成这七步。
需要提醒的是：对于重要的生产级别的应用，大家一定要找专业的运维工程师确认，保障安全。
工业级部署：携 Skill 以令“Agent”
其实上述的七个步骤让 AI 完成最简单的方法就是：让 Agent 基于一个优秀的 Skill 把这些步骤写进一个脚本文件，之后每次部署，运行这一个文件就够了。借此机会我也分享一下如何鉴别好的 Skill，以及怎么利用好 Skill。
首先，网上有大量的 Skill 平台，我在这里推荐两个：
一是：skills.sh，这个平台会自动扫描 GitHub 上公开发布的 Skill，只要满足一定条件就可以被展示。
二是：Anthropic 官方的 Skill 库。
其次，甄别 Skill 最好的方法是直接安装，然后问 Claude Code/Codex，这个 Skill 可以做什么，看看它是否能满足你的诉求。如果不满足，在对应的目录下删除即可。
这节课，我们要完成代码部署和数据库创建，我会使用两个 Skill：
一是 devops-engineer skill，在 GitHub 上有 9 千 Star，主要协助完成部署上线。
二是 supabase-postgres-best-practices skill，主要完成数据库相关的任务。
下载安装之后，直接告诉 AI Coding 工具：
使用 devops-engineer skill，帮我创建一个部署脚本，让我以后运行这个脚本就能完成部署上线，途中遇到需要我提供的任何东西，请你告诉我。
还要完成数据库的初始化，创建数据库的时候，使用 supabase-postgres-best-practices skill 构建，并生成一个数据库初始化的脚本。
在你已经理解部署流程之后，顺着这个方向，就可以完成所有的部署、数据库搭建工作。
比如我自己项目的前端脚本长这样，你可以使用 AI 来读这段脚本的含义来理解。
set -e
PORT=22
SSH_URL=root@< ip >
# 连接服务器解压文件
# ssh -p 22 root@< ip > "cd /www/server/x007/x007-web && rm -rf dist/ && unzip -o dist.zip && rm -rf dist.zip"
ssh -p $PORT $SSH_URL "set -e; cd /App/book-skill/frontend; git clean -f public/favicon/; git pull; npm install; npm run export; cp nginx.conf /www/server/panel/vhost/nginx/html_book2skills.com.conf && nginx -t && nginx -s reload"
日常运维：逐步自己搞定
到这里，我从一个产品经理的角度介绍了部署、上线的概念和思路。
无论你是通过哪种方式完成的，上线之后都需要持续更新、维护。你可以继续借助这两个 Skill 完成，在这里我也列出一些常用的指令，让你做到心中有数。
代码更新上线
git add .                          # 把修改的文件标记为"准备提交"
git commit -m "fix: 修复登录按钮问题"  # 写清楚这次改了什么
git push origin main               # 推到 GitHub
# 如果是 Vercel：推完自动触发部署，不用额外操作
# 如果是自有服务器：再 SSH 进去跑一次 deploy.sh
建新数据库（新功能需要新表时）
psql -U postgres                           # 进入数据库命令行
CREATE DATABASE myApp_prod;               # 建库
CREATE USER myApp_user WITH PASSWORD '强密码'; # 建专用用户（不用 root）
GRANT ALL PRIVILEGES ON DATABASE myApp_prod TO myApp_user; # 授权
\q                                         # 退出
对于大部分的运维工作 AI 还是可以很好地解决的。

# 17 选方向：找到真需求的三种方法
你好，我是产品二姐。
不知不觉这个专栏更新到了最后一章——商业化，也就是怎么让你的产品赚到钱。
机会总是留给有准备的人，我换一种更贴切的说法是：“赚钱的机会总是留给有准备的人”。实际上前面所有章节都在讲如何“准备”，而这一章讲的就是怎么抓住“赚钱的机会”。
不过，我们需要认清：机会是需要等待的，它并不一定在努力后就马上出现。换句话说：能不能做出产品是完全可控制的，但能不能把产品卖出去就不那么可控了。实际上，你看到的每一个商业故事背后，都隐藏着创始人长期的潜伏与失败。而我的方法就是：不断播下种子，在实践中等待机会，在等待机会的路上实践。
所以，这一章就是分享如何选择正确的种子播下去，最大可能地增加商业价值实现的概率。这也是我过去两年经过真实经验拷打后的一套方法，希望对你有所帮助。这套方法总共分四步：

第一步：选方向。就是找到一个真正可以付费的场景。我会分享三个帮你选择方向、确定需求的方法。
第二步：被看见。就是找到目标客户经常去的地方，我会详细讲述如何通过 SEO/GEO 的方法让你的产品被用户看见。
第三步：吸引力。就是吸引目标客户到你这里来，我会讲述如何通过 Skill 工作流，生产营销内容的方法。
第四步：卖出去。我会讲述 to C 用户的促单和增长方法，to B 客户产品预演展示方法，以及面向职场领导的高阶表达方法。

这四步会分 4 节课讲完，每一步都必不可少。
这一节讲的是第一步选方向。当我们在前面的内容中知道如何做产品之后，下一个问题就是：我到底该做什么？

> 你可能会遇到以下问题：
> 如果做自己需要的？会不会陷入自嗨。
> 如果做别人需要的？身边人的反馈又太少，而且别人可能只是说说而已。
> 如果跟风做热点？可能刚做完，热度就已经过去了。


但是，如果我在这三句话后面再加上三个条件，就能大大增加播种的成功概率，那就是：
> 做自己需要的，且会反复、长期需要的。
> 做别人需要的，且会真实付费买单的。
> 跟风做热点，且热度过后仍然会长期存在的。
 
接下来我就按照这三个要求，分享如何找到真需求的方法。
## 做自己需要的，且会反复、长期需要的

在 OpenAI 创始人 Sam Altman 写的创业手册里，有这么一句话：
> 理想情况下，你本身就是目标用户。其次，你对目标用户非常了解。所以，如果你的产品来源于自身诉求，千万不要怀疑它的价值，你要相信这世界上一定有一群有同样诉求的人。但是，我们必须要注意：这个诉求是反复、长期存在的。如果不是这样，那等你做出来产品的时候，它就不会再被需要了。

所以，每冒出一个想法，都可以问自己几个问题：
* 我是为了赚钱而做它，还是它确实能解决我的问题？
* 未来半年，我还会需要它吗？
* 做出来之后，我自己会不会经常用？
* 随着我的使用，这个产品会不会越积累越有价值？

健身记录工具「训记 App」就是一个很好的从自身需要出发的例子，开发者自己就是健身爱好者，他把自己长期习得的科学健身方法与习惯用训记 App 管理起来，并通过公众号文章持续和健身爱好者建立链接。

根据七麦数据，训记的月均收入大约在 6 万人民币左右（注：根据月均下载量 3800 左右，Pro 版一次性收费 88 元，按照 18% 左右的转化率计算可以核实）。
当我在公众号“训志 +”上追溯了训记的成长记录后，得出了几点训记商业化成功的要素：

### 一是长期。
训记从 2019 年到现在，花了六年时间。如果不是发自内心需要，开发者是难以坚持如此之久的。
### 二是面向用户做内容。
开发者在公众号上记录的多数是健身指南，而不是如何开发，用了什么框架与技术。这一点是刚刚起步的开发者容易陷入的误区，大家一定要注意。
### 三是增长。
训记里有一个功能，就是健身教练可以在 App 里记录学员的健身进度。那么，教练为了记录进度会主动下载 App，而学员为了看进度，也会下载 App。一个教练带动十个学员，那么就是一比十的裂变。
### 四是价格。
88 元买断，对于国人来说接受度比较高。

其中第一点和第二点靠的就是：这个需求开发者自己长期、反复需要。
当然，这个案例比较理想化。大多数情况下，我们从自身痛点出发挖掘出来的需求还要经过两层考验：
市场上到底有多少人也会长期需要它；
竞争对手多不多，你有没有可能打出差异化。
这里就要用到关键词分析。接下来我会以 AlphaWiseWin、book2skills 为例说明，如何通过大数据工具来判断这两点。
AlphaWiseWin 是 AI 股票分析工具，它要贴近的关键词可能是“AI 股票分析”“股票 Agent”这类找工具的关键词，但更可能是“英伟达股票分析”这类找个股分析的关键词。在这里，我们以“nvda stock”这个关键词为例说明。我会用到三个工具：
* Ahrefs 的关键词难度小工具
* Semrush：数据全面的 SEO 工具，可以对关键词、网站流量进行深度分析
* Google 搜索本身。

而 book2skills 则不一样，即使是把巴菲特推荐过的经典财经书籍《Common Stocks and Uncommon Profits》作为关键词，难度也没那么大。而且 Agent Skill 本身处在上升趋势里。所以更适合作为种子播种下去。
以上就是几个帮你判断自身需求值不值得做的方法：
* 一是这个需求长期、反复存在；
* 二是通过大数据工具分析，识别蓝海，更适合起步。
当然，如果你没有一个强烈的自身需求，那我推荐你使用下一种方法：找到别人需要的且会真实付费的。
## 做别人需要的，且会真实付费买单的
在这种情况下，我会通过三类信号看：
* 搜索信号。这类信号通过刚刚说的关键词分析可以顺藤摸瓜地寻找，就不再详述。
* 社交信号。比如在小红书中被疯狂留言的帖子，尤其是用户表达了强烈需要，而不是凑热闹的评论。
* 成交信号。这是最真实，但同时也是最难获得的信号。

我先讲一个身边的例子：一位朋友所在的公司面向海外投标，要准备数百份翻译材料，包括技术规格说明书，检验证书，类似下图这样。
当时她在小红书上找到一些翻译软件，但这些工具要么无法完整保留原来排版，要么无法批量完成。后来在我的协助下，找到了一款海外的工具，一次性帮她完成了这个任务。之后，我的朋友便在小红书上发帖，把这个翻译效果发出来，结果当天就收获了很多评论。于是她开始在小红书上接单尝试。
此时她没有做任何开发工作，只是承担了翻译公司的角色，接到一些批量翻译的订单。这个案例简直是 AI 视频生成公司 HeyGen 的缩小版。所以你看，我的朋友抓住了 2 个差异化：保留原版，批量翻译，借助一个成熟软件的“壳”就完成了商业验证。
后来由于朋友时间不足，且 AI 技术进步飞速，translator 本身也是一个红海市场，她并没有选择自己研发。但这个故事却非常有意思，从开发者的角度，在产品出来之前，通过评论区的这种社交信号来观察用户的诉求，不失为验证真需求的办法。这就是我所说的社交信号。
接下来我们看最接近真付费需求的“成交信号”。这里我推荐几个平台，供大家验证，哪些需求有人在付费。
1. TrustMRR
这个网站是著名的独立开发者 Marc Louvion 开发的。当时开发者大神 Pieter Levels 有一个痛点，就是无法判断某些应用的真实收入。于是 Marc 就抓住这一点，他做了一个网站聚合站 TrustMRR，要想在 TrustMRR 展示你的产品，就必须提供付费平台 Stripe 的 API key，保证 TrustMRR 拿到的都是真实数据。所以你这里看到的都是真实付费诉求。
2. Starter Story
与 TrustMRR 类似，也可以看到应用的营业额。
3. 七麦数据。
2013 年创新工场孵化的项目，主要监测移动端的 App 数据，比如前文提到的训记 App 数据，就是从这里获得的。
4. Sensor Tower。
可以追踪 App 的数据，但是免费版能看到的数据较少，供你参考。

## 跟风做热点，且热度过后仍然长期存在
我并不反对跟热点。不过你需要识别热点是一个事件，还是代表一种趋势。
如果一直做事件性热点产品，每一次热点过后价值归零，是没有复利效应的，并且维持时间非常短，短到你还没做出来产品热点就已经过去了；而如果你做的是趋势性热点，热点过后确实会有回落，但接下来会进入正常成长期，就会有复利效应。
事件性热点是指事件本身不会对行业产生深远影响，比如 Claude Code 代码泄露，或者近期由于 Claude 通过极致手段禁止中国用户访问，我认为这都是事件。

而趋势性热点会对 AI 行业产生深远影响，比如 OpenClaw/Hermes 提供的开源框架，与之前的 Dify、LangGraph 这类静态工作流框架相比，让 Agent 的能力跨上了新的台阶；又比如 Skills 作为一种标准，还远远没有渗透到各行各业，也是一种趋势。
也就是说，趋势性热点一般是抽象的，适用场景很广的；而事件性热点是非常具体的。
我们可以把上述的几个例子拉到 Google 趋势里来验证一下，就能清晰地看到 OpenClaw /Hermes /Agent Skills 的生命周期要长很多，虽然有短暂的下落期，但它的框架已经被行业使用，具有长期价值。
所以，对热点我的建议是：可以借势，但不要把产品根基建在一次性事件上，长期趋势才适合做你的资产。
如果你持续不断地通过以上三种方法广泛吸收，你大概率会找到合适的切入点。找到这个切入点之后，接下来就用最小成本去验证它。
最后，用最小验证把方向落地
验证的方式有非常多，你可以做一个在线的小应用，比如上节课的插件。除此之外还可以有以下几种方式：
1. 不发布产品，只在社交媒体或论坛上发效果展示。
注意不是 Demo，是面向用户的效果展示。避免写成类似：“我用 Codex 半小时完成了 xxx”。这是开发或产品经理经常容易写的汇报体或炫耀体。但大家可以想想：你的受众是否关心你花了几小时？他们会因为崇拜你，而购买你的产品吗？所以，我更推荐以下标题，它们更加贴近用户诉求，比如：
* 翻译类软件可以写：完整保留翻译排版，太爱了
* 健身类软件可以写：重拾健身，你可以这样做计划
* 动画类产品可以写：如何做出活人感的动画
2. 先只做服务交付方，不做研发。类似上述我朋友提供翻译服务的方式。
3. 先依托垂直流量的平台做一个产品展示页，比如一些众筹网站，让感兴趣的用户留下联系方式。

这些方式中，最有价值的信号是：
是否有人愿意付费？
是否有人愿意留下联系方式？
是否有人愿意上传自己的材料？
这些需要用户花成本来完成，成本越高，则真需求的可能性越大。
## 总结
到这里，我就把找真需求的方法讲完了，尽管这一步我们还没有开始动手 coding，但对最后的结果至关重要，甚至是最重要的一步。
我们来总结一下今天讲三种方法：
* 第一，做自己需要的，且会反复、长期需要的；可以从自身出发，结合 Semrush、Ahrefs、Google 里的关键词分析得出市场空间和竞争格局，来确定要不要做。
* 第二，做别人需要的，且会真实付费买单的；我们通过几个体现真实付费数据的网站，可以调研出用户会为什么样的产品买单。
* 第三，跟风做热点，且热度过后仍然长期存在；我们通过区分抽象的趋势性热点还是具体的事件性热点，来判断热点是否值得做。
最后我们也简单讲述了几种验证需求的方式。
看完这一套方法后，你可以按照这个思路在日常生活中广泛涉猎。因为寻找需求不像是一次目的明确的旅程，而是在轻松的随机漫步中收获的惊喜与灵光一现。一旦你完成了这一步，那么接下来的商业路径就会清晰许多。
当然，你也需要做好心理准备，第一次的商业化之路总是充满艰辛与迷茫，尤其是初期你根本无法收集到足够的样本反馈。如果是这样，你不妨选择一个你眼下最看好的点子做起来，跟着我继续往前探索到下一讲，看看如何让这个点子被看见，让你收集到更多的样本反馈。
