- **业务问题与 MVP 边界**：人工专家解读耗时长、经验难复制，因此把专家服务拆成「上传画作 → 画面结构标定 → Lite 报告 → 报告内追问 → 历史记录」的 Web 链路；围绕「输入是什么、AI 能输出什么、什么情况下不能给确定结论、用户如何继续追问」定义方案边界，Lite / Pro 分层验证报告价值感与付费转化路径。

### Miro · 一镜一梳疗愈师端 AI 工作台（2026.09 - 至今）

**已实现并端到端跑通 · 尚未对外发布**（本人即目标用户：执业疗愈师） ｜ 独立产品负责人 + 技术推进者（工程实现以 AI 结对方式完成）

- **客户问题诊断**：已上线版本的三个硬伤不是「功能不够」，而是生成过程无审计、输出质量无评估、To C 形态风险与责任边界不清。据此把服务对象从「来访者直接使用」改为「疗愈师使用」，来访者不接触产品、交付物为 PDF 报告——先解决责任边界，再谈功能。
- **方案边界写进验收口径**：四层 Spec——设计层含「绝对不做」硬边界 → 控制层异常路径总表逐条预设处理规则 → 工程层红线优先、工具白名单与调用序列写死（序列之外一律禁止调用）→ 验收层先写可验证的量化指标与验收用例。设计先行共 3,600+ 行文档后才开始编码。
- **可靠性归规则、决策权归模型**：规则只做安全红线（危机信号命中直接转人工、不做兜底生成）、JSON 接口契约、生成后校验三件事；另把确定性几何问题从 AI 职责移出——图像矫正与三圈标记线由程序完成、疗愈师确认后定稿。
- **验收与可核验**：建成领域知识库（8 类文档 → 267 个结构化知识单元、10.2 万字符、23 个本体状态），报告引用全部走稳定规则 ID（颜色域 C / 组合模式 CP / 失衡模式 IM / 直断法 D / 状态 S），可逐条审计。已实测的两处：输入预处理六步全程序化，黄金集 **18/18 通过**、单张 ≤0.6 秒；报告问答在真实个案上 18 问实测——锚定 97.8%、相关 5.00、准确 4.83、边界标注 100%、安全越界 0 条、硬性断言 18/18 通过、延迟 P95 8.4 秒。
- **问答 Agent 按场景交付**：同一 Agent 按场景配置——「解读参谋」（专业、深、多视角，L1，不限轮次）与「应答准备」（通俗可转述、给可能性不给定论、附边界口径提醒，L2，≤15 轮）；助手永不直接面对来访者。6 个工具白名单 + 按 6 类问题各自写死的调用序列，序列外一律禁止调用；输出缺来源标注视为不完整、禁止输出。
- **主动交局限**：① 所有产品指标（采纳率 >70% / 编辑率 <30% / 问答使用率 >60% / 交付完成率 >80%）都是**目标值**，无实测值——未上线、无真实疗愈师使用数据；② 18 问是单份报告上的单 run 验证，跨个案泛化性未测，judge 为 LLM 评分、人工评审仍在进行中；③ 前端未建，暂无可交互 Demo；记忆模块与自动意图判别未做。④ 评测当天抓出的两类真实缺陷（模型吐非法 JSON、断言把合规免责误判为违规）已当天闭环修复。**这些是我主动说出来的，不是被问出来的。**
