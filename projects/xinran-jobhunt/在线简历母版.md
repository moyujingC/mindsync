【生意底子】7 年一线服务（保险 2 年 + 房产单边代理 5 年），把一套原本依赖个人经验的服务，做成了能复制的体系。

- **这套工作分三步**：**① 现场诊断**——客户访谈与真实需求诊断、预算与风险识别；**② 定制方案落地**——方案设计、谈判、合同与付款风控；**③ 沉淀成体系**——SOP、知识库、培训体系。
- **体系产出**：孵化 30+ 名独立经纪人，新人独立上岗周期从约 18 个月压缩到约 6 个月；我退出后体系仍在运转。
- **和做 AI 的关系**：前两步对应客户现场与方案交付，第三步就是我现在建 AI 领域知识库的那一套。

【AI 产品 0→1】近 2 年独立做 AI 产品，同一个方向做过三个版本——每一版都在解决上一版暴露出来的问题。

- **第一版（已上线运营）**：To C 曼陀罗解读产品「一镜一梳」；底层人工解读服务累计 **45 单真实付费**，验证了场景的付费意愿。
- **为什么推倒**：上线后判定它三个硬伤——结论无法追溯、好坏没有判据、责任边界不清。
- **第二版（未采用）**：仍没有自动评测，改一次要人工把案例重读一遍，成本不可接受。
- **第三版（当前）**：疗愈师端工作台，双 Agent（报告生成 + 报告问答）已端到端跑通；报告问答在真实个案上 18 问实测：回答有据可查 97.8%、安全越界 0 条、延迟 P95 8.4 秒。
- **做法**：先定义边界与验收标准，再进入实现——禁止表述清单、每个结论必须溯源到具体知识条目、不达标不出报告，三条都落成系统里真正执行的规则。
- **三个版本得出同一条结论**：**切入点要小、别先做 UI，验证要前置**——AI 项目不只验需求，还要先验技术栈可行性。

面向曼陀罗绘画解读场景的多模态 AI 产品。用户上传画作，系统通过图像理解、知识匹配与生成式 AI 输出参考性报告，主链路覆盖上传、画面结构标定、报告生成与报告内追问。产品曾上线并运营，后因判定其架构解决不了"结论可追溯、质量有判据、责任边界清晰"三个问题，推倒重做为 §4.2。

#### 项目职责

本人担任独立产品负责人与独立开发者，负责需求定义、MVP 范围、模型评测、生成链路设计、前后端实现、部署运维、安全边界与商业化路径。

- **先验证技术，再定方案**：用 11 个真实案例对比两种生成方式，确认一次成稿会丢失画面细节，改成"先描述画面、再逐项解读"的两段式。
- **给输出定判据**：每次改动都用 5 组固定案例回归，防止改坏；候选模型经稳定性评测后淘汰；两个模型都识别失败时返回保守结果，不强行猜测。
- **先划安全边界，再谈体验**：在问答功能里设了三条不可越过的线——不诊断、不承诺结果、不诱导依赖。

#### 项目业绩

- 完成从真实服务痛点到公网可体验产品的 0→1 上线。
- 两段式生成链路解决结构化输出丢失画面细节的问题，并成为后续版本的基础。
- 5 组标准测试用例支撑每次改动后的质量回归；稳定性评测淘汰不稳定候选模型。
- 建立失败降级与安全边界机制，控制过度解读与敏感场景越界风险。

### 4.2 Miro · 一镜一梳疗愈师端 AI 工作台（2026.09 - 至今）

#### 项目描述

Miro 是给疗愈师用的 AI 工作台：疗愈师上传来访者的曼陀罗画作，系统生成两版报告——给来访者看的干净版，和给疗愈师逐条核查的溯源版（每个结论标明来自哪条解读规则）。报告生成后，疗愈师可就报告继续提问，AI 参谋只依据报告与知识库回答，不越界。它是我主动推倒重做的第二版：上一版（已上线的 To C）暴露出结论无法追溯、质量无判据、责任边界不清三个问题，这一版把这三个问题解决在架构里，再写代码。

#### 项目职责

本人担任独立产品负责人与技术推进者，负责需求定义、架构分层、知识库设计、生成链路、评测与安全体系及全部验收设计；工程实现以 AI 结对方式完成。核心工作：

- **领域知识库从 0 建立**：把 8 类疗愈方法文档整理成 267 个结构化知识单元（10.2 万字符、23 个状态），每条带稳定编号——报告里每个结论都能追到具体条目，追不到就不许输出。
- **确定性环节交给程序**：图像矫正、裁切、圈界检测等 6 步预处理全部用代码实现（18 张测试图全过、单张 0.6 秒内），守住"不改画作内容"的底线；模型只做语义判断，程序只做验证和标注。
- **模型分工按实测结果调整**：文字 DeepSeek、视觉 Kimi。颜色命名从视觉模型挪给文本模型后，单次生成从约 7 分钟降到约 1.75 分钟，边界色反而更准。
- **安全与评测先于功能**：两级安全护栏共 17 项检查，任一红线触发即禁止发布；18 问评测当天抓出 2 个真实缺陷并当天修复。
- **调度层保持克制**：主 Agent 只负责路由与失败兜底，不引入第三方 Agent 框架；评估过引入框架的收益后判定 MVP 不需要，并写下何时才该引入的触发条件。

#### 项目业绩

- 从 0 建成领域知识库（267 个结构化单元、23 个状态、稳定编号体系），报告结论可逐条审计。
- 图像预处理 6 步全程序化：18/18 通过、单张 ≤0.6 秒、pytest 12 项全过。
- 报告生成端到端跑通，一次出两版（干净版 / 溯源版）；端到端耗时从约 7 分钟优化到约 1.75 分钟。
- 报告问答 18 问实测：回答有据可查 97.8%、切题 5.00、准确 4.83、安全越界 0 条、硬性检查 18/18 通过、延迟 P95 8.4 秒。
- 评测当天抓出并闭环 2 个真实缺陷（非法 JSON 容错、合规免责句误判）。

## 七、ATS 与"没有大厂背景"的对策

### 7.1 大厂背景怎么体现（三条，都不用撒谎）

1. **客户品牌代替公司品牌**：早期项目写**发行商**——2K Games、Activision。HR 和 ATS 都认大厂名，这是最强的一条。
2. **公司定性短语**：昱泉国际 = "当时游戏行业头部企业"；维塔士 = "全球头部游戏开发服务商"。
3. **项目量级词**：3A、跨平台（PS3 / Xbox 360 / Wii）、全球发行、主机游戏。

**面试话术**：「我早期两家是那个年代的头部——昱泉是当时国内游戏行业的头部企业，维塔士现在仍是全球头部游戏开发服务商，做的是 2K、Activision 的项目。行业后来整体下行，不是公司不行。」

### 7.2 ATS 关键词对策

**2026 市场现状（来源：4 篇 Agent PM 招聘拆解 + 作业帮 Agent PM 岗 40–70k/月 JD）**

- 核心已从 **workflow 转向 Agent**；Prompt 工程、Loop 工程不再是高薪岗重点，重心是**智能体体系化设计**。
- Agent ≈ **行为准则 + 工具 / 记忆 / 知识库 / Skill**。
- JD 四大模块：① 主 / 子 Agent 分工 ② 知识供给体系 ③ 工具与权限设计 ④ **不确定性评估体系**（评估从"功能是否正确"转向"行为是否得体"）。

**关键词对照（只写真实具备的）**

| Agent / 多智能体 | 双 Agent（报告生成 + 报告问答），主 Agent 路由 + 兜底 | ✅ |

### 7.4 会过期的状态不写进对外材料

简历 / 附件 / 打招呼语是**快照**，产品进度是**流水**，两者绑定必然出错。

- **不写**：当前是否在线、是否已发布、前端是否建好、评测是否复测完成、有无真实用户。
- **只写**：成就性表述（"已上线并运营过""已实现并端到端跑通"）+ 可核验数字。
- **改为**：进度与局限只作**面试口径**口头交代，被问到时如实说。

### 7.5 表达规则

- **金字塔**：结论先行 → 3–6 条平行条目 → 数字落在它支撑的那条里。**一个长句里出现两个以上分号或破折号，就必须拆条目。判定：作者本人重读一遍也觉得累，就是没写对。**
- **提炼**：素材 ≠ 简历内容。①背景还是成果？②删了它，判断会不会变？③需要读者懂我的行业才看得懂吗？
- **不生造行业词**：去 AI 圈的文章和 JD 里搜，别人是不是这么说的。
- **不用自媒体口吻**：辩论式"不是 A 而是 B"、未落地的比喻、口语化收尾。
- **不堆不会的词**：keyword stuffing 面试当场穿帮。记忆 / MCP 未做，不写。
- **创业经历可以写，写成能力证据**：可以提创业、创办公司、独立带团队、从 0 到 1、自己扛完整闭环；这些是"经历复合、能力综合"的硬证据。定位句仍以岗位能力为主（如"工程师出身的 AI 产品经理"），不以"我是创业者"作自我介绍的开头；每段材料末尾保留"回团队"信号，对冲稳定性疑虑。
