## 1. 项目是什么

`馨冉求职` 关注的是一个现实执行问题：

- 如何围绕当前求职目标，持续产出高质量材料。
- 如何维护适合当前方向的简历、作品集和表达素材。
- 如何把求职过程沉淀成可交接、可追踪的 artifact。

它不是泛化职业产品定义，也不默认承担对外产品化目标。

## 2. 当前阶段

当前阶段是 **2026-08 投递包收束与定向投递**。

本轮目标：

- 城市：上海。
- 薪资：不写进任何材料正文；只在平台字段或私下沟通中处理。
- 第一主攻：FDE / AI 解决方案工程师。
- 第二主攻：AI 产品经理，限定为 AI Builder / 产品工程型 PM / 中小团队产品负责人。
- 机会型补充：AI 应用工程师 / 大模型应用工程师 / Agent 应用工程师。
- 相邻叙事：AI 转型咨询顾问，仅作为 FDE / 猎头扩展方向，不作为第一主线。

当前工作重点不是继续扩张版本，而是：**收束入口、冻结旧口径、形成可投递附件版，并按周同步材料。**

## 4. 同步规则

事实或口径变化时，按固定顺序改：

1. 先更新 [职业经历全量报告](职业经历全量报告.md)。
2. 如果影响岗位论点、证据排序或选岗口径，再更新 [三岗位认知卡](三岗位认知卡.md)。
3. 如果影响 BOSS 在线字段，再同步 [总在线简历-BOSS版](总在线简历-BOSS版.md)。
4. 如果影响附件投递，再同步受影响的 [工程版](崔兴-AI应用工程师简历.md) / [FDE 版](崔兴-FDE-AI解决方案工程师简历.md) / [产品版](崔兴-AI产品经理简历.md)。
5. 如果只影响面试表达，更新自我介绍、问答或作品集，不反向污染事实源。

不能在某一份简历里单独发明项目事实。

## 5. JD 数据库

当前项目在仓库内维护 `JD 数据库`，作为岗位输入层使用：

- [JD 数据库说明](jd-database/README.md)
- [JD 数据库总索引](jd-database/index.yaml)
- [JD 数据库导航入口](delivery/2026-06-09-JD数据库导航入口.md)

这套数据库的作用不是维护招聘 App 操作流水，而是：

- 把岗位截图 / 文本整理成结构化 JD 样本。
- 记录 BOSS 竞争力分析。
- 支撑横向分析、分桶判断和简历优化决策。

单条 JD 不直接改主简历；累积到共性信号后再进入材料迭代。
