- **知识供给按场景选，不是套 RAG**：从 0 建成 267 个结构化领域知识单元（10.2 万字符、23 个状态），每条带稳定编号；报告里每个结论必须挂到具体条目，挂不上就不许输出，因此报告可逐条审计。RAG 方案已设计，MVP 阶段按场景选择全量注入。

- **工具与权限做成硬约束**：6 个工具白名单，调用序列按问题类型写死，序列外一律禁止调用——Agent 最容易出事故的地方，我不交给 prompt 自觉。
- **从"功能是否正确"管到"行为是否得体"**：两级安全护栏共 17 项检查，任一红线触发即禁发；不诊断、不承诺、不诱导依赖全部规则化，输出侧拦截 + 输入侧风险提醒双侧覆盖。确定性的活（图像矫正、圈界检测）全部交给程序，模型只做语义判断，程序只做验证和标注。

### 一镜一梳 To C 版 · 曼陀罗绘画 AI 解读产品（2025.01 - 至今）

多模态 AI 产品，来自一线服务的真实痛点：人工解读耗时长、质量依赖个人状态、经验难以复制。用户上传曼陀罗画作，系统经图像理解、知识匹配与生成式 AI 输出参考性报告。**已上线并运营过**，以内测兑换码模式运行；底层人工解读服务已有 45 单真实付费。

**职责**：独立产品负责人与独立开发者——需求定义、MVP 范围、模型评测、生成链路设计、前后端实现、部署运维、安全边界与商业化路径。

**关键工作与业绩**

- **链路**：React / Vite + FastAPI + 腾讯云 COS 私有存储 + 签名 URL + 视觉模型 + 文本模型 + 降级兜底；"视觉草稿 → 议题报告"两阶段链路已接入线上主链。
- **生成方式**：先输出自然语言画面事实、再按议题推理——用 11 个完整案例做 A/B 对照，证实直接输出结构化 JSON 会丢失画面细节，故改两段式。
- **失败降级与安全边界**：两个模型都识别失败时返回保守默认结果；报告内追问限定为报告陪读，不做诊断、不承诺治疗、不诱导依赖。
- **质量回归**：9 图 × 3 轮稳定性评测淘汰不稳定候选模型，5 组标准测试用例支撑每次改动后的回归验证。
- **主动推倒重做**：判定上一版结论无法追溯、质量无判据、责任边界不清，启动 Miro 重做（见下）。

> 与疗愈师端工作台同名不同形态，对外必须带区分语（To C 版 / 疗愈师端工作台）。

### Miro · 一镜一梳疗愈师端 AI 工作台（2026.09 - 至今）

给疗愈师用的 AI 工作台：疗愈师上传来访者的曼陀罗画作，系统生成两版报告——给来访者的干净版、给疗愈师逐条核查的溯源版（每个结论标明来自哪条解读规则）；报告生成后疗愈师可继续追问，AI 参谋只依据报告与知识库回答，不越界。**已实现并端到端跑通**，本人即目标用户（执业疗愈师）。

**职责**：独立产品负责人与技术推进者——需求定义、架构分层、知识库设计、生成链路、评测与安全体系及全部验收设计；工程实现以 AI 结对方式完成。

**关键工作与业绩**

- **领域知识库从 0 建立**：把 8 类疗愈方法文档整理成 267 个结构化知识单元（10.2 万字符、23 个状态），每条带稳定编号——报告里每个结论都能追到具体条目，追不到就不许输出，报告可逐条审计。
- **确定性环节交给程序**：图像矫正、裁切、圈界检测 6 步预处理全部代码实现，18 张测试图全过、单张 ≤0.6 秒、pytest 12 项全过；守住"不改画作内容"的底线，模型只做语义判断，程序只做验证和标注。
- **模型分工按实测调整**：文本 DeepSeek、视觉 Kimi。颜色命名从视觉模型挪给文本模型后，单次生成从约 7 分钟降到约 1.75 分钟，边界色反而更准。
- **工具与权限硬约束**：报告问答 6 个工具（report_search / state_query / knowledge_retrieve / reason_chain / five_elements_reason / intervention_query）按 6 类问题各自写死调用序列，序列外一律禁止调用。
- **安全与评测先于功能**：两级安全护栏共 17 项检查，任一红线触发即禁止发布；18 问评测当天抓出 2 个真实缺陷并当天修复。
- **调度层保持克制**：主 Agent 只做路由与失败兜底，不引入第三方 Agent 框架；评估过引入框架的收益后判定 MVP 不需要，并写下何时才该引入的触发条件。
- **评测结果（真实个案 18 问）**：回答有据可查 97.8%、切题 5.00、准确 4.83、安全越界 0 条、硬性检查 18/18 通过、延迟 P95 8.4 秒。
