## 3. 曼陀罗绘画 AI 解读产品

### 3.1 来源文件

- `projects/aimandala/docs/specs/ToC-MVP-产品规范.md`

### 3.2 当前状态

曼陀罗绘画 AI 解读产品 / 曼陀罗绘画 AI 解读产品已经从“想法 / 即将上线”推进为一条更清晰的 To C Web MVP 主线。

当前 MVP 只覆盖 To C 用户主路径：

1. 用户进入手机端 Web 产品。
2. 用户上传曼陀罗图片，并补充少量必要描述。
3. 系统生成 Lite 报告。
4. 用户查看 Lite 报告。
5. 用户可从 Lite 报告入口升级 Pro。
6. Pro 支付成功后查看 Pro 权益内容。
7. 用户可围绕当前报告向曼曼继续追问。
8. 用户可查看历史记录。

当前产品层级：

- 一镜 Lite 版：面向首次体验用户，当前入口价格 9.9 元。
- 一梳 Pro 版：只能从 Lite 后升级，当前升级价 29 元，不提供独立购买入口。

### 3.4 曼陀罗解读智能体技术选型 / 工作流亮点

新版曼陀罗解读智能体采用“端到端 + 提示词缓存 + 可复用视觉基准”的主线。

当前正式生产默认链路为 `two_pass_e2e`：

1. Vision Pass：基于用户原画作、三圈标记图和基础知识包生成可复用视觉基准 `visual_draft`。
2. Reasoning Pass：基于视觉基准、财富 prompt pack、输出规范和用户意图生成 Lite / Pro 报告。

这个设计的价值：

- 同一幅画只有一个画作级视觉基准。
- 未来同一画作生成多个议题报告时，可以复用同一视觉基准。
- 避免不同议题报告对同一画作的视觉观察互相矛盾。
- 保留报告的带读感和流派感，而不是变成系统检测结果。

Prompt pack 设计原则：

- 稳定前缀版本化。
- 用户图片、用户问题、本次视觉草稿不进入稳定前缀。
- 通过顺序固定提高缓存命中率。
- 质量门检查是否越界、是否保留视觉证据和三圈带读。

### 3.5 曼曼 avatar / 报告追问边界

曼曼适合表达为：

> Aimandala 的报告陪读与追问 avatar，负责帮助用户读懂本次曼陀罗报告，并在本次画作与本次报告范围内回答追问。

产品边界：

- 只围绕本次画作和本次报告。
- 不做长期陪伴。
- 不做心理咨询。
- 不做财务或人生决策。
- Persona 负责表达层，不能替代事实观察、安全判断和质量门。

### 3.6 适合证明的能力

- 从一线服务痛点中定义 AI 产品。
- 控制 MVP 范围。
- 设计复杂高信任场景的 AI 输出边界。
- 设计报告生成 agent 工作流。
- 用质量门和安全边界控制 AI 输出风险。
- 在感性体验和工程可验证之间做取舍。

### 3.7 不可夸大边界

不要写：

- 已大规模上线。
- 已服务大量用户。
- 已完成完整商业化验证。
- 医疗诊断 / 心理治疗 / 心理咨询产品。
- 完整 To B / Studio / App 产品已经交付。

推荐边界写法：

> Web MVP 主线 / 上线准备 / 可验证产品闭环 / 报告链路重构中。

## 4. 一人公司的 AI 工作系统

### 4.1 来源文件

- `AGENTS.md`
- `COMPANY.md`
- `MONOREPO.md`
- `company/knowledge-base/system/一人公司的 AI 工作系统-设计机制分析.md`

### 4.2 当前状态

这个系统是公司内核 + 多项目工作区 Monorepo，不是单一应用仓库。

它同时承载：

- 公司治理
- 角色定义
- 项目入口
- 共享工具
- 长期知识库

该系统与运行时环境的关系：

- 该系统：治理源、文档源、实现源、知识源。
- 运行时环境：运行时控制面、任务派发与回写面、执行状态面。

### 4.3 可公开表达

可以写：

> 自建 一人公司的 AI 工作系统，以 Monorepo 管理公司治理、项目入口、角色定义、知识库、共享工具和阶段 artifact，支撑 AI 产品、研究、内容和求职材料等多项目并行。

更克制写法：

> 搭建自用 AI 工作系统 一人公司的 AI 工作系统，用文档即系统的方式管理多项目、角色分工、知识沉淀和任务流转，支撑 AI 产品和个人转型项目持续推进。

### 4.4 系统结构亮点

系统采用五层结构：

1. `agents/`：角色定义，回答“谁负责做什么”。
2. `company/`：公司治理规则、注册表、蓝图、公司级入口。
3. `projects/`：项目工作区、项目实现、项目级文档。
4. `shared/`：共享脚本、模板和跨项目工具。
5. `company/knowledge-base/`：长期复用知识沉淀。

它解决的问题：

- 信息不再散落在聊天记录、运行时和历史仓库。
- Agent 进入项目时有稳定入口。
- 项目从 spec、task、QA 到 delivery 有可追踪 artifact。
- 多项目可以在同一系统内保持边界和状态。

### 4.5 适合证明的能力

- 系统化思维。
- AI 协作流程设计。
- 知识治理。
- 多项目管理。
- 文档即系统。
- 把模糊任务转成可分派、可验证、可回写的工作流。

### 4.6 不可夸大边界

不要写：

- 成熟商业化 SaaS。
- 企业级多人协作平台。
- 已销售给客户的 AI Agent 平台。
- 完全自动化公司。

推荐边界写法：

> 自用 AI 工作系统 / Monorepo 实践 / 一人公司操作系统原型。
