本文定义 `馨冉求职` 的材料迭代闭环。它不替代 [投递期材料迭代工作流](投递期材料迭代工作流.md)，而是在本轮简历评估后，把附件简历、平台在线简历、作品集、面试逐字稿、JD 数据库和面试反馈串成一个系统。

## 1. 系统目标

求职材料不再按“临时改一份简历”运行，而是按以下闭环迭代：

> JD / HR / 猎头 / 面试反馈 / 新证据 → 触发判断 → 新建日期化阶段报告并冻结基线 → 确定允许与禁止改动范围 → 事实源 → 岗位认知卡 → 公共表达原则 → 平台在线简历母版 + 分岗位附件简历 → 作品集证据 / 面试逐字稿 → 改后复评 → QA → 关闭归档。

阶段评估是输入与材料修改之间的决策层。它汇总当前信号、质量判断和改写范围，但不成为事实源或投递材料。

每次改动先判断影响层级，避免：

- 为单条 JD 大改全套材料。
- 在某一份简历里单独发明事实。
- 把面试口播问题误改成事实问题。
- 把作品集详情塞回简历首屏。
- 因焦虑继续扩张版本。

## 2. 材料层级

| 层级 | 文件 | 职责 | 何时更新 |
|---|---|---|---|
| 事实层 | [职业经历全量报告](职业经历全量报告.md) | 事实、数字、时间线、口径唯一来源 | 出现新事实或旧事实校准 |
| 论点层 | [三岗位认知卡](三岗位认知卡.md) | 三岗位能力主张和证据排序 | 岗位策略或证据排序变化 |
| 公共规则层 | [求职材料公共问题与改写原则](求职材料公共问题与改写原则.md) | 所有材料共享的表达原则 | 多份材料出现同类问题 |
| 附件简历层 | 工程版 / FDE 版 / 产品版 | 分岗位约面材料 | 阶段性共性信号触发 |
| 平台入口层 | [在线简历母版](在线简历母版.md) | BOSS / 猎聘共用在线简历内容源，承接平台检索、系统过筛、HR 初筛和多职位统一画像 | 平台反馈、系统筛选信号或方向优先级变化 |
| 作品集层 | [个人职业叙事作品集网站](个人职业叙事作品集网站/README.md) | 项目证据、截图、详情、案例 | 面试追问缺证据 |
| 面试表达层 | [面试逐字稿打磨系统](面试逐字稿打磨系统.md)、[三岗位2分钟自我介绍](三岗位2分钟自我介绍.md) | 开场、追问、FAQ、逐字稿 | 口播卡住或面试反馈出现 |
| 反馈输入层 | JD 数据库 / delivery | JD、HR、猎头、面试反馈和新证据 | 每次值得复用的输入出现 |
| 阶段评估层 | `delivery/YYYY-MM-DD-求职材料阶段性评估.md` | 冻结基线、汇总质量判断、确定改写范围、记录改后复评和残余风险 | 达到阶段评估触发条件时新建；同轮修改完成后回写 |

阶段评估层不替代事实层。报告发现事实变化时，必须先更新职业经历全量报告，再按层级同步。

## 3. 输入分类与处理

### 3.1 单条 JD

默认不改主简历。只做：

1. 判方向：工程版、FDE 版、产品版。
2. 判断是否值得定制。
3. 如需定制，最多改标题、个人优势前 2-3 行、一个项目 bullet 或项目排序。

### 3.2 高频 JD 信号

3-5 条以上 JD 反复出现同类要求时，进入阶段性材料迭代。

常见信号：

- Agent / Workflow / Multi-Agent。
- RAG / 知识库 / 数据治理。
- PoC / MVP / Demo / 原型验证。
- 客户现场 / 方案设计 / 交付。
- 评测 / Guardrails / 安全边界。
- 培训赋能 / SOP / 组织推广。

### 3.3 HR / 猎头反馈

先判断反馈属于哪类：

| 反馈 | 处理 |
|---|---|
| 看不懂岗位定位 | 改 BOSS 首屏或附件简历开头 |
| 质疑经历跨度 | 改公共主线和面试 FAQ |
| 质疑商业化 | 改商业化口径，补数据或降级为内测验证 |
| 质疑技术深度 | 补工程版技术断面和面试 FAQ |
| 质疑客户交付 | 补 FDE 版 PoC / MVP / 验收表达 |
| 对某项目很感兴趣 | 补作品集详情页和项目深挖稿 |

### 3.4 面试反馈

每次面试后至少记录：

1. 对方最关心什么。
2. 哪段表达有效，哪段卡住。
3. 哪份材料需要改。

处理原则：

- 只是口播卡住：改面试逐字稿。
- 缺项目证据：补作品集。
- 简历表达误导：改对应简历。
- 事实不清或数字更新：先改事实源。
- 岗位明显错配：记录，不改材料。

## 4. 阶段评估生命周期

### 4.1 触发条件

满足以下任一情况时，进入阶段评估，而不是直接大改材料：

- 3–5 条以上 JD 暴露同一材料缺口，或累计 10 个同类 JD。
- 累计 5 次有效 HR、猎头或面试沟通。
- 当前主攻方向变化。
- 新增真实用户、运行数据、客户试点、付费、PR、测试或评测证据。
- 多位招聘方连续误判同一能力或质疑同一事实。
- 上一轮 P0 / P1 动作完成，需要改后复评。

单条 JD、单个未回复和纯审美偏好不触发全套评估。

### 4.2 报告状态

| 状态 | 含义 | 进入下一状态的条件 |
|---|---|---|
| `working` | 报告形成中，正在核对输入、对象或结论 | 基线和改写范围已冻结 |
| `current` | 当前阶段的执行依据 | 本轮允许的材料修改完成 |
| `in_review` | 改写已完成，等待改后复评与 QA | QA 通过并记录残余风险 |
| `historical-reference` | 本轮关闭，或已被下一份日期化报告替代 | 不再滚动修改，只供追溯 |

状态只使用 [DOCS_GOVERNANCE](../../DOCS_GOVERNANCE.md) 已定义的治理状态，不新增 `verifying`、`completed` 等私有状态。

### 4.3 同轮执行规则

1. 新建 `delivery/YYYY-MM-DD-求职材料阶段性评估.md`，记录评估对象、输入、方法和改前基线。
2. 在报告内明确 P0 / P1 / P2、影响层级、目标文件、允许改动和禁止改动范围。
3. 按事实源 → 认知卡 → 公共规则 → 在线母版 / 附件简历 → 作品集 / 面试材料执行。
4. 回到同一报告记录改后分数、已关闭问题、未关闭问题和残余风险。
5. 在 `qa/` 新建或更新同轮 QA，检查 active 对象、事实追溯、链接、状态和同步完整性。
6. QA 通过后转为 `historical-reference`；下一轮必须新建日期文件。

## 5. 修改决策树

```text
出现新输入
  ↓
是否达到阶段评估触发条件？
  是 → 新建日期化阶段报告并冻结基线 → 确定允许与禁止改动范围
  否 ↓
是否是事实变化？
  是 → 职业经历全量报告 → 影响论点则同步认知卡 → 同步材料
  否 ↓
是否影响当前投递动作？
  是 → 最多定制 3 处
  否 ↓
是否影响面试表达？
  是 → 面试逐字稿 / FAQ / 作品集
  否 → 记录到 JD 数据库或 delivery，暂不改
```

## 6. 本轮评估后的系统改造任务

### 6.1 公共部分

优先执行 [求职材料公共问题与改写原则](求职材料公共问题与改写原则.md)：

- 删除正式简历内部备注。
- 校验时间线。
- 确认模型名称。
- 统一“一镜一梳”的通用表达。
- 降级商业化强表述。
- 压缩 MindSync 个人系统表达。

### 6.2 分岗位简历

上一轮分岗位“简历评估与改写建议”已完成支撑公共收束的阶段性用途，并归档到 [2026-08-06 简历评估与改写建议归档](delivery/2026-08-06-简历评估与改写建议归档/README.md)。

当前不再直接按这些评估文档滚动修改材料；后续若要重新评估某一份简历，应基于当轮 JD、反馈和材料状态新建评估文档。

### 6.3 面试逐字稿

按 [面试逐字稿打磨系统](面试逐字稿打磨系统.md) 拆成：

- 15 秒一句话版。
- 45 秒电话版。
- 90 秒面试版。
- 2 分钟深聊版。
- 风险 FAQ。
- 项目深挖逐字稿。

优先做 FDE 版，因为当前第一主攻是 FDE / AI 解决方案工程师。

## 7. 每周节奏

### 7.1 日常投递

- 不为每条 JD 大改材料。
- 只使用当前 active 简历。
- 投递前执行 60 秒红线检查。
- 有复用价值的 JD 和反馈进入数据库或 delivery。

### 7.2 周评

每周做一次：

1. 汇总 JD 高频词、HR / 猎头 / 面试反馈和新证据。
2. 对照触发条件判断是否需要阶段评估。
3. 如触发，先新建日期化阶段报告并冻结基线，不直接修改全套材料。
4. 在报告中确定允许改动、禁止改动、P0 / P1 / P2 和目标文件。
5. 按层级完成同步后，回到报告记录改后复评，并执行同轮 QA。
6. 检查作品集是否缺承接页，更新面试 FAQ。
7. 冻结下一周主攻方向和材料版本。

## 8. 版本控制原则

- 不继续扩张新的简历版本。
- 当前只维护工程版、FDE 版、产品版和 BOSS 唯一在线版。
- 评估文档是工作依据，不直接投递。
- 面试逐字稿是表达训练材料，不作为简历事实源。
- 作品集承接详情，不反向塞爆简历。

## 9. 完成定义

本系统跑顺的标志：

1. 所有正式投递简历无内部备注。
2. 三份简历共享同一职业主线，但岗位表达不同。
3. BOSS 首屏短、清楚、方向不发散。
4. 面试开场有 45 秒和 90 秒版本，不再只背 2 分钟稿。
5. 常见质疑有 FAQ，而不是塞进开场介绍。
6. 每次面试后能明确判断该改事实源、简历、作品集还是逐字稿。
7. 每周只基于共性信号改材料，不因单条 JD 频繁重写。
