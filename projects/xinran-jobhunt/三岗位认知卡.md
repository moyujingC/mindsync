## 0. 三张卡共用的最新岗位要求（v3 新增，2026-09-16）

### 0.1 门槛已经变了

招聘市场从"你会不会用 AI"转向"你能不能讲清楚一个 Agent 项目"。2026 春节后，没有 Agent 项目求职难度明显上升；普通 demo、内部小工具、套一层大模型 API 的玩具项目已经打动不了面试官，要看**真实场景、复杂链路、评估指标、失败处理**。

### 0.2 Agent 的定义方式：可调配的资源

**Agent ≈ 一套行为准则 + 可调用的工具、记忆、知识库、Skill。** 不同业务场景对四类资源的权重需求完全不同，直接决定岗位的能力要求差异。写项目时先说清"这个 Agent 能调动什么资源"，比罗列架构名词更能区分层次。Skill 是串联四类资源的调度中枢。

### 0.3 2026 年的能力重心迁移

| 维度 | 2023-2024 常见重点 | 2026 高薪岗位重点 | 本人的对应情况 |
| --- | --- | --- | --- |
| 编排 | 简单多 Agent 协同 | 复杂多智能体调度 | ❌ 无事实对应，是当前最大结构性缺口 |
| 检索 | 基础 RAG | 复杂知识管理体系 | ✅ 267 个结构化单元、23 个本体状态、全量灌与检索的取舍决策 |
| 新增重点 | — | 安全权限、全流程评测 | ✅ 安全：L1/L2 两级 + 上线前安全对抗集硬门禁（L1 共 7 项 + L2 共 10 项，任一红禁发）+ 危机信号双侧覆盖（输出侧拦截 + 输入侧来访者原话触发风险提醒）。✅ 评测：黄金集 F1 0.821 + 评估治理六项（见 0.5）。❌ 仍缺：权限分级与人审产品化 |
| 已降权 | 提示词工程、Loop 工程 | 不再是核心考察点 | 简历不必再铺 Prompt 相关表述 |

### 0.4 企业级 Agent 的八个硬性条件（FDE 与工程师卡的边界判据）

业务侧：业务闭环、系统集成、流程嵌入、角色清晰（人是审核、判定与责任主体，Agent 是执行器）。
工程侧：安全可控、成本可算、效果可评估、能力可复制。

本人当前覆盖：业务闭环（人工服务已有付费成交）、安全可控（安全红线 + 失败降级）、效果可评估（黄金集 F1 0.821）、角色清晰（知识治理闭环由疗愈师审核入库）、能力可复制（房产 SOP 与培训体系）。未覆盖：系统集成、流程嵌入、权限分级、成本可算（仅有按份计费设计，无真实成本数据）。

### 0.5 三模块：只要深写 2 个就合格

| 模块 | 市场合格标准 | 本人事实 |
| --- | --- | --- |
| 知识库 | 强业务专属 + 生产 / 处理 / 更新 / 复盘四环节 | ✅ 8 类文档 → 267 单元 → 23 本体状态；知识治理闭环覆盖更新与审核（生产与复盘环节待补表述） |
| 评测 | 分层：知识库检索 / 记忆提取调用 / 端到端业务效果；指标精准定义 | ✅ 黄金集 11 例 F1 0.821、章节完整 8/8、15.6k token/份（口径：AI 预标注基线，人工复验中）。**v3.1 补强——治理层已建**：judge 独立（裁判≠被测模型）、可复现配置快照（模型版本/温度/次数/种子/知识库 commit/提示词版本）、常规题与安全题分桶、指标期望值变更留痕（防改考卷）、调试污染案例排除（防污染）、judge 人工一致率 ≥80% 才采信 |

### 0.6 三张卡共同的两条禁忌（v3 新增）

1. **可套用即不合格**：把项目名与业务名词换成任意其他场景后描述仍成立的，属泛化表述，必须删改。已按此复检出现有简历，识别出 5 条需删改（见 [基线评估](delivery/2026-09-15-简历评分标准v2-基线评估.md) 4.5）。
2. **提交次数不写进简历**：提交数只证明投入强度，不证明能力；改用可核验物证（合入 PR 编号、可访问产品、评测集与 A/B 记录、自动化复盘机制）。详见各卡第 7 节。
3. **项目阶段如实表达（v3.1）**：Miro（一镜一梳）当前为 **MVP 探索期——设计定稿 + 知识库建成 + 首跑基线已建立**，仓库无实现代码、未上线。可写"设计 / 知识库 / 评测基线"，不可写"已上线""已交付""已有客户"。已上线的是另一个项目（一镜一梳 To C），两者不得混写。被追问时直接说："设计已到可直接编码的粒度，下一步是实现与试点，我不把设计说成上线。"
4. **中文名撞车必须带区分语（v3.1）**：已上线的 To C 产品叫「一镜一梳」（web.jingshu.cc）；Miro 项目中文名同为「一镜一梳」，是**疗愈师端 AI 工作台、未上线**。口头与书面一律区分为「一镜一梳（web.jingshu.cc）」与「Miro / 一镜一梳疗愈师端工作台」。不区分会两边都出错。

### 0.7 岗位权重：不做通用简历

不同企业的 Agent 岗位能力要求差异明显。**投递前必须针对目标岗位做能力维度权重分析，突出 1-2 项与岗位强相关的核心优势**，不做大而全的通用简历。三张卡的"能力主张排序"就是权重分析的输入，投递时按 JD 重新排序，不重写事实。

## 认知卡一：AI 应用工程师 / 大模型应用工程师

1. **岗位本质**：让 AI 应用在真实环境里稳定产生价值。课程印证：Agent 岗的筛选入口已从"会不会用 AI"变成"能不能讲清楚一个 Agent 项目的完整链路"。
2. **能力主张（按重要性排序；v2 已定稿）**：

   * ① AI 原生开发全流程（SDD / Harness Engineering）：需求拆解 → 规格 → AI 生成引导 → 代码审查 → 调试 → 部署排障

   * ② 评估驱动的质量闭环：评测集建设、模型选型与 A/B、失败样本归因、持续迭代

   * ③ 生产级防御工程意识：终止与降级硬边界、安全边界、可观测与 trace、成本意识

   * ④ 快速进入陌生领域并产出（学习力）

3. **招聘方的雷**（2026-08-05 本人确认口径不变）：手写代码能力 → 不回避，正面框定：早年多年手写经验（C++/Lua/C#/Obj-C/Java/Qt），需要时稍作温习即可手写；现在用 AI 原生开发是因为没必要手写，不是不能手写。只投自己也在用 AI coding 的团队。
4. **差异化优势**：真实上线且可访问的产品、可核验的工程物证（5 个合入 PR + 评测集与 A/B 记录）、方法论来自真实失败（v1 报废，天然契合 v0→v1→v2 叙事）、懂业务懂客户（纯工程师没有）。**不使用提交次数作为证据**（详见第 7 节）。
5. **不争**：算法 / 模型训练深度、大厂工程背书、现场手写算法题。
6. **证据映射**（v3 补充 Miro 证据，标注【新】）：

   * ① ← v1（Lovable，文档过时致 AI 生成出错）报废 → SDD/Harness 重建；MindSync 六阶段门

   * ② ← 双模型选型决策（GLM 经 9 图 × 3 轮稳定性评测落选）；golden case 评测集；两段式链路 A/B 对照。【新】黄金集 11 例首跑：状态命中 F1 0.821（P 83.6% / R 80.9%）、章节完整 8/8、15.6k token/份、48.7 秒/份、0 错误（口径：AI 预标注基线，疗愈师复验进行中）。【v3.1】**评估治理六项**：judge 独立、可复现配置快照、安全题分桶、指标变更留痕、调试污染排除、judge 人工一致率门槛 ≥80%——把"跑过分"升级为"分数可信"

   * ③ ← 双失败降级为低置信度默认三圈；追问安全拦截；三台 CVM 分工 + nightly smoke + auto-repair；中间产物留痕。【新】规则三件套：安全红线（危机信号拦截、越界表述）、JSON 接口契约、生成后校验（核心状态齐全、五行矛盾检测）——决策权归 LLM、可靠性归规则，两边不重叠。【v3.1】**把确定性工作从 LLM 手里拿出来的三次判断**：① 三圈划分移出 AI 职责，改由程序画标记线 + 疗愈师确认（D-060）；② 圈界从固定 1/3、2/3 等分改为径向分布分析自动提议，避免切割图案组，固定比例仅兜底，提议参数留存可审计（D-061）；③ 色名长尾用 R-AI-003 归一化，原始色名与归一化目标并存落盘，未命中走"候选 → 标注暂无规则 → 缺口队列"兜底链，不硬编含义（D-056/057）

   * ④ ← 疗愈领域 0→1（知识库三次重构 + 产品上线）

7. **面试表达口径**：

   * 项目名格式：业务场景 + Agent 核心能力 + 系统定位。

   * 每条贡献写法：关键技术词汇 + 优化动作 + 数据（绝对值 + 相对值），每个数字都能讲清统计口径。

   * 叙事主线三段式（2026-08-05 本人确认）：阶段一 Lovable v1 报废 → 阶段二 ai-mandala 独立仓两周重写 → 阶段三 迁入 monorepo 治理升级。定位：每一步都在主动提高工程标准。

   * 【v3 新增·执行机制口径】"workflow 外壳 + Agent 内核"：8 章生成是确定性 workflow（步骤固定、无循环、无工具调用），质量把关处用反思循环——LLM 以独立审核者身份给出具体修改指令，生成者带指令定向重写，≤2 轮。**判据：重试是工程容错，反思才是智能。**

   * 【v3 新增·取舍口径】知识供给用全量灌而非检索：知识库 10.2 万字符在模型窗口内，且解读属强整体性任务、检索切碎伤质量；检索保留为规模开关（超约 20 万字符时启用粗筛子集 + 子集全量灌）。**"什么时候该检索由知识库规模数据决定，不是架构洁癖。"**

   * 禁忌：不写无法解释口径的数字；技术词只写用过且能讲清"解决了什么问题"的；**不写提交次数**；**不讲"我的系统是 Agent"而不说清哪部分是 workflow**。

8. **当前缺口（v3，禁止包装）**：

   * 多智能体调度：无产品侧事实，不得包装。
   * 记忆与上下文管理：无分层、筛选、影响输出的设计表述。

   * 反思循环、全量灌改造等 Miro 待实现项：只有决策与工程现状，不得写成已完成。

## 认知卡二：FDE / AI 解决方案工程师

1. **岗位本质**（课程定义）：嵌入客户现场、主动交付有价值结果的产品探索者。两条硬标准：对**可衡量的业务结果**负责；**现场认知必须回流进产品**。AI 时代最稀缺的 FDE，是一个人把前线交付和沉淀回产品两头都担起来的人。

   【v3 补充】市场规模印证：2026.05 OpenAI 成立企业部署公司并一次性获得约 150 名 FDE，Anthropic 跟进；硅谷 FDE 岗位招聘需求一年增长十倍不止。MIT 研究显示约 95% 的组织在生成式 AI 上回报为零，瓶颈在最后一公里交付。**壁垒是私有数据、业务理解、客户信任；单纯的现场定制交付在 AI 时代不稀缺。**

2. **能力主张（按重要性排序）**：

   * ① 高信任场景的需求诊断：从访谈中识别真实目标、约束、风险（不是问"你要什么"）

   * ② 现场认知的沉淀与回流：把单个客户的经验变成 SOP、知识库、培训体系、产品能力。简历主句用结果导向表述「经验能沉淀为体系、且不依赖我个人持续运转」，"第二个客户更容易"保留作面试官锚点

   * ③ 非标准化业务 → 标准化交付的翻译能力（SOP、知识库、验收口径）

   * ④ 方案设计与边界管理 + 技术可行性判断

   * ⑤ 面客表达：业务问题与量级 → 关键证据 → 建议方案 → 风险与控制 → 资源诉求

3. **招聘方的雷**：没有大厂 / 知名企业 AI 交付案例 → 用"对什么负责"的框架正面回应：房产 5 年就是对可衡量业务结果负责的交付（4 人团队年营收 200 万、150+ 客户、约 70% 转介绍）；复利标准有硬证据（上岗周期 18→6 个月、孵化 30+ 经纪人）。AI 侧，自己的产品与系统就是"一人公司版前线 + 回流"的活样本。

   【v3 补充】业务闭环证据升级：底层人工解读服务已通过小红书获得真实付费客户（定价 ¥99、限时 ¥39，30 分钟视频解读交付）。**口径边界：这是人工服务成交，不是 AI 产品收入，两者不得合并表述。**

4. **差异化优势**：技术 + 高信任咨询 + 创业闭环的三重组合；方法论可复制有实证；明确不夸大（不包装未成交的服务）。

   【v3 补充】知识治理闭环是"认知回流"在 AI 侧的对应物，且有人审设计：案例 → 假设 → 冲突检测与证据链 → 提案 → **疗愈师审核** → 入库更新本体。这正好落在企业级条件"角色清晰（人是审核、判定与责任主体，Agent 是执行器）"上，是面试里最硬的一段。

5. **不争**：大厂项目履历、纯技术深度、英文交付（外企 FDE 岗除外）。
6. **选岗口径**（投递决策与面试工具，不写进简历）：

   * **JD 阶段可判断的**：薪资结构含销售提成的"FDE" → 售前换皮，不投；JD 强调"促成签单、方案宣讲、投标"的同理。

   * **JD 判断不了、靠面试反问的**："经验是否回流产品""是否只做配置集成""第二个客户是否更容易"——三条反问清单：
     - "上一个客户项目里验证过的东西，有多少进了产品的下一个版本？"
     - "第二个同类客户交付时，团队规模和周期比第一个少了吗？"

## 认知卡三：AI 产品经理（中小团队 / 产品负责人方向）

1. **岗位本质**（v3 按资源视角改写）：AI 时代 PM 正在走向全栈 AI builder——需求、设计、开发同步开展、融合在少数人身上；在资源受限的小团队里就是产品的 CEO：从真实问题定义产品，推动 0→1 上线，并管赛道、流量、留存、商业化。
