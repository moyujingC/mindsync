## 0. 三张卡共用的最新岗位要求（v3 新增，2026-09-16）

### 0.1 门槛已经变了

招聘市场从"你会不会用 AI"转向"你能不能讲清楚一个 Agent 项目"。2026 春节后，没有 Agent 项目求职难度明显上升；普通 demo、内部小工具、套一层大模型 API 的玩具项目已经打动不了面试官，要看**真实场景、复杂链路、评估指标、失败处理**。

### 0.2 Agent 的定义方式：可调配的资源

**Agent ≈ 一套行为准则 + 可调用的工具、记忆、知识库、Skill。** 不同业务场景对四类资源的权重需求完全不同，直接决定岗位的能力要求差异。写项目时先说清"这个 Agent 能调动什么资源"，比罗列架构名词更能区分层次。Skill 是串联四类资源的调度中枢。

### 0.3 2026 年的能力重心迁移

| 维度 | 2023-2024 常见重点 | 2026 高薪岗位重点 | 本人的对应情况 |
| --- | --- | --- | --- |
| 编排 | 简单多 Agent 协同 | 复杂多智能体调度 | ⚠️ **v3.2 修正**：由"❌ 无事实对应"改为"有设计、无实现"。已有两个 Agent 的职责边界与数据契约（解读 Agent 只写不读 / 问答 Agent 只读不写，回答以链路产物为准、正文为辅，冲突时以产物为准并主动指出矛盾）+ 双场景分化（L1 不限轮次 / L2 ≤15 轮）+ 两 Agent 数据流方向（D-045）。**仍无多智能体运行时**，不得写成"已落地" |

### 0.4 企业级 Agent 的八个硬性条件（FDE 与工程师卡的边界判据）

业务侧：业务闭环、系统集成、流程嵌入、角色清晰（人是审核、判定与责任主体，Agent 是执行器）。
工程侧：安全可控、成本可算、效果可评估、能力可复制。

本人当前覆盖：业务闭环（人工服务已有付费成交）、安全可控（安全红线 + 失败降级）、效果可评估（黄金集 F1 0.821）、角色清晰（知识治理闭环由疗愈师审核入库）、能力可复制（房产 SOP 与培训体系）。未覆盖：系统集成、流程嵌入、权限分级、成本可算（仅有按份计费设计，无真实成本数据）。

### 0.6 三张卡共同的表达禁忌（v3 新增两条，v3.1 两条，v3.2 两条）

1. **可套用即不合格**：把项目名与业务名词换成任意其他场景后描述仍成立的，属泛化表述，必须删改。已按此复检出现有简历，识别出 5 条需删改（见 [基线评估](delivery/2026-09-15-简历评分标准v2-基线评估.md) 4.5）。
2. **提交次数不写进简历**：提交数只证明投入强度，不证明能力；改用可核验物证（合入 PR 编号、可访问产品、评测集与 A/B 记录、自动化复盘机制）。详见各卡第 7 节。
3. **项目阶段如实表达（v3.3 修正发布形态口径）**：Miro（一镜一梳）当前为 **设计定稿 + 知识库建成 + 报告生成链路端到端跑通（23 次运行）+ 本地运行、尚未对外发布**。仓库 50 次提交、24 个 `.py` 已入库；报告生成链路（`stage35.py` / `engine.py`）在工作区完成，**尚未提交**。
   - **发布形态不是缺陷，别当缺陷写（v3.3 新增）**：Miro 面向疗愈师单端，**本人即目标用户**（执业疗愈师，100+ 小时个案），本地能跑即可交付——**不要用"是否上线"衡量它**，也不要反复用"未上线"当限定词（那是拿 To C 的尺子量疗愈师工具，会自我否定）。对外统一用形态描述「本地运行 · 尚未对外发布」。
   - 可写"设计 / 知识库 / 评测基线 / 链路跑通 / 双版本报告 / 已知缺陷 / 本地运行"，**不可写**"已上线""已交付""已有客户""已投入生产"。已上线的是另一个项目（一镜一梳 To C），两者不得混写。
   - 被追问时直接说："这是给疗愈师用的自用工作台，我在本地跑，本来就不必做成线上产品。链路已经跑通并留了 23 次运行记录，但我还没拿它当对外交付物。"
   - **v3.3 提醒**：发布形态的修正不代表项目"完善"。用户侧指标（编辑率 / 采纳率）目前**零记录**，而这是自用形态下就能测的——见第 7 条。
4. **每句话必须能标出层级（v3.2 新增，最重要的一条）**：写任何 Miro 相关表述前，先判定它属于哪一层，并确保表述与层级一致——**① 已跑通**（有 run 记录、有数字，如双版本报告、F1 0.821、23 次运行）／**② 已设计未实现**（有 Spec、有决策编号，无代码，如问答 Agent 的 6 工具白名单、三层记忆、权限分级）／**③ 目标值**（如报告采纳率 >70%、编辑率 <30%，全部待试点回填）。**三层混写是本项目最大的翻车风险**：面试官只要追问一句"这个数字是怎么来的"，混写就会当场崩。此条同时是简历与面试的表达纪律。
5. **主动交缺陷是加分项，不是减分项（v3.2 新增）**：跑通后暴露的已知缺陷（溯源去重率 0.23、状态层与议题层 0 来源标记、证据门 `needs_human` 从 14–16 降到 0 即失去区分度、`_reference_case()` 硬编码注入绕过已设计的 `source_ref` 防线）**必须主动说**。理由：① 与"不编"的红线同源；② 面试官问"你的评估体系有没有失效过"，能答出"我的门禁连续 23 次一次都没拒绝过，所以它现在不是门禁"的人，比说"我的评估很完善"的人高一个层级；③ 缺陷本身是设计能力的证据——能定位到"根因是 `_build_claims()` 没给状态层组句子 + 提示词第 3 条禁止工程术语 + `state-explanation.md` 不在注入清单里"，说明真的读过自己的代码。
6. **中文名撞车必须带区分语（v3.1）**：已上线的 To C 产品叫「一镜一梳」（web.jingshu.cc）；Miro 项目中文名同为「一镜一梳」，是**疗愈师端 AI 工作台**。口头与书面一律区分为「一镜一梳（web.jingshu.cc）」与「Miro / 一镜一梳疗愈师端工作台」。不区分会两边都出错。
7. **「本人即用户」是当前最被低估的资产，也是最快能出硬数字的地方（v3.3 新增）**：三张卡此前把"自用"当成"缺外部用户"的减分项，**这个判断是错的**。Miro 面向疗愈师单端，本人即执业疗愈师（100+ 小时个案）——真实用户、真实场景、可随时迭代，这三样是行业里最难拿的。
   - **推论（这条要改动作，不只是改表述）**：用户侧指标**在自用形态下就能测**，不需要上线、不需要外部客户、不需要写新代码——只需要在下一次真实个案时，把「我改了几处 / 一共几段」记下来，跑够 10–20 份就有编辑率。
   - **现状**：`runs/` 已有 23 次运行记录（**最近一次 2026-09-17 16:07，即今天**），但**编辑率 / 采纳率零记录**——机器已经在了，测量键没按。
   - **判据**：这一条的价值等于简历「内容质量」维度能否从 22/30 抬到 26/30。而它不依赖 V2，**今天就能开始记**。三张卡的用户侧证据缺口（原写"没有真实个案使用数据"）应改为"有真实个案与运行记录，缺测量记录"。

### 0.7 岗位权重：不做通用简历

不同企业的 Agent 岗位能力要求差异明显。**投递前必须针对目标岗位做能力维度权重分析，突出 1-2 项与岗位强相关的核心优势**，不做大而全的通用简历。三张卡的"能力主张排序"就是权重分析的输入，投递时按 JD 重新排序，不重写事实。

## 认知卡二：FDE / AI 解决方案工程师

1. **岗位本质**（课程定义）：嵌入客户现场、主动交付有价值结果的产品探索者。两条硬标准：对**可衡量的业务结果**负责；**现场认知必须回流进产品**。AI 时代最稀缺的 FDE，是一个人把前线交付和沉淀回产品两头都担起来的人。

   【v3 补充】市场规模印证：2026.05 OpenAI 成立企业部署公司并一次性获得约 150 名 FDE，Anthropic 跟进；硅谷 FDE 岗位招聘需求一年增长十倍不止。MIT 研究显示约 95% 的组织在生成式 AI 上回报为零，瓶颈在最后一公里交付。**壁垒是私有数据、业务理解、客户信任；单纯的现场定制交付在 AI 时代不稀缺。**

2. **能力主张（按重要性排序）**：

   * ① 高信任场景的需求诊断：从访谈中识别真实目标、约束、风险（不是问"你要什么"）

   * ② 现场认知的沉淀与回流：把单个客户的经验变成 SOP、知识库、培训体系、产品能力。简历主句用结果导向表述「经验能沉淀为体系、且不依赖我个人持续运转」，"第二个客户更容易"保留作面试官锚点

   * ③ 非标准化业务 → 标准化交付的翻译能力（SOP、知识库、验收口径）

   * ④ 方案设计与边界管理 + 技术可行性判断

   * ⑤ 面客表达：业务问题与量级 → 关键证据 → 建议方案 → 风险与控制 → 资源诉求

3. **招聘方的雷**：没有大厂 / 知名企业 AI 交付案例 → 用"对什么负责"的框架正面回应：房产 5 年就是对可衡量业务结果负责的交付（4 人团队年营收 200 万、150+ 客户、约 70% 转介绍）；复利标准有硬证据（上岗周期 18→6 个月、孵化 30+ 经纪人）。AI 侧，自己的产品与系统就是"一人公司版前线 + 回流"的活样本。

   【v3 补充】业务闭环证据升级：底层人工解读服务已通过小红书获得真实付费客户（定价 ¥99、限时 ¥39，30 分钟视频解读交付）。**口径边界：这是人工服务成交，不是 AI 产品收入，两者不得合并表述。**

4. **差异化优势**：技术 + 高信任咨询 + 创业闭环的三重组合；方法论可复制有实证；明确不夸大（不包装未成交的服务）。

   【v3 补充】知识治理闭环是"认知回流"在 AI 侧的对应物，且有人审设计：案例 → 假设 → 冲突检测与证据链 → 提案 → **疗愈师审核** → 入库更新本体。这正好落在企业级条件"角色清晰（人是审核、判定与责任主体，Agent 是执行器）"上，是面试里最硬的一段。

5. **不争**：大厂项目履历、纯技术深度、英文交付（外企 FDE 岗除外）。
6. **选岗口径**（投递决策与面试工具，不写进简历）：

   * **JD 阶段可判断的**：薪资结构含销售提成的"FDE" → 售前换皮，不投；JD 强调"促成签单、方案宣讲、投标"的同理。

   * **JD 判断不了、靠面试反问的**："经验是否回流产品""是否只做配置集成""第二个客户是否更容易"——三条反问清单：
     - "上一个客户项目里验证过的东西，有多少进了产品的下一个版本？"
     - "第二个同类客户交付时，团队规模和周期比第一个少了吗？"
     - "这个岗位的考核是签单、工时，还是客户的业务指标？"
   * 反问同时也在向对方展示自己对 FDE 的理解深度，本身就是加分动作。

7. **证据映射**（v3 补充标注【新】）：

   * ⑤ ← 材料更新：`面试知识备份/2026-09-13` 的 Miro 五问逐字稿（Q1 为什么是 Agent 不是 Workflow、Q2 返工是否等于 if-else 重试、Q3 知识库更新是否属于 Agent、Q4 黄金集是否一直用这 11 个、Q5 怎么知道系统准）可直接作为面客表达的结构模板。【v3.2】新增可用的**局限说明模板**：被问"这套东西现在能交付给客户吗"，答"设计可以，实现只有一半——解读链路跑通了，问答 Agent 一行代码没有；而且我不打算在自用验证之前上线"。**主动说局限在 FDE 面试里是加分动作**，客户最怕的是兜不住

## 认知卡三：AI 产品经理（中小团队 / 产品负责人方向）

1. **岗位本质**（v3 按资源视角改写）：AI 时代 PM 正在走向全栈 AI builder——需求、设计、开发同步开展、融合在少数人身上；在资源受限的小团队里就是产品的 CEO：从真实问题定义产品，推动 0→1 上线，并管赛道、流量、留存、商业化。

   【v3 补充·资源视角】**Agent ≈ 行为准则 + 可调配的工具、知识库、Skill、记忆。** PM 的核心工作之一是定义这个 Agent 能调动什么资源、各资源的权重如何，以及资源使用的安全边界。

2. **能力主张（按重要性排序）**：

   * ① 从真实场景定义产品的能力（需求来自一线服务，自己就是目标用户）

   * ② 产品判断与取舍（范围、分层、什么不做）

   * ③ AI 输出的产品化：质量标准、评测、边界（AI PM 区别于传统 PM 的核心）
