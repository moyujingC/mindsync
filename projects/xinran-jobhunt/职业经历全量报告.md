- 阶段一（2026.02）：Lovable 快速验证 v1。因文档过时导致 AI 生成频繁出错、UI 移植失败，主动报废；沉淀原则「文档必须成为 AI 的一等事实源」。

- 阶段三（2026.04 至今）：迁入 MindSync Monorepo（moyujingC/mindsync 下 projects/aimandala）。建立六阶段交付门、golden case 回归验证，并将“视觉草稿 → 议题报告”两阶段端到端链路接入线上 API 主链。项目同时具备夜间自动冒烟测试与受控自动修复能力，web.jingshu.cc 持续内测。

**模型与质量：**

- 文字模型 DeepSeek V4；视觉模型 qwen-vl-max（豆包兜底）；候选模型 GLM 经 9 张测试图 × 3 轮重复生成的稳定性评测后淘汰。
- 两段式生成链路：先让视觉模型把画作转成自然语言"画面事实描述"，再让推理模型按议题生成解读（直接输出结构化 JSON 会丢失画面细节，故改用自然语言并保留 A/B 对照）。
- 5 组标准测试用例（golden case，内部代号 wealth-case-001~005）；端到端回归 fixture 保存视觉草稿、版本化提示词包、最终报告和质量门产物，用于人工审阅、故障定位和回归验证。
- 方案演进说明：2026-05 曾实现并跑通 stage-00 至 stage-16 的离线过程原型，但验证后发现重结构化中间层会损失画面整体信息、使报告偏向系统检测结果，因此停止扩展并改为“视觉草稿 → 议题报告”的两阶段端到端链路。旧 stage 原型只作为架构取舍案例，不作为当前实现或质量机制。
- A/B 测试：围绕 `two_pass_e2e` 与 `single_pass_e2e` 两类报告方案，用 11 个完整案例进行对照批跑，比较视觉一致性、可复用性、可排错性和报告体验，并将实验结果用于反哺两阶段方案。
- RAG 方案设计：在 2026-07-31 共用曼陀罗解读引擎 draft 产品规格中，定义按画面信号、议题、交付模式和风险边界取回受控知识单元，并保留证据追溯和质量门；该 RAG 引擎尚处于规格阶段，未上线。
- 两个模型都识别失败时，系统降级返回保守默认结果，不强行猜测。
