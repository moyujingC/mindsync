# 投递期材料迭代工作流

> 状态：current
> 版本：0.3.0
> owner：CEO / Orchestrator
> last_updated：2026-08-06
> source_of_truth：projects/xinran-jobhunt/投递期材料迭代工作流.md

这份文档用于承接真实投递阶段，把不断出现的 JD、竞争力分析、猎头反馈、面试反馈，稳定转成可迭代的求职材料。招聘 App 操作流水继续留在招聘平台内处理。

2026-08-06 后，本工作流服从 [README-文件结构与同步规则](README-文件结构与同步规则.md)：`职业经历全量报告.md` 是事实唯一来源，`在线简历母版.md` 是 BOSS / 猎聘共用在线简历唯一内容源，`工程版 / FDE 版 / 产品版` 是当前三份附件简历来源。

## 1. 这套工作流服务什么

投递期维护两层资产。

### 1.1 底层资产层

用于阶段性收束、周评和大改：

1. `JD 数据库`：持续收集岗位 JD、BOSS 竞争力分析、猎头职位和面试反馈。
2. `职业经历全量报告.md`：事实唯一来源。
3. `三岗位认知卡.md`：岗位论点、证据排序和选岗口径。
4. `简历评分标准.md`：周评、大改、上线前质量门（唯一评分依据，含事实底线、证据上限、口径红线与在线 B 卡 / 附件 C 卡双卡；`在线简历评分标准.md` 为 v1 历史快照，不再引用）。
5. `个人职业叙事作品集网站/`：项目证据、截图、作品详情和职业叙事。

### 1.2 日常投递层

用于快速投递和小范围定制：

1. `在线简历母版.md`：BOSS / 猎聘共用在线简历唯一内容源。
2. `崔兴-AI应用工程师简历.md`：AI 应用工程师 / 大模型应用工程师附件简历来源。
3. `崔兴-FDE-AI解决方案工程师简历.md`：FDE / AI 解决方案工程师附件简历来源，当前第一主攻。
4. `崔兴-AI产品经理简历.md`：AI 产品经理 / AI Builder 附件简历来源。
5. `delivery/2026-07-13-BOSS直聘沟通SOP.md`：BOSS 首聊、跟进、回复策略。

## 2. 输入怎么进来

每次出现新的岗位或反馈，先判断它属于哪种输入。

| 输入类型 | 记录位置 | 处理方式 |
|---|---|---|
| 单条 JD 截图 / 链接 | `jd-database/jobs/` | 转成文字版 JD，补结构化拆解和岗位判断 |
| BOSS 竞争力分析 | 对应单条 JD 文档 | 记录平台判低分的位置，判断是简历问题、岗位错配还是算法误判 |
| 猎头发来的岗位 | `jd-database/jobs/` | 标记来源为猎头，额外记录猎头强调的筛选点 |
| 面试反馈 | `delivery/` 或对应岗位文档 | 提炼成材料改写点、面试表达点、作品集补证据点 |
| 高频 JD 主题 | [JD 高频词与材料映射](delivery/JD高频词与材料映射.md) | 累积到阶段性关键词分析，再决定是否修改简历和作品集 |
| 可公开判断 | `projects/content-matrix/accounts/墨予镜/` | 转成小红书 / 公众号选题或草稿 |
| BOSS 首聊 / 跟进反馈 | 对应岗位文档或 [BOSS 直聘沟通 SOP](delivery/2026-07-13-BOSS直聘沟通SOP.md) | 单个岗位写定制消息，通用沟通规则沉淀为 SOP |

原则：招聘 App 里的操作流水仍然留在招聘平台。仓库只保留后续还能复用的岗位文本、判断和材料版本。

## 3. 单条 JD 到投递动作

看到一个岗位时，不先改主简历，只做三步。

### 3.1 判方向

只选一个主方向：

| 岗位方向 | 使用材料 |
|---|---|
| AI 应用工程师 / 大模型应用工程师 / Agent 应用工程师 | [AI 应用工程师简历](崔兴-AI应用工程师简历.md) |
| FDE / AI 解决方案工程师 / AI 应用交付 | [FDE / AI 解决方案工程师简历](崔兴-FDE-AI解决方案工程师简历.md) |
| AI 产品经理 / AI Builder / 产品工程型 PM | [AI 产品经理简历](崔兴-AI产品经理简历.md) |

AI 转型咨询顾问暂不作为第一主线。若 JD 明确要求流程诊断、培训赋能、组织采用，可优先判断是否能归入 FDE / AI 解决方案叙事。

### 3.2 判是否值得定制

只有满足以下任一条件，才定制：

- 目标公司重要，且计划认真准备面试。
- JD 与当前简历标题 / 首段明显不贴。
- JD 有一个高价值关键词，但当前 active 简历完全没有。
- 猎头或 HR 明确指出某表达影响推荐。
- 连续多条 JD 暴露同一材料缺口。

否则直接投，不改主简历。

### 3.3 最多改 3 个位置

如果确实需要定制，最多改：

1. 求职意向 / 标题。
2. 个人优势前 2-3 行。
3. 一个项目 bullet 或项目排序。

禁止为了单条 JD 大改事实源、重写全部工作经历、重排整个简历。

## 4. 形成共性信号后再改材料

当 3–5 条以上 JD 都出现同一类要求时，进入阶段评估触发判断。达到触发条件后，先新建日期化阶段报告、冻结改前基线和改写范围，再进入材料迭代；不从共性信号直接跳到全套简历修改。

优先观察这些信号：

- `Agent / 智能体 / Workflow / Multi-Agent`
- `RAG / 知识库 / 数据治理 / 结构化知识`
- `PoC / MVP / Demo / 原型验证`
- `客户现场 / 业务场景 / 方案设计 / 交付`
- `评测 / 质量门 / Guardrails / 安全边界`
- `培训赋能 / SOP / 组织推广 / AI 工具采用`

个别岗位的特殊要求先放进岗位分析，暂不改主简历。

## 5. 阶段评估后再同步材料

达到以下任一条件时，新建 `delivery/YYYY-MM-DD-求职材料阶段性评估.md`：累计 10 个同类 JD、5 次有效沟通、主攻方向变化、新增实质证据、连续出现同类误判，或上一轮动作完成需要复评。

阶段报告必须先记录：

1. 当前 active 评估对象与改前基线。
2. 输入来源、有效结果和排除规则。
3. 允许改动与禁止改动范围。
4. P0 / P1 / P2、影响层级和目标文件。
5. 改后复评、QA 结论和残余风险。

报告状态按 `working → current → in_review → historical-reference` 流转。新一轮必须新建日期文件，不在旧报告或历史归档中继续滚动修改。

### 5.1 事实 → 论点 → 表达的同步顺序

涉及事实或口径变化时，顺序固定：

1. 更新 [职业经历全量报告](职业经历全量报告.md)。
2. 如果影响能力主张或证据排序，同步 [三岗位认知卡](三岗位认知卡.md)。
3. 如果影响平台在线字段，同步 [在线简历母版](在线简历母版.md)。
4. 如果影响附件投递，同步受影响的 [工程版](崔兴-AI应用工程师简历.md) / [FDE 版](崔兴-FDE-AI解决方案工程师简历.md) / [产品版](崔兴-AI产品经理简历.md)。
5. 如果只影响面试表达，更新 [三岗位 2 分钟自我介绍](三岗位2分钟自我介绍.md)、问答素材或作品集。

不能在某一份简历里单独发明项目事实。

## 6. 各材料怎么分工

### 6.1 平台在线简历

来源：[在线简历母版](在线简历母版.md)

用途：BOSS / 猎聘共用在线简历内容源，承接平台检索、系统过筛、HR 初筛和多职位统一画像。

写法：

- 在线简历不按单个职位拆多版；同一份母版覆盖当前主攻方向的共同关键词。
- BOSS 与猎聘共用同一内容源，再按平台字段映射拆填。
- 在线简历允许较多字数，不追求极短，但开头仍要清楚呈现 AI 应用落地型候选人画像。
- 打招呼语按方向选择：FDE / AI 产品经理 / AI 应用工程师。
- 附件简历只从工程版 / FDE 版 / 产品版导出。

### 6.2 附件简历

用途：官网投递、邮件附件、HR 转发、面试前补充。

写法：

- 每次只投一个主方向，不做大而全。
- FDE / AI 解决方案优先使用 FDE 版。
- AI 产品经理只投 AI Builder / 产品工程型 PM / 中小团队产品负责人，不投传统大厂分工型 PM。
- AI 应用工程师只投 AI Coding 友好、应用层落地岗位，不投算法、底层模型、高并发平台或强 LeetCode 岗。

| PDF 方向 | Markdown 来源 | 导出方式 |
|---|---|---|
| FDE / AI 解决方案工程师 | [FDE / AI 解决方案工程师简历](崔兴-FDE-AI解决方案工程师简历.md) | 用户从 Obsidian 手动导出到下载目录 |
| AI 应用工程师 | [AI 应用工程师简历](崔兴-AI应用工程师简历.md) | 用户从 Obsidian 手动导出到下载目录 |
| AI 产品经理 | [AI 产品经理简历](崔兴-AI产品经理简历.md) | 用户从 Obsidian 手动导出到下载目录 |

### 6.3 作品集网站

作品集网站负责承接三类内容：

1. 简历里写不下的项目证据。
2. 面试时可展开讲的职业叙事。
3. 对招聘方释放的外部可信信号。

每次改简历时，只检查作品集是否需要同步，不要求跟每条 JD 修改。

### 6.4 墨予镜内容

内容输出从 JD 高频信号里长出来，但不反向支配简历。只有当公开内容沉淀出稳定表达，并且不引入新事实时，才可作为面试表达参考。

## 7. 面试准备怎么沉淀

面试准备不只背自我介绍，而是持续补三类材料：

| 面试输入 | 产物 |
|---|---|
| 高频追问 | 更新 [三岗位 2 分钟自我介绍](三岗位2分钟自我介绍.md) 或新增问答素材 |
| 项目深挖 | 补作品集详情页和 STAR 案例 |
| 被质疑的短板 | 回到 JD 数据库判断是材料表达问题、事实短板还是岗位错配 |

每次面试后至少留三条信息：

1. 对方最关心什么。
2. 我哪段表达有效，哪段卡住。
3. 哪份材料需要改。

## 8. 每周节奏

### 8.1 每日轻量循环

1. 收集 1-5 条值得保留的 JD 或猎头岗位。
2. 判方向：工程版 / FDE 版 / 产品版。
3. 判断是否值得定制；不值得则直接投。
4. 记录会复用的岗位文本、关键词和风险点。
5. 投递前执行 60 秒红线检查。

### 8.2 每周同步

1. 汇总本周 JD 高频词、HR / 猎头反馈、面试问题和新证据。
2. 对照触发条件判断是否需要阶段评估。
3. 如触发，先新建日期化阶段报告，冻结基线并确定本轮允许与禁止改动范围。
4. 按报告范围更新事实源，再更新认知卡、公共原则、在线简历母版、工程版 / FDE 版 / 产品版，以及必要的作品集或面试材料。
5. 回到同一报告记录改后复评；用 [简历评分标准](简历评分标准.md) 检查事实底线、口径红线与最低分项——在线版看 B 卡、附件版看 C 卡，不交叉套用，也不全文润色。
6. 完成同轮 QA，记录未关闭项和残余风险，再冻结下周投递与面试准备重点。

## 9. 判断是否该改材料

出现以下情况，应该改材料：

- 多条 JD 反复出现同一个关键词，而简历没有明确表达。
- 猎头或 HR 明确指出某个经历看不懂。
- 面试中对方反复追问同一个项目，但现有作品集没有承接。
- 平台竞争力分析持续低估某项能力，且岗位本身确实匹配。
- 当前投递方向发生阶段性变化，例如从 AI 产品转向 FDE 优先。
- AI 产品出现真实证据更新，例如可演示链路、用户反馈、订单、报告量、PR、测试记录。

出现以下情况，先不改材料：

- 只有一条 JD 的个性化要求。
- 岗位本身明显错配。
- 平台算法判低分，但 JD 细看并不适合。
- 修改会破坏三阶段叙事或造成事实夸大。
- 只是想让简历“更好看”，但没有明确反馈或证据变化。

## 10. 投递前 60 秒红线检查

每次发出前只查以下 8 项：

1. 是否使用正确方向的 active 简历：工程版 / FDE 版 / 产品版。
2. 文件名和求职意向是否一致。
3. 电话、邮箱、城市、链接是否正确。
4. 是否出现期望薪资。
5. 是否还有“写作说明 / 投递前删除 / 选岗提醒 / 内部备注”。
6. 支付口径是否为：**内测兑换码模式运行中，在线支付接入中**。
7. 是否出现禁用旧口径：育碧 / Ubisoft、成熟商业化平台、已接入支付系统、医疗诊断、心理治疗。
8. 所有强数字是否能解释来源和统计口径。

通过即可投递。不因单次投递执行完整 100 分评分。
