# 投递期材料迭代工作流

> 状态：current
> 版本：0.1.0
> owner：CEO / Orchestrator
> last_updated：2026-06-16
> source_of_truth：projects/xinran-jobhunt/投递期材料迭代工作流.md

这份文档用于承接 2026-06 开始的真实投递阶段。

当前目标是把投递过程中不断出现的 JD、竞争力分析、猎头反馈、面试反馈，稳定转成可迭代的求职材料。招聘 App 操作流水继续留在招聘平台内处理。

## 1. 这套工作流服务什么

投递期要同时维护六类资产：

1. `JD 数据库`：持续收集岗位 JD、BOSS 竞争力分析、猎头转发职位和面试反馈。
2. `在线简历母版`：用于各招聘网站的在线简历，要求覆盖面更广、关键词更完整、填写成本更低。
3. `PDF 版附件简历`：用于主动投递、官网投递、邮件投递和面试前转发，要求更聚焦、更像正式候选人材料。
4. `猎头版简历`：用于给猎头快速判断方向、薪资、行业适配和可推荐岗位，要求直接、便于转发。
5. `个人职业叙事作品集网站`：用于承接简历里无法展开的项目证据、职业叙事和作品详情。
6. `墨予镜内容输出`：把 JD 高频需求和求职过程里的判断转成公开内容，同时反向强化外部职业信号。

## 2. 输入怎么进来

每次出现新的岗位或反馈，先判断它属于哪种输入。

| 输入类型 | 记录位置 | 处理方式 |
|---|---|---|
| 单条 JD 截图 / 链接 | `jd-database/jobs/` | 转成文字版 JD，补结构化拆解和岗位判断 |
| BOSS 竞争力分析 | 对应单条 JD 文档 | 记录平台判低分的位置，判断是简历问题、岗位错配还是算法误判 |
| 猎头发来的岗位 | `jd-database/jobs/` | 标记来源为猎头，额外记录猎头强调的筛选点 |
| 面试反馈 | `delivery/` 或对应岗位文档 | 提炼成材料改写点、面试表达点、作品集补证据点 |
| 高频 JD 主题 | [JD 高频词与材料映射](delivery/JD高频词与材料映射.md) | 累积到阶段性关键词分析，再决定是否修改简历和作品集 |
| 可公开判断 | `projects/content-matrix/accounts/墨予镜/` | 转成小红书 / 公众号选题或草稿 |
| BOSS 首聊 / 跟进反馈 | 对应岗位文档或 [BOSS 直聘沟通 SOP](delivery/2026-07-13-BOSS直聘沟通SOP.md) | 单个岗位写定制消息，通用沟通规则沉淀为 SOP |

原则：招聘 App 里的操作流水仍然留在招聘平台。仓库只保留后续还能复用的岗位文本、判断和材料版本。

BOSS 直聘上的首聊、二次跟进、活跃 HR 筛选和回复率排查，统一看 [BOSS 直聘沟通 SOP](delivery/2026-07-13-BOSS直聘沟通SOP.md)。仓库不保存完整聊天记录，但要保存可复用话术、关键反馈和会影响材料迭代的共性信号。

## 3. JD 到材料的流转规则

### 3.1 单条 JD 不直接改简历

单条 JD 只进入 `JD 数据库`，不因为一条岗位就改在线简历或 PDF 简历。

例外情况：

- 岗位来自高优先级目标公司，且计划立刻定向投递。
- JD 暴露出当前简历的硬缺口，例如完全没有出现 `Agent 工作流`、`PoC`、`客户现场` 等核心词。
- 猎头明确指出某个表达会影响推荐。

### 3.2 形成共性信号后再改母版

当 3-5 条以上 JD 都出现同一类要求时，进入材料迭代。

优先观察这些信号：

- `Agent / 智能体 / Workflow / Multi-Agent`
- `RAG / 知识库 / 数据治理 / 结构化知识`
- `PoC / MVP / Demo / 原型验证`
- `客户现场 / 业务场景 / 方案设计 / 交付`
- `评测 / 质量门 / Guardrails / 安全边界`
- `培训赋能 / SOP / 组织推广 / AI 工具采用`

个别岗位的特殊要求先放进岗位分析，暂不改主简历。

### 3.3 先改事实底稿，再改表达材料

涉及 AI 项目事实变化时，顺序固定：

1. 更新 [AI 项目事实底稿](2026-06-01-AI项目事实底稿.md)。
2. 同步 [在线简历母版](在线简历母版.md)。
3. 同步三版岗位简历、猎头版简历或 PDF 附件简历。
4. 同步 [作品集前四张详情页方案](作品集前四张详情页方案.md) 和网站内容。
5. 必要时同步 `墨予镜` 公开内容选题。

不能在某一份简历里单独发明项目事实。

## 4. 各材料怎么分工

### 4.1 在线简历母版

用途：招聘网站在线表单、BOSS / 猎聘 / 拉勾等平台基础资料。

写法：

- 覆盖三条主方向：AI 产品经理、AI 转型咨询顾问、FDE。
- 关键词更完整，便于平台搜索和算法匹配。
- 工作经历写得相对全，但每段都要服务目标岗位。
- 允许保留更完整的职业路径，包括保险经历，但要避免喧宾夺主。

优先优化：

- 个人优势 / 自我评价
- 核心技能
- 一人公司 / AI 产品实践
- 房产咨询经历向 `业务诊断 + 方案交付 + SOP / 知识库` 的转译
- 自由职业和游戏研发经历向 `工程交付 + 跨团队协作 + 技术理解` 的转译

### 4.2 PDF 版附件简历

用途：官网投递、邮件附件、HR 转发、面试前补充。

写法：

- 每次只投一个主方向，不做大而全。
- 继续保留“三阶段职业叙事”：技术筑基期、能力迁移期、融合创新期。
- 重点项目要比在线简历更聚焦，减少平台表单式细节。
- 默认不把保险经历作为 FDE 版简历主内容，除非岗位要求强销售、客户经营或高信任咨询背景。

当前维护三份岗位版 PDF 来源：

- AI 产品经理版
- AI 转型咨询顾问版
- FDE / AI 解决方案工程师版

### 4.3 猎头版简历

用途：让猎头在 30 秒内知道“可以把我推给什么岗位”。

当前维护一份猎头专用 Markdown 版本，后续可按猎头反馈再导出 PDF。

结构建议：

1. 基础信息：城市、薪资、到岗状态、作品集链接。
2. 可推荐方向：AI 产品经理、AI 转型咨询顾问、FDE / AI 解决方案工程师。
3. 一句话候选人定位：18 年技术、咨询、创业和 AI 产品实践的复合背景。
4. 三类岗位推荐关键词：每类 6-10 个关键词，方便猎头复制给客户。
5. 最强项目证据：曼陀罗 AI 产品、MindSync 工作系统、房产咨询体系、游戏 / 工程经历。
6. 不推荐方向：纯算法、纯销售、纯传统项目经理、低薪泛运营。

猎头版优先服务“可推荐、可转发、可快速匹配”，不追求完整经历。

## 5. 作品集网站怎么跟着投递迭代

作品集网站负责承接三类内容：

1. 简历里写不下的项目证据。
2. 面试时可展开讲的职业叙事。
3. 对招聘方释放的外部可信信号。

每次改简历时，要检查作品集是否需要同步：

- 简历新增了 `Agent 工作流`，作品集里是否有对应项目详情。
- 简历强调 `Prompt Pack / 输出契约 / 质量门`，作品集是否解释了这套设计。
- 简历强调 `客户诊断 / 方案设计 / SOP`，作品集是否能看到房产咨询体系证据。
- 简历强调 `FDE / 解决方案交付`，作品集是否有技术交付和现场问题转译证据。

作品集不必跟每条 JD 修改，但要跟随阶段性定位变化。

## 6. 墨予镜内容怎么接入

内容输出不单独另起一条线，它从 JD 高频信号里长出来。

当 JD 数据库持续出现某类需求时，可以转成内容选题：

- `AI Agent`：什么场景适合做 Agent，什么场景只是套概念。
- `RAG（检索增强生成）`：为什么很多团队应该先整理知识，再谈 RAG。
- `PoC（概念验证）`：一个 AI PoC 最小闭环应该长什么样。
- `FDE（前线部署工程师）`：现场问题如何翻译成可交付系统。
- `AI 转型`：企业做 AI 转型为什么要从流程开始。

内容结构沿用“热点层 -> 判断层 -> 证据层”：

1. 热点层：从 JD 高频词或行业热议切入。
2. 判断层：给出自己的拆解。
3. 证据层：用真实项目或方法论支撑判断。

内容不要写成单纯求职日记。它要让招聘方看到判断力、场景感、AI 应用理解和表达能力。

## 7. 面试准备怎么沉淀

面试准备不只背自我介绍，而是持续补三类材料：

| 面试输入 | 产物 |
|---|---|
| 高频追问 | 更新 [三岗位 2 分钟自我介绍](三岗位2分钟自我介绍.md) 或新增问答素材 |
| 项目深挖 | 补作品集详情页和 STAR 案例 |
| 被质疑的短板 | 回到 JD 数据库判断是材料表达问题、事实短板还是岗位错配 |

每次面试后至少留三条信息：

1. 对方最关心什么。
2. 我哪段表达有效，哪段卡住。
3. 哪份材料需要改。

## 8. 每周节奏

### 每日轻量循环

1. 收集 1-5 条值得保留的 JD 或猎头岗位。
2. 录入 `JD 数据库`。
3. 标记岗位轨道、关键词和风险点。
4. 如果发现可公开判断，放入 `墨予镜` 选题池。

### 每 2-3 天小迭代

1. 汇总新增 JD 的高频词。
2. 更新 [JD 高频词与材料映射](delivery/JD高频词与材料映射.md)。
3. 针对当前投递重点微调一份 PDF 简历。
4. 补 1-2 个面试问答或 STAR 案例。

### 每周大迭代

1. 更新 [JD 高频词与材料映射](delivery/JD高频词与材料映射.md) 和 JD 阶段性分析。
2. 调整在线简历母版。
3. 更新三份岗位版 PDF 简历来源中的一份或多份。
4. 检查作品集网站是否需要同步。
5. 产出 1-2 篇 `墨予镜` 求职向内容草稿。
6. 更新下周投递重点和面试准备重点。

## 9. 判断是否该改材料

出现以下情况，应该改材料：

- 多条 JD 反复出现同一个关键词，而简历没有明确表达。
- 猎头或 HR 明确指出某个经历看不懂。
- 面试中对方反复追问同一个项目，但现有作品集没有承接。
- 平台竞争力分析持续低估某项能力，且岗位本身确实匹配。
- 当前投递方向发生阶段性变化，例如从 AI 产品转向 FDE 优先。

出现以下情况，先不改材料：

- 只有一条 JD 的个性化要求。
- 岗位本身明显错配。
- 平台算法判低分，但 JD 细看并不适合。
- 修改会破坏三阶段叙事或造成事实夸大。
