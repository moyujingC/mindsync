## 三、阶段评估报告规则

1. 达到共性信号、有效沟通、方向变化或新证据等触发条件时，新建 `delivery/YYYY-MM-DD-求职材料阶段性评估.md`。
2. 阶段报告属于 `support / stage-review`，只承担改前基线、质量判断、改写范围、改后复评和残余风险，不进入 active 投递来源。
3. 报告状态按 `working → current → in_review → historical-reference` 流转，只使用仓库治理规范已有状态。
4. 新一轮必须新建日期文件；旧报告和 [历史评估归档](delivery/2026-08-06-简历评估与改写建议归档/README.md) 不继续滚动修改。
5. 报告发现事实变化时，必须先回写 `职业经历全量报告.md`，不能把报告本身当成新增简历事实的依据。
6. 归档前必须记录 P0 关闭情况、改后复评、QA 结论和残余风险。

## 四、同步规则（事实 → 论点 → 投递材料）

事实或口径变化时，按固定顺序改，一次提交完成：

1. 先改 `职业经历全量报告.md`（事实唯一来源，追加到校准增量一节）。
2. 涉及能力主张、证据排序或选岗口径 → 改 `三岗位认知卡.md`。
3. 涉及平台在线字段 → 同步 `在线简历母版.md`。
4. 涉及附件投递 → 同步受影响的 `工程版 / FDE 版 / 产品版` 分职位简历。
5. 只影响面试表达或作品展示 → 更新自我介绍、作品集或问答材料，不反向污染事实源。

禁止在某一份简历里单独发明项目事实。

## 五、日常投递轻量流程

看到一个岗位时，不先改简历，只做三步：

1. **判方向**：AI 应用工程师用 `工程版`；FDE / AI 解决方案用 `FDE 版`；AI 产品经理用 `产品版`。
2. **判是否值得定制**：只有目标公司重要、JD 高匹配、HR/猎头明确反馈、或 JD 暴露当前简历硬缺口时，才定制。
3. **最多改 3 处**：标题 / 求职意向、个人优势前 2-3 行、一个项目 bullet 或项目排序。单条 JD 不重写事实源和全套简历。

## 六、投递前 60 秒红线检查

每次发出前只查以下 10 项。第 9、10 项于 2026-09-15 从 [简历评分标准](简历评分标准.md) 2.3 同步过来；口径红线的完整定义以该文件 2.3 为准，本节只保留投递前的快速检查项，不另立副本。

（以下为检查项）

1. 是否用了正确方向的 active 简历：`工程版 / FDE 版 / 产品版`。
2. 文件名和求职意向是否一致。
3. 电话、邮箱、城市、链接是否正确。
4. 是否出现期望薪资。
5. 是否还有“写作说明 / 投递前删除 / 选岗提醒 / 内部备注”。
6. 支付口径是否为：**内测兑换码模式运行中，在线支付接入中**。
7. 是否出现禁用旧口径：育碧 / Ubisoft、成熟商业化平台、已接入支付系统、医疗诊断、心理治疗。
8. 所有强数字是否能解释来源和统计口径。
9. 项目描述是否通过替换测试：把项目名与业务名词换成任意其他场景后仍成立的描述，属泛化表述，须删改（判据见 [简历评分标准](简历评分标准.md) 1.8 与 [AI产品经理岗位能力补充](AI产品经理岗位能力补充-2026-09-15.md) 第 8 节）。
10. 使用脱敏样本、自建集合或模拟环境的项目，是否已标明性质，未暗示来自真实企业生产环境。
