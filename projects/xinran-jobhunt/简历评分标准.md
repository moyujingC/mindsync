## 0. 这套标准解决什么

三件事：用市场需求而非单条 JD 校准评分口径；在线简历与附件简历分开评分；评分结果可复核、可交接。

### 0.1 三类材料与三个判断

| 材料 | 谁在看 | 判断方式 | 决定什么 |
| --- | --- | --- | --- |
| 在线简历（BOSS / 猎聘字段） | 平台检索 + HR | 关键词检索 + 15 秒扫读 | 能不能被搜到、被点开 |
| 附件简历（PDF，1-2 页） | HR + 面试官 | 60 秒通读 + 面试逐句对照 | 能不能进面、面试时能不能站住 |
| 作品集 / 面试材料 | 面试官 | 追问时查阅 | 追问环节能不能加分 |

### 0.2 为什么在线简历和附件简历要分开评分

三份材料由不同机制筛选，用一张卡会把问题掩盖掉：

- 在线简历是"检索 + 扫读"：输了关键词、字段不完整、首屏不对口，直接没有曝光；写得再好也没机会被读到。
- 附件简历是"逐句读 + 当场追问"：关键词齐全不代表叙事站得住，面试官会挑每一条 bullet 追问设计与口径。
- 同一份分数会误导动作：在线 85 / 附件 70 的候选人，问题出在附件和面试，按在线分去优化只会白改一遍。

分开之后仍有两层共用：事实底线、证据上限、口径红线（第 2 节）。这两层不满足时，两张卡都不计分。

现行材料分工已在 [README-文件结构与同步规则](README-文件结构与同步规则.md) 中确定：在线唯一母版 + 三个方向的附件版（工程 / FDE / 产品）。

## 1. 市场需求基线（来源：本地课程材料）

本节是两张评分卡的权重依据。只使用 `projects/research-center/courses/` 下的课程材料作为市场信号来源，不读 JD。市场信号变化时只改本节。

### 1.1 门槛变化：从"会不会用 AI"到"能不能讲清一个 Agent 项目"

来源：`2026-07-10-AI Agent 系统设计面试现场/00｜百场面试录音复盘`、`加餐-简历篇`

- 招聘市场正在从"你会不会用 AI"转向"你能不能讲清楚一个 Agent 项目"。
- 2025.10 前后，很多 Java 岗位改成了 Agent 工程师岗，筛人逻辑跟着改。
- 2026 春节后，没有 Agent 项目，求职难度明显上升；岗位持续转向 AI 应用、Agent 平台、智能助手、企业内部自动化。
- 大厂标准又抬高一档：普通 demo、内部小工具、套一层大模型 API 的玩具项目越来越难打动面试官，要看真实场景、复杂链路、评估指标、失败处理。
- 面试高频问题固定：意图怎么识别、任务怎么规划、工具怎么调用、上下文怎么管理、效果怎么评估；追问紧跟"为什么这么设计、哪里会失败、怎么兜底"。

对评分的含义：附件简历里"机制"和"失败处理"必须有具体痕迹；功能罗列不得分。

### 1.2 需求分布：破局者岗位量更大

来源：`2026-07-03-Harness Agent 脚手架实战课/00`

- 两类岗位：造局者（做通用 Agent 能力，如对标 Claude Code 的 AI Coding 产品）；破局者（把 AI 接进千行百业，含互联网大厂、FDE、传统企业内部智能化转型）。
- 从就业与招聘需求看，破局者的需求量明显更大，对应企业从数字化转型走向智能化转型。
- 破局者岗位特征：短平快、垂类智能体、技术难度未必极高、周期极短，企业要看到降本提效的实际结果。
- 该赛道的竞争力落在"快"：能否迅速掌握前沿 Agent 思想、套路、脚手架并交付。

对评分的含义：能证明"把 AI 快速落到具体业务场景并跑出结果"的经历，权重大于"掌握多少框架"。

### 1.3 FDE 的真实门槛：认知回流产品

来源：`2026-07-28-FDE业务落地实战/00、课程介绍`

- 2026.05 OpenAI 成立企业部署公司并一次性获得约 150 名 FDE，Anthropic 随后跟进；硅谷 FDE 类岗位招聘需求一年增长十倍不止。
- MIT 研究：企业在生成式 AI 上投入数百亿美元，约 95% 的组织回报为零。
- 判断分工："AI 负责做出来，人负责判断是否做得好"；瓶颈在最后一公里的交付与落地。
- 新壁垒：私有数据、业务理解、客户信任。
- 真假 FDE 的分界：AI 越强，单纯的现场定制交付越不稀缺；"现场得到的认知能不能回流进产品"才是壁垒。

对评分的含义：FDE 方向必须写"现场认知 → 产品 / 方法沉淀"的闭环，只写"在客户现场搭了一套系统"不加分。

### 1.4 企业级 Agent 的八个硬性条件

来源：`2026-00-极客内参：直播精华/Harness Engineering/03`

| 侧 | 条件 | 判断标准 |
| --- | --- | --- |
| 业务 | 业务闭环 | 进入系统后自动输出标准格式的确定性结果，不是闲聊外挂 |
| 业务 | 系统集成 | 咬合既有 CI/CD、CRM、权限中轴，消灭信息孤岛 |
| 业务 | 流程嵌入 | 作为原子级齿轮嵌入企业现有流程 |
| 业务 | 角色清晰 | 分工黑白分明，人是审核、判定与责任主体，Agent 是执行器 |
| 工程 | 安全可控 | Hook 拦截与安全沙箱守住高危动作，异常可回滚 |
| 工程 | 成本可算 | token、缓存与会话生命周期作为一等财务资源治理 |
| 工程 | 效果可评估 | 覆盖率与指标齐全：首通通过率、人机介入比、异常频率、token 命中率 |
| 工程 | 能力可复制 | 通过控制面与 SOP 把单人提效无损复制到组织，不依赖个人经验 |

对评分的含义：这八条就是"企业级"的证据清单，附件简历的机制密度维度直接对照它打分。

### 1.5 Agent 项目简历的写法标准

来源：`2026-07-10.../加餐-简历篇`、`小哲电商Agent/简历写法指南.md`

- 三问结构：发现了什么业务或技术问题 → 设计了什么机制解决 → 结果改善到什么程度。
- 项目名 = 业务场景 + Agent 核心能力 + 平台或系统定位；避免"AI 智能平台""大模型应用系统"这类宽泛命名。
- 技术栈按层次排列（模型与编排 / 检索与知识库 / 应用与数据 / 部署与可观测），不做平铺罗列。
- 九类贡献方向有优先级：必选是架构与核心链路、意图识别、执行机制、上下文管理、评估与反馈闭环；候选是检索与 RAG；可选是可观测性、团队管理、0→1 落地。
- 只深写 2-3 个模块，其余一句带过；全写等于没写，一眼看出是课程清单。
- 数字必须能自己跑出来、说清口径；"成本降低 60%"却说不出分子分母，整份简历失信。
- 每条 bullet 都要能撑住对应的面试官必追问。
- 主动讲清能力边界（哪些没做、差在哪）是加分项，不是减分项。

### 1.6 雷同风险

来源：`小哲电商Agent/简历写法指南.md`

- 同一门课出来的简历高度雷同，"上千份简历里出现等于自曝培训班出身"。
- 差异化四个动作：换场景（业务名词换、机制不动）、选切面（9 个模块只深写 2-3 个）、跑数字（自己动手跑）、定性质。
- 经历性质三档与风险递增：个人生产级实战项目（零风险）→ 远程兼职 / 小团队交付（中风险，细节追问要自洽）→ 写成实习（高风险，背调与网申核验会翻车）。

对评分的含义：与课程、模板高度雷同且讲不出自己的取舍，差异化维度直接判低分。

### 1.8 AI 产品经理岗位专项

来源：[AI产品经理岗位能力补充-2026-09-15](AI产品经理岗位能力补充-2026-09-15.md)（得到笔记分享，产品二姐 × 言e实验室，基于 BOSS 高薪岗位 JD 拆解；标杆案例作业帮 Agent 产品经理岗月薪 4 万-7 万）

**能力重心的迁移：**

| 维度 | 2023-2024 常见重点 | 2026 高薪岗位重点 |
| --- | --- | --- |
| 编排 | 简单多 Agent 协同 | 复杂多智能体调度 |
| 检索 | 基础 RAG | 复杂知识管理体系 |
| 新增重点 | — | 安全权限、全流程评测 |
| 已降权 | 提示词工程、Loop 工程 | 不再是核心考察点 |

**岗位能力的资源视角**：Agent ≈ 一套行为准则 + 可调用的工具、记忆、知识库、Skill。不同场景对四类资源的权重不同，直接决定岗位的能力要求差异。Skill 被定义为串联四类资源的调度中枢。

**三个模块只要深写 2 个即可合格**：

1. 知识库：强业务专属 + 生产 / 处理 / 更新 / 复盘四环节。
2. 记忆：记忆边界的权衡（过多导致 token 占用过高、过少降低粘性）+ 高价值记忆的筛选逻辑 + 记忆如何影响输出。
3. 评测：分层体系——知识库检索效果、记忆提取与调用效果、端到端业务效果（关联真实用户反馈）。指标必须精准定义，区分"正确""完整"等维度，不能只写提升比例。

**工具安全七类机制**：权限分级、调用白名单、调用黑名单、安全模式切换、调用前校验、调用后结果兜底、工具描述与边界限定。

**工作流与 Agent 的边界**：能说清什么场景用简单工作流、什么场景引入 Agent，优先轻量化可落地方案。

对评分的含义：以上条目构成 C 卡"Agent 机制密度"的细化判据（见第 4 节）；第 8 节的替换测试直接决定差异化维度得分。证 |

## 2. 共同底线（两张卡都适用；不通过则不计分）

### 2.1 事实底线

| 检查项 | 通过标准 |
| --- | --- |
| 事实可追溯 | 每个职位、项目、数字和开源贡献都能找到本人经历、项目材料或公开链接支撑 |
| 进度如实表达 | 已上线、已完成、在实施、已确认方案、待验证不混用 |
| 时间线一致 | 工作、项目、学习与独立实践不存在无法解释的重叠或空档 |
| 隐私与边界 | 不暴露客户隐私；疗愈相关内容不承诺医疗诊断或治疗效果 |
| 平台可填写 | 各文本字段低于平台限制；每段工作经历恰好保留 10 个技能 |

### 2.2 证据上限

以下上限避免"方案写得很完整"被当成"能力已被证明"。评分时先套上限，再打维度分。

| 条件 | 受限维度 | 上限 |
| --- | --- | --- |
| 只有课程、设计稿、规格或已确认路线，没有可运行链路与测试 / 评测记录 | C 卡机制密度；B 卡岗位匹配密度 | 满分的 60% |
| 当前 AI 项目没有真实用户、运行数据、质量记录或外部使用证据 | 两卡证据与结果维度 | 满分的 67% |
| 没有真实客户现场、交付责任或采用反馈 | C 卡岗位匹配（FDE 方向） | 满分的 53% |
| 与课程或模板高度雷同，讲不出自己的取舍 | C 卡差异化 | 满分的 30% |
| 数字说不出来源与统计口径 | 按事实底线处理，直接不通过 | — |

### 2.3 口径红线

- 未上线不得写"已上线"；未成交不得写成商业闭环；支付未接入不得写"已接入支付"。
- 人工服务成交与产品成交必须区分，不得把服务收入写成产品收入。
- 课程实战项目的场景与命名不得照搬课程原文。
- 外部不可公开的信息（客户隐私、未公开仓库细节）不得写入。
- **可套用即不合格**：把项目名与业务名词替换成任意其他场景后仍然成立的描述，属于泛化表述，必须删改（判据见 1.8 与 [AI产品经理岗位能力补充](AI产品经理岗位能力补充-2026-09-15.md) 第 8 节）。
- **自建数据须标明性质**：脱敏样本、自建集合、模拟环境可以写，但不得暗示来自真实企业生产环境。

## 3. B 卡：在线简历评分卡（BOSS / 猎聘字段版）100 分

判断机制：平台关键词检索 + HR 15 秒扫读。评分对象是在线母版及其平台字段。

| 维度 | 分值 | 满分标准 |
| --- | ---: | --- |
| 检索与关键词命中 | 15 | 目标岗位的市场通用叫法出现在求职意向、个人优势前 3 行、技能标签与经历中；分布自然，不堆砌不重复 |
| 15 秒定位 | 15 | 首 3 行说清"年限结构 + 已上线产品 + 要找什么岗"，HR 不需要猜 |
| 岗位匹配密度 | 15 | 每个目标岗位的核心要求都能在字段里找到对应证据，不靠"懂业务"这类泛称 |
| 证据与物证 | 15 | 每个主要阶段至少一条可核验结果；产品可访问、PR 可查、数字可解释 |
| 字段规范 | 10 | 各字段在平台字数内；每段经历恰好 10 个技能；经历严格倒序；无内部备注 |
| 可读与取舍 | 10 | 句子可扫读；低价值信息不挤占证据；未完成态不占据强证明位 |
| 职业连续性 | 10 | 早期工程、中期复杂服务、当前 AI 应用之间的迁移关系清楚；无空档与重叠 |
| 真实与节制 | 10 | 状态如实；不夸大；不用同一能力换关键词充数 |

## 4. C 卡：附件简历评分卡（PDF / 1-2 页）100 分

判断机制：HR 通读 + 面试官逐句对照 + 当场追问。评分对象是三个方向的附件版。

| 维度 | 分值 | 满分标准 |
| --- | ---: | --- |
| 叙事与三问结构 | 15 | 每段经历清楚回答"什么问题 → 什么机制 → 什么结果"；一页讲清主线 |
| Agent 机制密度 | 20 | 先说清可调配资源（工具 / 知识库 / Skill / 记忆）；再覆盖需求侧链路（意图、计划执行、上下文、检索、评估闭环）与企业级边界（权限、人审、降级、成本、可观测）；按 1.5 只深写 2-3 个切面，其中至少 1 个来自 1.8 的知识库、记忆、评测三模块并写到位（知识库含四环节、记忆含边界与筛选、评测含三层与精准指标） |
| 结果与数据口径 | 15 | 每条亮点带量化结果；指标有精准定义（区分正确、完整等不同判定维度）；口径能当场解释（分子分母、样本量、时间窗口） |
| 目标岗位匹配 | 10 | 三个方向各自做证据排序，不共用同一顺序；针对目标岗位突出 1-2 项核心权重能力，不做大而全通用简历；FDE 方向须体现认知回流产品 |
| 追问可防守 | 10 | 每条 bullet 对应的面试官必追问都能讲 3 分钟；讲不出的不上简历 |
| 差异化 | 10 | 场景、切面、数字为本人独有，与课程、模板、同类候选人不撞；通过替换测试——把项目名与业务名词换成任意其他场景后描述仍成立，该条判不合格 |
| 可核验物证 | 10 | 产品入口、公开 PR、可演示链路；能屏幕共享演示细节 |
| 长度与格式 | 5 | 1-2 页；无内部备注；无格式噪声 |
| 职业迁移逻辑 | 5 | 早期工程、中期服务、当前 AI 之间的迁移点明确写出 |

## 5. 发布判断

两张卡分别判断，不取平均。

| 分数 | 在线简历（B 卡） | 附件简历（C 卡） |
| --- | --- | --- |
| 85-100 | 强主简历，只按 JD 微调意向与技能排序 | 可直接投主攻方向，按 JD 调项目顺序 |
| 75-84 | 可发布，优先补工程或交付证据 | 可投，按 JD 取用对应版本 |
| 60-74 | 过渡版本，先补一个可验证项目证据 | 只投匹配度高的岗位，先补机制密度 |
| 低于 60 | 不作为主简历发布 | 暂停投递对应方向，回到事实源与定位 |

组合判断：在线 ≥75 但附件 <75 时，先修附件——能被点开却在附件阶段失分，是当前最主要的漏损形态。

## 6. 市场反馈如何进入评分

每累计 10 个同类 JD、5 次有效沟通或出现明确反馈后记录一次。反馈用于校准岗位匹配，不否定经历价值。

| 信号 | 可能说明 | 下一步 |
| --- | --- | --- |
| 有浏览、无回复 | B 卡前三项不对口 | 微调定位、意向与技能排序，不改事实 |
| 有约聊、技术面不足 | C 卡机制密度或物证不足 | 补可演示链路、评测记录、机制表述 |
| 有约聊、业务面不足 | 场景、客户、指标叙事不具体 | 补一个真实业务案例与问题拆解 |
| 被误判为传统产品 / 项目经理 | AI 与工程关键词不够靠前 | 前置 AI 应用、开源 PR、部署 |
| 被误判为纯工程师 | 产品、客户、交付结果不可见 | 前置用户流程、业务约束、验收 |
| 简历像课程作业 | 与课程或模板雷同 | 换场景、换切面、换数字 |
| 初筛通过、面试被打穿 | 写了撑不住的条目 | 按追问自检删条目，不上没把握的内容 |

## 7. 维护规则

1. 市场信号变化只改第 1 节，并更新来源标注。
2. 阶段评分、问题清单与动作写入 `delivery/YYYY-MM-DD-求职材料阶段性评估.md`；本文件只维护稳定标准。

4. 附件简历复用第 2 节共同底线，但按第 4 节分维度评分，不套用在线母版总分。
5. 第 1 节的市场信号只在累计到新的课程材料或明确反馈时更新，不追单条信息。
