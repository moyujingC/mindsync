## 文字版 JD

岗位职责：

1. 独立主导 AI Desk 全链路交付（POC -> 私有化部署 -> Agent/Skill 定制 -> 系统集成 -> 上线 -> 持续优化）
2. 直接与客户业务负责人、IT 负责人深度对话，将模糊业务诉求转化为清晰的 Agent 行为设计方案
3. 独立完成 Agent 提示词 / Memory / 评估集设计、Skill 代码开发（API 对接、脚本、浏览器自动化）
4. 负责知识库建设（文档清洗、切片策略、Graph RAG）及 ITSM / HCM / ERP 系统集成
5. 对客户业务结果负责：AI 替代率、客户 NPS、ROI，不只是“项目按期交付”
6. 将客户现场沉淀的共性能力打包成可复用 Skill，持续反哺产品

岗位要求：

3 年以上研发或产品相关经验，有 AI 产品交付工程经验，有完整的客户项目交付经历
有 LLM / Agent 真实项目经验（RAG、Function Calling、Prompt Engineering、Eval），能深入讲清楚架构设计
具备独立客户沟通能力，可独立主导需求访谈、方案讲解及现场问题应对，不依赖 PM 中转
接受客户驻场出差（通常 1-2 周 / 月）

## 职责拆解

- 做 Agent/Skill 交付全链路
- 做知识库、Graph RAG 和企业系统集成
- 直接面对客户做需求、方案和问题处理
- 对 AI 替代率、NPS、ROI 负责
- 把交付经验沉淀成通用 Skill 反哺产品

## 任职要求拆解

- 这是很标准的 FDE 样本，而且偏成熟交付型
- 要懂客户、懂交付、懂代码、懂 RAG、懂集成
- 要从“按时交付”升级为“结果负责”
- 和产品岗相比，更强调驻场、现场推进、系统落地

## 关键词提炼

- 业务关键词：客户交付、驻场、需求访谈、业务结果、NPS、ROI
- AI 关键词：Agent、Memory、RAG、Graph RAG、Function Calling、Eval
- 工具关键词：Skill、API 对接、脚本、浏览器自动化、ITSM、HCM、ERP
- 行业关键词：私有化部署、企业系统集成、AI Desk

## 匹配判断

### 匹配点

- 这是目前样本库里最标准、最完整的 FDE 岗位之一
- 它很好地定义了 FDE 不是“会点原型”或“会点产品”的模糊角色，而是结果导向的 AI 交付工程角色
- 和 KN Group 的 Builder 岗相比，它更偏客户项目交付和系统集成

### 缺口

- 需要更多同类样本来判断 FDE 市场是否普遍要求驻场和结果指标
- 城市在杭州，不是上海主市场样本
- JD 没有展开组织背景和团队分工

### 风险

- 如果把它和通用 Builder 岗混合分析，会掩盖 FDE 的客户交付属性
- 驻场、出差和客户现场推进能力是强门槛
- 这类岗位对真正项目经历的要求比一般岗位更硬

## 市场信号

- 这个岗位反映出的岗位趋势：FDE 正在被明确定义为“Agent 交付 + 系统集成 + 结果负责”的企业 AI 落地角色。
- 这个岗位对候选人的主要筛选逻辑：先看真实项目交付与 RAG/Agent/Skill 经验，再看客户沟通和系统集成能力，最后看是否能对业务结果负责。
- 这条样本后续应归入哪类观察桶：`FDE / 企业AI交付 / Graph RAG / Skill集成 / 结果导向`
