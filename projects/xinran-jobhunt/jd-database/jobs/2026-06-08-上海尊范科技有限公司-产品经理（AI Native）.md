- 城市：上海

## 文字版 JD

该岗位默认享有每天至少 2000 美金级别的 AI Token / Agent 工具预算，用于高强度产品调研、需求分析、原型验证、用户访谈、数据分析、竞品研究和 Agent 协作工作。我们希望你不是“偶尔用 AI”，而是把 Agent 当作日常协作者和产品生产力放大器。

岗位介绍

TabTin 是一个面向企业场景优化的 Agent 工作平台。我们不是在做普通 AI 聊天工具，也不是简单把大模型接进办公软件，而是在构建一个让人和 Agent 在同一个 Space 里持续工作的系统：表格、文档、PPT、浏览器、代码、终端、设备控制、任务追踪等能力都可以被 Agent 使用、协作和交付。

我们在找一位 AI Native 产品经理。

这个岗位不是传统“写 PRD、排需求、跟进迭代”的产品经理。你需要理解 AI Agent 如何改变企业工作流，能把模糊的产品方向拆成清晰的对象模型、交互流程、权限边界和验收标准；能用 Agent 做调研、原型、分析、文档和验证；也能和工程、设计一起把复杂系统推进到真实可用。

你会负责什么

- 负责 TabTin 核心产品能力规划与落地，包括 Agent、Space、Workteam、App Surface、权限、运行时、任务追踪等。
- 深入理解企业用户、AI 发烧友、开发者和知识工作者的真实工作流。
- 将复杂的 Agent 工作场景拆解为清晰的产品模型、用户路径、状态流和交互方案。
- 使用 AI Agent 辅助完成竞品研究、用户访谈整理、需求文档、原型方案、数据分析和验收测试。
- 和工程一起定义 API、数据结构、权限规则、边界状态和异常流程。
- 和设计一起打磨真实界面体验，而不是只停留在流程图和 PRD。
- 跟踪产品数据和用户反馈，持续优化激活、留存、任务完成率和用户满意度。
- 参与企业级能力设计，包括团队协作、授权、审计、审批、回滚、数据安全和工作空间治理。

我们希望你具备

- 有 AI 产品、SaaS、B 端、协作工具、开发者工具、效率工具或复杂系统产品经验。
- 具备扎实的产品抽象能力，能把复杂业务拆成清楚的对象、关系、流程和状态。
- 理解技术实现约束，能和工程讨论接口、数据模型、权限、异常和验收标准。
- 高频使用 AI 工具，或愿意快速把 Agent 融入日常产品工作。
- 能写清文档，但不迷信文档；更关注真实体验、真实用户和真实交付。
- 有较强的用户洞察能力，愿意做访谈、看数据、复盘行为路径。
- 逻辑清楚，表达直接，能在不确定问题中推动团队形成判断。
- 对 AI Agent、企业软件和下一代工作平台有强烈兴趣。

加分项

- 深度使用过 ChatGPT、Claude、Cursor、Codex、Claude Code、Gemini、Dify、Coze 等 AI / Agent 产品。
- 有开发背景，能看懂基础代码、SQL、接口文档或日志。
- 有表格、文档、知识库、自动化、工作流、RPA、低代码、企业权限系统经验。
- 有从 0 到 1 产品经验，尤其是复杂系统早期定义经验。
- 有企业客户访谈、售前、客户成功或行业解决方案经验。
- 熟悉 Figma、Notion、飞书、多维表、数据分析工具，能快速搭原型和分析流程。
- 英文阅读能力较好，能持续追踪海外 AI Agent、企业软件和开发者工具动态。
- 有很强的审美和体验敏感度，能发现“功能对了但用起来不顺”的问题。

这个岗位不适合谁

- 只想写 PRD，不愿意深入真实产品和真实用户的人。
- 不愿意理解技术对象、数据流、权限边界和工程约束的人。
- 不愿意高频使用 AI Agent 工作的人。
- 只会提“大方向”，不能拆成具体路径、状态和验收标准的人。
- 对企业软件、复杂系统、AI Agent 没有兴趣的人。
- 习惯把需求交给设计和工程后就结束，不愿意一起验收和打磨的人。

你会怎么工作

你可能会这样度过一天：

- 访谈一个企业用户，理解他希望 Agent 接管哪部分重复工作。
- 让 Agent 帮你整理访谈纪要、提炼需求、对比竞品。
- 和工程一起梳理某个 Space 权限流或 Agent 工具授权边界。
- 写出一个清楚的产品方案，包括对象关系、状态流、异常场景和验收标准。
- 和设计一起检查界面是否真的能让用户理解和完成任务。
- 在测试环境里自己跑完整流程，发现问题后推动修正。
- 根据用户反馈和数据，决定下一轮该收敛、补齐还是重做。

我们提供

- 每天至少 2000 美金级别的 AI Token / Agent 工具预算。
- 一个真正 AI Native 的产品现场，你会参与定义企业 Agent 工作平台的产品形态。
- 与创始人、工程、设计、运营、HR 和 Agent 高密度协作。
- 复杂但有价值的问题：Agent、企业协作、权限治理、运行时、App Surface、任务追踪。
- 足够大的发挥空间，不只是排需求，而是参与构建下一代工作系统。

## 匹配判断

### 匹配点

- 这条岗位把“AI Native 产品经理”写得非常完整，几乎是企业协作方向的标准画像
- 它和 Ponder 那条都属于 AI Native PM，但它更偏企业工作平台、复杂系统和权限治理
- 它把 Agent 当成 PM 的日常工作方式，而不只是产品对象，这是很强的市场信号
- 它把复杂系统产品能力、工程沟通能力和用户洞察放在同一岗位里，样本价值很高

### 缺口

- 需要继续观察是否还有更多公司会像它一样明确写出 Space、权限、运行时、App Surface 这类系统级概念
- 它的公司和产品还偏早期，话语体系可能比大公司更前沿，不一定代表市场平均水平
- 需要后续和更传统 B 端 AI PM 样本做对照

### 风险

- 这条 JD 容易把理想型 PM 描绘得过于完整，分析时要区分“真实必需”与“创始团队理想画像”
- 由于公司产品定位鲜明，这类样本对整体市场的代表性需要更多同类样本验证
- 它的 AI Tool 预算和高密度 Agent 协作方式可能是少数团队特征，不应直接外推

## 市场信号

- 这个岗位反映出的岗位趋势：AI Native 产品经理正在从“会做 AI 产品”升级为“能在企业复杂系统里，把 Agent、权限、空间、运行时和协作机制一起定义出来”的系统型 PM。
- 这个岗位对候选人的主要筛选逻辑：先看复杂系统抽象与企业工作流理解，再看是否高频使用 Agent 工作，最后看技术沟通、用户研究和产品打磨能力。
- 这条样本后续应归入哪类观察桶：`AI Native PM / 企业协作平台 / 复杂系统 / 权限治理 / Agent工作平台`
