## 三、同步规则（事实 → 论点 → 投递材料）

事实或口径变化时，按固定顺序改，一次提交完成：

1. 先改 `职业经历全量报告.md`（事实唯一来源，追加到校准增量一节）。
2. 涉及能力主张、证据排序或选岗口径 → 改 `02-三岗位认知卡.md`。
3. 涉及 BOSS 在线字段 → 同步 `09-总在线简历-BOSS版.md`。
4. 涉及附件投递 → 同步受影响的 `06/07/08` 分职位简历。
5. 只影响面试表达或作品展示 → 更新自我介绍、作品集或问答材料，不反向污染事实源。

禁止在某一份简历里单独发明项目事实。

## 四、日常投递轻量流程

看到一个岗位时，不先改简历，只做三步：

1. **判方向**：AI 应用工程师用 `06`；FDE / AI 解决方案用 `07`；AI 产品经理用 `08`。
2. **判是否值得定制**：只有目标公司重要、JD 高匹配、HR/猎头明确反馈、或 JD 暴露当前简历硬缺口时，才定制。
3. **最多改 3 处**：标题 / 求职意向、个人优势前 2-3 行、一个项目 bullet 或项目排序。单条 JD 不重写事实源和全套简历。

## 五、投递前 60 秒红线检查

每次发出前只查以下 8 项：

1. 是否用了正确方向的 active 简历：`06/07/08`。
2. 文件名和求职意向是否一致。
3. 电话、邮箱、城市、链接是否正确。
4. 是否出现期望薪资。
5. 是否还有“写作说明 / 投递前删除 / 选岗提醒 / 内部备注”。
6. 支付口径是否为：**内测兑换码模式运行中，在线支付接入中**。
7. 是否出现禁用旧口径：育碧 / Ubisoft、成熟商业化平台、已接入支付系统、医疗诊断、心理治疗。
8. 所有强数字是否能解释来源和统计口径。
