#### 项目描述

Miro 是「一镜一梳」的产品线重做版本，把服务对象从"来访者直接使用"改为"疗愈师使用"——来访者不接触产品，交付物为报告文件。它不是功能扩展，而是为补上已上线 To C 版的三个硬伤：生成过程无审计（中间产物不留痕、结论无法回溯）、输出质量无评估（好与坏没有判据）、To C 形态本身风险与责任边界不清。

架构采用"通用底座 + 流派插件 + 应用工作流"三层可插拔设计，MVP 双核心为 WF-01 解读报告生成与 WF-02 报告问答（「解读参谋」与「应答准备」两个场景，均面向疗愈师，不直接面对来访者）。这是一个设计先行的项目：先完成合计 3,600+ 行设计文档（两份四层 Spec、知识库与 RAG 工程化设计、评估方案与评测治理、验收指标字典），再动手写代码。

当前进展（2026-09-23）：后端已落地（FastAPI），输入预处理六步链路黄金集 18/18 通过，报告生成端到端跑通并出两版报告，报告问答已实现并完成 18 问真实评测；前端预留未建，尚未进入真实疗愈师共创。

#### 项目职责

本人担任独立产品负责人与技术推进者，负责定位重定义、架构分层、知识库与本体论、生成链路设计、评估与安全体系、输入预处理方案及全部 Spec 与验收设计；工程实现以 AI 结对方式完成。核心工作：

- **四层 Spec 方法论**：设计层（含"绝对不做"硬边界）→ 控制层（异常路径总表，逐条预设处理规则）→ 工程层（红线优先、工具白名单与调用序列写死）→ 验收层（先写可验证的量化指标与验收用例），文末必带未决事项清单。
- **可信边界三层**：① 确定性几何移出 AI——图像矫正与圈界标记由程序完成、疗愈师确认后"买定离手"；② 识别权交给视觉模型，程序退到像素验证位只标注不否决；③ 来源标注精确到稳定规则 ID（如 IM-07）与原文引句，缺标注视为不完整、禁止输出。
- **薄路由而非厚编排**：主 Agent 调度层只做"接什么活 / 交给谁 / 怎么兜底"，不做规划不迭代；护栏、知识库、工具白名单、会话与 trace 全部沉到通用底座。MVP 由人在入口显式指定 Agent，自动意图判别留到 Agent 数量上来之后。
- **不引入第三方 Agent 框架**：架构文档原写 Smolagents，但 spec 红线要求固定编排 + 规则代码、实际代码也无框架依赖，改为自研薄编排，并把"引入框架"设为触发条件式（3+ Agent 稳定协同 / 状态持久化 / 企业级安全）。
- **两个 Agent 的职责边界与数据契约**：解读 Agent 只写不读（产出报告正文、三级链路产物与 trace 落盘），问答 Agent 只读不写（消费报告与链路产物、按需注入 trace）；回答依据以链路产物为准、正文为辅。
- **问答 Agent 的双场景分化**：同一 Agent 按场景配置——「解读参谋」（专业、深、多视角，L1，不限轮次）与「应答准备」（通俗可转述、给可能性不给定论、附边界口径提醒，L2，≤15 轮）；助手永不直接面对来访者。多轮历史为窗口原文保留 + 超窗滚动摘要 + 轮次硬限，每轮问答（含护栏拒绝与降级话术）落盘留痕。
- **工具白名单与写死的调用序列**：6 个工具（报告检索 / 状态查询 / 知识库检索 / 因果链推理 / 五行推理 / 疗愈方案查询），按 6 类问题各自写死调用顺序、前序输出作后序输入，序列之外一律禁止调用。

#### 项目业绩

- 从 0 建立曼陀罗疗愈领域知识库：8 类文档 → 267 个结构化知识单元、10.2 万字符、23 个本体状态；建成稳定规则 ID 体系（颜色域 C / 组合模式 CP / 失衡模式 IM / 直断法 D / 状态 S），报告引用可逐条审计。
