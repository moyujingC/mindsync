## AI 产品实践

### AI-Mandala（一镜一梳）｜AI 曼陀罗解读 Web MVP

面向 To C 用户的曼陀罗绘画上传与解读产品，将上传画作、三圈识别、Lite / Pro 报告、付费升级和报告追问收束为手机端 Web MVP 主路径。

- **产品定义**：从疗愈服务中的人工解读耗时痛点出发，定义 To C 用户主路径：上传画作 → 生成 Lite 报告 → 从 Lite 升级 Pro → 查看权益内容 → 围绕本次报告继续追问。
- **MVP 收束**：明确当前只聚焦 mobile-web 与 To C 主产品，不扩张 To B、Studio、V3 实验线或完整 App，避免早期产品范围失焦。
- **商业路径**：设计 Lite / Pro 权益关系，Lite 作为首次体验入口，Pro 只能从 Lite 后升级，不提供独立购买入口，降低用户理解和权限恢复复杂度。
- **AI 报告链路**：参与设计 two-pass e2e 报告生成链路，先生成可复用视觉基准，再结合 prompt pack、议题规则和输出规范生成 Lite / Pro 报告。
- **安全边界**：为报告和“曼曼”追问定义边界，不做心理诊断、医疗建议、投资建议、长期陪伴或重大人生决策，追问只绑定本次画作和报告。

### MindSync｜AI 一人公司工作系统 / Monorepo 实践

自建 AI 工作系统，用 Monorepo 管理公司治理、项目入口、角色定义、知识库、共享工具和阶段 artifact，支撑 AI 产品、研究、内容和求职材料等多项目并行。

- **系统产品思维**：将复杂工作系统拆分为 `agents / company / projects / shared / knowledge-base` 五层，让角色、规则、项目、工具和长期知识各有入口。
- **工作流设计**：通过项目注册表、spec、task、QA、delivery、handoff 等 artifact，把聊天式 AI 协作转成可追踪、可交接、可复用的工作流。
- **AI 协作边界**：区分 MindSync 与 Paperclip 的职责，MindSync 承接治理源、文档源、实现源和知识源，Paperclip 承接运行时控制面和任务状态面。
