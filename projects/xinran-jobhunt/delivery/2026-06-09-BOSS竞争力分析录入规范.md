# BOSS 竞争力分析录入规范

> date: 2026-06-09
> scope: projects/xinran-jobhunt/jd-database
> owner: Codex

## 1. 为什么要单独记录这部分

BOSS 的竞争力分析不是附属信息。

它至少能补充三类判断：

1. 平台算法把你低估在什么地方
2. 这个岗位更像哪一种真实职责桶
3. 低分到底来自简历表达问题，还是来自岗位本身是混合画像

所以后续只要你发了这类截图，就默认并入单条 JD 文档。

## 2. 标准录入位置

单条岗位文档固定顺序如下：

1. frontmatter
2. 岗位摘要
3. 文字版 JD
4. `BOSS 竞争力分析（可选）`
5. 职责拆解
6. 任职要求拆解
7. 关键词提炼
8. 匹配判断
9. 市场信号

## 3. frontmatter 约定

如果该岗位带有 BOSS 竞争力分析，frontmatter 中写：

```yaml
boss_competitiveness_available: true
```

如果没有，就写：

```yaml
boss_competitiveness_available: false
```

## 4. 必录字段

只要截图里能看到，就尽量录入这些字段：

### 总体排名

- 排名
- 超过百分比

### 简历匹配度

- 简历匹配度 PK
- 当前所在区间

### 学历 PK

- 超过百分比
- 岗位要求学历
- 平台提示

### 工作经验 PK

- 超过百分比
- 当前被平台归到的经验档位

### 期望薪资 PK

- 超过百分比
- 当前期望薪资区间
- 岗位薪资范围

### 沟通进度 PK

- 超过百分比
- 当前状态
- 其他候选人所处状态

## 5. 分析时必须额外补的三句话

如果一条岗位带 BOSS 竞争力分析，在 `匹配判断` 下必须额外写：

1. `平台低估的点`
2. `可能被算法忽略的真实优势`
3. `这是简历表达问题，还是岗位混合画像问题`

## 6. 当前最值得重点积累的样本

后续优先积累这几类带 BOSS 分析的岗位：

1. 标题写 `AI产品经理`，实际偏方案 / 咨询 / 交付
2. 标题写 `FDE`，但实际偏 Demo / 低代码 / 客户交付 / 系统集成中的某一种
3. 标题写 `解决方案架构师`，但内部差异很大
4. 平台分低，但招聘方真人继续沟通或主动要简历

## 7. 当前不要做的事

现阶段不要因为单条岗位分低，就立刻回头改简历。

更合理的顺序是：

1. 先累计更多“JD + BOSS 分析”配对样本
2. 找出平台持续低估你的共性模式
3. 再决定三版简历分别怎么调

这样改动才会更稳，不会被个别岗位带偏。
