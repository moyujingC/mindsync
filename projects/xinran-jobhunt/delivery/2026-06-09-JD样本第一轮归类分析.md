## 2. 当前三条主线

### A. AI 产品经理线

这是当前样本最多的一条线，但内部差异也最大。不能再把它当成一个统一桶。

当前至少已经分出 5 个子类：

1. `AI Native 协作 / 知识工作型`
   - 样本：
     - `北京寻途未来科技-AI Agent产品经理（小而美AI Native团队）`
   - 特征：
     - 强调用户工作流、Agent 交互、Vibe Coding、MVP、协作工具

2. `AI Native 企业平台 / 复杂系统型`
   - 样本：
     - `上海尊范科技有限公司-产品经理（AI Native）`
   - 特征：
     - 强调企业协作平台、权限治理、运行时、App Surface、复杂系统抽象

3. `商业化 / 广告投放增强型`
   - 样本：
     - `上海某大型电子商务公司-商业化-AI Native产品经理`
   - 特征：
     - 本质仍是电商广告 / 商业化产品，AI 更多是增强项

4. `电商服务 / 智能客服 Agent 型`
   - 样本：
     - `拼多多集团-PDD-Agent智能服务产品`
   - 特征：
     - 面向售前、售后、客服、人机协同和 NLU 向 LLM + Agent 迁移

5. `垂直场景教育科技型`
   - 样本：
     - `北京软通动力教育科技有限公司-AI产品经理（高校方向）`
   - 特征：
     - 面向高校、实训、实验室、课程资源和培训产品

补充说明：

- `字节跳动-AI Builder产品实习生` 更像实习样本，不适合和全职样本直接并列判断。
- `上海瀚讯信息技术股份有限公司-AI native产品原型 Builder` 是 AI PM 和 Builder 之间的混合型样本，更像原型 / Demo 驱动角色。

### B. AI 转型咨询 / 解决方案线

这条线样本数虽然少于 `ai-pm`，但内部结构已经很清楚。

当前至少分出 3 个子类：

1. `方案型 AI 产品经理 / 企业级 AI 方案岗`
   - 样本：
     - `英湃（成都）科技有限公司-AI产品经理`
   - 特征：
     - 业务抽象、方案设计、技术理解、交付推进、知识闭环、行业数字化

2. `工程型 AI 解决方案架构师`
   - 样本：
     - `某大型互联网上市公司-AI解决方案架构师`
   - 特征：
     - 强代码、强 POC、强售前、强技术布道、强 SDK / Demo 资产沉淀

3. `业务增长 / 客户解决方案型`
   - 样本：
     - `蚂蚁集团-客户技术解决方案架构师-AI方向`
   - 特征：
     - 强客户需求洞察、强行业机会判断、强原型、强生态共建、强业务增长目标

另外出现了一个很重要的新子类：

4. `AI 业务赋能 / AI Ops / 内部转型推进型`
   - 样本：
     - `艾特士信息咨询（成都）有限公司-AI应用业务伙伴`
   - 特征：
     - 强 Prompt、强 Agent、强 Skill、强 MCP（模型上下文协议）、强知识库治理、强内部推广和 AI 化落地

这说明 `ai-consulting` 不应只理解成“咨询公司顾问”，它至少包含两大层：

- 面向客户的方案 / 架构 / 交付角色
- 面向企业内部的 AI 落地赋能 / AI Ops 角色

### C. FDE / Builder / 交付工程线

当前样本数最少，但角色定义最清楚。

当前可分为 3 种靠近关系：

1. `标准 FDE / 企业AI交付型`
   - 样本：
     - `网易-FDE工程师`
   - 特征：
     - 全链路交付、私有化部署、系统集成、Graph RAG、客户结果负责

2. `Builder / 业务工具搭建型`
   - 样本：
     - `美团-AI Builder（自营维修项目）`
     - `KN Group-AI Builder`
   - 特征：
     - 强 Agent、Workflow、AI Coding、RAG、知识库、Demo、业务落地

3. `原型 / Demo 驱动型混合角色`
   - 样本：
     - `上海瀚讯信息技术股份有限公司-AI native产品原型 Builder`
   - 特征：
     - 强原型、强页面、强展示脚本、强轻量开发、强里程碑交付

这条线当前最明显的共性是：

- 要求候选人“自己动手”
- 对代码、集成、自动化、部署、可复用能力有明确要求
- 很多岗位要求直接对接客户或业务负责人，而不是只对内协作

## 3. 当前最清楚的市场主线

如果只看已经积累的样本，当前最清楚的主线其实不是一个，而是下面四条：

1. `AI Native 产品经理`
2. `企业级 AI 方案 / 架构 / 转型推进`
3. `FDE / Builder / Agent 交付工程`
4. `电商场景 AI 产品`

其中第 4 条其实是场景线，不是岗位线。它横跨了：

- 商业化广告
- 智能客服 / 售后服务

所以更准确的说法是：

- 岗位主线有 3 条
- 行业主线里，`电商` 已经足够明显，是需要单独观察的一条垂直行业线

## 5. 现在能先下的几个判断

### 判断 1：`AI PM` 已经不是一个岗位，而是一组岗位

至少要拆成：

- AI Native 产品经理
- 商业化 / 电商广告 AI 产品
- 电商服务 / 客服 Agent 产品
- 教育科技 / 高校场景 AI 产品

如果后面继续把这些岗位混成一个总类，分析会失真。

### 判断 2：`AI Native` 不是稳定的岗位定义，而是一个被不同岗位借用的标签

当前样本里，“AI Native”至少有三种用法：

1. 真正的新工作方式和产品形态
   - 例：Ponder、TabTin
2. 原型 / Demo / 快速交付能力
   - 例：上海瀚讯
3. 传统商业化产品的 AI 升级版
   - 例：匿名电商广告岗

所以后面看到带 `AI Native` 的 JD，不能直接判成同类岗位。

### 判断 3：`FDE` 与 `Builder` 相关，但不完全相同

当前样本显示：

- `Builder` 更像强调从想法到工具 / 原型 / 工作流的搭建能力
- `FDE` 更像强调面向客户和企业场景的交付、部署、集成与结果负责

两者有交叉，但不能合并。

### 判断 4：`AI 转型咨询` 也不是单一职业桶

当前至少可拆：

- 方案型 AI 产品经理
- 工程型解决方案架构师
- 大厂客户解决方案 / 业务增长型架构师
- AI 业务赋能 / AI Ops

这条线的共性不是“都在咨询公司”，而是：

- 都在做复杂业务问题到 AI 落地之间的转译和推进

## 6. 当前边界样本

这些样本不是没价值，而是更适合作为边界参考，不适合代表主流目标市场：

1. `字节跳动-AI Builder产品实习生`
   - 原因：实习岗，在校生硬门槛，和当前全职主市场口径不同

2. `北京软通动力教育科技有限公司-AI产品经理（高校方向）`
   - 原因：高校教培、校企合作、培训产品导向较强，和当前主样本群差异大

3. `上海瀚讯信息技术股份有限公司-AI native产品原型 Builder`
   - 原因：更像原型 / 展示驱动的短周期岗位，适合作为混合样本参考

## 8. 对你当前策略的直接含义

基于这轮样本，当前最合理的求职地图不是“三份简历对应三个模糊方向”，而是：

1. `AI 产品经理`
   - 重点盯：
     - AI Native 产品
     - 企业平台型 AI PM
     - 电商服务 / 商业化里更适配的 AI PM

2. `AI 转型咨询顾问`
   - 重点盯：
     - 方案型 AI 产品经理
     - 客户解决方案架构师
     - AI 业务赋能 / AI Ops / 转型推进

3. `FDE`
   - 重点盯：
     - Agent 交付
     - Skill / MCP / RAG 集成
     - 企业系统接入与客户结果负责

也就是说，当前三条主线是成立的，但每条线内部都已经能看到更细的子类。
