## 2. 作品一：AI-Mandala（一镜一梳）｜AI 曼陀罗解读 Web MVP

### 2.1 项目一句话

AI-Mandala / 一镜一梳是面向 To C 用户的曼陀罗绘画上传与解读 Web MVP，围绕上传画作、三圈识别、Lite / Pro 报告、付费升级和报告追问构建最小产品闭环。

### 2.2 背景问题

曼陀罗解读属于高信任、感性、非标准化的服务场景。人工解读耗时高，公域获客与深度交付之间容易出现精力瓶颈。

项目需要解决的问题不是“让 AI 给结论”，而是：

- 如何让用户上传画作后得到一份可阅读、温和、不过界的报告。
- 如何把人工解读流程收束成产品路径。
- 如何在 AI 输出中保留画面证据、三圈带读和安全边界。

### 2.3 我的角色

负责产品定义、MVP 范围收束、用户主路径设计、AI 报告生成链路设计和安全边界梳理。

### 2.4 我做了什么

- 定义 To C 主路径：上传画作 → 生成 Lite 报告 → 从 Lite 升级 Pro → 查看 Pro 权益 → 围绕本次报告继续追问。
- 收束 MVP 范围：当前聚焦 mobile-web 和 To C 主产品，不同时扩张 To B、Studio、V3 实验线和完整 App。
- 设计 Lite / Pro 权益关系：Lite 作为首次体验入口，Pro 只能从 Lite 后升级，不提供独立购买入口。
- 参与设计报告生成链路：先生成可复用视觉基准，再结合 prompt pack、议题规则和输出规范生成报告。
- 定义“曼曼”报告陪读和追问边界：只围绕本次画作和本次报告，不做长期陪伴、心理咨询、医疗诊断或重大决策建议。

### 2.5 当前状态

- 已形成 To C Web MVP 产品规范。
- 当前用户端主入口为手机端 Web。
- 当前主路径覆盖上传、Lite / Pro 报告、Pro 升级、报告追问和历史记录。
- 解读智能体架构采用 two-pass e2e：Vision Pass 生成可复用视觉基准，Reasoning Pass 生成议题报告。

### 2.6 证明的能力

- 从真实服务痛点定义 AI 产品。
- MVP 范围收束。
- 用户主路径和付费路径设计。
- Agent / prompt pack / quality gate 工作流设计。
- 高信任场景中的 AI 输出边界意识。

### 2.7 可展示材料 / 来源

- `projects/aimandala/docs/specs/ToC-MVP-产品规范.md`
- `projects/aimandala/docs/architecture/解读智能层-曼陀罗解读智能体架构.md`
- `projects/aimandala/docs/specs/2026-05-30-曼曼-avatar报告陪读与追问-handoff.md`

### 2.8 表达边界

不表达为：

- 医疗、心理诊断或心理治疗产品。
- 已经大规模商业化。
- 已服务大量用户。
- 已完成完整 To B / Studio / App 产品。

## 3. 作品二：MindSync｜AI 一人公司工作系统 / Monorepo 实践

### 3.1 项目一句话

MindSync 是自建 AI 一人公司工作系统，以 Monorepo 管理公司治理、项目入口、角色定义、知识库、共享工具和阶段 artifact，支撑多个项目并行推进。

### 3.2 背景问题

同时推进 AI 产品、研究、内容、求职材料和系统建设时，信息很容易散落在聊天记录、运行时系统、历史仓库和临时操作里。

如果没有稳定结构，会出现：

- 规则找不到。
- 项目入口不稳定。
- Agent 每次都像第一次进入现场。
- 交付物无法追踪和复用。

### 3.3 我的角色

负责系统设计、信息架构、项目注册表、文档治理、角色边界和 AI 协作流程设计。

### 3.4 我做了什么

- 将系统拆分为 `agents / company / projects / shared / knowledge-base` 五层。
- 用项目注册表管理 product、capability、brand 等对象。
- 将 spec、task、QA、delivery、handoff 等阶段 artifact 固化到项目中。
- 区分 MindSync 与 Paperclip 的职责：MindSync 是治理源、文档源、实现源和知识源，Paperclip 是运行时控制面和任务状态面。
- 用 Docs as System 的方式，让 AI 协作不只停留在聊天输出，而能沉淀为可交接、可验证、可回写的工作流。

### 3.5 当前状态

- 已作为公司内核 + 多项目工作区 Monorepo 使用。
- 已承载公司治理、角色定义、项目入口、共享工具和长期知识库。
- 已用于 AI-Mandala、RelayHub、馨冉求职等多个项目的持续推进。

### 3.6 证明的能力

- 复杂系统拆解。
- AI 协作流程设计。
- 知识治理。
- 多项目管理。
- 文档即系统。
- 把模糊任务转成可分派、可验证、可交接的工作流。

### 3.7 可展示材料 / 来源

- `AGENTS.md`
- `COMPANY.md`
- `MONOREPO.md`
- `company/knowledge-base/system/MindSync-设计机制分析.md`

### 3.8 表达边界

不表达为：

- 成熟企业级 SaaS。
- 已商业化客户系统。
- 大团队协作平台。
- 完全自动化 Agent 公司。

## 4. 作品三：RelayHub｜模型接入、评测与优化决策能力

### 4.1 项目一句话

RelayHub 是公司级共享模型能力项目，用于把个人开发、产品生产和旁路评测中的模型接入与优化决策收束到同一治理框架。

### 4.2 背景问题

AI 应用落地时，模型使用经常混在一起：

- 个人开发需要比较第三方中转、国产模型和免费国外 API。
- 产品生产需要更稳定、更可控、更合规的模型接入策略。
- 公司层面需要把模型测评、成本优化和供应商选择沉淀成可复用能力。

如果开发实验、生产数据和评测逻辑混用，会带来隐私、成本、质量和稳定性风险。

### 4.3 我的角色

负责产品 / 架构边界定义、控制台信息架构、运行形态拆分与试用链路收束。

### 4.4 我做了什么

- 定义三类运行形态：
  - `dev-relay`：服务个人开发工作流和 Claude Code / Codex 等编码代理场景。
  - `prod-relay/<product>`：服务产品生产流量，强调隐私治理和任务级路由。
  - `eval-sidecar`：服务 benchmark、探活、日报、评分板和优化建议。
- 明确生产边界：心理疗愈应用生产版只允许国产模型，第三方中转不进入生产用户数据主链路，不默认记录正文敏感数据。
- 设计控制台信息架构：Dashboard、Environments、Providers、Routes、Usage、Eval、Policies、Runs、Settings。
- 将 RelayHub v1 定义为公司级共享能力，而不是大而全的 AI Gateway。

### 4.5 当前状态

- 已形成 RelayHub v1 产品与架构定义。
- 已有控制台信息架构草图。
- 已推进 release 静态试用入口和只读 provider 试点。

### 4.6 证明的能力

- AI 模型接入治理。
- 开发 / 生产 / 评测边界设计。
- AI 基础设施产品的信息架构。
- 质量、成本、隐私和稳定性之间的权衡。
- 将底层能力抽象为可复用 company capability。

### 4.7 可展示材料 / 来源

- `projects/relayhub/specs/2026-04-16-RelayHub-v1-架构与产品定义.md`
- `projects/relayhub/specs/2026-04-16-RelayHub-v1-控制台信息架构草图.md`
- `projects/relayhub/delivery/2026-04-18-v1-relayhub-console-release-节点静态试用入口-交付说明.md`

### 4.8 表达边界

不表达为：

- 已上线完整 AI Gateway。
- 已承载大规模生产流量。
- 已实现智能路由 / 自动切流。
- 已完成企业级管理后台。
- 成熟 MLOps 平台。

## 5. 作品四：房产定制化方案与经纪人孵化体系

### 5.1 项目一句话

在房产咨询工作室中，以单边代理和客户利益优先为原则，为客户提供定制化房产方案，并将一线服务经验沉淀为经纪人孵化和培训体系。

### 5.2 背景问题

房产交易是高金额、高风险、高信任的复杂决策。客户表面上常说“想买大房子”或“想卖高价”，但真实问题往往涉及家庭关系、资金安全、资产配置、居住体验、市场周期和交易风险。

### 5.3 我的角色

创始合伙人、一线业务打样者、咨询方案设计者和后期经纪人孵化体系参与者。

### 5.4 我做了什么

- 用真实市场数据映照客户需求，帮助客户识别表层诉求背后的真实取舍。
- 为客户设计买房、卖房、信贷、装修、售前美化、民宿运营、出租管家等方案。
- 负责落地推进，整合执行人力、行业资源、交易节点和风险控制。
- 后期参与建立经纪人孵化体系，提供分佣模式、知识库、SOP、法务财税和长期陪跑支持。

### 5.5 结果

- 2 经纪人 + 2 助理产出约等于传统 20 人门店年营收，约 200 万 / 年，且成本更低。
- 70% 客户来源于转介绍。
- 累计孵化 30+ 经纪人。
- 零基础新人成长周期可缩短到约 6 个月。

### 5.6 证明的能力

- 高信任需求洞察。
- 定制化方案设计。
- 复杂流程推进。
- 资源整合和风控。
- 培训体系和知识沉淀。
- AI 转型咨询岗位所需的业务理解与落地陪跑能力。

- `projects/xinran-jobhunt/职业经历全量报告.md`
- `projects/xinran-jobhunt/specs/2026-04-27-职业叙事基础档-SPEC.md`
- `projects/xinran-jobhunt/delivery/2026-04-29-核心STAR案例库.md`

### 5.8 表达边界

不表达为：

- 传统中介撮合。
- 大规模组织管理。
- 标准化 SaaS 产品。
- 管理几十人团队。

这四个作品共同证明：

1. 我能从真实问题出发，而不是从工具或概念出发。
2. 我能把复杂、敏感、非标准化场景拆成可执行路径。

5. 我理解 AI 落地中的边界问题：质量、隐私、合规、安全、成本和用户理解都需要被设计进去。
