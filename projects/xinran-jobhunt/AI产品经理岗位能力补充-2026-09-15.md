## 1. Agent 怎么被定义：可调配的资源决定形态

- 核心结论：**Agent 可调配的资源，才是定义 Agent 的核心方式**。
- 基础可调配资源清单四类：**工具、知识库、Skill（技能）、记忆**。
- 不同业务场景下的 Agent，对四类资源的权重需求完全不同，这直接决定了对应 Agent 产品经理的能力要求差异。
- 定义式表达：**Agent ≈ 一套 Agent 行为准则 + 可调用的工具、记忆、知识库、Skill 等配套资源**。

对简历的含义：写 Agent 项目时先说清"这个 Agent 能调动什么资源"，比罗列架构名词更能区分层次。

## 2. 工具安全的七类管控机制

1. 工具权限分级
2. 调用白名单
3. 调用黑名单
4. Agent 安全模式切换
5. 工具调用前校验
6. 工具调用后结果兜底保障
7. 工具本身的精准描述与边界限定

对简历的含义：本人现有事实可覆盖第 5、6、7 类（识别失败校验、失败保守降级、工具与追问的边界限定）；第 1-4 类（权限分级、黑白名单、安全模式）未见对应事实，属工具治理缺口。

## 3. 工作流与 Agent 的边界

- 要清晰掌握「传统工作流」与「Agent 化工作流」的适用边界：什么场景用简单工作流，什么场景引入 Agent 能力。
- 原则：优先轻量化可落地方案，避免过度设计复杂框架。

对简历的含义：能写出"哪里故意不用 Agent"的取舍，比通篇 Agent 更能体现产品判断。一镜一梳的 two-pass / single-pass 取舍、Lovable v1 报废决策，都属于这类证据。

## 4. 记忆模块的设计要求

- 核心能力是高效沉淀系统化、持续迭代的用户记忆，避免无效信息冗余，保障记忆的精准性与可追溯性。
- 记忆边界的权衡：记忆内容过多会导致 token 占用过高、引发模型性能下降；记忆内容过少会降低用户粘性。
- 需要说清筛选高价值记忆信息的设计逻辑。
- 对长期陪伴型 Agent，记忆能力是核心基本功，要明确记忆如何影响 Agent 的回答输出。

对简历的含义：这是当前最明确的缺口。一镜一梳有"历史记录"功能，但没有记忆分层、记忆筛选、记忆影响输出的设计表述。写记忆模块前先在事实源确认有没有对应实现，没有则不写。

## 5. Skill 的定义与调试要求

- Skill 是串联知识库、Agent 工具、工作流、记忆四类资源的综合能力；任意一类资源权重提升都会直接拉高 Skill 的能力等级，是指导 Agent 调用各类资源的核心调度中枢。
- 实操提醒：Skill 开发完成后不能直接上线，必须投入至少 2 天反复调试校验；忽略这一步会导致 Skill 可用性极低、最终被弃用。

对简历的含义：这条是可直接使用的面试弹药——"Skill 开发后要留独立调试期"是做过的人才会说的话。

## 6. 产品路线图的两条路径

- **存量 SaaS 迭代路径**：优先把原有成熟功能改造为 Agent 可识别调用的工具，先留存老客户，再拓展新场景。
- **AI 原生路径**：直接切入核心痛点场景。举例：热点选品——通过 MCP 工具获取全网热点数据，再调用专属选品 Skill 完成分析输出。

对简历的含义：一镜一梳属 AI 原生路径。若投递存量 SaaS 转 AI 的公司，需补一条"老功能工具化"的经历或判断，目前材料里没有。

## 7. 2026 年 AI 产品经理招聘趋势

来源：产品二姐 × 言e实验室，基于 BOSS 平台高薪岗位 JD 拆解；标杆案例为作业帮 Agent 产品经理岗，月薪 4 万-7 万。

- 能力重心已从传统 workflow 全面转向 Agent 方向。
- 趋势认知迭代（2023 → 2026）：
  - 简单多 Agent 协同 → **复杂多智能体调度**
  - 基础 RAG → **复杂知识管理体系**
  - **安全权限、全流程评测**成为本阶段新增核心重点
- **提示词工程、Loop 工程已不再是 2026 年高薪 Agent 岗位的核心考察重点**，重心转向智能体体系化设计。
- 不同企业的 Agent 产品经理能力要求差异明显，求职前需针对目标岗位做能力维度权重分析，避免通用化准备。
- 提升通过率的三个动作：
  1. **JD 隐含任务拆解**：从 JD 的一句话描述延伸出背后的落地任务，把相关实践经验精准写进简历。
  2. **赛道与竞品参照物梳理**：面试时能清晰表达对赛道产品的差异化理解。
  3. **趋势认知迭代**：用 2026 年的标准而非 2023 年的概念作答。

对简历的含义：三条趋势里，"安全权限 + 全流程评测"本人可以补（评测已有 golden case 与 A/B；权限有私有存储与签名 URL）；"复杂多智能体调度"仍无事实对应。提示词工程不再是重点，意味着简历不必再铺 Prompt 相关表述。

## 8. AI 项目简历的优劣判别方法

### 反面案例的特征（原文以投递作业帮的"智能教学 agent 项目"为例）

项目描述仅为：负责项目架构与升级、精细化运营，使课件任务解决力提升 10% 达到 B+ 等级，设计闭环 agentic workflow，建立评测局域监控模板，优化召回率等指标，提及 SDD / TDD 等技术名词。

判定不合格的原因：**完全没有专属业务属性**。把项目名换成"法大大法律审核 agent""医疗 agent"等任意场景，所有描述依然可以直接套用。面试官一眼能识别内容虚假——求职者只是零散听过术语，不理解术语之间的业务关联逻辑。

### 合格标准：不需要覆盖所有模块，深写 2 个即可

| 模块 | 合格标准 |
| --- | --- |
| 知识库 | 体现强业务专属属性，标注知识库覆盖的专属业务内容；拆解出**生产、处理、更新、复盘** 4 个完整落地环节；让内容无法被其他业务场景直接套用 |
| 记忆 | 说清记忆边界的思考：过多导致 token 占用过高、过少降低粘性；说明筛选高价值记忆的设计逻辑；明确记忆如何影响 Agent 的回答输出 |
| 评测 | 通用必备，搭建**分层评测体系**三个维度：① 知识库检索效果评测；② 记忆提取与记忆调用效果评测（例：验证 Agent 能否基于用户"价值型投资者"的记忆标签，输出匹配偏好的投资分析）；③ 端到端业务效果评测，直接关联 C 端 / B 端用户真实反馈 |

### 指标细节要求

所有项目成果指标必须有精准定义。例如知识库检索效果要明确区分"正确""完整"等不同维度的判定标准，不能只笼统标注提升比例。

### 投递策略

**投递岗位前不要制作大而全的通用简历**，必须针对性匹配目标岗位的核心能力权重，着重突出 1-2 项与岗位强相关的核心优势。

## 9. "三无"困境与零资源落地

三类资源缺失（行业称"三无"）：

1. 无真实用户数据：缺少支撑个性化应答的用户身份、标签、画像数据。
2. 无真实知识库 / 问答数据：缺少企业私有知识库、垂直场景历史问答沉淀。
3. 无真实外部系统支持：想对接传统业务系统时没有现成系统。

原作者的判断与建议：

- 三类问题都有低成本、可落地的解决方式（具体方案表在分享页未展开）。
- 面试官核心考察的是 Agent 产品设计、落地能力，而非数据是否来自企业真实生产环境；讲清设计逻辑与实现路径即可获得认可。
- 掌握数据生成与资源整合原理后可自主生成任意规模的项目所需数据。
- 普通学习者约 1 个月可独立搭建符合上述框架的 Agent 产品原型。

## 10. 与本人事实底线的冲突及处理（必须遵守）

| 原作者口径 | 本人处理 |
| --- | --- |
| 数据不必来自真实生产环境 | 可以用脱敏样本、自建集合、模拟环境，但必须在简历与面试中明示性质，不得暗示来自真实企业客户 |
| 讲清设计逻辑即可获得认可 | 接受；但"已上线""已交付""已有客户"三类状态词继续严格对应真实状态 |
| 1 个月可搭出符合框架的原型 | 作为补项目的时间预期，不写进简历；简历只写已完成且可解释的部分 |

违反上述处理的后果是面试追问阶段被打穿，整份简历连带失信。
