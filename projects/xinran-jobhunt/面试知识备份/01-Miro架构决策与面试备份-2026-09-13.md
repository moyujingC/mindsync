## 1. 已拍板的架构决策（2026-09-13 聊透）

### D-1 知识供给：全量灌，不是检索

| 项 | 内容 |
|---|---|
| 判断 | 知识库文档 **10.2 万字符 ≈ 5-8 万 token**，长上下文模型窗口装得下 |
| 依据 | 全量灌生成质量最高（实测验证）；疗愈解读是**强整体性任务**，检索切碎会伤质量 |
| 实现 | 8 类知识文档原文拼入 system prompt；`store.search()` 保留为**规模开关**（知识库超窗口约 20 万字符时再启用"粗筛子集 + 子集全量灌"） |
| 附带 | 分步生成（信号→五行→状态→议题→报告）保留，中间产物 = 可观测记录 = 评估对象 |

**面试话术**："知识库 10.2 万字符在模型窗口内，所以采用全量上下文生成，质量优先。检索不是不用，是留作知识库超限时的规模开关——什么时候该检索由知识库规模数据决定，不是架构洁癖。"

### D-2 生成形态：workflow 外壳 + Agent 内核

- **5 步固定编排是 workflow**，不硬叫 Agent（判定：步骤固定、无循环、无工具调用）
- **Agent 内核 = 反思循环（Reflection）**：生成 → 规则硬检 → LLM 软审（给具体修改指令）→ **带指令定向修改**（≤2 轮）→ 通过交付
- **重试 ≠ 反思**：原样重跑（Retry）是工程容错，仍是 workflow；带审核意见定向修改（Refine）才让 LLM 决策改变后续行为，是 Agent 入门形态
- 一句话判据：**重试是工程容错，反思才是智能**

**面试话术（防追问）**："我的系统是混合架构：8 章生成走确定性 workflow，因为输出结构固定、要保证一致性和成本；质量把关处引入 Agent 审核-修复循环——LLM 以独立审核者身份检查生成结果，给出具体修改指令（如'第4章五行表与正文矛盾'），生成者带指令定向重写，直到通过或达轮次上限。任务需要多少自主性就给多少。"

### D-3 规则三件套（不是决策引擎）

规则只做三件可靠性的事，**决策权 100% 归 LLM，可靠性 100% 归规则，两边不重叠**：

1. **安全红线**：危机信号拦截 / 越界表述检测（刹车）
2. **JSON 接口契约**：结构化输出格式约束（接口）
3. **生成后校验**：核心状态齐全 / 五行矛盾检测（质检）

### D-4 三闭环架构（生产级系统的骨架）

| 闭环 | 性质 | 回答的面试问题 |
|---|---|---|
| ① 运行闭环 | 在线生成：workflow + 反思循环，每次生成记录中间决策/token/时延 | "系统怎么工作的？" |
| ② 评估闭环 | 定期考试：黄金集跑批 → F1 / 章节完整率 / 成本基线 / 一致率 | "**你怎么知道它准？**" |
| ③ 知识治理闭环 | 持续、人在环、**Agent 核心**：案例 → 新状态/新关系假设 → 冲突检测/证据链 → 提案 → **疗愈师审核** → 入库更新本体 | "知识库怎么增长？" |

- ③ 是 Miro 里"最 Agent"的部分：探索性任务（读大量画作提假设、自主论证），人在环审核是**加分项**（AI 提案、人做领域决策）
- ③ 更新知识 → ① 上下文增长 → ② 重新验证 → 不足回到 ③

### D-5 黄金集生命周期：冻结锚 + 持续扩充 + 版本化

- **必须冻结**：核心案例保持稳定（同卷子比成绩），分数才可比
- **必须扩充**：防过拟合（背题）+ 覆盖新知识（治理闭环新增状态要有考题）
- **版本化**：v1.0（11 例）→ 每季度并入新案例发布新版本，**旧案例永不删**，新旧对齐可比
- **防污染硬规则**：调试过的案例（因它改过 prompt）必须从正式评估集排除——用知识库 `source` 来源过滤实现（A1 防泄漏）

**现状提醒**：当前 11 例为 **AI 预标注基线**，待疗愈师复验 → **第一步（最高优先级）疗愈师复验升级为"人工确认黄金集 v1.0"**——"标准答案是人审过的"是评估可信度的根。

**面试话术**："黄金集版本化冻结——核心案例稳定保证可比，持续扩充防过拟合、覆盖新知识，新案例经疗愈师审核按季度并入，旧案例永不删；调试过的案例从正式集排除防污染。"

## 4. 面试逐字稿汇总（防追问话术）

**Q1：这为什么是 Agent 不是 Workflow？**
"我的系统是混合架构：8 章生成走确定性 workflow，因为输出结构固定、要保证一致性和成本；但在质量把关处引入了 Agent 审核-修复循环——LLM 以独立审核者身份检查生成结果，自主决定是否带意见重写，直到通过或达到轮次上限。任务需要多少自主性就给多少，不是所有东西都要套 Agent。"

**Q2：你的"返工"不就是 if-else 重试吗？**
"不是重试，是反思。重试是原样重跑，输出不会有本质变化；我的审核者是 LLM，它读完整份报告给出具体修改指令（如'第4章五行表与正文矛盾，证据链在第6章断裂'），生成者带着指令定向重写——第二次输出是被审核决策改变的。这就是 Reflection 模式的工程实现，每次循环都带回新的决策信息。"

**Q3：知识库更新是你 Agent 的一部分吗？**
"是，而且是治理闭环，跟报告生成是两个闭环。报告生成是 workflow+反思的确定性链路；知识治理是探索性 Agent——模型在大量新画作中发现状态/关系候选假设，自主对照已有本体做冲突检测、构建证据链、生成提案，但**人在环的环节是分开的：疗愈师只提供反馈信号（零门槛，不懂知识库结构也能提），审核与入库决策由我这个平台维护者做**。原因很实在——知识库架构有专业门槛，多租户下各家自己改会导致解读标准漂移，'知识库 = 单一事实源'就破了。AI 负责提出和论证，人负责领域决策。知识库随案例增长，每次更新后黄金集重新验证——这是会自学习的系统。"

**Q4：黄金集会一直用这 11 个吗？**
"黄金集是版本化冻结的——核心案例保持稳定保证成绩可比，但必须持续扩充防过拟合、覆盖新知识。新案例经疗愈师审核按季度并入发布新版本，旧案例永不删。另有一条硬规则：调试过的案例从正式评估集排除，防止污染。"

**Q5：你怎么知道你的系统准？**
"我们有黄金集——11 个真实案例。**先说清口径：这 11 例的标准答案目前是 AI 预标注基线，疗愈师人工复验还没做完，这是团队最高优先级的共创期任务**——'标准答案经人审'是 judge 和所有指标的可信度根基，所以我把它当成第一位的债，不藏。系统每改一次，就拿这批案例重新跑一遍，对比核心状态命中率。当前基线 F1 0.821（P 83.6% / R 80.9%）、章节完整 8/8、单份约 15.6k token、约 48.7 秒。任何改动——换模型、改 prompt、加反思循环、更新知识库——都用这套分数验证，涨了留下、跌了回滚。数据说话，不拍脑袋。"
