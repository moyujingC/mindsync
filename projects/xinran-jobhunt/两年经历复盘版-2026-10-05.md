## 2. 项目一：一镜一梳 · 疗愈师端 AI 工作台（miro）

一句话主张：面向执业疗愈师的曼陀罗个案 AI 工作台——双 Agent（生成 + QA）+ 可治理的流派知识库 + 完整评测闭环。

### 2.1 技术工程【重点写】

- 【事实】架构：FastAPI + 自研薄编排，不引入第三方 Agent 框架；文本 DeepSeek、视觉 Kimi K3（D-093 / D-066）
- 【事实】双 Agent：报告生成 = one-shot 工作流 + 磁盘 trace；报告 QA = 三层记忆架构（记忆归通用底座，D-051 起）
- 【事实】语料管道：983 篇公众号语料 → 结构化入库（F-009），入库时 ontology 同步登记
- 【事实】检索架构决策：L1 结构化路由 / L2 关键词召回零依赖，论证 MVP 阶段不需要向量化（约 17 万字语料实测）
- 【事实】输入预处理移出 AI：透视变换矫正、径向分布分析、四标记参数（圆心 R r1 r2）——黄金集 18/18、单张 ≤0.6 秒
- 【事实】本地 UI v1：四栏布局、编辑即落盘 md + 重渲，161 tests green（D-111）
- 【事实】工程治理：spec-first + D-NNN 决策级联 + 124~161 tests 全程绿
- 【手写】砍掉的"反思循环/Agent 内核"（D-083：实测收益不明确后主动删掉）——这是一个好故事，你自己写当时的判断过程

### 2.2 知识体系 / 领域建模【重点写】

- 【事实】曼陀罗解读本体论：层级↔圈层、画面圈位、三圈（天地人，别名意识圈/能量圈/物质圈）、20 失衡模式
- 【事实】跨流派口径裁决机制：五行颜色口径维持师承不改（D-055）、表外颜色不硬安五行归属（D-056）、单一来源知识先候选后验证（D-054）
- 【事实】知识治理闭环：疗愈师给反馈信号，开发者审核入库（D-043）
- 【事实】缺口队列：语料覆盖不到的领域显式登记，不糊弄
- 【手写】为什么这事重要（你的原话方向：市面上没有现成系统化的疗愈师学习内容，且昂贵）+ 师承知识"不可言传"的部分是怎么被结构化的

### 2.3 产品【重点写】

- 【事实】定位三轮收敛：个人用户-only、微信人工收款、求职展品属性（2026-09-18 定案）
- 【事实】MVP 降级决策 D-106：砍多租户/前端/分享，企业级三支柱改为质量门 / 评测 / 知识库治理
- 【事实】从"报告生成跑通"到"双 Agent 端到端"的阶段口径管理（认知卡 v3.4 记录过这条红线的演进）
- 【事实】产品表面持续重组：旧 To C 版 → 工作台 → 课程体系总官网（web.jingshu.cc）
- 【手写】每次砍需求的取舍过程（D-106 为什么敢砍：当时的判断依据）

### 2.4 保质量 / AI 评测【重点写】

- 【事实】报告 QA 两轮真实评测：7 问 → 18 问，全部通过；judge 独立、防改考卷、防污染（eval-suite A1~A4、B1、B3、D2）
- 【事实】18 问硬指标：锚定 97.8%、相关 5.00、准确 4.83、边界标注 100%、安全越界 0 条、可转述性 5.00、硬性断言 18/18、延迟 P95 8.4s（口径：单 run、LLM 评分、跨个案泛化未测）
- 【事实】真实回归溯源：评测当天抓出"模型吐非法 JSON、合规免责被误判"两类缺陷并当天修复
- 【事实】照搬核对阈值校准实验：15 字阈值 46 处命中 → 20/25 字仍 41/36 处，确认噪声源为结构件重合，阈值悬置待校准
- 【手写】你是从哪一刻开始意识到"AI 课程/AI 应用都必须做评测"的（这次课程渲染稿评测是同一个方法论的第二次落地）

## 6. 复盘版 → 正式版的翻译原则（防"AI 味复盘"）

来自 [求职材料公共问题与改写原则](求职材料公共问题与改写原则.md) 的既有结论，正式版必须遵守：
1. 从"完整证明我很强"转成"招聘方快速判断我适合这个岗位"——写读者，不写自己
2. 每个维度最多 2-3 条证据，其余砍；解释欲强的过程描述（砍需求的纠结、评测的波折）留给面试口播
3. 个人项目色彩要主动外部化：上线链接、演示地址、可核验物证（全量报告 §8）
4. 数字必须带口径或干脆不带（单 run、LLM 评分、推算值这类）
