这份文档定义 `模型接入与评测中心` 的 v1 产品边界、系统结构和默认决策。

它的目标不是提前写实现细节，而是把当前已经确认的产品意图、运行形态和部署分层收束成可直接 handoff 的正式 spec。

## 1. 背景与目标

当前公司在模型使用上已经同时存在三类现实需求：

- 个人开发工作流需要比较第三方中转、国产模型和少量可获得免费国外 API 的真实使用效果
- 产品生产流量需要一个更可控、更可治理的模型接入层
- 公司层面需要把模型选择、模型测评与降本优化从零散试验升级成可复用能力

因此，v1 要解决的问题不是“做一个通用 AI 网关”，而是建立一套共享底座，让公司能够稳定回答两类关键问题：

1. 哪些中转站值得个人继续买，哪些更适合 `Claude Code`、`Codex`
2. 在产品生产场景里，哪些任务应该交给哪些国产模型，如何在质量、延迟和成本之间做正式决策

## 2. v1 产品定义

`模型接入与评测中心` 是公司级共享模型能力项目。

它由一个共享底座承载 3 类运行形态：

### 2.1 `dev-relay`

用途：

- 面向个人开发工作流
- 为 `Claude Code`、`Codex` 等客户端提供统一模型接入入口
- 比较第三方中转与国产模型在真实编码代理任务中的效果

允许接入：

- 第三方中转 API
- 国产模型 API
- 少量可获得的免费国外 API

目标输出：

- 中转站续费建议
- 编码代理场景下的模型与 provider 对比结论

### 2.2 `prod-relay/<product>`

用途：

- 面向具体产品的正式生产流量
- 承担统一鉴权、路由、隐私治理、供应商收口与成本观测

当前已确认的第一类生产实例：

- 心理疗愈应用生产版 relay

该实例的硬边界：

- 只允许国产模型
- 第三方中转不进入生产用户数据主链路
- 不默认记录正文级敏感数据

目标输出：

- 生产任务级模型分配建议
- 成本、延迟和稳定性观察结果

### 2.3 `eval-sidecar`

用途：

- 面向旁路评测、评分板、日报、探活和优化建议
- 不与生产主链路强耦合

职责：

- 汇总匿名化指标
- 跑定时 benchmark 与健康检查
- 生成模型对比结果
- 输出中转站续费与国产替代建议

## 3. 共享底座边界

共享底座 v1 只承接共用骨架，不在第一轮承接所有高级能力。

v1 共享底座至少包括：

- provider 抽象与统一 API 入口
- 基础鉴权
- 模型到 provider 的配置映射
- 流式透传能力
- usage、延迟、错误、状态码、TTFT 等基础指标采集
- 运行模式切换：`dev-relay`、`prod-relay/<product>`、`eval-sidecar`

v1 不要求：

- 复杂自动路由
- 智能切流
- 正文缓存
- 企业级管理后台

## 4. 默认 provider 边界

### 4.1 开发版

开发版默认可以连接：

- 多个第三方中转站
- 多个国产模型
- 少量可获得的免费国外 API

开发版的第一优先任务不是生产治理，而是帮助你在真实工作流里完成：

- 中转站比较
- 模型效果比较
- 续费决策

### 4.2 生产版

当前心理疗愈应用生产版的 provider 边界写死为：

- 只允许国产模型

不允许：

- 第三方中转
- 国外付费模型作为默认生产上游
- 将开发环境的 provider 白名单直接复用于生产

这条约束是 v1 的正式硬边界，不是实现期可随意改变的偏好。

## 5. 评测与优化目标

v1 要覆盖三类正式输出：

### 5.1 模型选择

回答：

- 哪些模型适合个人编码代理任务
- 哪些国产模型适合心理疗愈产品的不同任务类型

### 5.2 模型测评

回答：

- 哪些第三方中转更稳定、更透明、更适合 `Claude Code`、`Codex`
- 国产模型与第三方中转下国外模型在你的真实任务里差距有多大

### 5.3 模型优化

回答：

- 哪些任务可以切到更便宜模型
- 哪些任务必须保留高质量模型
- 在不牺牲核心体验的前提下，哪里可以降本增效

因此 v1 的最终输出不应只是日志，而应是：

- 中转站续费建议
- 任务级国产模型替代建议

## 6. 部署建议

当前部署建议按三层分工执行：

### 6.1 本地

用途：

- 开发、调试、provider 接入验证、危险实验

不承担：

- 稳定域名入口
- 公司共享访问
- 产品生产流量

### 6.2 `4G / 4核` automation 节点

用途：

- `eval-sidecar`
- 定时 benchmark
- 探活
- 日报
- 健康检查

不承担：

- 公司级主 Relay API
- 多产品生产流量入口

### 6.3 `4G / 8核` 生产机

用途：

- 公司级主 Relay
- 各产品生产版 relay
- 域名入口
- 正式运行时配置与指标出口

默认结论：

- v1 主 Relay 正式部署优先放在 `4G / 8核` 生产机

## 7. 当前不做事项

v1 当前明确不做：

- 把个人开发版和生产版做成同一套无差别策略
- 把第三方中转引入心理疗愈生产用户主链路
- 把复杂评测逻辑直接塞进生产 API 主进程
- 把缓存节省 token 作为第一优先目标
- 在没有 QA 基线前直接进入 provider 适配实现

## 8. 一句话结论

`模型接入与评测中心` v1 不是一个泛化“大而全”的 AI Gateway 产品。

它首先是一个公司级共享能力项目，用于把个人开发版 relay、产品生产版 relay 和旁路评测正式收束到一套可治理、可评估、可优化的系统边界内。
