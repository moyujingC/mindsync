## 1. 本批目标

本批目标是把报告链路从“字段结构正确”推进到“原始解读教程算法保真”。

实施范围固定为：

1. runtime evidence 四步法结构
2. 五行太过 / 不足教程状态与工程评分状态分离
3. narrative plan 从算法 trace 派生 Lite / Pro 内容
4. report contract 内容来源修复
5. debug / workbench / eval 增加算法保真检查

## 2. 实施顺序

本批按 4 个提交收口：

1. Batch E 文档 artifact
2. runtime algorithm evidence 与单测
3. narrative / contract / debug 修复与单测
4. eval / QA / Delivery 与验证记录

## 3. 具体接口改动

内部接口固定新增或收紧：

1. `Layer0Raw.rule_evaluations.interpretation_method_trace`
2. `rule_evaluations.element_states[].tutorial_state`
3. `rule_evaluations.element_states[].scoring_state`
4. `narrative_plan.evidence_trace_summary.direct_judgment_refs`
5. `narrative_plan.evidence_trace_summary.color_analysis_refs`
6. `narrative_plan.evidence_trace_summary.shape_analysis_refs`
7. `narrative_plan.evidence_trace_summary.circle_relation_refs`
8. `knowledge_debug.algorithm_fidelity_trace`

对外 `LiteStructuredReport` / `ProStructuredReport` 字段 shape 不变。

## 4. 风险边界

1. 若视觉抽取无法识别形状，本批允许 `shape_analysis.used=false`，但必须显式说明原因。
2. 若图像颜色提取失败，fallback 可以存在，但不得伪装成教程算法结论。
3. 工程评分仍可用于候选排序，但不得作为教程状态对外解释。
4. 旧兼容字段可保留在 debug / legacy 层，但不得主导正式产品区块内容。

## 5. 验收门槛

本批只有同时满足以下条件才算通过：

1. 后端单测覆盖四步法 trace、教程阈值、Pro 独立语义和 raw dict 防泄漏。
2. `toc-mvp-fixture-001 / 002 / 004` eval 无算法保真 regression flag。
3. 静态检查确认正式生成链路无旧升级、解锁、Lite 依赖 Pro/Pro 依赖 Lite 语义。
4. QA 与 Delivery 已回填实际验证结果。
