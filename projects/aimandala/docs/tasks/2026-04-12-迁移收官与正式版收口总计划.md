## 1. 本轮目标

把 `2026-04-12` 的目标定义为：

**按“产品正式版”口径完成 `aimandala` 收口，但只保证从现在开始的新生成链路正式化；历史已有 `interpretation` 继续兼容读取，不做全量回填。**

今天完成后，项目应满足：

1. `mindsync/projects/aimandala` 成为唯一开发与发布主入口
2. 新生成的 Lite / Pro 报告走正式主链，而不是以迁移期 placeholder 为主
3. 上传生命周期、structured schema、部署口径都有单一权威入口
4. `release` 具备真实切流所需的 smoke test、回退路径和交付记录

## 2. 本轮范围

### 2.1 要做

- Lite / Pro 正式生成链路收口到 `PromptBuilder + schema + PromptBackedReportGenerationRuntime + Unified LLM client`
- 把 `report.structured` 的 Lite / Pro 字段定义收为后端单一入口
- 把 `image_path / image_url / storage_backend / storage_key / image_local_expires_at` 收为长期正式契约
- 把 `release` 环境口径统一为 `openai_compatible + cos + https://web-api.jingshu.cc + debug off`
- 补齐 task / qa / delivery artifact，并更新项目状态文档

### 2.2 不做

- 不对历史 `interpretation` 做全量回填
- 不把旧仓库逻辑逐段搬运回新仓库
- 不在今天引入引用计数系统或完整上传治理平台
- 不扩张到 To B、Studio 或 `V3`

## 3. 实现策略

### 3.1 报告生成

- `PromptBackedReportGenerationRuntime` 作为新生成链路的正式主干
- deterministic runtime 保留为开发/QA/失败场景下的受控 fallback
- `prompt_schema_validation_issues` 继续保留，作为正式质量门的一部分

### 3.2 上传生命周期

- 远端对象元数据作为正式保留语义
- 本地上传文件只作为运行时缓存或 fallback
- `release` 默认走 `cos`

### 3.3 schema 权威入口

- 新增后端 structured report contract 单一入口
- `report_contracts`、prompt schema、前端 shared types 按该入口同步
- 历史记录继续 compat read，不强制回填

### 3.4 部署与切流

- `main -> dev`
- `release -> prod`
- GitHub Actions 增加最小 smoke check
- 旧容器保留为当日回退目标

## 4. 验收标准

### 4.1 自动化与脚本

- 相关后端单测通过
- 前端关键行为测试通过
- `validate_knowledge_workbench.py` 通过
- `run_knowledge_evals.py --build-selector current` 通过
- `structured_missing_count = 0`
- `regression_flag_count = 0`

### 4.2 部署口径

- release docker 默认值与 `.env.release.example` 对齐正式环境
- runbook、docker README、workflow 三者口径一致
- 明确 smoke test 与回退步骤

### 4.3 迁移口径

- 项目状态从“迁移中”转为“主工作区迁移完成 + 正式版主链收口”
- 旧仓库只保留历史参考角色
