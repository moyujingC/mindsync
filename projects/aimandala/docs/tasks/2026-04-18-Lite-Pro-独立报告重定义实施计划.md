## 1. 目标

把当前 `Lite / Pro` 从“升级链路语义”收口为“独立产品语义”，并同步落到：

1. 文档
2. structured contract
3. 前端类型
4. Lite 页面承接
5. 关键自动化测试

## 2. 本批实现内容

### 2.1 文档

1. 新增 `Lite / Pro` 定位与内容边界 spec
2. 回写总 spec / architecture / qa / delivery 母文档入口
3. 把本子任务挂到当前 task 入口

### 2.2 合同

1. `LiteStructuredReport` 新增 `lite_healing_guidance`
2. `LiteStructuredReport` 用 `pro_report_entry` 替代 `pro_teaser`
3. `experiment_rendered` 降为兼容字段
4. `ProStructuredReport.healing_suggestions` 保持正式完整疗愈语义

### 2.3 前端

1. Lite 页面新增轻疗愈区块
2. Lite 页面中的 `Pro` 入口改为独立产品语义
3. 共享类型和 CTA 文案去掉升级暗示

## 3. 风险与边界

1. 本批不重做底层 narrative 生成算法，只先把现有 Lite 输出重组为新合同
2. `can_upgrade / upgrade_price` 暂保留兼容读取
3. `upgrade` 路径残留治理放到后续 `Batch C`

## 4. 通过条件

1. 新 spec 已成为当前正式入口之一
2. Lite 合同存在 `lite_healing_guidance` 与 `pro_report_entry`
3. 前端可渲染轻疗愈区块
4. Lite 页面 `Pro` 入口不再出现升级语义
5. 关键后端 / 前端测试通过
