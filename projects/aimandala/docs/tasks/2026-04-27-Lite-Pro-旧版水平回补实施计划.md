## 1. 本批目标

本批目标不是重开新一轮架构设计，而是先把当前 `Lite / Pro` 报告生成结果回补到旧版 `dev/ai-mandala` 的成文水平。

这里的“旧版水平”固定指：

1. Lite 首段更快命中用户状态，不再偏弱或偏占位。
2. Lite 六段故事与主题区块具备旧版那种递进感，而不是只有字段齐全。
3. Pro 具备更明确的执行摘要、根因递进和建议深度，不再像 Lite 扩写版。
4. 本批只改生成约束与测试，不改对外合同字段 shape，不改前端渲染结构。

## 2. 改动边界

本批允许修改：

1. `toC/app/backend/app/core/prompt/templates/lite_v1.6.md`
2. `toC/app/backend/app/core/prompt/templates/pro_v1.6.md`
3. `toC/app/backend/app/core/pipeline/report_prompt_preview.py`（仅当补充 prompt 上下文确有必要）
4. 对应单测

本批不修改：

1. `Layer0` 结构
2. `NarrativeContextService` 主接口
3. `report_contracts` 字段结构
4. 前端结果页合同消费

## 3. 实施顺序

本批按 3 步收口：

1. 新增最小 `task / qa` artifact，明确本批只做“旧版水平回补”。
2. 调整 Lite / Pro prompt 模板，把旧版成文纪律补回当前模板。
3. 补单测并执行后端 prompt / pipeline 回归。

## 4. 具体验收点

Lite 必须满足：

1. 模板明确要求首段快速命中当前状态。
2. 模板明确要求六段故事形成递进，不重复同一判断。
3. 模板明确要求主题区块落到现实场景和具体影响。

Pro 必须满足：

1. 模板明确要求先被看见，再做深度分析。
2. 模板明确要求执行摘要、根因三层和疗愈建议各自承担不同职责。
3. 模板明确要求 Pro 是独立深度报告，不是 Lite 的简单扩写。

## 5. 风险与回退

当前主要风险：

1. 如果模板约束过强，可能让 LLM 输出更僵。
2. 如果模板只加字数要求，不加结构纪律，结果会更长但不更像旧版。

默认回退口径：

1. 不回退 `evidence-first` 骨架。
2. 只在模板层回退不合适的新约束。
3. 若测试显示 prompt 结构被破坏，则以当前合同字段兼容为最高优先级修正。
