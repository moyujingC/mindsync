这份计划用于把“测试哪个国产视觉大模型更适合 Aimandala”拆成可执行任务。

## 1. 当前已定事项

- MVP 文字大模型默认选用 `DeepSeek V4`。
- Aimandala 后端继续使用 `openai_compatible` 作为模型接入协议。
- 视觉模型暂不直接指定，需要先完成国产视觉模型对比评测。
- 生产用户图片主链路不走第三方中转。

## 2. 任务目标

完成一轮小样本、可复现、可人工审阅的国产视觉模型评测，并给出：

- 默认视觉模型推荐
- 备选视觉模型推荐
- 是否经 RelayHub 接入的建议
- 生产配置建议

## 3. 候选模型池

第一轮建议至少覆盖 3 个国产视觉模型入口。

候选类型：

- 豆包视觉模型
- 通义千问视觉模型
- 智谱 GLM 视觉模型
- Kimi 视觉模型
- 其他已具备稳定 OpenAI-compatible 或可快速适配接口的国产视觉模型

实际候选以可拿到 API key、可稳定调用、可用于生产用户数据为准。

## 5. 实施步骤

### 5.1 确认候选入口

输出：

- 模型名称
- model id
- base URL
- API key 来源
- 是否支持图片输入
- 是否允许生产用户数据
- 是否可通过 RelayHub 绑定

### 5.2 准备统一 prompt

prompt 应要求模型只做视觉结构观察，不做心理诊断。

最小要求：

- 输出中文
- 输出结构化 JSON
- 明确中心、三圈边界、颜色块、结构特征
- 对不确定区域标注不确定
- 不生成医学或心理治疗结论

### 5.3 执行模型调用

每个候选模型跑同一批 fixture。

当前可执行入口：

```bash
PYTHONPATH=projects/aimandala/toC/app/backend \
python3 projects/aimandala/toC/app/backend/scripts/run_vision_model_evals.py \
  --candidate-config <candidate-config.json> \
  --fixture-id toc-mvp-fixture-001 \
  --fixture-id toc-mvp-fixture-002 \
  --fixture-id toc-mvp-fixture-003 \
  --fixture-id toc-mvp-fixture-004 \
  --execute
```

在没有真实 API key 前，可先运行计划模式：

```bash
PYTHONPATH=projects/aimandala/toC/app/backend \
python3 projects/aimandala/toC/app/backend/scripts/run_vision_model_evals.py \
  --fixture-id toc-mvp-fixture-001
```

候选配置模板：

```bash
PYTHONPATH=projects/aimandala/toC/app/backend \
python3 projects/aimandala/toC/app/backend/scripts/run_vision_model_evals.py \
  --print-config-template
```

当前模板内置候选：

- `doubao-vision`
- `qwen-vl`
- `glm-vision`
- `kimi-vision`

输出建议路径：

```text
projects/aimandala/docs/qa/model-evals/2026-05-06-vision/<model-id>/<fixture-id>.json
```

### 5.4 人工评审

按 QA 基线记录 Pass / Fail：

- `structure_pass`
- `circle_pass`
- `color_pass`
- `grounding_pass`
- `product_pass`

同时记录失败模式。

### 5.5 形成验证记录

新增验证记录：

```text
projects/aimandala/docs/qa/2026-05-05-mvp-国产视觉模型评测验证记录.md
```

验证记录必须给出：

- 推荐默认模型
- 备选模型
- 不推荐模型及原因
- 是否建议经 RelayHub 接入
- `AIMANDALA_LLM_VISION_MODEL` 建议值

## 6. 生产配置建议

在评测完成前，不改生产默认视觉模型。

评测完成后，建议只改环境变量：

```bash
AIMANDALA_LLM_BACKEND=openai_compatible
AIMANDALA_LLM_MODEL=deepseek-v4-pro
AIMANDALA_LLM_CHAT_MODEL=deepseek-v4-pro
AIMANDALA_LLM_VISION_MODEL=<vision-winner-model-id>
```

如果经 RelayHub 接入，则将 `AIMANDALA_LLM_BASE_URL` 指向 `prod-relay/aimandala` 的 OpenAI-compatible 入口，并把 `task-aimandala-vision` 绑定到胜出视觉模型。

## 7. 验收标准

本任务完成时必须满足：

- 至少 3 个国产视觉模型完成同样 fixture 调用。
- 至少 4 个正式 fixture 完成人工评审。
- 每个模型都有原始输出留档。
- 有清晰 Pass / Fail 表。
- 有默认模型与备选模型建议。
- 明确说明是否接 RelayHub。
- 没有把第三方中转列为生产默认候选。

## 8. 当前不做

- 不直接上线未经评测的视觉模型。
- 不重写三圈识别主链路。
- 不引入国外视觉模型作为 MVP 默认候选。
- 不把视觉评测扩大为完整报告质量评测。
- 不要求本轮完成自动评分器。
