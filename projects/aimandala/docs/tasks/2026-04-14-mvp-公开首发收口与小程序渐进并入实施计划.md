## 1. 本轮目标

1. 为 `Web MVP` 公开首发做最后收口

## 4. MVP 首发收口执行顺序

### 4.1 先补质量门

先在 `qa basis` 中写死以下上线门槛：

- `fixture_fallback_count = 0`
- `structured_missing_count = 0`
- `regression_flag_count = 0`
- Web 主链路 smoke 可重复通过
- 手机端人工主路径完整走通

### 4.2 再做实现与验证

执行顺序固定为：

1. 复盘并清零当前 `2` 个 fallback fixture
2. 补强 smoke、深烟测和人工主路径验收
3. 做少量高收益体验修正
4. 回写 `verification / delivery`

## 5. 小程序渐进并入策略

`codex/aimandala-dual-channel-ui` 不整支直接合并到 `main`，只允许分批摘入。

### 5.1 批次定义

1. 批次 A：`shared/types + shared/core + shared/design-system`
2. 批次 B：`shared/ui + mobile-web` 消费 `shared/ui`
3. 批次 C：`miniapp` 预览壳 / 静态壳
4. 批次 D：`/api/v2/miniapp/*` contract / stub-only 能力
5. 批次 E：真实微信 `session / wechat pay / native host`

### 5.2 各批次并入标准

#### 批次 A

- 只吸收 channel-neutral 的 shared 基础层
- 不引入微信、小程序宿主、支付或 session exchange
- `mobile-web` 行为不退化
- `npm test`、`typecheck`、`build:mobile-web` 必须通过

#### 批次 B

- 吸收 `shared/ui` 与 Web 对 shared UI 的消费改造
- 允许带入 miniapp 预览级 page shell
- shared UI 不依赖路由、上传、支付、登录
- miniapp 仍只能是预览级骨架，不是真实运行时

#### 批次 C

- 只承接 `miniapp` runtime shell、route plan 与页面壳接线
- 不接真实微信会话与支付
- 不成为 `main` 发布阻塞项
- 不改当前对外产品口径

#### 批次 D

- 只承接 `/api/v2/miniapp/*` 下的 contract-ready 或 stub-ready 能力
- 默认向后兼容
- 不影响当前 Web 用户主路径
- 必须有独立单测、contract test 与环境边界说明

#### 批次 E

- 只在小程序进入明确上线窗口时推进
- 包括真实微信 `session / wechat pay / native host / gray config`
- 必须单独补 `spec / task / qa / delivery`
- 不与当前 Web MVP 首发准备混做

### 5.3 主线吸收节奏

默认采用下面三层分支流，不整支直并：

1. `codex/aimandala-dual-channel-ui`
   - 持续并行开发，不要求随时可并
2. `codex/aimandala-miniapp-batch-<n>`
   - 从 worktree 摘出单一批次，形成可审阅、可回归的小批量集成分支
3. `main`
   - 只接收通过验证的分批成果

### 5.4 并入纪律

- 每批代码并入时，必须同步并入对应的 `task / qa / delivery`
- 不允许只并代码、不并 artifact
- `main` 上的新改动默认优先沉淀为 shared-friendly 改动
- 任何纯业务规则、状态机、DTO、展示数据整形，默认优先进入 `shared`
- `mobile-web` 中出现可复用展示主体时，优先抽到 `shared/ui`
- 不把浏览器专属能力重新写回 `shared`
- 真实微信 live 能力仅在小程序明确上线窗口单独推进

### 5.5 当前建议的吸收顺序

当前最值得先吸收的顺序固定为：

1. 批次 A
2. 批次 B
3. 批次 C 中的预览壳 / 静态壳部分
4. 批次 D 中的 contract / stub-only 部分
5. 批次 E 最后

原因是：

- A/B 能先降低未来冲突，并反向提升当前 Web 结构
- C 可占位，但不应压主线风险
- D 涉及接口与数据语义，必须在 Web 首发稳定后再吸收
- E 属于未来小程序上线窗口，而不是当前 MVP 首发窗口
