## 1. 本轮目标

把 `Paperclip` 中的 CI/CD workflow 面板，从“历史 run 列表”整改为“当前健康度优先”的视图。

## 2. 需要落地的变更

### 2.1 展示层

1. workflow 首屏增加“当前状态摘要”
2. workflow 展开后默认只展示最近窗口：
   - 推荐 `最近 5 次`
3. 更早 run 进入折叠层，不默认展开

### 2.2 判断层

1. 新增“历史失败已被覆盖”的判定
2. 新增“持续红灯”的判定
3. 区分：
   - 当前失败
   - 已被覆盖的历史失败
   - 持续性失败
   - 基础设施阻塞

### 2.3 与 issue 的联动口径

1. `commit-summary` 父任务保留按提交聚合的语义
2. 当较新成功 run 已覆盖旧失败时，旧失败不再继续占据 workflow 首屏
3. 只有持续失败或当前主链阻塞时，相关 issue 才继续作为当前问题高亮

## 3. 分阶段实施

### 3.1 第一阶段：产品与治理对齐

1. 固化本轮 `spec / task / qa / delivery`
2. 更新 CI/CD 机制文档中的展示口径
3. 明确 GitHub 对齐原则

### 3.2 第二阶段：Paperclip UI 实现

如果在 `paperclip` 仓库内实施，建议拆成下面几个小改动：

1. workflow 列表增加 summary row 的状态计算
2. run list 增加最近窗口裁剪
3. 历史 run 改为折叠区
4. 对被覆盖的旧失败降级视觉权重

### 3.3 第三阶段：回归验证

至少用下面三类样本验收：

1. 最新失败，旧成功
2. 最新成功，旧失败
3. 最近窗口连续失败

## 4. 边界与约束

1. 不删除历史 run 数据
2. 不伪造全绿结果
3. 不把 issue 关闭策略和 workflow 可视化强行绑死
4. 不因为历史 run 仍存在，就继续向用户施加当前处理压力

## 5. 完成标准

1. 用户进入 workflow 面板后，首屏先看到“当前状态”而不是长历史
2. 较早提交上的单次失败，在后续成功覆盖后，不再继续表现为当前红灯
3. 连续失败、最新失败、基础设施阻塞三类问题仍能稳定暴露
4. 视图判断结果与 `commit-summary` / job issue 的协作语义不冲突
