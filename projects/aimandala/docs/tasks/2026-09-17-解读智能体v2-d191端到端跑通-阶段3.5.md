## 一、为什么先做这个

v2 计划（阶段 0–6）技术设计成立，但可交付节点靠后：能拿出手的东西最早出现在阶段 5 之后。本任务把顺序倒过来——**先用一张图打穿全链路，再回头加固**。

本任务的目的有两个，缺一不可：
1. 产出一份可对外展示的端到端产物（简历项目素材 + build log 素材）
2. 用真实链路暴露问题，让后续阶段 1（人工金标准）只需标注「哪里离谱」，而不是凭空填几十个字段

## 二、目标

输入 `d191` 一张矫正后的曼陀罗图 + 人确认过的三圈参数，跑完整条链路，产出**一份疗愈师读得懂的工作底稿**。

产出物是**一份能读完的文件**，不是一套架构。

## 五、产出目录

落盘到 `runs/d191-<时间戳>/`：

| 文件 | 内容 |
|---|---|
| `run.json` | 运行 ID、输入哈希、模型、时延、token、警告 |
| `observations.json` | 圈层、区域坐标、可见颜色/形状/结构/面积/深浅、原始色名与归一化结果、来源（程序统计 or 视觉模型）、置信度、来源是否一致 |
| `analysis.md` | 完整自然语言：画面理解、候选解释、歧义、待核对问题 |
| `hypotheses.json` | 候选类型（五行/失衡/状态/议题）、支持证据 ID、反证 ID、知识规则引用、原因端、结果端、状态层级、置信度、状态（candidate/accepted/rejected/needs_human）、被排除原因 |
| `claims.json` | 允许写入报告的主张，每条引用 ≥1 个画面观察 + ≥1 条知识规则 |
| `report.md` | 疗愈师工作底稿，正文只从 accepted claims 生成，段落带可机读引用标记 |

## 六、固定链路

1. **输入校验 + 危机分级**：出现具体计划、迫近危险或直接求助 → 停止常规生成，转人工，不写报告；一般风险转述 → 显示提醒，允许继续生成底稿
2. **程序侧**：读三圈参数、生成分圈裁图、颜色面积统计（OpenCV）
3. **Kimi**：看**整体图（必）** + 三圈裁图（补充），输出颜色、形状、结构、动势、特殊点；模板线与三圈标记线**不得**作为五行证据
4. **合并**：程序事实与视觉事实合并，冲突项标记 `needs_human`
5. **DeepSeek**：读 `analysis.md` + 完整知识上下文，生成五行候选与失衡候选
6. **状态映射**：逐条绑定失衡模式 + 画面证据 + 知识规则；绑不上就不出状态
7. **claims**：通过证据门者进 accepted；不足者进「待疗愈师核对」，不写正文
8. **报告生成**：按 accepted claims 逐章产出 `report.md`
9. **G1 自测**：引用完整性、前后矛盾、章节、安全、低置信检查

## 七、硬性约束

- 不存在无来源的 accepted claim
- 不自动补齐状态、失衡模式或议题
- 视觉模型与程序统计冲突时进 `needs_human`，不得由模型自行消解
- 不保存模型思维链，只保存简洁理由、证据引用、知识来源、被排除原因
- 中心对称曼陀罗不生成没有画面依据的九宫方位读数
- 报告定位为「疗愈师工作底稿」，不是来访者直接阅读成品
- `referral-redlines.md` 永不进入生成上下文

## 八、已知风险（本次记录，不作处理）

- **色彩未矫正**：图只做了几何矫正，拍照/扫描色偏会让归一化色名不稳。本次所有颜色结论一律标 `needs_human`，由人工确认后再用
- **裁图丢失全局信息**：动势与整体疏密只有全图可见；裁图产生的区域坐标必须能对回原图坐标系
