## 1. 本批目标

本批目标是把 Batch G 后已可追溯、但仍偏机械的报告表达压缩为用户可读的教程式解读。

本批不改 Lite / Pro 对外字段 shape，不改安全协议，不扩展 shape recognition。

## 2. 实施顺序

本批按 4 个提交收口：

1. Batch H `Spec / Task / QA / Delivery` 文档。
2. Narrative 逐圈证据压缩与 Pro 去重复。
3. Root cause / healing plan 表达修复与测试。
4. Golden 重导、review / eval summary 回填。

## 3. 具体改动

### 3.1 Narrative 逐圈证据压缩

修改 `narrative_context_service.py`：

1. 保留现有 `per_circle_color_summary` 作为 trace 摘要。
2. 新增面向用户阅读的 `per_circle_observation_summary`。
3. Lite `visual_elements` 注入观察句，不注入 `#hex` 或“逐圈深浅依据”。
4. Pro `circle_readings` 只注入对应圈的观察句，不重复完整三圈摘要。

### 3.2 Report Contract 表达治理

修改 `report_contracts.py`：

1. `evidence_digest` 使用 Pro narrative plan 中的去重复圈段。
2. `root_cause_chain` 增加句段清理，去掉异常空格和重复片段。
3. `healing_plan` fallback 绑定当前失衡、根因链和议题，不重复同一 practice。
4. 保持 raw payload 与旧升级语义 sanitization。

### 3.3 Debug 与 Golden

修改 `report_knowledge_debug.py` 与 `workbench.py`：

1. debug evidence trace 增加人可读观察摘要，同时保留机器 trace。
2. golden `report.md` 正文摘录剥离安全声明，避免人工审阅先看到声明而非正文。
3. eval summary 字段语义不变。

## 4. 验收门槛

本批只有同时满足以下条件才算通过：

1. 新增测试先验证旧行为失败，再实现通过。
2. `test_knowledge_runtime_v21.py` 通过。
3. `test_report_contracts.py` 与 `test_api_v2_report_contracts.py` 通过。
4. `test_knowledge_workbench_v22.py` 通过。
5. `validate_fixtures.py` 通过。
6. `001-lite / 002-pro / 002-lite` golden 已重导。
7. QA / Delivery 明确记录表达 drift 的修复结果和剩余风险。
