## 1. 本轮目标

把 `aimandala` 从“已有 CI/CD 主链”推进到“PR 可作为严格质量门”的中高强度状态。

本轮重点不是扩全仓库，也不是一次性补齐安全治理，而是让 `PR -> main` 具备：

- 稳定的 required checks
- 明确的失败分类与本地复现命令
- 与 Paperclip 路由一致的质量门闭环

## 2. 本轮范围

### 2.1 要做

- 重命名并固定 PR required checks：
  - `frontend-quality`
  - `backend-quality`
  - `knowledge-quality`
  - `ci-summary`
- 前端新增：
  - `lint`
  - `format:check`
  - `test:coverage`
- 前端补最小 ESLint / Prettier / 覆盖率配置
- 后端补最小 `ruff` 静态检查
- 扩展 Paperclip `kind`：
  - `lint-failure`
  - `format-failure`
  - `coverage-failure`
- 扩展 auto-repair 白名单到前端 lint / format、后端 ruff
- 补一份项目侧 PR 质量门 runbook

### 2.2 不做

- 不引入 Playwright
- 不引入 CodeQL / Dependabot / gitleaks
- 不把 `aicareer` 并入同一套 workflow
- 不把后端 `mypy` 作为首轮 required check

## 3. 实施策略

### 3.1 前端

- 先锁定“当前可执行的严格度”，不把所有历史页面壳一次性纳入 coverage
- lint 重点覆盖：
  - 未使用变量 / import
  - 明显 `any`
  - promise 漏处理
  - type import 规范
- format 仅做 `--check`
- coverage 只统计当前已纳入核心验证的 shared / controller / identity / 核心 page shell

### 3.2 后端

- 先用 `ruff` 建立最小静态门
- 首轮只启用可控、确定性的 `F` 类错误
- 不把历史长行和大面积风格债一次性并入 required check

### 3.3 路由与自动修复

- 新失败类型必须写清 `failed_step`、`repro_command` 和日志摘要
- 只有以下失败进入 auto-repair 白名单：
  - 前端 lint
  - 前端 format
  - 后端 ruff
- coverage / knowledge eval / deploy / smoke 不进入自动修复

## 4. 完成标准

1. 本地 `frontend-quality` 对应命令全部可执行
2. 本地 `backend-quality` 对应命令全部可执行
3. workflow 名称已稳定为 required check 口径
4. Paperclip 新失败类型可正确建单
5. 项目侧已有 runbook 可指导下一位工程师本地复现与在线接入
