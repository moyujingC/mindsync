## 1. 本轮目标

把 `aimandala` 从“只有 deploy workflow 的单链发布”推进到“自托管 runner + CI + nightly smoke + Paperclip 路由 + 安全自动修复”的最小闭环。

## 2. 本轮范围

### 2.1 要做

- 新增 4 条 workflow
- 新增 `shared/tools/ci/` 公共脚本
- 新增 GitHub runner 部署文档
- 更新 `服务器部署与运维手册`
- 更新公司侧治理规则
- 补齐 `spec / task / qa / delivery`

### 2.2 不做

- 不真实创建 GitHub secrets / vars
- 不在本轮直接把 runner 安装到服务器
- 不在本轮引入 Playwright
- 不对 `aicareer` 和 `research-center` 并入同一套 workflow

## 3. 任务拆解

### 3.1 共享脚本

- `common.mjs`
  - 统一参数、HTTP、shell、git 辅助
- `paperclip-sync-lib.mjs`
  - 聚合键、标签映射、issue create/update
- `paperclip-ci-issue.mjs`
  - workflow 侧 CLI 包装
- `aimandala-smoke.mjs`
  - basic / deep smoke
- `aimandala-auto-repair.mjs`
  - workflow_run 失败分析、白名单判断、隔离分支修复
- `check-runner-heartbeat.mjs`
  - runner watchdog

### 3.2 GitHub workflows

- `aimandala-ci.yml`
  - `frontend-ci`
  - `backend-ci`
  - `knowledge-ci`
- `aimandala-deploy.yml`
  - `deploy-dev`
  - `deploy-prod`
- `aimandala-nightly-smoke.yml`
  - `nightly-dev-smoke`
  - `nightly-prod-smoke`
- `aimandala-auto-repair.yml`
  - `auto-repair`

### 3.3 文档与治理

- 项目侧：
  - runner runbook
  - ops runbook
  - spec / qa / delivery
- 公司侧：
  - `研发原则`
  - `任务类型与标签规范`
  - `任务创建模板`

## 4. 完成标准

1. 共享脚本能本地 `node --check`
2. `aimandala-smoke.mjs --env dev --mode basic` 可通过
3. `aimandala-smoke.mjs --env prod --mode basic` 可通过
4. workflow 中的 runner 标签、Paperclip 路由、自动修复边界都已显式写出
5. 文档入口已经能指导下一位工程师继续接入真实在线配置
