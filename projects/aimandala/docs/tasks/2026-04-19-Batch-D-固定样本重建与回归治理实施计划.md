## 1. 本批目标

本批是 `Batch D` 的第一块正式实现，目标固定为：

1. 把 `toc-mvp` 固定样本从旧 `sample-a ~ sample-e` 重建为 `toc-mvp-fixture-001 ~ 004`
2. 让固定样本直接对齐 Batch C 已落地的新 Lite / Pro 产品区块合同
3. 收口 fixture 治理、验证脚本、workbench/debug 摘要和 eval 产物

## 2. 固定范围

本批固定覆盖：

1. fixture descriptor
2. `fixtures/manifest.yaml`
3. `fixtures/README.md`
4. `fixtures/toc-mvp/README.md`
5. `fixtures/toc-mvp/VALIDATION.md`
6. `validate_fixtures.py`
7. `verify_fixture_003_existing_reuse.py`
8. knowledge workbench / browser debug panel / eval summary / backend test 中的 fixture id 和 fixture count
9. `toC/data/knowledge/builds/*/evals/*.json` 与 `summary.json`
10. 本批 QA / Delivery 收口

## 4. 实施口径

实施时固定遵守：

1. 新样本验证字段直接对齐 Batch C 新合同
2. 不保留旧 `sample-*` 作为当前正式入口
3. manifest、descriptor、文档、脚本全部改成 repo-relative / `$REPO_ROOT`
4. `mobile-web/dev-fixtures.ts` 不纳入本批治理
5. 不改业务 API，不做长期双样本兼容

## 5. 执行顺序

本批按下面顺序推进：

1. 先重建 fixture / manifest / 文档 / 脚本
2. 再重建 workbench / debug / eval 产物与自动化测试
3. 最后回填 QA / Delivery，并单独提交

## 6. 通过条件

本批只有同时满足以下条件才可判定通过：

1. 当前正式固定样本入口只剩 4 组新 fixture
2. workbench/debug/eval 摘要统一使用新 fixture id 和 `fixture_count=4`
3. 样本验证直接跟 Batch C 新合同对齐
4. fixture 文档、manifest、脚本、测试不再依赖机器绝对路径
