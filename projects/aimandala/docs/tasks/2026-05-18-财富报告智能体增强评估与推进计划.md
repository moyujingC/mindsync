本文记录 2026-05-18 对财富议题解读报告智能体和相关知识库的阶段评估，并作为后续逐步推进的任务入口。

本轮目标不是扩展更多主议题，而是先把财富议题报告做到可稳定内测、可人工审核、可进入小范围付费试运营。

## 1. 当前阶段判断

当前系统已经形成新主链路：

```text
/api/wealth-reports
  -> KnowledgePackBuilder
  -> MandalaInterpretationAgent
  -> WealthReportRuntime
  -> 疗愈体系知识库
```

旧报告链路不作为当前实现依据，也不新增兼容层。

当前结论：

- 后端主链路已经可用。
- 财富知识库框架已经成型。
- Lite / Pro 都能生成用户可见报告。
- 报告已经开始显性展示圈内五行分析。
- 浮现议题已经从独立段落调整为融入三圈解读。
- 下一次曼陀罗探索建议已经有初步规则。

但当前还不适合直接作为稳定付费交付。它更适合作为内测版，用真实案例和人工审核继续收敛。

## 3. 当前主要缺口

### 3.1 画面识别缺口

已经确认的错误类型：

- 把疗愈师三圈标记线识别为画作内容。
- 把模板黑色线稿识别为画作元素。
- 把红色渐变误识别为粉红色。
- 把浅蓝色圆形误识别为白色留白。
- 漏掉圈内留白作为金能量。
- 对元素是否相邻、是否接触、是否被留白切分判断不足。

这些错误会直接影响五行判断和财富翻译，所以优先级最高。

### 3.2 五行分析缺口

当前代码已经避免“给整圈贴五行标签”，但结构仍不够细。

需要改成元素级分析：

```text
圈层
  -> 可见元素
  -> 元素颜色 / 形状 / 面积 / 位置 / 相邻关系
  -> 五行归类
  -> 同圈元素生克候选
  -> 五行失衡类型候选
  -> 议题翻译
```

需要特别纳入：

- 留白为金。
- 画作外边以内的留白可作为金能量。
- 模板黑线排除。
- 三圈标记线排除。
- 紫色按阴阳和视觉特征归类。
- 橙色、粉色按弱火并结合阴阳倾向判断。
- 无根之木判断：圈内无水，或有水但木没有挨着水。
- 五行关系只限同一圈内部元素之间。
- 三圈联动不使用五行生克。

### 3.3 财富翻译缺口

当前财富翻译层已经存在，但运行时还没有稳定做到：

```text
画面事实
  -> 基础层状态含义
  -> 圈内五行 / 形状 / 色彩解读
  -> 财富机制
  -> 报告段落位置
  -> 用户可读语言
```

需要减少单纯关键词命中，改为更明确的结构化路由。

### 3.4 浮现议题缺口

当前已定义 7 类浮现机制：

- 自我价值与配得感
- 安全感与匮乏感
- 关系与交换边界
- 家庭系统脚本
- 情绪能量与消耗
- 身体承载与行动力
- 事业表达与世界连接

下一步要让运行时明确选出本次报告中出现的浮现机制，并把它们融入对应圈层，不再写成独立报告。

### 3.5 Lite / Pro 交付缺口

当前 Pro 更像“更长的 Lite”。后续应调整为：

- Lite：完整但收束，像一次付费初读，不是免费摘要。
- Pro：更像疗愈师带读，逐圈展开、机制更完整、证据更多、建议更具体。

Pro 需要增加的价值：

- 更细的画面证据。
- 更完整的圈内五行过程。
- 更清楚的主轴选择理由。
- 更完整的三圈来龙去脉。
- 更明确的浮现机制融入。
- 1-2 个下一次探索建议。

## 4. 推进顺序

### Phase 1：补画面识别结构

状态：todo

目标：让视觉模型输出更稳定、更可审核。

任务：

- 定义新的视觉识别 schema。
- 每个视觉元素必须包含圈层、颜色、形状、面积倾向、位置、相邻关系、是否留白、是否模板线、置信度。
- 明确排除三圈标记线和模板黑线。
- 增加颜色误判、留白误判、标记线误判的质量检查。
- 用 11 个完整案例重新生成视觉识别结果，进入人工审核。

验收标准：

- case-001 到 case-011 都有结构化视觉识别结果。
- 每个案例都能区分原画元素、模板线、三圈标记线。
- 留白金能量不再系统性漏判。

### Phase 2：补圈内五行对象模型

状态：todo

目标：把五行从关键词判断升级为元素级推导。

任务：

- 在 stage-05 / stage-06 输出中增加元素级五行对象。
- 支持同圈元素生克候选。
- 支持五行失衡类型候选。
- 支持无根之木、留白金切分、弱火、紫色阴阳归类。
- 质量门继续禁止整圈五行标签和跨圈五行生克。

验收标准：

- 报告能说明“哪个元素因为什么被判为某五行”。
- 生克只发生在同圈元素之间。
- 三圈联动仍然只用圈层结构解释。

### Phase 3：补财富路由和翻译层

状态：todo

目标：让财富条款命中更稳定，而不是依赖模型临场发挥。

任务：

- 把财富 routing 从关键词命中升级为结构化条件。
- 条件至少支持：圈层、元素、五行、面积倾向、相邻关系、留白切分、强弱、三圈状态。
- 为每条财富条款补“适用证据”和“不可使用条件”。
- 让运行时输出本次命中的财富机制、证据和段落位置。

验收标准：

- 每份报告至少有 1 条明确财富主线。
- 财富主线能追溯到画面证据和知识库条款。
- Pro 不再出现 `selected_clause_count=0` 但仍生成完整报告的情况。

### Phase 4：补浮现机制选择

状态：todo

目标：让其他议题自然浮现，但始终服务财富主线。

任务：

- 运行时输出 `selected_emergent_mechanisms`。
- 每个浮现机制必须包含：机制 ID、触发证据、财富回译、报告落点。
- Lite 最多使用 1 个浮现机制。
- Pro 最多使用 2 个浮现机制。
- 下一次探索建议必须从未充分展开的浮现机制中选择。

验收标准：

- 报告不再单独设“浮现议题”段落。
- 关系、家庭、身体、情绪、事业线索能融入三圈解读。
- 下一次探索建议能说明画面依据和本次不展开原因。

### Phase 5：重做 Lite / Pro 样例标准

状态：todo

目标：建立可人工审核的报告标准样例。

任务：

- 选 3 个代表性案例生成 Lite / Pro 标准样例。
- Lite 作为完整付费初读。
- Pro 作为更深入带读。
- 人工标注：画面证据、五行过程、财富主线、浮现机制、疗愈语言、建议质量。
- 把人工认可的段落风格回填到语言风格指南和 prompt。

验收标准：

- Lite 不显得轻。
- Pro 有明确加码价值。
- 报告读起来像疗愈师带用户看画，而不是检测报告。

### Phase 6：建立真实回归集

状态：todo

目标：让每次修改都能知道报告有没有变好。

任务：

- 使用 11 个完整案例作为第一批回归集。
- 使用片段示范作为单点规则回归集。
- 每个样例保存：图片、三圈边界、视觉识别、五行分析、财富路由、最终报告、人工审核结论。
- 建立失败归因分类：视觉识别、五行判断、财富路由、浮现机制、报告语言、质量门。

验收标准：

- 每次修改都能跑一批固定样例。
- 失败能定位到具体模块。
- 人工审核意见能回填到知识库或代码。

## 5. 下一步执行入口

下一步先做 Phase 1，不直接继续改报告文案。

原因：

- 当前报告问题的上游主要是画面识别和元素结构不稳。
- 继续调 prompt 只能短期改善语言，不能稳定提升判断。
- 五行和财富翻译都依赖准确的视觉元素对象。

Phase 1 的最小交付物：

1. 新视觉识别 schema。
2. stage-03 输出结构调整方案。
3. 11 个案例的视觉识别审核表模板。
4. 视觉识别质量门新增项。

- 每完成一层，都用 11 个案例验证一次。
- 所有新增规则都进入知识库或运行时结构，不只停留在聊天记录。
