## 1. 目的

这份手册用于收口 `aimandala / 一镜一梳` 当前两台腾讯云服务器的职责、目录、服务、部署方式与日常运维命令，避免后续继续依赖聊天记录回忆现场。

## 2. 当前服务器分工

当前采用两台服务器分工：

- 开发测试机：`main`
- 正式发布机：`release`

当前确定策略：

1. 本地开发完成后，先提交到 `main`
2. 开发测试机从远程仓库拉取 `main`
3. 接近发布时，再从 `main` 收口到 `release`
4. 正式发布机后续只承接 `release`

## 6. 开发测试机当前服务清单

### 6.1 后端服务

- systemd 名称：`aimandala-main-backend`
- 启动命令：

```bash
/opt/aimandala-main/backend/venv/bin/uvicorn app.api.main:app --host 0.0.0.0 --port 8000
```

- 核心环境变量：

```bash
PYTHONPATH=/opt/aimandala-main/app/mindsync/projects/aimandala/toC/app/backend
AIMANDALA_LLM_BACKEND=noop
AIMANDALA_UPLOAD_BACKEND=local
```

说明：

- 开发测试机允许继续使用 `noop + local` 作为联调兜底
- 这不是 `release` 口径，不能把开发机默认值误当正式发布配置

### 6.2 前端静态站点

当前正式入口是 `nginx` 提供的静态目录：

- 站点目录：`/var/www/dev-web.jingshu.cc`
- 入口端口：`80`

同时保留了一个临时 Python 静态服务用于排障：

- systemd 名称：`dev-web-8001`
- 端口：`8001`

说明：

- 日常访问优先走 `80`
- `8001` 只作为临时调试保留
- 后续若确认不再需要，可停用 `dev-web-8001`

### 6.3 nginx

当前 `nginx` 配置思路：

- `/`：前端静态站点 + SPA fallback
- `/api/`：反代到 `127.0.0.1:8000`
- `/health`：反代到 `127.0.0.1:8000/health`

## 7. 当前一键部署方式

开发测试机当前一键部署脚本：

```bash
/opt/aimandala-main/scripts/deploy-main.sh
```

它当前负责：

1. 拉取 `origin/main`
2. 确保后端依赖存在
3. 重启 `aimandala-main-backend`
4. 安装前端依赖
5. 重新 build mobile-web
6. 把前端产物同步到 `/var/www/dev-web.jingshu.cc`

当前脚本应固定把前端 API 指到反代入口，而不是裸 `:8000` 端口。

当前推荐值：

```bash
http://101.43.98.40
```

域名解析完成后推荐切到：

```bash
http://dev-web-api.jingshu.cc
```

2. 通过宿主机 `nginx` 或容器入口切回旧流量
3. 记录回退原因与时间
4. 问题修复后，仍回到 `release -> prod` 正式发布流

## 9. GitHub Actions CI/CD 约定

仓库内已增加工作流：

- `/Users/xinran/Downloads/dev/mindsync/.github/workflows/aimandala-deploy.yml`

当前约定：

1. 推送到 `main` 时，自动部署开发测试机
2. 推送到 `release` 时，自动部署正式发布机
3. 也支持在 GitHub Actions 中手动选择 `dev / prod` 执行

需要在 GitHub 仓库 Secrets 中预先配置：

- `AIMANDALA_DEV_HOST`
- `AIMANDALA_DEV_USER`
- `AIMANDALA_DEV_SSH_KEY`
- `AIMANDALA_PROD_HOST`
- `AIMANDALA_PROD_USER`
- `AIMANDALA_PROD_SSH_KEY`

说明：

- Actions 只负责 SSH 到服务器触发部署
- 服务器仍然自己从 GitHub 拉对应分支
- 开发机走 `/opt/aimandala-main/scripts/deploy-main.sh`
- 正式机走 `docker compose build && docker compose up -d`
- workflow 已增加最小 smoke check，用于校验容器和公开入口是否仍可访问

## 10. 当前需要记住的约束

1. 服务器上的代码不是权威源，GitHub 仓库才是权威源
2. 开发测试机只跟 `main`
3. 正式机未来只跟 `release`
4. 未经确认，不要在服务器上直接改业务代码并长期保留
5. 若必须临时改服务器文件，应尽快回写到仓库
6. 正式机当前前端若重新 build，必须确保 `VITE_AIMANDALA_API_BASE_URL=https://web-api.jingshu.cc`
7. 正式机必须确保 `AIMANDALA_LLM_BACKEND=openai_compatible`
8. 正式机必须确保 `AIMANDALA_UPLOAD_BACKEND=cos`
9. 正式机必须确保 `AIMANDALA_ENABLE_DEBUG_WORKBENCH=0`
