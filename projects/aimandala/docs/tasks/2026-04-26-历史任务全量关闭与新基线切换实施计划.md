## 1. 本轮目标

本轮只收“历史任务全量关闭 + 新基线切换”的正式实施入口，不进入自动脚本实现。

本轮目标固定为：

1. 明确旧任务批量关闭的执行顺序
2. 明确保留名单的最小人工决策点
3. 明确关闭 comment 口径
4. 明确默认终态使用什么状态
5. 明确基线切换后如何观察新任务

## 2. 本轮边界

本轮明确要做：

1. 新建本实施计划
2. 新建配套 QA Basis
3. 把该文档链挂进 `docs/tasks/README.md`、`docs/qa/README.md` 和 `docs/specs/README.md`

本轮明确不做：

1. 不直接批量 patch 线上任务
2. 不实现自动关闭脚本
3. 不修改 heartbeat gate
4. 不修改 diagnosis 分桶
5. 不修改 `paperclip-sync-lib.mjs`

## 3. 实施顺序

### 3.1 先准备关闭范围

执行前必须先固定三件事：

1. 新基线时间：`2026-04-26 00:00 Asia/Shanghai`
2. 默认关闭范围：所有历史任务
3. 例外名单：`0` 到 `5` 条

### 3.2 再收保留名单

如果存在必须保留的旧任务，执行顺序固定为：

1. 先由你点名保留任务
2. 再生成最终关闭清单
3. 最后批量执行关闭

禁止边关边想。

### 3.3 再统一关闭旧任务

批量关闭时必须统一：

1. 关闭状态口径
2. comment 模板
3. 截止时间口径

本轮默认关闭状态固定为：

1. `done`

禁止实现者在执行时临时改成：

1. `archived`
2. `blocked`
3. 其他未在当前仓运行链中稳定使用的终态

推荐 comment 模板固定包含：

1. 历史任务基线重置
2. 本任务属于 `2026-04-26` 之前的旧窗口
3. 后续以新基线后产生的新任务为准
4. 如问题仍成立，应由新规则重新生成新任务

推荐 comment 模板正文固定为：

```text
历史任务基线重置时间：<ISO 时间>
- 当前收口状态：done
- 历史窗口：2026-04-26 00:00 Asia/Shanghai 之前创建
- 当前说明：本任务按历史窗口统一收口，不代表问题已技术解决
- 后续口径：后续仅跟踪新基线后产生的新任务
- 若问题仍成立：应由新模板 / 新执行规则重新生成新的任务，而不是继续复用本任务
```

### 3.4 关闭后只看新任务

关闭旧任务后，后续窗口默认只观察：

1. 新产生的 automation 任务
2. 新产生的普通人工任务
3. 普通任务本地 Mac 自动执行链路上的样本表现

## 4. 与本地 Mac 自动执行主线的关系

本计划必须明确：

1. 历史任务全量关闭，不替代普通任务本地 Mac 自动执行主线
2. 普通任务先在本地 Mac 自动执行，才是新基线后的第一主线
3. automation 模板语义修复退到其后
4. 历史任务关闭只是为了把旧噪音从控制面视图中移开

也就是说：

1. 旧任务是“收口动作”
2. 普通任务本地 Mac 自动执行是“第一治理动作”
3. automation 模板语义修复是“第二治理动作”

## 5. 例外管理规则

### 5.1 例外名单格式

如需保留个别旧任务，建议固定记录：

1. `identifier`
2. `保留原因`
3. `预计保留到何时`
4. `谁负责继续跟进`

### 5.2 例外名单控制

必须控制：

1. 总量不超过 `5`
2. 不允许把整个旧桶整体保留
3. 不允许因为“也许以后还会看”就默认保留

## 6. 完成标准

只有同时满足下面条件，本轮计划才算可执行：

1. 新基线时间已固定
2. 默认关闭范围已固定为“历史普通任务 + 历史 automation 任务”
3. 例外名单规则已固定
4. 已明确默认终态使用 `done`
5. 已明确关闭旧任务不是技术问题已解决
6. 已明确新基线后先满足普通任务在本地 Mac 自动执行
