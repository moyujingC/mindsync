## 1. 目的

本文件专门回答一个问题：

`一镜一梳` 的“报告产品”到底要帮用户完成什么任务。

这里先不直接讨论最终命名，也不强行把当前产品永久限定为 `Lite / Pro` 两档，而是先定义报告这一类产品的核心用户任务。

后续若要优化：

- 当前临时 Lite / Pro 报告
- 新的报告矩阵
- 报告内容结构
- 报告阅读流程
- 报告后的承接动作

都应优先回到本文件校验。

## 2. 报告产品的定位

报告产品的本质是：

- `理解产品`

而不是：

- 训练产品
- 陪伴产品
- 活动产品
- 专业治疗替代品

报告的核心价值不是“内容很多”，而是：

1. 让用户觉得自己被看见
2. 让用户觉得自己的状态被说清楚了
3. 让用户知道这张画为什么会被这样理解
4. 让用户知道下一步可以往哪里走

一句话定义：

`报告负责把用户从“模糊”带到“明白”。`

## 3. 报告的核心目标用户

报告产品当前优先服务以下三类用户：

### 3.1 看懂自己型

典型心态：

- “我最近有很多感受，但说不清。”
- “我想知道自己到底是怎么回事。”
- “我想看这张画到底表达了什么。”

她对报告的核心期待：

- 命中感
- 结构化
- 被解释

### 3.2 议题解决型

典型心态：

- “我不是泛泛地想看自己，我是卡在关系/事业/边界上。”
- “我想知道这个问题为什么反复出现。”
- “我想知道这张画和我现在的问题有什么关系。”

她对报告的核心期待：

- 具体
- 贴场景
- 不只是人格描述

### 3.3 情绪安放型中的部分用户

典型心态：

- “我状态不太好，想找一点理解。”
- “我想被接住，但也想知道自己发生了什么。”

她对报告的核心期待：

- 温柔
- 不压迫
- 有共鸣

## 4. 报告不优先服务的用户

以下用户不是报告产品的第一优先承接对象：

### 4.1 审美探索型的纯体验用户

她更适合先从：

- 账号内容
- 陪你画 / 共修营

进入，而不是一开始就读一份高密度报告。

### 4.2 高复杂度支持型

当用户的问题明显超出 AI 适合主承接的范围时，报告不应继续承担主要责任。

报告可以做的只有：

- 温和承认边界
- 提醒外部专业支持

不应假装自己能完成复杂承接。

## 5. 报告产品的用户任务

这里采用任务视角，而不是功能视角。

也就是说，不问“报告包含什么模块”，而先问“用户为什么要打开这份报告”。

## 5.1 一级任务：被看见

用户任务：

- “我想确认：我现在这种状态不是乱，而是有迹可循。”

用户希望报告完成什么：

1. 迅速说中她当前的核心状态
2. 让她觉得“这不是在套模板”
3. 让她产生“对，就是我”的感觉

对应产品要求：

- 开头不能过慢
- 第一屏或第一段就要有命中感
- 语气要像在理解人，而不是在展示方法

失败信号：

- 用户读了很多，还是不知道这份报告到底在说什么
- 用户觉得文字漂亮，但没有真正说中她

## 5.2 一级任务：被解释

用户任务：

- “我想知道：为什么会这样。”

用户希望报告完成什么：

1. 把画面元素与状态判断连接起来
2. 把状态判断与现实模式连接起来
3. 让她理解这不是随便说说，而是有依据的

对应产品要求：

- 报告必须包含“解释链”
- 不能只有形容词堆积
- 不能只有共鸣语言，没有判断依据

失败信号：

- 用户会问：“你为什么这么说？”
- 用户觉得内容像泛心理测试结果

## 5.3 一级任务：被命名

用户任务：

- “我心里的东西终于有名字了。”

用户希望报告完成什么：

1. 帮她命名当前状态
2. 帮她命名模式
3. 帮她命名卡点

对应产品要求：

- 报告需要把模糊感翻译成可理解的结构
- 比如：
  - 当前状态
  - 核心拉扯
  - 反复模式
  - 现实议题

失败信号：

- 用户读完只觉得被安慰，没有觉得更清楚

## 5.4 一级任务：被连接

用户任务：

- “这和我的现实生活到底有什么关系？”

用户希望报告完成什么：

1. 把画和现实场景连起来
2. 把感受和具体议题连起来
3. 把内在模式和外在行为连起来

对应产品要求：

- 报告至少要能落到一个现实维度
- 例如：
  - 关系
  - 情绪
  - 表达
  - 边界
  - 事业阶段

失败信号：

- 用户觉得“说得都对，但跟我的现实没什么关系”

## 5.5 一级任务：被指引

用户任务：

- “那我接下来怎么办？”

用户希望报告完成什么：

1. 不是提供大量动作
2. 而是提供一个恰当的下一步
3. 让她知道自己可以往哪里继续

对应产品要求：

- 报告末尾需要一个低压、可接受的下一步
- 这一步可以是：
  - 一个轻觉察动作
  - 一个微练习
  - 进入主题方案
  - 进入 21 天定制方案
  - 参加陪你画活动

失败信号：

- 用户读完停在“懂了，但然后呢”

## 6. 报告的次级任务

在一级任务之外，报告还有几个次级任务，但优先级低于前面五项。

### 6.1 建立专业信任

报告要让用户相信：

- 这不是随机生成
- 背后有方法论
- 画面的解读有内部逻辑

### 6.2 建立产品升级意愿

报告本身也是后续产品的承接点。

它应帮助用户判断：

- 我是否还想继续更深入
- 我更适合进入主题方案还是 21 天定制方案
- 我是否更适合先去参加陪你画或共修活动

### 6.3 建立长期关系

报告不是一次性交付文件，它也应成为后续 AI 陪伴的起点。

## 7. 报告不该承担的任务

为了防止报告产品无限膨胀，以下任务明确不由报告主承担：

### 7.1 不负责长期改变

报告可以提供方向，但不应承担长期 program 的全部责任。

### 7.2 不负责主题训练

如果用户已经明确想解决某个问题，应转向主题方案，而不是继续在报告里塞更多建议。

### 7.3 不负责深度连续陪伴

连续陪伴更适合：

- AI 长期陪伴模块
- 21 天定制方案

### 7.4 不负责高复杂度专业承接

当问题超出 AI 主承接边界时，报告必须停下来，而不是继续伪装能处理一切。

## 8. 报告的最小成功标准

一份“成立”的报告，至少应同时满足以下四个条件：

### 8.1 有命中感

用户至少读到 1-3 句时会明确觉得：

- “这说中了我”

### 8.2 有解释链

用户能理解：

- 为什么这张画会被这样理解

### 8.3 有现实连接

用户能看见：

- 这和我最近的关系/情绪/状态/议题有什么关系

### 8.4 有下一步

用户知道：

- 我读完之后可以做什么

## 9. 报告的最小内容结构

基于用户任务，而非基于页面美观，当前建议报告最小结构如下：

1. `整体命中句`
   - 第一段就要说中状态
2. `画面依据`
   - 这张画有哪些关键特征
3. `状态解释`
   - 这说明了什么
4. `模式 / 议题连接`
   - 它会怎么出现在现实里
5. `一个下一步`
   - 轻量、可接受、可继续

这 5 段是报告的最小骨架。

如果后续扩展，也应围绕用户任务增加，而不是只为了显得更长。

## 10. 对当前 Lite / Pro 评估的启发

基于本文件，后续评估当前 Lite / Pro 内容时，应优先看这些问题：

### 10.1 Lite 评估问题

1. 开头是否足够快地建立命中感
2. 是否讲清楚“为什么这么判断”
3. 是否和现实议题连接
4. 是否让用户觉得这是一个完整付费产品，而不是轻提示卡
5. 是否给了一个明确、不过量的下一步

### 10.2 Pro 评估问题

1. 是否真正比基础报告多出“更深的理解”
2. 是否形成了更强的洞察递进，而不是更长的文字
3. 是否有更完整的证据链与机制层
4. 是否能自然承接进入方案或长期陪伴

## 11. 当前结论

当前阶段，报告产品不是“所有事情都做一点”的容器，而应集中完成五项任务：

1. 被看见
2. 被解释
3. 被命名
4. 被连接
5. 被指引

只有先把这五件事做好，后续：

- Lite / Pro 的内容优化
- 报告价格判断
- 报告与方案的边界

才有稳定基础。

## 13. 报告产品的分层原则

在前面 1-12 节基础上，当前进一步明确：

`一镜一梳` 的报告产品，当前就按下面三种商品理解：

- `Lite`
- `Pro`
- `Journey`

这里不再额外引入新的一级报告命名。

真正需要区分的，是每种商品里的解读方式：

1. `Lite`
   - `全面解读`
   - `专题解读`
2. `Pro`
   - `全面解读`
   - `专题解读`
3. `Journey`
   - 基于多次历史画作的长期综合解读

因此，当前主框架不是：

- 先理解一套内容能力分层，再去映射商品层

而是：

- 直接以用户真正会购买和感知到的三种报告来组织

## 14. 当前建议的 3 种报告

| 报告类型 | 主要服务谁 | 核心用户任务 | 主价值 | 最适合的后续承接 |
|---|---|---|---|---|
| Lite | 情绪安放型中的轻中度用户、初次进入报告的用户 | 先被接住，先看见当下状态 | 低压命中感、轻解释、轻连接 | 再画一幅 / 陪你画 / Pro / 主题方案 |
| Pro | 看懂自己型、议题解决型中的高意愿用户 | 更完整地看懂自己，或围绕某个主题看清楚 | 稳定解释链、模式命名、现实连接、主路径 | 主题方案 / 多次画作后进入 Journey |
| Journey 报告 | 成长深化型、高意愿持续用户 | 基于多次历史画作看见反复模式、机制与优先级 | 深层机制、根源递进、行动方向 | 21 天定制方案 / 长期 AI 陪伴 |

### 14.1 Lite

`Lite` 当前应支持两种解读方式：

1. `全面解读`
   - 当用户没有选主题时默认进入
2. `专题解读`
   - 当用户选了某个主题时围绕该主题展开

它负责解决的问题是：

- 用户现在状态乱，但还没有准备好进入高密度分析
- 她此刻首先需要被接住，而不是被讲一套复杂逻辑
- 她希望先知道“我现在大概怎么了”

它的成立标准是：

1. 开头很快命中
2. 语气低压
3. 有依据、有解释，但不过量
4. 能落回当前主题或当前生活面向
5. 有一个轻轻的下一步

它不负责：

- 深层机制拆解
- 高密度结构化命名
- 长周期行动设计

它的最小内容骨架应是：

1. 当前状态命中
2. 画面中的主要依据
3. 一句温柔但清楚的解释
4. 一句现实连接
5. 一个低压下一步

### 14.2 Pro

`Pro` 当前也应支持两种解读方式：

1. `全面解读`
   - 当用户没有选主题时默认使用
2. `专题解读`
   - 当用户选了某个主题时围绕该主题做完整解读

它负责解决的问题是：

- 用户不只想被看见，她想真正看懂自己
- 她有很多感受，但说不清，或者已经明确卡在某个主题上
- 她希望从模糊进入明白，或者把一个现实问题看透一点

它的成立标准是：

1. 有明显命中感
2. 有稳定解释链
3. 能帮用户命名状态与模式
4. 能落回现实生活或当前主题
5. 能给出清楚下一步

它不负责：

- 跨多次历史画作的长期模式判断
- 深层根源拆解到成长方案级别
- 替代主题方案或 21 天定制方案

它的最小内容骨架应是：

1. 整体命中句
2. 画面依据
3. 状态解释
4. 模式命名
5. 现实连接
6. 一个下一步

当前优先适合做成 `专题解读` 的主题包括：

- 关系
- 边界
- 情绪稳定
- 表达
- 事业阶段

### 14.3 Journey 报告

它负责解决的问题是：

- 用户已经不满足于“知道自己怎么了”
- 她更想知道“为什么我总会这样”
- 她已经有多次历史画作，可以据此看到更稳定的重复模式、形成机制与改变优先级

它的成立标准是：

1. 比单次 `Pro` 报告多出质变，而不是只多字数
2. 有跨多次画作的证据链
3. 有更明确的机制递进
4. 有更清楚的根源层次
5. 有更强的行动承接能力

它不负责：

- 专业治疗替代
- 高风险心理承接
- 直接变成 21 天方案本身

它的最小内容骨架应是：

1. 深层主判断
2. 结构化执行摘要
3. 机制拆解
4. 根源递进
5. 优先级判断
6. 后续进入方案或长期陪伴的方向

## 15. 三种报告之间的关系

### 15.1 不是线性升级关系

这三种报告不是：

- `Lite -> Pro -> Journey`

这样一条对所有用户都成立的强制升级链。

更合理的理解是：

- `Lite`
  - 是低压进入型报告
- `Pro`
  - 是单次画作下的完整正式解读
- `Journey`
  - 是基于多次历史画作的高阶长期解读

### 15.2 当前推荐主路径

当前更推荐的主路径是：

1. 对刚进入、状态较乱、承载力较低的用户
   - `账号内容 / 陪你画 / Lite`
2. 对大多数真正愿意付费看懂自己的用户
   - `Pro`
3. 对已经明确“我卡在关系/边界/事业”的用户
   - `Pro / 专题解读`
4. 对已经建立信任、愿意继续深入的用户
   - `Journey 报告`

### 15.3 报告与非报告产品的边界

下面这些不应继续混进报告定义里：

- `主题方案`
  - 它是改变产品，不是理解产品
- `21 天定制方案`
  - 它是连续推进产品，不是理解产品
- `长期 AI 陪伴`
  - 它是陪伴产品，不是一次性报告
- `陪你画 / 共修营`
  - 它是过程与场域产品，不是报告

## 16. 与当前 Lite / Pro 原型的关系

为了避免当前系统与新定义断裂，当前先做如下收束：

### 16.1 当前 Lite 原型

当前 `Lite` 原型应直接被理解为：

- `Lite / 全面解读`
- `Lite / 专题解读`

它的问题不是名字，而是：

1. 解释链还不够稳定
2. 主题利用还不够强
3. 还没有把“轻但成立”写得足够清楚

### 16.2 当前 Pro 原型

当前 `Pro` 原型应直接被理解为：

- `Pro / 全面解读`
- `Pro / 专题解读`

并夹带了一部分本不应在单次解读里直接成立的深层分析倾向。

它的问题不是名字，而是：

1. 全面解读和专题解读还没有稳定拉开
2. 递进结构不够稳
3. 还没有把 `Pro` 比 `Lite` 多出的质变讲清楚

## 17. 当前阶段的收束建议

基于以上定义，当前建议先收束到下面四个判断：

1. 当前产品真相就是 `Lite / Pro / Journey`
2. `Lite` 和 `Pro` 都支持：
   - `全面解读`
   - `专题解读`
3. 当用户没有选主题时，`Lite` 和 `Pro` 都默认进入 `全面解读`
4. `Journey 报告` 是基于多次历史画作的高阶分析，不等于“只是更长的 Pro”
5. 后续文档应优先围绕三种商品和两类单次解读方式继续展开

## 18. 本轮做什么 / 不做什么

### 18.1 本轮做什么

本轮先明确：

- 报告产品的长期分层原则
- 当前建议的报告矩阵
- 各类报告的用户任务与边界
- 新矩阵与当前 Lite / Pro 原型的映射关系

### 18.2 本轮不做什么

本轮暂不直接定义：

- 最终对外命名
- 最终定价
- 页面入口排序
- 每一类报告的最终 UI 结构
- 每个主题是否都立刻独立成单独报告

## 19. 后续建议

基于本轮定义，后续最适合继续补的文档不再只是：

- 当前 Lite 报告优化提纲
- 当前 Pro 报告优化提纲

而应优先变成：

1. `Lite` 内容优化提纲
2. `Pro` 内容优化提纲
3. `Journey 报告` 产品定义
4. `Lite / Pro / Journey` 结果页分流策略

如果只允许先做一篇，当前最值得优先展开的是：

- `Pro` 内容优化提纲

因为它最可能成为后续单次报告体验的中枢。
