## 1. 背景

Batch E 已把报告链路修到 runtime、narrative、contract、debug 都可追溯，但当前固定样本体系仍缺少人工可读质量闭环。

当前问题固定为：

1. workbench 当前会生成完整报告，但 `toC/data/knowledge/builds/*/evals/*.json` 只沉淀摘要，不沉淀可复审的完整报告快照。
2. `fixtures/toc-mvp/evidence/*.md` 目前主要是样本治理说明，不是“本次输出 + 教程对照 + 偏差结论”的 golden 证据。
3. 因此现在还不能稳定回答“这份报告是否仍在曲解原始解读教程算法”。

## 2. 目标行为

Batch F 完成后，固定样本体系必须满足：

1. `toc-mvp-fixture-001` Lite、`toc-mvp-fixture-002` Pro、`toc-mvp-fixture-002` Lite 都能导出完整 golden 审阅资产。
2. 每份审阅资产都能同时看到：
   - 完整报告快照
   - 面向人工阅读的 Markdown 摘录
   - 精简 debug trace
   - 正式审阅结论
3. 人工审阅必须同时回答：
   - 是否符合四步法顺序
   - 是否符合 Lite / Pro 产品定位
   - 是否存在偏差，以及偏差属于哪一层
4. 偏差必须进入结构化回灌记录，而不是只留在聊天或 QA 摘要里。
5. 自动化 eval summary 继续保留机器摘要角色，但不能冒充人工审阅结论。

## 3. 审阅模型

本批固定采用两层审阅模型：

1. 自动摘要层
   - 继续使用 `evals/*.json` 与 `summary.json`
   - 负责字段完整性、fallback、warning、algorithm fidelity 等程序性检查
2. 人工 golden 层
   - 负责完整报告快照、人工审阅 markdown、偏差结论和下一批回灌入口
   - 不复用 `evals/*.json` 作为唯一审阅载体

golden 审阅资产固定落到：

- `projects/aimandala/fixtures/toc-mvp/golden/<fixture-id>/<mode>.report.json`
- `projects/aimandala/fixtures/toc-mvp/golden/<fixture-id>/<mode>.report.md`
- `projects/aimandala/fixtures/toc-mvp/golden/<fixture-id>/<mode>.debug.json`
- `projects/aimandala/fixtures/toc-mvp/golden/<fixture-id>/<mode>.review.md`

## 4. 审阅口径

人工 rubric 固定按两轴执行。

算法轴必须判断：

1. 是否先给直断命中，而不是先给抽象总结。
2. 是否明确给出逐圈颜色、深浅、面积依据。
3. 是否只在必要时使用形状分析，且不越权替代颜色判断。
4. 是否在基础元素状态之后，再进入关系失衡解释。
5. 是否能指出当前议题下的主判断来自哪条教程链。

产品轴必须判断：

1. Lite 是否独立闭环，不依赖 Pro。
2. Pro 是否独立闭环，不引用 Lite。
3. `topic_context.orientation` 是否帮助用户理解议题，而不是扩成一章。
4. Lite 疗愈是否轻量、即时、低压。
5. Pro 疗愈是否与失衡或根因链绑定，而不是只更长。
6. 是否残留升级、解锁、补全版等旧语义。
7. 是否存在 raw dict、占位分析、fallback 伪装成正常结论。

每份审阅固定输出：

- `pass`
- `pass_with_drift`
- `fail`

若不是纯 `pass`，必须同时落一条结构化偏差项：

- `deviation_id`
- `fixture_id`
- `mode`
- `topic`
- `tutorial_step`
- `symptom`
- `suspected_layer`
- `severity`
- `next_owner`

## 5. 非目标

本批不做：

1. 不改 Lite / Pro 对外字段 shape。
2. 不把 prompt 调整当成主修复手段。
3. 不在本批顺手继续修 `shape_analysis`、narrative 压缩或主题语言。
4. 不把 `004` 直接纳入第一批主 golden 样本。

## 6. 成功标准

本批成功标准固定为：

1. `001-lite`、`002-pro`、`002-lite` 都存在完整 golden 资产。
2. `001` 与 `002` evidence 文档升级为正式审阅索引页。
3. `eval summary` 明确新增人工审阅聚合字段，但与自动检查语义分离。
4. 每份审阅都能给出明确结论与偏差回灌入口。
5. 正式文档与 golden 资产元数据不再出现机器绝对路径。
