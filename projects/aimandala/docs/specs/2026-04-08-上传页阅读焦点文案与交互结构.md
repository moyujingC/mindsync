## 1. 目的

本文件专门收束上传页最容易让用户困惑的一层：

- 用户在上传页到底应该看到什么语言，才能顺利表达这次想看的重点，而不是被迫先理解整个报告矩阵

这份文档重点回答：

1. 上传页该如何介绍“阅读焦点”
2. 焦点选项应该怎么命名
3. 焦点选择与后续 `Lite / Pro` 选择页的关系该如何说明
4. 上传完成后，页面应如何自然进入 `Lite / Pro` 选择页

它不是：

- 技术实现文档
- 最终视觉稿
- 最终运营文案
- 报告类型定义文档

它是：

- 上传页用户语言 spec
- 阅读焦点交互 spec
- 上传页到 `Lite / Pro` 选择页的衔接 spec

## 2. 当前适用范围

本规则当前只适用于 `To C MVP` 的单次画作主路径：

1. `upload`
2. 上传后的 `三圈识别`
3. 到 `Lite / Pro` 选择页之前的衔接说明

当前不覆盖：

1. `Journey` 的独立入口
2. 历史页里的深度引导
3. 结果页 CTA 文案
4. `Lite / Pro` 选择页的完整卡片文案
5. 支付页的最终商品话术

## 3. 当前最重要的收束判断

本轮先收束到下面 8 个判断：

1. 上传页对用户公开的是 `阅读焦点`，不是 `报告类型`
2. 上传页只让用户回答：
   - `这次更想重点看什么`
3. 焦点选择不是最终诊断，也不是最终报告结论
4. 用户即使选了某个主题，也不等于一定直接进入某个固定报告
5. 上传页不直接展示 `Lite / Pro / Journey` 三层产品货架
6. 如果用户不主动选主题，默认走 `general`
7. `general` 的用户可见语言应是 `全面看看`
8. 上传后会先经过 `三圈识别`，再进入明面的 `Lite / Pro` 选择页

## 4. 上传页的页面任务

上传页最核心的任务只有 4 个：

1. 让用户完成图片上传
2. 让用户补充最少必要上下文
3. 让用户说出这次最想重点看的方向
4. 让用户自然进入下一步，而不是在入口就被产品结构劝退

因此，上传页不应该承担：

1. 教用户理解三种报告矩阵
2. 解释 `全面解读 / 专题解读` 的内部区别
3. 做成商品选择页
4. 一上来就讨论价格

## 5. 上传页建议结构

当前建议上传页按下面顺序组织：

1. `上传作品`
2. `补充这次的简单背景`
3. `选择这次更想重点看的方向`
4. `进入下一步`

对应的用户理解应该是：

1. 我先把画上传上来
2. 我简单说一下这次的状态
3. 我告诉系统这次更想从哪个角度看
4. 系统先完成识别，再让我自己选 `Lite` 或 `Pro`

## 6. 上传页建议文案

## 6.1 焦点模块标题

当前建议优先使用下面一类标题：

- `这次你更想重点看什么？`

可接受备选：

- `如果你愿意，这次可以选一个更想重点看的方向`
- `这次你更想先看哪一部分？`

当前不建议：

- `请选择报告类型`
- `请选择解读版本`
- `请选择全面解读 / 专题解读`

## 6.2 焦点模块辅助说明

当前建议配一行很短的说明：

- `你可以先全面看看，也可以选一个最近更在意的主题。`

可接受备选：

- `这只是这次的阅读焦点，不是对你的最终定义。`
- `如果没有特别想看的主题，就选“全面看看”。`

## 6.3 上传按钮附近的说明

当前建议上传页底部给一条轻说明：

- `上传后会先进行识别，再进入 Lite 和 Pro 的选择页。`

这样可以提前解释：

1. 上传后不是直接开始生成
2. 中间还会经过识别与选择页
3. 用户不是提交后就被黑盒分流

## 7. 阅读焦点选项设计

## 7.1 焦点值与用户可见名称

当前建议保留下面 6 个焦点值：

| 内部值 | 用户可见名称 | 一句话说明 |
|---|---|---|
| `general` | `全面看看` | 先整体看看我现在是什么状态 |
| `relationship` | `关系` | 我最近更想看看关系里的感受和拉扯 |
| `boundary` | `边界` | 我更想看看自己在靠近、拒绝或保护上的状态 |
| `emotion` | `情绪` | 我更想看看最近情绪里的起伏、压住或耗竭 |
| `expression` | `表达` | 我更想看看自己在表达、说出口或创作上的卡点 |
| `career` | `事业` | 我更想看看工作、方向感和现实推进里的状态 |

## 7.2 默认项

当前建议默认选中：

- `全面看看`

原因是：

1. 它能降低用户的选择负担
2. 用户即使不选主题，也能清楚知道这次会走“整体阅读”
3. 它比完全留空更不容易让用户以为自己漏填了什么

这里的默认逻辑应明确写成：

- `全面看看（默认）`

## 7.3 焦点卡片的说明风格

每个焦点项的说明都应满足下面 4 条：

1. 像用户会说的话
2. 强调“这次想先看哪里”
3. 不使用分析术语
4. 不暗示已经对用户做了分类

例如：

- 好的写法：`我最近更想看看关系里的感受和拉扯`
- 不好的写法：`分析你的关系模式`

## 8. 交互规则

## 8.1 选择方式

当前建议焦点模块采用：

- `单选`

原因是：

1. 单次报告需要一条清楚主线
2. 多选会让上传页重新变复杂
3. 也更方便后续进入 `全面解读` 或 `专题解读`

## 8.2 是否允许不选

产品逻辑上允许用户不主动改选，但页面表现上不建议让它处于空状态。

更准确的规则是：

1. 页面默认选中 `全面看看`
2. 用户可以主动改选成某个主题
3. 用户不改选，就按 `general` 进入下一步

## 8.3 焦点是否可修改

当前建议焦点至少在上传页可修改。

如果后续 `Lite / Pro` 选择页也要显示主题，则可以允许：

1. 上传页修改
2. 选择页回退后再改

这样可以降低用户的黑盒感：

1. 上传时先做低成本表达
2. 到选择页前，用户仍知道自己这次提交了什么方向

## 8.4 焦点与报告的关系提示

上传页不需要把关系讲得太复杂，但至少要让用户知道：

- `这次选的只是阅读方向，上传后你还可以在 Lite 和 Pro 之间自己选择。`

## 9. 上传后到 Lite / Pro 选择页的衔接规则

## 9.1 页面任务

上传完成后，链路至少要让用户理解下面 4 件事：

1. 会先进行 `三圈识别`
2. 识别之后才进入 `Lite / Pro` 选择页
3. `Lite / Pro` 是用户自己选，不是系统替她选
4. 当前上传页里的主题会继续带到后面的解读里

## 9.2 上传页应该提前说清什么

当前建议上传页至少要提前说清：

1. 上传后不是立即出报告
2. 中间会先做识别
3. 识别后会进入 `Lite / Pro` 选择页
4. 主题只影响后续内容方向，不直接替代版本选择

## 10. 焦点到解读方式的建议映射

## 10.1 `general`

当用户选择 `全面看看` 时，更适合理解为：

1. 如果后续选 `Lite`
   - 更接近 `Lite / 全面解读`
2. 如果后续选 `Pro`
   - 更接近 `Pro / 全面解读`

## 10.2 具体主题

当用户选择具体主题时，更适合理解为：

1. 如果后续选 `Lite`
   - 更接近 `Lite / 专题解读`
2. 如果后续选 `Pro`
   - 更接近 `Pro / 专题解读`

但这里要明确：

1. 这不是自动硬路由
2. 当前不会由系统替用户决定 `Lite` 还是 `Pro`
3. 主题不等于自动升级到更深层商品

## 11. 当前最需要避免的写法

当前最需要避免下面 8 种写法：

1. 上传页直接写 `请选择 Lite / Pro / Journey`
2. 上传页直接写 `请选择全面解读 / 专题解读`
3. 把 `阅读焦点` 写成心理测试题
4. 把主题名称写得过于抽象或专业
5. 用户没选主题时，页面处于空白未选状态
6. 上传后系统直接黑盒跳转，不解释后面还会发生什么
7. 后续选择页同时出现很多强选项，像套餐货架
8. 让用户以为选了某个主题，就一定进入某个固定价格层

## 12. 当前阶段建议文案底稿

## 12.1 上传页

标题：

- `上传你的作品`

焦点模块标题：

- `这次你更想重点看什么？`

焦点模块说明：

- `你可以先全面看看，也可以选一个最近更在意的主题。`

底部提示：

- `上传后会先进行识别，再进入 Lite 和 Pro 的选择页。`

## 12.2 上传后衔接提示

过渡提示：

- `正在识别你的作品结构`
- `识别完成后，你可以选择 Lite 或 Pro 继续解读`

## 13. 当前阶段收束结论

基于以上定义，当前建议先收束到下面 5 个判断：

1. 上传页第一层只公开 `阅读焦点`，不公开完整报告矩阵
2. `全面看看` 应作为默认焦点，降低选择负担
3. 上传后会先经过 `三圈识别`，再进入 `Lite / Pro` 选择页
4. 焦点决定阅读角度，不等于最终商品层结论
5. 后续上传页、选择页、支付页与结果页文案，都应回到这份文档统一校验
