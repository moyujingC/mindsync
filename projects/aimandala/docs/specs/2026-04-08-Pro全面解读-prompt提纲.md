## 1. 目的

本文件用于定义 `Pro / 全面解读` 的 prompt 提纲。

它重点回答：

1. 这一版如何生成“更完整地看懂自己”的单次正式解读
2. 解释链应该怎样展开
3. 怎样和 `Lite / 全面解读`、`Pro / 专题解读` 拉开差异

## 2. 这份 Prompt 要完成什么

`Pro / 全面解读` 要生成的是：

- 一份围绕用户当前整体状态展开、具有稳定解释链与模式命名的单次正式解读

它最核心要完成的 5 件事是：

1. 先命中整体状态
2. 用画面和输入支持判断
3. 整理出一条可理解的解释链
4. 命名当前最主要的模式
5. 给一个清楚但不压迫的下一步

## 3. 输入优先级

当前建议 prompt 按下面顺序使用输入：

1. `画作本身`
   - 主要证据来源
2. `绘画过程中的感受`
   - 用于补强状态判断和拉扯解释
3. `绘画前意图`
   - 用于对照用户原本想看的方向与实际暴露出来的状态
4. `主题`
   - 此版本默认是 `general`，用于整体阅读视角，不做专项收束

## 4. 生成目标

prompt 应明确要求模型输出下面 7 段内容：

1. `标题`
2. `开头命中`
3. `画面依据`
4. `状态解释`
5. `模式命名`
6. `现实连接`
7. `一个主方向`

## 5. 每段生成要求

## 5.1 标题

要求：

1. 要有明确状态轴
2. 不要纯诗化
3. 要能承接整份报告主线

## 5.2 开头命中

要求：

1. 开头先完成被看见
2. 第二句或第三句再带出“这次更值得看清的主线”
3. 不要直接用摘要表口吻开场

## 5.3 画面依据

要求：

1. 至少给出 `2-4` 个关键画面锚点
2. 要把锚点与状态判断连起来
3. 意图或过程感受应从这里开始进入解释链

## 5.4 状态解释

要求：

1. 至少形成 `依据 -> 状态 -> 拉扯` 的递进
2. 让用户能复述“为什么会这样判断”
3. 不要堆多个平行结论

## 5.5 模式命名

要求：

1. 命名必须通俗、可带走
2. 不只说模式是什么，还要说它为什么形成
3. 不要使用过多术语

## 5.6 现实连接

要求：

1. 至少落一个真实生活场景
2. 要说明这种模式平时怎么出现
3. 不要只停在抽象理解层

## 5.7 一个主方向

要求：

1. 只给一个主路径
2. 要让用户知道下一步最自然该往哪里走
3. 可以为 `Pro / 专题解读` 预留桥接

## 6. 语气要求

prompt 应明确要求生成语气满足下面 5 条：

1. 有命中感
2. 有解释力
3. 有结构感
4. 有现实感
5. 有方向感，但不居高临下

## 7. 明确禁止项

prompt 应明确禁止下面写法：

1. 写成更长的 `Lite`
2. 写成信息堆叠长文
3. 写成术语展示
4. 单次画作硬写成长期固定机制
5. 把没讲清的部分丢给 AI 问答补

## 8. 推荐 Prompt 骨架

当前建议 prompt 可按下面顺序组织指令：

1. `角色定义`
   - 你要生成的是一份 `Pro / 全面解读`
2. `任务定义`
   - 帮用户更完整地看懂自己当前整体状态
3. `输入说明`
   - 画作、意图、过程感受、默认 general 主题
4. `输出结构`
   - 标题、命中、依据、解释、命名、连接、主方向
5. `语气要求`
6. `禁止项`
7. `输出前自检`

## 9. 输出前自检

prompt 末尾建议加上下面 7 条自检要求：

1. 开头是否先有命中感
2. 是否存在清楚的画面依据
3. 是否形成了一条可复述的解释链
4. 是否出现了清楚的模式命名
5. 是否落到真实生活场景
6. 是否只保留了一个主方向
7. 是否没有越界写成 `Journey`

## 10. 当前阶段收束结论

基于以上提纲，当前建议先收束到下面 4 个判断：

1. `Pro / 全面解读` 的核心是完整解释链，而不是更长
2. `画作 + 过程感受 + 意图` 应形成这版最重要的输入组合
3. 输出结构必须固定收束为 `7` 段
4. 这份 prompt 的成功标准，是让用户从“模糊”走到“明白”
