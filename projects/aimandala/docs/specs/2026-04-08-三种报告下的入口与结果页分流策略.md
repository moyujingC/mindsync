## 1. 目的

本文件专门回答一个现在必须收束的问题：

- 在三种报告已经成立之后，用户入口到底该怎么设计，结果页又该怎么承接，才能不让用户感到混乱

这份文档重点不是继续定义三种报告本身，而是定义：

1. 用户在前台到底看见什么
2. 系统在后台到底怎么判断
3. 上传页、`Lite / Pro` 选择页、生成页、结果页之间应该如何分工
4. 什么情况下应继续留在当前报告
5. 什么情况下应在结果页引导下一类报告

它不是：

- 最终 UI 稿
- 最终技术实现文档
- 最终运营投放文案
- 最终支付页文案

它是：

- 报告矩阵下的入口规则 spec
- 结果页分流规则 spec
- 用户可见层与系统内部层的边界说明

补充说明：

- 本文主要定义长期产品分流真相
- 当前 `To C MVP` 的结果页 CTA 文案，应再受 [2026-04-08-MVP阶段结果页CTA规则.md](/Users/xinran/Downloads/dev/mindsync/projects/aimandala/docs/specs/2026-04-08-MVP阶段结果页CTA规则.md) 约束

## 2. 继承的上游结论

本文件明确继承以下判断，不重复改写：

1. 当前产品真相就是 `Lite / Pro / Journey`
2. `Lite` 与 `Pro` 都支持：
   - `全面解读`
   - `专题解读`
3. 如果用户没有选主题，`Lite` 与 `Pro` 都默认进入 `全面解读`
4. `Journey` 只在有多次历史画作时才成立
5. 用户在第一次进入时，不应被迫理解完整的内部实现逻辑

## 3. 当前最重要的收束判断

本轮先收束到下面 8 个判断：

1. 上传页不直接要求用户先理解完整报告矩阵
2. 上传页先让用户完成画作与基础信息提交
3. 上传后会先进行 `三圈识别`
4. 三圈识别之后，再进入明面的 `Lite / Pro` 选择页
5. `Lite / Pro` 选择页必须告诉用户：
   - `Lite` 与 `Pro` 的内容差异
   - 价格差异
   - 选择之后会直接进入对应 loading 页面
6. 当前明面分流由用户在 `Lite / Pro` 选择页主动完成
7. `Pro` 内部可以有 `全面解读` 与 `专题解读` 两种解读方向
8. `Journey` 不属于单次上传后的直接选项，只有在存在多次历史画作时才应被推荐

## 4. 用户可见层 vs 系统内部层

## 4.1 用户可见层

用户在前台当前不需要一上来就理解的概念：

- 三种报告的完整内部实现细节
- `Pro` 内部是如何决定全面解读或专题解读
- 内部分流判定逻辑

用户在前台第一步只需要完成两件事：

1. 上传这张画
2. 补充最少必要描述

但在上传和三圈识别之后，用户应继续看见一层明确说明：

1. `Lite` 和 `Pro` 分别是什么
2. 两者内容和价格差异是什么
3. 她现在可以自己选哪一种

因此，当前更建议用户看见的是：

- `上传作品`
- `基础描述`
- `Lite / Pro` 的明面选择

而不应该一开始就直接看见：

- 复杂的内部分流判断
- 黑盒式推荐理由

## 4.2 系统内部层

系统内部仍然需要保留的概念：

1. 当前实际生成的是哪一种报告
2. 当前输入是否足以进入后续专题解读
3. 用户是否选择了主题
4. 用户是否已经具备进入更深机制层的条件

但这里要补一条关键原则：

- `内部判断` 可以存在
- `分流结果` 不能完全隐藏

也就是说：

- `上传页 + Lite / Pro 选择页` 是第一步用户可见交互语言
- `Lite / Pro / Journey` 是用户最终会理解到的报告产品
- `全面解读 / 专题解读` 是 `Lite` 与 `Pro` 内部的解读方式
- 真正不能直接暴露的，是复杂的内部生成与判定过程，而不是用户自己的选择结果

这三层必须区分，不应混写：

1. 用户先表达什么
2. 系统据此如何判断
3. 最终向用户推荐什么

## 5. 上传页与 Lite / Pro 选择页规则

## 5.1 上传页的核心任务

上传页最核心的任务不是教育用户理解三种报告，而是帮助用户低成本进入：

1. 上传作品
2. 补充必要描述
3. 感到这次解读和自己当下有关

上传页完成后，不建议直接生成结果，而应先经过：

1. `三圈识别`
2. `Lite / Pro` 选择页

## 5.2 上传页建议使用的交互语言

当前更建议上传页使用的语言是：

- `上传你的作品`
- `如果你愿意，可以补充这次的简单背景`
- `你也可以选一个这次更想重点看的主题`

当前不建议上传页直接使用的语言是：

- `请选择报告类型`
- `请选择全面解读 / 专题解读`
- `请选择基础版 / 深度版`

## 5.3 上传页建议保留的焦点类型

如果上传页当前保留主题字段，当前建议只呈现有限的主题方向：

1. `general`
   - 更像“先整体看看我现在是什么状态”
2. `father_relationship`
3. `mother_relationship`
4. `intimate_relationship`
5. `parent_child_relationship`
6. `wealth_career`
7. `health_wellness`
8. `personal_growth`

这些是用户补充的阅读方向，不是对用户公开的产品线命名。

## 5.4 Lite / Pro 选择页应如何解释 Lite / Pro

当前更建议这页优先告诉用户：

1. `Lite`
   - 更轻、更快、更像先看清当前状态的一次低压解读
2. `Pro`
   - 更完整、更深入、更像一次正式解读

如果当前还带有主题信息，也可以补一句说明：

1. `Lite` 和 `Pro` 都可能基于这次主题生成
2. 主题不会替用户自动决定价格层

## 5.5 Lite / Pro 选择页的作用

`Lite / Pro` 选择页的存在，不是为了替用户做判断，而是为了完成三件事：

1. 让分流发生在明面上
2. 让用户理解 `Lite` 和 `Pro` 到底差在哪里
3. 避免用户对价格差与内容差产生黑盒困惑

它要回答的核心问题是：

- `我现在应该选 Lite 还是 Pro`

而不是：

- `系统已经替你决定好了`

## 5.6 Lite / Pro 选择页建议结构

当前建议这页只保留非常轻量的结构：

1. `Lite 卡片`
   - 一句话说明
   - 价格
   - 继续按钮
2. `Pro 卡片`
   - 一句话说明
   - 价格
   - 继续按钮
3. `差异提示`
   - 更轻 / 更完整
4. `用户已提交内容提示`
   - 让用户知道当前选择会直接基于这次上传继续生成

## 5.7 Lite / Pro 选择页不建议做成什么

当前不建议把这页做成：

1. 复杂套餐页
2. 太长的教育页
3. 带黑盒推荐语气的选择页
4. 需要用户重新理解完整报告矩阵的页面

## 6. 第一份报告的默认落点

## 6.1 默认规则

当前 `To C MVP` 已确认的默认规则是：

- 第一份上传完成并经过 `三圈识别` 后，先进入 `Lite / Pro` 选择页

原因不是因为它“最中间”，而是因为：

1. 当前真实流程就是由用户自己选 `Lite` 或 `Pro`
2. 它让价格差和内容差发生在明面上
3. 它比黑盒推荐更符合当前产品现状
4. 它仍然能作为后续结果页分流的起点

## 6.2 `general` 的解释

当用户选择 `general` 时，更适合理解为：

- 她想先整体看懂自己当前状态

因此：

- 在当前流程里，它更适合被解释为：
  - 如果选 `Lite`，更接近 `Lite / 全面解读`
  - 如果选 `Pro`，更接近 `Pro / 全面解读`

这里更适合作为选择页上的轻说明，而不是系统替用户做自动推荐。

## 6.3 具体主题的解释

当用户选择某个具体主题时，更合理的理解是：

- 她这次希望阅读更偏向这个方向

这意味着：

1. 在当前流程里，它更适合作为选择页上的解释提示：
   - 如果选 `Lite`，更接近 `Lite / 专题解读`
   - 如果选 `Pro`，更接近 `Pro / 专题解读`
2. 如果用户最后仍选 `Pro` 下的整体理解，也可以保留主题视角
3. 结果页可以优先承接同主题的后续路径

但不意味着：

- 这一次一定只能是 `专题解读`

当前更建议在选择页明说：

- 你这次的关注点更偏某个主题
- 因此无论选 `Lite` 还是 `Pro`，都会更偏向这次主题

## 7. 当前 MVP 为什么先让用户自己选 Lite / Pro

当前流程不做系统推荐，而是让用户自己在选择页判断 `Lite` 或 `Pro`。

这样设计的现实好处是：

1. 价格差发生在明面上
2. 用户不会困惑“为什么系统这次替我选了这个版本”
3. 内容差和价格差更容易一起解释清楚

## 7.1 选择页应该怎么帮助用户做决定

虽然当前是用户自己选，但页面仍应提供足够清楚的帮助信息：

1. `Lite`
   - 更轻、更快、更像先看清当前状态
2. `Pro`
   - 更完整、更深入、更像一次正式解读
3. 如果当前带了主题
   - 也应补一句说明：两者都会围绕这次主题继续解读，只是深度不同

## 7.2 当前最需要避免的错误引导

即使页面会解释差异，也不建议：

1. 暗中把用户往某个版本推
2. 用过强的推荐语气替用户做决定
3. 把 `Lite` 写成“低配版”
4. 把 `Pro` 写成“唯一正确答案”

## 8. 什么情况下在长期分流中引导 Pro 的专题解读

长期方向上，`Pro / 专题解读` 不适合在上传页直接硬分成独立商品，但可以在 `Pro` 推荐中被明确说明是这次更贴合当前主题的解读方式。

但在当前 `To C MVP` 阶段，结果页是否出现具体动作，仍必须受 [2026-04-08-MVP阶段结果页CTA规则.md](/Users/xinran/Downloads/dev/mindsync/projects/aimandala/docs/specs/2026-04-08-MVP阶段结果页CTA规则.md) 约束。

## 8.1 适合引导 Pro 专题解读的信号

当后续版本的结果页已经能确认下面判断时，可优先引导 `Pro / 专题解读`：

1. 用户当前卡点已经明显收束到单一主题
2. 用户最在意的是某个现实问题，而不是整体看懂自己
3. 当前报告里某个主题的命中感明显高于其他部分
4. 用户读完后更自然会问：
   - “那关系里为什么总这样？”
   - “那边界这件事到底怎么回事？”
   - “那我在表达上为什么总卡住？”

## 8.2 Pro 专题解读的结果页表述原则

长期方向上，当前建议用下面这类语言承接：

- `如果你想沿着这个主题继续看清楚，可以继续看这一部分`
- `如果你更想把这个问题讲透，我们可以只围绕这个主题继续展开`

当前不建议直接让用户感到：

- 她刚刚其实“选错了报告”
- 她被系统重新改派到了另一条线路

因此更合理的承接是：

- 当前这份报告先完成当前这一轮理解
- 下一步再进入专题理解

## 9. 什么情况下在长期路径中引导 Journey 报告

`Journey` 的位置不应是单次上传后的主入口。

它只应在下面条件成立时被明确解释：

1. 用户已经有多次历史画作
2. 系统确实能做跨时间对照分析

## 9.1 适合引导 Journey 报告的信号

当出现下面判断时，可优先引导 `Journey`：

1. 用户已经有多次历史画作
2. 用户已经被命中，但仍明显觉得“不够”
3. 用户更想知道“为什么我总会这样”
4. 当前问题已经不只是单点议题，而像跨时间重复模式

## 9.2 Journey 的表述原则

当前更建议用下面这类承接语言：

- `如果你想继续看见更深一层的重复模式，可以继续往下看`
- `如果你已经不只想知道现在怎么了，而想知道为什么总会这样，可以继续深入`

当前不建议把它写成：

- `升级到更贵版本`
- `解锁完整版报告`

因为这会把用户重新拉回旧的 `Lite / Pro` 认知。

但在当前 `To C MVP` 阶段，上述内容只应保留为长期产品方向，不应直接写进当前结果页 CTA。

## 10. 三种报告的承接方向

长期产品方向上，当前建议的主承接方向如下：

| 当前报告 | 更适合承接什么 | 说明 |
|---|---|---|
| Lite | `Pro` / `再画一幅` | 先从轻解读走向更完整理解，不急着推深 |
| Pro / 全面解读 | `Pro / 专题解读` / `多次画作后进入 Journey` | 当某个主题逐渐收束时，可以继续往专题方向走 |
| Pro / 专题解读 | `同主题再画一幅` / `多次画作后进入 Journey` | 更适合继续往专题理解或后续积累走 |
| Journey 报告 | `21 天定制方案` / `长期 AI 陪伴` / `优先级动作` | 更适合进入连续路径，而不是再回到浅层报告 |

当前 `To C MVP` 页面动作上，应进一步收束为：

| 当前页面 | 当前主 CTA | 当前辅助动作 |
|---|---|---|
| Lite 结果页 | `查看更深层报告` / `看看更深层模式` / `带着这份理解再画一幅` | `重新上传画作` / `查看历史记录` |
| Pro 结果页 | `再画一幅` | `保存报告` / `开始 AI 对话` / `查看历史记录` |

当前页面内可点击动作，以 [2026-04-08-MVP阶段结果页CTA规则.md](/Users/xinran/Downloads/dev/mindsync/projects/aimandala/docs/specs/2026-04-08-MVP阶段结果页CTA规则.md) 为准。

## 11. 结果页 CTA 优先级

## 11.1 总原则

结果页的目标不是一次性把所有后续产品都摆出来，而是：

1. 先完成这份报告本身的交付
2. 只给一个最自然的主动作
3. 允许再保留一个更轻的次动作

## 11.2 当前建议规则

当前建议每个结果页最多保留：

1. `1` 个主 CTA
2. `1` 个次 CTA

推荐顺序如下：

1. 主 CTA
   - 指向当前最自然的下一步理解或行动
2. 次 CTA
   - 指向更轻的继续陪伴、再画一幅或延后决策

## 11.3 当前不建议事项

当前不建议结果页出现以下情况：

1. 同时并列展示 `3` 个以上强 CTA
2. 一边引导 `Pro / 专题解读`，一边引导 Journey，一边又推活动，权重都一样
3. 把所有报告类型直接摆成菜单让用户重新选
4. 把结果页写成“产品货架”

## 11.4 MVP 阶段的额外收束

上面这些规则定义的是长期产品分流方向。

但在当前 `To C MVP` 阶段，还需要额外补一条现实约束：

- 结果页 CTA 只能写当前已经存在、且点击后能走通的动作

因此在当前阶段：

1. `Lite` 结果页可以围绕：
   - `进入 Pro`
   - `再画一幅`
   - `查看历史记录`
2. `Pro` 结果页当前应先收束为：
   - `再画一幅`
   - 以及页面内已有的 `保存报告`、`开始 AI 对话`、`查看历史记录`
3. `主题方案`
4. `Journey`
5. `21 天定制方案`
6. `长期 AI 陪伴`
   - 当前都不应直接写进 MVP 的结果页 CTA

## 12. 可执行分流判断表

| 场景 | 用户可见输入 | 系统内部判断 | 当前输出 / 承接建议 |
|---|---|---|---|
| 初次进入，想整体看看 | `general` | 当前不做黑盒推荐 | 选择页由用户自己选 `Lite` 或 `Pro`；文案说明更偏整体解读 |
| 初次进入，选了具体主题，但还在泛模糊状态 | `intimate_relationship` / `wealth_career` / `personal_growth` 等 | 主题作为阅读方向，但不自动决定价格层 | 选择页由用户自己选 `Lite` 或 `Pro`；文案说明会更偏主题解读 |
| 初次进入，明显只想先被接住 | 任意主题或未选主题 | 当前仍不替用户自动决策 | 选择页可把 `Lite` 写得更易理解，但仍由用户自己选择 |
| 已读 Pro 全面解读，明确还想继续看某一主题 | 结果页行为 / 明确表达 | 主题已收束 | 引导 `Pro / 专题解读` |
| 已读 Pro，明确想看更深机制，且已有多次历史画作 | 结果页行为 / 明确表达 | 深度意愿成立且输入条件满足 | 作为长期产品方向，可在后续版本中引导 `Journey` |
| 已读 Journey 报告，想继续推进 | 结果页行为 / 明确表达 | 进入连续路径 | 作为长期产品方向，可在后续版本中引导连续服务 |

## 13. 当前阶段最重要的避免事项

当前最需要避免重新滑回下面 6 种写法：

1. `选主题 = 自动进入另一种完全不同等级的报告`
2. 上传后系统默默分流，却不给用户解释
3. 上传页直接要求用户理解很多内部报告差异
4. 把 `Journey 报告` 写成“完整版”
5. 把 `Lite` 写成“缩水版”
6. 让用户以为单次一幅画也能直接得出长期稳定模式

因为这些写法都会把已经收束好的三种报告结构，重新拉回：

- 轻版 / 重版
- 入门版 / 升级版
- 用户必须先理解产品线再开始使用

这类旧逻辑。
