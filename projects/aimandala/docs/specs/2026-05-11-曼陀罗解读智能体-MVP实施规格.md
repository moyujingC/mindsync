## 1. 目标

MVP 阶段重做 `曼陀罗解读智能体`，用于生成财富议题 Lite / Pro 解读报告。

实现依据只来自：

1. 架构边界：[解读智能层-曼陀罗解读智能体架构.md](../architecture/解读智能层-曼陀罗解读智能体架构.md)
2. 方法入口：[曼陀罗基础层解读流程.md](../疗愈体系知识库/20-疗愈体系/20-流派层/10-曼陀罗/00-曼陀罗基础层解读流程.md)
3. 手册原文：[01-曼陀罗解读手册原文.md](../疗愈体系知识库/20-疗愈体系/20-流派层/10-曼陀罗/90-来源原文/01-曼陀罗解读手册原文.md)

旧 `stage_process_package / builder_v2 / placeholder renderer / 16 stage` 链路不再作为新实现依据。

## 2. MVP 范围

### 2.1 要做

- 新增端到端直出报告链路。
- 新增轻量视觉草稿 `visual_draft`。
- 新增版本化稳定前缀包 `prompt_pack`。
- 使用真实视觉模型生成 `visual_draft`。
- 使用 DeepSeek v4 Pro 读取稳定前缀包、视觉草稿和用户输入，直出 `final_report`。
- 保存质量门 `quality_gate`。
- 保存可人工审阅的运行产物。

### 2.2 不做

- 不恢复旧 16 stage。
- 不把中间层做成重 JSON 机器。
- 不把 `<think>` 当作业务中间产物。
- 不实现报告追问智能体。
- 不生成真实可视化图片。
- 不接入支付、订单、登录和历史列表改造。
- 不复用旧 placeholder renderer 生成最终报告。

## 3. 新执行结构

```text
用户图片 + 三圈标记图 + 用户输入
  ↓
Vision Pass：生成 visual_draft
  ↓
Prompt Pack：加载版本化稳定前缀
  ↓
Reasoning Pass：DeepSeek v4 Pro 端到端直出 final_report
  ↓
Quality Gate：拦截越界、泄漏和明显质量问题
```

## 5. 输出合同

智能体输出至少包含：

- `agent_input.json`
- `visual_draft.md`
- `visual_draft.json`
- `prompt_pack_manifest.json`
- `final_report.md`
- `final_report.json`
- `quality_gate.json`
- `run_summary.json`

`run_summary.json` 至少包含：

```json
{
  "agent_version": "mandala-e2e-agent-v1",
  "report_mode": "lite",
  "prompt_pack_id": "wealth-report-v1.0.0",
  "model_trace": {
    "vision": [],
    "reasoning": []
  },
  "prompt_cache": {
    "hit_tokens": 0,
    "miss_tokens": 0
  },
  "status": "complete"
}
```

## 6. visual_draft

`visual_draft` 是显式中间产物，用于人工审核、回归测试和排错。

建议 Markdown 结构：

```md
## 整体观察

## 三圈观察
### 内圈
### 中圈
### 外圈
### 跨圈衔接

## 主要视觉单元

## 留白与相邻关系

## 可供后续解读的视觉重点
```

原则：

- 不是最终报告。
- 不写财富、心理、身体、关系或疗愈结论。
- 不强求重 JSON，但要足够清晰。
- 必须能帮助判断报告错误来自看图问题还是写作问题。

## 7. prompt_pack

`prompt_pack` 是稳定前缀包，用于提高 DeepSeek 上下文缓存命中率。

建议目录：

```text
prompt_packs/
  wealth-report-v1.0.0/
    manifest.json
    00-system.md
    10-mandala-manual.md
    20-wealth-topic-rules.md
    30-style-guide.md
    40-safety-boundary.md
    50-output-contract.md
```

原则：

- 稳定内容放前面。
- 用户输入、视觉草稿、报告模式放后面。
- 同一版本内文件顺序固定。
- 记录 pack hash，支持回归对照。
- 不把缓存命中当作业务逻辑条件。

## 8. 模型调用边界

- Vision Pass 调用真实视觉模型，MVP 默认使用当前已接通的 Qwen/DashScope 路线。
- Reasoning Pass 调用 DeepSeek v4 Pro。
- DeepSeek v4 Pro 当前只作为文字 / 推理模型使用，不直接读图。
- `thinking` 参数默认可配置，不把思维链作为业务产物。
- 模型失败不得静默生成伪报告。

## 9. 质量门

MVP 质量门至少检查：

- `visual_draft` 存在且不为空。
- `final_report.md` 存在且不为空。
- 最终报告不包含内部标签。
- 最终报告不包含开发态语言。
- 最终报告不包含 placeholder 兜底句。
- 最终报告不输出财务预测、投资建议、心理诊断或医疗判断。
- 最终报告有画面依据和三圈带读。
- 最终报告保留曼陀罗流派特征。

## 10. 验收标准

MVP 通过时，应满足：

1. 离线 runner 可用真实模型跑至少 1 个 fixture。
2. Lite / Pro 至少各有一份真实模型报告样本。
3. 每份样本有 `visual_draft.md`、`prompt_pack_manifest.json`、`final_report.md` 和 `quality_gate.json`。
4. 用户可见报告不泄漏内部文本。
5. `visual_draft` 能支持人工判断视觉识别是否准确。
6. `prompt_pack` 版本和 hash 可追溯。
