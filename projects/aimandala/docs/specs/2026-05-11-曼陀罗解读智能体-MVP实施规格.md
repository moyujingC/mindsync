## 1. 目标

MVP 阶段新增 `曼陀罗解读智能体`，用于生成 Lite / Pro 解读报告。

实现依据只来自：

1. 方法真值源：[三圈五行流派解读方法与步骤.md](../sources/知识库构建/三圈五行流派解读方法与步骤.md)
2. 架构边界：[解读智能层-曼陀罗解读智能体架构.md](../architecture/解读智能层-曼陀罗解读智能体架构.md)

旧 `stage_process_package / builder_v2 / placeholder renderer` 链路已移出 active 目录，不再作为新实现依据。

## 2. MVP 范围

### 2.1 要做

- 新增 `reading_intelligence` 后端模块
- 新增曼陀罗解读智能体输入 / 输出合同
- 新增精简知识包构建器
- 新增离线 fixture runner
- 使用真实模型生成 Lite / Pro 报告
- 输出 16 个 `stage-*` 方法交付物
- 输出 5 个 execution block 运行 trace
- 输出 `Report Context Package`
- 输出文本质量门结果

### 2.2 不做

- 不实现报告追问智能体
- 不生成真实可视化图片
- 不接入支付、订单、登录和历史列表改造
- 不把完整 Markdown 真值源塞进模型 prompt
- 不复用旧 placeholder renderer 生成最终报告
- 不把旧链路文档重新放回 active 入口

## 3. 方法与执行结构

方法层保留 16 个 stage。执行层压缩为 5 个 MVP block。

```text
Block 1：输入与边界锁定
  stage-00 / stage-01 / stage-02

Block 2：视觉观察与直断互验
  stage-03 / stage-04

Block 3：逐圈规则推导
  stage-05 / stage-06 / stage-07 / stage-08 / stage-09

Block 4：解读主轴与写作输入整理
  stage-10 / stage-11 / stage-12

Block 5：报告生成与交付质检
  stage-13 / stage-14 / stage-15 / stage-16
```

实现可以按 block 组织代码，但输出必须保留完整 `stage_outputs`。

## 6. Report Context Package

MVP 必须保存 `Report Context Package`，给下一阶段报告追问智能体使用。

最小字段：

- `report_id`
- `report_mode`
- `user_context`
- `visual_observation`
- `circle_interpretation`
- `five_element_interpretation`
- `theme_interpretation`
- `core_thesis`
- `healing_direction`
- `final_report`
- `evidence_map`
- `boundaries`
- `permissions`

最终报告 Markdown 只负责用户阅读，不承担追问检索的全部信息。

## 7. 模型调用边界

- Block 1 不调用模型
- Block 2 调用视觉模型
- Block 3 默认不调用模型
- Block 4 调用一次文字模型
- Block 5 按需调用文字模型生成 Lite / Pro 正文
- MVP 阶段不调用文生图模型生成真实可视化图片

模型失败不得静默生成伪报告。失败时必须输出失败状态和可读错误。

## 8. 质量门

MVP 文本质量门至少检查：

- JSON 可解析
- 必要字段存在
- 16 个 `stage-*` 输出完整
- 5 个 execution block trace 完整
- 最终用户可见报告不包含内部标签
- 最终用户可见报告不包含开发态语言
- 最终用户可见报告不包含 placeholder 兜底句
- 报告主判断能回到 `stage_outputs` 和 `evidence_map`
- `Report Context Package` 可用于后续追问

## 9. 验收标准

MVP 通过时，应满足：

1. 离线 runner 可用真实模型跑至少 1 个 fixture。
2. 产物目录包含第 5 节列出的全部文件。
3. 16 个 `stage-*` 都存在。
4. 5 个 execution block trace 都存在。
5. Lite / Pro 至少各有一份真实模型报告样本。
6. 用户可见报告不泄漏 `stage-`、`transition-overload`、`placeholder`、`legacy` 等内部文本。
7. `Report Context Package` 足够支持报告追问智能体设计。
