## 1. 目的

本文件专门回答四个问题：

1. 四类报告各自到底应该写什么
2. 四类报告之间的功能边界到底怎么切
3. 当前阶段最适合采用什么价格梯度
4. 后续如果继续拆单篇产品定义，各篇应共同遵守什么母规则

这份文档不是：

- 单篇报告的最终长文产品定义
- UI 结构稿
- 技术 schema
- 最终商业化合同文本

它是：

- 四类报告的母表
- 内容结构总约束
- 功能分层总约束
- 当前阶段建议定价方案

## 2. 继承的上游结论

本文件继承以下前提：

1. 报告的 `内容能力层` 不应再只按 `Lite / Pro` 两档理解
2. 报告矩阵当前按 `4` 类内容能力理解：
   - `当下映照报告`
   - `自我理解报告`
   - `议题聚焦报告`
   - `Journey 报告`
3. 报告的 `商品层` 仍可以保留明确的 `Lite / Pro` 差异
4. `Journey 报告` 不属于当前单次画作解读，而是基于多次历史画作的高阶分析
5. 四类报告不是强制线性升级关系，而是围绕不同用户任务展开

## 3. 当前建议先收束的核心判断

本轮先收束到下面 7 个判断：

1. `当下映照报告` 对应当前更接近 `Lite` 的商品层
2. `当下映照报告` 当前应分为：
   - `general` 的整体映照版
   - 具体主题的议题映照版
3. `自我理解报告` 与 `议题聚焦报告` 对应当前更接近 `Pro` 的商品层
4. `自我理解报告` 是 `Pro` 的整体向版本
5. `议题聚焦报告` 是 `Pro` 的主题向版本
6. `Journey 报告` 不能根据单次一幅画直接成立，而必须基于多次历史画作
7. `Journey` 应被理解为单独的高阶历史分析产品，而不是当前单次解读页里的同层选择项

## 4. 四类报告总览

| 报告类型 | 核心用户任务 | 主要服务谁 | 输入跨度 | 商品层映射 | 结果后的典型承接 |
|---|---|---|---|---|---|---|
| 当下映照报告 | 先被接住，先看见当下 | 初次进入报告、状态较乱、承载力较低的用户 | 单次画作 | `Lite` | 自我理解报告 / 陪你画 / 主题方案 |
| 自我理解报告 | 从模糊到明白 | 大多数真正想看懂自己的用户 | 单次画作 | `Pro` 的整体向版本 | 主题方案 / 多次画作后进入 Journey |
| 议题聚焦报告 | 围绕一个具体问题看清楚 | 已明确卡在关系 / 边界 / 表达 / 事业等主题的用户 | 单次画作 | `Pro` 的主题向版本 | 主题方案 / 多次画作后进入 Journey |
| Journey 报告 | 看见跨时间重复机制与改变优先级 | 已累计多次历史画作、愿意继续深入的高意愿用户 | 多次历史画作 | `Journey` | 21 天定制方案 / 长期 AI 陪伴 |

## 4.1 内容能力层与商品层的关系

当前更合理的理解不是把四类报告直接当成四个并列商品，而是分成两层：

1. `内容能力层`
   - 当下映照
   - 自我理解
   - 议题聚焦
   - Journey
2. `商品层`
   - `Lite`
     - 对应 `当下映照报告`
   - `Pro`
     - 对应 `自我理解报告` 与 `议题聚焦报告`
   - `Journey`
     - 对应基于多次历史画作的高阶分析

## 5. 四类报告的内容结构

## 5.1 当下映照报告

### 一句话定义

- 帮用户先确认“我现在这样是能被看见和接住的”，而不是立刻把自己读成一份高密度分析

### 当前建议的两个版本

1. `整体映照版`
   - 对应 `general`
   - 更偏“先整体看看我现在是什么状态”
2. `议题映照版`
   - 对应具体主题
   - 更偏“先在这个主题里被看见，但仍保持 Lite 的低压风格”

### 最小内容骨架

1. `当前状态命中`
   - 第一时间说中她此刻最主要的感受气候
2. `画面中的主要依据`
   - 告诉她为什么会这样理解
3. `一句温柔但清楚的解释`
   - 不展开复杂机制，只解释当前处在什么状态
4. `一句现实连接`
   - 让她知道这和最近的生活有关
5. `一个低压下一步`
   - 例如一个觉察动作、一次再画、一个陪你画入口

### 这个报告最应该强调什么

1. 快速命中
2. 低压语气
3. 被接住感
4. 不让用户觉得自己被分析得太重

### 这个报告不应该承担什么

1. 深层机制拆解
2. 高密度模式命名
3. 根源分析
4. 长周期行动设计

## 5.2 自我理解报告

### 一句话定义

- 帮用户把一团说不清的内在感受，整理成一条她能看懂、能相信、能带走的理解链

### 最小内容骨架

1. `整体命中`
2. `画面依据`
3. `状态解释`
4. `模式命名`
5. `现实连接`
6. `一个下一步`

### 可选辅助内容

1. `主题洞察`
2. `日常小觉察`

### 这个报告最应该强调什么

1. 命中感
2. 解释链
3. 结构化命名
4. 与现实生活的连接
5. 一个清楚但不压迫的下一步

### 这个报告不应该承担什么

1. 围绕单一议题做深专项分析
2. 把所有主题都讲一遍
3. 挖到根源方案级别
4. 直接变成训练计划

## 5.3 议题聚焦报告

### 一句话定义

- 围绕一个已经明确的现实主题，把“这张画为什么会指向这个问题”讲清楚

### 最小内容骨架

1. `当前议题下的命中句`
   - 先回答“这份报告为什么和这个主题有关”
2. `画面为何指向该议题`
   - 说明哪些画面线索让我们判断这个议题成立
3. `该议题里的核心拉扯`
   - 例如关系里的靠近与退缩、边界里的想守住与怕得罪
4. `现实中的典型场景`
   - 把问题拉回具体生活场景
5. `为什么它会在这个主题里反复出现`
   - 不做最深根源分析，但要解释重复机制
6. `一个议题向下一步`
   - 必须是围绕该主题的动作，而不是泛建议

### 当前优先适用主题

1. 关系
2. 边界
3. 情绪稳定
4. 表达
5. 事业阶段

### 这个报告最应该强调什么

1. 主题聚焦度
2. 场景具体度
3. 问题解释力
4. 与现实处境的直接相关性

### 这个报告不应该承担什么

1. 完整人格画像
2. 泛泛讲“你是谁”
3. 深层根源方案级拆解
4. 不分主题地通用输出

## 5.4 Journey 报告

### 一句话定义

- 基于用户多次历史画作，看见“为什么我总会这样”的重复机制、形成逻辑与当前最该优先处理的层次

### 最小内容骨架

1. `深层主判断`
   - 先给出最核心的模式判断
2. `结构化执行摘要`
   - 用较高压缩度总结核心洞察
3. `机制拆解`
   - 把状态、模式、防御、代价串成一条链
4. `根源递进`
   - 从表层表现走向更深层原因
5. `优先级判断`
   - 告诉用户不是所有问题都要一起改，当前先处理什么
6. `后续方向`
   - 承接到方案、长期陪伴或更明确的连续推进

### 这个报告最应该强调什么

1. 深度质变
2. 机制递进
3. 根源层次
4. 改变优先级
5. 更强的后续承接能力

### 这个报告不应该承担什么

1. 专业治疗替代
2. 高风险危机承接
3. 把“更深”误写成“更多漂亮话”
4. 只靠篇幅长来证明价值

## 6. 四类报告之间的功能区分

## 6.1 不是按“长短”区分

四类报告不应按下面方式理解：

- 当下映照 = 最短
- 自我理解 = 中等
- 议题聚焦 = 更长
- Journey = 最长

更准确的区分方式应是：

- `当下映照报告`
  - 解决“我现在需要先被看见吗”
- `自我理解报告`
  - 解决“我到底怎么了”
- `议题聚焦报告`
  - 解决“这件事为什么一直卡在这个主题里”
- `Journey 报告`
  - 解决“为什么我总会这样，以及现在该先处理哪一层”

## 6.2 不是按“轻版 / 重版”区分

当前最需要避免的是把四类报告重新写回：

- 轻版报告
- 标准版报告
- 深度版报告

这种模糊线性梯度。

因为这样会让每份报告重新退回“只是信息多少不同”，而不是用户任务不同。

## 6.3 真正的区分维度

当前建议用下面 6 个维度区分四类报告：

1. `入口承载力`
   - 用户是否准备好读高密度内容
2. `问题清晰度`
   - 用户是泛模糊，还是已聚焦到单一议题
3. `输入跨度`
   - 是基于单次画作，还是多次历史画作
4. `解释深度`
   - 只解释当前，还是解释反复机制
5. `场景聚焦度`
   - 是通用理解，还是主题专项理解
6. `后续承接强度`
   - 是轻承接，还是直接进入连续方案层

## 7. 当前建议定价方案

## 7.1 定价原则

当前建议遵循以下 5 条原则：

1. `价格首先反映商品层，而不只是内容块名称`
2. `Lite 与 Pro 必须有清楚价格差`
3. `Pro 内可以有整体向与主题向两种版本，但不一定拆成不同价格`
4. `Journey 报告` 不应沿用单次解读的定价逻辑
5. `当前先把单次解读价格说清，再单独定义历史画作分析价格`

## 7.2 当前建议价

| 商品 / 报告类型 | 当前建议价 | 价格角色 |
|---|---|---|
| 当下映照报告（Lite，含整体映照版 / 议题映照版） | `9.9` 元 | 低压入口型产品 |
| 自我理解报告（Pro 整体向） | `39` 元 | 完整解读主产品 |
| 议题聚焦报告（Pro 主题向） | `39` 元 | 完整解读的主题版本 |
| Journey（多次历史画作分析） | `待单独定义` | 高阶历史分析产品 |

## 7.3 为什么这样定

### 当下映照报告：`9.9` 元

原因：

1. 它的价值是真实的，但更偏入口与安放心智
2. 太高会提高首次尝试门槛
3. 完全免费又容易把“报告”整体价值做低

它更适合扮演：

- 首次付费入口
- 活动赠送权益
- 从内容或陪你画进入后的低门槛第一次购买

### 自我理解报告：`39` 元

原因：

1. 它是当前最核心、最通用的理解型主报告
2. 对大多数用户而言，它已经是“值得单独付费的一次完整理解”
3. 需要与更轻入口拉开明显差价，但又不能高到压制转化

### 议题聚焦报告：`39` 元

原因：

1. 它属于 `Pro` 商品层中的主题向版本
2. 它的价值来自“更准、更聚焦”，而不是“更长”
3. 与自我理解报告同价，更符合它们同属 `Pro` 的真实用户感知

### Journey：`待单独定义`

原因：

1. 它不再是单次一幅画作的解读
2. 它建立在多次历史画作的累计之上
3. 它的价值逻辑更接近“历史模式分析”，不应与 Lite / Pro 单次解读混写

## 7.4 当前建议补差价逻辑

当前建议采用下面的简化补差价逻辑：

1. `当下映照报告（Lite） -> Pro`
   - 补差价进入
2. `Pro` 内部从 `自我理解报告` 切到 `议题聚焦报告`
   - 当前更适合视作同层改选，不必强调升级
3. `自我理解报告 / 议题聚焦报告 -> Journey`
   - 不建议简单写成补差价
   - 更适合在已累计多次画作后，作为单独高阶分析入口

当前不建议：

1. 强推 `自我理解报告 -> 议题聚焦报告`
2. 强推 `议题聚焦报告 -> 自我理解报告`

因为这两者当前更应该被理解为：

- 同属 `Pro` 的两种解读方向

## 8. 当前阶段最推荐的入口策略

## 8.1 默认主入口

当前更推荐的不是把用户直接丢到四类报告货架，而是：

- 在上传后，明确推荐 `Lite` 或 `Pro`

原因：

1. 用户首先更容易理解价格层级差异
2. `Lite / Pro` 本来就是当前真实存在的风格差与价格差
3. 在 `Pro` 内再区分 `自我理解` 与 `议题聚焦`，会比直接摆四类商品更不容易困惑

## 8.2 什么情况下优先推当下映照报告

当用户明显呈现以下特征时，可优先推荐 `Lite / 当下映照报告`：

1. 状态较乱
2. 表达承载力较低
3. 只想先被接住，不想被分析太多
4. 是第一次进入报告付费

## 8.3 什么情况下优先推议题聚焦报告

当用户已经明确说出：

1. “我现在就是卡在关系里”
2. “我只想看边界问题”
3. “我想知道事业为什么最近一直不顺”

这类明确主题表达时，可优先推荐：

- `Pro / 议题聚焦报告`

## 8.4 什么情况下优先推 Journey 报告

当用户明显呈现以下特征时，才适合引导 `Journey`：

1. 已有多次历史画作可供对照
2. 已读过 `Lite` 或 `Pro` 仍觉得“不够”
3. 明确想看“为什么我总会这样”
4. 已建立信任，愿意进入历史模式分析

## 9. 当前文档层后续建议

基于本文件，后续最适合继续补的文档顺序建议为：

1. `议题聚焦报告` 产品定义
2. `Journey 报告` 产品定义
3. `当下映照报告` 产品定义
4. `四类报告矩阵下的结果页分流策略`

如果只允许先做一篇，当前最值得优先展开的是：

- `议题聚焦报告` 产品定义

因为：

1. `自我理解报告` 已经基本展开
2. `议题聚焦报告` 是下一步最容易和主题系统真正接上的主报告
3. 它会直接影响后续入口分流、价格话术和主题方案承接
