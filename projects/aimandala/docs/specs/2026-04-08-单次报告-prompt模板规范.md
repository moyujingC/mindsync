## 1. 目的

本文件用于把当前 4 份单次报告 prompt 提纲继续收束成一套统一模板规范。

这里不直接写最终可执行 prompt 文案，而是先明确：

1. 单次报告 prompt 的共同骨架是什么
2. 哪些部分应该做成公共模板
3. 哪些部分必须按 `Lite / Pro`、`全面解读 / 专题解读` 分叉
4. 后续技术实现更适合怎样组织模板层

## 2. 适用范围

本规范当前只覆盖单次画作下的 4 种生成类型：

1. `Lite / 全面解读`
2. `Lite / 专题解读`
3. `Pro / 全面解读`
4. `Pro / 专题解读`

当前不覆盖：

1. `Journey`
2. 结果页 CTA 文案
3. AI 问答追问 prompt
4. 主题方案或长期陪伴 prompt

## 3. 当前最重要的收束判断

本轮先收束到下面 6 个判断：

1. 单次报告 prompt 应共享一套母模板
2. 母模板下至少有两层分叉：
   - `tier`: `Lite` / `Pro`
   - `mode`: `overall` / `topic`
3. `Lite / Pro` 的主要差异，不是字段名，而是任务深度与语气密度
4. `overall / topic` 的主要差异，不是主题词替换，而是正文主线不同
5. 输入装配层和写作规则层应分开管理
6. 禁止把 4 份 prompt 完全写成 4 份彼此无关的大段文本

## 4. 统一模板的推荐结构

当前建议所有单次报告 prompt 共享下面 8 段母结构：

1. `角色定义`
2. `任务定义`
3. `输入说明`
4. `输出结构`
5. `写作要求`
6. `语气要求`
7. `禁止项`
8. `输出前自检`

## 5. 哪些部分应做成公共模板

## 5.1 角色定义

公共部分应固定回答：

1. 这是 `一镜一梳` 的正式解读报告
2. 目标是帮助用户看清自己，而不是做治疗替代
3. 必须基于画作和输入生成，不可泛泛套话

变体部分只需注入：

1. 当前商品层
2. 当前解读方向

## 5.2 输入说明

公共部分应固定声明：

1. 可用输入包括：
   - 主题
   - 绘画前意图
   - 绘画过程中的感受
   - 画作本身
2. 画作始终是主要证据来源
3. 不能忽略意图和过程感受

变体部分只需注入：

1. 当前输入优先级
2. 当前模式是否需要把主题作为前提输入

## 5.3 输出结构

公共部分应固定声明：

1. 输出必须是结构化分段报告
2. 每段有明确任务，不得随意增删
3. 结尾只能有一个主方向

变体部分只需注入：

1. 当前版本的段落数
2. 当前版本的段落名

## 5.4 禁止项

公共部分应固定禁止：

1. 套模板式安慰
2. 长篇空泛散文
3. 输入没吃进去
4. 一次给很多建议
5. 越界写成高风险支持

变体部分再追加：

1. `Lite` 不可越界写成 `Pro`
2. `Pro` 不可越界写成 `Journey`
3. `topic` 不可只换标题不换正文

## 5.5 输出前自检

公共部分应固定检查：

1. 是否有命中感
2. 是否有画面依据
3. 是否吃进了输入
4. 是否落到现实
5. 是否只有一个主方向

变体部分只需补充：

1. 当前版本专属的边界检查

## 6. 哪些部分必须做成变体模板

## 6.1 任务定义

这部分必须按 `tier + mode` 组合分叉，不能共用一句话：

1. `Lite / 全面解读`
   - 先低压看清当前整体状态
2. `Lite / 专题解读`
   - 先在某个主题里低压看清当前状态
3. `Pro / 全面解读`
   - 更完整地看懂当前整体状态与主模式
4. `Pro / 专题解读`
   - 围绕某个主题做完整正式解读

## 6.2 写作要求

这部分必须分叉，因为它直接决定正文深度：

1. `Lite`
   - 重点是快、轻、近、收
2. `Pro`
   - 重点是命中、有据、递进、命名、落地
3. `overall`
   - 重点是整体状态主线
4. `topic`
   - 重点是主题判断与主题场景主线

## 6.3 语气要求

这部分也必须分叉：

1. `Lite`
   - 更轻、更柔和、更低压
2. `Pro`
   - 更完整、更清楚、更有方向感
3. `topic`
   - 更聚焦，但不能更重

## 7. 推荐的模板变量

当前建议后续技术实现至少保留下面这些模板变量：

```yaml
tier: lite | pro
mode: overall | topic
topic: general | relationship | boundary | emotion | expression | career
uses_intention: boolean
uses_process_feeling: boolean
section_titles: string[]
main_goal: string
tone_profile: string[]
forbidden_patterns: string[]
self_check_items: string[]
```

## 8. 推荐的模板装配方式

当前更推荐把 prompt 拆成下面 4 层装配：

1. `base_template`
   - 所有单次报告通用
2. `tier_layer`
   - `Lite` 或 `Pro`
3. `mode_layer`
   - `overall` 或 `topic`
4. `final_check_layer`
   - 输出前自检

不建议：

1. 为每个版本复制整份完整大 prompt
2. 把所有差异都堆在 if/else 的单个超长模板里

## 9. 当前 4 份 prompt 的映射关系

| 版本 | 共同母模板 | tier_layer | mode_layer |
|---|---|---|---|
| `Lite / 全面解读` | `single_report_base` | `lite_layer` | `overall_layer` |
| `Lite / 专题解读` | `single_report_base` | `lite_layer` | `topic_layer` |
| `Pro / 全面解读` | `single_report_base` | `pro_layer` | `overall_layer` |
| `Pro / 专题解读` | `single_report_base` | `pro_layer` | `topic_layer` |

## 10. 当前阶段最重要的收束结论

基于以上规范，当前建议先收束到下面 5 个判断：

1. 单次报告 prompt 不是 4 份彼此无关的文本，而是一套共享骨架下的 4 个变体
2. `tier` 决定深度与语气，`mode` 决定主线与段落重心
3. 公共模板应只保留真正稳定的部分，不要把差异写死
4. 后续技术实现最适合按 `base + layer` 方式组织
