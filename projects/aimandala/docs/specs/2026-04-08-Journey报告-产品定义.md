## 1. 目的

本文件专门定义：

- `Journey 报告` 到底是什么
- 它主要服务谁
- 它要帮用户完成什么任务
- 它和 `自我理解报告`、`议题聚焦报告` 的边界在哪里
- 它当前最小可交付版本应长什么样

这份文档是四类报告矩阵中的高阶历史分析产品定义。

当前默认判断是：

- `Journey 报告` 不是“更长的 Pro”，也不是单次画作就能成立的报告
- 它必须建立在用户多次历史画作之上，才能真正看见稳定模式

因此，后续若要继续推进：

- 结果页升级逻辑
- 高价报告价值表达
- 向 21 天定制方案或长期 AI 陪伴的承接
- 深度分析内容结构

都应优先回到本文件校验。

## 2. 本轮任务级别

本轮属于：

- `局部实验中的主干定义`

更具体地说，是：

- 在已确认的四类报告矩阵内，补齐高阶历史分析层的产品定义

它不是：

- 对整个项目定位的重写
- 对长期 program 产品的替代定义
- 对最终高价商业化方案的完整结论

## 3. 继承的上游结论

本文件明确继承以下判断，不重复改写：

1. `一镜一梳` 的报告产品本质是 `理解产品`
2. 报告的一级任务是：
   - 被看见
   - 被解释
   - 被命名
   - 被连接
   - 被指引
3. 报告长期不应再按 `Lite / Pro` 作为唯一主框架
4. 当前建议的报告矩阵包含：
   - 当下映照报告
   - 自我理解报告
   - 议题聚焦报告
   - Journey 报告
5. `Journey 报告` 是高意愿用户进入的高阶历史分析层
6. `Journey` 必须基于多次历史画作，而不是单次上传

## 4. 本轮允许变化 / 禁止变化

### 4.1 本轮允许变化

本轮允许继续定义：

- Journey 报告的目标用户
- Journey 报告的最小内容结构
- Journey 报告与其他报告的边界
- Journey 报告结果页的后续承接原则

### 4.2 本轮禁止变化

本轮不在这里改写：

- 整个项目的目标用户
- 整个产品矩阵
- 21 天定制方案与长期 AI 陪伴的具体产品定义
- 高风险支持边界
- 最终商业化闭环设计

## 5. 产品定位

`Journey 报告` 的一句话定义是：

- 基于用户多次历史画作，看见“为什么我总会这样”的重复机制、形成逻辑与当前最该优先处理的层次

它的本质是：

- `深度机制型理解报告`

它不是：

- 更长的自我理解报告
- 更重的议题聚焦报告
- 高风险心理承接产品
- 21 天定制方案本身
- 连续陪伴本身

## 6. 核心目标用户

### 6.1 第一优先用户

- `成长深化型`

她的典型心态是：

- “我已经不满足于知道自己怎么了，我更想知道为什么我总会这样。”
- “我想看清更深层的机制，而不是只停在感受描述。”
- “我愿意花更多时间读完一份真正有层次的报告。”

### 6.2 第二优先用户

- 已读过主报告、并建立起信任的高意愿用户

她的典型心态是：

- “基础理解已经不够了，我想再往下看一层。”
- “我想知道这些模式背后更深的逻辑和优先级。”

### 6.3 可兼容用户

- `议题解决型` 中已经意识到“问题背后还有更深模式”的用户

她的典型心态是：

- “我知道自己卡在关系/边界里，但我已经感觉到这不是单点问题。”

### 6.4 不优先服务的用户

以下用户不应默认由 Journey 报告主承接：

1. 只想先被接住或低压进入的用户
   - 更适合 `当下映照报告`
2. 还处在泛模糊状态、只想先看清当前自己的用户
   - 更适合 `自我理解报告`
3. 只想围绕单一主题看当前问题的用户
   - 更适合 `议题聚焦报告`
4. 高复杂度支持型用户
   - 不应由 AI 报告主承接
5. 只有单次一幅画作、没有历史序列的用户
   - 当前不应默认进入 `Journey 报告`

## 7. 用户任务定义

Journey 报告最核心要完成的，不是“再讲更多”，而是完成下面五件事。

### 7.1 让我知道最深层的主判断是什么

用户任务：

- “如果只能说一句，最核心的问题到底是什么？”

对应要求：

- 开头必须给出更深层主判断
- 不能只是把前面报告换种说法重写一遍

### 7.2 让我看到机制是怎样一层层形成的

用户任务：

- “我想知道这不是随机发生，而是有一条机制链。”

对应要求：

- 必须有机制递进
- 至少能从表层状态走向更深层保护逻辑或根源层

### 7.3 让我知道为什么它会一再重复

用户任务：

- “我最想知道的是，为什么这件事总会在不同场景里重演。”

对应要求：

- 必须解释重复模式如何形成
- 不能只停留在单次状态描述

### 7.4 让我知道当前最该先处理哪一层

用户任务：

- “我不想一下处理全部问题，我想知道现在先动哪里最关键。”

对应要求：

- 必须给出优先级判断
- 要帮助用户从“全都重要”走向“先处理这一层”

### 7.5 让我知道读完之后该往哪里继续

用户任务：

- “既然已经看得更深了，那后面应该去哪一条路径？”

对应要求：

- 必须有更强的后续承接能力
- 要能自然接向 `21 天定制方案`、`长期 AI 陪伴` 或更明确的连续路径

## 8. Journey 报告的独特价值

相对于其他三类报告，Journey 报告最独特的地方不是：

- 最长
- 最贵
- 最复杂
- 最会用术语

而是：

- 它最擅长把“我为什么总会这样”解释成一条更深、更稳定的机制链

它的独特价值在于：

1. 比 `自我理解报告` 多出机制递进与优先级判断
2. 比 `议题聚焦报告` 更不局限在单一现实问题
3. 比 `当下映照报告` 更能承接高意愿用户的深度需求
4. 它最适合成为连续改变产品的前置理解层

## 9. 与其他报告的边界

### 9.1 与当下映照报告的边界

当下映照报告：

- 更偏“我现在大概处在什么状态”

Journey 报告：

- 更偏“为什么这个状态会持续重复出现”

关键差异是：

- Journey 报告必须有明显机制深度，而不是只加更多文字

### 9.2 与自我理解报告的边界

自我理解报告：

- 更偏“从模糊到明白”

Journey 报告：

- 更偏“从明白到更深层地理解自己为什么总会这样”

关键差异是：

- 自我理解报告可以清楚，但不必挖到最深层机制
- Journey 报告必须比它多出根源递进与优先级判断

### 9.3 与议题聚焦报告的边界

议题聚焦报告：

- 更偏“这件事为什么卡在这个主题里”

Journey 报告：

- 更偏“这个问题背后的反复模式和形成逻辑是什么”

关键差异是：

- 议题聚焦报告优先服务一个问题
- Journey 报告优先服务一个更深层的重复机制

## 10. 输入利用逻辑

Journey 报告当前默认应吃五层输入：

1. `多次历史画作`
   - 这是成立前提，不可缺失
2. `各次主题`
   - 用于判断模式是跨主题还是集中在单一主题
3. `各次绘画前意图`
   - 用于观察显性入口如何变化
4. `各次绘画过程中的感受`
   - 用于识别反复出现的拉扯与保护逻辑
5. `时间顺序`
   - 用于判断哪些模式是持续存在、哪些是阶段性放大

与其他报告相比，它最需要强化的不是：

- 更多漂亮表达

而是：

- 更稳定地把 `历史序列 -> 重复证据 -> 机制 -> 优先级` 连成一条深层解释链

## 11. 最小可交付版本

当前建议 `Journey 报告` 的最小可交付单元为：

1. 一份基于多次历史画作的深度报告
2. 每份报告至少同时满足下面 5 条：
   - 深层主判断成立
   - 机制递进清楚
   - 根源层次可读
   - 优先级判断明确
   - 后续方向具体
3. 结果页至少支持一个后续动作：
   - 进入 `21 天定制方案`
   - 进入 `长期 AI 陪伴`
   - 或回到现实中围绕优先级做下一步

## 12. 结果页承接原则

Journey 报告的结果页，不应停在“看完很震撼”，也不应只是重复销售同类理解产品。

它最适合承接的后续方向是：

1. `进入 21 天定制方案`
   - 当用户已经不只想理解，而是想连续推进
2. `进入长期 AI 陪伴`
   - 当用户更适合在持续反馈中慢慢工作
3. `围绕当前优先级先做一个现实动作`
   - 当用户还没准备好进入 program，但已经知道先处理哪一层

当前不建议它的结果页优先承接：

- 回到 `自我理解报告`
- 回到 `议题聚焦报告`

因为：

- 这会让用户感到路径倒退

## 13. 与当前迁移期原型的关系

在迁移期语境下，当前最接近 Journey 报告的，是：

- 当前 `Pro` 原型中的深度分析层

但旧 `Pro` 原型并不能直接等于 Journey 报告。

原因是：

1. 旧 `Pro` 原型里同时混有一部分主题分析和深度分析
2. Journey 报告要求“深度质变”，不是只多信息量
3. 它应更明确地回答机制、根源与优先级，而不是只给更多章节

因此，迁移期更合理的理解应是：

- 现有 `Pro` 只是部分过渡承载壳
- 真正成立的 Journey 报告仍需要单独定义

## 14. 当前阶段最重要的收束结论

基于以上定义，当前建议先收束到下面 5 个判断：

1. `Journey 报告` 不是更长的通用报告，而是基于多次历史画作的机制型报告
2. 它必须比 `自我理解报告` 多出深度质变，而不是只多字数
3. 它最核心的价值是解释重复机制与帮助用户排序优先级
4. 它最自然的后续承接是 `21 天定制方案` 与 `长期 AI 陪伴`
5. 它不应与单次 `Lite / Pro` 解读共用同一产品入口

## 15. 本轮做什么 / 不做什么

### 15.1 本轮做什么

本轮先明确：

- Journey 报告的产品定位
- Journey 报告的目标用户
- Journey 报告的任务与边界
- Journey 报告的最小可交付版本
- Journey 报告的结果页承接原则

### 15.2 本轮不做什么

本轮暂不直接定义：

- 具体 structured 字段
- 最终 prompt 结构
- 页面 UI 稿
- 21 天方案与长期陪伴的详细产品设计
- 最终销售话术

## 16. 后续建议

基于本轮定义，后续最适合继续补的文档应是：

1. `Journey 报告` 内容结构与字段定义
2. `当下映照报告` 内容结构与字段定义
3. `四类报告矩阵下的入口与结果页分流策略`

如果只允许先做一篇，当前最值得优先展开的是：

- `Journey 报告` 内容结构与字段定义

因为：

1. 产品边界已经清楚
2. 下一步最需要把“深度质变”翻译成可生成、可渲染的结构
3. 它会直接影响后续升级逻辑与高价产品价值表达
