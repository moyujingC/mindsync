## 1. 目的

本文件用于收束当前 `Pro` 商品层的内容优化方向，重点回答：

1. 当前 `Pro` 报告到底应该比 `Lite` 多出什么质变
2. 当前 `Pro` 报告应该怎样同时承接：
   - `全面解读`
   - `专题解读`
3. 当前 `Pro` 报告哪些内容值得强化
4. 当前 `Pro` 报告哪些旧做法不该继续放大

这里讨论的是：

- 当前商品层 `Pro`

因此，`Pro` 不是一份固定长文，而是：

- 同一商品层下的两种完整解读方向

## 2. 继承的上游结论

本文件明确继承以下判断：

1. `Pro` 当前仍然是合理的商品层
2. `Pro` 支持 `全面解读`
3. `Pro` 支持 `专题解读`
4. `Pro` 不能被写成 `Journey` 的单次缩水版
5. `Pro` 必须比 `Lite` 多出更稳定的解释链、模式命名与后续承接
6. `Pro` 内部虽然有两个方向，但不应让用户感觉是在买两个完全不同层级的产品

## 3. 当前评估给出的关键信号

基于 [2026-04-06-当前两份报告内容评估.md](/Users/xinran/Downloads/dev/mindsync/projects/aimandala/docs/specs/2026-04-06-当前两份报告内容评估.md)，当前 `Pro` 原型最值得保留的优势是：

1. 信息密度足够
2. 模式命名能力强
3. 更像正式深度报告
4. 更容易承接到 AI 问答或后续路径

当前最需要修的，不是“不够深”，而是下面 5 件事：

1. 洞察递进不够稳定
2. 被看见感略弱于 `Lite`
3. 对现实场景的落点还不够稳定
4. `绘画前意图` 与 `绘画过程中的感受` 没有真正吃进去
5. 行动承接虽然存在，但仍偏悬空

## 4. Pro 这一轮要优化成什么

这一轮建议把 `Pro` 从：

- `更长、更密集的深度内容`

优化到：

- `更完整的理解链 + 更稳定的模式命名 + 更清楚的下一步路径`

更具体地说，用户读完 `Pro` 后，应有下面 5 个感受：

1. `这份报告不只是更长，而是真的更懂我`
2. `我知道它为什么会得出这个更深的判断`
3. `我能复述我当前最主要的模式是什么`
4. `我能看到它在现实里通常怎么出现`
5. `我知道自己更适合继续往哪个方向走`

## 5. Pro 的共同主骨架

无论是 `Pro / 全面解读` 还是 `Pro / 专题解读`，当前都建议共享下面 6 个主骨架：

1. `开头命中`
   - 先完成“被看见”，而不是一上来就像摘要表
2. `画面依据`
   - 说清为什么会这样判断
3. `状态解释`
   - 把当前状态整理成一条可理解的解释链
4. `模式命名`
   - 命名当前最主要的反复结构或拉扯
5. `现实连接`
   - 落回真实场景、真实影响
6. `一个主方向`
   - 给一个更清楚的下一步，不泛、不散

## 6. Pro 的两个版本如何区分

### 6.1 全面解读

它更适合回答：

- `我到底怎么了`

它应重点强化：

1. 从模糊到明白的解释链
2. 当前状态与模式的结构化命名
3. 现实生活中的典型落点
4. 一个清楚但不压迫的下一步

### 6.2 专题解读

它更适合回答：

- `为什么这件事总卡在这个主题里`

它应重点强化：

1. 当前议题为什么成立
2. 该议题里的核心拉扯
3. 现实中的典型场景
4. `触发 -> 自动反应 -> 强化结果` 的最小问题闭环
5. 围绕该主题成立的下一步

## 7. Pro 当前最该加强的 7 个内容动作

### 7.1 开头要先被看见，再进入深度

要求：

1. 第一段仍然要有命中感
2. 第二句再说明这份报告比 `Lite` 多看见了什么
3. 不要一上来就是摘要或表格语言

### 7.2 解释链必须形成递进

要求：

1. 至少形成 `画面依据 -> 状态判断 -> 模式 -> 现实影响`
2. 每一段都应比前一段更进一步
3. 不要把多个洞察并列堆在一起

### 7.3 主题要真正改变正文

要求：

1. 如果用户选了具体主题，正文结构和场景必须发生变化
2. 不能只是标题写了主题，正文仍输出通用深度文
3. `专题解读` 要明显比 `全面解读` 更聚焦问题

### 7.4 意图至少进入两处分析

要求：

1. 用户填写了 `绘画前意图` 时，至少两处进入正文
2. 一处可用于解释她原本想看什么
3. 一处可用于对照画面实际暴露出来的真实状态

### 7.5 过程感受进入机制解释

要求：

1. 用户填写了 `绘画过程中的感受` 时，至少一处进入“解释链”主段
2. 它不应只成为补充备注
3. 它应帮助说明用户在画的时候如何体验自己的拉扯、压抑或释放

### 7.6 下一步要从“提示”升级成“主路径”

要求：

1. `Pro` 不能只有行动提示语
2. 必须告诉用户当前最自然的继续方向是什么
3. 只给一个主路径，必要时再加一个轻量次路径

### 7.7 AI 问答是延伸，不是补锅

要求：

1. 主报告本身必须成立
2. 不能把没讲清的内容丢给 AI 问答补
3. AI 问答应承接进一步展开，而不是替代正文

## 8. Pro 不该继续强化的旧内容

当前不建议继续把下面这些块当成 `Pro` 的主价值来源：

1. `信息堆叠式长文`
   - 长并不自动等于深
2. `过度依赖表格`
   - 表格只能做执行摘要，不能代替递进正文
3. `假深层根源`
   - 单次画作不应硬写成长期固定机制
4. `空泛的 21 天承接`
   - 如果本轮不做方案，就不要假装已经进入方案
5. `只讲分析、不讲现实`
   - 会让用户觉得被研究，但没有被真正理解

## 9. Pro 与 Lite、Journey 的边界

### 9.1 与 Lite 的边界

`Pro` 比 `Lite` 多出的质变应是：

1. 更稳定的解释链
2. 更明确的模式命名
3. 更强的现实连接
4. 更清楚的后续路径

不是：

- 更多段落
- 更重语气
- 更多术语

### 9.2 与 Journey 的边界

`Pro` 当前仍然是单次画作下的完整解读。

因此它不应：

1. 把自己写成长期历史模式分析
2. 假装已经看见跨时间稳定机制
3. 直接替代 `Journey 报告`

它更适合做到的是：

1. 把这次单次输入看得更完整
2. 在必要时引导用户未来进入 `Journey`

## 10. 对当前实现壳的指导

当前这份提纲讨论的是 `Pro` 商品层的真实目标内容，不要求本轮直接改技术实现。

但如果后续继续沿用当前 `pro_v1.6` 外壳，建议遵守下面 4 条：

1. `first_impression` 必须先承担命中与过渡，不只是摘要开场
2. `core_insight_table` 只能作为执行摘要，不能代替正文递进
3. `root_cause` 只能停在单次画作可支持的解释深度
4. 同一套壳下需要明确区分：
   - `Pro / 全面解读`
   - `Pro / 专题解读`

## 11. 当前阶段收束结论

基于以上判断，当前建议先收束到下面 7 个结论：

1. `Pro` 的价值不是更长，而是更完整的理解质变
2. `Pro` 商品层内部应区分全面解读和专题解读两种内容方向
3. `Pro` 共同骨架应收束为 `6` 个主内容块
4. `Pro` 必须真正使用 `主题 + 意图 + 过程感受 + 画作结果`
5. `Pro` 的递进结构必须明显强于当前原型
6. `Pro` 的结果页与正文都应给出一个主路径
7. `Pro` 不能越界写成 `Journey` 的单次版

## 12. 后续建议

基于本文件，后续最适合继续推进的是：

1. 重写一版 `Pro / 全面解读` prompt 提纲
2. 重写一版 `Pro / 专题解读` prompt 提纲
3. 补一份 `Pro` 结果页 CTA 与分流规则细化文档
