## 1. 背景

Batch G 已关闭 Batch F 登记的 raw payload、debug scope 与逐圈深浅进入用户报告的问题。当前剩余问题不再是“证据有没有进入链路”，而是“证据进入用户报告后的表达是否仍像 debug dump”。

当前 golden 报告可见的表达 drift 包括：

1. Lite `visual_basis` 把 `#hex`、面积、深浅、填充直接串成证据摘要，阅读上接近调试输出。
2. Pro `evidence_digest` 在内圈、中圈、外圈段落中重复完整三圈摘要，造成信息噪音。
3. Pro `root_cause_chain` 存在硬拼接、异常空格和半截句风险。
4. Pro `healing_plan` 已不再泄漏 raw payload，但仍可能重复同一练习或退回泛化建议。
5. golden `report.md` 的正文摘录容易被安全声明占满，不利于人工审阅主报告内容。

本规格只修表达保真和可读性压缩，不改 Lite / Pro 对外字段 shape，不改安全协议，不扩展 shape recognition。

## 2. 目标行为

Batch H 完成后必须满足：

1. Lite `visual_basis` 仍能呈现三圈颜色、深浅、面积或填充依据，但表达为教程式观察句。
2. Lite 用户可读文本不出现 `#hex`，不出现“逐圈深浅依据：”这类 debug 标题。
3. Pro `evidence_digest` 先给一次完整三圈观察，再进入各圈说明；每个圈段只讲本圈，不重复完整三圈摘要。
4. Debug trace 继续保留 `per_circle_color_summary`、`color_analysis_refs` 与原始 trace，保证可追溯性不被可读性压缩破坏。
5. Pro `root_cause_chain` 输出为完整自然句，不出现异常空格拼接、重复片段或半截句。
6. Pro `healing_plan` 每条建议必须绑定议题、失衡或根因链，不重复同一 practice，不回退到空泛“稳定调节”。
7. Golden `report.md` 的“正文摘录”应优先展示去除安全声明后的正文片段，API full report 仍保持安全 wrapper 行为。

## 3. 合同边界

对外合同保持不变：

1. `LiteStructuredReport` 字段 shape 不变。
2. `ProStructuredReport` 字段 shape 不变。
3. `ReportResponse` 顶层版本号不变。
4. 不新增前端主消费字段。

内部与治理侧允许补充：

1. `narrative_plan.evidence_trace_summary` 可新增 `per_circle_observation_summary`。
2. `ReportDebugContract.product_block_debug.*.evidence_trace` 可补充人可读逐圈观察摘要。
3. `KnowledgeWorkbench` golden export 可对 `report.md` 正文摘录做安全声明剥离。

## 4. 修复口径

### 4.1 逐圈观察压缩

逐圈观察必须从 Batch E / G 已有 evidence 派生：

1. 来源为 `interpretation_method_trace.per_circle_color_analysis.*.state_basis`。
2. `per_circle_color_summary` 继续保留机器可追溯摘要，可包含色值。
3. `per_circle_observation_summary` 面向用户阅读，不包含色值。
4. Lite 使用一段压缩观察。
5. Pro 使用一次完整观察 + 各圈单圈观察，不把完整观察重复塞进每个圈段。

### 4.2 Pro 文本质量

Pro 正式输出必须满足：

1. `root_cause_chain.surface / mechanism / core` 每项都是完整短句。
2. 清理异常空格、重复句段和内部 payload 残留。
3. `healing_plan` 每条建议至少能追到当前 `imbalance_diagnosis`、`root_cause_chain` 或 topic。
4. 若上游 healing 数据不足，fallback 也必须使用当前议题和根因链重建，不能只输出泛化调节句。

### 4.3 Golden 审阅呈现

Golden markdown 只作为人工审阅资产优化：

1. `report.json` 保留完整 API 快照。
2. `report.md` 产品区块保持完整。
3. `report.md` 正文摘录使用去安全声明后的正文片段。
4. 不修改 API full report 中安全声明的输出策略。

## 5. 成功标准

本批成功标准固定为：

1. Lite `visual_basis` 无 `#`、无“逐圈深浅依据”，但含内圈、中圈、外圈与深浅 / 面积 / 填充语义。
2. Pro `evidence_digest` 无重复完整逐圈摘要，且基础颜色证据在关系解释前出现。
3. Pro `root_cause_chain` 与 `healing_plan` 无 raw payload、旧升级语义、异常空格拼接和重复 practice。
4. Golden `report.md` 正文摘录不以“重要声明”开头。
5. `001-lite / 002-pro / 002-lite` golden 已重导，review 与 eval summary 已回填。
6. 正式文档、fixture、golden 资产不出现机器绝对路径或临时工作区路径。
