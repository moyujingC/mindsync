## 1. 背景

Batch A-D 已经让报告链路具备新合同、fixture 与 trace 基础，但新生成的 Lite / Pro 报告仍不能判定为合格。

本批确认的问题不是文案风格，而是原始解读教程算法在 runtime 和 narrative 层被曲解：

1. `Layer 0` 没有完整承接四步法。
2. 五行太过 / 不足阈值被工程 scoring 口径替代。
3. narrative plan 仍先生成 legacy projection，再包装成 `evidence_first`。
4. 测试只验证字段存在，未验证教程算法是否被正确消费。

## 2. 目标行为

Batch E 完成后，报告生成必须满足：

1. runtime evidence 能显式表示四步法：
   - 直断
   - 逐圈颜色分析
   - 形状分析
   - 圈级生克分析
   - 最终算法依据
2. `element_states` 必须区分：
   - `tutorial_state`：按原始教程判断太过 / 正常 / 不足
   - `scoring_state`：用于 20 种失衡候选排序的工程评分
3. narrative plan 必须直接消费四步法 evidence，不得把 legacy projection 当作事实来源。
4. Lite / Pro 对外产品区块字段 shape 不变，但字段内容必须来自 algorithm trace。
5. Pro 必须独立成立，不得引用 Lite 标题或 Lite 内容。
6. debug payload 必须能下钻到每个产品区块对应的算法证据。

## 3. 算法口径

本批固定采用下列算法口径：

1. `direct_judgment`
   - 基于整体填充、深浅、留白、明显颜色模式做快速筛查。
   - 只作为切入和提示，不直接替代后续详细分析。
2. `per_circle_color_analysis`
   - 每圈保留颜色列表、面积比例、五行映射、深浅状态和状态依据。
   - 同一颜色在不同圈层必须保留圈层语境。
3. `tutorial_state`
   - 面积比例 `> 0.50` 判定为 `excess`。
   - 面积比例 `< 0.10` 判定为 `deficient`。
   - 深重 / 浅淡证据可增强状态判断，但不得覆盖面积证据来源。
4. `shape_analysis`
   - 形状是辅助维度。
   - 只在存在可识别形状或颜色 / 形状关系冲突时展开。
5. `circle_relation_analysis`
   - 先解释基础元素状态，再解释圈内、圈间五行生克关系。
   - 20 种失衡类型属于关系状态，不得越过单元素状态直接下结论。

## 4. 非目标

本批不做：

1. 不改 Lite / Pro 对外产品区块字段 shape。
2. 不重定价，不重做 `General / 主题` SKU 模型。
3. 不把 prompt 当作知识推理层。
4. 不把这批修复扩展成新的图片识别大模型项目。
5. 不清理 `mobile-web/dev-fixtures.ts`。

## 5. 成功标准

本批成功标准固定为：

1. `Layer0Raw.rule_evaluations.interpretation_method_trace` 存在并包含五个算法段。
2. `element_states` 同时包含 `tutorial_state` 和 `scoring_state`。
3. Lite 样本能读出直断和逐圈颜色依据。
4. Pro 样本能读出逐圈状态、生克关系、失衡诊断、根因链和完整疗愈方案。
5. 正式报告链路不再出现：
   - `Lite 里`
   - `解锁完整版`
   - `补全版`
   - `升级版`
   - `21天`
   - raw Python dict 字符串
6. `toc-mvp` eval summary 新增 algorithm fidelity 结果。
