## 1. 背景

Batch F 已建立固定样本 golden 审阅闭环，并确认三份首批 golden 资产仍存在内容偏差：

1. `toc-mvp-fixture-001 / lite`：逐圈深浅状态没有稳定进入用户可读报告。
2. `toc-mvp-fixture-002 / pro`：`healing_plan` 泄漏内部 raw payload，且逐圈深浅状态没有稳定展开。
3. `toc-mvp-fixture-002 / lite`：显式 Lite 审阅被同一 interpretation 的 Pro raw payload 污染，且逐圈深浅状态没有稳定展开。

本规格只修复上述 Batch F 已登记偏差，不重新设计 Lite / Pro 合同，不改业务 API，不扩展 shape recognition。

## 2. 目标行为

Batch G 完成后必须满足：

1. Pro `healing_plan` 只包含干净的用户可读自然语言，不泄漏 Python dict、JSON-like 片段或截断 raw payload。
2. Lite golden / Lite debug 的算法保真判断只扫描 Lite 正式输出、Lite narrative plan 与 Lite 相关 trace，不再被 Pro draft 污染。
3. Pro debug 仍扫描 Pro 正式输出与 Pro draft，raw payload 修复后应转为通过。
4. Lite `visual_basis` 必须稳定压缩逐圈颜色、深浅或明暗、面积或填充依据。
5. Pro `evidence_digest` 必须稳定展开逐圈颜色状态，并在关系失衡诊断之前呈现基础颜色证据。
6. debug 产品区块 trace 必须能追到 `per_circle_color_analysis` 和人可读逐圈颜色摘要。

## 3. 合同边界

对外合同保持不变：

1. `LiteStructuredReport` 字段 shape 不变。
2. `ProStructuredReport` 字段 shape 不变。
3. `ReportResponse` 顶层版本号不变。
4. 不新增前端主消费字段。

内部与治理侧允许收紧：

1. `ReportDebugContract.algorithm_fidelity_trace` 增加或使用明确 `scope`。
2. `raw_payload_leak_found` 按当前 `scope` 计算。
3. 可保留 `raw_payload_leak_by_scope` 用于内部审计。
4. `narrative_plan.evidence_trace_summary` 可补充人可读 `per_circle_color_summary`。

## 4. 修复口径

### 4.1 Raw Payload Sanitization

`healing_plan` 装配必须执行强制清洗：

1. 禁止出现 raw Python dict 或截断 dict 片段。
2. 禁止出现 `{'inner'`、`'middle':`、`'outer':`、`": '金色'"` 等内部 payload 形态。
3. 清洗后为空的字段必须从 `root_cause_chain`、`imbalance_diagnosis`、`topic_context` 或 `narrative_plan` 重建。
4. 不允许把内部 payload 透传给用户主报告。

### 4.2 Debug Scope

算法保真 debug 默认按当前请求模式计算：

1. Lite scope 不扫描 Pro draft。
2. Pro scope 必须扫描 Pro draft。
3. 全量内部审计可使用 `all` scope，但不能作为 Lite golden 默认结论。

### 4.3 Narrative Compression

逐圈深浅状态必须从 Batch E runtime evidence 派生：

1. 来源字段为 `interpretation_method_trace.per_circle_color_analysis.*.state_basis`。
2. Lite 压缩为一段简洁画面依据。
3. Pro 展开为更完整的证据摘要。
4. 形状分析不在本批扩展。

## 5. 成功标准

本批成功标准固定为：

1. `BATCH-F-002-PRO-FAIL-001` 关闭。
2. `BATCH-F-002-LITE-FAIL-001` 关闭。
3. 三个逐圈深浅偏差至少降级为 `pass` 或明确剩余 `pass_with_drift`。
4. `toC/data/knowledge/builds/*/evals/summary.json` 中 `raw_payload_leak_found_count = 0`。
5. `toC/data/knowledge/builds/*/evals/summary.json` 中 `algorithm_fidelity_fail_count = 0`。
6. 正式文档、fixture、golden 资产不出现机器绝对路径或临时工作区路径。
