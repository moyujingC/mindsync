## 1. 目的

本文件专门回答：

- `当下映照报告` 的正文到底由哪些内容块组成
- 这些内容块各自承担什么任务
- 生成侧应该输出哪些结构化字段
- 当前如果要把低压入口型报告从主报告中拆出来，建议怎么定义 canonical 结构

这份文档不是页面视觉稿，也不是 prompt 文案本身。

它是：

- 内容结构定义
- structured schema 前置定义
- 页面渲染与生成实现之间的共同接口说明

## 2. 继承的上游结论

本文件继承以下前提：

1. `当下映照报告` 是 `低压入口型理解报告`
2. 它的核心用户任务是：
   - 快速命中
   - 少量依据
   - 温柔解释
   - 现实连接
   - 低压下一步
3. 它的最小内容骨架是：
   - 当前状态命中
   - 画面中的主要依据
   - 一句温柔但清楚的解释
   - 一句现实连接
   - 一个低压下一步

## 3. 本轮做什么 / 不做什么

### 3.1 本轮做什么

本轮明确：

- 内容块定义
- 字段层级
- 字段命名建议
- 每个字段的生成要求
- 低压入口型报告的 canonical 结构

### 3.2 本轮不做什么

本轮不直接定义：

- 最终对外文案语气
- 最终 UI 排版
- 具体价格
- 是否免费赠送或和活动怎么绑定
- 主报告的升级链路实现

## 4. 结构设计原则

当下映照报告的结构，不应只是“短”，而应明显感觉更轻。

当前建议遵循以下 5 条原则：

1. `先命中，不铺垫`
   - 用户第一眼就要被接住
2. `只给够用的依据`
   - 有依据，但不展开成大篇分析
3. `解释只到当前状态层`
   - 不强行上升到 Journey 层的长期模式分析
4. `现实连接要轻`
   - 落地即可，不做长篇场景拆解
5. `下一步必须低压`
   - 不能太重、太多、太像训练计划

## 5. 当前建议的内容块

当前建议将 `当下映照报告` 拆成 `5` 个主内容块与 `2` 个辅助内容块。

### 5.1 五个主内容块

1. `标题`
   - 用来定住当前状态气候
2. `当前状态命中`
   - 快速建立“被看见”感
3. `画面中的主要依据`
   - 告诉用户为什么会这样理解
4. `一句现实连接`
   - 轻轻把报告拉回生活
5. `一个低压下一步`
   - 帮用户带走一个最轻的动作

### 5.2 两个辅助内容块

1. `温柔解释`
   - 对当前状态做一句更清楚的翻译
2. `后续入口提示`
   - 为主报告或陪你画承接预留接口

## 6. Canonical 内容结构

当前建议把 `当下映照报告` 的 canonical 内容结构定义为：

```yaml
current_mirroring_report:
  focus_mode: string
  focus_topic: string
  title: string
  state_hit:
    opening: string
    emotional_weather: string
  visual_evidence:
    summary: string
    anchors: string[]
  gentle_explanation:
    current_state: string
    why_it_makes_sense: string
  reality_echo:
    life_touchpoint: string
    recent_echo: string
  next_step:
    direction: string
    action: string
  gentle_bridge:
    continue_option: string
    why_continue: string
```

说明：

- 这是一份“产品语义结构”
- 后续如需从主报告中拆出低压入口，应尽量向这份结构靠拢

## 7. 字段定义

## 7.1 title

### 作用

- 给整份低压报告定一个情绪气候

### 要求

- 要轻
- 要有画面感
- 不要故作深刻

## 7.2 state_hit

### 作用

- 承担“快速命中”任务

### 子字段

- `opening`
- `emotional_weather`

### 要求

- 2 句以内最好
- 第一眼就要像在说她现在

## 7.3 visual_evidence

### 作用

- 承担“不是随机安慰”的依据任务

### 子字段

- `summary`
- `anchors`

### 要求

- 只能给最关键依据
- 不能展开成长篇技术分析

## 7.4 gentle_explanation

### 作用

- 承担“温柔解释”任务

### 子字段

- `current_state`
- `why_it_makes_sense`

### 要求

- 让用户知道自己现在这样是有原因的
- 但不要上升到模式命名或根源分析

## 7.5 reality_echo

### 作用

- 承担“现实连接”任务

### 子字段

- `life_touchpoint`
- `recent_echo`

### 要求

- 轻轻落地即可
- 不需要展开复杂场景

## 7.6 next_step

### 作用

- 承担“低压下一步”任务

### 子字段

- `direction`
- `action`

### 要求

- 要轻
- 要现实
- 要让用户觉得可以做到

## 7.7 gentle_bridge

### 作用

- 为主报告、陪你画或再画一幅预留后续接口

### 子字段

- `continue_option`
- `why_continue`

### 要求

- 只能轻提示
- 不能喧宾夺主

## 8. 当前阶段收束建议

基于以上定义，当前建议先收束到下面 4 个判断：

1. 当下映照报告的重点不是结构多，而是进入轻
2. 它的依据必须存在，但只到“够成立”为止
3. 它的解释必须停在当前状态层
4. 它的结尾应优先服务低压承接，而不是重销售
