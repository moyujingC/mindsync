## 1. 文档定位

这份文档用于约束 `一镜一梳` 当前一轮草稿页快速提质。

它不是最终视觉设计稿，也不替代 Figma Make 中已经确认可用的页面。它的作用是让 UI skill 或代码试改在同一套审美、信息层级和产品边界下工作，避免把草稿页改成另一套风格。

当前工作分三类页面处理：

1. 已在 Figma Make 中设计过、用户认为基本可用的页面：只允许做细节优化，不做结构性重画。
2. 功能已经实现但明显是草稿的页面：允许用 skill 快速出一版暂时可用版本。
3. 试改后仍无法达到产品气质的关键页面：回到 Figma Make 重新设计，再回代码复刻。

## 2. 本轮目标

本轮目标不是做完整设计系统，而是先把草稿页拉到“可以继续验证主链路”的水平。

优先保证：

1. 用户知道当前在哪一步。
2. 用户知道下一步能做什么。
3. 页面视觉气质不破坏 `一镜一梳` 的疗愈、内省和陪伴感。
4. 主要 CTA 清楚，次要动作不抢注意力。
5. 草稿页与已可用页面看起来属于同一个产品。

暂不追求：

1. 完整跨端设计系统。
2. 大量复杂动效。
3. 全量 icon 体系。
4. 所有页面一次性达到最终上线视觉质量。

## 3. 产品气质

`一镜一梳` 的界面应给用户的第一感受是：

1. 安静
2. 清晰
3. 被接住
4. 有东方身心练习的含蓄气质
5. 不神秘化、不玄学化、不制造焦虑

应避免：

1. 过度赛博、过度 AI 工具感。
2. 过度塔罗、占卜、水晶、神秘学视觉符号。
3. 过度医疗化、诊断化表达。
4. 高饱和紫色、霓虹渐变、模板化玻璃卡片堆叠。
5. 页面看起来像营销漏斗，而不是一次自我照见的体验。

## 4. 页面处理规则

### 4.1 已有 Figma Make 基础的页面

这类页面以既有设计为准。

允许：

1. 调整间距、字号、对齐、按钮状态。
2. 修正移动端溢出、视觉拥挤和可读性问题。
3. 统一局部 icon、分割线、标签样式。

不允许：

1. 改变页面主结构。
2. 替换核心视觉语言。
3. 重写页面叙事顺序。
4. 因为某个 skill 的偏好引入新风格。

### 4.2 功能已实现但仍是草稿的页面

这类页面允许进行快速提质。

优先处理顺序：

1. 信息层级
2. CTA 层级
3. 页面留白与阅读节奏
4. 色彩和材质统一
5. icon 和装饰元素
6. 轻量动效

每页必须先回答：

1. 用户来到这页时最关心什么？
2. 页面只需要推动用户完成哪一个主动作？
3. 哪些信息是当前必须读，哪些可以折叠或降权？
4. 这页是否和前后页面的情绪节奏一致？

### 4.3 应回到 Figma Make 的页面

如果页面满足任一条件，不应继续只靠 skill 修补：

1. 页面需要重新定义阅读结构。
2. 页面承载大量报告内容，阅读节奏比组件样式更重要。
3. 页面需要新的品牌级视觉母题。
4. 页面当前结构会误导用户理解 `Lite / Pro / Journey` 的产品边界。
5. 连续两轮 skill 试改后仍然像拼贴稿。

## 5. 核心页面判断

### 5.1 上传页

上传页的核心任务是让用户放心提交作品，并理解三圈识别会发生什么。

设计重点：

1. 画作预览和三圈结构应是视觉中心。
2. 文案要降低不确定感，不要催促用户。
3. 主题、感受、意图等输入不要压过上传动作。
4. CTA 应明确表达“开始识别”或“继续生成”这一类动作。

上传页可以用 skill 做 polish，但如果已经有可用 Figma Make 版本，应以 Figma Make 为准。

### 5.2 报告选择页

报告选择页的核心任务是帮助用户在 `Lite` 与 `Pro` 间做清楚选择。

设计重点：

1. 不要暗示 `Lite` 是错误选择。
2. 不要把 `Pro` 做成强压式 upsell。
3. 两种报告的差异应围绕用户任务，而不是只围绕价格。
4. 主要差异应该一眼能读懂。

这类页面适合用 skill 快速提质。

### 5.3 Loading 页

Loading 页的核心任务是承接等待，不是展示技术能力。

设计重点：

1. 告诉用户正在发生什么。
2. 给出温和、可信的等待反馈。
3. 不要堆砌 AI 分析、模型推理、神秘仪式感。
4. 动效可以有，但必须安静、低频、低干扰。

这类页面适合用 skill 快速提质，但不建议优先引入复杂 motion。

### 5.4 报告阅读页

报告阅读页的核心任务是帮助用户读懂自己，而不是展示一份复杂报告。

设计重点：

1. 第一屏先给用户安全感和阅读方向。
2. 长内容必须有清晰分段、摘要和节奏。
3. CTA 不应打断核心阅读。
4. `Lite` 与 `Pro` 的信息密度应明显不同，但不应让 `Lite` 显得廉价。

报告阅读页如果只是样式粗糙，可以先试改；如果阅读结构本身不成立，应回到 Figma Make。

## 6. Skill 使用边界

### 6.1 taste skill

适合用于：

1. 判断草稿页是否像模板。
2. 提升页面层级、气质和完整度。
3. 检查视觉语言是否和产品气质冲突。
4. 给出页面 polish 方向。

使用要求：

1. 不允许覆盖已确认可用的 Figma Make 主结构。
2. 不允许只追求“高级感”而牺牲任务清晰度。
3. 每次输出必须指出哪些建议是必改，哪些只是可选。

### 6.2 better icons

适合用于：

1. 统一局部 icon 风格。
2. 删除低质量装饰图标。
3. 为报告、上传、历史、生成状态建立少量稳定符号。

使用要求：

1. icon 只服务识别和节奏，不承担主要叙事。
2. 不引入过度玄学符号。
3. 同一页内 icon 风格必须统一。

### 6.3 motion ai kit

当前不作为优先 skill。

仅在以下情况使用：

1. Loading 页需要低干扰等待反馈。
2. 页面切换需要轻量过渡来降低突兀感。
3. 已确认静态结构可用，只差动效节奏。

禁止：

1. 为了“看起来高级”添加动效。
2. 让动效拖慢主链路。
3. 在报告阅读页加入抢注意力的动态装饰。

### 6.4 impeccable

适合第二阶段用于重点页面强化。

当前只建议用于：

1. Landing 或关键首屏。
2. 已经确定结构、但需要提升视觉完成度的单页。
3. 需要接近正式稿质感的页面。

不建议用于大面积修草稿页。

### 6.5 泛化 UI skills

当前不建议作为主力。

如果使用，必须受本文件约束，不能输出与 `一镜一梳` 产品气质冲突的通用 SaaS、AI 工具或营销页风格。

## 7. 快速验收标准

一页草稿页经过 skill 试改后，至少满足：

1. 第一屏能看出页面目的。
2. 主 CTA 明确且唯一。
3. 文案和视觉不制造焦虑。
4. 页面不再像临时拼装稿。
5. 与前后页面风格不明显断裂。
6. 移动端阅读不拥挤。
7. 没有引入新的产品语义，例如把 `Lite / Pro` 改回升级关系。

如果不满足，应继续小改；如果两轮后仍不满足，应回到 Figma Make 重做。

## 8. 本轮推荐流程

1. 先选择一个“最草但重要”的页面做试点。
2. 用本文件作为约束输入，让 skill 出一版提质方案。
3. 只实现必要结构和样式，不同步引入复杂动效。
4. 对照快速验收标准判断是否可继续沿用。
5. 如果试点有效，再扩展到同类草稿页。
6. 如果试点无效，停止批量试改，回 Figma Make 重新设计关键页。
