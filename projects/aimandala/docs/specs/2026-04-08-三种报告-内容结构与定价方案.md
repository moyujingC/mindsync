## 1. 目的

本文件专门回答四个问题：

1. 三种报告各自到底应该写什么
2. 三种报告之间的功能边界到底怎么切
3. 当前阶段最适合采用什么价格梯度
4. 后续如果继续拆单篇产品定义，各篇应共同遵守什么母规则

这份文档不是：

- 单篇报告的最终长文产品定义
- UI 结构稿
- 技术 schema
- 最终商业化合同文本

它是：

- 三种报告的母表
- 内容结构总约束
- 功能分层总约束
- 当前阶段建议定价方案

## 2. 继承的上游结论

本文件继承以下前提：

1. 当前报告产品直接按 `Lite / Pro / Journey` 三种商品理解
2. `Lite` 与 `Pro` 都支持：
   - `全面解读`
   - `专题解读`
3. 如果用户没有选主题，则 `Lite` 与 `Pro` 都默认进入 `全面解读`
4. `Journey 报告` 不属于当前单次画作解读，而是基于多次历史画作的高阶分析
5. 三种报告不是强制线性升级关系，而是围绕不同用户任务展开

## 3. 当前建议先收束的核心判断

本轮先收束到下面 6 个判断：

1. 当前真实对外商品就是 `Lite / Pro / Journey`
2. `Lite` 支持：
   - `全面解读`
   - `专题解读`
3. `Pro` 支持：
   - `全面解读`
   - `专题解读`
4. 如果用户没选主题，`Lite` 与 `Pro` 都默认进入 `全面解读`
5. `Journey 报告` 不能根据单次一幅画直接成立，而必须基于多次历史画作
6. `Journey` 应被理解为单独的高阶历史分析产品，而不是当前单次解读页里的同层选择项

## 4. 三种报告总览

| 报告类型 | 当前解读方式 | 核心用户任务 | 主要服务谁 | 输入跨度 | 长期方向上的典型承接 |
|---|---|---|---|---|---|
| Lite | `全面解读` / `专题解读` | 先被接住，先看见当下 | 初次进入报告、状态较乱、承载力较低的用户 | 单次画作 | 再画一幅 / Pro |
| Pro | `全面解读` / `专题解读` | 更完整地看懂自己，或围绕某个主题看清楚 | 大多数真正想看懂自己的用户，或已明确卡在某个主题的用户 | 单次画作 | 同主题继续深入 / 多次画作后进入 Journey |
| Journey 报告 | 长期综合解读 | 看见跨时间重复机制与改变优先级 | 已累计多次历史画作、愿意继续深入的高意愿用户 | 多次历史画作 | 21 天定制方案 / 长期 AI 陪伴 |

补充说明：

- 上表定义的是长期产品方向，不等于当前 `To C MVP` 结果页会直接出现的 CTA
- 当前 `Lite / Pro` 结果页动作，以 [2026-04-08-MVP阶段结果页CTA规则.md](/Users/xinran/Downloads/dev/mindsync/projects/aimandala/docs/specs/2026-04-08-MVP阶段结果页CTA规则.md) 为准

## 5. 三种报告的内容结构

## 5.1 Lite

### 一句话定义

- 帮用户先确认“我现在这样是能被看见和接住的”，而不是立刻把自己读成一份高密度分析

### 当前建议的两个版本

1. `全面解读`
   - 对应 `general`
   - 更偏“先整体看看我现在是什么状态”
2. `专题解读`
   - 对应具体主题
   - 更偏“先在这个主题里被看见，但仍保持 Lite 的低压风格”

### 最小内容骨架

1. `当前状态命中`
   - 第一时间说中她此刻最主要的感受气候
2. `画面中的主要依据`
   - 告诉她为什么会这样理解
3. `一句温柔但清楚的解释`
   - 不展开复杂机制，只解释当前处在什么状态
4. `一句现实连接`
   - 让她知道这和最近的生活有关
5. `一个低压下一步`
   - 例如一个觉察动作或一次再画

### 这个报告最应该强调什么

1. 快速命中
2. 低压语气
3. 被接住感
4. 不让用户觉得自己被分析得太重

### 这个报告不应该承担什么

1. 深层机制拆解
2. 高密度模式命名
3. 根源分析
4. 长周期行动设计

## 5.2 Pro

### 一句话定义

- 帮用户更完整地看懂自己，或者围绕一个已选主题看得更深、更清楚

### 当前建议的两个版本

1. `全面解读`
   - 当用户没有选主题时默认进入
   - 更偏“把我当前整体状态看清楚”
2. `专题解读`
   - 当用户选了主题时围绕该主题展开
   - 更偏“把这个问题在当前主题里看清楚”

### 共同最小内容骨架

1. `整体命中`
2. `画面依据`
3. `状态解释`
4. `模式命名`
5. `现实连接`
6. `一个下一步`

### 这个报告最应该强调什么

1. 命中感
2. 解释链
3. 结构化命名
4. 与现实生活的连接
5. 一个清楚但不压迫的下一步

### 这个报告最应该强调什么

1. 比 Lite 更完整的解释力
2. 全面解读与专题解读都成立
3. 场景具体度
4. 模式命名与现实连接
5. 清楚的主路径

### 这个报告不应该承担什么

1. 跨多次画作的长期综合判断
2. 假装已经进入 Journey 层
3. 把所有主题都讲一遍
4. 直接变成训练计划

### 当前优先适用主题

1. 关系
2. 边界
3. 情绪稳定
4. 表达
5. 事业阶段

## 5.3 Journey 报告

### 一句话定义

- 基于用户多次历史画作，看见“为什么我总会这样”的重复机制、形成逻辑与当前最该优先处理的层次

### 最小内容骨架

1. `深层主判断`
   - 先给出最核心的模式判断
2. `结构化执行摘要`
   - 用较高压缩度总结核心洞察
3. `机制拆解`
   - 把状态、模式、防御、代价串成一条链
4. `根源递进`
   - 从表层表现走向更深层原因
5. `优先级判断`
   - 告诉用户不是所有问题都要一起改，当前先处理什么
6. `后续方向`
   - 承接到方案、长期陪伴或更明确的连续推进

### 这个报告最应该强调什么

1. 深度质变
2. 机制递进
3. 根源层次
4. 改变优先级
5. 更强的后续承接能力

### 这个报告不应该承担什么

1. 专业治疗替代
2. 高风险危机承接
3. 把“更深”误写成“更多漂亮话”
4. 只靠篇幅长来证明价值

## 6. 三种报告之间的功能区分

## 6.1 不是按“长短”区分

三种报告不应按下面方式理解：

- Lite = 最短
- Pro = 更长
- Journey = 最长

更准确的区分方式应是：

- `Lite`
  - 解决“我现在需要先被看见吗”
- `Pro`
  - 解决“我到底怎么了”，或者“这件事为什么一直卡在这个主题里”
- `Journey 报告`
  - 解决“为什么我总会这样，以及现在该先处理哪一层”

## 6.2 不是按“轻版 / 重版”区分

当前最需要避免的是把三种报告重新写回：

- 轻版报告
- 标准版报告
- 深度版报告

这种模糊线性梯度。

因为这样会让每份报告重新退回“只是信息多少不同”，而不是用户任务不同。

## 6.3 真正的区分维度

当前建议用下面 6 个维度区分三种报告：

1. `入口承载力`
   - 用户是否准备好读高密度内容
2. `问题清晰度`
   - 用户是泛模糊，还是已聚焦到单一议题
3. `输入跨度`
   - 是基于单次画作，还是多次历史画作
4. `解释深度`
   - 只解释当前，还是解释反复机制
5. `场景聚焦度`
   - 是通用理解，还是主题专项理解
6. `后续承接强度`
   - 是轻承接，还是直接进入连续方案层

## 7. 当前建议定价方案

## 7.1 定价原则

当前建议遵循以下 5 条原则：

1. `价格首先反映商品层，而不只是内容块名称`
2. `Lite 与 Pro 必须有清楚价格差`
3. `Pro` 内可以有 `全面解读` 与 `专题解读` 两种版本，但不一定拆成不同价格
4. `Journey 报告` 不应沿用单次解读的定价逻辑
5. `当前先把单次解读价格说清，再单独定义历史画作分析价格`

## 7.2 当前建议价

| 商品 / 报告类型          | 当前建议价   | 价格角色     |
| ------------------ | ------- | -------- |
| Lite（含全面解读 / 专题解读） | `9.9` 元 | 低压入口型产品  |
| Pro（含全面解读 / 专题解读）  | `39` 元  | 完整解读主产品  |
| Journey（多次历史画作分析）  | `待单独定义` | 高阶历史分析产品 |

## 7.3 为什么这样定

### Lite：`9.9` 元

原因：

1. 它的价值是真实的，但更偏入口与安放心智
2. 太高会提高首次尝试门槛
3. 完全免费又容易把“报告”整体价值做低

它更适合扮演：

- 首次付费入口
- 活动赠送权益
- 从内容进入后的低门槛第一次购买

### Pro：`39` 元

原因：

1. 它是当前最核心的单次正式解读商品
2. 对大多数用户而言，它已经是“值得单独付费的一次完整理解”
3. 需要与更轻入口拉开明显差价，但又不能高到压制转化

### Journey：`待单独定义`

原因：

1. 它不再是单次一幅画作的解读
2. 它建立在多次历史画作的累计之上
3. 它的价值逻辑更接近“历史模式分析”，不应与 Lite / Pro 单次解读混写

## 7.4 当前建议补差价逻辑

当前建议采用下面的简化补差价逻辑：

1. `Lite -> Pro`
   - 补差价进入
2. `Pro` 内部从 `全面解读` 切到 `专题解读`
   - 当前更适合视作同层改选，不必强调升级
3. `Pro -> Journey`
   - 不建议简单写成补差价
   - 更适合在已累计多次画作后，作为单独高阶分析入口

当前不建议：

1. 强推 `Pro / 全面解读 -> Pro / 专题解读`
2. 强推 `Pro / 专题解读 -> Pro / 全面解读`

因为这两者当前更应该被理解为：

- 同属 `Pro` 的两种解读方向

## 8. 当前阶段最推荐的入口策略

## 8.1 默认主入口

当前更推荐的不是把用户直接丢到三种报告货架，而是：

- 在上传和三圈识别之后，进入明面的 `Lite / Pro` 选择页

原因：

1. 用户首先更容易理解价格层级差异
2. `Lite / Pro` 本来就是当前真实存在的风格差与价格差
3. 让用户自己选，比黑盒推荐更符合当前真实流程
4. 在 `Pro` 内再区分 `全面解读` 与 `专题解读`，会比直接摆更多商品更不容易困惑

## 8.2 选择页应该怎么帮助用户理解 Lite

当前选择页应重点解释：

1. `Lite` 更轻、更快、更像先看清当前状态
2. `Pro` 更完整、更深入、更像一次正式解读
3. 两者都是正式报告，不是“有用”和“没用”的区别

## 8.3 主题在选择页中如何起作用

如果用户已经选了具体主题，选择页更适合这样解释：

1. `Lite`
   - 会围绕这个主题做更轻的解读
2. `Pro`
   - 会围绕这个主题做更完整的解读

这里的主题作用是帮助用户理解内容重心，不是替用户自动决定价格层。

## 8.4 什么情况下优先推 Journey 报告

当用户明显呈现以下特征时，才适合引导 `Journey`：

1. 已有多次历史画作可供对照
2. 已读过 `Lite` 或 `Pro` 仍觉得“不够”
3. 明确想看“为什么我总会这样”
4. 已建立信任，愿意进入历史模式分析

## 9. 当前文档层后续建议

基于本文件，后续最适合继续补的文档顺序建议为：

1. `Pro` 内容优化提纲
2. `Journey 报告` 产品定义
3. `Lite` 内容优化提纲
4. `Lite / Pro / Journey` 结果页分流策略

如果只允许先做一篇，当前最值得优先展开的是：

- `Pro` 内容优化提纲

因为：

1. `Pro` 是当前单次解读的主产品
2. `Pro / 专题解读` 是下一步最容易和主题系统真正接上的解读方式
3. 它会直接影响后续入口分流、价格话术和结果页承接口径
