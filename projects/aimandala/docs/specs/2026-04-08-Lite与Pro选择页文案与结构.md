## 1. 目的

本文件专门定义当前 `To C MVP` 里最关键的一层明面分流：

- 用户在上传完成并经过 `三圈识别` 之后，如何在 `Lite` 和 `Pro` 之间自己做选择

这份文档重点回答：

1. 选择页要告诉用户什么
2. `Lite` 与 `Pro` 的卡片应该怎么写
3. 页面该如何解释两者差异
4. 用户点击后应该怎么进入 loading 页面

## 2. 当前适用范围

本规则当前只适用于：

1. `upload`
2. `detect`
3. `Lite / Pro` 选择页
4. 选择后的 loading 页面

当前不覆盖：

1. 结果页 CTA
2. `Journey`
3. 结果页里的再次升级入口
4. 支付链路的最终实现细节

## 3. 当前最重要的收束判断

本轮先收束到下面 8 个判断：

1. 当前选择页不是系统推荐页，而是用户主动选择页
2. 页面必须明说 `Lite` 和 `Pro` 的差异
3. 页面必须明说价格差异
4. 页面不需要替用户做判断
5. 页面不应把 `Lite` 写成缩水版
6. 页面不应把 `Pro` 写成唯一正确答案
7. 选择后应直接进入对应报告的 loading 页面
8. `Journey` 不应出现在当前选择页

## 4. 页面任务

当前选择页只需要完成 4 个任务：

1. 告诉用户已经完成上传和识别
2. 让用户知道现在要在 `Lite` 和 `Pro` 之间选一个
3. 用最短的话解释两者差异
4. 让用户点下去后直接进入对应生成链路

它不需要完成：

1. 深度教育完整报告矩阵
2. 系统替用户评分和推荐
3. 展示未来产品线
4. 解释所有技术细节

## 5. 页面建议结构

当前建议页面按下面顺序组织：

1. `识别完成提示`
2. `一句选择说明`
3. `Lite 卡片`
4. `Pro 卡片`
5. `轻量差异说明`

## 6. 顶部文案建议

## 6.1 顶部状态提示

当前建议：

- `作品识别完成`

可接受备选：

- `识别完成，接下来请选择解读方式`

## 6.2 页面主标题

当前建议：

- `这次你想用哪种方式开始解读？`

可接受备选：

- `选择这次的解读方式`

当前不建议：

- `系统推荐你选择`
- `请选择适合你的版本`

## 6.3 页面辅助说明

当前建议：

- `Lite 更轻、更快；Pro 更完整、更深入。`

如果当前上传页带了主题，也可以补一行：

- `无论选 Lite 还是 Pro，都会围绕你这次上传的内容继续解读。`

## 7. Lite 卡片文案建议

## 7.1 卡片标题

- `Lite`

## 7.2 一句话说明

当前建议：

- `先轻一点地看清这次的状态。`

可接受备选：

- `更轻、更快，先看看这次画里最明显的状态。`

## 7.3 价格

- `9.9 元`

## 7.4 按钮文案

- `选择 Lite`

## 7.5 说明重点

`Lite` 卡片最该强调：

1. 低压进入
2. 当前状态
3. 更轻的阅读负担

## 8. Pro 卡片文案建议

## 8.1 卡片标题

- `Pro`

## 8.2 一句话说明

当前建议：

- `更完整地看懂这次画在表达什么。`

可接受备选：

- `更完整、更深入，适合想认真看懂这次状态的人。`

## 8.3 价格

- `39 元`

## 8.4 按钮文案

- `选择 Pro`

## 8.5 说明重点

`Pro` 卡片最该强调：

1. 完整解读
2. 更清楚的解释链
3. 更深入的现实连接

## 9. 差异说明应该怎么写

当前建议只用非常短的方式说明差异：

1. `Lite`
   - 更轻、更快
2. `Pro`
   - 更完整、更深入

如果页面需要再多一句，只建议补：

- `两者都会基于你这次上传的作品继续解读。`

当前不建议：

1. 写很长的产品教育
2. 用术语解释差异
3. 暗示系统更推荐某一个
4. 把差异写成“便宜版 / 正式版”

## 10. 主题在选择页中的显示方式

如果当前上传页已经选了主题，选择页更适合轻量显示：

- `这次你更想重点看：关系`
- `这次你更想重点看：全面看看`

它的作用是：

1. 让用户确认自己的输入还在
2. 让后续 loading 更连贯
3. 让用户知道选 `Lite` 或 `Pro` 不是从头再来

## 11. 点击后的链路规则

当前点击规则应明确为：

1. 点击 `选择 Lite`
   - 直接进入 `Lite` 对应 loading 页面
2. 点击 `选择 Pro`
   - 直接进入 `Pro` 对应 loading 页面

当前价格露出、购买关系与选择后跳转的支付承接口径，以 [2026-04-08-Lite与Pro选择后支付与跳转规则.md](/Users/xinran/Downloads/dev/mindsync/projects/aimandala/docs/specs/2026-04-08-Lite与Pro选择后支付与跳转规则.md) 为准。

loading 页的具体文案与状态规则，以 [2026-04-08-Lite与Pro解读loading页文案与状态规则.md](/Users/xinran/Downloads/dev/mindsync/projects/aimandala/docs/specs/2026-04-08-Lite与Pro解读loading页文案与状态规则.md) 为准。

页面不应再额外插入：

1. 第二层推荐页
2. 系统二次确认页
3. 多余的解释弹窗

## 12. 当前最需要避免的写法

当前最需要避免下面 8 种情况：

1. 把选择页写成推荐页
2. 页面暗中把用户推向某一个版本
3. `Lite` 和 `Pro` 的按钮都很长很复杂
4. 卡片说明过长，像销售页
5. 把 `Journey` 混进选择页
6. 把主题直接写成新的版本选择
7. 点击后还要再多跳一层选择
8. 把价格差写得不清楚

## 14. 当前阶段收束结论

基于以上定义，当前建议先收束到下面 5 个判断：

1. 当前 `Lite / Pro` 页面本质上是用户主动选择页，不是推荐页
2. 页面核心任务是讲清差异，而不是替用户做决定
3. `Lite` 与 `Pro` 的价格差和内容差都必须明说
4. 选择之后应直接进入对应 loading 页面
5. 后续上传页、选择页、loading 页与支付页文案，都应回到这份文档统一校验
