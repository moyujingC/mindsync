## 1. 当前判断

当前报告版本已经作为 MVP 可接受版本。

本轮上线不再重新打开 Lite / Pro 报告结构设计，不再把历史讨论中的固定结构、固定字数或固定模块作为上线验收依据。

MVP 上线判断只看：用户是否能完成真实付费体验，报告和追问是否安全可交付，失败时是否不失控。

## 2. 当前必须保证

1. 用户能进入产品、提交画作、生成并查看报告。
2. Lite 价格为 9.9 元。
3. Pro 只能从 Lite 后升级，不提供独立购买入口。
4. Pro 升级价为 29 元。
5. 付费后能看到对应权益内容。
6. 未付费不能越权查看付费内容。
7. 支付失败、取消或同步中不会造成权益错乱或重复付费。
8. 报告和 followup 不出现诊断、恐吓、治疗承诺、投资建议、未来预测或依赖诱导。
9. followup 只围绕本次报告追问，不做长期陪伴、跨报告人格总结或重大现实决策替代。
10. 关键失败状态不白屏，至少告诉用户发生了什么和下一步怎么做。
11. 上线后能人工查到支付、权益、报告和 followup 的基本状态。

## 3. 本轮不再验收

以下内容不再作为当前 MVP 上线验收依据：

1. Lite 是否符合某个固定内容层级。
2. Pro 是否符合某个固定内容层级。
3. Lite / Pro 固定字数范围。
4. 固定报告模块、固定段落顺序或固定根源拆解层级。
5. 报告 prompt 是否继续大改。
6. 当前报告是否需要重新按历史内容边界设计。

如果后续需要重新定义 Lite / Pro 内容差异，应单独开启新 spec，不从旧文档自动继承。

## 4. 最小上线检查

上线前只保留以下最小检查：

| 检查项 | 通过标准 |
|---|---|
| 主流程 | 进入、提交、生成、查看、升级、追问能跑通 |
| 支付权益 | 付费可看，未付费不可看，失败不解锁，成功不丢权益 |
| 报告内容 | 当前版本用户可接受，非空，不明显脱离画作，无安全越界 |
| Followup | 围绕本次报告，不串报告，不做诊断 / 投资 / 长期陪伴 |
| 异常状态 | 上传、生成、支付、followup 失败时不白屏，有下一步 |
| 人工排障 | 能查支付、权益、report_id、followup 请求和失败原因 |

## 5. 文档使用规则

后续涉及 MVP 上线判断时，先读本文。

如其他文档仍保留历史 Lite / Pro 内容结构、固定字数、固定模块或旧购买流程，以本文为准，并应删除旧信息而不是继续引用。
