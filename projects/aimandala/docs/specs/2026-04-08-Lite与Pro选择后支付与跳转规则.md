## 1. 目的

本文件专门收束当前主链路里一个容易被误写的点：

- `Lite / Pro` 选择之后，价格如何被用户理解，购买关系如何表达，以及为什么用户会直接进入 loading，而不是先看到一层独立支付页

这份文档重点回答：

1. 当前是否存在独立支付页
2. 选择页里该如何露出价格
3. `Lite` 和 `Pro` 的购买关系该如何表达
4. 选择之后应该如何跳到 loading

## 2. 当前适用范围

本规则当前只适用于 `To C MVP` 主链路中的：

1. `Lite / Pro` 选择页
2. 选择后的支付承接说明
3. 进入 loading 页之前的跳转逻辑

当前不覆盖：

1. 渠道级支付实现细节
2. 支付接口设计
3. 支付异常与退款流程
4. 结果页里的升级逻辑

## 3. 当前最重要的收束判断

本轮先收束到下面 8 个判断：

1. 当前文档口径里，不单独拆一层用户可见的支付页
2. 价格信息应在 `Lite / Pro` 选择页明示
3. `Lite` 与 `Pro` 当前是独立购买，不是默认先买 `Lite`
4. 用户在选择页做的是版本选择，不是补差价选择
5. 选择后，用户视角上应直接进入对应 loading 页
6. 当前不把支付流程再拆成多层页面说明
7. 优惠仍然属于渠道优惠券或兑换码逻辑，不在页面主文案里展开
8. 如果未来要拆出独立支付页，应单独开 spec

## 4. 当前购买关系

当前正式口径应统一为：

1. `Lite`
   - 独立购买
2. `Pro`
   - 独立购买
3. 两者不是“先买 Lite，再默认升级到 Pro”的强制链路

这意味着当前选择页要传达的是：

- `你现在要选择的是这次购买哪一种解读`

而不是：

- `你先买一个，后面再说`

## 5. 当前为什么不单独拆支付页

基于当前已确认的真实流程，用户在选择 `Lite / Pro` 后会直接进入 loading。

因此当前更准确的产品口径应是：

1. 价格信息已经在选择页明示
2. 用户点击选择后，支付承接不再单独暴露成一层页面
3. 用户视角里会直接进入对应生成等待

这不是在否认支付存在，而是在收束：

- 当前用户可见流程里，不再额外插一页专门讲支付

## 6. 选择页里价格该怎么露出

当前建议价格露出只做最小必要表达：

1. `Lite`
   - `9.9 元`
2. `Pro`
   - `39 元`

价格露出的作用是：

1. 让用户知道两者不是同价
2. 让价格差和内容差同时发生在明面上
3. 降低后续“为什么这次花得不一样”的困惑

当前不建议：

1. 在选择页讲太多支付规则
2. 在主文案里展开优惠券逻辑
3. 把价格写成复杂套餐说明

## 7. 选择按钮与支付承接关系

当前建议用户理解路径应是：

1. 看见 `Lite` / `Pro` 差异
2. 看见对应价格
3. 点击 `选择 Lite` 或 `选择 Pro`
4. 直接进入对应 loading 页

因此按钮的产品含义更接近：

- `选择并继续`

但当前页面文案仍建议维持简洁：

1. `选择 Lite`
2. `选择 Pro`

## 8. 当前页面不该写什么

当前选择页和跳转承接里，不建议写：

1. `立即支付`
2. `确认支付后开始`
3. `先购买再生成`
4. `补差价升级`

原因是：

1. 这些写法会让用户预期后面还有一层独立支付页
2. 与当前“选完直接进 loading”的现状不一致
3. 会把主链路写得更复杂

## 9. 优惠与补差价的当前口径

当前正式口径仍保持：

1. 挂牌价固定
   - `Lite = 9.9`
   - `Pro = 39`
2. 优惠优先通过渠道优惠券或兑换码处理
3. `Lite -> Pro` 的补差价逻辑可以作为长期存在的购买关系说明

但在当前主链路页面文案里：

1. 不主动强调补差价
2. 不把补差价写成当前入口主路径
3. 不让它抢走“当前先自己选 Lite 或 Pro”的流程真相

## 10. 跳转规则

当前建议跳转规则明确为：

1. 点击 `选择 Lite`
   - 直接进入 `Lite` loading
2. 点击 `选择 Pro`
   - 直接进入 `Pro` loading

当前不建议：

1. 选择后先跳一层支付说明页
2. 选择后再跳一层版本确认页
3. 让用户在 loading 前再次确认价格

## 11. 当前最需要避免的写法

当前最需要避免下面 8 种写法：

1. 文档里把当前流程写成“先支付，再决定版本”
2. 文档里把当前流程写成“默认先买 Lite”
3. 页面按钮写成明显支付按钮
4. 价格露出不清楚
5. 把补差价写成主入口逻辑
6. 把优惠券写成页面主文案
7. 选择后再插入独立支付页
8. 让用户以为点完选择还没真正开始

## 12. 当前阶段建议文案底稿

选择页卡片价格：

- `9.9 元`
- `39 元`

按钮：

- `选择 Lite`
- `选择 Pro`

跳转后的用户感受应是：

- `我已经选好了，系统现在正在为我生成对应解读。`

## 13. 当前阶段收束结论

基于以上定义，当前建议先收束到下面 5 个判断：

1. 当前用户可见流程里不单独拆支付页
2. 价格信息应在 `Lite / Pro` 选择页明示
3. `Lite` 与 `Pro` 当前应按独立购买理解
4. 选择之后应直接进入对应 loading 页
5. 如果未来要拆独立支付页或强化补差价入口，应单独开新 spec
