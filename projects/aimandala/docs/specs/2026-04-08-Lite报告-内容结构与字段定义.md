## 1. 目的

本文件用于统一定义 `Lite` 的内容骨架与字段接口。

这里要回答的是：

1. `Lite` 共享哪些正文主骨架
2. `全面解读` 与 `专题解读` 的差异放在哪里
3. `Lite` 怎样保持轻，但仍然成立

## 2. 设计原则

`Lite` 的结构应同时满足下面 5 条原则：

1. `先命中，不铺垫`
2. `只给够用的依据`
3. `解释停在当前状态层`
4. `现实连接要轻`
5. `下一步必须低压`

## 3. Lite 的共享主骨架

无论是 `全面解读` 还是 `专题解读`，当前都建议共享下面 `5` 个主内容块：

1. `标题`
2. `当前状态命中`
3. `画面主要依据`
4. `轻解释与轻连接`
5. `低压下一步`

## 4. 两种方向的差异块

## 4.1 全面解读的差异块

`全面解读` 额外强调：

1. 当前整体气候
2. 这次最主要的状态判断

## 4.2 专题解读的差异块

`专题解读` 额外强调：

1. 当前主题视角
2. 该主题里最明显的卡点或状态

## 5. Canonical 内容结构

当前建议把 `Lite` 的 canonical 内容结构定义为：

```yaml
lite_report:
  mode: overall | topic
  topic: general | father_relationship | mother_relationship | intimate_relationship | parent_child_relationship | wealth_career | health_wellness | personal_growth
  title: string
  opening_hit:
    summary: string
    emotional_weather: string
  visual_evidence:
    summary: string
    anchors: string[]
  gentle_interpretation:
    current_state: string
    why_it_makes_sense: string
  reality_connection:
    life_touchpoint: string
    recent_echo: string
  next_step:
    direction: string
    action: string
  overall_view:
    main_state: string
  topic_view:
    why_this_topic_now: string
    topic_state: string
  bridge:
    continue_option: string
    why_continue: string
```

说明：

1. `overall_view` 只在 `mode = overall` 时必填
2. `topic_view` 只在 `mode = topic` 时必填
3. 其余字段为 `Lite` 的共享主结构

## 6. 字段定义

## 6.1 title

### 作用

- 给整份报告定住当前状态气候

### 要求

1. 要轻
2. 要有画面感
3. 不要故作深刻

## 6.2 opening_hit

### 作用

- 承担“快速命中”任务

### 子字段

- `summary`
- `emotional_weather`

### 要求

1. 第一眼就像在说她现在
2. 最好 2 句以内

## 6.3 visual_evidence

### 作用

- 承担“不是随机安慰”的依据任务

### 子字段

- `summary`
- `anchors`

### 要求

1. 只能给最关键依据
2. 不能展开成长篇分析

## 6.4 gentle_interpretation

### 作用

- 承担“轻解释”任务

### 子字段

- `current_state`
- `why_it_makes_sense`

### 要求

1. 让用户知道自己现在这样是有原因的
2. 不上升到高密度模式分析

## 6.5 reality_connection

### 作用

- 承担“轻现实连接”任务

### 子字段

- `life_touchpoint`
- `recent_echo`

### 要求

1. 轻轻落地即可
2. 不展开复杂场景链条

## 6.6 next_step

### 作用

- 承担“低压下一步”任务

### 子字段

- `direction`
- `action`

### 要求

1. 要轻
2. 要现实
3. 要让用户觉得做得到

## 6.7 overall_view

### 作用

- 只服务 `全面解读`

### 子字段

- `main_state`

### 要求

1. 帮用户快速抓住当前整体状态
2. 不发散成多个主题

## 6.8 topic_view

### 作用

- 只服务 `专题解读`

### 子字段

- `why_this_topic_now`
- `topic_state`

### 要求

1. 带出主题视角
2. 但仍保持 `Lite` 的轻量风格

## 6.9 bridge

### 作用

- 为结果页后续承接预留接口
- 当前应只承接已经存在的 `MVP` 页面动作

### 子字段

- `continue_option`
- `why_continue`

### 要求

1. 优先承接到 `Pro`
2. 也可承接 `再画一幅`
3. 不写入尚未落地的未来模块名称
4. 当前结果页动作仍以 `MVP阶段结果页CTA规则` 为准

## 7. 当前阶段收束建议

基于以上定义，当前建议先收束到下面 5 个判断：

1. `Lite` 必须共用一套母 schema，再按 `mode` 分叉
2. `Lite` 的重点不是结构多，而是进入轻
3. `Lite` 的依据必须存在，但只到“够成立”为止
4. `Lite` 的解释必须停在当前状态层
5. `Lite` 的结尾应优先服务低压承接，而不是重销售
