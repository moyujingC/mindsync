## 1. 目的

本文件专门定义当前 `To C MVP` 里从选择页进入报告结果页之间的过渡层：

- 用户选了 `Lite` 或 `Pro` 之后，loading 页到底该如何承接，才不会让等待过程显得突兀、空白或像付款后的黑盒

这份文档重点回答：

1. loading 页要告诉用户什么
2. `Lite` 和 `Pro` 的 loading 文案应该怎么区分
3. 页面应该如何表达“正在生成”
4. 页面何时应该跳到结果页

## 2. 当前适用范围

本规则当前只适用于：

1. `Lite` 选择后的 loading 页
2. `Pro` 选择后的 loading 页

当前不覆盖：

1. 三圈识别中的 loading
2. 支付页等待状态
3. 结果页 CTA
4. 错误页与异常中断页

## 3. 当前最重要的收束判断

本轮先收束到下面 8 个判断：

1. loading 页的任务是承接与安放，不是继续销售
2. 页面必须明说用户刚刚选的是 `Lite` 还是 `Pro`
3. 页面必须让用户知道当前正在生成报告
4. 页面不需要再解释完整产品矩阵
5. 页面不需要再让用户做二次选择
6. `Lite` 与 `Pro` 的 loading 文案可以有轻微差异，但不应像两套完全不同产品
7. 生成完成后应直接进入对应结果页
8. 当前 loading 页不应加入未来产品入口

## 4. 页面任务

当前 loading 页只需要完成 4 个任务：

1. 告诉用户她刚刚的选择已生效
2. 告诉用户系统正在生成对应报告
3. 让等待过程有基本的被承接感
4. 在生成完成后自动进入结果页

它不需要完成：

1. 再次比较 `Lite` 和 `Pro`
2. 再次推荐升级
3. 解释过多技术过程
4. 在等待页里提前摆结果页 CTA

## 5. 页面建议结构

当前建议 loading 页按下面顺序组织：

1. `当前状态提示`
2. `当前所选报告标签`
3. `一句简短等待文案`
4. `轻量过程提示`

## 6. 顶部文案建议

## 6.1 当前状态提示

当前建议统一用：

- `正在生成解读`

可接受备选：

- `正在为你生成报告`

当前不建议：

- `AI 深度分析中`
- `系统正在计算你的心理结构`

## 6.2 所选报告标签

页面应明确显示：

1. `Lite 解读`
2. `Pro 解读`

这样做的作用是：

1. 让用户确认自己刚刚点选成功了
2. 降低“我现在到底在等什么”的不确定感

## 7. Lite loading 页文案建议

## 7.1 一句话主文案

当前建议：

- `我们正在为你整理这次画里最明显的状态。`

可接受备选：

- `我们正在为你生成一份更轻一点的当下解读。`

## 7.2 过程提示

当前建议：

- `很快就好，请稍等片刻。`

## 7.3 语气重点

`Lite` loading 页更适合强调：

1. 轻
2. 稳
3. 不制造紧张感

## 8. Pro loading 页文案建议

## 8.1 一句话主文案

当前建议：

- `我们正在把这次画里的状态、线索和现实连接整理成一份完整解读。`

可接受备选：

- `我们正在为你生成一份更完整的正式解读。`

## 8.2 过程提示

当前建议：

- `请稍等片刻，马上带你进入结果页。`

## 8.3 语气重点

`Pro` loading 页更适合强调：

1. 完整
2. 清楚
3. 更正式一些，但不要高压

## 9. Lite 与 Pro 的差异应该怎么控制

当前建议两者差异只体现在：

1. 主文案重心不同
2. 所选报告标签不同

当前不建议：

1. 整个页面视觉结构完全不同
2. `Pro` 文案明显更重，像另一种产品
3. `Lite` 文案明显更弱，像免费占位页

## 10. 页面不该写什么

loading 页当前不应出现：

1. `升级到 Pro`
2. `进入 Journey`
3. `开始 AI 对话`
4. `保存报告`
5. 任何结果页 CTA

原因是：

1. 当前任务是完成等待承接
2. 用户还没有真正进入结果页
3. 太早出现动作会打断生成体验

## 11. 跳转规则

当前建议跳转规则明确为：

1. 用户在选择页点 `Lite`
   - 进入 `Lite` loading
   - 生成完成后直接进入 `Lite` 结果页
2. 用户在选择页点 `Pro`
   - 进入 `Pro` loading
   - 生成完成后直接进入 `Pro` 结果页

当前不建议：

1. loading 完成后再插入一层确认
2. 先跳到中间页再跳结果页
3. 在 loading 页让用户重新做选择

## 12. 当前最需要避免的写法

当前最需要避免下面 8 种情况：

1. loading 页像空白占位页
2. 文案太技术化
3. 文案太像营销页
4. 用户看不出自己现在在等 `Lite` 还是 `Pro`
5. loading 页提前出现结果页 CTA
6. 把等待文案写成高压心理分析
7. 让用户误以为还要再做一次选择
8. 加入未来产品模块入口

## 13. 当前阶段建议文案底稿

## 13.1 Lite

顶部状态：

- `正在生成解读`

标签：

- `Lite 解读`

主文案：

- `我们正在为你整理这次画里最明显的状态。`

过程提示：

- `很快就好，请稍等片刻。`

## 13.2 Pro

顶部状态：

- `正在生成解读`

标签：

- `Pro 解读`

主文案：

- `我们正在把这次画里的状态、线索和现实连接整理成一份完整解读。`

过程提示：

- `请稍等片刻，马上带你进入结果页。`

## 14. 当前阶段收束结论

基于以上定义，当前建议先收束到下面 5 个判断：

1. loading 页的任务是承接等待，不是继续分流
2. `Lite` 和 `Pro` loading 页都必须明确所选报告层级
3. 两者差异只需要轻度体现，不应分裂成两套产品
4. 生成完成后应直接进入对应结果页
5. 后续选择页、loading 页与结果页文案，都应回到这份文档统一校验
