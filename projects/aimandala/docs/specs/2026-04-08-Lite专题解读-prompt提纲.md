## 1. 目的

本文件用于定义 `Lite / 专题解读` 的 prompt 提纲。

它重点回答：

1. 这一版如何围绕主题生成
2. 主题如何真正改变正文
3. 怎样保持 `Lite` 的轻量感，而不滑向 `Pro / 专题解读`

## 2. 这份 Prompt 要完成什么

`Lite / 专题解读` 要生成的是：

- 一份围绕用户已选主题展开、但仍然保持低压风格的单次正式解读

它最核心要完成的 4 件事是：

1. 先说中这个主题下的当前感受
2. 说明画面为什么会指向这个主题
3. 轻轻解释该主题里的当前影响
4. 给一个围绕该主题成立的低压下一步

## 3. 输入优先级

当前建议 prompt 按下面顺序使用输入：

1. `主题`
   - 这是这版成立的前提输入
2. `画作本身`
   - 仍是主要证据来源
3. `绘画前意图`
   - 用于判断用户为什么会带着这个问题进入
4. `绘画过程中的感受`
   - 用于补强当前主题下的状态判断

## 4. 生成目标

prompt 应明确要求模型输出下面 6 段内容：

1. `标题`
2. `主题命中开头`
3. `画面为何指向这个主题`
4. `该主题下的当前状态解释`
5. `该主题里的现实连接`
6. `一个围绕该主题的低压下一步`

## 5. 每段生成要求

## 5.1 标题

要求：

1. 要带出明确主题感
2. 不要太泛
3. 仍保持 `Lite` 的轻量感

## 5.2 主题命中开头

要求：

1. 第一段就带出主题
2. 要让用户感觉“这份报告真的是在说我现在最在意的这个方向”
3. 不要写成泛通用开场

## 5.3 画面为何指向这个主题

要求：

1. 必须说明为什么是这个主题，而不是别的主题
2. 至少给出 `2-3` 个关键画面锚点
3. 解释链只需做到主题成立，不要进入问题闭环深挖

## 5.4 该主题下的当前状态解释

要求：

1. 说明用户在这个主题里现在正经历什么
2. 必须至少吃进：
   - `绘画前意图`
   - 或 `绘画过程中的感受`
3. 不上升到深层模式分析

## 5.5 该主题里的现实连接

要求：

1. 至少落一个该主题的现实场景
2. 要具体，但保持轻
3. 不要写成完整问题分析报告

## 5.6 一个围绕该主题的低压下一步

要求：

1. 只给一个主动作
2. 动作要贴合该主题
3. 不要突然升级成 `主题方案`

## 6. 语气要求

prompt 应明确要求生成语气满足下面 5 条：

1. 有主题感，但不高压
2. 更聚焦，但不沉重
3. 有依据，但不技术化
4. 有理解感，但不训导
5. 有方向，但不推进过度

## 7. 明确禁止项

prompt 应明确禁止下面写法：

1. 标题带主题，正文还是通用文
2. 写成缩短版 `Pro / 专题解读`
3. 对主题做过深机制拆解
4. 假装已经能解释反复闭环
5. 一次给多个动作或方案

## 8. 推荐 Prompt 骨架

当前建议 prompt 可按下面顺序组织指令：

1. `角色定义`
   - 你要生成的是一份 `Lite / 专题解读`
2. `任务定义`
   - 围绕用户已选主题，先低压地看清当前状态
3. `输入说明`
   - 主题、画作、意图、过程感受
4. `输出结构`
   - 标题、主题命中、依据、解释、连接、下一步
5. `语气要求`
6. `禁止项`
7. `输出前自检`

## 9. 输出前自检

prompt 末尾建议加上下面 6 条自检要求：

1. 开头是否明确带出主题
2. 是否解释了为什么画面会指向这个主题
3. 是否写清该主题下的当前状态
4. 是否落到了一个主题相关的现实场景
5. 是否没有越界写成 `Pro / 专题解读`
6. 是否只保留了一个围绕该主题的低压动作

## 10. 当前阶段收束结论

基于以上提纲，当前建议先收束到下面 4 个判断：

1. `Lite / 专题解读` 的核心不是把问题讲透，而是先在这个主题里把用户接住
2. 主题必须进入开头、依据、现实连接和下一步
3. 这版 prompt 的成功标准，是“聚焦但不沉重”
4. 它必须和 `Lite / 全面解读` 拉开正文重心，但仍保持同一商品层风格
