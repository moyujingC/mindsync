## 1. 核心判断

本轮固定采用以下判断：

1. `Lite` 和 `Pro` 是两个独立 SKU，不是升级关系。
2. 用户先买 `Lite`，后续再买 `Pro`，仍按独立购买语义处理。
3. `Lite` 必须是独立闭环的轻量完整解读，不得写成 `Pro` 的前半段。
4. `Pro` 必须是另一份独立成立的深度完整解读，不得只是 `Lite` 扩写稿。

## 2. Lite 的产品定位

`Lite` 定义为：

- 轻量完整解读

它的任务是：

1. 快速识别当前状态
2. 命名主要模式
3. 建立现实连接
4. 给出低压、即时、可执行的下一步

`Lite` 必须包含：

1. 当前整体命中
2. 画面依据
3. 状态解释
4. 模式命名
5. 现实连接
6. 轻量疗愈区块
7. `Pro` 独立产品入口

`Lite` 不得包含：

1. 阶段化疗愈方案
2. 完整根因链
3. 大段主题深读
4. “升级补全”语义

## 3. Pro 的产品定位

`Pro` 定义为：

- 深度完整解读

它的任务是：

1. 重新完成一次更深的正式解读
2. 提供更强的证据展开
3. 解释核心矛盾、失衡和根因链
4. 给出完整疗愈方案

`Pro` 必须包含：

1. 深度第一印象
2. 证据摘要与结构展开
3. 核心矛盾 / 失衡确认
4. 根因链
5. 主题深读
6. 完整疗愈建议

`Pro` 不得：

1. 只是复述 `Lite`
2. 只在篇幅上更长
3. 只靠语气更重制造“更高级”感

## 4. Lite / Pro 疗愈边界

### 4.1 Lite 疗愈

`Lite` 允许提供疗愈建议，但只能是：

1. 轻量
2. 即时
3. 低压
4. 非阶段化

正式结构固定为：

- `lite_healing_guidance`
  - `directions: 2-3`
  - `micro_practices: 2-3`

内容要求：

1. 只提供轻量调节方向
2. 只提供短小可执行练习
3. 不写成长程疗程
4. 不和 `Pro` 的完整疗愈方案重复

### 4.2 Pro 疗愈

`Pro` 中的 `healing_suggestions` 固定为完整疗愈方案。

默认要求：

1. 3 条建议
2. 每条建议都与主题、失衡或根因解释链对应
3. 明显深于 `Lite`

## 5. Pro 入口语义

`Lite` 中保留 `Pro` 入口，但固定按独立产品语义表达。

正式字段固定为：

- `pro_report_entry`
  - `title`
  - `summary`
  - `product_note`

禁止语义：

1. 升级版
2. 补全版
3. 解锁完整版
4. 补差价继续看

允许语义：

1. 另一份更深的独立报告
2. 如果你希望从更深层结构继续理解这张画
3. `Pro` 会提供更完整的结构、根因与疗愈视角

## 6. 对合同和页面的影响

本定义将直接影响：

1. `LiteStructuredReport`
2. `ProStructuredReport`
3. `report_contracts`
4. `mobile-web / shared-ui` 的 Lite 页面渲染
5. Lite 结果页与 `Pro` 入口文案

默认要求：

1. `experiment_rendered` 不再作为 Lite 疗愈的 canonical 字段
2. `pro_teaser` 不再作为正式字段名
3. `can_upgrade / upgrade_price` 只保留兼容语义，不再作为产品定义依据

## 7. 验收判断

本定义落地后，至少应满足：

1. 文档中明确写出 `Lite / Pro` 为独立产品
2. `Lite` 有独立轻疗愈区块
3. `Pro` 有明显更深的疗愈建议
4. Lite 页面中的 `Pro` 入口不再带升级语义
5. 固定样本中，`Lite` 和 `Pro` 的疗愈层次可以被稳定拉开
