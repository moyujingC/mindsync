## 1. 目的

本 spec 在“用户分群与产品矩阵决策”基础上，进一步明确：

1. 每类产品主要服务谁
2. 每类产品的核心卖点是什么
3. 每类产品当前最小可交付单元（MDU, Minimum Deliverable Unit）是什么

这里不直接定义最终定价，也不预设 `Lite / Pro` 为最终唯一产品结构。

## 2. 使用原则

后续若要继续定义：

- UI 页面
- 内容结构
- 活动运营
- 增长路径
- 商业化方案

应优先回到本文件确认：

1. 这个产品到底服务谁
2. 它的主价值是什么
3. 它的最小版本先交什么，而不是一开始什么都想做

## 3. 产品总览

| 产品 | 类型 | 主用户 | 主价值 | 当前优先级 |
|---|---|---|---|---|
| 账号内容 | 内容产品 | 审美探索型 / 情绪安放型 / 自我理解型 | 建立信任、教育用户、引流 | 高 |
| 陪你画 / 共修营 | 陪伴产品 | 审美探索型 / 情绪安放型 / 创作驱动用户 | 陪伴进入创作过程 | 高 |
| 报告 | 解读产品 | 自我理解型 / 议题解决型 | 看懂自己、命名状态、解释模式 | 最高 |
| 主题方案 | 标准化成长产品 | 议题解决型 / 被改变型用户 | 围绕问题开始改变 | 中 |
| 21天定制方案 | 个体化成长产品 | 成长深化型 / 高意愿持续用户 | 个体路径与连续推进 | 中低 |

## 4. 各产品定义

## 4.1 账号内容

### 目标用户

- 审美探索型
- 情绪安放型中的轻中度用户
- 自我理解型中的初次接触用户

### 用户进入时的典型心理

- “这是什么，看起来很特别。”
- “我最近状态不太好，想看看会不会有点帮助。”
- “我对曼陀罗有兴趣，但还不知道能不能真的看见自己。”

### 核心卖点

1. 让用户相信你们有方法，不是随机生成漂亮话术
2. 让用户理解曼陀罗与“纯占卜 / 纯星座解释”不同
3. 让用户低门槛地先获得一点被看见、被启发的体验
4. 为后续产品分流：报告、陪你画、主题方案

### 不负责

- 完整个体价值交付
- 深度个体化分析
- 长周期陪伴

### 当前最小交付单元（MDU）

1. 一个持续更新的内容账号
2. 三类稳定内容栏目
   - 方法认知类：曼陀罗怎么看、为什么值得信
   - 共鸣启发类：状态、关系、情绪、节气内容
   - 产品导流类：引导进入画、报告、活动
3. 每条内容都应明确指向一个后续动作
   - 去画
   - 去看报告
   - 去报名活动

### 当前判断

账号内容不是附属运营物料，而是产品入口本身。

## 4.2 陪你画 / 共修营

### 目标用户

- 审美探索型
- 情绪安放型
- 因为喜欢曼陀罗创作而进入的用户

### 用户进入时的典型心理

- “我想画，但想有人陪着我一起进入状态。”
- “我想感受一下，不一定先看分析。”
- “我喜欢这种仪式感和一起做点什么的感觉。”

### 核心卖点

1. 曼陀罗产品区别于泛解读产品的独特入口
2. 让“画”本身成为价值，不只是解读前置
3. 提供陪伴感、场域感、参与感
4. 适合做节气、节日、主题共修活动

### 不负责

- 深度个体解读
- 高密度问题解决
- 个体化连续改变路径

### 当前最小交付单元（MDU）

1. App 内一个活动报名入口
2. 微信群承接的单次或短周期活动
3. 一套最小活动结构
   - 活动说明
   - 画前引导
   - 集中绘制时间
   - 画后轻分享
   - 后续可选进入报告或方案
4. 第一批活动优先选高共鸣主题
   - 二十四节气共修
   - 节日前共修
   - 月度主题共画

### 当前判断

`陪你画` 是独立产品，不只是运营活动。

## 4.3 报告

### 目标用户

- 自我理解型
- 议题解决型
- 部分情绪安放型用户

### 用户进入时的典型心理

- “我想知道这张画在说什么。”
- “我想知道我现在到底处在什么状态。”
- “我为什么总是这样，我想看得更清楚一点。”

### 核心卖点

1. 让用户觉得“这份内容真的在说我”
2. 基于画作提供专属性解释，而不是泛内容安慰
3. 把情绪、结构、模式、现实场景连接起来
4. 让用户完成从“模糊”到“明白”的跨越

### 不负责

- 长周期训练
- 连续 program
- 高复杂度专业承接

### 当前最小交付单元（MDU）

1. 一条完整报告主线
   - 上传 / 画作确认
   - 报告生成
   - 报告阅读
2. 报告最小内容结构
   - 整体印象
   - 画面元素解释
   - 情绪/状态命名
   - 模式或议题拆解
   - 一个轻量可执行建议
3. 报告结果页支持后续动作
   - 进入主题方案
   - 进入 21 天定制方案
   - 或返回参与活动/继续陪伴

### 当前判断

报告是第一阶段最重要的核心付费产品，也是整个产品矩阵的理解中枢。

## 4.4 主题方案

### 目标用户

- 议题解决型
- 已经明确知道自己卡在哪的用户
- 从报告里读完后明确想继续行动的用户

### 用户进入时的典型心理

- “我不是只想懂，我想围绕这个问题开始调整。”
- “我最想改善的是关系/边界/表达/情绪稳定。”
- “我想要有步骤、有节奏，而不是只看一份分析。”

### 核心卖点

1. 围绕一个明确主题组织行动路径
2. 比报告更能帮助用户开始改变
3. 比 21 天定制方案更标准化、更轻、更容易规模化
4. 同一主题可以做成 App 自助版，也可以做成社群活动版

### 不负责

- 完整个体画像
- 高度个体化路径排序
- 复杂案例处理

### 当前最小交付单元（MDU）

1. 一个高需求主题的标准化方案
2. 方案最小结构
   - 主题说明
   - 适用用户
   - 7-14 天节奏设计
   - 每日/每阶段练习
   - 复盘问题
3. 一种主题先做两种承接形态中的一种
   - App 自助版
   - 活动社群版

建议首批主题从用户最容易共鸣的问题开始：

- 关系边界
- 情绪稳定
- 自我价值

### 当前判断

主题方案是连接“理解”与“改变”的中间层产品。

## 4.5 21天定制方案

### 目标用户

- 成长深化型
- 已对产品建立信任的高意愿用户
- 想进入持续改变过程的用户

### 用户进入时的典型心理

- “我不只想知道问题，我想系统推进。”
- “我想要一份更像是为我准备的节奏和路径。”
- “我愿意连续投入 21 天，看看自己会发生什么变化。”

### 核心卖点

1. 更强个体化
2. 更强连续性
3. 更强进展感与陪伴感
4. 不只是给练习，而是帮助用户排序优先级

### 不负责

- 高风险危机支持
- 专业治疗替代
- 所有用户的第一入口

### 当前最小交付单元（MDU）

1. 一套 21 天结构框架
   - 起始评估
   - 三阶段推进
   - 每日/隔日任务
   - 周期复盘
2. 一套最小定制变量
   - 用户当前主题
   - 报告结论
   - 近期对话重点
   - 当前优先卡点
3. 一个可被 AI 持续跟进的最小陪伴机制
   - 每日提醒
   - 任务反馈
   - 阶段总结

### 当前判断

21 天定制方案不应作为所有人的首产品，而应作为高价值承接层。

## 5. 跨产品关系

## 5.1 当前推荐关系

| 前一产品 | 可导向的后一产品 | 推荐强度 |
|---|---|---|
| 账号内容 | 陪你画 / 报告 / 主题方案 | 高 |
| 陪你画 / 共修营 | 报告 / 主题方案 | 高 |
| 报告 | 主题方案 / 21天定制方案 | 高 |
| 主题方案 | 21天定制方案 | 中高 |

## 5.2 当前不建议的关系

当前不建议默认把全部用户都直接推进：

- `账号内容 -> 21天定制方案`
- `陪你画 -> 21天定制方案`

原因：

- 信任还不够
- 理解基础不足
- 用户心智不稳定

## 6. 当前阶段建议

### 6.1 第一阶段重点验证的三个产品

1. 账号内容
2. 报告
3. 陪你画 / 小型共修活动

### 6.2 第二阶段再扩展

4. 主题方案

### 6.3 第三阶段建立高阶承接

5. 21天定制方案
