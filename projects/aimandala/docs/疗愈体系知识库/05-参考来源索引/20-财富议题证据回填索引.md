本文定义财富议题的证据回填方式。

> **说明**：结构化 YAML 单元层已废弃。当前证据管理直接在 Markdown 中进行。

证据关系记录格式：

```yaml
evidence_id:
clause_id:
source_id:
source_path:
source_location:
evidence_type:
support_level:
summary:
supported_part:
status:
notes:
```

## 1. 当前条款

当前财富议题有 7 条模型脚手架条款：

- `wealth.low_deservingness`：配得感不足。
- `wealth.scarcity_and_insecurity`：匮乏感和安全感不足。
- `wealth.approval_driven_earning`：求认可式赚钱。
- `wealth.emotional_spending`：情绪型漏财。
- `wealth.low_capacity`：承载力不足。
- `wealth.low_action`：行动力不足。
- `wealth.low_world_connection`：与世界链接不足。

这些条款仍是 `model_scaffold`，不能当作已经由电子书或跨来源验证得出的结论。

## 2. 证据关系长表

每条证据关系应单独记录，不增加矩阵列。

最小字段：

```yaml
evidence_id:
clause_id:
source_id:
source_path:
source_location:
evidence_type:
support_level:
summary:
supported_part:
status:
notes:
```

## 3. 字段说明

`evidence_type` 可选：

- `supports_concept`：来源支持这个概念或相近机制。
- `supports_expression`：来源支持报告表达方式或用户语言。
- `supports_practice`：来源支持对应疗愈方向或练习。
- `contradicts`：来源与条款存在明显冲突。
- `not_applicable`：来源主题不相关。

`support_level` 可选：

- `direct`：直接支持。
- `partial`：部分支持。
- `weak`：弱相关，只能作为启发。
- `conflict`：冲突。

`status` 可选：

- `draft`：已记录，未审阅。
- `reviewed`：已审阅。
- `accepted`：可用于升级条款来源状态。
- `rejected`：不纳入支持关系。

## 4. 来源登记

来源本体不写在横向矩阵里，应来自来源登记或研究母库路径。

优先回填来源：

- `projects/research-center/kb/sources/healing/对财富说是`
- `projects/research-center/kb/sources/healing/ACT就这么简单`
- `projects/research-center/kb/sources/healing/心理自助CBT书系`
- `projects/research-center/kb/sources/healing/创伤与复原`
- `projects/research-center/kb/sources/healing/格式塔心理咨询理论与实践`
- `projects/research-center/kb/sources/healing/谁在我家`

## 5. 升级规则

- 单一来源支持后，条款可从 `model_scaffold` 升为 `source_supported`，但必须写清支持的是概念、表达还是练习。
- 两个以上不同来源支持，且不存在明显冲突时，才可考虑升为 `cross_source_validated`。
- 如果只是同一作者或同一流派内部重复表达，不得升级为跨来源验证。
