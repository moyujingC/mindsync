## 1. 使用总原则

这批源资料很重要，但当前不能把整批原文无差别地当成正式规则入口。

当前报告生成方法的唯一入口是 [三圈五行流派解读方法与步骤.md](三圈五行流派解读方法与步骤.md)。报告生成必须保留 `stage-00-input-context` 到 `stage-16-final-report` 的中间交付物。旧报告链路只属于归档和历史样本语境，不再作为当前方法依据或默认运行路径。

默认规则是：

- 只有本文件中标到 `A. 单一真值源 / 当前正式依据` 的资料，才允许被当前 `specs`、`architecture`、运行时映射文档直接引用
- `B. 支撑参考资料` 只用于理论说明、设计支撑和思路对照
- `C. 历史评估 / 比较样本` 只作历史证据、质量样本和对比材料，不直接定义当前实现
- `D. 运行时投影` 只作为系统消费格式，不反向替代 Markdown 真值源

## 5. D. 运行时投影

下列文件是运行时消费格式，不是原始真值源：

- `projects/aimandala/toC/data/knowledge/packs/v2.2/`
  - 来源：本目录当前 Markdown 真值源，其中主题、疗愈和叙事资产来自 [主题知识](主题知识)。
  - 用途：作为 Markdown 真值源到运行时消费格式的 v2.2 投影候选。
- `projects/aimandala/toC/data/knowledge/packs/v2.1/`
  - 来源：旧 V2 Python runtime 投影。
  - 用途：旧兼容投影。除非处理兼容性问题，不应把它当作当前知识整理目标。
- `projects/aimandala/toC/data/knowledge/builds/current/index.json`
  - 当前仍指向 `aimandala-v2.1`。
  - 用途：当前后端读取的编译后运行时索引；切换到 v2.2 需另做运行时替换和回归验证。

运行时投影可以用于系统读取，但当投影与 Markdown 真值源冲突时，以 Markdown 真值源为准，并重新生成投影。

## 8. 与现有正式文档的分工

这批资料的分工应固定为：

- 本目录
  - 回答“知识源资料是什么、怎么分层、哪些可以直接引用”
- 本目录的 Markdown 真值源
  - 回答“当前报告生成应该遵循什么流派方法和知识规则”
- `projects/aimandala/toC/data/knowledge/`
  - 保存当前真正被运行时消费的 `pack + build` 资产

也就是说：

- 源资料不直接等于运行时 pack
- pack 也不反向代替源资料的流派出处

## 9. 默认引用方式

如果后续文档需要引用这批资料，默认应：

1. 先引用 [README.md](README.md)
2. 再引用本文件
3. 最后才引用具体原始资料文件

不要继续依赖旧仓库外部路径来理解这批知识来源。
