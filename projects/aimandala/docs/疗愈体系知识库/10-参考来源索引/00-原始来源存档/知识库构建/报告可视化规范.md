# 报告可视化规范

> 状态：current
> 日期：2026-05-09
> owner：Product / Knowledge Base
> source_of_truth：`projects/aimandala/docs/疗愈体系知识库/10-参考来源索引/00-原始来源存档/知识库构建/报告可视化规范.md`
> 适用步骤：`stage-13-lite-draft`、`stage-14-pro-draft`

## 目标

报告中的可视化模块用于帮助用户理解解读逻辑、增强疗愈体验和提升付费价值感。

可视化不是重新解读，也不是装饰图。每张图都必须服务于已有 stage 结果，把画面依据、能量流动、根因链或调节路径转成更容易理解的视觉表达。

## 共同原则

- 图片只视觉化已有结论，不新增象征含义。
- 图片 prompt 必须来自 `stage-09` 到 `stage-14` 的结构化数据。
- 图片不替代原始曼陀罗画作，也不作为新的画面依据。
- 图片文案要短，重点是帮助理解，不把报告正文搬进图里。
- 图片风格应有疗愈感：温和、清透、有呼吸感，不制造压迫或恐吓。
- 如果某张图的输入证据不足，应降级为文字说明或跳过，不强行生成。

## Lite 可视化

Lite 固定 2 张图。

### 1. 画面依据摘要图

用途：帮助用户快速理解 AI 是从哪些可见画面依据进入解读。

输入来源：

- `stage-03-visual-evidence`
- `stage-09-evidence-consolidation`
- `stage-11-user-facing-framing.visual_basis_candidates`
- `stage-13-lite-draft.visual_basis`

内容建议：

- 三圈结构简图。
- 3 到 5 条关键可见依据。
- 当前核心状态的一句话摘要。

不做内容：

- 不重新绘制用户原画。
- 不新增原画中没有的符号。
- 不把心理结论伪装成画面事实。

### 2. 小步疗愈建议卡

用途：把 Lite 的低压行动建议做成用户可保存、可回看的卡片。

输入来源：

- `stage-12-healing-direction-and-report-branching.lite_writing_input.small_step_suggestion`
- `stage-13-lite-draft.sections`
- `stage-13-lite-draft.suggestion_boundaries`

内容建议：

- 一句温和提醒。
- 一个可执行小动作。
- 一个“今天可以先这样做”的入口。

不做内容：

- 不承诺疗效。
- 不写成任务清单。
- 不给用户制造必须立刻改变的压力。

## Pro 可视化

Pro 固定 4 张图。

### 1. 画面依据深度图

用途：展示三圈结构和关键证据分布，让用户理解 Pro 分析从哪里开始。

输入来源：

- `stage-03-visual-evidence`
- `stage-09-evidence-consolidation`
- `stage-11-user-facing-framing.visual_basis_candidates`
- `stage-14-pro-draft.visual_basis`

内容建议：

- 三圈结构。
- 每一圈的关键颜色、形状、留白或边界特征。
- 证据强弱提示。

### 2. 能量流动诊断图

用途：把内圈、中圈、外圈之间的顺畅、堵点、回流或跳跃可视化。

输入来源：

- `stage-08-energy-flow-diagnosis`
- `stage-10-core-thesis-selection`
- `stage-14-pro-draft.mechanism_summary`

内容建议：

- 内在意识、关系表达、外在行动三段式流动。
- 顺畅点、卡点、回流点或跳跃点。
- 一句能量流动摘要。

### 3. 根因链图

用途：把“画面证据 -> 状态机制 -> 现实主题”的解释链可视化。

输入来源：

- `stage-10-core-thesis-selection`
- `stage-12-healing-direction-and-report-branching.pro_writing_input.root_cause_chain`
- `stage-14-pro-draft.root_cause_chain`

内容建议：

- 2 到 4 层根因链。
- 每层用短句说明。
- 保留证据到现实主题的递进关系。

### 4. 阶段性调节路径图

用途：把 Pro 的调节建议整理成可执行路径。

输入来源：

- `stage-12-healing-direction-and-report-branching.pro_writing_input.phased_healing_plan`
- `stage-14-pro-draft.healing_plan`
- `stage-14-pro-draft.suggestion_boundaries`

内容建议：

- 短期稳定。
- 中期整理。
- 长期行动。
- 每阶段 1 到 2 个重点。

## 输出字段建议

报告草稿中应包含 `visual_modules` 字段。

每个可视化模块至少包含：

```json
{
  "id": "",
  "title": "",
  "placement": "",
  "purpose": "",
  "source_stage_refs": [],
  "image_prompt_brief": "",
  "caption": "",
  "fallback_text": ""
}
```

## 成本与生成策略

MVP 阶段建议：

- Lite 固定 2 张。
- Pro 固定 4 张。
- 优先使用中等成本文生图模型。
- 如果文生图失败，不阻断报告交付，使用 `fallback_text` 替代。

后续如果 Pro 需要增强价值感，可以扩展到 6 张图，再增加“五行力量平衡图”和“主题疗愈仪式卡”。
