## 1. 议题角色与概念边界

### 设计意图

17 个议题在知识库本体上并列，表示它们都可以被独立建设、补来源、做条款和做报告。

在具体报告运行时，每个议题会经历以下链路：

```
主议题选择
  → 浮现议题角色判断
  → 浮现机制归类（当画面证据还不够具体时）
  → 背景线索写法（进入报告正文）
  → 具体议题条款
  → 疗愈方向
  → 后续画面映射
```

**同一个议题可以在这条链路的不同位置出现**：在一份报告里作为主议题，在另一份报告里作为浮现议题，在第三份报告里仅以背景线索方式嵌入。

### 四个核心概念的边界

| 概念 | 性质 | 说明 |
|------|------|------|
| **主议题** | 运行时角色 | 用户主动选择的报告主题，回答”用户这次想看什么” |
| **浮现议题** | 运行时角色标签 | 画面分析或报告组织过程中浮现的深层结构，回答”这个主议题背后还牵动了什么” |
| **浮现机制** | 共享知识池 | 当画面证据还不足以落到具体议题本体时，先使用的通用解释机制 |
| **背景线索** | 报告正文呈现口径 | 浮现机制在主议题报告中的落地写法，进入用户可见正文 |

> 注：`浮现议题` 是运行时角色判断，`背景线索` 是报告写作口径——两者说的是同一条链路上的不同位置，前者偏角色判断，后者偏正文表达。`浮现机制` 是知识池，`背景线索` 是它在主议题报告中的落地写法。

## 4. 运行时使用方式

同一幅曼陀罗可以被不同主议题解读，但必须共享同一份画面事实。

```text
画面识别结果
  -> 主议题报告包
  -> 该主议题的翻译层
  -> 必要时调用浮现机制
  -> 以背景线索方式写入正文
  -> 必要时引用其他议题本体
```

如果画面只能显示“关系与交换边界”这类混沌线索，不应强行落到父亲关系、母亲关系或亲密关系。只有用户输入或画面证据足够明确时，才引用具体关系议题。
