# 主议题报告包模板

> 状态：draft
> 内容来源状态：template
> 来源验证状态：not_applicable
> 版本：0.1.0
> date：2026-05-26
> owner：CEO / Knowledge Base
> source_of_truth：当前目录/20-疗愈体系/10-议题层/30-主议题报告包/00-主议题报告包模板.md

本文定义新增主议题报告包时的最小结构。

财富议题可以作为结构示范，但不能把财富议题中的具体条款、案例反推或来源状态直接复制到其他议题。其他议题必须重新建立自己的本体、手册、翻译层、浮现议题回译和回归验证。

## 1. 适用范围

当一个议题要成为产品里的主报告入口时，应先建立主议题报告包。

适用对象包括：

- 亲密关系
- 家庭与原生家庭
- 自我价值
- 事业发展
- 情绪与安全感
- 其他后续可作为主报告入口的议题

不适用对象：

- 只作为财富报告里的浮现议题线索。
- 只用于下一次探索建议。
- 只有少量案例语言、没有稳定规则来源的议题。

## 2. 目录结构

新增主议题时，建议使用：

```text
<议题目录>/
  README.md
  10-<议题>议题翻译层/
    README.md
    01-基础信号<议题>翻译总表.md
    02-报告路由位置说明.md
    03-颜色<议题>翻译表.md
    04-形状<议题>翻译表.md
    05-跨圈状态<议题>翻译表.md
    06-组合模式<议题>翻译表.md
  11-<议题>议题手册.md
  12-<议题>中的浮现议题回译规则.md
  13-下一次探索建议映射表.md
  90-<议题>案例反推.md
```

如果某个文件暂时没有足够内容，可以先建空壳，但必须标注 `source_needed` 或 `source_verification_pending`。

## 3. 必填内容

每个主议题报告包至少要回答：

1. 这个议题作为主线时，内圈、中圈、外圈分别优先解释什么。
2. 哪些基础层信号可以进入该议题，哪些只能作为候选。
3. 多个信号同时出现时，如何判断主轴和辅助线索。
4. 其他议题浮现时，如何回译到当前主议题。
5. Lite 报告最多展开到什么深度。
6. Pro 报告如果未来开放，最多展开哪些机制。
7. 哪些表达禁止进入报告。
8. 下一次探索建议如何选择，不能如何制造焦虑。

## 4. 来源状态

每条规则都必须标注来源状态。

推荐状态：

- `source_verified`：多个来源交叉支持，并已完成审核。
- `source_supported_draft`：已有来源层材料部分支持，可用于初版报告，但仍需 review。
- `manual_reviewed`：人工审核过表达或规则，但不代表完成来源验证。
- `ai_draft`：用于搭建结构，不作为稳定规则来源。
- `source_needed`：报告需要该模块，但缺少足够来源。

案例反推只能用于：

- 语言样本。
- 弱例证。
- 边界提醒。
- 后续人工审核候选。

案例反推不能用于：

- 直接沉淀主轴规则。
- 生成强结论。
- 替代上游来源。
- 反推用户固定人格、家庭因果或现实结果。

## 5. 翻译层规则

翻译层必须遵守：

- 上游基础层负责识别画面事实。
- 主议题翻译层只负责把画面信号翻译成该议题语言。
- 单一信号不得生成强结论。
- 多个信号共同指向同一条款时，才可提高报告权重。
- 报告必须保留画面依据。
- 不能把议题翻译写成现实预测、医学判断、心理诊断或人生定论。

每条翻译建议包含：

```text
基础信号
基础状态含义
主议题翻译
报告模块位置
可说表达
不可说表达
追问句
来源状态
```

## 6. 浮现议题回译

每个主议题都要定义其他议题如何进入本报告。

推荐结构：

```text
primary_topic -> emergent_topic -> translation_role -> allowed_depth -> translated_mechanisms
```

深度分级：

- `hint`：只点一句，不展开。
- `brief`：一小段解释其主议题含义。
- `supporting_mechanism`：进入机制拆解，但仍回到主线。

默认限制：

- Lite 最多到 `brief`。
- Pro 最多 2 个 `supporting_mechanism`。
- 浮现议题不能替代主线。

## 7. 报告生成要求

主议题报告包进入运行时前，至少要有：

- 一个 Lite prompt。
- 一个 Pro prompt 预留入口，即使 Pro 暂不上线。
- 明确的安全边界。
- 至少一组固定样本或完整案例回归。
- 质量门说明。

质量门至少覆盖：

- 是否锚定当前主议题。
- 是否泄漏内部字段、阶段名或质量门信息。
- 是否输出禁止表达。
- 是否把其他议题展开成主报告。
- 是否保留画面依据。

## 8. MVP 可用标准

一个主议题报告包达到 MVP 可用，不等于达到成熟理论。

MVP 可用至少要求：

1. Lite 能生成完整报告。
2. 主要目录结构齐全。
3. 主次判断规则明确。
4. 安全边界明确。
5. 至少一轮回归样本可追溯。
6. 失败样本和质量门问题被记录。
7. 所有来源状态清楚标注。

如果仍有大量 `ai_draft` 或 `source_needed`，可以作为产品试运行材料，但不能标成 `source_verified`。

## 9. 从财富议题复制什么

可以复制：

- 目录结构。
- 主次判断方式。
- 翻译层字段。
- 浮现议题回译深度。
- Lite / Pro prompt 分层。
- 质量门与回归记录方式。

不能复制：

- 财富条款内容。
- 财富案例反推规则。
- 财富来源状态。
- 财富报告里的主轴候选。
- 小样本案例得出的稳定判断。
