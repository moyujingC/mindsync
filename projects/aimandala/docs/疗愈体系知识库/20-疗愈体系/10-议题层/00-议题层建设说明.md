本文定义疗愈体系知识库议题层的建设方式。

## 0. 议题层元数据标签

所有议题层文档都必须使用同一套元数据字段，避免财富、关系、家庭、身体等议题后续各自形成不同口径。

标准字段：

| 字段 | 含义 | 常用取值 |
|------|------|----------|
| 状态 | 文档生命周期，不等于内容证据强度。 | `draft`、`reviewing`、`stable` |
| 内容来源状态 | 当前内容主要来自哪里。 | `ai_draft`、`case_reverse`、`manual_reviewed`、`source_supported_draft`、`mixed` |
| 来源验证状态 | 是否已经完成来源回填和交叉验证。 | `source_verification_pending`、`partially_source_verified`、`source_verified` |

取值说明：

- `ai_draft`：由大模型先搭框架或补内容，尚未完成来源验证。
- `case_reverse`：从案例中反推，适合做候选规则，不应直接泛化为完整议题共识。
- `manual_reviewed`：已由人工审核过表达或规则，但不代表完成跨来源验证。
- `source_supported_draft`：已有来源材料支撑初版表达，但仍处于草稿。
- `mixed`：同一文档混合了 AI 草拟、案例反推、人工审核或部分来源支持。
- `source_verification_pending`：尚未完成电子书、案例和流派材料的逐条回填验证。
- `partially_source_verified`：已有部分条目完成来源验证，但整份文档还未闭环。
- `source_verified`：主要条目已完成来源回填、人工审核和必要的跨来源对照。

财富议题也使用这套字段。当前财富议题不是纯 `ai_draft`，因为其中已经混合了案例反推、人工审核规则和部分来源支持；所以财富主文档通常标为 `mixed + source_verification_pending`，其中单条结构化条款可继续细分为 `ai_draft`、`case_reverse` 或 `source_supported_draft`。

## 1. 议题层定位

议题层不是从画面特征直接归纳出来的结论集合。

议题层应先独立建立每个疗愈议题的完整知识框架，再由流派层和应用适配层把画面信息对应到议题条款上。

也就是说，建设顺序应是：

1. 先建立议题本身的框架体系。
2. 再补充议题下的典型卡点、心理机制、疗愈目标和行动方案。
3. 再整理案例、培训材料和流派资料作为内容来源。
4. 最后建立画面特征到议题条款的映射关系。

## 2. 为什么不能只靠 11 个案例

11 个原始解读案例很有价值，但它们只是少量一线案例样本。

它们适合用于：

- 学习疗愈师如何组织报告。
- 学习案例中的判断语言和调整方案。
- 观察部分财富、成长、情感议题的高频表达。
- 校验疗愈体系知识库是否能支撑实际报告生成。

它们不适合直接作为：

- 某个议题的完整体系。
- 某个议题的全部卡点来源。
- 某个议题的唯一知识依据。
- 画面特征和议题条款之间的最终映射表。

## 3. 议题层的推荐结构

每个议题建议按以下结构建设：

1. 议题定义。
2. 议题范围。
3. 核心心理机制。
4. 常见卡点。
5. 深层来源。
6. 正向状态。
7. 疗愈目标。
8. 疗愈路径。
9. 可生成的报告条款。
10. 可生成的追问回答方向。
11. 可生成的定制化疗愈方案。
12. 后续画面映射入口。

## 4. 议题角色

本知识库的议题本体保持并列，但在具体报告里会分配不同角色：

1. 用户主动选择的主议题。
2. 解读过程中浮现出来的议题。
3. 尚未具体到某个议题本体时使用的浮现机制。

这三类不是目录高低关系，而是运行时标签。同一个议题可以在一份报告里作为主议题，在另一份报告里作为浮现议题。

### 4.1 主议题

主议题是用户在下单、提问或填写意图时容易直接说出来的主题。

例如：

- 财富。
- 事业 / 发展。
- 亲密关系。
- 父亲关系。
- 母亲关系。
- 亲子关系。
- 健康 / 身体。

这类议题适合作为产品入口和报告主线。它回答的是：“用户这次想看什么？”

### 4.2 浮现议题

浮现议题不一定是用户一开始会主动说出来的主题，而是在画面分析、报告组织或追问过程中逐渐显露出来的深层结构。

例如：

- 自我价值。
- 配得感。
- 安全感。
- 匮乏感。
- 内在小孩。
- 家庭系统脚本。
- 情绪能量。
- 防御模式。
- 边界感。
- 行动力。
- 与世界的链接。

这类议题适合作为报告中的解释层、追问回答依据和疗愈方案入口。它回答的是：“这个主议题背后还牵动了什么？”

在当前体系里，`浮现议题` 是上位运行时标签，`背景线索` 是更贴近报告写作的呈现口径。两者说的是同一条链上的不同位置：前者偏角色判断，后者偏正文表达。

### 4.3 浮现机制

浮现机制用于处理更混沌的中间状态。

例如财富报告中，中圈出现缠绕、切分、留白、红色外放时，画面通常只能说明“关系、交换、情绪和资源边界有线索”，不能直接判断为父亲关系、母亲关系或亲密关系。

这种情况下，应先使用：

- 关系与交换边界。
- 情绪能量与消耗。
- 安全感与匮乏感。
- 家庭系统脚本。

只有用户输入或画面证据足够明确时，才进一步引用具体议题本体。

`浮现机制` 和 `背景线索` 也不是两套并列体系。浮现机制更像共享知识池，背景线索更像它在主议题报告中的落地写法。

### 4.4 三者关系

一个主议题下面，通常会牵出多个浮现议题、浮现机制和背景线索。

例如用户选择“财富”时，实际解读中可能浮现：

- 配得感不足。
- 安全感不足。
- 原生家庭金钱脚本。
- 求认可式赚钱。
- 情绪型漏财。
- 承载力不足。
- 与世界链接不足。

因此，知识库建设议题时，应采用：

```text
主议题
  → 浮现机制 / 浮现议题
  → 背景线索写法
  → 具体议题条款
  → 疗愈方向
  → 后续画面映射
```

这样做可以同时满足两个需求：

- 产品上，用户有清晰入口。
- 解读上，AI 能进入更深层的心理和疗愈结构。

## 5. 首个试点议题

建议 首个完整试点议题选择“财富”。

原因：

- 财富是用户容易主动选择的议题，产品入口清晰。
- 现有 11 个案例中已经出现较多财富、配得感、行动力、自我价值、世界链接相关表达，可用于校验报告语言。
- 财富议题天然会牵出多个浮现议题，适合验证“用户主动议题 → 深层浮现议题 → 具体条款 → 疗愈方案”的结构。
- 财富议题需要避免简单写成“赚钱建议”，能逼迫知识库同时处理安全感、价值感、家庭脚本、行动力和承载力。

财富议题的建设方式应是：

```text
财富主议题
  → 配得感 / 安全感 / 自我价值 / 家庭脚本 / 行动力 / 承载力
  → 具体条款
  → 报告表达
  → 追问回答
  → 疗愈方案
  → 画面映射
```

## 6. 内容来源要求

完整议题应优先吸收：

- 心理学流派材料。
- 疗愈流派培训材料。
- 家庭系统、内在小孩、创伤疗愈、完形、萨提亚、荣格等相关资料。
- 金钱关系、亲密关系、事业发展、身体议题等专题材料。
- 已有案例中的一线表达和调整方案。

使用案例时，需要标注它是案例反推，不应把少量案例泛化成整个议题。

## 7. 与画面层的关系

议题层先回答：

- 这个议题本身有哪些结构？
- 用户在这个议题上可能卡在哪里？
- 每个卡点背后可能是什么心理机制？
- 这个卡点如何被疗愈和转化？

画面层和映射层后续再回答：

- 哪些颜色、形状、圈层、五行关系可能指向这些卡点？
- 哪些画面特征可以作为某个议题条款的证据？
- 哪些画面信息只能作为弱信号，不能单独下结论？

这样可以避免先被少量画面案例牵着走，也能避免把案例中出现过的内容误认为完整知识体系。

## 8. 议题翻译层

每个主议题报告包都可以建立翻译层，用来承接基础层信号。

翻译层的职责是：

- 把基础层信号翻译成当前议题语言。
- 指定对应的议题条款和报告位置。
- 写清楚表达边界。
- 标注哪些翻译已经稳定，哪些仍需来源回填或人工审核。

财富议题试点见 [30-主议题报告包/10-财富/10-财富议题翻译层/README.md](30-主议题报告包/10-财富/10-财富议题翻译层/README.md)。
