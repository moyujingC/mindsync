## 双重角色设计

同一议题可以同时存在于议题本体和浮现机制中，各有不同的使用场景：

| | 议题本体 | 浮现机制（背景线索） |
|---|---|---|
| **定位** | 完整议题知识 | 当它作为背景线索嵌入其他主议题时的翻译指南 |
| **使用场景** | 用户选择该议题为主议题时 | 该议题作为其他主议题的背景线索时 |
| **内容重心** | 议题范围、常见卡点、疗愈方向 | 通用画面识别规则、表达原则 |
| **主议题特定翻译** | 无 | 交给各主议题的翻译层 |

**角色元数据说明**：

- `用户入口角色`：描述议题在用户端的呈现方式（用户主动选择 / 只能被牵出 / 两者均可）
- `可作为浮现议题`：表示该议题可以作为背景线索被其他主议题牵出

当议题以浮现议题身份进入报告时，应由浮现机制版本提供翻译指南，以背景线索方式嵌入主报告正文，不直接作为用户可见章节标题。

## 2. 标准字段

每个议题本体文件至少保留以下字段：

```text
> 状态：draft
> 内容来源状态：ai_draft
> 来源验证状态：source_verification_pending
> 用户入口角色：active_selectable / emergent_only / both
> 可作为主议题：是/否
> 可作为浮现议题：是/否
> MVP入口优先级：mvp / later / advanced
```

字段说明：

- `可作为浮现议题`：表示运行时可以作为其他主议题背后的角色标签。
- `背景线索`：不是本体元数据字段，而是报告写作口径；当浮现议题进入某个主报告时，应以背景线索方式嵌入主线。
