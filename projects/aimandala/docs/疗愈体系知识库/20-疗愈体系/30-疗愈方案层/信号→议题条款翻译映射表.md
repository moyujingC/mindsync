本文建立画面信号（signal_id）到浮现机制（mechanism_id）的精确映射链路，作为信号→议题条款翻译链路的中间层。

## 1. 映射链路

```
画面信号 (signal_id)
  → 浮现机制 (mechanism_id)
    → 议题条款 (clause_id)
```

**第一层**：signal_id → mechanism_id，由本文件定义。
**第二层**：mechanism_id → clause_id，由各主议题报告包中的翻译层定义（见浮现机制说明节）。

本文件不直接跨越到议题条款层。议题条款的映射在各主议题报告包中维护，避免单一文件跨越过多议题导致维护困难。

## 4. 使用规则

### 4.1 运行时调用

生成报告时，signal_id 到 mechanism_id 的映射按以下规则使用：

1. 从画面观察提取 signal_id 列表。
2. 在本文件中查询每个 signal_id 对应的 mechanism_id。
3. 统计各 mechanism_id 的映射置信度，取置信度最高的 2-3 个作为主要浮现机制。
4. 在第 5 节 mechanism_id → clause_id 映射表中查询该机制对应的 clause_id。
5. 将 clause_id 填入运行时包的 `matched_issue_clauses` 字段。

### 4.2 置信度聚合

当多个 signal_id 映射到同一 mechanism_id 时，聚合置信度：

| 组合数量 | 聚合置信度 |
|---------|-----------|
| 1 个信号 | 使用单信号置信度 |
| 2-3 个信号 | 提升一级（low→medium, medium→high） |
| 4+ 个信号 | 最高不超过 high |

### 4.3 冲突处理

当同一 signal_id 映射到多个 mechanism_id 时：

- 置信度高的优先。
- 置信度相同时，取出现在本文件列表中位置靠前的。
- 报告生成时，应综合考虑所有映射结果，不应因单一映射而忽略其他可能性。

### 4.4 边界限制

- `visual.color.black` 映射到机制时，需在报告中保留安全边界说明。
- 置信度为 low 的映射，不应作为报告主要判断依据，应标记为"可能线索"。
- 所有映射结果在进入报告正文前，必须经过议题总索引中的报告生成规则审核。
