本文定义画面信号从 `needs_review` 到 `reviewed_case_rule` 的审核流程和标准。

## 1. 审核状态定义

| 状态 | 含义 | 使用边界 |
|------|------|----------|
| `manual_supported_draft` | 来自手册拆解，尚未完成结构化审核 | 可用于参考，不可进入报告生成 |
| `sample_based` | 来自 11 例样本反推，只能作为样本经验 | 可用于参考，不可直接用于报告 |
| `needs_review` | 需要回到来源正文或专家经验中复核 | **待审核**，本文件定义审核方式 |
| `reviewed_case_rule` | 来自案例，已完成人工审核 | **可用**，可作为正式知识库候选规则 |
| `source_supported` | 有明确来源材料支持 | 可用于报告生成，但需保留来源标注 |
| `runtime_ready` | 已完成审核、边界和结构化字段 | 可进入运行时 |

**优先级排序**：`needs_review` → `reviewed_case_rule` / `source_supported` → `runtime_ready`

## 3. 审核标准

每条信号审核时必须回答以下问题：

### 3.1 信号定义清晰度

- 这个信号的画面标准是什么？（具体可操作）
- 信号边界在哪里？（什么情况下算、什么情况下不算）
- 与相邻信号如何区分？（防止混淆）

### 3.2 案例支持度

- 这个信号在已有 11 例案例中是否有对应样本？
- 如果有样本：样本中案主的实际画面特征是什么？
- 如果没有样本：是否需要建立新的案例积累，还是标注为「需专家复核」？

### 3.3 解释链路完整性

- 从画面事实到这个信号的解释链路是否有来源支持？
- 来源是手册经验还是案例反推？
- 解释链路是否有明确的判断顺序约束？

### 3.4 报告表达安全性

- 这个信号在报告中的表达方式是否安全？
- 是否有禁止句式需要标注？
- 是否涉及诊断性语言需要过滤？

## 4. 审核流程

### 4.1 审核方式

| 信号类型 | 审核方式 | 说明 |
|----------|----------|------|
| 手册来源信号 | 专家复核 | 对照 `01-曼陀罗解读手册原文.md` 原章节，确认信号解释是否与手册一致 |
| 案例来源信号 | 案例对照 | 对照 `70-评估与案例/10-完整解读案例11例/90-来源原文/01-完整解读案例11例合并原文.md`，确认画面特征与信号描述一致 |
| 手册+案例混合 | 先案例后专家 | 先对照案例确认样本支持，再请专家复核手册解释链路 |

### 4.2 审核步骤

```
步骤 1：定位信号来源
  → 在 画面信号总目录 中找到信号的 source_path
  → 读取对应的来源文档

步骤 2：案例对照（适用于所有信号）
  → 遍历 11 个案例，寻找与该信号描述一致的画面特征
  → 记录：案例编号 + 具体画面描述 + 与信号的匹配度

步骤 3：判断审核结论
  → 案例有支持（≥ 1 例）→ 升为 reviewed_case_rule
  → 案例无支持但手册有来源 → 保留 needs_review，标注来源
  → 案例和手册均无支持 → 降为 manual_supported_draft 或 ai_draft

步骤 4：更新信号状态
  → 在 画面信号总目录 中更新 signal_id 的 review_status 列
  → 在来源文档中添加审核批注（审核人 + 日期 + 结论）
```

### 4.3 审核模板

每条信号的审核结论应记录在信号文件末尾：

```yaml
signal_id: [signal_id]
reviewed_date: 2026-05-27
reviewer: [审核人]
review_method: [manual/case_based/mixed]
case_support:
  - case_id: [案例编号]
    match_description: [与信号的匹配描述]
    confidence: [high/medium/low]
  - ...
manual_source_check: [手册来源核对结果]
review_status: [needs_review/reviewed_case_rule/manual_supported_draft]
review_notes: [其他说明]
```

## 6. 使用提醒

审核完成后，以下文件需要同步更新：

1. `01-画面信号总目录.md` — 更新 `review_status` 列
2. 对应的来源文档 — 添加审核批注
3. 浮现机制文件（如有引用该信号）— 同步更新来源状态

本文件是审核流程文档，本身不修改信号状态。审核结论记录在对应来源文档中。
