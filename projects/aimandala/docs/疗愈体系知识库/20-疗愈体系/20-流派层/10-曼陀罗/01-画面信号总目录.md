## 2. 画面信号层级

当前按四层登记，后层建立在前层基础上，不是平级并列：

1. 圈层信号。
2. 五行信号。
3. 圈内五行生克信号。
4. 三圈能量流动信号。

说明：

- 圈层信号先确定画面落在哪一圈、哪一层、哪一段边界。
- 五行信号再看颜色、形状、留白、浓淡、面积、重复、结构、方向等具体元素分别对应哪种五行。
- 解读圈内时，使用五行信号和圈内五行生克信号，判断同一圈内部元素之间是否相生、相克、截断、无根或失衡。
- 解读跨圈时，使用三圈能量流动信号，看内圈、中圈、外圈之间的承接、堵塞、外散、内收、失衡和是否能贯通。
- 跨圈解读不使用五行生克，不把一圈里的五行直接拿去判断另一圈。
- 圈内五行生克信号可以继续追溯到五行失衡，判断同圈内部是否形成失衡结构。

当前总目录只做登记，不把这些层级直接混写成一层结论。

## 7. 使用边界与可映射条款

当前总目录只做人工登记，不直接用于生成报告。

后续进入 runtime 前，每条信号都需要补齐：

- 结构化 ID（已有）。
- 来源路径（已有）。
- 原文语境。
- 可用场景。
- 不适用场景。
- 安全边界。
- **可映射条款（见下节）**。
- 审核状态（已有大部分）。

### 7.1 可映射条款字段规范

可映射条款字段使用 clause_id 或 mechanism_id 精确标识，格式为：

```yaml
mappable_clauses:
  - id: mechanism.self_worth          # 浮现机制 ID 或议题条款 clause_id
    confidence: high | medium | low   # 该信号对该机制/条款的映射置信度
    note: 描述性说明                   # 映射逻辑说明
```

### 7.2 映射链路说明

信号到议题条款的映射通过两层结构实现：

```
画面信号 (signal_id)
  → 浮现机制 (mechanism_id)
    → 议题条款 (clause_id)
```

第一层：信号 → 浮现机制，见 `../../30-疗愈方案层/信号→议题条款翻译映射表.md`
第二层：浮现机制 → 议题条款，见各主议题报告包中的翻译层
