这里是疗愈体系知识库的入口。

本知识库沉淀可复用、可扩展、可运行的疗愈体系。它不绑定单一产品形态；`aimandala` 是当前第一条应用链路。

## 1. 定位

本知识库的长期知识资产分为两类：

- 参考来源索引：指向研究母库、专家手册、案例源和其他可信来源，不重复保存大段来源正文。
- 疗愈体系：按议题、流派和疗愈方案组织产品可用知识。

当前产品应用是 `aimandala`，主要使用曼陀罗相关知识生成解读报告、回答追问和生成疗愈建议。曼陀罗在本知识库中属于疗愈体系的流派层；`aimandala` 的报告流程、交互规则和输出规范属于应用适配。

后续同一套疗愈体系可以继续支撑课程、训练营、陪伴式产品、议题专题内容、练习手册或其他衍生产品。

## 2. 与研究母库的关系

研究母库位于：

```text
projects/research-center/kb
```

它保存更原始、更通用的研究材料，包括来源、摘录、事实核查、通用 wiki 和原子知识。

本知识库不复制维护同一份来源正文。进入本知识库的内容，应是已经知道用途的产品化知识，或对研究母库材料的引用索引。

```text
research-center/kb
  = 来源正文与研究母库

疗愈体系知识库/05-参考来源索引
  = 来源索引、引用地图、入库记录

疗愈体系知识库/20-疗愈体系
  = 经过选择、重组、裁剪后可进入产品链路的知识
```

## 3. 主要应用场景

本知识库当前至少服务三类能力：

1. 生成解读报告。
2. 支持用户围绕解读报告继续追问。
3. 生成定制化疗愈方案。

后续可扩展到：

- AI 在分析画面后向用户提出补充问题，再结合回答生成更精准的报告。
- 把某个议题整理成课程大纲、课件、练习和作业。
- 把疗愈路径整理成陪伴式打卡方案。
- 把议题条款整理成内容选题、案例分析或社群引导材料。
- 把同一套议题体系接入新的测评、图像分析或问答产品。

## 5. 知识分层

本知识库采用三层：

```text
来源索引层
  → 自然语言知识层
  → 运行时知识包层
```

`20-疗愈体系` 和 `05-参考来源索引` 属于自然语言知识层；`60-运行时知识包` 属于运行时知识包层，运行时直接读取受控 Markdown 文档。

## 6. 版本编号

知识库版本采用 `major.minor.patch`（大版本.小版本.修订版）编号，并允许在稳定前使用 `alpha`、`beta`、`rc` 这类阶段标记。

当前从 `1.0.0-alpha` 开始：

- `1.0.0-alpha`：体系建设期，结构和条款仍在快速调整。
- `1.0.0-beta`：主要议题、流派知识和疗愈方案已经成型，进入生成测试。
- `1.0.0`：第一版可稳定用于报告生成、追问回答和疗愈方案生成。
- `1.1.0`：新增议题、流派、场景或能力，但不破坏已有结构。
- `1.1.1`：修正文案、链接、字段或少量条款，不改变结构。
- `2.0.0`：数据结构、推理链路或运行时协议发生不兼容变化。

更完整的编号规则见 [02-知识库版本编号规则.md](00-知识库治理/02-知识库版本编号规则.md)。

## 7. 协作规则

在这个目录中工作时，默认遵守：

- 先读本 README，再读 [00-体系框架.md](00-知识库治理/00-体系框架.md)。
- 新增内容应落在对应语义目录，不使用无语义的纯编号目录。
- 研究母库保存来源正文；本知识库保存来源索引和产品化知识。
- 写知识库定位时，应把“疗愈体系”作为上层边界，把 `aimandala` 作为当前应用链路。
- 每份知识文档应尽量保留 `状态`、`版本`、`date`、`owner`、`source_of_truth` 等元信息。
- 引入理论、人名、流派或参考资料时，应在 `05-参考来源索引` 建立引用说明，或在正文中标注来源。
- 不把一次性讨论、临时 prompt、排障记录混入知识库正文。
- 从来源材料整理出的内容默认采用“原文保真重组”：尽量保留原文措辞和一线经验，只调整结构、标题和顺序。

## 8. 不适合放在这里的内容

- 当前产品需求和验收标准，应放入 `projects/aimandala/docs/specs/`。
- 技术架构和运行时实现方案，应放入 `projects/aimandala/docs/architecture/`。
- 任务计划、QA 记录和交付说明，应分别放入 `tasks/`、`qa/`、`delivery/`。
- 运行时可消费的数据文件，应放入产品约定的数据目录，或由 `60-运行时知识包` 构建产出。
