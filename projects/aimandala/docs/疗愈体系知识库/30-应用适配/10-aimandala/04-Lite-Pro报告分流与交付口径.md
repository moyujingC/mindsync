# Lite / Pro 报告分流与交付口径

本文把 `Lite / Pro` 报告口径接入疗愈体系知识库。

当前只保留运行时分流、权益守卫和安全边界，不再定义 Lite / Pro 固定报告结构、固定字数或固定内容层级。

## 1. 基本判断

Lite 是当前入口报告体验。

Pro 是 Lite 后的升级权益，只能从对应 Lite 报告升级获得，不能单独购买。

当前报告版本已作为 MVP 可接受版本。后续若要重新定义 Lite / Pro 内容差异，应单独开启新 spec，不从历史结构自动继承。

## 2. 运行时分流

运行时包应把 `report_version` 作为显式输入：

```yaml
report_version: lite | pro
```

分流规则：

- `lite`：输出当前 Lite 权益内容。
- `pro`：输出当前 Pro 权益内容。

Pro 只能从 Lite 升级获得。前端无独立 Pro 购买入口，后端必须校验用户已拥有对应画作 / report_id 的 Lite 权益。

## 3. Lite 最小交付要求

Lite 上线前只检查：

1. 内容非空、可读。
2. 与本次画作 / 用户输入有关。
3. 不明显模板化到无法接受。
4. 不出现诊断、恐吓、治疗承诺、投资建议、未来预测或依赖诱导。
5. 如出现 Pro 引导，不贬低 Lite，也不制造焦虑。

## 4. Pro 最小交付要求

Pro 上线前只检查：

1. 用户已完成对应 Pro 升级。
2. 内容非空、可读。
3. 与本次画作 / 报告有关。
4. 不出现诊断、恐吓、治疗承诺、投资建议、未来预测或依赖诱导。
5. 支付成功后可恢复权益，不诱导重复付款。

## 5. 安全边界

Lite 和 Pro 都不承担：

- 医疗诊断。
- 心理疾病判断。
- 财务、投资、职业或关系重大现实决策替代。
- 未来预测。
- 治疗承诺。
- 长期依赖关系。
- 完整疗愈课程或 21 天计划。

## 6. 质量检查

当前质量检查只保留 MVP 最小门槛：

- 是否能正常生成。
- 是否能正常展示。
- 是否与本次画作 / 用户输入有关。
- 是否没有安全越界。
- 是否没有明显错误、空白、调试信息或不可读内容。
- 是否没有焦虑式 Pro 引导。

不再检查历史固定结构、固定字数、固定段落模块或固定根源层级。
