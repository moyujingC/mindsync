## 缺口概览

| 缺口 | 当前状态 | 影响 | 修复优先级 |
|------|----------|------|------------|
| 主议题 17 个议题本体 | 15 个框架占位，仅财富完整 | 浮现机制无处归附，报告链路无锚点 | P0 |
| 浮现机制 7 个背景线索 | 6 个框架占位，01 号有案例依据 | 背景线索层无法支撑实际解读 | P0 |
| 「信号 → 疗愈建议」映射表 | 完全缺失 | 从解读到疗愈方案链路断裂 | P0 |
| 来源验证 | 大部分文档标注 `ai_draft` | 无法保证知识准确性 | P1（基础设施） |

### 依赖关系

```
主议题补充（前置）
  → 浮现机制补充（依赖主议题）
    → 信号→疗愈映射表（依赖前两者）
      → 来源验证（贯穿全程）
```

**主议题是浮现机制的前置条件**：浮现机制作为背景线索嵌入主议题报告，如果主议题本体没有完整条款，浮现机制补充得再完整也无法落地。映射表同理。

### 1.2 修复策略

**核心原则**：围绕"能被主议题翻译层调用"这一目标建设，不追求一次性补全所有文件。

**推荐顺序**（基于对应主议题的建设优先级）：

```
1. 优先完成 01 号的来源验证
   → 建立修复模板和质量标准
   → 01 号已有一手内容，可直接进行来源回填
   → 对应主议题：财富、个人内在·自我价值

2. 补充 02 号或 05 号
   → 02-安全感与匮乏感：对应财富安全感、配得感议题
   → 05-情绪能量与消耗：通用性最高，对应财富情绪能量议题
   → 对应主议题：财富

3. 补充 03、04 号
   → 对应主议题：亲密关系、父亲关系、母亲关系
   → 关系议题背景线索的锚点

4. 补充 06、07 号
   → 对应主议题：健康身体、事业发展
   → 映射表覆盖的后续议题
```

### 1.3 修复标准

每个浮现机制文件应包含：

| 区块 | 内容 | 说明 |
|------|------|------|
| 议题定义 | 该背景线索的核心问题是什么 | 1-2 段，通用定义 |
| 画面识别规则 | 哪些画面特征可能指向该背景线索 | 核心：3-5 条具体规则 |
| 边界区分 | 与其他背景线索的区分点 | 表格形式，防止混淆 |
| 表达原则 | 在报告中的表达方式 | 禁止句式、建议句式 |
| 主议题嵌入方式 | 在哪些主议题报告中可被调用 | 指向对应翻译层 |
| 常见疗愈方向 | 该背景线索对应的通用疗愈方向 | 与映射表联动 |

**使用边界**：
- 浮现机制不是诊断，不能单独成报告
- 必须翻译回当前主议题语言才能进入正文
- 画面证据不足时优先使用浮现机制，不强行落到具体议题本体

## 3. 来源验证路径

### 3.1 当前状态

所有浮现机制文件标注 `source_verification_pending`，大部分主议题标注 `ai_draft`。

来源分类：
- `ai_draft`：AI 生成框架，来源待补充
- `case_reverse`：从案例反推，可信度中等，需交叉验证
- `source_supported_draft`：有来源材料支撑
- `mixed`：混合多种来源

### 3.2 验证优先级

```
高优先级（影响解读准确性）
  → 画面识别规则：哪些画面特征对应哪个背景线索
  → 议题核心定义：每个主议题/背景线索的核心问题

中优先级（影响报告质量）
  → 与其他议题/背景线索的区分
  → 常见卡点分类
  → 疗愈方向

低优先级（后续迭代）
  → 调整方案细节
  → 表达原则（相对通用）
```

### 3.3 来源建设策略

| 来源类型 | 建设方式 | 适用内容 |
|----------|----------|----------|
| 案例库 | 从 11 个案例中抽取相关片段 | 画面识别规则、表达方式 |
| 培训材料 | 引用现有课程/手册内容 | 核心定义、疗愈方向 |
| 心理学流派 | 引用家庭系统、创伤疗愈等理论 | 深层机制、卡点分类 |
| 人工审核 | 疗愈师经验审核 | 边界区分、表达原则 |

**来源标注格式**：
- 每个条目后标注来源类型和来源样本
- 避免把单一来源泛化为完整共识
- 案例反推条目应标注「案例编号 + 具体案例」
