## 1. 定位

本文档定义“疗愈体系知识库系统”的长期结构。

完整体系包含两部分：

- 上游研究母库：`projects/research-center/kb` 中的疗愈主题材料，负责保存来源、拆解原子知识和形成结构化理解。
- 下游产品化知识库：`projects/aimandala/docs/疗愈体系知识库`，负责把已经有用途、可审查、可进入产品链路的知识组织成疗愈体系、应用适配和运行时知识包。

体系目标是沉淀一套可用于解读报告、追问回答、定制化疗愈方案、课程和衍生产品的完整疗愈体系。当前第一条应用链路是 `aimandala`，但系统边界不等同于某一个产品，也不只等同于下游 `疗愈体系知识库/` 目录。

## 3. 上游研究母库与下游产品化知识库的分工

上游研究母库位于：

```text
projects/research-center/kb
```

其中疗愈主题位于：

```text
projects/research-center/kb/sources/healing
projects/research-center/kb/atoms/healing
projects/research-center/kb/wiki/healing
```

它承担低约束的研究沉淀，保存来源、摘录、核查、通用 wiki 和原子知识。这里允许材料处于不同成熟度：新来源、单本书整理、同一作者取向、跨来源对照、待验证观点都可以存在，但必须保留来源和边界。

下游产品化知识库位于：

```text
projects/aimandala/docs/疗愈体系知识库
```

它承担高约束的领域组织，保存已经知道用途、可以进入产品链路的知识。进入这里的内容，默认需要能回答以下问题：

- 来源在哪里。
- 由哪些上游 source、atom 或 wiki 支撑。
- 当前用于哪个议题、流派、疗愈方案或产品场景。
- 是否已人工审核，是否存在风险边界。
- 如果用于生成报告、追问或疗愈建议，应该如何表达，哪些表达必须避免。

```text
上游 sources/healing
  → 上游 atoms/healing
  → 上游 wiki/healing
  → 05-参考来源索引
  → 20-疗愈体系
  → 30-应用适配
  → 60-运行时知识包
```

原则：

- 原始资料只维护一份，优先放在研究母库。
- 上游 `sources/healing` 保存来源正文和来源登记；下游不复制大段来源正文。
- 上游 `atoms/healing` 保存可检查的最小知识判断；下游只引用与当前议题、流派或产品链路有关的判断。
- 上游 `wiki/healing` 保存研究理解和跨来源整理；下游只接收已经完成用途判断、边界判断和产品表达转换的部分。
- 本知识库不重复保存大段来源正文。
- 下游 `05-参考来源索引` 记录来源位置、入库用途、审核状态和影响文件。
- 下游 `20-疗愈体系` 保存经过选择、重组、裁剪后的产品化知识。
- 下游 `30-应用适配` 和 `60-运行时知识包` 不能直接吃上游原始来源，必须经由参考来源索引和疗愈体系层。

## 4. 疗愈体系内部结构

本节主要定义下游产品化知识库中的 `20-疗愈体系`。它不是全部疗愈材料的堆放处，而是从上游研究母库筛选、翻译和重组后的产品化知识层。

### 4.1 议题层

议题层站在用户经验出发，回答“用户可能遇到什么问题”。

当前已开始建设：

- 财富议题。
- 个人成长与自我价值议题。

后续可扩展：

- 事业 / 发展。
- 亲密关系。
- 父亲关系。
- 母亲关系。
- 亲子关系。
- 健康 / 身体。
- 情绪能量。
- 内在小孩。
- 潜意识伤痛。
- 内在渴望。
- 天赋优势。
- 人际关系。
- 灵性成长。
- 意识扩容。
- 自我关系。

### 4.2 流派层

流派层站在专业知识出发，回答“不同心理学或疗愈流派如何理解和处理这些议题”。

可纳入的流派包括：

- 心理学流派。
- 身心疗愈流派。
- 艺术疗愈。
- 曼陀罗。
- 东方体系中的阴阳、五行、三才等解释框架。

曼陀罗在这里是一个疗愈与表达系统，不是应用层本身。

当前曼陀罗流派下先沉淀：

- 画面识别与描述：三圈边界、颜色、形状、结构、留白和画作事实描述。
- 圈内五行解读：颜色和形状进入五行后的元素判断、相生相克、失衡类型。
- 跨圈能量解读：内圈、中圈、外圈之间的三圈联动和能量流动。
- 组合模式：多个画面信号共同出现后的综合判断和案例规则。
- 疗愈方案经验：基于曼陀罗的一线疗愈建议和操作经验。

### 4.3 疗愈方案层

疗愈方案层负责把议题层和流派层连接起来，形成可执行建议。

后续应沉淀：

- 觉察问题。
- 书写练习。
- 身体练习。
- 呼吸与冥想。
- 颜色和绘画练习。
- 行动建议。
- 周期性陪伴方案。

当前从曼陀罗手册拆出的疗愈建议先保留在 `20-流派层/10-曼陀罗/50-疗愈方案经验`，等通用方案框架稳定后，再抽取进入 `30-疗愈方案层`。

## 5. 应用适配

应用适配回答“某个产品如何调用疗愈体系知识”。

当前已有：

```text
30-应用适配/10-aimandala/
```

这里放 `aimandala` 的解读流程、报告组织规范、追问回答规则和与产品形态强相关的输出规范。

产品应用不应反向定义整个疗愈体系。应用可以使用议题、流派和疗愈方案，但不应把自己的页面结构、报告版本或交互细节写进通用疗愈体系层。

## 6. 运行链路

当前推荐链路：

```text
上游来源
  → 上游原子知识
  → 上游 wiki
  → 下游来源索引
  → 议题层
  → 流派层
  → 疗愈方案层
  → 应用适配
  → 运行时知识包
```

以 `aimandala` 为例：

```text
曼陀罗画面观察
  → 画面信号
  → 流派层解释
  → 议题层条款
  → 疗愈方案
  → 报告 / 追问 / 方案输出
```

画面信息不能直接等同于最终结论。它应先成为可描述的画面信号，再和议题层、流派层、用户主题一起形成解释链。

## 7. 当前建设顺序

1. 稳定完整体系边界：上游 `research-center/kb` 承担研究母库，下游 `aimandala/docs/疗愈体系知识库` 承担产品化知识库。
2. 先把上游 `sources/healing`、`atoms/healing`、`wiki/healing` 中已经进入下游的材料登记到 `05-参考来源索引`。
3. 优先建设议题层，不让少量案例或单一作者直接定义完整议题。
4. 补充流派层，尤其是心理学流派、疗愈流派和曼陀罗体系，并标注哪些内容来自上游 wiki，哪些来自一线案例。
5. 抽取通用疗愈方案层，把上游练习、方法和风险提示转成可执行、可审查的产品建议。
6. 维护 `aimandala` 的应用适配规则，确保产品表达不会反向污染通用疗愈体系。
7. 再逐步收束为受控 Markdown 运行时知识包。
