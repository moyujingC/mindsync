这是 `aimandala` 第一版可执行的报告生成入口。

它的目标很小：先让程序或 Agent 知道要读什么、按什么顺序生成、哪些话必须保留缓冲、哪些内容不能越界。

产品主分层固定为：

`入口产品 -> 解读产品 -> 主题转化产品 -> 长期陪伴产品`

其中 `Lite / Pro` 只属于“解读产品”的深度分流，不是产品架构主分层。

## 1. 适用范围

本包只用于曼陀罗解读报告的第一版生成。

当前只保证 `财富` 主题有对外稳定入口。

其他主题按运行时状态分级，不允许只因为存在模板就直接对外开放。

| 主题 | 运行时状态 | 默认动作 |
|------|------------|----------|
| 财富关系 | `public_candidate` | 可用于 Lite 报告生成，仍需保留来源和置信度 |
| 亲密关系 | `internal_test` | 可内部测试，不默认对外开放 |
| 父亲关系 | `internal_test` | 可内部测试，不默认对外开放 |
| 母亲关系 | `internal_test` | 可内部测试，不默认对外开放 |
| 亲子关系 | `internal_test` | 可内部测试，不默认对外开放 |
| 人际关系 | `internal_test` | 可内部测试，不默认对外开放 |
| 事业 / 发展 | `blocked_draft` | 暂不生成正式报告，只能说明需要补齐来源和翻译层 |
| 健康 / 身体 | `blocked_draft` | 暂不生成正式报告，不输出医疗判断 |
| 个人成长与自我价值 | `framework_only` | 可作为背景线索，不作为独立对外主题 |

状态含义：

- `public_candidate`：可进入对外候选报告，但仍需人工抽检。
- `internal_test`：可用于内部评测和案例回归，不进入正式用户输出。
- `framework_only`：只能作为背景线索或通用解释，不生成独立主题报告。
- `blocked_draft`：必须拦截，除非后续完成主议题报告包、来源索引和质量门。

## 2. 产品定位

报告在产品矩阵中属于“解读产品”，它的任务是：

- 解释这张画在表达什么。
- 命名用户状态。
- 梳理用户模式。
- 连接现实议题。

报告不承担：

- 连续训练。
- 长周期改变。
- 替代主题方案。
- 替代 21 天定制方案。

因此，报告里的“调整方案”应保持为轻量建议和下一步方向，不要写成完整训练计划。

报告与主题产品的关系是：

- 报告负责看懂、命名、连接。
- 主题转化产品负责围绕一个议题开始改变。
- 长期陪伴产品负责持续推进个体化路径。

## 4. 运行时输入

当前运行时输入来自部署生成的 prompt pack，并读取本目录中的受控 Markdown 运行时包。

它覆盖：

- 报告任务定义。
- 用户分群适配。
- 输入字段。
- 输出结构。
- Lite / Pro 分流。
- 产品衔接。
- 安全边界。
- 质量检查。

运行时在生成前还必须补齐这些中间字段：

```yaml
matched_visual_signals:
  - signal_id:
    evidence:
    confidence: high | medium | low
matched_issue_clauses:
  - clause_id:
    source_status: ai_draft | source_supported_draft | case_verified | reviewed
    runtime_permission: allow | allow_with_warning | block
emergent_topics:
  - topic:
    role: background_signal | switch_candidate | blocked
confidence_level: high | medium | low
blocked_reasons:
  - reason:
trace_required: true
```

缺少这些字段时，只能生成内部 draft 或追问，不能生成正式用户报告。

## 5. 用户分群口径

报告优先服务三类用户：

- 自我理解型：需要命名状态、理解模式、看懂自己。
- 议题解决型：需要围绕具体问题获得解释与方向。
- 成长深化型：需要看到机制、成因和长期路径入口。

情绪安放型用户可以使用轻解读，但报告语言应更重视安抚和承接。

高复杂度支持型用户不应由 AI 报告主承接，应触发安全边界与外部支持引导。

## 6. 输入

最小输入集如下：

```yaml
user_theme: 财富关系 | 个人成长与自我价值 | 其他
user_goal: 用户希望解决的具体问题
user_segment: 审美探索型 | 情绪安放型 | 自我理解型 | 议题解决型 | 成长深化型 | 高复杂度支持型 | 未知
product_intent: 轻解读 | 报告 | 主题方案入口 | 21天定制方案入口 | 未知
report_version: lite | pro | unknown
visual_observations:
  overall: 画面的第一直觉
  inner_circle: 里圈观察
  middle_circle: 中圈观察
  outer_circle: 外圈观察
  colors: 颜色与分布
  shapes: 形状与结构
  composition: 画面整体布局
  uncertainty: 无法确认或模糊的地方
current_context:
  user_description: 用户补充说明
  confidence_notes: 需要保留的不确定性
```

## 7. 输出顺序

报告固定按这个顺序输出：

1. 整体直觉。
2. 主题确认。
3. 三圈逐层解读。
4. 综合模式。
5. 主题卡点。
6. 生机。
7. 调整方案。

## 8. 生成规则

- 先写观察，再写判断，最后写建议。
- 每个判断都要尽量对应到可见画面信号。
- 不要把单个颜色、单个形状直接写成绝对结论。
- 不要把一条流派经验写成整个疗愈体系的通用真理。
- 主题不明确时，先确认主题，再继续往下写。
- 信息不足时，使用“可能”“倾向于”“从画面看起来”这类缓冲表达。
- 画面信息只用于支持解释，不用于医学诊断、财务承诺或心理诊断。
- 报告只给轻量调整方向，不生成完整主题方案或 21 天计划。
- 如果 `report_version` 已知，按 Lite / Pro 对应结构生成；如果未知，先根据用户任务和证据完整度分流。
- `user_segment` 只表示用户类型，`report_version` 只表示 Lite / Pro 报告版本，二者不得混用。
- 每个报告段落必须能追到至少一个画面信号或议题条款；追不到的内容只能作为低置信提示。

## 9. 三圈解释口径

- 里圈：更靠近自己、内在感受、意识和内心想法。
- 中圈：关系、能量流动、当下互动和承接。
- 外圈：外部世界、行动、物质表现和对外呈现。

写法上不要把三圈混成一段，要分圈说明，再做综合判断。

## 10. 主题映射口径

当前最小主题映射如下：

- 财富：配得感、安全感、自我价值、家庭金钱脚本、行动力、承载力、情绪能量、与世界的链接。
- 个人成长与自我价值：自我认同、边界感、内在力量、表达、行动、关系中的自我位置。

如果主题落在运行时状态表允许范围之外，先说明当前主题暂不能生成正式报告，不要套用财富或关系话术。

财富关系主题使用固定翻译链：

`画面信号 -> 状态含义 -> 财富关系议题翻译 -> 报告段落`

财富报告可以提及关系、情绪、家庭、身体等浮现议题，但必须先翻译回财富机制。浮现议题只能解释财富状态的背景，不单独展开成另一份报告。

## 11. 调整方案口径

调整方案至少包含一种可执行动作，优先顺序是：

1. 认知调整。
2. 情绪调频。
3. 具体练习。
4. 现实中的小行动。

建议要具体到频率、节奏或操作方式，避免只写”多爱自己”这类空话。

### 11.1 调整方案取料规则

调整方案从以下路径取疗愈建议，禁止绕过交叉索引直接引用信号疗愈映射表：

1. **确认浮现机制主题**（01-07，对应 `10-信号疗愈映射表.md` 中的映射编号）。
2. **在 `00-三库交叉索引.md` 第 1 章中找到对应映射编号**。
3. **优先取 ✅ 行**（三库完整覆盖的建议）。
4. **⚠️ 行**需注明缺失的库，并在报告中提示”建议参考其他练习渠道补充”。
5. **❌ 行**禁止直接写入报告，应替换为三库中有对应链路的建议，或标注”当前置信度不足”。

> 注意：`00-三库交叉索引.md` 当前为 draft 状态（v0.1.0），部分建议的来源状态需在使用时注明置信度。禁止从信号疗愈映射表直接复制”疗愈建议”到报告而不标注来源链路。

调整方案应停留在报告内的轻量建议。如果需要连续练习、阶段节奏或个体化陪伴，应引导到主题方案或 21 天定制方案，而不是在报告内展开完整计划。

## 12. 运行时质量门

进入用户可见报告前，所有可输出内容必须满足：

| 字段 | 要求 |
|------|------|
| `source_refs` | 至少能回到来源索引、atom、议题条款、案例或三库交叉索引之一 |
| `source_status` | 不得为 `source_needed`；`ai_draft` 只能内部测试 |
| `review_status` | 对外输出至少为 `approved_for_internal`，高风险内容需要人工确认 |
| `risk_level` | `high` 必须先走安全边界 |
| `runtime_permission` | `block` 不得输出，`allow_with_warning` 必须降级表达 |
| `trace` | 每段报告记录使用的画面信号和议题条款 |

段落级追踪最小格式：

```yaml
trace:
  report_section: 主题卡点
  visual_signals:
    - signal_id
  issue_clauses:
    - clause_id
  source_refs:
    - path-or-id
  confidence: high | medium | low
```

## 13. 风险路由

风险路由优先于主题路由、Lite / Pro 分流和报告生成。

| 风险类型 | 默认动作 | 输出边界 |
|----------|----------|----------|
| 自杀、自伤、活不下去 | 停止报告生成，提示外部专业支持 | 不输出画面分析结论 |
| 严重创伤具体事件 | 停止深度解读，转稳定化和外部支持 | 不做根因解释或暴露式练习 |
| 医疗症状、疾病、孕期、癫痫等 | 不做医学判断，建议医疗专业支持 | 只保留低风险观察和身体觉察 |
| 债务危机、破产、严重财务风险 | 不给财务承诺、投资建议或结果保证 | 只做情绪承接和下一步求助建议 |
| 关系暴力、控制、现实安全威胁 | 不做关系修复承诺 | 优先安全计划和外部支持 |

## 14. 示范材料过滤规则

`70-评估与案例/20-片段解读示范/` 中的片段示范默认只用于内部评估。

以下状态不得进入运行时输出：

- 待补图。
- 待人工审核。
- 仅从原始手册摘出但未做来源边界确认。
- 无法回到具体画面事实或案例编号。

## 15. 产品衔接

报告结尾可以根据用户状态给出下一步入口：

- 如果用户只是想理解自己，结尾保留为轻量觉察问题。
- 如果用户已经明确议题，结尾可以提示主题方案。
- 如果用户希望持续改变，结尾可以提示 21 天定制方案。
- 如果用户呈现高复杂度或高风险状态，结尾应提示外部专业支持。

## 16. Lite / Pro 分流

- Lite：用于快速命中、说明画面依据、连接主题，并给出 1 到 3 条低压建议。
- Pro：用于完整解释核心主轴、逐圈机制、生克失衡、能量流动、根因链和阶段性调节路径。
- Lite 和 Pro 都是报告产品，不承担完整主题方案或 21 天定制方案。
- `report_version = lite` 时输出 Lite。
- `report_version = pro` 且 `pro_activated = true` 时才输出 Pro。
- `pro_activated = false` 或未知时默认输出 Lite。

## 17. 安全边界

以下内容不要写：

- 诊断式措辞。
- 保证结果的财务承诺。
- 把画面直接写成疾病结论。
- 把一次解读写成终身定论。
- 把未经确认的推断写成事实。

## 18. 兜底规则

如果输入不足，优先输出：

- 已确认的画面事实。
- 当前最可能的解释方向。
- 还需要补问的问题。

不要为了完整而编造细节。
