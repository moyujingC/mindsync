## 2. 人工评审口径

人工评审采用 `Pass / Conditional / Fail`，不使用 1-5 分均值。

| 字段 | 含义 |
| --- | --- |
| `structure_pass` | 能稳定识别中心、层次、对称/放射结构。 |
| `circle_pass` | 能稳定描述内圈、中圈、外圈边界，不把三圈混成单层泛述。 |
| `color_pass` | 主色识别与图片大体一致。 |
| `grounding_pass` | 观察能落回可见元素，不大量引入不可见推断。 |
| `product_pass` | 可直接支撑后续报告 `visual_basis`，少清洗、少重写。 |
| `stability_pass` | 3 轮之间只有措辞漂移，没有核心观察反转。 |

本轮优先级：

1. 用户可见报告质量。
2. `visual_basis` 可直接使用程度。
3. 贴图与三圈边界稳定性。
4. 速度、confidence 和字段整洁度。

## 3. 总体对比

| candidate | structure_pass | circle_pass | color_pass | grounding_pass | product_pass | stability_pass | 人工结论 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `qwen-vl` | Pass | Pass | Pass | Pass | Pass | Pass | 推荐作为 MVP 默认视觉模型 |
| `doubao-vision` | Pass | Conditional | Pass | Pass | Conditional | Pass | 推荐作为 fallback / 备选 |

人工判断：

- `qwen-vl` 的输出更像“报告素材整理员”：三圈分层清楚、语言更规范、摘要密度适中，更适合直接进入 `visual_basis`。
- `doubao-vision` 的输出更像“视觉观察员”：贴图细节多、颜色和图形元素较丰富，但三圈边界经常用“大致、可能、边界模糊”表达，进入报告前更需要压缩和标准化。
- 两个候选都没有出现核心观察反转；主要差异不是“能不能识别”，而是“输出能否低成本进入产品报告”。

## 5. 主要风险与接入前处理

`qwen-vl` 主要风险：

- 有时会把“无明显异常”或轻微推断写入 `risk_flags`，该字段不应直接进入用户报告。
- 少数图存在数量描述漂移，例如小花数量从“四个”到“六个”变化；后续报告不应依赖精确计数。
- 响应耗时高于豆包，端到端接入时需要设置合理超时和 fallback。

`doubao-vision` 主要风险：

- 三圈边界常用“大致、可能、边界模糊”，对后续报告生成来说不如 `qwen-vl` 稳定规整。
- 输出更偏原始观察，直接进入 `visual_basis` 前更需要压缩和统一术语。
- 个别字段出现英文颜色或把“无明显断裂...”写入 `risk_flags`，字段清洗仍然必要。

## 6. 最终建议

MVP 默认视觉模型建议：

- 默认：`qwen-vl-max-latest`
- fallback：`ep-20260316095322-94wf5`
- 快速备选：`glm-4v-plus`

理由：

1. `qwen-vl` 的三圈结构更规整，输出更像可直接进入报告的 `visual_basis`。
2. `doubao-vision` 贴图观察能力强，但报告落地前需要更多压缩和标准化。
3. 在 MVP 阶段，用户可见报告质量优先于速度；因此即使 `qwen-vl` 更慢，也更适合作为默认模型。
4. 豆包适合作为 fallback：当 `qwen-vl` 超时、限流或成本不可接受时，豆包能提供足够可靠的视觉观察结果。

## 7. 下一步

进入端到端接入验证：

1. 将 `qwen-vl-max-latest` 配为 Aimandala 默认视觉模型。
2. 将 `ep-20260316095322-94wf5` 配为视觉 fallback。
3. 跑 3-5 张代表图的上传图片到 `visual_basis` 再到 Lite/Pro 报告的 smoke test。
4. 检查最终报告是否贴图、可读、边界安全，并确认 `risk_flags` 不直接泄漏到用户可见正文。
