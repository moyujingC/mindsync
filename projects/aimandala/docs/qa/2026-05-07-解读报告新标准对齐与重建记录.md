# Aimandala 解读报告新标准对齐与重建记录

> 日期：2026-05-07  
> 范围：Lite / Pro 报告内容生成层  
> 结论：进入第一轮重建验证。保留 API 字段合同，重建用户可见叙事口径。

## 背景

本轮不是复刻旧版报告，而是把迁移后明显下降的报告质感拉回到可交付水平，并在结构稳定性上超过旧版。

旧版报告的优势是“像解读师在说话”：开头有命中感，段落之间有递进，用户能读到自己当下的状态。迁移后版本虽然字段更稳定，但容易变成字段拼接、术语解释和工程化摘要。

## 新标准

Lite 的目标是“先命中、先看见、再解释”。开头两句必须先说中用户当前状态，再进入画面依据和模式解释。`visual_basis` 继续保留为画面依据区，但表达要像报告正文，不像检测日志。

Pro 的目标不是 Lite 加长版，而是独立深度报告。它必须在 Lite 之上继续补出机制递进、根因链和可执行建议。第一眼直觉要先完成“被看见”，再解释三圈、失衡、根因和行动方向。

语言默认“少术语”。三圈、五行和失衡类型可以作为内部依据或少量定位线索出现，但不能成为正文主角；如果出现术语，必须立刻翻译成普通人能读懂的现实状态。

## 本轮改动

本轮保留现有 API 返回字段和前端承接字段，不改 `Lite/Pro` 合同。

主要改动集中在三层：

- Prompt 模板：收紧 Lite / Pro 的输出约束，要求开头命中、少术语、避免字段拼装说明书。
- Blueprint 模板：调整默认文案底座，并避免引入未接线的新占位符，防止 `{dominant_theme}` 一类变量泄漏到用户可见报告。
- Runtime 叙事层：重写 Lite / Pro 的核心投射文案，让 `overall_impression`、`visual_elements`、`emotion_portrait`、`first_impression`、`block_point`、`root_cause` 更像完整报告。

## 验收口径

- Lite 必须保留 `visual_basis`、`current_reading`、`pattern_interpretation`、`life_connection`、`lite_healing_guidance`。
- Pro 必须保留 `deep_impression`、`evidence_digest`、`imbalance_diagnosis`、`root_cause_chain`、`deep_structure_interpretation`、`healing_plan`。
- 用户可见正文不得出现未渲染占位符，例如 `{dominant_theme}`、`{secondary_name}`、`{transition_sentence}`。
- 用户可见正文不得把失衡标签当作主结论堆叠；标签只能作为定位线索，且必须有现实状态翻译。
- 画面依据区必须继续保留三圈、颜色、结构依据，但表达应服务报告阅读，而不是像检测输出。

## 已验证

本轮补充和更新了单测断言：

- Lite / Pro narrative projection 不泄漏新占位符。
- Pro block point 不再把核心卡点写成 quoted label。
- 失衡根因不再强制暴露旧版议题术语，而是优先输出普通用户可理解的根因表达。
- Lite / Pro structured contract 仍保持原字段不变。

## 残留风险

这次修的是生成骨架和兜底表达，不能替代后续真实样本人工验收。下一步仍需要用旧版经典样例和当前 MVP 代表图各跑一轮 Lite / Pro，对照“命中感、可读性、术语密度、递进性”四项人工评审。
