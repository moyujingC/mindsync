## 1. 验证对象

本次验证对象是 `MIN-15`、`MIN-16` 暴露出的 CI/CD 运行稳定性和控制面治理问题，重点覆盖：

1. `automation` 节点 heartbeat / runner 观测链路是否真正恢复
2. `infra-runner-failure`、`credential_missing`、`infra_missing`、`workspace_drift` 是否能够被稳定区分
3. 任务状态、最新评论和执行基线是否保持一致
4. `MIN-12` 到 `MIN-16` 是否已形成正式的过渡期样本说明

## 2. 验收口径

### 2.1 运行底座

以下条件必须满足，才可认为运行底座恢复：

1. `paperclip-heartbeat` 使用的 GitHub token 不再触发 `accessDenied=true`
2. `runner-doctor.sh` 输出可以明确判断：
   - runner 是否注册
   - runner 是否在线
   - labels 是否匹配
   - token 是否具备 runner 读取能力
3. `mindsync-ci-runner.service`、`paperclip-heartbeat.service`、`paperclip-heartbeat.timer` 全部正常
4. 至少一条真实 `ci` workflow 不再长期 `queued`

### 2.2 控制面一致性

以下条件必须满足，才可认为控制面可信：

1. 新产生的 issue 标题遵循：
   - 父任务：`<emoji> <短 sha> · Aimandala-CI / Aimandala-Deploy · <时间>`
   - 子任务：`<emoji> <短 sha> · <Job> · <时间>`
2. issue 评论固定包含：
   - 当前判断
   - 已做动作
   - 下一步动作
   - 谁来解除阻塞
3. issue 描述固定包含执行基线：
   - `cwd`
   - `branch`
   - `head`
   - `dirty`
   - drift 信息
4. 若任务线程已出现“已修复 / 已回写”评论，但状态仍停留在 `todo` 或与评论结论不符，系统会补状态修正或诊断评论

### 2.3 过渡期样本一致性

必须能从正式文档中直接读出：

1. `MIN-12` 是旧诊断粗粒度样本
2. `MIN-15` 是新治理初版样本
3. `MIN-16` 是已细化到 `credential_missing` 的样本
4. `MIN-13`、`MIN-14` 属于旧口径下的代码修复样本，不再代表当前标准输出

## 3. 当前检查结果

### 3.1 已确认成立

截至 `2026-04-14` 当前窗口，以下结论已成立：

1. `MIN-15` 与 `MIN-16` 的问题不属于仓库代码失败，而属于同一条 `runner-heartbeat` 链路上的基础设施阻塞
2. `MIN-16` 已经细化到 `blocked_reason=credential_missing`
3. 新 issue 标题、执行基线和标准评论模板已经开始生效
4. 当前直接阻塞点已能明确收敛到 heartbeat GitHub token 权限不足

### 3.2 当前仍未完成

截至本记录落盘时，以下项仍未闭环：

1. heartbeat token 权限尚未在线修复，`accessDenied=true` 仍未被真实消除
2. 尚未记录到一条新的 `ci` run 被恢复后的 self-hosted runner 成功拾取并完成
3. `MIN-12`、`MIN-13`、`MIN-14` 仍保留旧标题和旧语义
4. `MIN-14` 已出现“已修复”评论但状态仍是 `todo`，说明状态回写一致性仍需继续治理

## 4. 验证方法

### 4.1 运行侧

推荐执行并记录：

```bash
GITHUB_TOKEN=<token> bash /opt/automation/app/mindsync/shared/tools/ci/runner-doctor.sh
systemctl status mindsync-ci-runner.service
systemctl status paperclip-heartbeat.service
systemctl status paperclip-heartbeat.timer
```

同时观察：

- heartbeat 不再返回 `accessDenied=true`
- runner 元数据和 labels 可读
- 最新一条 `ci` run 不再长期停留在 `queued`

### 4.2 任务系统侧

抽查最近产生的 infra issue，确认：

1. 标题符合三态 emoji 规则
2. `blocked_reason` 与正文判断一致
3. 执行基线已写入 issue 描述
4. 评论模板完整

### 4.3 样本侧

以 `MIN-12` 到 `MIN-16` 作为过渡期样本，确认：

1. 旧口径与新口径差异已被正式文档解释
2. 后续讨论不再依赖评论线程回忆上下文

## 5. 当前风险

1. 若 heartbeat token 权限迟迟不补齐，系统仍会停留在“能判断大方向，但无法真正恢复运行底座”的状态
2. 若 `MIN-14` 这类“评论已修复、状态未收口”的问题不继续治理，面板可信度仍会下降
3. 若后续新 issue 又回到旧标题和旧语义，说明新治理入口尚未真正收口
