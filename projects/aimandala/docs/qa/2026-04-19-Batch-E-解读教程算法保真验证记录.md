## 1. 验证目标

本记录验证 Batch E 是否把报告链路修到“算法保真”：

1. Layer 0 是否包含完整四步法 trace。
2. 元素教程状态是否与工程评分状态分离。
3. Lite / Pro 产品区块是否从算法 trace 派生。
4. Pro 是否独立成立，不再引用 Lite。
5. workbench / eval 是否能暴露算法保真结果。

## 3. 算法保真检查

固定检查：

1. `interpretation_method_trace.direct_judgment` 存在。
2. `interpretation_method_trace.per_circle_color_analysis` 覆盖 `inner / middle / outer`。
3. `interpretation_method_trace.shape_analysis` 存在，无法识别时必须显式 `used=false`。
4. `interpretation_method_trace.circle_relation_analysis` 必须在基础元素状态之后解释生克关系。
5. `element_states` 同时存在 `tutorial_state` 和 `scoring_state`。
6. `toc-mvp-fixture-002` Pro 报告不得出现 `Lite 里`。
7. 正式报告链路不得出现 raw Python dict 字符串。

## 4. 当前结果

已完成验证，结果如下：

1. `Layer 0` 已新增 `interpretation_method_trace`，固定包含：
   - `direct_judgment`
   - `per_circle_color_analysis`
   - `shape_analysis`
   - `circle_relation_analysis`
   - `final_algorithm_basis`
2. `element_states` 已同时输出 `tutorial_state` 与 `scoring_state`：
   - 教程口径固定为 `>50%` 太过、`<10%` 不足
   - 工程评分口径仍保留原 runtime scoring 阈值
3. `triad_states` 已包含 `tutorial_state`，且 `source_hit` 改为 `circle:<circle>:<element>`。
4. Lite / Pro `narrative_plan.evidence_trace_summary` 已固定输出：

5. Pro 叙事与合同已移除对 Lite 的依赖式表述，`deep_impression` 不再引用 Lite 标题。
6. `knowledge_debug` 已新增 `algorithm_fidelity_trace`，可见：
