## 人工初看

当前样本已经比早期“纯字段拼接”更进一步：

- 有开头命中感。
- 有画面依据区。
- 有三圈、颜色、五行、能量流动和卡点的过程链。
- Lite / Pro 能区分轻量判断和深层结构。
- QA 可以从最终报告倒查到每个中间过程。

但当前样本还没有达到最终报告标准：

- 用户可见报告仍有明显结构化拼接痕迹。
- 部分句子重复，例如“旧节奏尚未完全退场、新节奏又开始拉扯”多次出现。
- Pro 的“核心洞察表格”“根因链”仍像工程化产物，不像完整解读师表达。
- 部分术语虽然可接受，但解释还不够顺滑。
- 画面依据区还没有完全按“这个颜色/形状在这个位置如何形成关系”的自然观察方式展开。

因此，本轮样本适合作为 v2.2 知识链路与过程链基线，不适合作为最终用户可见文案。

## 真实 LLM 尝试结果

尝试命令：

```bash
source /Users/xinran/.mindsync/private/aimandala-vision-eval.env
PYTHONPATH=projects/aimandala/toC/app/backend \
python3 projects/aimandala/toC/app/backend/scripts/export_knowledge_fixture_golden.py \
  --fixture-id toc-mvp-fixture-003 \
  --build-selector candidate:v2.2-theme-md \
  --version lite \
  --output-dir projects/aimandala/docs/qa/report-samples/2026-05-09-v22-markdown-runtime-llm-real-chain
```

失败结果：

```text
RuntimeError: chat_generation_failed_blocking:lite:empty_response
```

排查结果：

- 当前私有 env 中存在视觉评测相关 key。
- 当前私有 env 中没有 `AIMANDALA_LLM_BASE_URL`、`AIMANDALA_LLM_API_KEY`、`AIMANDALA_LLM_MODEL` 这组文字模型配置。
- 后端因此走 legacy GLM 默认文本模型，而不是 MVP 决策中的 `deepseek-v4-pro`。
- 最小 GLM 文本请求可成功返回 JSON，说明接口本身可用。
- 完整 Lite 报告长 prompt 生成返回空，不能作为真实报告样本。

## 当前阻塞

要生成真正可评估的真实文字模型报告，需要先补齐本地 / staging 文字模型环境变量：

```bash
AIMANDALA_LLM_BACKEND=openai_compatible
AIMANDALA_LLM_BASE_URL=<text-openai-compatible-url>
AIMANDALA_LLM_API_KEY=<text-api-key>
AIMANDALA_LLM_MODEL=deepseek-v4-pro
AIMANDALA_LLM_CHAT_MODEL=deepseek-v4-pro
```

如果经 RelayHub，则 `AIMANDALA_LLM_BASE_URL` 应指向 `prod-relay/aimandala` 的 OpenAI-compatible 入口。

## 下一步建议

1. 先补本地私有文字模型 env，不把视觉评测 env 当成报告文字模型 env。
2. 用 `deepseek-v4-pro` 跑 `toc-mvp-fixture-003` 的 Lite / Pro 各一份真实报告。
3. 对比本轮确定性样本、真实 DeepSeek 样本和旧版报告，确认报告重建重点。
4. 如果真实 DeepSeek 仍不稳定，需要先改 prompt JSON 合同或拆分 Lite / Pro 生成步骤，再继续文案优化。
