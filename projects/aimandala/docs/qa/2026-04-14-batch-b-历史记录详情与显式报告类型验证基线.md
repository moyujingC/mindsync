## 1. 验证对象

本轮验证对象包括：

1. 前端报告读取接口显式化
2. history -> detail -> report 的新链路
3. 当前新解读主链路语义不退化

## 2. 目标行为

### 2.1 接口与调用

- `getInterpretationReport(...)` 所有调用点都显式传 `reportType`
- `refreshMobileWebReport(...)` 所有调用点都显式传 `reportType`
- TypeScript 不允许再省略报告类型参数

### 2.2 新解读主链路

- `upload -> detect -> report-choice -> selected-generating -> selected-ready`
- 选择 `Lite` 时显式请求 `lite`
- 选择 `Pro` 时显式请求 `pro`
- 当前“没有默认体验”的产品语义不变化

### 2.3 历史记录链路

- history 列表点击记录后进入 `history-record-detail`
- 若只有 `Lite`，详情页可明确打开 `Lite`
- 若同时拥有 `Lite + Pro`，详情页可分别打开 `Lite / Pro`
- 若 `Pro` 仍在生成中，详情页可显示状态与进度

## 3. 自动化

至少通过：

```bash
npm --prefix projects/aimandala/toC/app/frontend test
npm --prefix projects/aimandala/toC/app/frontend run typecheck
npm --prefix projects/aimandala/toC/app/frontend run build:mobile-web
```

重点覆盖：

- `controller.test.ts`
- `app.test.tsx`
- `runtime.tsx` 相关交互
- history / detail / report descriptor 与 shared UI 行为测试

## 4. 当前不在验证范围

- `/api/v2/miniapp/*`
- 支付链路
- 手机端人工主路径验收
