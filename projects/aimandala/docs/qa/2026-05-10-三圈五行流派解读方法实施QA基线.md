## 1. QA 目标

本 QA 基线验证的不是最终报告文案是否“好看”，而是系统是否严格按三圈五行 stage 链执行。

换句话说，最终报告可以继续优化表达，但底层必须能证明：

1. 方法来源来自 `sources/知识库构建/三圈五行流派解读方法与步骤.md`。
2. 实现输入来自 `stage_process_package`。
3. 每个关键判断都能追溯到 stage 交付物和知识条目。
4. 旧链路、旧样本、旧报告骨架没有进入默认生成路径。

## 2. 验证矩阵

| 验证项 | 通过条件 | 验证方式 |
| --- | --- | --- |
| 方法入口 | active 文档只把三圈五行方法文档作为当前方法入口 | `rg` 搜索 active 文档 |
| 输入合同 | Lite / Pro prompt 必须接收 `stage_process_package` | 单测 `test_prompt_builder.py` |
| 过程交付物 | record 持久化包含 `stage_process_package` | 单测 `test_pipeline_data_models.py` |
| 生成链路 | generation runtime 先生成 stage package，再生成 Lite / Pro | 单测 `test_pipeline_orchestrator.py` |
| QA 证据 | 样稿包含最终报告和中间过程版本 | 检查 `docs/qa/report-samples/` |
| 旧链路隔离 | 旧链路关键词只允许出现在 archive 或历史样本 | `rg` 门禁 |
| 敏感信息 | QA 样本和文档不包含 API key 或私有 env 路径 | 敏感扫描 |

## 4. 退回条件

出现以下任一情况，报告生成链路不得视为通过：

1. Lite / Pro prompt 直接拼入完整 Markdown 真值源。
2. Lite / Pro prompt 直接拼入旧全量运行容器。
3. 第 13 / 14 步在最终报告阶段新增前面 stage 没有出现过的画面事实。
4. 过程样稿只有最终报告，没有中间过程版本。
5. active 文档或 active 测试把旧链路描述成当前方法。
6. QA 样本包含明文 API key、私有 env 路径或本地 runtime data。

## 5. 当前状态

截至 2026-05-10，旧报告链路已从 active 默认路径移除，并归档到 archive。后续所有报告生成整改都应以本 QA 基线作为最低质量门。
