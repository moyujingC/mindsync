1. `MandalaAgentInput` / `MandalaAgentResult` 合同

6. `Report Context Package`

8. 10 个审阅文件写出

失败集中在旧 API / workbench 对 legacy placeholder 报告的预期：

1. `test_api_health.py` 中 create / history / status / report 相关用例期待 legacy pipeline 在无 LLM 时仍生成 lite / pro placeholder 报告。
2. `test_knowledge_workbench_v22.py` 中 golden export 相关用例期待旧 workbench 在 Noop LLM 下仍导出可用报告。

本轮没有修改 legacy API 接入、旧 orchestrator、旧 placeholder renderer 或 workbench 默认路径，因此不把这些旧链路失败作为 `reading_intelligence` 离线原型 blocker。

## 5. 当前结论

`曼陀罗解读智能体` MVP 离线原型已完成最小骨架和单元验证。

当前还没完成：

1. 真实模型 Lite / Pro 样本产出
2. 人工审阅中间交付物与最终报告
3. API 旁路 feature flag 接入
4. 旧 API / workbench 测试策略重定

下一步应先用真实模型跑 `toc-mvp-fixture-003`，产出 10 个审阅文件，再决定 agent prompt 和 stage 结构是否进入下一轮调整。
