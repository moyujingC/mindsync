## 1. 验证范围

本轮验证 `mandala_interpretation_agent` 离线原型，不接入正式 API，不替换 legacy report pipeline。

已覆盖：

1. `app/core/mandala_interpretation_agent/` 新模块
2. `scripts/run_mandala_interpretation_agent_fixture.py`
3. `tests/unit/test_mandala_interpretation_agent.py`
4. `toc-mvp-fixture-003` 输入解析
5. 无真实模型时的失败路径
6. 真实模型 Lite 样本产物

## 2. 已落地行为

离线原型已具备：

1. `MandalaAgentInput` / `MandalaAgentResult` 合同
2. 精简 `knowledge_pack` 构建器
3. `MandalaInterpretationAgent` 单智能体旁路
4. 16 个 `stage-*` 输出
5. 5 个 execution block trace
6. `Report Context Package`
7. 用户可见文本质量门
8. 10 个审阅文件写出
9. fixture runner
10. 无模型或模型失败时返回结构化失败，不写 fake 报告

模型配置：

1. 文字生成：DeepSeek V4 Pro
2. 视觉观察：Qwen VL Max Latest

说明：DeepSeek V4 Pro 文字调用可用；同一 DeepSeek endpoint 接收 `image_url` 图片输入时返回 `400 Bad Request`，因此本轮没有把 DeepSeek V4 Pro 作为视觉模型使用。

真实模型产物目录：

产物包含：


质量门结果：

```text
quality_gate_passed=true
missing_stages=[]
missing_visual_units=[]
leaked_terms=[]
missing_context_fields=[]
```

本轮曾发现真实模型返回的 `stage-03` 结构不是预期的 `visual_units` 形态。已补充规范化和 gate：

1. `inner_circle / middle_circle / outer_circle` 会规范成 `inner / middle / outer`
2. 圈层摘要会转成最小 `visual_units`
3. `quality_gate` 会阻断缺少三圈 visual units 或 evidence map 为空的产物

失败集中在旧 API / workbench 对 legacy placeholder 报告的预期：

1. `test_api_health.py` 中 create / history / status / report 相关用例期待 legacy pipeline 在无 LLM 时仍生成 lite / pro placeholder 报告。
2. `test_knowledge_workbench_v22.py` 中 golden export 相关用例期待旧 workbench 在 Noop LLM 下仍导出可用报告。

本轮没有修改 legacy API 接入、旧 orchestrator、旧 placeholder renderer 或 workbench 默认路径，因此不把这些旧链路失败作为 `mandala_interpretation_agent` 离线原型 blocker。
