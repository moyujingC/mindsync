## 1. 核验结论

当前不满足升级到 `v2026.428.0` 的前置条件。

原因不是 `Paperclip` 服务不可用，而是升级前治理状态存在阻断：

1. 当前运行代码仍是 dirty canary（脏的预发布基线）
2. `paperclip-heartbeat.service` 当前持续失败
3. execution health strict gate（执行健康严格门禁）检出活跃阻断项
4. 主镜像区和 Paperclip 主仓 checkout 都不是干净状态

因此本轮结论是：暂缓升级，先修复巡检入口、workspace materialization（工作区实例化）阻断和 checkout 脏状态。

### 5.2 手动 strict gate

用显式 `--api-key` 执行：

```bash
node shared/tools/ci/check-paperclip-execution-health.mjs \
  --company-id "$PAPERCLIP_COMPANY_ID" \
  --project-name "一镜一梳" \
  --api-base "$PAPERCLIP_API_BASE" \
  --api-key "$PAPERCLIP_API_KEY" \
  --expected-root "$PAPERCLIP_SERVER_WRITABLE_ALLOWED_ROOT" \
  --stale-minutes "${PAPERCLIP_EXECUTION_STALE_MINUTES:-15}" \
  --strict
```

结果：

```text

```

1. `MIN-202` / `mindsync-ci-runner`

   - taskClass：`automation-execution`
   - executionRoute：`server_automation`
   - executionWorkspaceId：`null`
2. `MIN-208` / `deploy-prod`
   - status：`in_review`
   - reason：`execution_workspace_policy_not_materialized`
   - taskClass：`automation-execution`
   - executionRoute：`server_automation`
   - executionWorkspaceId：`null`

结论：严格门禁当前不通过，不能作为升级后放行依据。
