## 1. 本轮验证对象

本轮只验证“关闭范围、例外规则和新基线切换口径”是否闭合，不验证线上批量关闭是否已实际执行。

验证对象固定为：

1. 历史任务关闭范围定义
2. 例外保留规则
3. 默认终态选择
4. 关闭 comment 口径
5. 新基线后的观察窗口规则

## 2. 测试矩阵

### 2.1 文档一致性

必须验证：

1. Spec、Task、QA 三份文档对新基线时间描述一致
2. 三份文档都明确历史普通任务与历史 automation 任务都在默认关闭范围内
3. 三份文档都明确旧任务关闭不代表技术问题已解决

### 2.2 关闭范围

必须验证：

1. 文档没有把历史普通任务排除在关闭范围外
2. 文档没有把历史 automation 任务单独特殊化
3. 文档没有暗示需要逐条技术复盘后才能关闭

### 2.3 例外规则

必须验证：

1. 例外名单必须显式点名
2. 例外名单数量上限明确为极少量
3. 文档没有把“以后也许要看”当成默认保留理由

### 2.4 新基线后的治理规则

必须验证：

1. 文档明确新基线后第一主线是普通任务在本地 Mac 自动执行
2. 文档没有把 heartbeat gate 修复写成本轮主目标
3. 文档没有把批量补 `executionWorkspaceId` 写成本轮主目标
4. 文档没有把 automation 模板语义修复提前到普通任务本地自动执行之前

### 2.5 关闭终态与 comment

必须验证：

1. 文档明确历史任务批量关闭默认使用 `done`
2. 文档明确不能把 `done` 误解释为“问题已技术解决”
3. comment 模板里明确写出“历史基线重置”与“若问题仍成立应重新生成新任务”

## 3. 阻断条件

出现任一情况，本轮不得宣称通过：

1. 文档没有把历史普通任务纳入默认关闭范围
2. 文档没有给出明确的新基线时间
3. 文档把关闭旧任务写成“问题已经技术解决”
4. 文档没有把默认终态写死
5. 文档没有限制例外名单规模
6. 文档把后续主线从普通任务本地 Mac 自动执行转回 heartbeat / 运行态补救

## 4. 验收条件

本轮通过条件：

1. Spec、Task、QA 三份文档已正式落地
2. 三份文档都把“历史普通任务 + 历史 automation 任务”纳入统一关闭范围
3. 三份文档都把 `2026-04-26 00:00 Asia/Shanghai` 固定为新基线
4. 三份文档都明确默认终态使用 `done`
5. 三份文档都明确旧任务关闭只是控制面重置，不是技术问题已解决
6. 三份文档都明确新基线后先满足普通任务在本地 Mac 自动执行
