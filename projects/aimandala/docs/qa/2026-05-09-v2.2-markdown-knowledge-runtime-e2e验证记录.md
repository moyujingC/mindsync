## 关于 006 / 008 的 regression flags

`toc-mvp-fixture-006` 和 `toc-mvp-fixture-008` 原本是视觉模型稳定性 fixture，其 `validation.required_structured_fields` 使用的是视觉识别字段：

- `center_observation`
- `circle_boundaries`
- `dominant_colors`
- `structure_notes`
- `risk_flags`
- `confidence`

本轮实际跑的是知识报告 Lite 输出，字段合同是：

- `topic_context`
- `current_reading`
- `visual_basis`
- `pattern_interpretation`
- `life_connection`
- `lite_healing_guidance`
- `pro_report_entry`

因此 006 / 008 的 regression flags 属于验证口径不匹配，不代表 `v2.2` 知识库接入失败，也不代表 Lite 报告字段缺失。

## 当前边界

本轮只验证 `v2.2` Markdown 知识包能被运行时选择，并被报告链路读取。

本轮不验证：

- 真实视觉大模型识别质量
- 真实文字大模型文案质量
- Lite / Pro 最终报告是否达到人工审美标准
- 是否可以把 `v2.2` 提升为 `current`

## 下一步建议

1. 为知识报告验证新增专用 fixture，避免复用视觉稳定性 fixture 造成字段校验误报。
2. 跑 `candidate:v2.2-theme-md` 的真实 Lite / Pro 报告样本，检查文案是否遵循三圈五行流派。
3. 若真实报告质量通过，再考虑把 `v2.2` promote 为 `current`。
