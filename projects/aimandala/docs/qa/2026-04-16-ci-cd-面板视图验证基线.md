## 1. 目标行为

CI/CD 面板默认服务“当前健康度判断”，而不是“历史失败清偿”。

## 2. 核心验收问题

用户进入面板后，应能快速回答：

1. `ci` 当前是红还是绿
2. `deploy` 当前是否可放行
3. 最近一次失败是否已经被后续绿色覆盖
4. 当前真正需要处理的是最新失败，还是持续性失败

## 3. 场景基线

### 3.1 最新失败

前置：

- workflow 最近一次 terminal run = failure

期望：

1. workflow 摘要显示 `failing`
2. 最近一次失败 run 出现在默认窗口
3. 用户无需展开历史层就能看出当前确实有问题

### 3.2 最新成功覆盖旧失败

前置：

- 最近一次 terminal run = success
- 更早一条 run = failure

期望：

1. workflow 摘要显示 `healthy` 或 `degraded`，但不能显示成当前红灯
2. 旧失败不应继续占据首屏主视觉
3. 旧失败只在默认窗口内弱化展示，或进入历史层

### 3.3 连续失败

前置：

- 最近窗口内连续 2 次及以上失败

期望：

1. workflow 摘要显示 `failing` 或明确的持续失败信号
2. 首屏能直接看出这是持续问题，不只是一次偶发旧红灯

### 3.4 基础设施阻塞

前置：

- run 处于 `queued timeout`
- 或 runner / credential / workspace drift 导致无法有效执行

期望：

1. 面板显示 `blocked`
2. 不把它混写成普通代码失败

## 4. 失败判定

任一情况出现即视为未通过：

1. 最新成功后，旧失败仍被当成当前主要红灯
2. 用户必须人工翻十几条历史记录才能判断当前是否健康
3. 连续失败与单次旧失败在视觉上没有明显区别
4. 基础设施阻塞被误标成代码失败
