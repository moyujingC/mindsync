## 1. 验证目标

本记录验证：

1. `Lite / Pro` 是否已按独立产品语义收口
2. `Lite` 是否新增轻疗愈区块
3. Lite 页中的 `Pro` 入口是否去掉升级语义
4. `Pro` 的疗愈建议是否仍保留更深层表达

## 2. 预期检查项

1. Lite contract 有 `lite_healing_guidance`
2. Lite contract 有 `pro_report_entry`
3. `pro_teaser` 不再是 canonical 字段
4. Pro contract 仍有 `healing_suggestions`
5. Lite 页面能显示：
   - 轻量调节方向
   - 现在可以先做的小练习
   - 独立 `Pro` 产品入口

## 3. 自动化命令

1. `pytest projects/aimandala/toC/app/backend/tests/unit/test_report_contracts.py`
2. `pytest projects/aimandala/toC/app/backend/tests/unit/test_api_v2_report_contracts.py`
3. `pytest projects/aimandala/toC/app/backend/tests/unit/test_pipeline_orchestrator.py`

## 4. 当前结果

1. 后端合同与链路验证通过
   - `python3 -m pytest tests/unit/test_report_contracts.py tests/unit/test_api_health.py tests/unit/test_pipeline_orchestrator.py tests/unit/test_api_v2_report_contracts.py -q`
   - 结果：`89 passed`
2. 前端定向测试已按新语义更新并通过
   - `npm test -- --run shared/core/flow.test.ts shared/core/report-structure.test.ts shared/ui/shared-ui.test.tsx mobile-web/controller.test.ts mobile-web/app.test.tsx`
   - 结果：`5 files passed, 23 tests passed`
3. 已验证产品语义收口
   - Lite contract 存在 `lite_healing_guidance`
   - Lite contract 存在 `pro_report_entry`
   - `pro_teaser` 仅作为兼容字段保留，不再作为 canonical 前端读取入口
