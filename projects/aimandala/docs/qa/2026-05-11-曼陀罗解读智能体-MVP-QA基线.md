## 1. QA 目标

本 QA 基线验证 `曼陀罗解读智能体` 是否按方法真值源生成报告，并保留后续报告追问所需的上下文。

QA 不以旧 `stage_process_package / builder_v2 / placeholder renderer` 链路为依据。

## 2. 验证矩阵

| 验证项 | 通过条件 | 验证方式 |
| --- | --- | --- |
| 方法入口 | active 文档只把三圈五行方法文档作为方法真值源 | `rg` 搜索 active 文档 |
| 架构入口 | active 架构入口指向解读智能层和曼陀罗解读智能体 | `rg` 搜索 architecture |
| 旧链路隔离 | active 文档不把旧 report pipeline 写成当前依据 | `rg` 搜索旧链路关键词 |
| stage 完整性 | `stage_outputs` 包含 stage-00 到 stage-16 | 检查 agent 输出 |
| block trace | execution trace 包含 5 个 MVP block | 检查 `execution_trace.json` |
| 真实模型 | fixture runner 使用真实模型，不接受 fake / mock 输出作为报告审阅样本 | 检查 runner 配置和输出 trace |
| Lite / Pro | Lite / Pro 均能生成报告样本 | 检查 `final_report.json` / `final_report.md` |
| 用户可见文本 | 最终报告不泄漏内部标签、开发态语言和 placeholder 文案 | 质量门检查 |
| 追问准备 | `Report Context Package` 字段完整 | 检查 `report_context_package.json` |
| 失败处理 | 模型失败时输出失败状态，不静默产出伪报告 | 单测或故障注入 |

## 3. 必查输出文件

离线 fixture runner 每次运行至少输出：

```text
agent_input.json
knowledge_pack.json
agent_output.json
interpretation_artifacts.json
stage_outputs.json
execution_trace.json
final_report.json
final_report.md
report_context_package.json
quality_gate.json
```

## 4. 旧链路隔离门禁

active 文档和新实现不得把旧链路写成当前依据。

建议门禁：

```bash
LEGACY_REPORT_CHAIN_PATTERN="stage_process_package|builder_v2|ReportPlaceholderAssembler|report_pipeline_output_components|placeholder renderer|old_report_skeleton|old_report_plan|legacy_report_chain|legacy-report-chain"
rg -n "$LEGACY_REPORT_CHAIN_PATTERN" \
  projects/aimandala/docs \
  -g '!**/archive/**' \
  -g '!**/2026-05-11-曼陀罗解读智能体-MVP-QA基线.md'
```

允许命中：

- 新架构文档中用于说明旧链路冻结和禁止复用的段落
- 新 spec 中用于说明旧链路已归档的段落

不允许命中：

- active spec / task / runbook 把旧链路写成实现入口
- active QA 把旧链路测试写成 MVP 必跑项

## 5. 用户可见文本门禁

最终报告 Markdown 不得出现：

- `stage-`
- `transition-overload`
- `placeholder`
- `legacy`
- `待完整 stage 证据确认`
- `需要进一步确认`
- `应由 stage`
- `回到画面证据`

`stage_outputs.json` 和 `interpretation_artifacts.json` 可以保留 `stage-*` 键名。

## 6. 退回条件

出现以下任一情况，MVP 不得通过：

1. 用 fake / mock 模型输出冒充报告审阅样本。
2. 只生成最终 Markdown，没有中间交付物。
3. 5 个 execution block 替代或删减了 16 个方法 stage。
4. 最终报告泄漏内部标签或开发态兜底句。
5. `Report Context Package` 缺少追问所需的依据字段。
6. active 文档继续把旧报告生成链路写成当前实现依据。

## 7. 最小验收场景

MVP 首轮至少跑：

- `toc-mvp-fixture-003`

后续扩展到 3-5 个 fixture 后，再进入 API 旁路接入。
