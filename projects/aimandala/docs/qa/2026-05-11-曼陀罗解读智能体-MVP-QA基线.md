## 1. QA 目标

本 QA 基线验证 `曼陀罗解读智能体` 是否按端到端直出架构生成财富议题 Lite / Pro 报告。

当前质量门只认以下产物：

- `visual_draft`
- `prompt_pack`
- `final_report`
- `quality_gate`

QA 不以旧 `stage_process_package / builder_v2 / placeholder renderer / 16 stage` 链路为依据。

## 2. 验证矩阵

| 验证项 | 通过条件 | 验证方式 |
| --- | --- | --- |
| 架构入口 | active 架构入口指向端到端直出链路 | 检查 architecture / spec / task |
| 旧链路隔离 | active 文档不把旧 report pipeline 写成当前依据 | `rg` 搜索旧链路关键词 |
| 视觉草稿 | `visual_draft.md` 存在，且能看出整体观察、三圈观察、视觉单元和留白关系 | 人工审阅 + 文件检查 |
| prompt pack | `prompt_pack_manifest.json` 存在，包含 pack id、文件顺序和 hash | 文件检查 |
| 真实模型 | Vision Pass 和 Reasoning Pass 使用真实模型，不接受 fake / mock 输出作为报告审阅样本 | 检查 model trace |
| Lite / Pro | Lite / Pro 均能生成报告样本 | 检查 `final_report.md` |
| 用户可见文本 | 最终报告不泄漏内部标签、开发态语言和 placeholder 文案 | 质量门检查 |
| 流派感 | 报告像疗愈师带用户看画，保留三圈、画面、五行或能量流动特色 | 人工审阅 |
| 安全边界 | 不输出财务预测、投资建议、心理诊断或医疗判断 | 质量门检查 |
| 失败处理 | 模型失败时输出失败状态，不静默产出伪报告 | 单测或故障注入 |

## 3. 必查输出文件

端到端 fixture runner 每次运行至少输出：

```text
agent_input.json
visual_draft.md
visual_draft.json
prompt_pack_manifest.json
final_report.json
final_report.md
quality_gate.json
run_summary.json
```

## 4. prompt cache 验证

`run_summary.json` 应记录 DeepSeek 返回的缓存信息。

最小字段：

```json
{
  "prompt_cache": {
    "hit_tokens": 0,
    "miss_tokens": 0
  }
}
```

通过条件：

- 不要求每次都命中缓存。
- 必须能记录命中 / 未命中的 token 数。
- 同一 `prompt_pack_id` 的稳定前缀文件顺序不得随机变化。

## 5. 旧链路隔离门禁

active 文档和新实现不得把旧链路写成当前依据。

建议门禁：

```bash
LEGACY_REPORT_CHAIN_PATTERN="stage_process_package|builder_v2|ReportPlaceholderAssembler|report_pipeline_output_components|placeholder renderer|old_report_skeleton|old_report_plan|legacy_report_chain|legacy-report-chain"
rg -n "$LEGACY_REPORT_CHAIN_PATTERN" \
  projects/aimandala/docs \
  -g '!**/archive/**' \
  -g '!**/2026-05-11-曼陀罗解读智能体-MVP-QA基线.md'
```

允许命中：

- 新架构、spec、task 或 QA 中用于说明旧链路冻结和禁止复用的段落。

不允许命中：

- active spec / task / runbook 把旧链路写成实现入口。
- active QA 把旧链路测试写成 MVP 必跑项。

## 6. 用户可见文本门禁

最终报告 Markdown 不得出现：

- `stage-`
- `stage_outputs`
- `execution block`
- `transition-overload`
- `placeholder`
- `legacy`
- `quality_gate`
- `prompt_pack`
- `visual_draft`
- `需要进一步确认`
- `回到画面证据`

这些词可以出现在 QA 产物和开发产物里，但不能出现在用户可见报告里。

## 7. 退回条件

出现以下任一情况，MVP 不得通过：

1. 用 fake / mock 模型输出冒充报告审阅样本。
2. 只生成最终 Markdown，没有 `visual_draft`。
3. 只生成最终 Markdown，没有 `prompt_pack_manifest`。
4. 最终报告泄漏内部标签或开发态兜底句。
5. 最终报告没有画面带读，只给议题结论。
6. 最终报告输出财务预测、投资建议、心理诊断或医疗判断。
7. active 文档继续把旧报告生成链路写成当前实现依据。
