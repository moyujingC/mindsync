这份记录保存 Aimandala MVP 视觉模型端到端 smoke 结果。

本轮目标不是继续做模型横评，而是验证 `qwen-vl-max-latest` 作为默认视觉模型、豆包 `ep-20260316095322-94wf5` 作为 fallback 时，真实 V2 API 主链是否能从图片进入三圈识别，并产出可用的 Lite / Pro 报告依据。

- 执行日期：`2026-05-06`
- 执行脚本：`projects/aimandala/toC/app/backend/scripts/run_vision_e2e_smoke.py`

- 覆盖链路：`upload-image -> detect-circles -> create interpretation -> status -> lite report -> miniapp pro order/pay/reconcile -> pro report`

验证口径：

- detect `method` 必须是 `llm_vision` 或 `llm_vision_estimated`，不能是 `default`。
- Lite `structured.visual_basis` 必须非空，并包含内圈 / 中圈 / 外圈或等价三层依据。
- Lite `error` 必须为空，`prompt_schema_validation_issues` 必须为空。
- Pro report 必须返回 `version=pro`，且主结构字段非空。

## 5. 结论

端到端后端 API smoke 通过：

1. `qwen-vl-max-latest` 能作为默认视觉模型进入真实 `detect-circles` 主链。
2. 3 张代表图均未落入 `default` fallback。
3. Lite 报告均产出可读 `visual_basis`。
4. Pro 购买 stub + reconcile 路径均能生成 Pro 报告。
5. 输出证据中没有明文 API key。

当前建议：

- 后端端到端视觉 smoke 已通过，可以进入前端 runtime smoke。
- 生产配置前仍需补一轮真实 mobile-web runtime 验证，确认浏览器端不是 preview，而是消费同一条真实 API 主链。
- 如果未来要让 DeepSeek 负责文字、Qwen 负责视觉，可直接使用当前 `AIMANDALA_LLM_CHAT_* / AIMANDALA_LLM_VISION_*` 多任务前缀；不必为了 MVP 端到端 smoke 强制引入 RelayHub。
