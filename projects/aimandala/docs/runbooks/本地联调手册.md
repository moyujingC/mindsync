> 版本：0.1.0

这份手册用于收口 `aimandala` 当前本地联调的最小正式路径。

它不替代后端 README、前端 README 或服务器运维手册，而是回答一个更直接的问题：

当前如果我要在本机把 `一镜一梳` 跑起来并做前后端联调，应该先怎么走。

## 1. 当前联调对象

当前默认联调的是：

- `To C` 主产品主链
- 后端 `V2` API
- mobile-web 浏览器宿主

当前不把下面这些混进同一条最小联调路径：

- 生产部署
- Paperclip automation 节点运维
- CI/CD 在线排障
- 小程序并行开发分支

## 3. 当前最小联调链路

当前最小链路是：

1. 启动后端
2. 启动 mobile-web 前端
3. 让前端走真实 runtime，而不是只停留在 preview
4. 验证 `upload -> detect -> create -> status -> report`

## 4. 后端启动

后端主入口说明见：

- [../../toC/app/backend/README.md](../../toC/app/backend/README.md)

当前最小启动方式：

```bash
cd $REPO_ROOT
export PYTHONPATH=$PROJECT_ROOT/toC/app/backend
uvicorn app.api.main:app --reload --host 127.0.0.1 --port 8000
```

健康检查：

```bash
curl -s http://127.0.0.1:8000/health
```

## 5. 前端启动

前端 mobile-web 入口说明见：

- [../../toC/app/frontend/mobile-web/README.md](../../toC/app/frontend/mobile-web/README.md)

当前最小启动方式：

```bash
cd $PROJECT_ROOT/toC/app/frontend
npm run dev:mobile-web
```

当前 `Vite dev` 下默认带本地预览壳。

这适合先看页面结构，但不等于真实联调已经发生。

## 6. 当前联调时要区分 preview 和 runtime

当前前端有两种状态：

- preview
  - 不请求真实后端
  - 用于快速看页面壳和状态切换
- runtime
  - 走真实 loader 和后端接口
  - 用于真正联调

如果目标是验证真实主链，不能只停在 preview 模式。

## 7. 当前建议的联调顺序

### 7.1 后端健康检查

先确认：

- `GET /health` 可用
- 上传页人工三圈边界确认可用

### 7.2 最小 API 联调

可以先按后端 README 里的 curl 顺序走：

1. `upload-image`
2. `create interpretation`（必须带人工确认后的 `inner_radius` / `middle_radius`）
3. `report?version=lite`
4. `upgrade`
5. `report?version=pro`

参考：

- [../../toC/app/backend/README.md](../../toC/app/backend/README.md)

### 7.3 前端真实联调

再用浏览器验证：

1. 上传图片
2. 人工确认三圈边界
3. 创建 Lite
4. loading 轮询
5. 打开 Lite 报告
6. 升级到 Pro
7. 查看 history

## 8. 当前联调时最重要的几个检查点

- 后端是否真的跑在 `127.0.0.1:8000`
- 前端当前是 preview 还是 runtime
- 上传对象是否已经进入统一 `uploadAsset` 契约
- Lite / Pro 是否走到了真实 `report` 接口
- history 是否加载真实记录而不是占位数据

## 9. 当前建议的最小验证命令

前端：

```bash
cd $PROJECT_ROOT/toC/app/frontend
npm test
npm run typecheck
npm run build:mobile-web
```

后端：

```bash
cd $REPO_ROOT
pytest projects/aimandala/toC/app/backend/tests/unit
```

## 10. 当前常见误区

### 10.1 只看页面壳就以为联调完成

如果还停留在 preview 模式，那只是前端预览，不是完整联调。

### 10.2 只看后端 health 就以为主链打通

`/health` 正常只说明服务活着，不等于 `upload -> report` 整条主链都通。

### 10.3 把线上运维手册当本地联调手册

服务器部署与运维手册是线上/远端操作入口，不是本机最短联调入口。
