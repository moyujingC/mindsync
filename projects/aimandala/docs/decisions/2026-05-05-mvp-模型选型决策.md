# MVP 模型选型决策

> 状态：current
> 版本：0.1.0
> owner：CEO / Orchestrator, Engineer
> last_updated：2026-05-06
> source_of_truth：projects/aimandala/docs/decisions/2026-05-05-mvp-模型选型决策.md
> 项目：aimandala
> 阶段：decision
> reviewers：Architect, Engineer, Test / QA

这份决策用于收口 `一镜一梳 / Aimandala` 在 MVP 阶段的大模型选型口径。

它只覆盖当前 To C MVP 主链路，不扩展到 To B、Studio、V3 实验线或其他公司项目。

## 1. 当前结论

### 1.1 文字大模型

MVP 阶段，Aimandala 的文字大模型默认选用：

- 模型：`DeepSeek V4`
- RelayHub 当前候选入口：`preset-deepseek-v4`
- 当前约定 model id：`deepseek-v4-pro`
- 用途：
  - Lite / Pro 报告相关文本任务的模型候选
  - 报告追问 chat
  - 后续可扩展到摘要、结构化解释和轻量改写任务

说明：

- 当前 Aimandala 后端仍通过 `openai_compatible` 协议接入模型。
- MVP 阶段不强制所有请求必须先经 RelayHub。
- 如果经 RelayHub，则应绑定到 `prod-relay/aimandala` 下的生产任务入口。
- 生产用户数据不应进入第三方中转主链路。

### 1.2 视觉大模型

MVP 本地 / staging 阶段，Aimandala 的视觉大模型默认选用：

- 默认模型：`qwen-vl-max-latest`
- 默认入口：阿里云百炼 DashScope OpenAI-compatible
- fallback 模型：豆包 `ep-20260316095322-94wf5`
- fallback 入口：火山方舟 OpenAI-compatible
- 用途：
  - 上传图片后的三圈识别
  - 生成 Lite `visual_basis` 的上游视觉依据
  - Pro 画面证据摘要的上游三圈依据

说明：

- 当前只落到本地 / staging 配置口径，不直接改生产。
- 视觉模型只负责图片观察和三圈识别；Lite / Pro 报告正文仍走 knowledge-first 本地主链。
- 如果 Qwen 失败，统一 LLM runtime 会尝试豆包 fallback；如果两者都失败，则回到低置信度默认三圈建议，并由产品侧引导用户重试或手动三圈。

## 2. 为什么文字模型可以先定

文字模型当前更适合先固定 DeepSeek V4，原因是：

- 文字报告与追问的主要风险是表达质量、边界感、稳定性和成本。
- DeepSeek 已经在 RelayHub 模型库中作为国产正式候选存在。
- Aimandala 后端已经支持按 `AIMANDALA_LLM_MODEL / AIMANDALA_LLM_CHAT_MODEL` 做环境级配置。
- 文字任务不依赖图片理解质量，可以先独立进入 MVP 运行验证。

## 3. 为什么视觉模型现在可以进入本地 / staging 默认接入

视觉模型此前不能直接定，原因是：

- Aimandala 的视觉任务不是普通图片描述，而是三圈识别。
- 三圈识别需要关注中心、边界、颜色块、结构层次和明显偏移。
- 不同国产视觉模型在绘画类图片上的可靠性差异可能很大。
- 单纯看通用榜单或厂商宣传，不能替代本项目样本测试。

现在可以进入本地 / staging 默认接入，原因是：

- 已完成 9 图 x 3 轮稳定性评测。
- 已完成人工细看，`qwen-vl` 和豆包进入最终候选，GLM 不进入默认候选。
- 已完成后端 3 图端到端 smoke。
- 已完成前端 runtime smoke。
- 已完成解读流派保真 QA Gate。
- 已完成 MVP 最终 3 图复测，3/3 `detect.method=llm_vision`，Lite / Pro 均通过。

通俗说：

- 文字模型看的是“会不会说得准、说得稳”
- 视觉模型看的是“能不能真正看懂这张画的结构”

## 4. 当前候选范围与结论

本轮只测试国产或国产可控入口。

已完成测试的主候选：

- 豆包视觉模型
- 通义千问视觉模型
- 智谱 GLM 视觉模型

当前结论：

- 默认：`qwen-vl-max-latest`
- fallback：豆包 `ep-20260316095322-94wf5`
- 暂不进入默认候选：GLM
- 暂不纳入本轮：Kimi，原因是本机私有 env 缺少有效 `MOONSHOT_API_KEY`，且候选配置缺少已验证真实 model id

后续新增候选仍必须满足：

- 支持图片输入
- 支持中文输出
- 可用于生产用户数据主链路
- 有稳定 API 与明确计费方式
- 可以在 Aimandala 后端或 RelayHub 中形成可复现调用

## 5. 当前不做

- 不用第三方中转承接生产用户图片主链路。
- 不用国外闭源视觉模型作为 MVP 默认生产候选。
- 不用单张图片或单次主观感觉决定模型。
- 不把视觉模型评测扩大成完整心理诊断能力评测。
- 不要求本轮同时完成 RelayHub eval-sidecar 产品化。
- 不直接修改生产环境模型配置。

## 6. 配置方向

Aimandala 后端当前已支持：

- `AIMANDALA_LLM_MODEL`
- `AIMANDALA_LLM_CHAT_MODEL`
- `AIMANDALA_LLM_VISION_MODEL`
- `AIMANDALA_LLM_VISION_FALLBACK_MODEL`

MVP 本地 / staging 配置方向：

```bash
AIMANDALA_LLM_BACKEND=openai_compatible
AIMANDALA_LLM_MODEL=deepseek-v4-pro
AIMANDALA_LLM_CHAT_MODEL=deepseek-v4-pro
AIMANDALA_LLM_VISION_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
AIMANDALA_LLM_VISION_MODEL=qwen-vl-max-latest
AIMANDALA_LLM_VISION_API_KEY=<DASHSCOPE_API_KEY>
AIMANDALA_LLM_VISION_FALLBACK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
AIMANDALA_LLM_VISION_FALLBACK_MODEL=ep-20260316095322-94wf5
AIMANDALA_LLM_VISION_FALLBACK_API_KEY=<DOUBAO_API_KEY>
```

生产配置必须单独走 production change record，不直接复用本地 / staging 改动。

## 7. 失败降级策略

视觉识别按以下顺序降级：

1. 优先调用 Qwen：`AIMANDALA_LLM_VISION_*`。
2. Qwen 请求失败、空响应或 JSON 解析失败时，自动尝试豆包：`AIMANDALA_LLM_VISION_FALLBACK_*`。
3. Qwen 与豆包都失败时，后端返回低置信度 `method=llm_fallback`，使用默认三圈 `inner=0.33 / middle=0.66`。
4. detector backend 未配置、图片不存在或上传失败时，返回 `method=default`。

产品侧口径：

- `llm_vision`：可自动进入报告。
- `llm_vision_estimated`：可进入报告，但视为估计结果。
- `llm_fallback` / `default`：不作为高可信自动识别，应提示用户手动三圈或重试。
