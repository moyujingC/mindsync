## 5. 本次发现的问题

### 5.1 后端最小依赖文档不够完整

实际启动时额外需要：

- `numpy`
- `opencv-python-headless`

仅依赖原 README 中最小列表，服务无法成功启动。

### 5.2 前端默认 API 基地址仍偏向直连后端端口

当前构建时默认值仍偏向：

```bash
http://101.43.98.40:8000
```

后续应收口到反代入口，避免前端同时依赖 `80` 和 `8000` 两种访问口径。

### 5.3 一键部署脚本仍有一个小缺口

当前脚本中的部署完成时间输出已记录，但仍建议下一轮把：

- 时间输出格式
- API 基地址
- 依赖安装策略

进一步收口成更稳定的运维脚本。

## 6. 本次交付结论

当前 `aimandala` 的开发测试机已经达到：

1. 可从远程仓库拉取 `main`
2. 可常驻运行后端 API
3. 可通过 `nginx` 对外提供前端与 API
4. 可通过一条脚本执行最小更新部署

这意味着后续可以继续在这台机器上：

- 做联调
- 做 smoke test
- 作为 `main` 的默认开发环境

正式机仍需后续单独接入，不应直接复用开发测试机当前目录和服务名。
