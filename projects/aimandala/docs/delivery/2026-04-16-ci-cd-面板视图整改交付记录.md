## 1. 本轮交付内容

本轮先完成 CI/CD 面板问题的正式收束，而不是直接在聊天里讨论：

1. 新增 `spec`
   - 明确 workflow 面板应服务“当前健康度”而不是“历史失败清偿”
2. 新增 `task`
   - 明确展示层、判断层、issue 联动层的整改范围
3. 新增 `qa basis`
   - 明确最新失败、旧失败被覆盖、连续失败、基础设施阻塞四类验收场景

## 2. 当前正式结论

结合现有 `Paperclip` 面板样本，当前问题已正式定义为：

1. workflow 面板错误地把历史 run 线性摊平成当前问题列表
2. 这导致旧红灯长期占据用户注意力
3. 该问题不应通过“要求人工把所有旧失败逐个修完”来解决
4. 正确方向是把旧失败降级为历史记录，把当前失败和持续失败保留为首屏信号

## 3. 后续 handoff

下一棒更适合交给：

1. `Engineer`
   - 在 `paperclip` UI 实现 summary + recent window + history collapse
2. `Test / QA`
   - 用最新失败、旧失败被覆盖、连续失败、基础设施阻塞四类样本做回归

## 4. 当前残留风险

1. 本轮尚未直接改 `paperclip` 前端代码
2. 真实 UI 改造仍需在 `paperclip` 仓库中实施
3. 如果实现时没有把“被覆盖的历史失败”与“持续失败”严格区分，仍可能回到旧问题
