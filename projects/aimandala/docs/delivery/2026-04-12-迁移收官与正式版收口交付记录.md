## 1. 本轮交付结论

截至 `2026-04-12`，`aimandala` 已完成：

1. 主工作区迁移完成
2. 新生成 Lite / Pro 正式主链收口
3. upload contract、structured schema、release 默认口径收口
4. 旧仓库降级为历史参考，不再承接新开发
5. `release -> prod` 真实部署与公网业务烟测已完成

这意味着后续新的功能开发，应直接在 `mindsync/projects/aimandala` 上继续推进。
当前“可继续在新版本开发”与“生产环境已完全达到正式目标配置”两者均已成立。

## 2. 本轮交付内容

### 2.1 生成链路

- Lite / Pro 正式链路固定为 `PromptBuilder + schema + PromptBackedReportGenerationRuntime + Unified LLM client`
- deterministic runtime 保留为开发/QA/失败场景下的 fallback
- `report-debug` 继续暴露 fallback 与 evidence 摘要，作为质量观察入口

### 2.2 structured contract

- 后端新增 structured report 单一权威入口
- `report_contracts` 统一从该入口组装 Lite / Pro `report.structured`
- 前端 shared types 已同步 `prompt_preview` 与新增 contract 语义

### 2.3 上传与部署

- 上传正式契约固定为 `image_path / image_url / storage_backend / storage_key / image_local_expires_at`
- `release` 默认口径收为：
  - `AIMANDALA_LLM_BACKEND=openai_compatible`
  - `AIMANDALA_UPLOAD_BACKEND=cos`
  - `VITE_AIMANDALA_API_BASE_URL=https://web-api.jingshu.cc`
  - `AIMANDALA_COS_SIGNED_URL_TTL_SECONDS=900`
  - `AIMANDALA_ENABLE_DEBUG_WORKBENCH=0`
- workflow/runbook/docker README 已统一 smoke check 与回退说明
- 当前公开入口 smoke check 已验证：
  - `https://web-api.jingshu.cc/health` healthy
  - `https://web.jingshu.cc` 返回 `200 OK`
- 当前公网真实业务链路已验证：
  - `upload-image`
  - `create interpretation`
  - Lite `report`
  - Pro `upgrade + report`
  - `history` 读取
- 当前公网签名 URL 主链已验证：
  - 上传返回 `https://img.jingshu.cc/...?...` 短期签名 URL
  - 直接下载签名 URL 返回 `200`
  - `status / report / history / reopen` 读取都会返回新的签名 URL
- 当前生产环境已额外完成：
  - `AIMANDALA_LLM_BACKEND` 从 `noop` 切到 `openai_compatible`
  - `AIMANDALA_LLM_BASE_URL=https://api.moonshot.cn/v1`
  - `AIMANDALA_LLM_MODEL=moonshot-v1-auto`
  - `report chat` 已通过真实 LLM 返回内容
- 为完成这一步，额外补了两次线上修复：
  - Docker 镜像补拷 `toC/domain`
  - knowledge runtime 改为按实际目录标志解析 ToC 根，而不是写死 `parents[5]`
  - release 镜像补装 `cos-python-sdk-v5`
  - COS 私有读改为后端按 `storage_key` 签发短期 URL
  - 自定义域名 `img.jingshu.cc` 改为直接参与 COS 签名，而不是签后重写域名

## 3. 迁移口径更新

本轮之后，迁移完成的正确表述应是：

- 主工作区迁移完成
- 正式版主链收口完成
- 历史记录兼容读取保留
- 旧仓库仅作历史参考
- 新功能可以只在 `mindsync/projects/aimandala` 上继续开发

不应再表述为：

- 旧仓库仍是主开发入口
- 迁移尚未完成所以继续在旧仓库开发
- 等以后再决定 release 环境怎么配

## 4. 剩余风险

### 4.1 内容质量仍需继续打磨

本轮完成的是主链正式化，不是“质量完全终局”。

后续仍应继续观察：

- fallback hotspot
- warning case
- 知识质量与提示词质量

### 4.2 当前主要剩余风险

本轮之后，迁移与部署层面的主风险已经收口，剩余风险主要转为持续优化类：

1. Lite / Pro 内容质量仍需继续观察与打磨
2. fallback hotspot 与 warning case 仍需按后续版本持续压降
3. 签名 URL TTL、前端体验和调试可观测性后续还可以继续优化

## 5. 后续默认动作

从本轮之后，默认按下面方式推进：

1. 新功能直接在 `projects/aimandala` 开发
2. 继续遵守 `main -> dev`、`release -> prod`
3. 新一轮重要改动继续补 `task / qa / delivery`
4. 不再把旧仓库作为主开发或主发布入口
