## 1. 本轮交付目标

本轮目标是把批次 B 从“shared/ui 集成收束”进一步推进为：

1. 前端报告读取链路显式 report type 化
2. 历史记录不再单卡直开，而是经过记录详情页选择版本

## 2. 预期交付内容

- `getInterpretationReport()` 改为强制显式 `reportType`
- `refreshMobileWebReport()` 改为强制显式 `interpretationId + reportType`
- 新增 `history-record-detail` 页面/状态/descriptor
- history -> detail -> report 链路可用
- 对应测试与 README/文档入口同步

## 3. 本轮实际交付

### 3.1 报告读取链路显式化

- `getInterpretationReport(interpretationId, reportType)` 已改为强制显式传入 `reportType`
- `refreshMobileWebReport(interpretationId, reportType, currentState?)` 已改为强制显式传入 `reportType`
- 前端调用点已完成收束：
  - `loading -> report`
  - `history -> detail -> report`
  - 本地 preview / examples / loaders
- 当前不再保留“省略版本参数，由运行时自己猜一个默认报告”的行为

### 3.2 history / reopen 新链路

- 新增 `history-record-detail` 路由、descriptor 与 page shell
- `history` 列表项不再直接推导最终报告版本并直开
- `history` 点击后统一进入“同一画作的解读记录详情页”
- 在详情页中：
  - 明确展示当前可查看版本
  - 明确展示版本演进信息
  - 明确提供 `打开 Lite 报告` / `打开 Pro 报告` 动作
- 当 `Pro` 仍在生成中时：
  - 详情页展示 `Pro 生成中`
  - 打开 `Pro` 时进入对应 loading / progress 态，而不是隐式落到 Lite

### 3.3 最小数据补充

- 后端未重做持久化模型
- 仅在 `InterpretationRecordResponse` 中向后兼容补充 `upgrade_history`
- 前端详情页基于：
  - `version_purchased`
  - `upgrade_history`
  构建版本可用性与演进摘要
