## 1. 当前判断

新版曼陀罗解读智能体以“端到端直出 + 提示词缓存”为主线，不再以旧的多 stage 链路为设计中心。

最近的真实模型对照显示：

- 完整手册原文能显著提升报告的流派感、带读感和可读性。
- 过重的结构化视觉 JSON 会压扁画面信息，让报告像系统检测结果。
- 直接把中间层做成重 JSON 机器，会让视觉信息损失更多。

因此新版链路采用“端到端直出 + 轻量视觉草稿 + 稳定前缀缓存 + 质量门”的方式。

```text
用户原画作 + 三圈标记图 + 用户输入
  ↓
1. 视觉草稿生成
  ↓
2. 稳定前缀组装
  ↓
3. 报告端到端直出
  ↓
4. 质量门与人工可审阅产物
```

这条链路的目标是让报告像疗愈师带用户看画，同时保留必要的证据追溯、版本追踪和安全边界。

## 2. 用户价值

MVP Web 版要完成一件事：用户上传曼陀罗画作，确认三圈边界，选择 Lite 或 Pro 后，系统生成一份能让用户跟着画面看懂自己的财富议题解读报告。

报告要满足：

- 先带用户看见画面，而不是直接给结论。
- 呈现曼陀罗流派特色，包括三圈、圈内五行、元素关系和三圈能量流动。
- 财富是主议题，情绪、关系、家庭、身体、事业等只作为画面中浮现的背景线索融入三圈解读。
- 不做财务预测、投资建议、心理诊断或确定性人生判断。
- Lite 和 Pro 都是收费交付，Lite 不能做成轻飘的摘要。

## 3. 模块边界

### 3.1 视觉草稿生成

职责：把画面看清楚，形成可继续解读的高质量观察草稿。

输入：

- 用户原画作。
- 三圈标记图，用于辅助确认内圈、中圈、外圈边界。
- 必要时可输入完整手册原文片段，帮助模型保持曼陀罗式观察方式。

输出：`visual_draft`。

建议结构：

```json
{
  "visual_draft": {
    "overall_impression": "",
    "main_visual_content": "",
    "circle_observations": {
      "inner": "",
      "middle": "",
      "outer": "",
      "cross_circle_connection": ""
    },
    "visual_units": [
      {
        "id": "inner-001",
        "circle": "inner",
        "name": "",
        "visual_description": "",
        "color": "",
        "shape": "",
        "texture": "",
        "position_relation": "",
        "blank_space_role": "",
        "estimated_area_ratio": 0
      }
    ]
  }
}
```

设计原则：

- 视觉草稿要富描述，不追求字段越多越好。
- 保留三圈和视觉单元，是为了后续引用，不是为了把画面切碎。
- `position_relation` 要写当前视觉单元与相邻元素、留白、同类重复元素之间的关系。
- `estimated_area_ratio` 只是当前圈内的粗略面积占比，用于后续判断能量强弱，不当作精确测量。
- 留白只要在画作最外边界以内，就是画作内容，后续五行按金处理。

不做：

- 不输出财富、关系、身体、心理或疗愈解释。
- 不判断整圈五行。
- 不把模板黑线、印刷线稿和三圈标记线当成画作元素。
- 不输出会干扰下游报告的 `uncertainties`、`excluded_marks`、`metal_candidate`。

### 3.2 稳定前缀组装

职责：把长期稳定不变的材料组合成版本化 prompt pack，供下游模型缓存。

输入：

- 完整手册原文的稳定片段
- 财富议题 routing 规则
- 报告语言风格指南
- 安全边界
- 报告模板骨架

输出：`prompt_pack`。

原则：

- 稳定前缀只放长期不变的内容。
- prompt pack 要版本化，便于回归和 cache 命中跟踪。
- 不把用户图片、用户问题和本次视觉草稿塞进稳定前缀。
- 前缀顺序要长期固定，才能提高缓存命中率。

建议目录：

```text
prompt_packs/
  wealth-report-v1.0.0/
    manifest.json
    00-system.md
    10-mandala-manual.md
    20-wealth-topic-rules.md
    30-style-guide.md
    40-safety-boundary.md
    50-output-contract.md
```

### 3.3 端到端直出报告

职责：在单次文字模型调用中，结合视觉草稿、稳定前缀和用户输入直接生成最终报告。

输入：

- `visual_draft`
- `prompt_pack`
- 用户主题与意图
- 报告版本（Lite / Pro）
- 完整手册原文的锚定内容

输出：

- `final_report_md`
- `final_report`

原则：

- 报告层是主输出层，目标是直接交付给用户。
- 输出要像疗愈师带着用户看画，而不是系统检测报告。
- 允许引用视觉草稿中的观察，但不能照抄成机械字段。
- 允许用 prompt cache 降低稳定前缀成本，但不能依赖缓存返回决定业务逻辑。
- `thinking` 只作为模型参数，不作为业务依赖和中间产物落盘依据。

### 3.4 曼陀罗基础判断

职责：如果后续还需要调试和校验，可以把视觉草稿翻译成曼陀罗基础层语言，用于内部 QA，不作为主链路必经产物。

输入：

- `visual_draft`。
- 曼陀罗基础层知识：
  - 画面识别与描述
  - 圈内五行解读
  - 圈内五行生克与失衡
  - 三圈能量流动

输出：`foundation_reading`。

建议结构：

```json
{
  "foundation_reading": {
    "element_sensing": [],
    "intra_circle_relations": [],
    "cross_circle_flow": [],
    "evidence_links": []
  }
}
```

边界：

- 五行只分析视觉单元，不给整圈贴单一五行。
- 圈内五行关系只分析同一圈内相邻或重叠的视觉单元。
- 如果两个视觉单元被留白隔开，不直接分析二者生克，而是分析 A 与留白、留白与 B。
- 三圈能量流动看结构、连续性、承接、断开、外散、内收和现实承接，不使用跨圈五行生克。
- 这一层仍不进入财富、关系、身体或心理解释。

### 3.5 质量门

职责：检查视觉草稿与最终报告是否越界，是否仍然保留流派感和证据链。

质量门不负责改写报告，只负责拦截风险和记录异常。

输入：

- `visual_draft`
- `prompt_pack`
- `final_report_md`
- `final_report`

## 4. 为什么不继续重结构化视觉层

当前视觉层如果继续强行扩展字段，会有三个问题：

- 画面被切得太碎，模型更像在填表。
- 视觉整体感、疗愈师式第一眼感受容易丢失。
- 后续报告层拿到的是干瘪字段，很难写出像人的报告。

但完全放弃结构化也不合适：

- 视觉错误难以审查。
- 五行和三圈判断缺少证据链接。
- 回归测试无法稳定比较。

所以视觉层采用轻结构：

- 三圈保留。
- 视觉单元保留。
- 位置关系保留。
- 面积占比保留为粗估。
- 其他字段减少，更多信息放进富描述。

## 5. prompt cache 管理原则

DeepSeek 的上下文缓存是前缀缓存。架构层要保证的是“稳定前缀包”的版本稳定和前缀顺序稳定，而不是手动控制缓存对象。

管理原则：

1. 稳定前缀包版本化
2. 同一版本内顺序固定
3. 用户输入始终放在动态区
4. 视觉草稿放在动态区
5. 报告版本 Lite / Pro 放在动态区
6. 每次输出记录 cache 命中情况，作为 QA 证据

不做：

- 不把整份 prompt 当作不可解释的大字符串。
- 不把用户输入塞进稳定前缀。
- 不把缓存结果当作业务判断依据。

## 6. 质量门

质量门不负责改写报告，只负责拦截风险。

必须检查：

- 是否使用真实视觉证据。
- 是否把模板黑线、标记线当成画作内容。
- 是否给整圈贴五行标签。
- 是否做跨圈五行生克。
- 是否把财富报告写成投资、财务预测或诊断。
- 是否泄漏内部流程词。
- 是否缺少三圈带读。
- 是否缺少曼陀罗流派特征。

质量门输出只进入开发和 QA，不进入用户报告。

## 7. 当前代码影响

当前后端仍有这些模块：

- `app/core/mandala_interpretation_agent/agent.py`
- `app/core/mandala_interpretation_agent/prompts/vision/observe_visual.md`
- `app/core/mandala_interpretation_agent/prompts/foundation/analyze_from_visual.md`
- `app/core/mandala_interpretation_agent/prompts/report/write.md`
- `app/core/mandala_interpretation_agent/quality_gate.py`

下一轮实现时，不应继续补旧 stage，而应把运行时合同改成：

```text
visual_draft
prompt_pack
final_report
quality_gate
```

当前已有实验脚本：

- `projects/aimandala/toC/app/backend/scripts/run_manual_source_wealth_report_experiment.py`

该脚本证明完整手册原文可作为报告写作锚点。后续可新增同类实验脚本验证“手册原文辅助视觉观察”的稳定性。

## 8. 不做范围

当前不做：

- 旧报告链路兼容层。
- 旧 16 stage 继续扩展。
- 小程序旧链路清理。
- 支付、订单、历史和追问能力重构。
- 通用解读主题扩展。
- 让基础判断直接输出心理、疗愈、身体、财富、关系或事业结论。
- 把 11 个案例经验当成完整映射总表。

## 9. 验收口径

新版链路成立，需要满足：

- 视觉草稿能准确描述画面，不复述旧案例文本。
- 视觉草稿有整体感，不只是字段表。
- 视觉单元能支持后续理解和回归，不要求重 JSON 化。
- 报告层能稳定直出财富主线。
- prompt cache 命中逻辑清晰、可追踪。
- 稳定前缀包版本可追溯。
- 报告像疗愈师带用户看画，而不是只给结论。
- Lite / Pro 都达到收费交付水准。
