## 2. 用户价值

MVP Web 版要完成一件事：用户上传曼陀罗画作，确认三圈边界，选择财富议题报告后，系统生成一份能让用户跟着画面看懂自己的 Lite / Pro 解读报告。

报告要满足：

- 先让用户看到画面事实，而不是直接给结论。
- 展示曼陀罗流派的特色，包括三圈、圈内五行、元素关系和跨圈能量。
- 财富是主议题，情绪、关系、家庭、身体、事业等只作为从画面中浮现的背景线索融入三圈解读。
- 不做财务预测、投资建议、心理诊断或确定性人生判断。

## 3. 新版生成链路

新版链路按“少调用、少丢失视觉信息”的原则组织。视觉大模型在基础层只调用一次，同时看到用户原画作和三圈标记图；这一次调用完成从画面事实到曼陀罗基础层语言的翻译。

```text
用户原画作 + 三圈标记图 + 用户输入
  ↓
1. 基础层图像解读
   - 画面观察
   - 圈内五行识别
   - 圈内五行关系
   - 三圈能量流动
  ↓
2. 主议题与浮现议题翻译
  ↓
3. 报告主轴选择
  ↓
4. Lite / Pro 报告写作
  ↓
5. 质量门与可审阅产物
```

基础层图像解读只做“画面视觉语言 -> 曼陀罗基础层语言”的翻译。它可以判断五行识别、同圈五行关系和三圈能量流动，但不进入心理学、疗愈、身体、财富、关系、事业等议题解释。

后续议题翻译层才负责把基础层结论翻译到财富主议题和浮现议题。报告写作层再把翻译结果组织成用户能阅读的 Lite / Pro 报告。

## 4. 中间数据分层

### 4.1 基础层图像解读

输入：

- 用户原画作。
- 三圈标记图，仅用于辅助确认内圈、中圈、外圈边界。
- 用户确认的三圈边界数据。
- 曼陀罗基础层知识：画面识别、颜色/形状感知、五行感知、五行生克、失衡类型、三圈结构法。

输出建议对象：`foundation_image_reading`。

该对象包含四个分区。

#### 4.1.1 画面观察

输出：

- `overall_observation`：整幅画的整体感受、主要视觉内容、明暗、疏密、动势和视觉重心。
- `three_circle_observation`：内圈、中圈、外圈分别画了什么，以及三圈之间如何连接或断开。
- `circle_visual_units`：逐圈视觉单元，包括颜色、形状、大小、重复、密度、笔触、留白、同类元素排列、相邻、包围、切分和隔开关系。

边界：

- 模板黑线、印刷线稿和三圈标记线不作为视觉单元。
- 留白是画作内容，进入视觉单元；后续五行一律按金处理。
- 不输出心理、财富、关系、身体或疗愈判断。
- 不需要把排除项和不确定项传给后续报告生成，避免干扰下游解读；必要时只在审核产物里保留。

#### 4.1.2 圈内五行识别

输出：

- 每个视觉单元的五行候选。
- 五行依据：颜色、形状、留白、方向、结构、重复、深浅、笔触或密度。
- 置信度和证据引用。

边界：

- 不给整圈判定单一五行。
- 五行只分析圈内元素。
- 留白、真实白色、色块缝隙按金处理。
- 模板黑线和三圈标记线不进入五行判断。
- 不把五行结论翻译成心理、疗愈、身体或财富含义。

#### 4.1.3 圈内五行关系

输出：

- 同一圈内部的相生、相克、被切分、包围、隔开、无根、失衡或循环不起来等候选。
- 每条关系必须引用对应视觉单元。
- 若关系依赖“是否相邻”“是否隔开”“是否有留白切分”，必须写清视觉依据。

边界：

- 不做跨圈五行生克。
- 不把元素关系写成用户心理结论。
- 如果缺少相邻关系证据，就不能强行判断生克或无根。

#### 4.1.4 三圈能量流动

输出：

- 内圈、中圈、外圈之间的承接、断裂、外散、内收、压住、包围、现实层承接等判断。
- 每条判断引用三圈视觉事实或圈内基础层结果。

边界：

- 三圈联动使用三才和圈层语义，不使用五行生克替代。
- 可以引用圈内元素状态作为证据，但不能写成“内圈某五行克外圈某五行”。
- 不翻译为财富、关系、身体或心理结论。

建议 JSON 骨架：

```json
{
  "foundation_image_reading": {
    "visual_observation": {},
    "element_sensing": {},
    "intra_circle_relations": {},
    "cross_circle_flow": {},
    "evidence_links": []
  }
}
```

`evidence_links` 用来保证基础层判断可追溯。每条五行识别、圈内关系和三圈流动判断都应能回指到视觉单元或三圈观察。

### 4.2 主议题与浮现议题翻译

输入：

- `foundation_image_reading`。
- 主议题翻译层，MVP 先是财富。
- 浮现议题翻译层，当前可先使用框架和 AI draft，后续补来源验证。

输出：

- 财富主线解释：金钱、价值、资源、交换、承接、边界、行动。
- 浮现线索：关系、家庭、情绪、身体、事业等背景线索。
- 每条翻译必须回到画面证据和基础层判断。

边界：

- 浮现议题不单独做成报告章节，而是融入对应三圈。
- 主议题仍然是财富，报告最后要收束回财富议题。

### 4.3 报告主轴选择

输入：

- `foundation_image_reading`。
- 财富翻译和浮现议题线索。

输出：

- `entry_circle`：从哪个圈切入。
- `entry_signal`：从哪个画面信号开始讲。
- `narrative_order`：三圈叙事顺序。
- `core_thesis`：整篇报告主轴。
- `integrated_context_threads`：需要融入三圈的浮现线索。

这一层决定报告像不像疗愈师带用户看画。它不应机械固定为内圈、中圈、外圈顺序。

### 4.4 Lite / Pro 报告写作

Lite 和 Pro 都是收费交付，不应把 Lite 做得太轻。

Lite 当前应提供：

- 画面证据速写。
- 圈内五行感知。
- 财富主线解读。
- 三圈中最关键的承接关系。
- 一个低风险行动建议。
- 一个下一次探索方向。

Pro 应在 Lite 基础上加码：

- 更完整的三圈带读。
- 更清楚的圈内元素关系。
- 更深的财富机制拆解。
- 更丰富的浮现线索融入。
- 2 到 3 个行动建议。
- 1 到 2 个下一次曼陀罗探索建议。

## 6. 后续重构方向

下一步不应继续围绕旧 16 stage 做小修小补，而应把代码合同逐步改成新版链路的数据对象。

建议拆成三轮：

1. 定义 `foundation_image_reading` schema：一次视觉模型调用，分区输出画面观察、五行识别、圈内关系、三圈能量流动和证据链接。
2. 重写视觉 prompt：输入原图和三圈标记图，任务限定为基础层图像解读，不进入心理、疗愈、身体或财富议题解释。
3. 调整报告写作输入：让 Lite / Pro 只读取 `foundation_image_reading`、财富议题翻译和浮现议题线索。

旧 `stage-*` 可以在过渡期继续作为 artifact 文件名，但不再作为方法论来源。等新版数据对象稳定后，再删除或重命名旧 stage 合同。

## 7. 不做范围

当前不做：

- 旧报告链路兼容层。
- 通用解读主题扩展。
- 小程序旧链路清理。
- 支付、订单、历史和追问能力重构。
- 让视觉模型直接生成整份报告。
- 让基础层图像解读直接生成心理、疗愈、身体、财富、关系或事业结论。
- 把 11 个案例经验当成完整映射总表。

## 8. 验收口径

后续判断新链路是否成立，至少看：

- 视觉识别是否能准确描述画面，而不是复述旧案例文本。
- 圈内五行是否按元素判断，而不是给整圈贴标签。
- 同圈生克是否有位置关系证据。
- 三圈联动是否不用跨圈五行生克。
- 财富报告是否有主线，同时允许关系、家庭、情绪等线索融入三圈。
- 报告是否像带用户看画，而不是只给结论。
- Lite / Pro 是否都达到收费交付水准。
