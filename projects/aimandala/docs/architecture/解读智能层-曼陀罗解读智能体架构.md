## 1. 当前判断

新版曼陀罗解读智能体不再以旧的多 stage 链路为设计中心。

最近的真实模型对照显示：

- 完整手册原文能显著提升报告的流派感、带读感和可读性。
- 过重的结构化视觉 JSON 会压扁画面信息，让报告像系统检测结果。
- 完全直出虽然自然，但容易补细节，缺少可校验性。

因此新版链路采用“轻结构 + 手册锚定 + 质量门”的方式。

```text
用户原画作 + 三圈标记图 + 用户输入
  ↓
1. 视觉观察草稿
  ↓
2. 曼陀罗基础判断
  ↓
3. 议题翻译与报告主轴
  ↓
4. 完整手册原文锚定写作
  ↓
5. 质量门与人工可审阅产物
```

这条链路的目标是让报告像疗愈师带用户看画，同时保留必要的证据追溯和安全边界。

## 2. 用户价值

MVP Web 版要完成一件事：用户上传曼陀罗画作，确认三圈边界，选择 Lite 或 Pro 后，系统生成一份能让用户跟着画面看懂自己的财富议题解读报告。

报告要满足：

- 先带用户看见画面，而不是直接给结论。
- 呈现曼陀罗流派特色，包括三圈、圈内五行、元素关系和三圈能量流动。
- 财富是主议题，情绪、关系、家庭、身体、事业等只作为画面中浮现的背景线索融入三圈解读。
- 不做财务预测、投资建议、心理诊断或确定性人生判断。
- Lite 和 Pro 都是收费交付，Lite 不能做成轻飘的摘要。

## 3. 模块边界

### 3.1 视觉观察草稿

职责：把画面看清楚，形成可继续解读的高质量观察草稿。

输入：

- 用户原画作。
- 三圈标记图，用于辅助确认内圈、中圈、外圈边界。
- 必要时可输入完整手册原文或视觉观察说明，帮助模型保持曼陀罗式观察方式。

输出：`visual_draft`。

建议结构：

```json
{
  "visual_draft": {
    "overall_impression": "",
    "main_visual_content": "",
    "circle_observations": {
      "inner": "",
      "middle": "",
      "outer": "",
      "cross_circle_connection": ""
    },
    "visual_units": [
      {
        "id": "inner-001",
        "circle": "inner",
        "name": "",
        "visual_description": "",
        "color": "",
        "shape": "",
        "texture": "",
        "position_relation": "",
        "blank_space_role": "",
        "estimated_area_ratio": 0
      }
    ]
  }
}
```

设计原则：

- 视觉草稿要富描述，不追求字段越多越好。
- 保留三圈和视觉单元，是为了后续引用，不是为了把画面切碎。
- `position_relation` 要写当前视觉单元与相邻元素、留白、同类重复元素之间的关系。
- `estimated_area_ratio` 只是当前圈内的粗略面积占比，用于后续判断能量强弱，不当作精确测量。
- 留白只要在画作最外边界以内，就是画作内容，后续五行按金处理。

不做：

- 不输出财富、关系、身体、心理或疗愈解释。
- 不判断整圈五行。
- 不把模板黑线、印刷线稿和三圈标记线当成画作元素。
- 不输出会干扰下游报告的 `uncertainties`、`excluded_marks`、`metal_candidate`。

### 3.2 曼陀罗基础判断

职责：把视觉草稿翻译成曼陀罗基础层语言。

输入：

- `visual_draft`。
- 曼陀罗基础层知识：
  - 画面识别与描述
  - 圈内五行解读
  - 圈内五行生克与失衡
  - 三圈能量流动

输出：`foundation_reading`。

建议结构：

```json
{
  "foundation_reading": {
    "element_sensing": [],
    "intra_circle_relations": [],
    "cross_circle_flow": [],
    "evidence_links": []
  }
}
```

边界：

- 五行只分析视觉单元，不给整圈贴单一五行。
- 圈内五行关系只分析同一圈内相邻或重叠的视觉单元。
- 如果两个视觉单元被留白隔开，不直接分析二者生克，而是分析 A 与留白、留白与 B。
- 三圈能量流动看结构、连续性、承接、断开、外散、内收和现实承接，不使用跨圈五行生克。
- 这一层仍不进入财富、关系、身体或心理解释。

### 3.3 议题翻译与报告主轴

职责：把基础判断翻译到用户选择的议题，并决定报告从哪里讲起。

MVP 主议题：财富。

输入：

- `visual_draft`
- `foundation_reading`
- 财富议题翻译层
- 浮现议题翻译框架
- 用户输入的意图和感受

输出：`report_plan`。

建议结构：

```json
{
  "report_plan": {
    "theme": "wealth",
    "entry_circle": "",
    "entry_signal": "",
    "core_thesis": "",
    "narrative_order": [],
    "wealth_translation_points": [],
    "emergent_threads": [],
    "next_exploration_candidates": []
  }
}
```

原则：

- 主议题是财富，报告要收束到财富。
- 浮现议题不单独拉成独立章节，而是融入三圈带读。
- 中圈在财富报告中优先看情绪、关系、交换、价值感、边界和资源流动，不预设为父亲、母亲或亲密关系。
- 下一次探索建议来自本次画面暴露但未展开的卡点，可以推荐 1 到 2 个方向。

### 3.4 完整手册原文锚定写作

职责：生成用户可见的 Lite / Pro Markdown 报告。

输入：

- 用户原画作。
- `visual_draft`。
- `foundation_reading`。
- `report_plan`。
- 完整手册原文。
- Lite / Pro 交付口径。
- 报告安全边界。

输出：

- `final_report_md`
- `final_report`

写作原则：

- 报告写作层必须使用完整手册原文作为流派和语言锚点。
- 报告要像疗愈师带用户看画，而不是像自动检测报告。
- 写作可以引用视觉草稿和基础判断，但不能机械照搬 JSON 字段。
- 不要泄漏 stage、schema、prompt、quality gate 等内部词。
- 不做财务预测、投资建议、心理诊断或治疗承诺。

Lite 应包含：

- 整体画面带读。
- 关键三圈解读。
- 必要的圈内五行感知。
- 财富主线解释。
- 1 到 2 个温和行动建议。
- 1 个下一次曼陀罗探索方向。

Pro 应在 Lite 基础上加码：

- 更完整的三圈带读。
- 更细的圈内元素关系。
- 更清楚的财富机制拆解。
- 更自然地融入浮现议题线索。
- 2 到 3 个行动建议。
- 1 到 2 个下一次探索方向。

## 4. 为什么不继续重结构化视觉层

当前视觉层如果继续强行扩展字段，会有三个问题：

- 画面被切得太碎，模型更像在填表。
- 视觉整体感、疗愈师式第一眼感受容易丢失。
- 后续报告层拿到的是干瘪字段，很难写出像人的报告。

但完全放弃结构化也不合适：

- 视觉错误难以审查。
- 五行和三圈判断缺少证据链接。
- 回归测试无法稳定比较。

所以视觉层采用轻结构：

- 三圈保留。
- 视觉单元保留。
- 位置关系保留。
- 面积占比保留为粗估。
- 其他字段减少，更多信息放进富描述。

## 5. 质量门

质量门不负责改写报告，只负责拦截风险。

必须检查：

- 是否使用真实视觉证据。
- 是否把模板黑线、标记线当成画作内容。
- 是否给整圈贴五行标签。
- 是否做跨圈五行生克。
- 是否把财富报告写成投资、财务预测或诊断。
- 是否泄漏内部流程词。
- 是否缺少三圈带读。
- 是否缺少曼陀罗流派特征。

质量门输出只进入开发和 QA，不进入用户报告。

## 6. 当前代码影响

当前后端仍有这些模块：

- `app/core/mandala_interpretation_agent/agent.py`
- `app/core/mandala_interpretation_agent/prompts/vision/observe_visual.md`
- `app/core/mandala_interpretation_agent/prompts/foundation/analyze_from_visual.md`
- `app/core/mandala_interpretation_agent/prompts/report/write.md`
- `app/core/mandala_interpretation_agent/quality_gate.py`

下一轮实现时，不应继续补旧 stage，而应把运行时合同改成：

```text
visual_draft
foundation_reading
report_plan
final_report
quality_gate
```

当前已有实验脚本：

- `projects/aimandala/toC/app/backend/scripts/run_manual_source_wealth_report_experiment.py`

该脚本证明完整手册原文可作为报告写作锚点。后续可新增同类实验脚本验证“手册原文辅助视觉观察”的稳定性。

## 7. 不做范围

当前不做：

- 旧报告链路兼容层。
- 旧 16 stage 继续扩展。
- 小程序旧链路清理。
- 支付、订单、历史和追问能力重构。
- 通用解读主题扩展。
- 让基础判断直接输出心理、疗愈、身体、财富、关系或事业结论。
- 把 11 个案例经验当成完整映射总表。

## 8. 验收口径

新版链路成立，需要满足：

- 视觉草稿能准确描述画面，不复述旧案例文本。
- 视觉草稿有整体感，不只是字段表。
- 视觉单元能支持后续五行判断。
- 圈内五行按视觉单元判断，不给整圈贴标签。
- 圈内生克有相邻、重叠、留白隔开等位置证据。
- 三圈联动不使用跨圈五行生克。
- 财富报告有主线，同时允许关系、家庭、情绪等线索融入三圈。
- 报告像疗愈师带用户看画，而不是只给结论。
- Lite / Pro 都达到收费交付水准。
