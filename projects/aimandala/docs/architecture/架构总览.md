这份文档给 `aimandala` 当前架构材料提供一个总览入口。

它主要回答：

1. 当前主系统由哪几块组成
2. 每一块应该看哪份文档
3. 哪些部分已经落地，哪些仍是下一阶段

## 3. 与 spec / runbook / qa 的边界

- `spec`
  - 回答做什么、验收什么
- `architecture`
  - 回答系统怎么拆、运行时怎么组织、为什么这样分层
- `runbook`
  - 回答怎么部署、怎么联调、怎么处理运行事件
- `qa`
  - 回答当前是否验证通过、风险还剩什么

## 4. 当前最容易混淆的点

- `mandala_interpretation_agent` 已经落地到离线原型，不代表线上默认报告链已经切换
- `wealth_report` 仍在当前代码树中，是现有主链的一部分；`mandala_interpretation_agent` 是并行重建的新链
- CI 现在是“双层口径”：
  - `mvp-ci` 管日常最小放行
  - `aimandala-ci + deploy + nightly-smoke + auto-repair` 管增强验证和自动化治理
