这里是 `一镜一梳 / aimandala` 的曼陀罗解读知识库入口。

本知识库从当前版本重新建设，采用独立的数据结构、文档组织方式和运行架构。知识库名称不使用版本号；版本号只用于标识当前知识系统的发布阶段。

## 1. 定位

本知识库用于沉淀曼陀罗解读体系，包括：

- 曼陀罗画面分析方法
- 画面特征到解读条目的映射关系
- 议题层知识与疗愈解释框架
- 疗愈方案、行动建议和执行规范
- 后续可扩展的参考文献与理论来源

它当前是 `docs/sources/` 下的源资料与知识整理入口，不直接等同于产品 `spec`、技术 `architecture` 或运行时 `pack`。

## 2. 主要应用场景

本知识库后续主要服务三类产品能力：

1. 生成解读报告。当前不在知识库入口绑定 Lite、Pro 或其他具体报告版本，避免未来报告形态扩展时反复改动知识源结构。
2. 支持用户围绕解读报告继续追问。知识库需要保留足够清晰的概念、判断依据和解释链路，方便 AI 回答用户的后续问题。
3. 生成定制化疗愈方案。知识库需要把画面特征、议题判断和疗愈建议建立可追溯关系，支撑个体化行动建议。

## 3. 版本编号

知识库版本采用 `major.minor.patch`（大版本.小版本.修订版）编号，并允许在正式稳定前使用 `alpha`、`beta`、`rc` 这类阶段标记。

当前建议从 `1.0.0-alpha` 开始：

- `1.0.0-alpha`：体系建设期，结构和条款仍在快速调整。
- `1.0.0-beta`：主要议题、画面映射和疗愈方案已经成型，进入生成测试。
- `1.0.0`：第一版可稳定用于报告生成、追问回答和疗愈方案生成。
- `1.1.0`：新增议题、场景或能力，但不破坏已有结构。
- `1.1.1`：修正文案、链接、字段或少量条款，不改变结构。
- `2.0.0`：数据结构、推理链路或运行时协议发生不兼容变化。

更完整的编号规则见 [KB-00-02-知识库版本编号规则.md](KB-00-02-知识库版本编号规则.md)。

## 5. 协作规则

在这个目录中工作时，默认遵守：

- 先读本 README，再读 [KB-00-体系框架.md](KB-00-体系框架.md)。
- 新增内容应落在对应 `KB-*` 目录，不把不同层级混写到同一文档。
- 每份知识文档应尽量保留 `状态`、`版本`、`date`、`owner`、`source_of_truth` 等元信息。
- 引入理论、人名、流派或参考资料时，应尽量放入 `参考文献/` 或在正文中标注来源。
- 不把一次性讨论、临时 prompt、排障记录混入知识库正文。
- 从来源材料整理出的内容默认采用“原文保真重组”：尽量保留原文措辞和一线经验，只调整结构、标题和顺序。

## 6. 不适合放在这里的内容

- 当前产品需求和验收标准，应放入 `projects/aimandala/docs/specs/`。
- 技术架构和运行时实现方案，应放入 `projects/aimandala/docs/architecture/`。
- 任务计划、QA 记录和交付说明，应分别放入 `tasks/`、`qa/`、`delivery/`。
- 运行时可消费的数据文件，应放入 `projects/aimandala/toC/data/knowledge/`。

## 7. 当前状态

当前知识库仍处于草稿建设期。当前优先目标是先建立清晰、可持续维护的知识结构，再逐步补齐每个模块的内容密度和引用依据。
