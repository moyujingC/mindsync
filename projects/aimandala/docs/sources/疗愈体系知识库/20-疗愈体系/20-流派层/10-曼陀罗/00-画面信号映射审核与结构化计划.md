本文定义曼陀罗画面信号映射的审核、补全和结构化方式。

当前不是从零建设曼陀罗画面框架。`10-曼陀罗` 文件夹中的三圈结构法、画面分析基础、形状感知法、五行感知法、五行生克、暧昧色解读和疗愈方案经验，已经来自 `01-曼陀罗解读手册-来源索引.md` 指向的原始手册拆解，框架基本完整。

当前缺口是：这些自然语言条目还没有完成审核、覆盖检查、证据等级标注和结构化落表。后续工作应围绕“审核和结构化”推进，而不是把 11 个案例反推材料当成主框架。

框架来源：

- `10-画面语言/03-形状感知法.md`

- `20-五行与色彩/五行生克/*`

样本来源：

- `12-高频组合模式.md`
- `90-财富议题案例反推.md`

问题不是没有框架，而是样本来源容易被误用为完整映射依据。

当前风险是：

- `12-高频组合模式.md` 和 `90-财富议题案例反推.md` 来自 11 个原始案例，只能代表样本经验。

- 财富主题会被过早绑到少数组合模式上，导致漏判。

## 2. 审核目标

审核后的映射层要回答四个问题：

1. 这幅画里看见了什么。
2. 这些视觉特征属于哪一类画面信号。
3. 这些画面信号可能落到哪些议题条款。
4. 这些条款在财富、关系、事业、自我价值等主题里分别怎么用。

目标不是让单个信号直接推出结论，而是让不同画面构成都能先落到稳定信号，再进入组合判断和主题路由。

## 3. 需要审核和结构化的画面维度

### 3.1 位置维度

至少按以下位置拆分：

- 内圈。
- 中圈。
- 外圈。
- 圈与圈之间的过渡带。
- 圈层边界。

### 3.2 颜色维度

至少按以下维度拆分：

- 红、黄、蓝、黑、绿、白。
- 粉、橙、紫、咖、淡黄、淡蓝等暧昧色。
- 单色、混色、主色、辅色。
- 浓、淡、深、浅。
- 连续、碎片化、断裂、局部堆积。

### 3.3 形状维度

至少按以下维度拆分：

- 圆。
- 小圆。
- 大圆。
- 三角形。
- 长方形 / 条状。
- 正方形。
- 波纹状。
- 花边、点状、星状、碎片状。
- 尖角、截断、闭合、空洞。

### 3.4 结构维度

至少按以下维度拆分：

- 成片 / 不成片。
- 连续 / 断裂。
- 集中 / 分散。
- 内聚 / 外散。
- 平衡 / 偏斜。
- 规则 / 混乱。
- 填满 / 留白。

### 3.5 动力维度

至少按以下维度拆分：

- 向内 / 向外。
- 向上 / 向下。
- 扩张 / 收缩。
- 滞留 / 流动。
- 稳定 / 波动。
- 受阻 / 贯通。

### 3.6 五行维度

五行不是单独的最终结论，而是颜色、形状、位置和流动状态的二次解释层。

必须分别识别：

- 木。
- 火。
- 土。
- 金。
- 水。

并记录其太过、不足、平衡、相生、相克、被截断、无法成循环等状态。

## 4. 审核对象分层

### 4.1 第一层：画面信号

这是最小识别层，只回答“看见了什么”。

例子：

- 外圈红色明显。
- 中圈断裂。
- 土零散不成片。
- 白色把其他颜色割裂开。

### 4.2 第二层：画面组合模式

这是组合判断层，只回答“这些信号组合后通常像什么”。

其中一部分来自手册框架，一部分来自 11 例样本反推。样本组合必须标记为：

- `sample_pattern`
- `not_exhaustive`
- `sample_based`

`12-高频组合模式.md` 应归入这一层，不作为最终映射总表。

### 4.3 第三层：议题映射

这是产品可用层，只回答“这个信号组合可能通向哪些议题条款”。

例子：

- 外圈红色 + 碎点 -> 情绪型漏财、低行动。
- 土零散不成片 -> 承载力不足。
- 金多 + 白色割裂 -> 求认可式赚钱、配得感不足。

这一层需要从手册框架中系统整理，不应只保留 11 例里出现过的组合。

### 4.4 第四层：主题映射

这是应用层，只回答“在财富主题里，这个条款怎么解释；在别的主题里又怎么解释”。

财富只是第一主题入口，后续可以扩展到：

- 个人成长与自我价值。
- 亲密关系。
- 事业。
- 家庭关系。
- 健康和身体。

## 5. 现有样本文档的角色

### 5.1 `12-高频组合模式.md`

现在只适合作为：

- 样本组合记录。
- 解读语言参考。
- 组合判断的经验入口。

不适合作为：

- 完整画面映射表。
- 穷举式规则库。
- 直接路由的唯一依据。

### 5.2 `90-财富议题案例反推.md`

现在只适合作为：

- 财富主题样本回归。
- 组合信号与财富条款的经验对照。
- 调整方向的表达参考。

不适合作为：

- 财富主题的完整映射依据。
- 对所有财富画面的覆盖规则。

## 6. 建议的结构化对象

后续应拆成四类结构化对象：

1. `visual_signal`：单个画面信号。
2. `visual_pattern`：多个信号的组合模式。
3. `mapping_rule`：画面信号 / 组合模式到议题条款的映射规则。
4. `theme_routing`：主题级组合规则，负责把财富、关系、事业等主题接到对应模块。

## 7. 审核与结构化顺序

建议顺序如下：

1. 先以 `10-曼陀罗` 已有文件为主源，建立 `visual_signal` 清单。
2. 对每条信号标注来源文件、原文语境、审核状态和风险边界。
3. 再把 `visual_pattern` 从手册框架和样本材料中拆出来，区分 `manual_supported` 与 `sample_based`。
4. 再把 `mapping_rule` 做成可检索的长表。
5. 再让主题路由使用 `mapping_rule`，而不是直接依赖样本组合。
6. 最后才让 runtime 使用这些规则生成报告。

## 8. 对当前财富链路的影响

当前财富 routing 里的 `visual_signal_routes` 只能保留为候选映射，不应被理解为完整映射表。

对应处理原则：

- 画面信号可以命中财富条款。
- 样本组合可以辅助优先级排序。
- 但任何单一样本组合都不能覆盖全部视觉构成。
