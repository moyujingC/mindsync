# 画面信号穷举映射建设方案

> 状态：draft
> 版本：0.1.0
> date：2026-05-16
> owner：CEO / Knowledge Base
> source_of_truth：当前目录/20-疗愈体系/20-流派层/10-曼陀罗/00-画面信号穷举映射建设方案.md

本文定义曼陀罗画面信号的穷举式映射建设方式。

当前目标不是“把 11 个案例总结得更像体系”，而是把画面分析拆成可持续扩展的映射层：无论视觉构成如何变化，都能先落到稳定的画面信号，再落到议题条款、报告表达和安全边界。

## 1. 当前问题

当前已有两份样本文档：

- `12-高频组合模式.md`
- `90-财富议题案例反推.md`

它们都来自 11 个原始案例，只能代表有限样本经验，不能承担穷举映射依据的角色。

风险是：

- 这些样本容易被误当成完整规则库。
- 画面信号一旦超出样本文本出现的形式，就没有稳定落点。
- 财富主题会被过早绑到少数组合模式上，导致漏判。

## 2. 建设目标

映射层要回答四个问题：

1. 这幅画里看见了什么。
2. 这些视觉特征属于哪一类画面信号。
3. 这些画面信号可能落到哪些议题条款。
4. 这些条款在财富、关系、事业、自我价值等主题里分别怎么用。

目标不是让单个信号直接推出结论，而是让不同画面构成都能有稳定入口。

## 3. 需要穷举的画面维度

### 3.1 位置维度

至少按以下位置拆分：

- 内圈。
- 中圈。
- 外圈。
- 圈与圈之间的过渡带。
- 圈层边界。

### 3.2 颜色维度

至少按以下维度拆分：

- 红、黄、蓝、黑、绿、白。
- 粉、橙、紫、咖、淡黄、淡蓝等暧昧色。
- 单色、混色、主色、辅色。
- 浓、淡、深、浅。
- 连续、碎片化、断裂、局部堆积。

### 3.3 形状维度

至少按以下维度拆分：

- 圆。
- 小圆。
- 大圆。
- 三角形。
- 长方形 / 条状。
- 正方形。
- 波纹状。
- 花边、点状、星状、碎片状。
- 尖角、截断、闭合、空洞。

### 3.4 结构维度

至少按以下维度拆分：

- 成片 / 不成片。
- 连续 / 断裂。
- 集中 / 分散。
- 内聚 / 外散。
- 平衡 / 偏斜。
- 规则 / 混乱。
- 填满 / 留白。

### 3.5 动力维度

至少按以下维度拆分：

- 向内 / 向外。
- 向上 / 向下。
- 扩张 / 收缩。
- 滞留 / 流动。
- 稳定 / 波动。
- 受阻 / 贯通。

### 3.6 五行维度

五行不是单独的最终结论，而是颜色、形状、位置和流动状态的二次解释层。

必须分别识别：

- 木。
- 火。
- 土。
- 金。
- 水。

并记录其太过、不足、平衡、相生、相克、被截断、无法成循环等状态。

## 4. 映射对象分层

### 4.1 第一层：画面信号

这是最小识别层，只回答“看见了什么”。

例子：

- 外圈红色明显。
- 中圈断裂。
- 土零散不成片。
- 白色把其他颜色割裂开。

### 4.2 第二层：画面组合模式

这是样本归纳层，只回答“这些信号组合后通常像什么”。

这里可暂时保留样本组合，但必须标记为：

- `sample_pattern`
- `not_exhaustive`
- `sample_based`

`12-高频组合模式.md` 应归入这一层，不作为最终映射总表。

### 4.3 第三层：议题映射

这是产品可用层，只回答“这个信号组合可能通向哪些议题条款”。

例子：

- 外圈红色 + 碎点 -> 情绪型漏财、低行动。
- 土零散不成片 -> 承载力不足。
- 金多 + 白色割裂 -> 求认可式赚钱、配得感不足。

这一层需要穷举，而不是只保留 11 例里出现过的组合。

### 4.4 第四层：主题映射

这是应用层，只回答“在财富主题里，这个条款怎么解释；在别的主题里又怎么解释”。

财富只是第一主题入口，后续可以扩展到：

- 个人成长与自我价值。
- 亲密关系。
- 事业。
- 家庭关系。
- 健康和身体。

## 5. 现有样本的角色

### 5.1 `12-高频组合模式.md`

现在只适合作为：

- 样本组合记录。
- 解读语言参考。
- 组合判断的经验入口。

不适合作为：

- 完整画面映射表。
- 穷举式规则库。
- 直接路由的唯一依据。

### 5.2 `90-财富议题案例反推.md`

现在只适合作为：

- 财富主题样本回归。
- 组合信号与财富条款的经验对照。
- 调整方向的表达参考。

不适合作为：

- 财富主题的完整映射依据。
- 对所有财富画面的覆盖规则。

## 6. 建议的新结构

后续应拆成四类结构化对象：

1. `visual_signal`：单个画面信号。
2. `visual_pattern`：多个信号的组合模式。
3. `mapping_rule`：画面信号 / 组合模式到议题条款的映射规则。
4. `theme_routing`：主题级组合规则，负责把财富、关系、事业等主题接到对应模块。

## 7. 建设顺序

建议顺序如下：

1. 先把 `visual_signal` 目录补齐，优先按三圈、颜色、形状、结构、五行分层。
2. 再把 `visual_pattern` 从样本中拆出来，但明确标记样本来源和非穷举属性。
3. 再把 `mapping_rule` 做成可检索的长表。
4. 再把主题路由从条款路由上层拆出来。
5. 最后才让 runtime 使用这些规则生成报告。

## 8. 对当前财富链路的影响

当前财富 routing 里的 `visual_signal_routes` 只能保留为候选映射，不应被理解为完整映射表。

对应处理原则：

- 画面信号可以命中财富条款。
- 样本组合可以辅助优先级排序。
- 但任何单一样本组合都不能覆盖全部视觉构成。

## 9. 不做范围

当前不做：

- 直接重写成完整穷举映射表。
- 直接删除样本型文档。
- 直接把 11 例扩大解释成完整体系。
- 直接让 runtime 假装已经有全覆盖映射。

## 10. 下一步

下一步应该先补一份 `visual_signal` 总目录，再决定如何把 `12-高频组合模式.md` 拆回到可维护的规则层。
