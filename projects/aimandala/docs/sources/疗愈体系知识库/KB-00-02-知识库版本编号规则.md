# 知识库版本编号规则

> 状态：draft
> 文档版本：0.1.0
> 知识库版本：1.0.0-alpha
> date：2026-05-14
> owner：CEO / Knowledge Base / Architect
> source_of_truth：当前目录 KB-00-02-知识库版本编号规则.md

本文定义疗愈体系知识库的版本编号方式。知识库名称不使用版本号，也不绑定某一个单一应用形态；版本号只用于标识知识系统、运行时知识包和文档的迭代状态。

## 1. 三类版本

本知识库后续至少会同时存在三类版本：

| 类型 | 字段 | 用途 |
|------|------|------|
| 知识库系统版本 | `knowledge_base_version` | 标识整套知识系统当前处于哪个发布阶段。 |
| 运行时知识包版本 | `pack_version` | 标识某一次可被产品调用的结构化知识包。 |
| 文档版本 | `document_version` | 标识单篇 Markdown 文档自身的修订状态。 |

这三类版本不要混用。

例如：

```yaml
knowledge_base_version: 1.0.0-alpha
pack_version: 1.0.0-alpha.3
document_version: 0.2.0
```

含义是：整套知识库处于 `1.0.0-alpha` 阶段，当前运行时包是该阶段的第 3 次打包，某篇文档自身修订到 `0.2.0`。

## 2. 知识库系统版本

知识库系统版本采用 `major.minor.patch`（大版本.小版本.修订版）。

当前建议从 `1.0.0-alpha` 开始，而不是继续用目录名或代号作为知识库名称。

### 2.1 大版本 major

大版本用于标识不兼容变化。

以下情况应提升大版本：

- 知识单元的基本结构发生不兼容变化。
- 报告生成、追问回答、疗愈方案生成或课程生成的主链路发生重构。
- 运行时 pack 的读取协议发生变化。
- 大量条款需要重新映射和重新评估。

### 2.2 小版本 minor

小版本用于标识向后兼容的能力扩展。

以下情况应提升小版本：

- 新增一个完整议题。
- 新增一类报告能力。
- 新增一类疗愈方案。
- 新增一类课程、训练营、陪伴方案或衍生产品能力。
- 新增一组画面信号或映射规则。

### 2.3 修订版 patch

修订版用于标识不改变结构的小修正。

以下情况应提升修订版：

- 修正文案。
- 修复链接。
- 补充少量来源引用。
- 修正字段值。
- 调整单个条款的表达，但不改变知识结构。

## 3. 阶段标记

正式稳定前，可以使用阶段标记：

| 标记 | 含义 |
|------|------|
| `alpha` | 结构建设期，允许较频繁调整。 |
| `beta` | 主要结构成型，进入生成测试和案例评估。 |
| `rc` | 候选稳定版，只处理阻断问题和高风险问题。 |

建议路线：

```text
1.0.0-alpha
  → 1.0.0-beta
  → 1.0.0-rc.1
  → 1.0.0
```

## 4. 运行时知识包版本

运行时知识包是产品实际调用的数据包，应比 Markdown 源文档更严格。

建议命名：

```yaml
pack_id: aimandala-healing-system-kb
pack_version: 1.0.0-alpha.1
knowledge_base_version: 1.0.0-alpha
```

每次打包都应记录：

- 本次包含哪些知识单元。
- 本次新增、修改、废弃了哪些条款。
- 本次支持哪些产品场景。
- 本次通过了哪些案例评估。
- 本次有哪些已知限制。

## 5. 文档版本

Markdown 文档使用 `document_version` 或中文 `文档版本` 字段。

文档版本只表示单篇文档自身的变化，不代表整套知识库的发布状态。

例如，某篇财富议题文档可以从 `0.1.0` 改到 `0.3.0`，但整套知识库仍然处于 `1.0.0-alpha`。

## 6. 当前建议

当前阶段采用：

```yaml
knowledge_base_name: aimandala-healing-system-knowledge-base
knowledge_base_version: 1.0.0-alpha
```

中文名称使用：

```text
疗愈体系知识库
```

后续文档中应优先使用“本知识库”“当前知识库”或“疗愈体系知识库”，不要把版本号或某个具体应用形态写成知识库名称。
