## 1. 定位

本文档定义疗愈体系知识库的长期结构。

体系目标是沉淀一套可用于解读报告、追问回答、定制化疗愈方案、课程和衍生产品的完整疗愈体系。当前第一条应用链路是 `aimandala`，但知识库边界不等同于某一个产品。

## 2. 总体结构

```text
疗愈体系知识库/
  00-知识库治理/
  10-参考来源索引/
  20-疗愈体系/
    10-议题层/
    20-流派层/
      10-曼陀罗/
        10-画面语言/
        20-五行与色彩/
        30-疗愈方案经验/
    30-疗愈方案层/
  30-应用适配/
    10-aimandala/
  50-结构化知识单元/
  60-运行时知识包/
  70-评估与案例/
```

| 层级 | 定位 | 内容 |
|------|------|------|
| `00-知识库治理` | 维护知识库规则 | 边界、版本、数据结构、运行架构、决策记录 |
| `10-参考来源索引` | 指向来源本体 | 研究母库引用、专家手册来源说明、案例源索引 |
| `20-疗愈体系/10-议题层` | 用户经验视角 | 财富、事业、关系、健康、自我价值等议题 |
| `20-疗愈体系/20-流派层` | 专业知识视角 | 心理学流派、疗愈流派、曼陀罗等 |
| `20-疗愈体系/30-疗愈方案层` | 行动落地 | 练习、觉察问题、书写任务、身体练习、冥想、行动建议 |
| `30-应用适配` | 产品调用规则 | 某个产品如何使用疗愈体系知识 |
| `50-结构化知识单元` | 机器可读知识 | YAML / JSON 知识单元 |
| `60-运行时知识包` | 产品运行时资产 | schema、pack、index、检索配置 |
| `70-评估与案例` | 质量验证 | 案例回归、评估集、生成质量检查 |

## 3. 研究母库与本知识库的分工

研究母库位于：

```text
projects/research-center/kb
```

它承担低约束的研究沉淀，保存来源、摘录、核查、通用 wiki 和原子知识。

疗愈体系知识库承担高约束的领域组织，保存已经知道用途、可以进入产品链路的知识。

```text
研究母库
  → 10-参考来源索引
  → 20-疗愈体系
  → 30-应用适配
  → 50-结构化知识单元
  → 60-运行时知识包
```

原则：

- 原始资料只维护一份，优先放在研究母库。
- 本知识库不重复保存大段来源正文。
- 本知识库的 `10-参考来源索引` 记录来源位置、入库用途、审核状态和影响文件。
- 本知识库的 `20-疗愈体系` 保存经过选择、重组、裁剪后的产品化知识。

## 4. 疗愈体系内部结构

### 4.1 议题层

议题层站在用户经验出发，回答“用户可能遇到什么问题”。

当前已开始建设：

- 财富议题。
- 个人成长与自我价值议题。

后续可扩展：

- 事业 / 发展。
- 亲密关系。
- 父亲关系。
- 母亲关系。
- 亲子关系。
- 健康 / 身体。
- 情绪能量。
- 内在小孩。
- 潜意识伤痛。
- 内在渴望。
- 天赋优势。
- 人际关系。
- 灵性成长。
- 意识扩容。
- 自我关系。

### 4.2 流派层

流派层站在专业知识出发，回答“不同心理学或疗愈流派如何理解和处理这些议题”。

可纳入的流派包括：

- 心理学流派。
- 身心疗愈流派。
- 艺术疗愈。
- 曼陀罗。
- 东方体系中的阴阳、五行、三才等解释框架。

曼陀罗在这里是一个疗愈与表达系统，不是应用层本身。

当前曼陀罗流派下先沉淀：

- 画面语言：三圈、形状、位置关系、高频组合。
- 五行与色彩：五行感知、相生相克、暧昧色。
- 疗愈方案经验：基于曼陀罗的一线疗愈建议和操作经验。

### 4.3 疗愈方案层

疗愈方案层负责把议题层和流派层连接起来，形成可执行建议。

后续应沉淀：

- 觉察问题。
- 书写练习。
- 身体练习。
- 呼吸与冥想。
- 颜色和绘画练习。
- 行动建议。
- 周期性陪伴方案。

当前从曼陀罗手册拆出的疗愈建议先保留在 `20-流派层/10-曼陀罗/30-疗愈方案经验`，等通用方案框架稳定后，再抽取进入 `30-疗愈方案层`。

## 5. 应用适配

应用适配回答“某个产品如何调用疗愈体系知识”。

当前已有：

```text
30-应用适配/10-aimandala/
```

这里放 `aimandala` 的解读流程、报告组织规范、追问回答规则和与产品形态强相关的输出规范。

产品应用不应反向定义整个疗愈体系。应用可以使用议题、流派和疗愈方案，但不应把自己的页面结构、报告版本或交互细节写进通用疗愈体系层。

## 6. 运行链路

当前推荐链路：

```text
来源索引
  → 议题层
  → 流派层
  → 疗愈方案层
  → 应用适配
  → 结构化知识单元
  → 运行时知识包
```

以 `aimandala` 为例：

```text
曼陀罗画面观察
  → 画面信号
  → 流派层解释
  → 议题层条款
  → 疗愈方案
  → 报告 / 追问 / 方案输出
```

画面信息不能直接等同于最终结论。它应先成为可描述的画面信号，再和议题层、流派层、用户主题一起形成解释链。

## 7. 当前建设顺序

1. 稳定知识库目录边界和来源索引规则。
2. 优先建设议题层，不让少量案例定义完整议题。
3. 补充流派层，尤其是心理学流派、疗愈流派和曼陀罗体系。
4. 抽取通用疗愈方案层。
5. 维护 `aimandala` 的应用适配规则。
6. 再逐步结构化为知识单元和运行时知识包。
