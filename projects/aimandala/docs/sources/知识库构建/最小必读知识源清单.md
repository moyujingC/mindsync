这份清单服务一个很具体的场景：

- 后续要做报告链路整改
- 要检查当前报告是否偏离我们的解读流派
- 要判断 `knowledge_skeleton`、`Layer 0`、`theme_context`、runtime projection 是否保真

这时不需要先读完整个 `知识库构建` 镜像目录，而应先读下面这组最小必读材料。

## 1. 最小必读顺序

### 1.0 先看当前方法单一真值源

1. [三圈五行流派解读方法与步骤.md](三圈五行流派解读方法与步骤.md)
   - 用来确认当前 AI 报告生成必须遵循的步骤和过程链。
   - 当前方法判断以这份文档为准，不再以旧 `06_interpretation_methods*.md` 为准。

### 1.1 先看流派总来源

2. [00_app_数据源溯源文档.md](原始镜像/00_app_数据源溯源文档.md)
   - 用来确认这批知识最早来自哪些手册、速查表、主题特化数据和补充整理

### 1.2 再看基础解读骨架

3. [01_曼陀罗解读手册.md](原始镜像/01_曼陀罗解读手册.md)
   - 用来理解原始解读师语境中的主方法、解释口径和案例感
4. [00_kb_md/05_direct_judgments.md](原始镜像/00_kb_md/05_direct_judgments.md)
   - 用来确认直断规则的 Markdown 真值源。
5. [01_曼陀罗解读速查表.md](原始镜像/01_曼陀罗解读速查表.md)
   - 用来快速对照颜色、圈层和常用解释入口

### 1.3 再看失衡与三元结构

6. [02_20种失衡类型体系.md](原始镜像/02_20种失衡类型体系.md)
   - 用来确认失衡类型的原始体系，不被当前简化 runtime 误导
7. [06_主题解读三元论结构.md](原始镜像/06_四步法重构知识库/06_主题解读三元论结构.md)
   - 用来确认主题特化不是二元判断，而是三元状态结构
8. [06_通用解读知识库.md](原始镜像/06_四步法重构知识库/06_通用解读知识库.md)
   - 用来确认通用解释层如何作为主题解释的基础层

### 1.4 最后看当前最相关主题

9. [03_主题特化_亲密关系.md](原始镜像/03_主题特化数据生成与解读报告分层/03_主题特化_亲密关系.md)
   - 这是目前报告偏移排查里最常用的主题样本之一
10. [05补颜色.md](原始镜像/05_颜色与形状知识库补充/05补颜色.md)
   - 用来确认颜色细分解释有没有在当前运行时被压平
