这里收口 `aimandala` 项目中的“源资料”目录。

它回答的问题不是：

- 产品当前怎么定义
- 架构当前怎么分层
- 任务现在做到哪一步

而是：

- 某项项目知识、历史材料或方法论原文最早来自哪里
- 当前哪些外部或历史资料已经被正式镜像进 workspace
- 当前正式规则与原始资料之间如何建立引用关系

## 1. 适合放在这里的内容

- 项目专属的源资料镜像
- 旧仓库迁入后的原始材料入口
- 当前正式依据与原始资料之间的分层说明
- 原始资料与当前运行时/正式文档之间的映射清单

## 2. 不适合放在这里的内容

- 当前产品 spec
- 技术架构母文档
- 执行计划、QA、交付记录
- 运行时 pack/build 资产本身

这些内容仍应分别放在：

- `../specs/`
- `../architecture/`
- `../tasks/`
- `../qa/`
- `../../toC/data/`
