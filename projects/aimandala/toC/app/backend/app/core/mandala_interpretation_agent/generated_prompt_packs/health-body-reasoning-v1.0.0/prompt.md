## 5. 使用规则

- 先写画面事实，再写身体翻译。
- 单一信号只作为候选解释，不能单独定性用户身体状态。
- 多个信号共同指向同一条款时，该条款可作为报告主轴候选。
- 所有表达都必须保留"可能、像是、从画面看起来"等缓冲语气。
- 医疗风险标记为"是"的条目，必须在报告中加入医疗提醒路由。
- 不输出医疗判断，不替代医疗建议。

本文定义当健康身体报告中出现其他议题线索时，回译成身体承载机制的原则。

## 1. 回译原则

健康身体报告以身体能量和承载力为主线。当画面中出现其他议题信号时，按以下规则处理：

1. **识别浮现议题**：识别画面中的情绪、关系、财富、事业等信号。
2. **回译到身体主线**：将浮现议题翻译成身体承载机制，不单独展开其他议题报告。
3. **保持报告深度**：回译后保持 brief 或 hint 深度，不抢其他议题主线。
4. **回到身体语言**：用身体语言描述，不使用其他议题的专门术语。

## 3. 回译表达规则

- 回译时必须用身体语言描述，不使用其他议题的专门术语。
- 回译深度保持 hint/brief，不抢其他议题主线。
- 多个议题同时出现时，按优先级排序：情绪 > 关系 > 财富 > 事业 > 安全感 > 灵性。
- 回译后必须回到健康身体主线（身体能量/承载力/阻滞）。
- 不展开成其他议题报告，保持健康身体报告的完整性。

## 1. 使用原则

- 先看颜色是什么，再看落在哪一圈，再看深浅、面积、留白和相邻关系。
- 同一种颜色在不同圈层的身体语义不同。
- 颜色在健康身体议题里不是单独定论，而是进入条款和报告模块的线索。

- 颜色只能作为身体能量的线索，不能生成医疗判断。

## 8. 组合使用

- 红色 + 黑色：身体可能储存了较深的情绪，身体紧张模式可能较明显，身体警报可能处于抑制或过度激活状态。
- 蓝色 + 黑色：身体可能处于压抑或阻滞状态，身体能量流动可能受限，身体感知可能有阻滞。
- 绿色 + 留白：身体能量有流动感，身体觉察能力可能在发展，身体落地较稳。
- 紫色 + 金：身体能量可能较轻盈，身体感知范围可能较开放，身体觉察可能在发展。
- 土色 + 黑色：身体能量可能偏沉重，湿寒积累可能性，身体承载偏紧。

## 9. 使用边界

- 本表只做健康身体翻译，不取代基础层颜色定义。
- 单色只能作为候选，不直接做身体结论。
- 需要时必须回到圈层、形状、组合模式一起看。
- 若要进入结构化路由，必须先经过人工审核。
- 不输出医疗判断，不替代医疗建议。

```text
  -> 放入"身体能量状态 / 湿寒与温暖"
  -> 不能写成身体有疾病或诊断
```

## 2. 健康身体报告中的三圈

健康身体报告里的三圈优先解读为：

```text
内圈：身体核心能量、内在安全感和自我接纳
  -> 身体承载力基础

中圈：情绪承载、感受积累、滋养与阻滞
  -> 情绪的身体容器
  -> 感受积累与身体症状
外圈：现实行动、落地能力、与世界互动
  -> 行动落地能力
  -> 身体与现实
```

## 3. 安全边界总则

健康身体报告必须始终遵守以下边界：

- **不输出医疗判断**：不写成"你的身体有某种疾病"或"你有某种具体症状"
- **不说"身体导致"**：不说"你的身体问题导致了..."等因果表达
- **不替代医疗建议**：不输出具体的医疗或治疗建议
- **不说"必须运动"**：不把身体活动写成必须的疗愈方式
- **身体信号只是线索**：身体信号只能作为背景线索，不能生成诊断
- **不说"你身体不好"**：避免让用户对自己的身体产生负面评价

# 解读与个案沟通流程

> 状态：draft
> 文档版本：0.1.0
> date：2026-05-13
> owner：CEO / Knowledge Base
> source_of_truth：当前目录/30-应用适配/10-aimandala/01-解读与个案沟通流程.md
> 原始来源：01-曼陀罗解读手册原文.md
> 整理方式：原文保真重组

本文从 `01-曼陀罗解读手册原文.md` 中拆出解读时如何与案主沟通、如何做完整个案的流程经验。

## 1. 解读沟通的六大流程

原文将上千个解读个案经验整理为六大流程：

1. 建立信任。
2. 确定目标。
3. 打开内心。
4. 爆破卡点。
5. 清理情绪。
6. 定制方案。

## 2. 建立信任

你的语言要有疗愈感。在咨询关系正式确定之前，疗愈师往往需要跟案主做前期沟通。前期沟通并不是简单地确定时间、价格等，更重要的是跟案主建立信任。

如果案主对你的能力还在不停地质疑，或者让你极力去证明自己值某个价格，那说明给他做个案的时机还没到，可以建议他缓一缓，考虑清楚了再做。

原文提醒：信任关系不是用一番话或者一套话术就能够解决的。这种信任关系的沉淀，来源于平日的短视频、推文、朋友圈的内容输出。

只有让案主感受到你的专业性，和语言当中的疗愈感，再加上时机成熟，自然就会有案主主动来找你。

## 3. 确定目标

下一步，要确定的是案主的目标：通过个案解决什么问题？

不要漫无边际地解读。因为一个人从小到大的伤痛、负面情绪，是永永远远挖掘不完的。

案主当下最迫切要解决的问题，就是他的痛点。

目标有的案主刚开始内心打不开，或者不愿意深入说，也可以问：这幅曼陀罗的绘画主题是什么？借此打开话题。

## 4. 打开内心

原文指出，一个疗愈师的水平高低，很大程度上取决于能不能打开一个人的内心，让他把伤痛袒露出来。

原文给出几句推进个案节奏的话：

1. 别害怕，在这里你是安全的。
2. 在这里，一切都是被允许的。
3. 亲爱的，你知道吗？这个世界上没有别人，只有你自己。

在案主描述自己卡住了，或者不愿意打开时，可以适当使用这些话推进个案节奏。

## 5. 爆破卡点

这一步是帮助案主找到伤痛事件背后的根源事件。

例如有案主想解决的问题是：跟女儿的关系不好，沟通上有很大的隔阂和障碍，似乎无论怎么做都走不近女儿的内心，经常聊着聊着就闹矛盾。

这时，可以通过她画的曼陀罗寻找事件背后的根源事件，例如：她的掌控欲是不是很强？她跟自己的母亲关系好不好？她近期的情绪、脾气好不好等。

根源事件的挖掘，要看案主敞开的程度。不一定每一个人都能做得很深，具体要看案主的意愿，和疗愈师的感知力。

## 6. 清理情绪

一旦冰山下面的“真相”浮出水面，下一步就是在主意识层面，告诉案主要清理和调整的方向。

原文示例：

“母亲对女儿的过分的关爱和担心，其实也是一种控制。因为你担心的念头一产生时，你的身体是紧绷的，释放的情绪是恐惧的，女儿无形中接收到了这些信号，就会躲着你了。”

“只要你放松下来，给她自由的空间去体验和成长，即使中间有些磕磕碰碰没关系的。放下你紧绷的情绪，你们的关系逐渐就能够缓和了。”

除了主意识的语言引导以外，还可以让案主画黑色清理画，清理内在的恐惧；以及画蓝色清理画，让身体保持放松。结合曼陀罗的情绪清理，个案效果会更快速显现。

## 7. 定制方案

最后一步，就是设计一套绘画方案。

原文示例：

清理方案：每天画 14 张黑色清理画，7 张蓝色清理画，坚持 21 天；21 天后反馈个案效果。

显化方案：每周绘画 1 张彩色订单画，一边画一边观想女儿小时候，跟她融洽、有爱地相处，大家一起相处时最开心的种种画面。

原文提醒：有的个案能六步全走完，把个案做得很深。有的也许做得浅一点，案主敞开的程度也没那么深。具体的火候，需要多练习才能把握得精准、到位。

## 8. 完整个案流程

原文把完整个案拆为六个阶段：

1. 个案准备。
2. 引领觉察。
3. 找到根源。
4. 清理情绪。
5. 检视效果。
6. 锚定信念。

## 9. 第一阶段：个案准备

个案就是针对案主的问题，给他做一次较为彻底的解决和疗愈。要做到“快、狠、准”。而要精准地找到案主的核心问题，必须借助曼陀罗这个工具，辅助案主做创伤事件的挖掘。

首先，疗愈师可以让案主准备好一本曼陀罗绘画和一套画笔。一个安静、能够独处的环境，保证在个案开工的时间内不被打扰。然后指引案主，绘制第一张彩色曼陀罗。

面对一些难以进入状态的案主，可以为其选择几首轻柔的纯音乐。一边听着音乐一边绘画，更容易让案主的状态平静下来。

即使案主画上 1 个小时左右，疗愈师也不要催促，只需要静静地陪伴即可。

前期准备非常重要。疗愈师要轻柔地告诉案主：我会在这里陪着你，直到你绘画完毕。当你画好了，就告诉我。别担心，有我在，一切都是安全的。

个案工具：让案主绘制第一张彩色曼陀罗，根据自己的心意和喜好涂色。

## 10. 第二阶段：引领觉察

当案主绘画完毕后，要将以下问题依次问他：

1. 在绘画的过程中，你感觉如何呢？
2. 你希望通过个案，解决什么问题呢？
3. 现在，我邀请你，通过这幅曼陀罗做一个内在的觉察，你愿意吗？

如果在这个过程中，案主很抗拒，或者情绪爆发，则必须先安抚好案主，不能将流程强行推进下去。

当案主状态稳定，也回复“愿意”，就可以结合案主想要解决的问题，做针对性的解读。

新手解读师如果对解读的知识点和内容不是很纯熟，可以先给自己缓冲时间。在这个阶段先收集到案主的曼陀罗，然后再另行预约解读时间，给自己充足的时间做好详细的解读笔记。

可对案主说：很感谢你的信任。我需要一点时间，对你的作品做一个详细的解读。我们把个案解读时间定在 X 月 X 日 XX 时可以吗？

个案工具：曼陀罗解读笔记，即场解读或提前准备均可。

## 11. 第三阶段：找到根源

这一步是最考验疗愈师功力的，因为有很多功夫超出了曼陀罗解读以外的心理学底蕴。新手解读师也不要惧怕，大胆尝试就行。任何经验都是从零开始积累的。

开始时要重复锚定案主的问题，让问题变得聚焦。否则解读的内容会太过发散，很难做到效果。

解读句式：

从你的曼陀罗中，可以看出……；因为你的用色 / 结构 / 布局 / 形态是……的，因此你面对这个问题时会……

重点是对自己的解读内容给出理论依据。有了依据才能让案主信服。

原文示例：

从你的曼陀罗中，可以看出你的消费习惯不太节制，容易乱花钱；因为你在外圈画了像火焰形状的红色，外圈代表物质圈，红色的火能量代表着一种发散，因此你的消费习惯会很随性，花钱不太节制。

当把能够解读到的内容告诉案主后，真正的根源问题挖掘才刚刚开始。

可以继续问：

1. 回到你最初的问题。听完我对你的曼陀罗解读后，你的感受是什么？
2. 这份感受，是让你舒服的，还是不舒服的呢？

## 12. 第四阶段：清理情绪

清理阶段，至少每天要让案主抽出 30 分钟去画清理画。

每天可以画 3 张以上，最好能画到 7 张。以 7 天为一个清理周期。

如果有几个主题需要清理，就告诉案主用色和清理的画法，分配好每天清理画的数量。

在清理周期内，可以隔 2-3 天问一次案主绘画清理画的感受和体会，及时跟进案主的变化。

个案工具：按照定制的绘画方案进行绘画清理。

## 13. 第五阶段：检视效果

清理阶段结束后，要让案主再次绘画一幅彩色曼陀罗。

然后拿出第一阶段的曼陀罗作品，做对比解读。

告诉案主第一次的作品和这次的作品有什么变化，这意味着哪些情绪已经减少，让案主通过曼陀罗直观地看到自己的实际变化。

个案工具：让案主绘制一张彩色曼陀罗，根据自己的心意和喜好涂色。

## 14. 第六阶段：锚定信念

最后一步，要夯实基础，巩固效果。让案主把这份疗愈的能量带回现实生活，提升生命质量和幸福感。

沟通句式参照：

1. 当你看到自己的变化后，之前的问题还能困扰你吗？
2. 下一次，当你遇到类似的问题，你有信心去解决吗？
3. 伸出双手，给自己一个充满爱和有力量的拥抱。让我们带着这份爱和力量，结束这次的个案。

## 15. 使用提醒

用户对报告进行追问时，可以借鉴本文中的“锚定问题 - 解释依据 - 询问感受 - 进入清理方向”的沟通结构。

生成疗愈方案时，可以借鉴“清理方案 + 显化方案 + 检视效果”的结构。

在产品化使用时，需要把个案表达转为安全、温和、非诊断式的建议，避免承诺疗愈结果。

本文从 11 个原始案例中反推解读报告的组织顺序。

## 1. 报告基本顺序

案例中的完整解读通常按这个顺序展开：

1. 凭直觉描述整体画面。
2. 确定绘画者的曼陀罗主题。
3. 以神识为准划分三圈。
4. 识别本图颜色和五行属性。
5. 逐圈解读。
6. 结合五行相生相克关系做综合判断。
7. 回到用户主题，说明卡点。
8. 给出生机和调整方案。

## 2. 开头：整体画面直觉

多个案例会先写“拿到图的瞬间”或“首先凭直觉来描绘一下整体看到的画面”。

案例表达：

- 我的直觉是：像花圈，漂亮，情感丰富，情绪多，渴望被看见。
- 我的直觉是：漂亮、内在阴寒、有很多项链、珠宝、爱美。
- 它的整体特征是：水火两重天，案主的脾气会容易被点着。
- 画面特征是：整张曼陀罗颜色画得比较粗糙，很多线条画出线了，整体看着偏凌乱。

用途：

- 快速进入案主当前状态。
- 让报告不只是规则堆砌，而有疗愈师面对作品时的第一感。
- 帮助打开用户心防。

## 3. 主题确认

案例每次都会先确认主题：

- 主题是个人成长和财富。
- 主题是我值得拥有幸福和爱。
- 主题是两性情感关系。
- 主题是事业发展。
- 主题是财富提升。
- 主题是自我提升。

报告不应泛泛分析所有方面。主题决定解读重点，也决定哪些画面信息优先被调用。

## 4. 三圈推进

案例中的三圈语义基本稳定：

- 第一圈 / 里圈：意识、情感、过去、自己内心的想法，自己与自己的关系。
- 第二圈 / 中圈：能量、财富能量、现在和亲人之间的情感关系。
- 第三圈 / 外圈：物质、财富、身体、未来、行动力，别人怎么看 Ta。

报告写作时应逐圈推进，不要把三个圈的信息混成一段。

## 5. 每圈内部写法

每一圈通常按这个顺序写：

1. 这一圈代表什么。
2. 有哪些颜色和形状。
3. 这些颜色分别对应什么五行。
4. 相生相克关系是什么。
5. 面积比例、深浅、是否截断、是否成片。
6. 推出对应的意识、情绪、关系、财富或行动力判断。
7. 必要时回到主题解释影响。

## 6. 判断句式

案例中高频句式：

- 从第一圈可以看出……
- 说明案主……
- 由此可看出……
- 还可以看到……
- 为什么说……？因为……
- 结合中圈到外圈的能量状态来解读……
- 这也是为什么……的原因。

这些句式的作用是把画面证据和解读判断连起来，避免只给结论。

## 7. 生机写法

案例里的解读不是只指出问题，也会指出生机：

- 但这也是她的勇气和生机所在。
- 这是非常值得赞扬的，也是曼陀罗解读师要给到案主的生机。
- 内在生起了欢喜心。
- 有了新的生机。
- 能看到自己更多的可能性。

报告中应避免只有卡点和负面判断。每个主要卡点后，至少要给出一个可转化方向。

## 8. 调整方案写法

调整方案通常包含：

- 意识调频：认知、转念、放下评判、锚定目标。
- 能量调频：呼吸、站桩、八段锦、冥想、情绪清理。
- 曼陀罗绘画：具体颜色、张数、周期、主题。
- 行动建议：做计划、找工作、专注目标、每天小行动。
- 关系建议：建立边界、减少讨好、链接他人、理解家人。

调整方案需要尽量具体，不只写“多爱自己”“提升能量”。

## 9. 报告边界

案例里的语言有强烈一线疗愈师风格。生成报告时可以保留疗愈感，但需要注意：

- 不把身体判断写成医学诊断。
- 不把财富判断写成财务承诺。
- 不把心理创伤判断写成临床诊断。
- 保留“可能”“倾向于”“从画面看起来”等缓冲表达。

## 10. 使用提醒

报告生成不是把画面语言、流派解释和议题条款依次罗列，而是根据用户主题和画面证据组织成一条解释链。

推荐结构是：

整体直觉 -> 主题确认 -> 三圈逐层解读 -> 综合模式 -> 主题卡点 -> 生机 -> 调整方案。

# 解读报告生成最小规则

> 状态：draft
> 文档版本：0.1.3
> date：2026-05-28
> 变更说明：修正 Lite / Pro 分流字段，明确 `user_segment` 只表示用户类型，`report_version` 才表示报告版本。
> owner：CEO / Knowledge Base
> source_of_truth：当前目录/30-应用适配/10-aimandala/03-解读报告生成最小规则.md
> product_decision：projects/aimandala/docs/decisions/2026-04-06-用户分群与产品矩阵决策.md

本文把 `aimandala` 的解读报告生成流程收成一版可直接执行的最小规则。

## 1. 目的

目标不是一次性写出完整疗愈体系，而是先让报告生成有统一入口、统一顺序、统一安全边界。

## 2. 运行前读取顺序

生成前按这个顺序读：

1. 用户分群与产品矩阵决策。
2. 体系框架。
3. 数据结构与运行架构。
4. 来源索引。
5. 议题层文件。
6. 个案沟通流程。
7. 报告组织规范。
8. Lite / Pro 报告分流与交付口径。
9. 运行时知识包。

## 3. 报告产品边界

报告负责：

- 解释这张画在表达什么。
- 命名用户状态。
- 梳理用户模式。
- 连接现实议题。

报告不负责：

- 连续训练。
- 长周期改变。
- 替代主题方案。
- 替代 21 天定制方案。

因此，报告可以给轻量调整建议，但不要把报告写成完整训练产品。

产品主分层固定为：

`入口产品 -> 解读产品 -> 主题转化产品 -> 长期陪伴产品`

`Lite / Pro` 只属于解读产品内部的深度分流，不是产品架构主分层。

## 4. 最小输入

最小输入必须包含：

- 用户主题。
- 用户想解决的具体问题。
- 用户分群或进入动机，如果已知。
- 报告版本：Lite / Pro / 未知。
- 画面整体直觉。
- 里圈、中圈、外圈的观察。
- 颜色、形状、布局的观察。
- 不能确认的地方。

如果主题没有确认，先补主题，不要直接开始下判断。

## 5. 生成步骤

1. 先写整体直觉，只写看见了什么和第一感受。
2. 再确认主题，说明这次报告聚焦什么。
3. 再按里圈、中圈、外圈逐层展开。
4. 每层都先描述观察，再给出解释。
5. 最后把三圈信息收束成综合模式。
6. 回到用户主题，说清楚最可能的卡点。
7. 一定要写出生机，而不是只写问题。
8. 最后给出可执行的调整方案。

## 5.1 财富关系主题的专用收束顺序

当主题是财富时，报告要按以下顺序收束：

1. 先锚定财富主线，明确当前最重要的财富状态。
2. 再解释这条主线背后的机制，优先用财富手册中的条款。
3. 如有健康、关系、情绪、家庭等浮现议题，只能先翻译回财富机制，再简短提及背景。
4. 不把浮现议题单独展开成另一份报告。
5. 最后再给出低风险建议和下一步入口。

可用表达方式：

- 从财富关系议题看，这里更像是在说……
- 如果把这个线索翻回财富主线，它可能影响的是……
- 这条背景线索本身值得观察，但在这份报告里只作为财富机制的背景。

## 6. 用户分群适配

- 自我理解型：重点写“命名状态”和“看懂模式”。
- 议题解决型：重点写“现实议题”和“下一步方向”。
- 成长深化型：可以多写机制、成因和长期路径入口。
- 情绪安放型：减少强判断，增加承接、稳定和温和表达。
- 高复杂度支持型：不继续做深度 AI 解读，转入安全边界和外部支持引导。

## 7. 解释原则

- 解释必须回到画面证据。
- 单一信号不能承担过重结论。
- 能确定的写确定，不能确定的写可能。
- 先说观察，再说判断，再说建议。
- 不把“看起来像”写成“就是”。

## 8. 主题使用规则

当前先优先使用：

- 财富。
- 个人成长与自我价值。

如果用户主题不在这两个范围内，仍然可以输出通用报告框架，但要明确说明当前知识包还没有完整主题模块。

财富关系主题使用固定翻译链：

`画面信号 -> 状态含义 -> 财富关系议题翻译 -> 报告段落`

关系、情绪、家庭、身体等浮现议题可以出现，但必须先翻译回财富机制，只能作为背景解释，不单独展开成另一份报告。

## 9. 报告边界

报告中不输出以下内容：

- 医学诊断。
- 心理诊断。
- 财务保证。
- 绝对化预言。
- 把单一作者体系写成整个疗愈领域的共识。
- 完整主题方案或 21 天计划。

## 10. 语气要求

报告语言风格以 [07-报告语言风格指南.md](07-报告语言风格指南.md) 为唯一入口。

本文件只保留结构、边界和生成顺序，不再重复定义语气细则。

不要用夸张断言，也不要把不确定性藏起来。

## 11. 产品衔接

报告结尾可以保留下一步入口，但必须区分：

- 报告内建议：轻量、短周期、低风险。
- 主题方案：围绕一个议题开始改变。
- 21 天定制方案：持续推进个体化改变。
- 外部专业支持：高复杂度或高风险情况。

## 12. Lite / Pro 分流

Lite / Pro 的详细口径见 [04-Lite-Pro报告分流与交付口径.md](04-Lite-Pro报告分流与交付口径.md)。

最小规则是：

- Lite 负责快速命中、画面依据、当前状态、主题连接和低压小步建议。
- Pro 负责核心主轴、逐圈整合、生克失衡、能量流动、根因链和阶段性调节路径。
- 两者都是完整付费报告。
- 两者都不能越界写成主题方案或 21 天计划。

## 13. 质量检查

每次生成前后都检查：

- 主题是否明确。
- 每一圈是否都有对应观察。
- 综合判断是否回到主题。
- 调整方案是否可执行。
- 是否存在诊断式或承诺式语言。
- 是否把报告越界写成方案产品。
- 是否符合 Lite / Pro 的版本边界。

## 15. AI 可执行决策树

本节把所有生成前判断收束成一组可直接执行的 if/then 规则，每条规则的优先级标注在末尾。每个决策节点后附”报告表达”，即用户可见的标准返回文字。

### 15.1 输入有效性判断 [P0]

**目的**：当用户输入不完整时，AI 必须能识别并做出正确响应，避免生成证据不足的报告。

```
IF user_theme 未确认 AND 画面分析不足以落到具体议题
THEN
  → 返回”需要确认主题”的追问，列出可能的议题方向
  → 不生成报告
  报告表达：
  “在你开始解读之前，我想先确认一下——你心里最想通过这张画解决的是什么？
  目前我看到的画面信号……（描述观察），可能的议题方向包括……（列出 2-3 个），
  你可以告诉我最贴近的那个，或者告诉我另一个方向。”

IF user_theme 已确认 BUT 画面分析缺乏关键信号（里中外圈任意一圈缺失描述）
THEN
  → 标记”观察不足”，返回追问信号点
  → 不生成正式报告，生成”初步观察”
  报告表达：
  “目前我看到的画面……，不过要给出更完整的解读，
  我还需要知道……（指出缺失的圈层或信号），你能补充一下那部分吗？”

IF user_theme 已确认 AND 画面分析完整
THEN
  → 继续生成流程
```

### 15.2 多议题浮现时的收束规则 [P1]

**目的**：当画面涉及多个议题浮现时，保持主线清晰，防止报告变成多议题拼盘。

```
IF 浮现议题数量 > 2
THEN
  → 选择与主议题关联最强的 2 个作为”背景线索”
  → 其余议题不单独展开，记录为”待探索”
  → 在报告中说明”本次聚焦 X 和 Y，Z 议题在后续可以单独探索”
  报告表达：
  “在这张画里，除了[主议题]之外，我还看到了一些其他线索。
  本次我会重点回应 X 和 Y，它们和你的主议题直接相关。
  Z 这个方向也值得注意，但这次先不在这里展开——
  如果你之后想专门探索它，可以单独做一份报告。”

IF 浮现议题与主议题冲突（如用户选财富但浮现大量关系议题）
THEN
  → 确认用户是否要切换主议题
  → 或将关系作为”背景线索”翻译回财富主线
  报告表达：
  “我注意到这张画里浮现了很多关系层面的信号，
  和你选择的财富关系主题不完全重合。
  有两种处理方式——
  一种是把关系翻译回财富视角，作为财富卡点的一个背景成因；
  另一种是如果你觉得关系更迫切，我们可以先把主议题换成关系。
  你倾向于哪种？”
```

### 15.3 安全边界触发识别规则 [P0]

**目的**：识别高风险信号并触发安全边界，区分”立即停止”和”附带提示”两种响应。

```
IF 用户输入中出现以下触发词
  - “债务” “破产” “负债”
  - “想死” “自杀” “活不下去”
  - “创伤” + 具体事件描述
THEN
  → 立即停止报告生成
  → 返回安全边界提示
  → 不输出任何画面分析结论
  报告表达：
  “这个议题已经涉及到……（描述触发词指向的领域）的深层困难，
  这类情况非常需要专业人士的陪伴和支持。
  我建议你可以联系心理咨询师、社工或相关支持机构——
  他们有训练和资源来更好地支持你走过这一段。
  当你准备好了，这份画可以随时再来分析。”

IF 画面分析中出现以下高风险信号组合
  - 内圈大面积深黑色 + 外圈空白 + 用户输入涉及经济压力
  - 外圈破损 + 红色深重（创伤相关信号）
THEN
  → 报告正常生成，末尾附带专业支持提示
  报告表达：
  “在你阅读这份报告的同时，如果你觉得当前的困难已经影响到
  基本生活、安全感或情绪稳定，建议先寻求专业支持。
  这不是说你不能从自我观察中受益，而是有些情况
  有专业人士在身边会更安全、更有效。”
```

### 15.4 Lite / Pro 分流的唯一权威版本 [P0]

**目的**：统一 03 / 04 / 运行时包三处的分流定义，作为报告生成时唯一执行的路由规则。

```
IF report_version = 'lite' OR 报告长度限制明确
THEN
  → 输出 Lite 版
  → 内容包含：主题命中 + 3-6 条画面依据 + 1-2 个背景线索回译 + 低压小步建议
  → 长度区间：300-500 字
  → 报告语气：分析 40%，安抚与可执行建议 60%
  → 不要展开根因链，不要生成逐圈长篇

IF report_version = 'pro' AND pro_activated = true
THEN
  → 输出 Pro 版
  → 内容包含：Lite 全部 + 逐圈整合 + 完整背景线索回译 + 生克失衡 + 根因链 + 阶段性调节路径
  → 长度区间：800-1200 字
  → 报告语气：分析 60%，安抚与调节路径 40%
  → 注意：当前 Pro 仍为内部预备形态，对外输出前需确认产品上线状态

IF pro_activated = false（即当前默认状态，且用户未明确购买 Pro）
THEN
  → 输出 Lite 版
  → 在报告末尾注明：”Pro 版本后续上线，如需更完整的机制解释，届时可以升级。”
```

### 15.5 与现有规则体系的对应关系

本节决策树与前述各节对应如下：

| 决策树 | 对应章节 | 核心约束 |
|--------|----------|----------|
| 15.1 输入有效性 | 第 4 节 最小输入 | 最小输入不足时禁止生成报告 |
| 15.2 多议题收束 | 第 5.1 节 财富关系主题专用顺序 / 第 8 节 主题使用规则 | 浮现议题不单独展开，先翻译回主线 |
| 15.3 安全边界 | 第 6 节 用户分群适配（高复杂度支持型）/ 第 9 节 报告边界 | 触发词立即停止，高风险信号附提示 |
| 15.4 Lite/Pro 分流 | 第 12 节 Lite/Pro 分流 / 04-Lite-Pro报告分流与交付口径.md | 默认 Lite，Pro 仅在 pro_activated=true 时输出 |

本节所有 if/then 规则为生成流程的前置守卫，优先于第 5 节生成步骤执行。

运行时包在调用本规则时，应在进入第 5 节之前依次完成 15.1 至 15.4 的判断，并以判断结果作为后续步骤的输入参数。

字段边界：

- `user_segment`：用户类型，例如情绪安放型、自我理解型、议题解决型。
- `report_version`：报告版本，只能是 `lite`、`pro` 或 `unknown`。
- `product_intent`：产品意图，例如轻解读、报告、主题方案入口、21 天定制方案入口。

不得用 `user_segment = lite/pro` 判断报告版本。

## 16. 和运行时包的关系

本规则负责”怎么写”。

# Lite / Pro 报告分流与交付口径

> 状态：draft
> 文档版本：0.1.0
> date：2026-05-15
> owner：CEO / Knowledge Base
> source_of_truth：当前目录/30-应用适配/10-aimandala/04-Lite-Pro报告分流与交付口径.md
> product_decision：projects/aimandala/docs/decisions/2026-04-06-用户分群与产品矩阵决策.md
> source_refs：30-应用适配/10-aimandala/06-财富关系议题解读报告模板.md

本文把 `Lite / Pro` 报告口径接入疗愈体系知识库。

这里定义当前产品矩阵和运行时知识包中的 Lite / Pro 使用边界。财富关系议题的具体段落组织以 [06-财富关系议题解读报告模板.md](06-财富关系议题解读报告模板.md) 为准。

## 1. 基本判断

当前财富解读报告以 Lite 作为对外交付版本。

Lite 不是免费摘要，而是当前正式可交付的完整报告口径。

Pro 不是 Lite 的简单加长版，但当前只作为内部预备形态，MVP 阶段暂不上线。

## 2. 产品矩阵位置

在产品矩阵中，Lite 属于当前对外交付的“报告”产品。Pro 保留为后续报告产品形态。

报告负责：

- 解释这张画在表达什么。
- 命名用户状态。
- 梳理用户模式。
- 连接现实议题。

报告不负责：

- 连续训练。
- 长周期改变。
- 替代主题方案。
- 替代 21 天定制方案。

因此，Lite 可以给低风险建议，但不能越界生成完整方案产品。Pro 在上线前也必须遵守同一边界。

## 3. Lite 报告口径

Lite 的任务是让用户快速感到：

- 这张画被看见了。
- 当前状态被说中了。
- 画面依据是清楚的。
- 主题连接是具体的。
- 有一个低压可执行的调整方向。

Lite 应包含：

1. 开头命中。
2. 画面依据区。
3. 当前状态解读。
4. 主题连接。
5. 小步建议。
6. 温和收束。

Lite 不承担：

- 完整逐圈长篇展开。
- 多层根因链拆解。
- 复杂能量流动复盘。
- 长周期疗愈计划。

正式写作规则见：[06-财富关系议题解读报告模板.md](06-财富关系议题解读报告模板.md)。

## 4. Pro 报告口径

Pro 的任务是把画面证据、逐圈分析、五行生克、失衡候选和能量流动诊断组织成一条完整解释链。当前 Pro 仅作为内部验证和后续 MVP 预备项，不对外开放。

Pro 应包含：

1. 开头命中。
2. 画面依据区。
3. 核心主轴。
4. 逐圈整合。
5. 生克与失衡机制。
6. 能量流动诊断。
7. 根因链。
8. 阶段性调节路径。
9. 收束与提醒。

Pro 不承担：

- 医疗、诊断或确定性预言。
- 脱离画面证据的性格定论。
- 与用户主题无关的大而全人生分析。
- 21 天连续陪伴方案。

正式写作规则见：[06-财富关系议题解读报告模板.md](06-财富关系议题解读报告模板.md)。

### 4.1 当前上线状态

- Lite：当前财富解读报告的正式上线版本。
- Pro：MVP 暂不上线，只保留内部实现、评测和后续打磨入口。

## 5. 分流规则

默认分流可以按用户任务判断：

- 情绪安放型：优先轻解读或 Lite，重点是被接住、被理解、低压建议。
- 自我理解型：优先 Lite。
- 议题解决型：优先 Lite，必要时转主题方案入口，不直接开放 Pro。
- 成长深化型：优先 Lite，并在结尾保留主题方案或后续路线入口。Pro 暂不上线。
- 高复杂度支持型：不进入深度 AI 报告，触发安全边界与外部支持引导。

如果只知道用户购买的是 Lite，则以 Lite 为准。Pro 购买入口在 MVP 阶段不开放；用户分群只影响语气、重点和结尾衔接。

## 6. 和主题方案的关系

报告可以指出方向，但主题方案才负责围绕一个议题开始改变。

报告结尾可以引导：

- “如果你只想先理解自己，可以先从这份报告里的小步建议开始。”
- “如果你已经确认想处理这个议题，可以继续进入主题方案。”
- “如果你希望有人陪你持续推进，可以进入 21 天定制方案。”

不要在报告正文中直接写完整训练周期、打卡节奏或高度个体化陪伴计划。

## 7. 和运行时包的关系

运行时包应把 `report_version` 作为显式输入或生成分支，但当前对外只允许 Lite：

```yaml
report_version: lite | pro | unknown
```

如果 `report_version` 为 `unknown`：

- 输入不足、用户只想快速理解：默认 Lite。
- 证据链完整、用户需要机制解释：仍默认 Lite，并引导后续主题方案或人工支持；Pro 暂不上线。
- 用户状态高风险：不默认生成 Pro，先进入安全边界。

## 8. 质量检查

Lite 检查：

- 是否快速命中。
- 是否保留 3 到 6 条画面依据。
- 是否有主题连接。
- 是否只有低压小步建议。

Pro 检查：

- 是否解释核心主轴。
- 是否完成逐圈整合。
- 是否说明生克、失衡和能量流动。
- 是否有根因链和阶段性调节路径。
- 是否仍然保持报告边界，没有变成 21 天计划。
- 是否仍标记为内部预备形态，而非对外交付版本。

# 报告任务定义

> 状态：draft
> 文档版本：0.1.0
> date：2026-05-15
> owner：CEO / Knowledge Base
> source_of_truth：当前目录/30-应用适配/10-aimandala/05-报告任务定义.md
> product_decision：projects/aimandala/docs/decisions/2026-04-06-用户分群与产品矩阵决策.md

本文定义 `aimandala` 报告产品的任务边界。

## 1. 问题定义

用户在看曼陀罗时，先需要的通常不是长周期改变，而是先看懂自己当前在什么状态、这张画在表达什么、当前主题的卡点是什么。

报告就是解决这件事的产品。

## 2. 用户场景

报告主要服务以下场景：

- 用户想知道这张画在说什么。
- 用户对自己有感受，但说不清。
- 用户卡在某个具体议题上，需要解释和方向。
- 用户已经做过一定自我探索，想看更深一点的机制。

## 3. 本轮范围

报告本轮只做：

- 解释画面。
- 命名状态。
- 梳理模式。
- 连接现实议题。
- 给出轻量建议或阶段性调节路径入口。

## 4. 不做范围

报告不做：

- 连续训练。
- 长周期陪伴计划。
- 主题方案完整设计。
- 21 天定制方案完整设计。
- 医疗、心理或财务承诺。

## 5. Lite / Pro 对应

- Lite：当前对外交付的正式报告版本，负责快速命中、看见当前状态、保留画面依据、给低压小步建议。
- Pro：内部预备版本，暂不上线，保留完整解释核心主轴、逐圈机制、生克失衡、能量流动、根因链和阶段性调节路径的实现能力。

## 6. 方案比较

可选方案有三种：

1. 直接做完整方案产品。
2. 先做报告，再转主题方案。
3. 先做报告，再转 21 天定制方案。

当前阶段最合理的是第 2 和第 3 种，不优先把报告直接做成方案产品。

原因是：

- 用户首先需要看懂自己。
- 报告更适合承接理解和命名。
- 方案产品更适合承接改变和练习。

## 7. 验收标准

一份合格的报告任务定义应满足：

- 能明确报告服务的用户是谁。
- 能明确报告解决什么问题。
- 能明确报告不做什么。
- 能明确 Lite 和 Pro 的差异，并清楚标注 Pro 当前暂不上线。
- 能明确下一阶段该交给谁。

## 8. 下一阶段 handoff

报告任务定义完成后，可交给：

- `30-应用适配/10-aimandala/03-解读报告生成最小规则.md`
- `30-应用适配/10-aimandala/04-Lite-Pro报告分流与交付口径.md`
- 后续的运行时知识包

## 9. 最小结论

报告是理解入口，不是改变终点。

它先负责让用户看懂自己，再决定要不要进入主题方案或 21 天定制方案。

本文定义健康身体主题解读报告的段落模板。

报告语言风格统一由 [07-报告语言风格指南.md](07-报告语言风格指南.md) 控制。本文只定义健康身体报告结构和段落职责。

**核心定位**：健康身体在曼陀罗解读中的定位是**身体能量和承载力层面**——观察身体如何承载心理议题、情绪压力和关系模式。不输出医疗判断，不替代专业医疗建议。

## 1. 使用前提

生成健康身体报告前，先满足这三个条件：

1. `user_theme` 已确认是 `健康身体`（或画面证据落到身体能量/承载力/阻滞主题）。
2. 已完成基础画面观察。
3. 已选出至少 1 个身体条款。

**重要边界**：健康身体报告只做身体能量和承载力层面的解释，不输出医疗判断。

## 2. 报告主线

健康身体报告只维护一条主线：

`画面信号 -> 身体能量状态 -> 承载力/情绪机制 -> 浮现议题回译 -> 身体线索 -> 低风险建议`

其中：

- 主线围绕身体能量和承载力展开：身体如何承载心理议题、情绪压力、关系模式。
- 浮现议题可以出现，但只能作为身体背景。
- 不把身体写成医疗诊断，不替代专业医疗建议。

## 3. 固定段落

健康身体报告按以下顺序输出：

1. 整体直觉
2. 身体主线确认
3. 三圈身体读法
4. 机制拆解
5. 浮现议题回译
6. 身体线索
7. 生机
8. 调整建议

## 4. 段落路由

| 段落 | 主要内容 | 典型输入 |
|------|----------|----------|
| 整体直觉 | 第一眼印象和身体能量整体感受。 | 画面总感、能量轻重、流动还是阻滞。 |
| 身体主线确认 | 说明本次报告围绕的身体状态。 | 承载力、能量流动、湿寒/温暖。 |
| 三圈身体读法 | 分别看内圈、中圈、外圈。 | 身体核心能量、情绪承载、行动落地。 |
| 机制拆解 | 解释身体为何呈现这种状态。 | `body.overload`、`body.dampness`、`body.tension`。 |
| 浮现议题回译 | 把情绪/关系/财富翻回身体承载。 | 情绪→身体容器；关系→身体如何承载关系压力。 |
| 身体线索 | 写身体层面的观察，但不写诊断。 | 身体能量偏沉重/轻盈、可能有阻滞感。 |
| 生机 | 保留可用力量和出口。 | 身体觉察能力、承载力扩容、释放路径。 |
| 调整建议 | 给低风险动作。 | 身体觉察、慈悲对待、释放练习。 |

## 5. 段落职责

### 5.1 整体直觉

先写第一眼看到什么，再写这张画整体传达的身体能量感受。

要求：先被看见，不写诊断，不抢结论。

### 5.2 身体主线确认

明确这份报告围绕什么身体状态展开。

可写方向：

- 身体是情绪的容器，身体状态反映内在能量的轻重和流动。
- 当前更像是在看身体承载力，而不是单看身体好不好。

### 5.3 三圈身体读法

三圈写法固定如下：

- 内圈：更靠近身体核心能量、内在安全感和自我接纳。
- 中圈：情绪承载、感受积累、滋养与阻滞。
- 外圈：现实行动、落地能力、与世界互动。

健康身体报告优先级：

1. 内圈看身体核心能量和承载力基础。
2. 中圈看情绪承载和身体感受积累。
3. 外圈看行动落地和现实互动。

### 5.4 机制拆解

这里解释身体为什么会呈现当前状态。

优先使用的机制（来自 [03-健康身体.md](../20-疗愈体系/10-议题层/10-议题本体/30-现实/03-健康身体.md)，来源状态 `source_supported_draft`）：

| 条款ID | 条款名称 | 核心描述 | 来源 |
|--------|----------|----------|------|
| `body.bearing` | 身体承载能力 | 身体如何承载心理议题、情绪压力和关系模式。当承载过重时，身体会以症状形式"报警"。 | 《真原医》 |
| `body.overload` | 承载过重 | 身体承载了过多心理压力。常见表现：身体紧绷、疲惫。 | 《真原医》 |
| `body.dissociation` | 身体解离 | 身体与感受分离，无法感知身体信号。可能关联早年创伤或长期情绪压抑。 | 《创伤与复原》 |
| `body.emotion_container` | 情绪的身体承载 | 情绪不仅存在于心理，也存在于身体。身体是情绪的容器，积压的情绪以身体症状呈现。 | 《真原医》+《ACT》 |
| `body.tension` | 身体紧张模式 | 身体特定部位储存情绪压力。肩膀/颈部：承担压力；胸部/腹部：情绪积累。 | 《真原医》 |
| `body.dampness` | 湿寒（沉重能量） | 身体偏向沉重、迟缓、阻滞。可能关联未处理的情绪、长期压力。 | 《真原医》 |
| `body.warmth` | 温暖（轻盈能量） | 身体偏向轻盈、流动、有活力。与身体承载力、情绪释放相关。 | 《真原医》 |
| `body.trauma_stored` | 身体保存创伤 | 身体会以症状形式保存创伤信号。赫尔曼认为身体是创伤的第三个存储场所。 | 《创伤与复原》 |
| `body.alarm` | 身体警报 | 身体对危险信号的反应（战斗/逃跑/崩溃）。警报过度激活可能导致慢性紧张。 | 《创伤与复原》 |
| `body.action_capacity` | 行动落地能力 | 身体与行动力的关系。身体是否"愿意"行动，还是有阻力。 | 《ACT》 |

**画面信号对应**（来自议题本体）：

| 条款ID | 画面信号 |
|--------|----------|
| `body.bearing` | 内圈厚实、能量沉稳 → 身体承载力较好 |
| `body.overload` | 内圈沉重、颜色偏暗、能量受压 → 身体承载过重 |
| `body.dissociation` | 内圈模糊、与身体感知脱节 → 可能有身体解离 |
| `body.emotion_container` | 内圈有情绪积累、颜色混杂 → 可能有情绪身体化 |
| `body.tension` | 特定区域紧张 → 对应可能的议题方向 |
| `body.dampness` | 颜色偏暗、土色浓重 → 可能有湿寒积累 |
| `body.warmth` | 颜色偏暖、有流动感 → 身体能量较轻盈 |
| `body.trauma_stored` | 内圈有创伤线索、身体感知阻滞 → 可能有身体保存创伤 |
| `body.alarm` | 外圈有警报线索 → 可能有身体警报过度激活 |
| `body.action_capacity` | 外圈稳定、能量落地 → 行动落地能力较好 |

### 5.5 浮现议题回译

当报告里出现情绪、关系、财富等线索时，先回译成身体承载机制，再简短提及背景。

| 浮现议题 | 身体健康翻译 | 报告深度 |
|----------|-------------|----------|
| 情绪能量 | 身体是情绪的容器，身体症状是情绪积累的表现 | hint/brief |
| 亲密关系 | 身体如何承载关系压力，关系中的身体反应 | brief |
| 财富关系 | 身体承载力与财富行动力相关 | hint |
| 安全感与匮乏感 | 身体如何承载安全感的议题 | hint |
| 事业 | 身体与行动力、落地能力的关系 | brief |

### 5.6 身体线索

这里写身体层面的观察，但不写诊断。

可写：

- 身体能量偏向沉重/轻盈——这可能与身体承载的情绪压力有关。
- 内圈有一些阻滞感——这可能代表身体承载了一些需要释放的东西。
- 外圈比较稳定——这可能代表身体有一定的落地和行动能力。

不可写：

- 你身体有某种疾病。
- 你的身体有某种具体症状。
- 你的身体问题导致了你的情绪/关系问题。
- 你必须做某种身体活动或治疗。

**重要**：身体信号只能作为"线索"，不能生成诊断。

### 5.7 生机

每份健康身体报告必须保留生机，不只写卡点。

生机可以来自：

- 身体承载力有扩容的空间——身体不是一成不变的。
- 身体有自我释放的智慧——身体知道如何处理积压的情绪。
- 能以友善的方式对待身体——身体慈悲本身就是疗愈的开始。
- 觉察本身就是开始——能看见身体信号，已经是重要的第一步。

### 5.8 调整建议

建议只给低风险动作，优先顺序：认知调整 → 情绪调频 → 具体练习。

**调整建议与条款对照**（来自议题本体）：

| 条款 | 认知调整 | 情绪调频 | 具体练习 |
|------|----------|----------|----------|
| 承载过重 | "身体可能承载了一些需要释放的压力" | 黄色画提升承载力 | 站桩固脾胃，感受身体 |
| 身体解离 | "能否感知到自己的身体？身体有哪些信号？" | 温和的身体扫描冥想 | 从每天5分钟身体觉察开始 |
| 湿寒积累 | "身体能量沉重可能与未处理的情绪有关" | 红色画温暖、蓝色画放松 | 温和的身体活动，释放阻滞 |
| 情绪身体化 | "情绪是身体的语言，身体在通过症状传递信息" | 绿色画流动、开放 | 记录身体感受日记 |
| 身体警报过度 | "身体警报可能在过度警觉状态" | 蓝色画平静 | 呼吸练习，激活副交感神经 |
| 身体慈悲（正向） | "身体不是敌人，而是信息的载体" | 温暖色冥想 | 用友善而非评判的方式对待身体 |

**安全边界提醒**：
- **不输出医疗判断**：不写成"你的身体有某种疾病"或"你有某种身体症状"
- **不说"身体导致"**：不说"你的身体问题导致了..."等因果表达
- **不替代医疗建议**：不输出具体的医疗或治疗建议
- **不说"必须运动"**：不把身体活动写成必须的疗愈方式
- **身体信号只是线索**：身体信号只能作为背景线索，不能生成诊断
- **不说"你身体不好"**：避免让用户对自己的身体产生负面评价

## 6. Lite / Pro 使用差异

- Lite：先命中信号类型，保留少量关键条款，输出短而清楚的身体解释。
- Pro：在 Lite 基础上展开逐圈机制、回译线索。MVP 阶段暂不上线。

## 7. 质量检查

生成完成后检查：

- [ ] 是否始终回到健康身体主线（身体能量/承载力/阻滞）
- [ ] 是否把浮现议题回译回身体承载机制
- [ ] 条款（body.*）是否正确嵌入到机制拆解和调整建议中
- [ ] 是否遵守安全边界（不写医疗判断、不替代医疗建议）
- [ ] 是否保留生机
- [ ] 身体信号是否仅作为线索而非诊断输出

## 8. 风险路由

> 本节对齐 60-运行时知识包/10-aimandala-解读报告生成最小包.md 第13节。
>
> 风险路由优先于主题路由和报告生成。

### 8.1 高风险场景

| 风险类型 | 画面信号触发条件 | 默认动作 | 报告表达边界 |
|---------|-----------------|---------|------------|
| 医疗症状 | 内圈或中圈出现具体器官/身体部位缺失；身体轮廓扭曲或变形；疼痛符号（咬牙、皱眉、捂痛部位）；警示色（深紫/深黑）聚集于身体区域；画面整体呈现明显身体不适或疾病意象 | 停止医疗判断，不输出身体症状结论，建议专业支持 | 只保留"身体能量偏沉重/轻盈"等低风险观察和身体觉察提示 |
| 严重身体症状 | 内圈出现肢体缺失/身体极度扭曲/能量完全阻滞（全黑/全灰/无流动感）；画面传达强烈身体失控感；反复出现外伤/疤痕/疾病等具体身体意象 | 停止解读，转稳定化，不做机制拆解或根因分析 | 不在报告主体输出任何身体诊断性内容 |
| 创伤身体化 | 内圈有明显身体保存创伤信号：反复出现的伤口/疤痕意象；身体区域出现隔离/冷冻感；画面呈现"身体解离"（身体感知模糊、与感受脱节） | 停止深度解读，转承接和外部支持提示 | 只做低强度观察，不做根因暴露 |
| 孕期/特殊生理期 | 画面出现与生育/孕期/流产等相关的具体身体意象；身体区域呈现明显身体特殊性画面 | 不输出任何孕期/特殊生理相关身体判断，建议专业支持 | 只保留低风险整体身体能量观察 |
| 自伤/自杀风险信号 | 画面出现割伤/自伤/绝食/身体自我攻击等具体意象；内圈呈现"活不下去"的能量状态 | 停止报告生成，立即触发外部专业支持提示 | 不输出任何画面分析结论 |

**通用动作规则**：一旦命中上述触发条件之一，立即停止报告生成中的医疗/身体诊断类内容，转入外部支持引导。

### 8.2 画面信号级别的风险触发

以下画面信号组合应触发风险路由：

**一级触发（立即停止医疗判断，建议专业支持）：**

- 身体部位（器官）具体缺失或变形
- 疼痛符号（咬牙、捂痛等）与身体区域关联出现
- 警示色（深紫、深黑）聚集于身体核心区域

**二级触发（停止解读，转稳定化）：**

- 内圈能量完全阻滞（全黑/全灰/无流动感）
- 身体区域出现明显创伤意象（伤口、疤痕、疾病）
- 身体与感受严重分离（解离状态）

**报告表达安全边界：**

- 只要进入风险路由，报告只能表达"身体能量状态"的低风险观察
- 禁止将身体信号写成诊断结论
- 禁止在风险路由触发后继续展开机制拆解
- 禁止将身体问题与其他议题写成因果关系

### 8.3 禁止句式（医疗相关）

以下句式在健康身体报告中严格禁止：

| 禁止句式 | 替换建议 |
|---------|---------|
| "你的身体有某种疾病" | "从画面看，身体能量偏沉重，可能需要更多关注" |
| "你的身体有某种具体症状" | "身体可能有某种需要释放的积累" |
| "你的身体问题导致了你的情绪/关系问题" | "身体的能量状态可能与当前的情绪压力有关" |
| "你必须做某种身体活动或治疗" | "如果有条件，可以尝试温和地关注身体感受" |
| "你的身体在报警" | "身体可能在传递一些需要被看见的信息" |
| "你身体指标/器官有问题" | "从画面看，身体能量的流动可能有阻滞" |
| "你身体不好/你身体有问题" | 避免任何负面身体评价；改为"身体在承载一些需要释放的东西" |

**核心原则**：所有涉及身体的表达只能作为"线索背景"，不能生成诊断，不能产生羞耻感，不能暗示用户"必须"采取某种身体行动。

# 报告语言风格指南

> 状态：draft
> 文档版本：0.1.0
> date：2026-05-18
> owner：CEO / Knowledge Base
> source_of_truth：当前目录/30-应用适配/10-aimandala/07-报告语言风格指南.md

本文是 `aimandala` 解读报告的唯一语言风格入口。

其他文档可以定义结构、条款、路由和安全边界，但不再单独定义报告语气。运行时生成报告时，以本文为语言风格源。

## 1. 风格目标

报告读起来应像一位稳定、有经验的疗愈师在陪用户看画。

它需要同时做到：

- 有画面依据。
- 有疗愈感。
- 有边界。
- 有行动出口。

## 2. 基本语气

- 先接住用户，再进入分析。
- 先说看见了什么，再说这可能意味着什么。
- 语言温和、清楚、有陪伴感。
- 不用审判、训导、命令或诊断口吻。
- 不把用户的问题写成缺陷。

## 3. 疗愈感写法

优先使用这类表达：

- 这张画里，我先看到的是……
- 这里不是在说你没有能力，更像是在说……
- 这部分可以先不用急着改变，先看见它已经很重要。
- 如果把这个线索放回财富关系议题，它更像是在提醒你……
- 画面里不只有卡住，也有一部分力量还在往外找出口。
- 你可以先从一个很小、身体能承受的动作开始。

避免使用这类表达：

- 你就是……
- 你一定……
- 你必须……
- 说明你有问题。
- 这就是你的根因。
- 你应该立刻……

## 4. 分析与疗愈的比例

Lite 报告：

- 分析占 40% 左右。
- 安抚、承接和可执行小动作占 60% 左右。
- 不展开复杂根因链。

Pro 报告：

- 分析占 60% 左右。
- 安抚、承接和调节路径占 40% 左右。
- 可以解释机制，但每个机制后都要留出生机或下一步。

## 5. 段落风格

整体直觉：

- 像疗愈师拿到画后的第一眼感受。
- 不要一上来就下结论。

画面依据：

- 语言要具体，但不要像检测报告。
- 每条依据后尽量跟一句“它可能在说什么”。

财富核心解读：

- 不写财务结果。
- 把财富写成资源、价值、承载、交换和安全感的关系。

浮现议题回译：

- 可以提到情绪、关系、家庭、身体和事业。
- 提到后必须拉回财富主线。
- 不展开成另一份主题报告。

建议：

- 给小动作，不给命令。
- 给可观察的练习，不给高风险决策。
- 建议语气要像邀请，不像任务布置。

## 6. 安全边界

风格可以温柔，但边界不能放松。

报告不能输出：

- 财务预测。
- 投资建议。
- 职业决策建议。
- 心理诊断。
- 医疗判断。
- 确定性因果。

需要边界提示时，用温和表达：

- 这份报告更适合作为自我观察，不替代现实中的财务或专业决策。
- 如果这个议题已经影响到安全、债务、健康或关系暴力，需要优先寻求现实中的专业支持。

## 7. 统一入口规则

- 修改报告语气时，只改本文。
- 条款文件只提供内容素材。
- 模板文件只定义段落结构。
- 路由文件只定义条款进入哪个段落。
- 运行时 prompt 只从本文读取语言风格。
