## 1. 一句话结论

当前 `Pro report chat` 的定位是：

**围绕本次报告做解释、追问和温和延展，而不是独立长期陪伴聊天产品。**

## 2. 为什么现在要先把边界钉住

如果当前不先定义边界，后面很容易出现两个问题：

1. 页面上看起来只是一个聊天框，但实际上承担了过多产品承诺
2. 实现层会把 `Pro report chat` 做成半个独立 `Conversation` 系统，打断当前 MVP 收口

因此这一版必须先把“能做什么、不能做什么、上下文从哪里来、安全边界在哪”说清楚。

## 3. 当前用户可以问什么

当前建议支持三类问题：

1. 报告解释类
   - 某一段是什么意思
   - 某个关键词代表什么
   - Lite 与 Pro 某部分差异如何理解
2. 本次作品追问类
   - 围绕本次作品颜色、结构、三圈结果、主题做进一步追问
   - 询问本次作品反映出的重点、张力、倾向
3. 温和延展类
   - 用户问“我接下来可以怎么理解自己”
   - 用户问“我最近可以留意什么”
   - 用户问“如果我还想继续探索，可以从哪里开始”

当前回答都应默认围绕**本次作品 + 本次报告**展开，而不是脱离上下文自由发散。

## 4. 当前不支持什么

当前明确不支持以下方向：

1. 跨多次作品建立长期陪伴记忆
2. 独立心理咨询式深度会谈
3. 完整疗愈计划生成
4. 绘画训练或创作陪伴
5. 与报告无关的开放式百科问答
6. 高风险情绪危机处置承诺

如果用户问题明显超出当前范围，系统应优先：

1. 温和收束回本次报告语境
2. 提供有限的下一步建议
3. 必要时给出边界提示

## 5. 当前上下文最小输入

当前建议 `Pro report chat` 只依赖一份最小上下文对象，而不是拼接整站状态。

最小上下文建议包含：

1. `reportId`
2. `reportType`
   - 当前至少区分 `lite` / `pro`
3. `workSummary`
   - 本次作品的轻量摘要
4. `detectionSummary`
   - 三圈检测的关键结果
5. `interpretationSummary`
   - 本次解读主结论摘要
6. `reportSections`
   - 可引用的报告段落摘要
7. `themeTags`
   - 当前作品的主题标签
8. `conversationConstraints`
   - 当前会话的边界说明

当前先不要依赖：

1. 用户长期画像全量历史
2. 多报告聚合记忆
3. 外部复杂 agent graph

## 6. 推荐的系统行为

当前建议 `Pro report chat` 默认遵守下面四条行为原则：

1. 先解释，再延展
   - 优先回答报告里已经出现的内容
2. 先收束，再发散
   - 先围绕本次作品和本次报告作答
3. 先温和建议，再升级承诺
   - 只给出轻量启发，不承诺系统性疗愈结果
4. 先承认边界，再提供下一步
   - 遇到越界问题，不要硬答

## 7. 安全边界

当前建议至少定义下面三层安全边界：

### 7.1 产品边界

1. 不把 AI 问答包装成专业医疗或心理治疗服务
2. 不承诺诊断、治愈、危机干预
3. 不把单次报告追问误导成长期关系承诺

### 7.2 回答边界

1. 避免绝对化判断
2. 避免高压指令式建议
3. 避免把报告内容表达成确定事实
4. 默认使用解释性、陪伴性、启发性语气

### 7.3 风险处理边界

如果用户输入出现明显高风险情绪或危机信号，当前建议：

1. 不继续沿原问题深挖
2. 先做安全导向回应
3. 视产品能力决定是否显示求助建议或人工支持指引

当前这部分应视为横切护栏，而不是把“风险能力域”正式升为当前一级 capability。

## 8. UI 与交互层的含义

这份边界定义对 UI 的含义是：

1. 入口应明确是“围绕报告继续提问”
2. 空态和引导文案应提示可问范围
3. 不要在视觉上伪装成通用聊天首页
4. 追问节奏应服务于“读报告 -> 提问题 -> 获得解释”这个链路

## 9. 对后续 Conversation 能力的接缝

这份边界不是要压死未来 `Conversation`，而是为了给它留出干净接缝。

未来独立 `Conversation` 时，可以平滑继承：

1. 当前报告上下文对象
2. 当前问答语气与安全边界
3. 当前“解释 -> 追问 -> 延展”的对话主线

但当前不应提前实现：

1. 跨报告统一记忆层
2. 多 agent 编排
3. 长期陪伴式主界面

## 10. 当前最小成功标准

如果当前 `Pro report chat` 满足下面四点，就算边界定义成功：

1. 用户能围绕本次报告继续提问
2. 回答明显基于本次报告，而不是泛泛而谈
3. 越界问题不会把系统拉成独立聊天产品
4. 后续独立 `Conversation` 时不需要推翻当前对象定义
