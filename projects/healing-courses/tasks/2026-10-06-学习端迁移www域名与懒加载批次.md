## 背景与目标

课程首页/详情页跳转 AI 师傅学习端（courses.jingshu.cc）体感慢。已定位三层原因并完成 P0（nginx gzip：1.1MB chunk 3.2s→0.63s）。本批次做剩余两层：

1. **域名合并**：学习端从 `courses.jingshu.cc` 迁入 `www.jingshu.cc/learn`（同机 42.192.65.145），消除跨子域 DNS 解析（~0.9s）+ TLS 握手（~0.2s）
2. **P1 懒加载**：markdown-flow-ui（three/katex/mermaid 全家桶 1.1MB）改动态 import，移出首屏关键路径

## 方案（用户已拍板 A）

Next.js `basePath=/learn` 重建 fork web 镜像，www 域名单条转发；courses 旧域 301 兜底。

### 关键架构事实（2026-10-06 侦察）

- 服务器跑的是 **fork 本地构建镜像**（tag 均为 :latest，含未提交微信支付 patch），非官方镜像
- 前端 API 寻址：fetch 根相对 `/api/config`（Next 路由处理器）→ 返回 `apiBaseUrl:""` → 后续走同源 `/api/*` → 内层 nginx → flask
- 后端 `public_urls.py`：`HOST_URL` 只允许纯 origin（不带路径）；支付回调 = `HOST_URL + PATH_PREFIX(/api) + /callback/*`；Stripe/Google 路径硬编码无前缀（未启用，记录为遗留）
- 内层 nginx（容器 :8080，配置 bind-mount `/opt/ai-shifu/docker/nginx.conf`）路由：`/api/i18n`、`/api/config` → cook-web:5000；其余 `/api/` → flask:5800；`/` → cook-web:5000
- cook-web next-server 监听 5000（PORT env）；Next 15.5.25
- basePath 会把 `/api/config`、`/api/i18n` 也挪到 `/learn/api/*` → 内层 nginx 需 remap

## 验收口径（qa basis）

1. `www.jingshu.cc/learn/c/75f1a0f0354c4bf891544d426eea6fb6` 返回 200，HTML 内资源链接均为 `/learn/_next/...`
2. `/learn/_next/` 资源带 gzip（Content-Encoding 头存在）
3. `www.jingshu.cc/api/config` 返回 `{"apiBaseUrl":""}`；`/api/i18n` 不 404
4. `www.jingshu.cc/api/callback/wechatpay-notify` POST 非 404（路由到 flask）
5. `courses.jingshu.cc/c/...` 301 到 www `/learn/c/...`；课站首页按钮链接已更新
6. 课站静态页（/、/course01/）回归正常，品牌 CSS 注入在 /learn 页面存在
7. 已知可接受影响：courses 旧域登录态失效（跨 host cookie 不迁移），用户需重新登录

## 实施修正与 QA 结果（2026-10-06）

- **Next 15.5.25 行为**：`basePath` 只作用于 HTML 资源 URL 生成，页面路由与资源实际仍在根路径服务 → 改为外层 nginx `proxy_pass http://127.0.0.1:8080/`（末尾斜杠剥离 /learn 前缀）解决，构建零代码改动
- 构建事故：`next build` 内存耗尽致整机挂起，强制重启恢复；已加 4GB swap（/swapfile，fstab 持久化）；构建产物在重启前已完成
- 服务器新增 fork 构建工作区 `~/ai-shifu-build/`（rsync 源），web 镜像在服务器本地构建
- QA 全过：/learn/c/<id> 200+品牌注入、/learn/_next gzip、/api/config 200、wechatpay 回调 400（路由达 flask）、旧域 301、静态站回归、课站 5 处链接已上线
- **白屏修复（2026-10-06）**：`/learn/c/<id>` HTML 本身 200，但 Next 15.5 的 `basePath` 只给 app-router 动态 chunk 加了 `/learn` 前缀，webpack 运行时 / CSS / polyfills / main-app 仍以根路径 `/_next/...` 引用；www nginx 只有 `location /learn/`，`/_next/...` 落到静态站 `location /` 的 `try_files` 返回 404，React 无法启动、整页白屏。修复：在 `web-jingshu` 新增 `location /_next/` 反代到 `127.0.0.1:8080`（不剥离前缀），`nginx -t` 通过后 reload。验证：`/_next/static/chunks/webpack-*.js`、`main-app-*.js`、`polyfills-*.js` 与 4 个 CSS 均 200，Playwright 渲染出课程内容（标题「安顿内心：自我疗愈入门」+ 状态选择交互项）
- **课程短链（2026-10-06）**：课程 URL 里的 `/c/75f1a0...` 是学习端的内部 ID（`shifu_bid`，32 位 UUID，无 slug 机制）。为便于分享，在 `web-jingshu` 加 `location = /ke1` → 301 到 `/learn/c/75f1a0f0354c4bf891544d426eea6fb6`（`www.jingshu.cc/ke1` 即课1 好记入口）。已知限制：跳转后地址栏仍显示 UUID；若需地址栏本身干净，需给 fork 增加 slug 字段并前后端解析 + 重建部署
- .env HOST_URL 已收敛单行 `https://www.jingshu.cc`；PATH_PREFIX 维持 /api
