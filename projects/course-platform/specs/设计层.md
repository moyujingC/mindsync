## 1. 是什么

基于开源项目 ai-shifu（AI 互动课平台）fork 定制的课程交付平台，对外统一挂 `墨予镜` 品牌。

形态为单实例、多课程：一套部署、一个后台，承载多条内容线。已知的两条线：

- `疗愈课程线`：内容由 healing-courses 项目产出，首门课为 `曼陀罗自我疗愈入门`
- `AI 课程线`：内容项目待定

每条产品线一个入口落地页，学员从落地页进入平台对应课程。落地页可以风格各异，平台主体始终只有一套。

## 2. 不是什么

- 不是内容生产系统：课程脚本、Course Prompt、讲义归内容项目（healing-courses 等）维护
- 不是品牌站群：不为每条课程线单独部署一套平台，除非未来出现强品牌隔离需求
- 不是支付/电商系统：第一期不接支付，用邀请码或白名单内测
- 不是医疗或诊断服务：平台承载的疗愈课程遵守 healing-courses 的安全边界，平台本身不提供诊断、治疗效果承诺类功能

## 3. 边界

### 3.1 平台与内容

平台只负责"跑起来、可学习、可管理"。一门课能不能上线，由内容项目的边界文档和验收决定，平台方不审核内容正确性。

### 3.2 平台与公司内核

平台是 projects/course-platform 项目工作区的职责，不往 company/ 写运行时配置；服务器信息按 company/服务器与基础设施入口.md 的口径登记。

### 3.3 定制与上游

品牌替换、样式覆盖属于平台定制；修复上游 bug、跟版属于平台维护。定制改动不得破坏跟随上游的能力，具体约束见工程层。

### 3.4 与一镜一梳的关系

一镜一梳（aimandala）是曼陀罗解读报告链路，课程平台不承接报告交付，也不复用其用户数据。

## 4. 已确认的产品决策

| 决策项 | 结论 |
| --- | --- |
| 品牌 | `墨予镜`，统一挂在平台外壳 |

| 入口页 | 每条产品线一个落地页，汇入同一平台 |
| 支付 | 后置，内测期用邀请码/白名单 |
