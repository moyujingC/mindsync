## 1. 目标

把 ai-shifu fork 定制为墨予镜的 AI 互动课程平台，并本地跑通首门课程的端到端流程：学员从入口页进入 → 学习 MarkdownFlow 互动课 → AI 按 Course Prompt 应答。

## 2. 已确认决策

| 决策项 | 结论 |
| --- | --- |
| 品牌 | `墨予镜`，统一挂在平台外壳 |
| 部署形态 | 单实例、多课程；不为每条课程线单独部署 |
| 入口页 | 每条产品线一个落地页（疗愈线、AI 线），汇入同一平台 |
| 支付 | 首发不接支付，用邀请码/白名单内测，支付后置 |
| 源码策略 | fork 上游仓库，定制改动独立 commit，保留 upstream remote 便于合并 |

## 3. 待决策项

| 决策项 | 说明 | 建议 |
| --- | --- | --- |
| LLM 供应商 | 决定课程交付成本与中文效果 | DeepSeek 优先，成本低、中文好；接入层 ai-shifu 支持多模型，可后换 |
| 正式宿主 | 本地跑通后迁哪台服务器 | 参考 company/服务器与基础设施入口.md 再定 |
| fork 归属 | fork 到个人 GitHub 账号下 | 开代理后执行 |

## 4. 实施步骤

1. 恢复 GitHub 访问（本机当前直连超时），fork ai-shifu 到个人账号
2. 克隆 fork 到 `projects/course-platform/` 源码目录（目录名待定，如 `app/`）
3. Docker Compose 本地起全栈，验证：注册学员账号 → 导入一门测试课 → 完成一轮互动学习
4. 品牌定制：平台名、logo、主题色替换为墨予镜；确认定制点是否都能走配置/主题层
5. 首门课 `曼陀罗自我疗愈入门` 导入联调（内容脚本由 healing-courses 产出）
6. 补部署 runbook，决定正式宿主并迁移

## 5. 验收标准

- 本地 `docker compose up` 一条命令起全栈
- 品牌名与页面样式已替换为墨予镜，且改动不与上游文件大面积冲突
- 一门课程可完整学习到底，AI 应答符合 Course Prompt 设定
- 后台可创建、编辑、上下架课程

## 6. 风险

- 本机 GitHub 直连不通，fork/克隆阻塞；需要代理或镜像
- ai-shifu 具体配置项、定制点需拿到代码后核实，本 SPEC 中架构描述以官方 README 为准
- LLM 成本：互动课按 token 计费，课程脚本定稿后需测算单学员成本
