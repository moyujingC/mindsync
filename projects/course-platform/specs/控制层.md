本层定义平台与课程两类对象的状态机、异常处理和决策权限。任何工程层改动必须能对应到本层的一个状态或一次合法迁移。

## 1. 平台生命周期状态机

| 状态 | 含义 | 进入条件 |
| --- | --- | --- |
| `blocked` | 有前置阻塞 | GitHub 不可达、fork 未完成 |
| `source-ready` | 源码就绪 | fork 克隆完成，upstream remote 已配置 |
| `local-running` | 本地全栈跑通 | 源码方式起全栈（MySQL/Redis/后端/前端），注册→学习测试课→完成一轮互动，全链路通过 |
| `branded` | 品牌定制完成 | 墨予镜品牌名、logo、主题色替换生效，定制点清单已记录 |
| `course-integrated` | 首门课联调完成 | `曼陀罗自我疗愈入门` 完整学习到底，AI 应答符合 Course Prompt |
| `deployed` | 正式宿主部署完成 | runbook 就绪，线上验证通过 |
| `operating` | 常态运营 | 课程可上下架，监控与成本观察在跑 |

合法迁移：`blocked → source-ready → local-running → branded → course-integrated → deployed → operating`。

回退规则：`branded`、`course-integrated`、`deployed` 任何一步验证失败，回退到上一个状态修复，禁止带故障前进。`operating` 出现线上故障时回退到 `deployed` 的修复流程，不在线上直接试改。

## 2. 课程状态机（平台内一门课）

| 状态 | 含义 |
| --- | --- |
| `draft` | 脚本草稿在内容项目中，未导入 |
| `imported` | 已导入平台后台，待联调 |
| `testing` | 内测中，邀请名单内可学 |
| `live` | 已上线，对外可见可购（内测期等价于 testing 的扩大版） |
| `offline` | 已下架，学员不可进入 |

合法迁移：`draft → imported → testing → live → offline`；`offline → testing` 允许（重新内测），`live/testing → draft` 不允许（回内容侧改稿后重新导入）。

状态变更权限：`imported`、`offline` 由 Engineer 执行；`testing → live` 由 CEO 确认内容侧验收通过后执行。

## 3. 异常处理

### 3.1 LLM 应答异常

| 异常 | 处理 |
| --- | --- |
| 调用超时/失败 | 自动重试 1 次；仍失败则向学员提示"网络波动，请重发"，不静默丢消息 |
| 应答明显跑题 | 依赖 Course Prompt 约束 + 后台抽查；连续出现同一课程跑题，该课 `testing → offline` |
| 触发安全红线（医疗建议、诊断、疗效承诺） | 平台层不自动拦截，靠课程内容层 Prompt 约束；后台抽查发现即下架该课回 `draft` |

### 3.2 成本异常

- 阈值口径：首门课脚本定稿后，用 DeepSeek 实测单学员完整学完的 token 消耗，CEO 按实测值定阈值
- 单学员单课 token 成本超过阈值（阈值待实测后确定，见设计层待决策项）时，Engineer 收到告警
- 连续 3 天超阈：该课回 `offline`，降本方案（换模型/改脚本）由 CEO 决策

### 3.3 工程异常

| 异常 | 处理 |
| --- | --- |
| 构建失败 | 本地复现 → 定位 → 修；禁止在 main 上直接调试线上构建 |
| 上游合并冲突 | 以"保留定制补丁"为准：先合并上游再重放定制 commit；重放失败则该定制点降级为配置/主题层实现 |
| 数据异常（学员学习记录丢失） | 按运维事故处理：停止相关操作 → 从备份恢复 → 记录到 runbook |

### 3.4 内容异常

课程内容引发学员投诉或安全质疑时，CEO 决定该课 `testing/live → offline` 并回退内容项目处理，平台层不自行裁决内容对错。

## 4. 决策权限

| 决策 | 权限 |
| --- | --- |
| LLM 供应商与切换 | CEO |
| 单学员成本阈值及其调整 | CEO 定，Engineer 执行告警 |
| 支付接入时机 | CEO |
| 部署、上下架的技术执行 | Engineer |
| `testing → live` | CEO 确认内容验收后 |
| 跟随上游升级节奏 | Engineer 提方案，CEO 确认 |
