## 1. 技术选型

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 基座 | ai-shifu fork | 上游：github.com/ai-shifu/ai-shifu |
| 部署 | Docker Compose | 本地与服务器同一份 compose 配置 |
| 前端 | 随上游（Next.js） | 只做主题层覆盖，不重写 |
| 后端 | 随上游（Python） | 只做配置与最小补丁 |
| 存储 | 随上游（MySQL + Redis） | 备份策略在 runbook 中定义 |
| LLM | 待 CEO 确认，建议 DeepSeek | 通过平台配置接入，模型可换不动代码 |

选型原则：跟随上游默认值，不引入第二套框架；确需替换时先回设计层确认。

## 2. 代码组织

fork 克隆到 `projects/course-platform/app/`（目录名以实际克隆为准）。

- `upstream` remote 指向上游仓库，定期 fetch
- 定制改动全部独立 commit，commit message 加 `custom:` 前缀，与跟版 commit 区分
- 品牌定制优先级：环境变量/配置 > 主题样式覆盖 > 代码补丁；走到代码补丁一层需在工程层的定制点清单中登记
- 密钥只进 env 文件与服务器侧配置，不进 git

## 4. 环境分层

| 环境 | 用途 | 状态对应（控制层） |
| --- | --- | --- |
| 本地 Docker | 开发、联调、验收 | source-ready → course-integrated |
| 正式服务器 | 内测与运营 | deployed → operating |

环境间用同一份 compose 文件 + 不同 env，不维护多份部署描述。

## 5. 变更纪律

- 工程层任何改动对应控制层的一个状态或合法迁移，对不上的不改
- 跟版（合并上游）与定制（新补丁）不混入同一 commit
- 数据库结构由上游迁移管理，不手写建表；确需扩展先回设计层
