| 项 | 选型 | 说明 |

| 基座 | ai-shifu fork | 上游：github.com/ai-shifu/ai-shifu |

fork 克隆到 Monorepo 外独立仓库 `/Users/xinran/Downloads/dev/ai-shifu`（代码不嵌入 mindsync；定制 commit 与跟版 commit 分离，remote 结构 origin=fork / upstream=上游）。

- `upstream` remote 指向上游仓库，定期 fetch

## 6. 本地直跑实操备忘（2026-09-11 实测）

以下结论修正 INSTALL_MANUAL.md 中与本地实测不符的部分，本地起栈以本条为准。

| 事项 | 实测结论 |
| --- | --- |
| Python 依赖安装 | 用 uv（pip 直连与镜像均极慢）。requirements.txt 第 127 行 `--extra-index-url https://pypi.org/simple/` 会让 pip/uv 每个包都额外请求一次 pypi.org，国内网络下表现为假死（0% CPU、无连接、无日志）。本地改用 `requirements-local.txt`（仅剔除该行，其余不变）+ 清华镜像 |
| 数据库初始化 | MySQL 建空库 `ai-shifu`（utf8mb4）即可，`python -m flask db upgrade` 自动建表 69 张。库中残留旧 alembic 版本号时报 "Can't locate revision"，重建空库解决 |
| 迁移命令形态 | 必须用 `python -m flask db upgrade`。requirements 里的 Flask-CLI==0.4.0 抢占了 `flask` 命令行入口（老式 CLI，无 `--app`、加载不到 `db` 子命令），直接敲 `flask db upgrade` 报 "No such command 'db'" |
| 后端启动 | **本地 macOS 用 `python app.py`（Werkzeug），不要用 gunicorn**。gunicorn 走 fork，worker 里首次 DNS 解析（getaddrinfo 的 NAT64 检测）或代理检测（SCDynamicStore）会触发 Apple 框架 fork 不安全崩溃（SIGSEGV，崩溃报告见 ~/Library/Logs/DiagnosticReports/）。Linux 服务器无此问题，保留 gunicorn。启动时带 `NO_PROXY='*'` 跳过 _scproxy 系统代理查询 |
| 进程保活 | 终端会话退出会连带杀掉 nohup 后台进程（macOS 无 setsid）。本地后端、前端都在持久终端会话里跑；后续可换 launchd 常驻 |
| 前端联调 | `src/web` 下 `npm run dev`（Next.js 15，Turbopack）。开发模式自动把 `/api/*` 代理到 `127.0.0.1:5800`，浏览器只需访问 3000 端口 |
| 最小 .env 项 | `SQLALCHEMY_DATABASE_URI`（本机 MySQL，root 无密码）、`REDIS_HOST=localhost`、`SECRET_KEY`（随机生成）、`DEEPSEEK_API_KEY`、`DEFAULT_LLM_MODEL` |
| 模型名口径 | DEFAULT_LLM_MODEL 必须是 DeepSeek `/models` 接口实际返回的 ID。实测该 Key 返回 `deepseek-flash`、`deepseek-v4-pro`（没有 deepseek-chat，配错会在跑课时报"模型 X 不支持"）。当前用 `deepseek-v4-pro` |

启动顺序：brew services 起 MySQL/Redis → 后端 `python app.py`（5800）→ 前端 npm run dev（3000）→ `python -m flask console update_demo_shifu` 导入演示课（可重复执行，内容不变时自动跳过）。

排障备忘：课时报 "Content is still generating" 是上次运行残留的 Redis 锁，删除 `ai-shifu::run_script:<user_id>:<outline_bid>(:running)` 两个 key 后重跑。API 鉴权用 `Token` 请求头（不是 Authorization: Bearer）。
