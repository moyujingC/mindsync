## 2026-09-03 第一轮：开放问题对齐

### 决策 1：目标轨道 = 双线（AI 产品经理 + FDE）

- **结论**：双线叙事，不做取舍。
- **理由**（用户）：疗愈师客群大量是个人疗愈师或小团队，即便有团队体量也很小。针对这个客群做 FDE，本来就应该做成"产品 + 轻陪跑"的形式——这恰好天然兼顾双线，不影响叙事。
- **推论**：项目形态不是纯开源 benchmark，而是"产品 + 轻服务"的 FDE 交付结构；benchmark 是产品内核，疗愈师共创与陪跑是 FDE 叙事素材。

### 决策 2：外部验证入口 = 有，疗愈师共创

- **结论**：用户认识一些疗愈师，可以合作共创。
- **意义**：解掉 HA7CH 评分引擎的硬地板（必须被外部一线用户验证过）；同时回应课程方法论"请客户出题，而不是建好了给客户看"——评估集的"什么算好"由疗愈师参与定义。

### 决策 3：与墨予镜的关系 = 拆出来独立，品牌沿用墨予镜

- **结论**：项目是独立仓库（建在 dev/ 下），但品牌可能用墨予镜。
- **推论**：项目名称 myj-healer-bench（myj = 墨予镜）成立；墨予镜 AI Copilot 可自然地成为首个被测对象与真实使用数据来源，但不构成依赖关系。

### 决策 4：情绪向好率等主观指标 = 待方案

- **结论**：用户暂无成熟想法，由我方基于课程方法论提出候选方案，下一轮讨论。（见下方"待讨论提案"）

### 决策 5：MVP 时间预算 = 暂不约束

- **结论**：忽略时间预算，按质量标准推进。

## 待讨论提案：主观指标（情绪向好率）怎么测

背景：面试课直播回放警告"情感陪伴类 Agent 的情绪向好率等指标，涉及心理健康场景时不能随便下结论"；八门课的一致立场是主观效果不能交给模型自评。课程留下的空白即本项目的技术亮点。

### 方案候选（组合使用，不互斥）

**A. 弃用单一"情绪向好率"，改多维结构化 rubric**
- 把"情绪好不好"拆成可独立评分的维度：共情质量 / 回应适切性 / 安全性（有无伤害性表达）/ 边界感（是否该转介人）
- 判定链：LLM judge 初筛（与被测模型不同源）→ 疗愈师专家抽检校准 → 报告 judge 与人工一致率
- 依据：执行评判分离（排雷课 01）、judge 一致性要进报告（排雷课 06）、允许 verdict=None（设计模式之美 19）

**B. 主观感受转为用户自评量表，不让模型"读心"**
- 借鉴临床心理学的成熟做法：对话前后嵌入 0-10 情绪自评（类似 SUDS / 情绪温度计），把"情绪向好"从模型主观判断变成用户自我报告
- 好处：正面回应"不能随便下结论"——我们的答案是"不下结论，用标准化自评工具 + 专家校准"
- 风险：真实用户数据采集涉及伦理（知情同意、数据脱敏），需要先定伦理边界

**C. 行为层信号作为辅助证据，不单独成指标**
- 接话率、复访率等行为信号只做辅助佐证，不进核心评分（疗愈场景样本小，行为数据周期长）
- 依据：Agent 面试课 23 的"从用户目标反推 + 护栏指标"方法论

### 待用户拍板
- A/B/C 的组合方式与权重
- B 的伦理边界（是否 MVP 阶段只做疗愈师专家评审的自评，不采真实用户数据）
