## 一、需要你裁决的定义级矛盾（最优先）

这些是"文档之间各说各话、必须选一个口径"的问题，多数没有 objectively 对错，**需要你或疗愈师共创拍板**，然后才能统一全文：

| # | 矛盾 | 两派位置 | 涉及文档 |
|---|---|---|---|
| D1 | **三才 ↔ 三圈映射**（内圈=天还是地？） | 派A"内圈=地=深层"：TOPICS、mandala-5e、ONTOLOGY；派B"内圈=天=深层"：SYSTEM_CORE、WF-REPORT-GEN。**TOPICS 自己内部就两派并存**（§2.1 vs §4.1） | 5 份 |
| D2 | **"20 种失衡模式"的构成** | ONTOLOGY：偏旺5+偏弱5+相乘5+相侮5；mandala-5e：相生太过5+子病犯母5+相乘5+相侮5（偏弱不在其中）。数量同为 20，引用时掩盖了差异 | ONTOLOGY vs mandala-5e |
| D3 | **九宫折叠原则 vs 宫位读取实操** | ONTOLOGY："标准曼陀罗九宫信息折叠，领域判断主要靠议题输入"；TOPICS 每个议题的诊断入口全靠宫位读取；报告模板第 5 章九宫能量表**没有合法数据来源**（case-004 的读数实为从议题反推） | ONTOLOGY vs TOPICS/模板/case-004 |
| D4 | **S-014 一物两名 + S-022 未登记** | ONTOLOGY：S-014=内在小孩未被看见；visual-signal-map/state-healing-map 快速索引：S-014=回避退缩模式；S-022 在 ONTOLOGY 不存在 | 3 份 |
| D5 | **长期衍生状态的层级** | ONTOLOGY：根因层方向；mandala-5e 实际映射：全部是表现层/核心层状态 | ONTOLOGY vs mandala-5e |
| D6 | **"土多金埋·土不足型"** | "土不足"在五行逻辑上无法"埋"金，模式名前提与变体前提互斥；该变体不在 20 种标准库却被 TOPICS 和 case-004 采用 | mandala-5e vs TOPICS/case-004 |

**处理建议**：D1–D8 本质是"本体论层的单源原则"缺失——建议在 ONTOLOGY 里确立"状态 ID 只在 ONTOLOGY 分配、术语以 mandala-5e 为唯一标准、三才语义裁定一版"，然后逐文档统一。这批适合和疗愈师共创时一起裁决（正好落地"请客户出题"的课程方法论）。

## 二、双端真空带（产品级漏洞，审查共识：单端完整、跨端全空）

| # | 漏洞 | 要害 |
|---|---|---|
| P1 | **部署形态悬空**："本地存储、不上传云端"（P0 验收项 ENG-SYS-002）与"来访者 H5 零注册公网访问"+DeepSeek/GPT API 直接矛盾 | 不定下来架构无法动工；建议新增决策（D-017）选：云端私有实例 / 静态报告+云端问答最小公网面 |
| P2 | **来访者数据可见性未定义**："数据归疗愈师所有" vs "匿名安全空间"正面冲突；疗愈师能不能看来访者问答记录，全文只字未提 | 信任产品的地基，必须写进免责声明 |
| P3 | **报告生成侧危机干预裸奔**：危机话术只在问答侧；来访者填"活着没意思"主题，系统照常生成报告；"人工审核"无执行人 | 报告侧需输入危机检测（P0） |
| P4 | **链接权限模型**：零门槛+无撤销，敏感报告转发即失控；有效期/撤销分享在 P1；报告编辑后已分享版本语义未定义 | 有效期+撤销应升 P0；定义"分享=快照"语义 |
| P5 | **mode 可由客户端伪造**：WF spec 把 mode 写成输入参数，来访者改参数即可解锁疗愈师知识库+跳过 L2 护栏 | mode 必须服务端从会话来源推导 |
| P6 | **CodeAgent × 公网访问 = 代码执行攻击面**：提示注入→任意代码执行；安全护栏只有内容过滤无执行隔离 | MVP 改用 ToolCallingAgent 或禁用自由代码执行 |
| P7 | **"理解度提升 >50%"数学不可达**（5 分制下自评 4 分者需 6 分）且前测流程不存在 | 改绝对值口径（如"≥4.0 分比例 >60%"） |
| P8 | **未成年人/责任归属/合规整体缺席**：危机话术无人审核声明、疗愈师资质无约束、生成式 AI 备案义务 0 提及 | PRD"不做什么"至少排除未成年人 |
| P9 | **商业模式缺席**：谁是付费方、API 成本谁担、来访者端成本黑洞（零门槛无限制）、"产品+轻陪跑"边界未定义 | MVP 可不做支付，但要有商业假设节 |
| P10 | **"只做财富议题" vs 报告九宫全覆盖**：KNOWLEDGE-BASE 说 MVP 只做财富，报告模板要全议题、问答要跨议题关联——非财富议题无知识单元，P0 验收过不了 | 二选一：MVP 限定财富主题，或 13 议题各补最小知识单元 |
| P11 | **D-009 框架选型自相矛盾**：升级触发条件（3+Agent/状态持久化/企业级安全）在 MVP 设计中已全部满足，但未复审 | 新增决策复审；可保留 Smolagents 但需显式化解触发条件 |

## 三、指标口径冲突（至少 8 处数字打架）

采纳率 60%/70% 两派、完成率 50%/60%、问答满意度 3.5/3.8 分、使用频率 2/3 次、多视角 ≥2/≥3、10 分制与 5 分制换算冲突、状态总数 20/21、测试集 10 幅/11 案例、知识单元数量级过期（30 状态 vs 实际 21）。

**处理建议**（审查共识）：确立 **ACCEPTANCE 第六章为唯一口径源**，其余文档只引用不复述；指标表统一补"计算方式"列（现在多张表没有，面试会被"数字四问"打穿）。

## 四、知识与内容层问题（不阻断但影响专业可信度）

1. **临床诊断标签混入心理学对应**："焦虑障碍""ADHD""躯体化"进 ONTOLOGY/TOPICS——与"不做诊断"原则冲突，有实际伤害风险，建议删或移入"鉴别转介参考（仅疗愈师可见）"
2. **验证措辞超出证据**：SYSTEM_CORE 写"已验证/大量个案"，实际样本 11 例；state-healing-map 定义了三级来源分级但 21 个状态**没有一条实际标注**；case-004 的验证结论是"人工能写报告"而非"按规则能生成"（状态链绕开 5e 表、方案超出映射表、九宫读数无来源）
3. **议题表现态无数据**："状态×议题"的表现态清单不存在，报告第 6 章的数据源缺失（链路最薄一环）
4. **危机资源只有框架**：所有"建议寻求专业帮助"都没有具体转介路径（热线、指引）
5. **生机点/加权算法/方案粒度**：模板第 7 章无规则支撑；第 4 章跨圈加权未定义；方案无步骤时长
