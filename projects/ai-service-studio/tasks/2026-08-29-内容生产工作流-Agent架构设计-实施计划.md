## 任务清单

### 任务 1：迁移内容访谈 Skill 输出边界

**目标**

让内容访谈 Skill 只输出结构化素材库，不再输出可直接发布的公众号草稿。

**背景**

当前基础版可能混合了“素材提取”和“草稿生成”。按 SPEC 第 3.2 节，内容访谈的输出应为：

- 背景信息
- 关键动作
- 踩坑记录
- 数据结果
- 核心认知
- 来源标注

**产物**

- 更新后的 `myj-ai-content-agents/skills/interview.py`
- 输出格式规范文档：`specs/2026-08-29-内容访谈Skill输出格式规范.md`

**验收标准**

- [ ] 输出数据结构只包含 `Material` 列表，无 `draft`、`body`、`article` 等草稿字段
- [ ] 每条 `Material` 必有 `category`（取值限定为背景/动作/踩坑/数据/认知）、`content`、`source`
- [ ] 运行 `python -m myj_ai_content_agents.cli interview --topic ...` 后，输出中不出现完整段落或第一人称观点
- [ ] 内容单元组装 Skill 仍能正常消费该输出并生成内容单元

---

### 任务 2：用 LLM 替代硬规则做素材分类

**目标**

把内容访谈 Skill 中粗糙的关键词硬规则分类，替换为 LLM 驱动的结构化提取。

**背景**

SPEC 第 3.2 节关键提醒：“素材库质量是内容单元质量的天花板”。当前硬规则无法处理复杂素材，需要 LLM 按固定框架做分类和摘要。

**产物**

- 更新后的 `myj-ai-content-agents/skills/interview.py`
- 新增 prompt 文件（建议放在 `myj-ai-content-agents/prompts/interview_classifier.txt` 或内嵌）

**验收标准**

- [ ] 同一份原始素材输入，LLM 分类结果与人工判断一致率 ≥ 70%
- [ ] 分类失败或置信度低时，输出 `needs_human_review: true` 并给出原因
- [ ] 保留本地 fallback：LLM 不可用时回退到硬规则，不阻断流程
- [ ] 单元测试覆盖 5 种以上典型素材（背景、动作、踩坑、数据、认知各至少 1 条）

---

### 任务 3：补全审阅打磨 Skill

**目标**

把 `skills/review.py` 从占位实现补全为可执行的结构审阅 + 成稿综合审阅。

**背景**

SPEC 第 4 节要求控制在 2 轮审阅：

- 第一轮：结构审阅（结构重复、逻辑硬伤、素材重复）
- 第二轮：成稿综合审阅（表达、读者适配、专业准确性、传播潜力）

**产物**

- 更新后的 `myj-ai-content-agents/skills/review.py`
- 审阅检查清单文档：`specs/2026-08-29-审阅打磨Skill检查清单.md`

**验收标准**

- [ ] 结构审阅能检测并报告：结构重复、逻辑硬伤、素材重复
- [ ] 成稿综合审阅能检测并报告：术语密度过高、金句数量、引用缺失、结尾交付物缺失
- [ ] 审阅结果以结构化 JSON 输出，包含 `issues` 列表和 `pass` 布尔值
- [ ] 人工可通过 `cli review` 查看审阅结果并决定 approve / request_rework / failed

---

### 任务 4：限制审阅轮数为 2 轮

**目标**

让系统默认最大审阅轮数与 SPEC 第 4 节一致，从 3 改为 2。

**产物**

- 更新后的 `myj-ai-content-agents/models/content_unit.py`（或等效模型文件）
- 更新后的 CLI 逻辑

**验收标准**

- [ ] `ContentUnit.max_rounds` 默认值为 2
- [ ] 第二轮 `request_rework` 后，第三轮只能 `approve` 或 `failed`，CLI 明确提示
- [ ] 状态机流转图与文档第 8.5.2 节一致

---

### 任务 5：决策 Get笔记语义召回不可用问题

**目标**

明确 Get笔记个人开发者模式下语义召回 404 的处理方案。

**背景**

SPEC 第 8.1 节已记录：Get笔记个人模式下 `POST /api/v1/resource/note/recall` 返回 404，当前降级为关键词筛选。需要决定是接受降级、寻找替代方案，还是暂不依赖 Get笔记。

**产物**

- 决策记录：`specs/2026-08-29-Get笔记语义召回不可用决策记录.md`

**验收标准**

- [ ] 明确当前降级方案（关键词筛选）的适用范围和限制
- [ ] 列出至少 1 个备选方案（如本地向量化、切换其他知识库来源）
- [ ] 给出是否继续投入 Get笔记集成的结论

---

### 任务 6：设计选题 Agent 最小版本

**目标**

为选题 Agent 设计最小可行版本，明确首期是否只支持人工 CLI 传入。

**背景**

SPEC 第 7 节第二步才“把选题独立成 Agent”，第一步以人工传入选题为主。需要把这一临时状态文档化，避免无限期停留在 CLI 传参。

**产物**

- SPEC 草案：`specs/2026-08-29-选题Agent最小版本设计.md`

**验收标准**

- [ ] 明确最小版本的输入：关键词库、历史内容数据、人工确认选题
- [ ] 明确最小版本的输出：选题池 JSON / SQLite 记录
- [ ] 明确自动化边界：首期只做“人工确认后的选题结构化存储”，不做主动扫描
- [ ] 给出向“主动扫描”演进的条件和触发标准

---

### 任务 7：设计分发 Agent 最小版本

**目标**

为分发 Agent 设计最小可行版本，明确首期只做格式转换还是支持公众号 API 发布。

**背景**

SPEC 第 5 节要求“一个平台一个 Agent”。当前内容单元生成后需人工复制到各平台发布，需要把这一临时状态文档化。

**产物**

- SPEC 草案：`specs/2026-08-29-分发Agent最小版本设计.md`

**验收标准**

- [ ] 明确首期只支持公众号平台
- [ ] 明确首期只输出“公众号适配格式”（Markdown/HTML），不自动发布
- [ ] 定义输入：已审核内容单元 + 账号配置
- [ ] 定义输出：可粘贴到公众号后台的格式 + 发布记录占位
- [ ] 给出接入公众号官方 API 的条件和风险评估

---

### 任务 8：设计数据回流最小版本

**目标**

为数据回流设计最小可行版本，明确首期是否只支持人工填写发布数据。

**背景**

SPEC 第 6 节要求发布数据沉淀到飞书多维表格。当前无自动回传，需要把最小可行方案文档化。

**产物**

- SPEC 草案：`specs/2026-08-29-数据回流最小版本设计.md`

**验收标准**

- [ ] 定义最小数据表结构：内容 ID、标题、平台、发布时间、阅读量、点赞、评论、转发、收藏
- [ ] 明确首期存储位置：本地 SQLite 表
- [ ] 明确人工填写入口：CLI 子命令或模板文件
- [ ] 给出向“自动回传”演进的数据源和触发条件
