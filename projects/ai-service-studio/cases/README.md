这里维护可用于售前沟通、客户展示和交付复盘的案例索引。它借鉴“按需求进入、按专题浏览”的知识库导航方式，但案例内容只记录有来源、有边界的第一方证据或外部参考。

## 1. 使用方式

先按客户问题进入，再查看相应案例：

| 客户问题 | 优先查看 | 当前可展示资产 |
| --- | --- | --- |
| 一条重复流程卡住，不确定 AI 是否适合介入 | `真实交付`、`自用验证` | 待补真实或自用验证案例 |
| 资料散乱，团队复用效率低 | `真实交付`、`自用验证` | 待补真实或自用验证案例 |
| 想把行业经验和素材沉淀为内容或 Skill | `外部参考` | [实体店 AI 获客 Skill](../references/2026-07-07-实体店AI获客Skill案例参考.md)、[YouMind 内容生产与 Skill 变现](../references/2026-07-11-YouMind内容生产与Skill变现案例参考.md) |
| 想做企业 AI 试点或流程落地 | `真实交付`、`自用验证` | 待补真实或自用验证案例 |

当前处于验证期，暂无可对外表述为“客户成果”的真实交付案例。对外沟通时应如实说明，并把自用验证或模拟演示与真实客户案例分开呈现。

## 2. 案例类型与展示规则

| 类型 | 可以如何表达 | 必须具备的证据 | 禁止表达 |
| --- | --- | --- | --- |
| 真实交付 | “为某客户 / 匿名团队完成的交付” | 客户授权或可公开的脱敏记录、实际输入、交付物、反馈 | 未证实的业务结果、客户未授权的身份和材料 |
| 自用验证 | “在知行AI服务自身工作流中的验证” | 可复查的输入、过程记录、产物、验证结果 | 写成客户项目或客户效果 |
| 模拟演示 | “基于公开 / 脱敏素材的场景演示” | 素材来源、假设、演示产物、未验证事项 | 写成真实项目、真实客户或实际 ROI（投入产出比） |
| 外部参考 | “外部案例参考，供方法比较” | 原始来源链接或原文留存、提炼说明 | 暗示由知行AI服务完成，或改写后作为自有案例 |

外部案例只用于提炼结构、服务边界和可验证假设；客户展示页必须保留来源属性，不能通过替换行业、客户名或措辞把它变成自有案例。

## 3. 案例卡的最小结构

每张案例卡复用 [案例卡模板](../templates/案例卡模板.md)，至少写清：

1. 案例类型与可公开范围。
2. 场景、原有流程和问题。
3. 本次服务范围与明确不做范围。
4. 输入、过程、交付物和人工审核点。
5. 已验证结果、未验证事项和风险。
6. 证据链接、来源和客户授权状态。

结果只能写已记录的事实。没有前后对比、使用反馈或客户确认时，写“尚未验证”，不推测节省时间、增长、成交或 ROI。

## 4. 入库与升级流程

```text
外部材料 / 自用实践 / 客户交付
  -> 保留来源和过程证据
  -> 按模板写案例卡
  -> 核对展示类型与脱敏范围
  -> 加入本索引
  -> 客户授权后才进入真实交付展示
```

- 外部材料先进入 [`references/`](../references/)，并遵守“原文 / OCR 原文 + 参考提炼”的双文件规则。
- 自用验证和模拟演示先写案例卡；没有真实客户输入和反馈时，不升级为真实交付。
- 客户案例先完成脱敏与授权确认，再从交付复盘中提炼案例卡。
- 同一案例的内部工作底稿可放在 `delivery/` 或 `records/`；本目录只保留可展示的案例卡和索引。

## 6. 对外展示前检查

- [ ] 类型标签与正文一致。

- [ ] 每个结果都有可定位的证据；无证据处已写明“尚未验证”。
