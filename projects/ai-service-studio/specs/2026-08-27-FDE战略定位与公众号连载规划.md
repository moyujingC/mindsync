## 1. 核心判断

### 1.1 Harness 是 FDE 的软实力，也是定价基础

客户买的不只是"AI 能跑起来"，而是"AI 能在我这里持续、可靠、可验收地跑起来"。后者就是 Harness。

模型是买得来的，Harness 才是 FDE 真正的工作量和价值所在。

> 来源共识：Agent = Model + Harness
> - 2026-07-03-Harness Agent 脚手架实战课
> - 2026-08-25-DeepSeek Harness 前沿工程实践
> - 2026-07-28-FDE业务落地实战
> - 2026-05-26-Agent 设计模式之美（The model spends; the harness budgets.）

### 1.2 当前最佳业务路径

- **长期目标客群**：30-200 人的成长型公司，有真实业务流程和落地压力
- **启动路径**：用保险 / 疗愈作为练习场 + 早期案例 + 内容素材，建立 FDE 方法论和 Harness 模板；同时通过公众号建立"AI 落地专家"的泛行业认知，逐步吸引成长型公司
- **交付方式**：前期一人做全链路，同时并行谈同行合作，防备接不住的案子并保持行业交流

## 2. 战略定位

### 2.1 公众号定位

**定位**：泛行业 FDE + 企业 AI 落地实践

**个人介绍可强调**：
- 现任：FDE / 企业 AI 落地
- 过往：游戏行业制作人（懂交付、懂工程、懂跨职能）→ 保险 / 房产 / 疗愈（懂高信任行业的业务逻辑和痛点）
- 独特视角：**既懂技术交付，又懂"人的业务"**

### 2.2 目标客户

30-200 人成长型公司的创始人 / CEO / 一号位 / 业务负责人。

他们关心：
- AI 怎么帮我降本增效
- 怎么不踩坑
- 怎么落地
- 怎么评估效果

### 2.3 行业路径

| 行业 | 优先级 | 用途 |
|------|--------|------|
| **保险经纪** | 首选 | 高客单、有团队、有知识库需求、有合规要求；和成长型公司的 FDE 需求高度同构 |
| **疗愈师** | 差异化入口 | 熟悉、竞争少、可建立"高信任行业 FDE"标签；天花板低，适合作为个人定位背书 |
| **房产经纪** | 暂时观望 | 收入压力大，付费意愿弱；作为后续补充，不作为启动主战场 |

### 2.4 交付边界

- 前期一人做全链路，确保自己完全搞懂
- 同时并行谈同行合作：防备接不住的案子 + 保持行业交流
- 服务内容聚焦：场景诊断、需求翻译、流程拆解、原型验证、交付机制、Harness 搭建

## 3. 内容策略：公众号连载

### 3.1 为什么做连载

- 不是输出零散观点，而是在建立一个体系
- 每篇文章"一个点打透"，天然适合按顺序展开
- 读者会追着看、收藏、转发
- 对自己的学习：每个模块就是一次系统打透
- 后续可整理成电子书 / 小册子 / 课程

### 3.2 系列名称

**定稿**：《FDE 视角下的企业 AI 落地》

### 3.3 文章类型

两种类型，严格区分：

| 类型 | 字数 | 形式 | 目的 |
|------|------|------|------|
| **专业长文** | 3000-5000 字 | 认真做封面和文内插图，好好排版 | 建立专业背书，可被收藏转发 |
| **个人洞察与感悟** | 几百字 | 像发朋友圈，纯文字即可 | 展示思考过程，增强人设信任 |

### 3.4 连载结构：5 个模块，15-17 篇

#### 模块一：认知重塑（3 篇）
目标：让读者意识到"模型不是答案"，建立跟着你看下去的理由。

1. 《为什么企业 AI 项目总是在 POC 后死掉？》
2. 《Agent = Model + Harness：企业 AI 落地的新公式》
3. 《你的 POC 通过了，为什么还是不能上线？》

#### 模块二：Harness 核心层（5 篇）
目标：把 Harness 拆成可操作的工程层，每篇讲透一层。

4. 《评估集：Harness 的"尺子"》
5. 《指令层：为什么 AGENTS.md 比 Prompt 更重要？》
6. 《执行循环：从 ReAct 到 Loop Engineering》
7. 《工具与护栏：AI 的"手脚"与"安全带"》
8. 《状态与记忆：让 Agent 知道自己在哪》

#### 模块三：FDE 交付实战（3 篇）
目标：讲清楚 FDE 怎么做交付。

9. 《FDE 是什么，为什么它会成为 AI 时代的新交付方式？》
10. 《从 POC 到生产：AI 项目的 10 个死亡陷阱》
11. 《一个人做 FDE：从第一个客户到可复用的 Harness》

#### 模块四：行业落地案例（4 篇）
目标：用垂直经验做案例，展示"我能把 AI 落到具体业务里"。

## 4. 学习体系：以输出倒逼输入

### 4.1 卡片笔记法

**输入卡片**（来自课程）：

每张卡片只写一个观点，结构固定：

```
卡片标题：一个可复用的判断
- 这个观点是什么？
- 谁在哪里说的？（引用课程/章节）
- 适用的边界条件是什么？
- 反例或常见误用是什么？
- 我自己的判断（同意/修正/反对）
```

**主题卡片**（来自多张输入卡片）：

写长文时，先把相关输入卡片聚合成 5-8 张主题卡片：
- 主题卡片 1：问题是什么？
- 主题卡片 2：常见错误认知是什么？
- 主题卡片 3：正确做法是什么？
- 主题卡片 4：一个真实案例
- 主题卡片 5：你可以怎么做？

### 4.2 Agent 集群采矿

对每个选题，启动多个 Agent 并行走查课程：
- Agent 1：Harness 专项课（技术视角）
- Agent 2：FDE / 业务落地课（交付视角）
- Agent 3：设计模式 / 生产级排雷课（工程视角）
- Agent 4：产品经理 / 工作流课（应用视角）

### 4.3 输出层次

```
课程原文 / Agent 输出
        ↓
输入卡片（一个观点一张卡）
        ↓
主题卡片（一篇文章一组卡）
        ↓
草稿（卡片拼装）
        ↓
成稿（公众号文章）
        ↓
可复用资产（AGENTS.md 模板、评估集模板、上线 checklist 等）
```

**卡片库存放位置**：[projects/content-matrix/accounts/墨予镜/cards/](projects/content-matrix/accounts/墨予镜/cards/)

目录结构：

```

  themes/          # 主题卡片：一篇文章的一组卡片
  drafts/          # 文章草稿：由主题卡片拼装而成
  assets/          # 可复用资产：模板、checklist、话术
```

## 5. 模块一大纲（定稿）

### 第 1 篇：《为什么企业 AI 项目总是在 POC 后死掉？》

**目标**：用具体场景建立问题意识，引出 Harness。

**核心观点**：
- 很多企业 AI 项目 POC 跑得通，但离生产还很远
- POC 验证的是"模型能不能做"，生产验证的是"系统能不能持续、可靠地做"
- POC 到生产之间隔着：评估集、护栏、状态管理、可观测性、HITL、治理
- 失败原因不在模型，而在 Harness 没搭起来
- FDE 的价值是把 POC 变成可运行的生产系统

**主题卡片**：
1. 问题卡：POC 后死掉的典型症状
2. 归因卡：为什么模型不是瓶颈
3. 差距卡：POC 和生产之间的 6 个关键差距
4. 框架卡：Harness 作为失败归因的新维度
5. 案例卡：FDE 课中的神策 / Anthropic 案例
6. 过渡卡：下一篇将给出新公式

**预计字数**：3500-4500 字

---

### 第 2 篇：《Agent = Model + Harness：企业 AI 落地的新公式》

**目标**：建立 Harness 的核心认知锚点。

**核心观点**：
- Agent = Model + Harness 是多个课程的共同结论
- 模型决定智力上限，Harness 决定智力能在现实世界发挥几成
- Harness 的四种比喻：马具、操作系统、车间、刹车系统
- 企业 AI 的壁垒不在模型，在 Harness

**主题卡片**：
1. 公式卡：Agent = Model + Harness 的来源和含义
2. 比喻卡：四种比喻帮助建立直觉
3. 组件卡：Harness 的八层核心组件（概述，不深拆）
4. 关系卡：Harness vs Agent vs Workflow vs Skill
5. 落地卡：这个公式对企业决策者意味着什么

**预计字数**：4000-5000 字

---

### 第 3 篇：《你的 POC 通过了，为什么还是不能上线？》

**目标**：讲清楚 POC 和生产的鸿沟，引出 FDE 交付方式。

**核心观点**：
- POC 验证的是"模型能不能做"，生产验证的是"系统能不能持续、可靠地做"
- POC 到生产之间隔着：评估集、护栏、状态管理、可观测性、HITL、治理
- FDE 的工作就是把 POC 级的能力工程化成生产级 Harness
- 企业 AI 的第一步不是买模型，是定义"好"并建立可验收的标准

**主题卡片**：
1. 问题卡：POC 通过后为什么不能直接上线
2. 差距卡：POC 和生产之间的 6 个关键差距
3. 方法卡：FDE 的交付顺序（标准 → 评估集 → Harness → Prompt）
4. 案例卡：小哲电商 Agent 的生产交付 checklist
5. 行动卡：企业决策者现在可以问自己的 5 个问题

**预计字数**：3500-4500 字
