# 内容访谈 Skill 输出格式规范

> 日期：2026-08-29
> 关联 SPEC：[内容生产工作流 Agent 架构设计](../specs/2026-08-28-内容生产工作流-Agent架构设计.md)
> 关联任务：[内容生产工作流 Agent 架构设计 — 实施计划](../tasks/2026-08-29-内容生产工作流-Agent架构设计-实施计划.md)
> 适用范围：`myj-ai-content-agents/skills/interview.py`

---

## 1. 设计目标

内容访谈 Skill 的输出不是文章草稿，而是**结构化素材库**。素材库质量是内容单元质量的天花板。

本规范定义：
- 输入合同
- 输出数据结构
- 分类规则
- 禁止事项
- 人工介入点

---

## 2. 输入合同

### 2.1 必填输入

| 字段 | 类型 | 说明 |
|------|------|------|
| `topic_id` | string | 选题唯一标识 |
| `topic_title` | string | 选题标题/方向 |
| `account_id` | string | 账号标识，如 `enterprise-ai` |
| `content_type` | enum | 内容类型：`deep-dive` / `opinion` / `case-report` |
| `target_reader` | string | 目标读者一句话描述 |
| `core_question` | string | 本文要回答的核心问题 |

### 2.2 可选输入

| 字段 | 类型 | 说明 |
|------|------|------|
| `boundary` | string | 不可写边界、不能承诺的内容 |
| `source_keywords` | list[string] | 用于知识库召回的关键词列表 |
| `known_facts` | list[string] | 创作者已确认可公开的事实 |

### 2.3 禁止输入

- 客户资料、联系方式、完整私信
- 未脱敏内部文件
- API Key、密码、Token
- 未经创作者确认的第一人称经历

---

## 3. 输出数据结构

输出必须是结构化数据，建议用 Pydantic 模型定义。

### 3.1 顶层输出

```python
class InterviewOutput(BaseModel):
    topic_id: str
    account_id: str
    content_type: str
    materials: list[Material]
    summary: InterviewSummary
    human_review_flags: list[HumanReviewFlag]
```

### 3.2 素材条目

```python
class Material(BaseModel):
    id: str                    # 素材唯一标识，如 mt-{uuid}
    category: str              # 限定取值见 3.3 节
    content: str               # 素材正文，一句话到一小段
    source: SourceItem         # 来源标注
    confidence: float          # 分类置信度 0.0-1.0
    related_materials: list[str] = []  # 关联素材 ID
    tags: list[str] = []       # 可选标签
```

### 3.3 分类取值

`category` 只接受以下 6 种：

| 取值 | 含义 | 示例 |
|------|------|------|
| `background` | 背景信息：时间、场景、人物、条件 | "2024 年 Q3，某制造业客户启动 ERP 与 AI 集成试点" |
| `action` | 关键动作：具体做了什么、顺序是什么 | "第一步先盘点 17 个高频重复流程，第二步选出 3 个 ROI 最高的试点" |
| `pitfall` | 踩坑记录：哪些尝试失败了、为什么 | "初期直接让业务人员写 prompt，结果合格率不到 10%" |
| `data` | 数据结果：效率提升、成本变化、用户反馈 | "试点后单条客服工单处理时间从 8 分钟降到 2.5 分钟" |
| `insight` | 核心认知：做完之后对这件事的理解变化 | "企业 AI 落地的瓶颈不在技术，而在‘谁对结果负责’的权责不清" |
| `source-only` | 仅来源标注，暂无法归入以上 5 类 | 用于保留原始引用，等待人工分类 |

### 3.4 来源标注

```python
class SourceItem(BaseModel):
    source_type: str           # 取值：local_markdown / getnote / interview / public_link / unknown
    source_id: str             # 文件路径、笔记 ID、链接等
    source_title: str          # 来源标题
    quote: str = ""            # 原始引用片段（可选，需脱敏）
```

### 3.5 访谈摘要

```python
class InterviewSummary(BaseModel):
    total_materials: int
    category_counts: dict[str, int]
    core_insights: list[str]   # 本次访谈提炼出的 1-3 条核心认知
    gaps: list[str]            # 仍缺失的关键信息
    suggested_next_step: str   # 建议下一步：assemble / need_more_sources / need_human_clarify
```

### 3.6 人工复核标记

```python
class HumanReviewFlag(BaseModel):
    material_id: str
    reason: str                # 为什么需要人工复核
    severity: str              # low / medium / high
```

## 4. 分类规则

### 4.1 硬规则 fallback

当 LLM 不可用时，使用以下最小硬规则：

| 关键词模式 | 分类 |
|-----------|------|
| 包含“202X 年”“Q1/Q2/Q3/Q4”“当时”“初期” | `background` |
| 包含“第一步”“第二步”“流程”“做了”“尝试” | `action` |
| 包含“失败”“踩坑”“没想到”“问题是”“瓶颈” | `pitfall` |
| 包含“%”“分钟”“小时”“元”“提升到”“降到” | `data` |
| 包含“意识到”“发现”“本质”“核心”“关键” | `insight` |
| 无法匹配以上任何模式 | `source-only` |

### 4.2 LLM 分类提示词要求

LLM 分类必须遵循：
- 每个素材只归一类，不允许多标签；
- 如果素材同时包含动作和数据，优先按“最能支持核心问题的角度”分类；
- 无法判断时宁可标为 `source-only`，不强行分类；
- 必须返回 `confidence` 和 `reason`。

### 4.3 置信度阈值

- `confidence >= 0.8`：自动通过
- `0.6 <= confidence < 0.8`：保留，但标记 `human_review_flags`
- `confidence < 0.6`：标为 `source-only`，等待人工分类

---

## 5. 禁止事项

内容访谈 Skill 输出中**不允许**出现：

1. 完整文章段落或可直接发布的草稿；
2. 未经确认的第一人称观点（“我认为”“我经历过”“我的客户”）；
3. 创作者未确认的因果判断；
4. 未标注来源的数据或案例；
5. 超出输入边界范围的承诺性表述（“保证降本 50%”等）。

---

## 6. 人工介入点

1. **输入前**：创作者确认选题、目标读者、核心问题、不可写边界；
2. **输出后**：检查 `human_review_flags`，对低置信度素材重新分类或补充来源；
3. **进入组装前**：确认 `suggested_next_step` 为 `assemble` 后，才调用内容单元组装 Skill。

---

## 7. 与下游 Skill 的衔接

内容单元组装 Skill 的输入是 `InterviewOutput.materials`，它会：
- 按 `category` 排序和分组；
- 优先使用 `insight` 和 `data` 构建核心论点；
- 用 `action` 和 `pitfall` 支撑案例；
- 用 `background` 提供上下文；
- 把 `source-only` 素材留给人工处理，不进入自动组装。

---

## 8. 验收标准

- [ ] 输出 JSON Schema 与本文 3.1-3.6 节一致；
- [ ] `category` 取值只包含 6 种限定值；
- [ ] 输出中不出现完整草稿或第一人称观点；
- [ ] 每条 `data`/`insight` 类素材都有 `source` 标注；
- [ ] 置信度低于 0.6 的素材自动标为 `source-only`；
- [ ] 内容单元组装 Skill 能正常消费该输出。
