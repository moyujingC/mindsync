> 日期：2026-08-29

> 适用范围：`myj-ai-content-agents/skills/review.py`

---

## 1. 设计目标

审阅打磨 Skill 对内容单元进行结构审阅和成稿综合审阅，控制在 **2 轮** 内。人工最终审核标题、摘要和金句。

本清单把 SPEC 第 4 节审阅标准转化为可执行检查项，供规则版 Eval 和 LLM 审阅共同使用。

---

## 2. 审阅阶段

### 2.1 第一轮：结构审阅

在内容单元阶段先做结构审阅，不要在成稿后再大修结构。

| 检查项 | 规则 | 严重程度 |
|--------|------|----------|
| 结构重复 | 同一结构（问题定义 → 案例拆解 → 底层逻辑 → 可复制方法）不应在正文内重复出现 | high |
| 逻辑硬伤 | 论点与论据之间无跳跃；避免“因为 A，所以 B”但 A 与 B 无因果关系 | high |
| 素材重复 | 同一案例/数据/引语在正文内只应出现一次；若需重复引用，应使用摘要或回顾 | medium |
| 段落失衡 | 深度拆解型文章建议每部分字数差异不超过 30%；观点输出型每段不超过 300 字 | low |
| 标题-摘要-正文一致性 | 标题承诺、摘要概括、正文展开三者必须一致 | high |

### 2.2 第二轮：成稿综合审阅

| 检查项 | 规则 | 严重程度 |
|--------|------|----------|
| 术语密度 | 非技术读者可接受；每 1000 字中专业术语不超过 5 个，且首次出现需有解释 | high |
| 金句数量 | 加粗金句控制在 3 句以内 | medium |
| 金句句式 | 3 句金句句式应错开，避免连续使用同一修辞结构 | low |
| 案例可推敲 | 每个案例都能说明“谁、在什么场景、做了什么、结果如何、为什么值得写” | high |
| 引用可追溯 | 每个观点、数据、案例都有来源标注；无法追溯时用模糊表述（如“某制造业客户”） | high |
| 结尾交付物 | 结尾给出可截图/可收藏的交付物：清单、框架图、行动步骤、判断标准 | medium |
| 读者适配 | 内容符合账号定位（个人 IP 号 70% 干货 + 20% 案例 + 10% 个人思考；获客内容号 90% 干货 + 10% 转化钩子） | high |
| 传播潜力 | 标题有冲突感；开头 100 字内点出核心问题；结尾有明确行动建议 | medium |
| 表达准确 | 无歧义表述、无过度绝对化用词（“一定”“必然”“所有人”） | medium |

## 3. 输出格式

审阅 Skill 输出必须是结构化 JSON：

```python
class ReviewOutput(BaseModel):
    round_no: int                      # 1 或 2
    review_type: str                   # structure / comprehensive
    passed: bool
    issues: list[ReviewIssue]
    summary: str                       # 一句话审阅结论
    suggested_action: str              # approve / request_rework / failed

class ReviewIssue(BaseModel):
    check_item: str                    # 检查项名称，对应本文第 2 节
    severity: str                      # high / medium / low
    location: str = ""                 # 问题位置，如“第 3 段”“标题”
    description: str                   # 具体问题描述
    suggestion: str = ""               # 修改建议
```

---

## 4. 通过规则

### 4.1 第一轮通过条件

- 无 `high` 级别结构问题；
- `medium` 级别问题不超过 2 个；
- 否则进入 rework，由内容单元组装 Skill 修改后重新审阅。

### 4.2 第二轮通过条件

- 无 `high` 级别表达/适配问题；
- `medium` 级别问题不超过 3 个；
- 否则由人工判断是否 `approve` 或标记为 `failed`。

### 4.3 轮次控制

- 最大审阅轮数为 2；
- 第二轮后若仍不通过，只能 `approve`（带问题发布）或 `failed`（放弃该内容单元）。

---

## 5. 人工最终审核点

即使审阅 Skill 输出 `passed`，人工仍需最终审核：

1. **标题**：是否有冲突感、是否准确概括核心观点、是否适合目标平台；
2. **摘要**：3-5 句话是否说清内容价值、是否吸引目标读者；
3. **金句**：加粗金句是否值得被截图传播、是否与全文立场一致；
4. **发布决策**：是否发布、发布到哪些平台、是否需要额外修改。

---

## 6. 与 CLI 的衔接

CLI 应提供：

```bash
# 运行审阅
python -m myj_ai_content_agents.cli review cu-xxx --round 1

# 查看审阅结果
python -m myj_ai_content_agents.cli show cu-xxx --review

# 人工批准
python -m myj_ai_content_agents.cli approve cu-xxx --reviewer 崔兴

# 请求返工
python -m myj_ai_content_agents.cli rework cu-xxx --feedback "第 3 段案例缺少来源"
```

## 7. 实现建议

### 7.1 规则版 Eval

先用规则完成基础检查：
- 术语密度（正则匹配 + 术语表）
- 金句数量（统计 `**...**` 或 `__...__` 数量）
- 字数/段落平衡
- 来源标注存在性（检查 `来源：`、`[Source]` 等模式）

### 7.2 LLM 审阅

复杂判断交给 LLM：
- 逻辑硬伤
- 案例可推敲性
- 读者适配
- 传播潜力

LLM 输出必须遵循第 3 节 `ReviewOutput` 格式。

- [ ] `high` 级别问题必须触发 `request_rework` 或 `failed`；
- [ ] 最大审阅轮数为 2，CLI 在第二轮后限制为 `approve`/`failed`；
- [ ] 检查清单覆盖本文第 2 节全部 11 项检查项；
