## 0. 背景

本篇复盘对应公众号连载《FDE 视角下的企业 AI 落地》模块一《认知重塑》的第一篇：

**《为什么企业 AI 项目总是在 POC 后死掉？》**

下面把从选题到成稿的完整过程拆开，找出对第二篇有用的经验。

---

## 一、选题与定位阶段

### 做了什么

- 先确定了系列框架：《FDE 视角下的企业 AI 落地》，5 个模块 15-17 篇
- 第一篇选定为模块一《认知重塑》的开篇：《为什么企业 AI 项目总是在 POC 后死掉？》
- 明确目标读者：30-200 人成长型公司的创始人 / CEO / 一号位
- 明确文章类型：3000-5000 字专业长文

### 做得好的地方

- **先定系列再定单篇**：第一篇不是孤立选题，而是整个课程的入口，降低了后续串联难度
- **选题有痛感**：POC 后死掉是目标读者真实经历过的事
- **避免"正确的废话"**：不是泛泛谈"AI 落地难"，而是聚焦一个具体问题

### 可以改进的

- 标题里"POC"对非技术读者仍是门槛，未来可以考虑主标题保留、用摘要/封面文案破圈
- 第一篇作为系列入口，承担了太多认知奠基工作，导致部分内容比较"满"

---

## 二、知识采矿阶段（Agent 集群）

### 做了什么

启动 4 个 Agent 并行走查 17 门课程：

- FDE / 业务落地视角
- 生产级排雷视角
- Harness 专项课视角
- Claude Code / Codex 工程视角

每个 Agent 输出 8-12 张输入卡片。

### 做得好的地方

- **并行走查效率极高**：4 个 Agent 同时跑，几分钟拿到大量证据
- **按主题而非按课程采矿**：不是填鸭式看课程，而是围绕问题找证据
- **输出格式统一**：每张卡片包含观点、来源、边界、反例、用处

### 可以改进的

- 第一轮采矿后卡片太多（45 张），筛选到 24 张核心卡片花了时间
- 部分卡片质量依赖 Agent 对主题的理解，需要人工判断取舍
- 下次可以更严格限定每个 Agent 的输出数量，避免信息过载

---

## 三、卡片整理阶段

### 做了什么

- 创建目录结构：`inputs/`、`themes/`、`drafts/`、`assets/`
- 用 Python 脚本批量生成 24 张输入卡片
- 手工整理 6 张主题卡片，把输入卡片聚合成文章骨架

### 做得好的地方

- **卡片笔记法确实帮助思考**：一张卡片一个观点，避免了大段复制的填鸭式学习
- **主题卡片是文章的骨架**：6 张主题卡片对应文章的 6 个部分
- **草稿由主题卡片拼装**：写作时不从零开始

### 可以改进的

- 主题卡片到草稿的转化过程中，有些卡片之间的联系可以更清晰
- 下次可以在主题卡片阶段就先确定每节的字数和案例，避免草稿阶段失衡

---

## 四、草稿阶段

### 做了什么

- 基于 6 张主题卡片写出第一版草稿
- 从约 3000 字扩充到约 4000 字
- 增加引用块、加粗金句、有序/无序列表

### 做得好的地方

- **先写内容再定表达**：草稿阶段不纠结修辞，先把信息密度堆够
- **案例具体**：847 次循环调用、`user_id` 遍历、理赔 Agent 重启等案例有画面感

### 做得不好的地方

- **草稿和成稿差别不大**：第一次"成稿"基本是复制+少量润色，没有完成"定表达"的任务
- **素材重复**："昂贵的玩具""围着 demo 提问"等表述重复出现
- **反面教材小节和六个差距重复**：这是结构层面的问题

---

## 五、成稿与多轮审阅阶段

### 做了什么

- 第一轮审阅：5 个 Agent 从表达、内容、读者适配、传播、专业准确性 5 个角度评分
- 根据反馈做第二轮重写
- 第二轮审阅：再次 5 个 Agent 审阅
- 根据反馈做第三轮小修
- 第三轮审阅：3 个 Agent 做终审
- 根据反馈做最终小修

### 做得好的地方

- **多轮审阅确实提升了质量**：从第一轮平均分 7.1 提升到第三轮 8.0+
- **不同维度的 Agent 发现不同问题**：表达修辞发现金句泛滥，读者适配发现术语密度，专业准确性发现引用问题
- **每次修改都有明确目标**：不是凭感觉改，而是按反馈清单改

### 可以改进的

- 审阅轮次偏多，成本较高。下次可以尝试：
  - 第一轮：3 个 Agent（表达、读者适配、专业准确性）
  - 第二轮：2 个 Agent（综合、传播潜力）
  - 如果第二轮评分都达到 8 分，可以考虑停止
- 应该在草稿阶段就请 Agent 审阅结构，而不是成稿后再大修结构

## 六、关键经验教训

### 1. 术语密度是第一杀手

读者适配从 6.5 到 8.5 的提升，核心就是降低了术语密度。非技术读者不会因为概念多而觉得你专业，只会因为看不懂而划走。

**应用到第二篇**：提前约定每个新概念必须用一句话人话解释，英文缩写尽量少用。

### 2. 金句要少而精

第一轮被批评"加粗金句泛滥且句式同构"。最后成稿只保留 3-4 句真正有力量的金句。

**应用到第二篇**：每篇文章最多 3 句加粗金句，且句式要错开。

### 3. 案例要自洽

"只读 Agent 发邮件"被指出逻辑硬伤。任何案例都要经得起专业读者推敲。

**应用到第二篇**：每个案例写完后，用"这件事在工程上是否可能发生"过一遍。

### 4. 引用要保守

Anthropic 实验被指出可能无出处。最后改成不具名引用或定性表述。

**应用到第二篇**：任何带数字、带公司名称的引用，都要能追溯到一手来源，否则用模糊表述。

### 5. 结尾要有可截图的交付物

"POC 生死清单"是全文最有收藏价值的部分。

**应用到第二篇**：每篇文章结尾尽量给一个可执行的清单/框架/问题集。

### 6. 成稿必须和草稿拉开差距

第一次"成稿"失败就是因为没做真正的润色。成稿阶段必须：统一语气、优化衔接、调整节奏、精简金句。

---

## 七、对第二篇的优化点

第二篇计划：《Agent = Model + Harness：企业 AI 落地的新公式》

基于第一篇经验，我建议：

- **提前控制字数**：目标 3500-4000 字，避免过度扩充
- **提前确定金句位置**：开头 1 句、中间 1 句、结尾 1 句
- **提前避免结构重复**：如果第一篇讲了六个差距，第二篇不要重复展开，而是聚焦"公式"和"人-Harness-模型三层协作"
- **提前做读者适配检查**：草稿完成后就启动读者适配审阅，不要等到成稿后
- **提前准备摘要文案**：和成稿一起写，而不是事后补
- **减少审阅轮次**：计划 2 轮审阅（草稿结构审阅 + 成稿综合审阅）

## 九、基于 Agent 架构讨论对工作流的重新设计

以上六个阶段是“人怎么做”的复盘。结合亦仁关于内容生产 Agent 架构的讨论，以下从“Agent 怎么做”的角度，重新设计更适合自动化、可规模化的内容生产工作流。

### 核心原则

1. **单 Agent 多 Skill，不是多 Agent 串联**：内容生产是一个强上下文依赖的流程，拆成多个 Agent 会导致上下文断裂、协调成本高。应该把内容生产环节放在一个 Agent 内，选题、访谈、组装、审阅做成 Skill。
2. **选题必须独立成 Agent**：选题需要信息广度、判断力和持续扫描，与内容生产的“深度收敛”是两种能力，必须独立。
3. **分发与生产分离**：多平台分发 Agent 与内容生产 Agent 目标不同、上下文不同、风险等级不同，不能合并。一个平台一个 Agent，一个账号一套 Agent 集合。
4. **“成稿”不是最终文章，而是标准化“内容单元”**：内容单元是中间产物，包含标题、摘要、正文、标签、适用场景，可被不同平台分发 Agent 复用。
5. **内容访谈不是草稿，而是结构化素材提取**：先通过访谈把隐性知识变成结构化素材库，再基于素材库组装内容单元。
6. **数据必须回流**：发布数据沉淀到飞书多维表格，反哺选题 Agent 和内容生产 Agent，形成闭环。

---

### 新六阶段工作流

#### 阶段一：选题 Agent —— 从信息源到选题池

**做什么**

- 独立运行，持续扫描信息源：
  - 行业 RSS、关键词搜索趋势
  - 竞品公众号/小红书/推特动态
  - 用户评论、私信、社群讨论
  - 课程知识库、历史内容数据
- 按预设标准输出选题列表，存入飞书知识库“选题池”
- 每个选题包含：标题方向、用户痛点、竞品覆盖情况、信息源、优先级

**与原流程的对应**

- 替代/扩展原来的“选题与定位阶段”
- 从“人工定选题”升级为“Agent 批量扫描 + 人工审核选题池”

**做得好的地方要保留**

- 先定系列再定单篇
- 选题要有痛感、避免正确的废话
- 目标读者和账号定位要明确

**可以改进的**

- 不要让人来天天想选题，让 Agent 批量产出，人只做判断
- 给选题 Agent 明确的判断标准：有冲突、有数据、有具体场景
- 建立数据反馈闭环：选题 Agent 定期读取发布数据，调整选题方向

---

#### 阶段二：内容访谈 Agent —— 从选题到结构化素材库

**做什么**

- 从选题池拉取高优先级选题
- 围绕选题，按固定框架进行“结构化素材提取”
- 输出不是文章，而是结构化的素材库，包含：
  - 背景信息：时间、场景、人物、条件
  - 关键动作：具体做了什么、顺序是什么
  - 踩坑记录：哪些尝试失败了、为什么
  - 数据结果：效率提升、成本变化、用户反馈
  - 核心认知：做完之后对这件事的理解变化
  - 来源标注：每条素材追溯到原始课程、文档或访谈

**与原流程的对应**

- 替代原来的“知识采矿阶段（Agent 集群）”和“卡片整理阶段”
- 输入卡片 ≈ 素材库中的条目；主题卡片 ≈ 素材库的结构化归类

**做得好的地方要保留**

- 按主题而非按课程采矿
- 输出格式统一（观点、来源、边界、反例、用处）
- 多个视角并行（FDE、生产级排雷、Harness、工程视角）

**可以改进的**

- 不要把 Agent 输出直接当草稿
- 严格控制每个 Agent/Skill 的输出数量，避免信息过载
- 素材库质量是内容单元质量的天花板，要重点打磨访谈框架

---

#### 阶段三：内容单元组装 Agent —— 从素材库到标准化内容单元

**做什么**

- 读取结构化素材库
- 按“内容单元”格式组装输出：
  - **标题**：一句话概括核心观点，有冲突感
  - **摘要**：3-5 句话说明内容价值
  - **正文**：按选题需要的长度展开，以“说透”为准，不设固定字数
  - **关键标签**：3-5 个关键词
  - **适用场景建议**：适合什么平台、什么人群、什么场景
- 内容单元是中间产物，不绑定任何平台

**与原流程的对应**

- 替代原来的“草稿阶段”和“成稿阶段”
- 原来的“草稿”变成“素材库组装过程”，原来的“成稿”变成“内容单元”

**做得好的地方要保留**

- 先堆信息密度再定表达
- 案例要具体、有画面感
- 结构清晰、逻辑自洽

**可以改进的**

- 不要固定字数，素材多就长、素材少就短
- 不要在组装阶段纠结平台适配，那是分发 Agent 的事
- 标题和摘要需要人工重点把关

---

#### 阶段四：审阅打磨阶段 —— 从内容单元到可发布内容

**做什么**

- 对内容单元进行结构审阅、表达审阅、读者适配审阅
- 控制在 2 轮：
  - 第一轮：结构审阅（Agent 检查结构重复、逻辑硬伤、素材重复）
  - 第二轮：成稿综合审阅（表达、读者适配、专业准确性、传播潜力）
- 人工最终审核标题、摘要和金句

**与原流程的对应**

- 扩展原来的“成稿与多轮审阅阶段”
- 从 3 轮 13 个 Agent 精简为 2 轮

**做得好的地方要保留**

- 多维度 Agent 发现不同问题
- 每次修改有明确目标
- 不同维度评分（表达、内容、读者适配、传播、专业准确性）

**可以改进的**

- 不要在成稿后再大修结构，结构审阅提前到内容单元阶段
- 减少审阅轮次，降低成本
- 把术语密度、金句数量、引用保守性写成明确的审阅标准

---

#### 阶段五：多平台分发 Agent 集群 —— 从内容单元到各平台发布

**做什么**

- 每个平台一个独立 Agent，从内容单元库拉取内容
- 按平台规则转换格式：公众号长文、小红书图文、即刻短内容等
- 处理标题、封面、排版、发布时间
- 调用平台 API 或 RPA 发布
- 记录发布结果和链接

**与原流程的对应**

- 原来的“配图、排版、发布”环节从内容生产中剥离，归入分发 Agent

**关键原则**

- 内容生产 Agent 不关心平台规则，分发 Agent 不关心内容创意
- 一个平台一个 Agent，一个账号一套 Agent 集合
- 分发 Agent 是“格式转换器 + 定时发布器”，不需要深度理解内容

**风险隔离**

- 每个平台 Agent 独立 IP、独立账号、独立 API Key
- 一个平台出问题不影响其他平台

---

#### 阶段六：数据回流与迭代 —— 从发布数据到系统优化

**做什么**

- 每个分发 Agent 定时回传数据：阅读量、点赞、评论、转发、收藏、转化
- 数据统一沉淀到飞书多维表格：
  - 内容数据总表：按内容维度聚合
  - 选题数据汇总表：按选题方向聚合
  - 平台健康度表：按平台维度聚合
- 定期由数据监控 Agent 或人工复盘
- 把结论以规则/提示词更新的方式，反哺选题 Agent 和内容生产 Agent

**反馈闭环**

- 选题 Agent 读取选题数据汇总表，调整选题方向
- 内容生产 Agent 读取高表现内容的共同特征，复用到提示词中
- 人工每月一次深度复盘，做方向性调整

### 账号定位：个人 IP 号 vs 获客内容号

根据亦仁的讨论，你的两个账号应该采用不同的 Agent 配置：

| 维度 | 企业 AI 落地业务账号 | 疗愈师 AI 课账号 |
|------|----------------------|------------------|
| 定位 | 个人 IP 号 | 获客内容号 |
| 核心目标 | 建立信任，降低高客单价决策门槛 | 批量获客，提升转化效率 |
| 内容逻辑 | 70% 干货 + 20% 案例 + 10% 个人思考 | 90% 干货 + 10% 转化钩子 |
| 选题方向 | 企业 AI 落地的真实问题、深度拆解 | 疗愈师痛点、AI 工具实操 |
| 内容风格 | 第一人称、真实案例、个人观点 | 信息密集、可复制、低门槛 |
| 分发平台 | 公众号、知乎、LinkedIn 为主 | 小红书、抖音、视频号为主 |
| 私域转化 | 高客单价，AI 培育 + 人工成交 | 低客单价，AI 可完成全链路 |

**关键提醒**：不要两个账号都“既要又要”。个人 IP 号不要批量生产干货，获客内容号不要花太多时间建立个人故事。

### 对第二篇的新优化点

第二篇计划：《Agent = Model + Harness：企业 AI 落地的新公式》

基于新的 Agent 架构思路，第二篇的优化点调整为：

- **用内容单元替代“成稿”**：产出标题、摘要、正文、标签、适用场景建议，不预设字数
- **先做结构化素材库再组装**：围绕“公式”主题，先按框架提取素材，再组装内容单元
- **结构审阅提前到内容单元阶段**：避免成稿后再大修结构
- **2 轮审阅即可**：结构审阅 + 成稿综合审阅
- **提前准备分发版本**：内容单元产出后，同步准备公众号/小红书/即刻的适配版本
- **提前埋入数据回传点**：发布后记录各平台数据，为后续选题优化做准备
- **控制金句和术语密度**：延续第一篇的经验，每篇最多 3 句加粗金句，术语用人话解释

### 新检查清单

#### 选题 Agent
- [ ] 是否持续扫描关键词搜索趋势、竞品动态、用户问题？
- [ ] 是否产出带优先级的选题池，而非单点选题？
- [ ] 选题是否满足“有冲突、有数据、有具体场景”？
- [ ] 是否建立了选题数据反馈闭环？

#### 内容访谈 Agent
- [ ] 是否按固定框架提取素材（背景、动作、踩坑、数据、认知）？
- [ ] 每条素材是否有来源标注？
- [ ] 是否限制了输出数量，避免信息过载？
- [ ] 输出是否是结构化素材库，而不是文章草稿？

#### 内容单元组装 Agent
- [ ] 是否产出标准化的内容单元（标题、摘要、正文、标签、适用场景）？
- [ ] 字数是否由“说透”决定，而不是固定模板？
- [ ] 标题和摘要是否经过人工把关？
- [ ] 是否避免在组装阶段处理平台适配？

#### 审阅打磨阶段
- [ ] 是否在内容单元阶段先做结构审阅？
- [ ] 是否控制在 2 轮审阅？
- [ ] 术语密度、金句数量、引用保守性是否写入审阅标准？
- [ ] 人工是否最终审核标题、摘要和金句？

#### 多平台分发 Agent 集群
- [ ] 是否每个平台一个独立 Agent？
- [ ] 是否每个账号一套独立的 Agent 集合？
- [ ] 分发 Agent 是否只负责格式转换和定时发布？
- [ ] 各平台账号、IP、API Key 是否隔离？

#### 数据回流与迭代
- [ ] 分发 Agent 是否定时回传阅读、点赞、评论、转发、转化数据？
- [ ] 数据是否统一沉淀到飞书多维表格？
- [ ] 选题 Agent 是否读取发布数据调整方向？
- [ ] 是否每月做一次人工深度复盘？
