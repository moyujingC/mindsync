## 1. 试点问题

本人每天需要在服务线索、售前资料准备、内容研究和人工待办之间切换。任务分散在飞书时，常见问题是：不知道先做什么、任务缺少必要信息、需要确认的动作被误当成可直接执行的动作。

本试点验证一条窄链路：从飞书“运营待办”表读取待处理事项，给出分诊建议和一份待确认动作清单。它不替代售前判断，也不自动接触客户、发送消息、更新案例或改变任务状态。

## 2. 用户与单一主路径

| 角色 | 要完成的事 | 试点提供的帮助 |
| --- | --- | --- |
| 本人（运营负责人） | 判断今天哪些事项值得处理、还缺什么 | 在飞书看到任务后得到优先级、缺失信息和下一步建议 |
| 本人（执行者） | 执行已确认的研究或资料准备 | 只拿到明确、可审阅的动作，不接收自动写入结果 |
| Codex | 开发、测试、修复和演进试点 | 维护代码、测试、配置模板和运行记录 |
| Hermes Agent | 长期承接受控的分诊判断 | 在已限制的 Skill 内解释任务、调用只读工具、生成建议 |
| 飞书 CLI | 读写日常协作台账 | 提供受控的外部系统适配能力，不保存第二份任务库 |

```text
飞书多维表格：待处理任务
  -> 飞书 CLI：只读取得最小字段
  -> Hermes：按运营分诊 Skill 归类、补齐问题、生成建议
  -> 本地建议文件 / 飞书待确认字段
  -> 人工明确确认
  -> （下一阶段才允许）飞书 CLI 写回同一条记录
```

Codex 位于这条运行链之外：它负责搭建、测试和修改上述链路，不是每次日常任务的运行时。

## 3. 本轮范围

### 3.1 要实现

1. 一个本地可运行的试点包，含配置模板、Hermes Skill、命令入口和离线测试样本。
2. 三类任务分诊：`research`（研究准备）、`service_follow_up`（人工跟进准备）、`internal_work`（内部资料/系统工作）。
3. 四种安全结果：`needs_clarification`、`proposal_only`、`handoff_required`、`blocked_sensitive_data`。
4. 默认只读：本地可产出建议 JSON；任何飞书写回均必须同时满足“配置显式开启 + 人工命令确认”。
5. 对 Hermes Gateway（网关）的可选 HTTP 适配；未配置 Gateway 时使用确定性规则完成离线演练，不伪称已接入 Hermes。Gateway 必须使用独立的无工具/只读 profile（配置档），不能复用拥有终端、浏览器或文件写入权限的日常 profile。
6. 对飞书 CLI 的命令模板适配；本轮不携带 App ID、App Secret、用户 Token 或表格 ID。

### 3.2 不做

- 不接入真实客户资料、联系人、完整聊天记录或企业内部文件。
- 不自动发送飞书消息、创建任务、更新任务状态、修改报价或安排会议。
- 不把 Hermes 的记忆当作客户资料库；本轮不启用跨任务长期记忆。
- 不把飞书作为本地证据、运行日志和正式项目文档的替代品。
- 不承诺 7×24 无人值守、生产稳定性或真实业务效果。

## 4. 任务与数据合同

每条输入只允许以下最小字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 飞书记录 ID 或本地演练 ID |
| `title` | 是 | 不含联系人或敏感资料的任务概括 |
| `category` | 否 | `research` / `service_follow_up` / `internal_work` |
| `status` | 否 | 默认 `pending` |
| `priority_hint` | 否 | `high` / `normal` / `low` |
| `context` | 否 | 脱敏后的背景摘要，最长 500 字 |
| `requires_external_write` | 否 | 默认 `false`；为真时一律转人工确认 |

以下内容一旦在输入中出现，试点停止处理正文并返回 `blocked_sensitive_data`：密码、API Key、Access Token、身份证号、银行卡号，或明显的客户联系人资料。规则是宁可要求人工脱敏，也不让内容进入模型或日志。

输出包含：`classification`、`priority`、`missing_fields`、`proposed_action`、`approval_required`、`reason`。输出不应复制输入中的敏感正文。

## 5. 分层与权限

| 层 | 责任 | 默认权限 |
| --- | --- | --- |
| Codex | 开发、代码审查、测试、配置升级 | 本地项目文件；不持有飞书生产凭证 |
| Hermes | 受控分诊、解释和建议 | 只读输入；不能自行执行外部写操作 |
| 飞书 CLI | 调用飞书 API | 试点默认只读；写操作必须二次显式开启 |
| 人工 | 确认、发送、更新状态、处理敏感内容 | 唯一可以批准外部写入的角色 |

所有真实凭证只可保存在机器私有环境文件或凭证管理器。仓库只保留 `config/pilot.example.json` 和环境变量名称。

Hermes 官方 API Server（API 服务器）会将该 profile 的完整工具集暴露给调用方。因此“在提示词里说不要用工具”不构成权限控制；接入前必须在 Hermes 自身配置中关闭终端、浏览器、文件写入等工具，且 Gateway 仅监听 `127.0.0.1`、启用 Bearer Key（访问密钥）。

## 6. 选型判断

| 组件 | 本试点职责 | 选择理由 | 替换边界 |
| --- | --- | --- | --- |
| Codex | 搭建和迭代 | 适合读取项目上下文、实现脚本与执行测试 | 不进入日常消息处理主链 |
| Hermes Agent | 长期 Agent 运行时 | 有 Skill、记忆、Gateway 和定时能力；本轮只启用 Skill + 受控调用 | Gateway 不可用时可离线演练，但不能称为上线 |
| `feishu-cli` | 飞书适配器 | 支持多维表格、消息、文档等命令，适合把飞书操作收为可审计命令 | 可替换为官方 `lark-oapi` SDK；业务合同不变 |
| 本地 JSON | 演练输入与输出 | 无凭证即可重复验证 | 不是第二个生产任务库；真实运行由飞书表承载 |

## 7. 验收标准

1. 执行 `python3 agent-pilot/bin/pilot.py check` 能准确报告 Codex、Hermes 和飞书 CLI 的安装/配置状态，缺失项不被伪装为可用。
2. 对离线样本执行 `route` 能生成建议；所有带 `requires_external_write` 的任务均标记 `approval_required: true`。
3. 含敏感字段或疑似凭证的样本输出 `blocked_sensitive_data`，且输出中不回显该敏感值。
4. `write` 在默认配置、没有 `--confirm` 或输入未获批准时均失败；测试不得发生真实外部写入。
5. 若配置 Hermes Gateway，HTTP 调用异常会降级为确定性规则并记录 `hermes_status`，不静默把规则结果标成模型结果。
6. 所有自动化测试在无飞书凭证、无 Hermes 安装的本机仍可执行。

## 8. 进入真实飞书演练的门槛

在满足上述验收前，不连接真实飞书表。满足后，才由用户创建或指定一个仅含模拟任务的测试表，并提供以下非仓库配置：飞书 profile（配置档）、表 App Token、Table ID、仅测试用途的机器人权限。

第一轮真实演练仅允许：读取不超过 5 条模拟任务，并把建议输出到本地文件供人工核对。写回飞书需在第二轮另行确认。

## 9. Handoff

- Engineer：实现试点包、离线测试和受控适配器。
- Test / QA：依据 QA 基线验证只读、敏感内容阻断和写入确认门。
- CEO：决定何时配置测试飞书表与 Hermes Gateway；确认后才进入真实集成演练。
