## 1. 能力定位

`AI 营销获客` 是 `知行AI服务` 的一个通用能力包。

它服务的不是“自动涨粉”或“自动成交”，而是这类业务：

- 线上需要持续获得注意力、咨询或线索。
- 线下或私域里有真实服务、课程、产品或体验可以交付。
- 成交依赖信任、解释、筛选和跟进。
- 团队现在主要靠人工经验做选题、发布、私信承接和客户记录。

一句话定义：

```text
用 AI 把市场信号、内容生产、私域承接和服务验证连成一条可复盘链路。
```

## 2. 适合客户

优先适合：

- 心理咨询师、疗愈师、教练、咨询顾问。
- 有课程、体验课、线下服务或高客单服务的个人专业服务者。
- 依赖小红书、公众号、视频号、抖音等平台获取咨询的小团队。
- 有内容更新压力，但缺少选题依据、承接话术和反馈记录的人。

暂不优先适合：

- 只想买流量、不愿整理服务和交付边界的客户。
- 希望承诺涨粉、成交、ROI（投入产出比）的客户。
- 没有可交付产品或服务，只想先做账号热闹的客户。
- 需要长期代运营、大规模账号矩阵或按效果付费增长的客户。

## 3. 典型问题

- 不知道该写什么内容，只能凭感觉选题。
- 内容有更新，但没有导向样本沟通、私信和服务诊断。
- 评论区、私信和客户反馈没有被记录，下一篇内容仍从零开始。
- 线上内容和线下服务割裂，客户看完内容不知道下一步做什么。
- 服务方不知道哪些需求是真痛点，哪些只是用户好奇。
- 私信承接靠临场发挥，容易过度解释或错过合适客户。

## 4. 标准交付动作

当前可以拆成五段：

| 阶段 | 服务动作 | 交付物候选 |
| --- | --- | --- |
| 市场信号整理 | 收集公开内容、评论、私信、历史客户问题 | 需求信号清单、目标读者分类 |
| 选题与服务指向 | 把需求转成内容选题，并标记对应服务入口 | 选题池、CTA（行动召唤）设计 |
| 内容生产工作流 | 梳理草稿、编辑、配图、发布准备流程 | 内容生产 SOP、提示词、模板 |
| 私域承接 | 设计评论、私信、样本沟通和诊断入口 | 私信话术、筛选问题、记录表 |
| 反馈回流 | 把互动和沟通结果回写到服务定义 | 反馈记录、下一轮选题和服务调整建议 |

## 5. 当前最小服务形态

第一阶段不做完整营销系统搭建，先做小诊断：

```text
30-60 分钟访谈
  -> 看 3-5 篇内容 / 3-5 条私信或评论 / 1 个服务入口
  -> 找出当前断点
  -> 输出一页“内容到咨询”的小闭环建议
```

可交付结果：

- 当前获客链路图。
- 内容选题和服务入口对应表。
- 3-5 个下一步选题。
- 1 套私信承接问题。
- 1 张反馈记录表字段建议。
- 是否适合进入后续工作流搭建的判断。

## 6. 与 Content Matrix 的边界

`Content Matrix` / `内容矩阵` 负责内容系统本体：

- 市场信号采集。
- 对标账号追踪。
- 选题、草稿、成稿、配图、排版和发布准备。
- 多账号内容治理。

`知行AI服务` 负责把这套能力变成可交付服务：

- 售前诊断。
- 客户输入材料判断。
- 服务范围和报价。
- 私域承接流程。
- 交付物和验收。
- 客户复盘与服务迭代。

因此，内容系统的产品定义留在 `projects/content-matrix/`；这里维护的是可交付服务包。

## 7. 行业复用方向

当前优先用于 [心理与疗愈行业](../../industries/psychology-healing/README.md)。

后续可观察：

- 本地生活服务。
- 培训咨询。
- 实体门店。
- 高客单体验课或小课。
- 小团队服务业。

每进入一个行业，先补行业客户、转化路径、合规边界和服务样本，不直接复制通用话术。
