这里承载 `知行AI服务` 的业务方法论、产品设计、获客销售、报价合同和交付 SOP。

它不是同行资料堆放区，也不是长期通用知识库。

## 1. 目录定位

`system/` 用来沉淀“我自己的 AI 服务业务系统”。

来源可以包括：

- 同行一线经验帖子
- 项目内参考资料
- 自己的样本沟通
- 报价和成交记录
- 交付复盘
- 后续客户反馈

但进入本目录后，内容必须转成 `知行AI服务` 自己可执行的方法、规则、SOP 或模板。

## 2. 与其它目录的边界

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `references/` | 同行帖子、原文留存、外部经验提炼 | 自己最终采用的 SOP |
| `system/` | 自己的产品体系、销售流程、报价合同、业务规则 | 未消化的原文材料 |
| `sops/` | 已经进入具体服务交付的操作 SOP | 尚在讨论中的业务系统草稿 |
| `templates/` | 对客户或交付过程可复用的表单、提纲、模板 | 方法论解释文 |
| `records/` | 样本沟通、报价、交付和复盘记录 | 抽象原则 |
| `projects/research-center/kb/` | 跨项目、可复用、经验证的知识结论 | 单项目临时策略 |

## 3. 当前要沉淀的模块

后续先围绕四类文档迭代：

1. `AI服务产品体系-v0.1.md`
   - 定义当前卖什么、不卖什么。
   - 区分入口产品、小单服务、企业试点和后续陪跑。
   - 说明企业内训、沙龙分享、工作坊和 FDE 式服务的关系。

2. `获客与售前SOP-v0.1.md`
   - 定义目标客户、渠道、邀约方式、售前访谈流程。
   - 沉淀需求判断、客户阶段、报价前置条件和跟单动作。

3. `报价与服务边界-v0.1.md`
   - 定义免费诊断、小单、试点、陪跑的报价逻辑。
   - 写清降价原则、缩小范围原则、交付边界和不承诺事项。

4. `合同条款清单-v0.1.md`
   - 整理付款、取消、改期、知识产权、数据安全、客户输入、验收和责任边界。
   - 先作为条款清单，不直接替代正式法律合同。

## 4. 迭代规则

- 先把同行材料转成“候选方法”，不要直接写成已验证事实。
- 只有自己实际用过、报价过、交付过或被客户反馈过的内容，才升级为稳定 SOP。
- 每次新增帖子，先进入 `references/`；只有改变自己的业务设计时，才同步更新 `system/`。
- 如果某个判断被多个来源和真实样本反复支持，再考虑抽到 `projects/research-center/kb/`。

## 5. 当前状态

当前仍处在方法论搭建期。

本目录先作为讨论和迭代入口；正式服务页、客户话术和交付模板仍分别放在 `outreach/`、`templates/` 和 `sops/`。
