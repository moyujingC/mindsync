## 1. 单一真相源

面向客户展示的案例目录、案例正文和案例卡模板统一维护在飞书；飞书是对外案例库的唯一权威源。

本地仓库不再维护这些内容的镜像、并行目录或可对外版本，以免两处修改后发生漂移。

## 2. 本地保留什么

本地只保留不直接面向客户的工作材料：

- 原始来源、OCR 原文和外部案例参考提炼：`references/`
- 客户输入、交付过程、复盘和沟通记录：`records/`、`delivery/`
- 服务边界、SOP、行业风险和内部判断：`system/`、`sops/`、`industries/`

这些材料用于支撑飞书案例的事实、脱敏和授权判断；它们不是对外案例正文。

## 3. 从内部证据到飞书案例

```text
内部来源 / 客户交付 / 自用验证
  -> 本地保留证据和复盘
  -> 确认脱敏与授权范围
  -> 在飞书创建或更新案例
  -> 在本地记录飞书链接和关联证据路径
```

每次更新飞书案例时，至少在对应本地交付或复盘记录中补充：

- 飞书案例链接。
- 展示类型：真实交付、自用验证、模拟演示或外部参考。
- 可公开范围与脱敏处理。
- 支撑该案例的本地证据路径。

## 4. 对外表达边界

- 真实交付：需有客户授权或可公开的脱敏记录、实际输入、交付物和反馈。
- 自用验证：明确是知行AI服务自身工作流验证，不能写成客户成果。
- 模拟演示：明确素材来源、场景假设和未验证项，不能写成真实项目。
- 外部参考：保留原始来源，不能通过改写行业、客户名或措辞变成自有案例。

没有前后对比、使用反馈或客户确认时，只能写“尚未验证”，不能推测节省时间、增长、成交或 ROI（投入产出比）。

## 5. 发布前检查

- [ ] 飞书案例类型与正文一致。
- [ ] 客户名称、资料、截图和数据已获授权或完成脱敏。
- [ ] 每个结果都能定位到本地证据或客户确认。
- [ ] 已写清本次做了什么、没有做什么。
- [ ] 外部案例保留来源，不暗示为自有交付。
- [ ] 心理、疗愈、医疗等敏感场景不含诊断、治疗、风险评级或效果承诺。
