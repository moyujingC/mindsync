## 1. 售前目标

售前不是收集“客户想要什么 AI”，而是把客户的业务语言翻译成：

- 一条流程或一批资料。
- 当前人工怎么做。
- 哪些节点可能适合 AI。
- 哪些节点暂不适合。
- 成功怎么判断。
- 失败谁兜底。
- 下一步是否值得报价。

第一轮沟通不追求成交，只追求判断：

```text
这个客户、这个场景、这个资料基础，是否值得进入一次付费诊断 / 小实验 / 工作坊。
```

报价前先判断客户适合哪种上车方式：

| 客户状态 | 售前判断问题 | 推荐下一步 |
| --- | --- | --- |
| 认知未对齐 | 老板、中层、使用人和 IT 是否在说同一件事？ | 小分享、认知对齐或小范围培训 |
| 方向拿不准 | 客户能否说出具体流程、岗位、资料和业务影响？ | 场景诊断或工作坊 |
| 场景明确 | 是否有输入、输出、样本、验收标准和人工兜底？ | 样板 demo、POC 或 7-14 天小实验 |
| 已有样板 | 是否有真实反馈、预算、负责人和迭代节奏？ | 试点定义、陪跑或合作交付 |

不能因为客户说“想做 AI”，就默认进入智能体、平台或自动化报价。

## 2. 获客入口

### 2.1 优先入口

当前优先从低压力关系和小范围演示开始：

- 熟人、前同事、弱关系。
- 小团队负责人。
- 有企业客户资源的人。
- 做企业服务、培训、咨询、代运营、SaaS、实施的人。
- 内容、销售、客服、交付、资料管理压力明显的人。

暂不优先：

- 投放获客。
- 大规模公开课。
- 城市组局官。
- 年框咨询销售。
- 培训平台招商。
- 团队化交付宣传。

### 2.2 低压力邀约模板

```text
我最近在验证一个小型 AI 服务，不做大而全的转型。

更像是拿一条具体流程或一批资料，看哪里适合 AI 介入，哪里暂时不适合。

如果你们最近也在想 AI 怎么先用起来，我可以先帮你看 30 分钟。
不用准备方案，拿一个真实流程聊就行。
```

面向资源方：

```text
我最近在整理企业 AI 服务的小诊断方法。

不急着接大项目，主要想找一些真实流程样本：
比如销售跟进、客服回复、资料整理、内容生产、项目交付这些。

如果你手上有企业客户正在问 AI，但还没想清楚怎么落地，
我们可以先聊一次资源方访谈，看看有没有适合做脱敏样本的小场景。
```

### 2.3 小分享承接动作

分享只讲一个具体场景，不讲泛 AI 转型。

可选主题：

- 企业做第一个 AI 小实验前要先问哪几个问题。
- 销售跟进流程怎么用 AI 辅助。
- 小团队项目资料怎么整理成可复用知识库。
- To Boss 和 To Business：企业 AI 服务到底服务谁。
- 一个 AI 服务产品矩阵怎么设计：引流品、利润品、明星品。
- 我怎么把一套自用 AI 内容工作流给团队跑起来。

会后只做三件事：

- 记录谁主动提到具体团队、流程、资料或预算。
- 24 小时内约 20-30 分钟诊断。
- 不发长服务介绍，直接问对方想跑通哪条流程。

## 3. 访谈前准备

### 3.1 访谈边界

开场说明：

```text
今天先不做完整方案。
我主要想了解你们现在一条具体流程怎么跑，
再判断它适不适合用 AI 做第一步。
```

如果要录音、转写或用 AI 生成纪要，先取得同意：

```text
为了避免遗漏，我希望对这次沟通做录音或整理 AI 会议纪要。
内容只用于需求确认、后续报价和本次服务记录，不会对外公开。
如果你不方便录音，我就只做手工笔记。
```

### 3.2 售前资产检查

每次外部沟通前，至少准备一种可信资产。无案例阶段不能伪造案例，但要用可解释的替代资产建立信任。

| 资产 | 用途 | 边界 |
| --- | --- | --- |
| 服务方介绍 | 说明我能解决哪类问题 | 不包装成成熟机构能力 |
| 小 demo | 让客户看到一个具体流程如何变化 | 说明是公开、模拟还是脱敏样本 |
| 方案 / 案例 PPT | 帮客户理解服务路径和交付物 | 不把外部案例写成自己的交付案例 |
| 试讲 / 小分享素材 | 降低第一次沟通门槛 | 不承诺课后直接产生业务结果 |
| 自用工作流 | 证明自己在真实使用 AI | 不等同于客户组织可直接照搬 |
| 模拟样板 | 展示可能的最终形态 | 必须标注为模拟，不作为项目结果 |
| 诊断提纲 | 让客户知道下一步会问什么 | 不免费输出完整方案 |

demo 准备必须遵守一个原则：

```text
原始输入
  -> 中间处理过程
  -> 客户想要的业务结果
  -> 人工审核点和不可承诺事项
```

只展示“AI 生成了一段内容”不够。售前 demo 要让客户看见这件事如何影响获客、成交、人效、交付或经验沉淀，同时标注它只是 demo、POC、试点还是生产级系统。

### 3.3 不直接问的问题

第一轮不要直接问：

- 你们有什么 AI 需求？
- 你们预算多少？
- 你们要不要做 Agent？
- 你们要不要做自动化？
- 你们要不要做知识库？

更好的入口：

- 哪个岗位最难招人或最依赖老员工？
- 哪个流程最耗时间、最容易返工或最容易出错？
- 哪批资料最难找、最难复用或最难交给新人？
- 哪个环节现在经常让客户、销售、交付或老板等待？
- 如果这件事快一天或少错一次，对收入、交付、客户体验或风险有没有影响？

## 4. 四张访谈检查表

真实访谈按四张表走。每次不一定全部问完，但报价前必须补齐。

### 4.1 客户认知检查表

目的：判断客户处在什么 AI 认知阶段，避免误导和错配。

| 检查项 | 访谈问题 | 判断 |
| --- | --- | --- |
| AI 没用 | 你们之前有没有试过 AI？哪里不好用？ | 用真实小 demo 建立信任，不讲大方案 |
| AI 万能 | 你希望 AI 最后替你完成到什么程度？ | 先讲资料、流程、人工校对、系统适配和使用人配合边界 |
| AI 可试 | 如果先用一个小场景试 7 天，你愿意提供什么资料和反馈？ | 可进入诊断、资料盘点或小实验 |
| To Boss | 这件事主要是老板个人体验，还是团队流程要变？ | 老板个人需求只作为破冰，不直接按组织交付报价 |
| To Business | 是否有员工、资料、SOP、流程、验收和复盘参与？ | 优先进入企业服务判断 |
| 管理者风险视角 | 如果 AI 错了，错误会不会被放大？谁能发现？谁来兜底？ | 先区分提效节点和错误放大节点，再谈自动化 |

老板或业务负责人可追问：

- 这件事半年后你希望变成什么样？
- 这条流程离开某个关键人能不能正常跑？
- 当前最卡的是执行、人员、流程、资金、渠道，还是资源整合？
- 你希望 AI 帮你省人，还是帮你放大业务？
- 你现在最想沉淀的是流程、内容、客户资产，还是员工经验？

### 4.2 业务流程检查表

目的：从业务路径里找可诊断节点，而不是从工具名出发。

| 检查项 | 访谈问题 |
| --- | --- |
| 流程对象 | 这条流程叫什么？从哪里开始，到哪里结束？ |
| 负责人 | 现在由谁负责？谁最懂细节？ |
| 频次 | 每天或每周重复几次？是否有旺季 / 淡季？ |
| 输入 | 每次开始前需要什么信息、文件、表格、客户消息或系统数据？ |
| 输出 | 做完以后产出什么？谁会使用这个产出？ |
| 最慢节点 | 哪一步最慢？慢在哪里？ |
| 返工节点 | 哪一步最容易漏、错、返工或被客户打回？ |
| 业务影响 | 它影响获客、成交、交付、客户体验、风险，还是新人上手？ |
| 当前判断标准 | 做得好和做得差，现在谁来判断？按什么判断？ |
| 人工兜底 | 如果 AI 做错，谁能发现？多久能发现？谁能改？ |
| 错误放大 | 错误会停留在内部返工，还是会传到客户、产线、财务、合同或外部平台？ |

场景筛选规则：

```text
高频 + 结构化 + 可评判 + 有人工兜底
  -> 优先进入小实验

高频 + 非结构化
  -> 先做资料整理 / SOP / 话术库

低频 + 高价值
  -> 可做诊断，不优先自动化

非结构化 + 不可评判
  -> 不承接自动化
```

### 4.3 资料 / 数据基础检查表

目的：判断是否能直接进入诊断、知识库或自动化，还是要先做入场前整理。

| 检查项 | 访谈问题 |
| --- | --- |
| 资料位置 | 资料在微信、飞书、企微、网盘、CRM、本地文件、纸质文件还是其他系统？ |
| 资料形态 | 是文档、表格、PDF、扫描件、图片、聊天记录、视频、语音还是旧系统导出？ |
| 电子化程度 | 是否已经电子化？是否需要 OCR、转写、格式清洗或人工校对？ |
| 结构化程度 | 是否有字段、分类、标签、命名规则和版本管理？ |
| 术语和规则 | 是否有行业术语、内部黑话、公式、合规规则或不能乱答的内容？ |
| 可提供样本 | 是否能提供真实或脱敏样本？样本规模多大？ |
| 敏感边界 | 是否涉及客户隐私、商业机密、账号、cookie、API Key 或密钥？ |
| 持续维护 | 谁负责后续补资料、改标签、反馈错误答案？ |
| 文档规模 | 当前是几十份、几百份、上千份，还是万级以上资料？ |
| 文档权责 | 每类资料来自哪个部门？谁确认版本、适用范围和是否可作为答案依据？ |
| 文档状态 | 资料是正式制度、业务手册、培训课件、会议纪要、历史归档，还是临时草稿？ |

知识库 / 内部 AI 助手类需求的前置规则：

```text
资料未盘点、未电子化、未清洗、未校对时，
只报价资料盘点 / 清洗 / 分类 / 入库前诊断，
不直接报价知识库问答效果。
```

#### 知识库 PoC 准入卡

当客户希望做 AI 问答、RAG 或内部助手时，报价前逐项确认。以下项目缺失时，只进入资料治理诊断，不进入 PoC 报价。

| 必填项 | 需要确认 | 缺失时的处理 |
| --- | --- | --- |
| 场景 | 谁在什么时刻要查什么资料或得到什么答案 | 先做场景诊断 |
| 使用与验收 | 至少一名使用人和一名验收人 | 不进入样板交付 |
| 代表资料 | 范围、数量、资料状态和可入库资格 | 先做资料盘点 / 清洗 |
| 资料责任 | 谁确认版本、适用范围和正式依据 | 暂不将资料用于正式回答 |
| 质量口径 | 5-20 个测试问题；哪些问题须引用、拒答或转人工 | 先定义测试与人工兜底 |
| 权限与数据 | 是否涉及多人、跨部门、敏感资料、源系统同步或自动写入 | 升级为生产设计评估或引入合作方 |

PoC 完成后只可作四种判断：仅做资料治理、进入样板 PoC、进入合作方生产设计、暂不承接。技术选型只能在完成这张准入卡后讨论。

自动化类需求的前置规则：

```text
没有完整手动流程、测试环境、成功标准、失败检测和人工兜底人，
不进入自动化试点报价。
```

### 4.4 决策链检查表

目的：确认谁买单、谁使用、谁给资料、谁验收，避免只和单点联系人聊天。

| 检查项 | 访谈问题 |
| --- | --- |
| 发起人 | 这次是谁先提出要看 AI？ |
| 买单人 | 谁决定是否付费？ |
| 使用人 | 最后谁每天用？ |
| 资料方 | 谁能提供流程资料、历史样本和账号权限？ |
| 验收人 | 谁判断这件事有没有价值？ |
| 总牵头人 | 如果跨部门推进，谁负责拍板、协调资料和推动反馈？ |
| 推进人 | 如果做 7 天小实验，谁每天反馈？ |
| 时间窗口 | 你们希望什么时候看到第一版结果？ |
| 预算来源 | 预算来自老板个人、部门、培训、数字化、IT、市场，还是临时试错？ |
| 预算信号 | 你们更想先做诊断、工作坊，还是小实验？ |
| 内部阻力 | 哪些人可能不愿意用、没时间用或担心被替代？ |

报价前必须至少确认：

- 买单人知道这件事。
- 使用人认可当前流程描述。
- 资料方知道需要提供什么。
- 验收人能说清“什么算有价值”。

### 4.5 资源方访谈检查表

资源方包括培训机构、企业服务商、行业顾问、流量博主、软件实施方、销售渠道和已有企业客户关系的人。

第一轮资源方访谈不谈分成比例，先拆责任。

| 检查项 | 访谈问题 | 判断 |
| --- | --- | --- |
| 客户来源 | 你手上的客户是长期服务客户、潜在客户，还是泛泛认识？ | 判断是否有真实信任基础 |
| 客户状态 | 客户现在是想了解 AI、找方向、已有场景，还是已有预算？ | 判断上车方式 |
| 资源方角色 | 你希望负责获客、背书、售前、策略、执行、回款，还是售后？ | 避免默认对方只介绍客户 |
| 策略责任 | 谁负责访谈、诊断、方案和边界确认？ | 策略不清时不进入完整报价 |
| 执行责任 | 谁负责搭建、培训、资料整理、测试和交付？ | 执行方未确认时只报诊断 |
| 回款路径 | 客户向谁付款？谁开票？谁承担坏账和延期回款？ | 影响报价和现金流 |
| 售后责任 | 客户后续问题找谁？响应边界是什么？ | 防止转介绍变成无限售后 |
| 客户归属 | 复购、转介绍和二次需求归谁跟进？ | 正式合作前写清 |

资源方合作的售前判断：

```text
获客、售前、策略、执行、回款、售后六件事没有拆清，
不承诺联合项目，不报价完整交付。
```

## 5. 场景处理规则

### 5.1 案例启发

客户答不上“有什么重复工作”时，用案例启发，不用案例替代需求。

使用原则：

- 可以用公开案例、同行样本和自建 demo 做场景启发。
- 必须说明哪些是公开材料、哪些是模拟案例、哪些是自己真实交付。
- 不能把别人的案例包装成自己的客户案例。
- 案例只用于激发需求，不能替代真实访谈。

### 5.2 自动化需求

客户说“想做自动化”“想做 Agent”“想批量处理”时，先影子跟跑手动流程。

额外追问：

- 这条流程如果完全手动跑一遍，需要多少步骤？
- 每一步涉及哪些平台、系统、账号、表格、文档或群聊？
- 哪些动作有平台审核、验证码、登录过期、权限限制或风控风险？
- 当前如何判断“发布成功、录入成功、通知成功、处理成功”？
- 如果自动化失败，客户内部谁能发现，多久能发现？
- 是否接受先用测试账号 / 测试数据跑小样，而不是直接上生产环境？
- 是否需要自动写入、自动发送、自动发布或自动操作客户账号？
- 是否有日志、截图、表格、通知或系统记录能证明动作成功？
- 谁有权限暂停、回滚、重试或改回人工处理？

判断规则：

```text
动作可执行，但结果不可验证
  -> 不进入自动化试点

动作可执行，结果可独立验证
  -> 可以做小范围试运行
```

自动化售前要明确层级：

| 层级 | 售前判断 |
| --- | --- |
| demo | 只用于展示可能性，不能承诺稳定使用 |
| POC | 只在约定样本和测试环境内验证 |
| 试点 | 需要真实使用人、反馈人、异常记录和人工兜底 |
| 生产级 | 需要权限、数据、日志、监控、回滚、维护、费用和责任机制 |

客户如果直接要求生产级 Agent 或无人值守自动化，先回到生产级条件检查，不直接报价。

### 5.3 知识库需求

客户说“做知识库”“做内部 AI 助手”“把资料丢进去问答”时，先做入库前判断。

不能直接承诺：

- 资料丢进去就能问。
- 能替代老师傅。
- 能自动保持长期准确。
- 能处理未清洗、未校对、未授权的资料。

可进入的第一步：

- 资料盘点。
- 分类结构。
- 可入库 / 暂不入库清单。
- 命名和标签规则。
- 需要人工校对的问题清单。
- AI 使用入口建议。

如果客户资料进入千级或万级规模，额外确认：

- 是否需要先去重。
- 是否存在新旧版本混用。
- 是否需要把相似主题资料聚类对比。
- 是否能给每份文档标记部门、场景、责任人和适用范围。
- 哪些资料可以作为正式回答依据，哪些只能作为背景或归档。
- 回答错误后由谁修正文档、标签、权限或检索规则。

### 5.4 内容获客 / AI Native 工作流需求

客户说“想做内容获客”“想用 AI 批量写内容”“想搭内容系统”时，不直接承诺代运营、爆款或全自动发布，先判断它是素材混乱、知识库缺失、Skill 缺失，还是分发和反馈链路缺失。

候选问题：

- 你们每天会产生哪些录音、客户对话、案例、课程材料、碎片想法或销售反馈？
- 这些输入现在去了哪里？会进入文档、表格、知识库，还是散在聊天记录里？
- 每次写内容时，是否都要重新找素材、重新解释产品、重新描述客户问题？
- 是否已有产品库、案例库、客户需求库、方法论库和内容生产库？
- 你希望 AI 帮你整理、筛选、出草稿给人审核，还是希望直接自动发布？
- 当前瓶颈是选题、脚本、素材、剪辑、分发、私域承接，还是数据复盘？
- 哪些内容必须人工审核？谁负责最终发布判断？

处理规则：

```text
有素材和客户对话，但复用差
  -> 可进入内容获客知识库 / Skill 工作坊候选

只有增长目标，没有素材、产品和审核机制
  -> 不承诺内容获客结果

要求全自动发布、爆款、GMV 或 ROI
  -> 不报价结果型交付，只能报价诊断或系统搭建边界
```

### 5.5 心理 / 疗愈行业需求

客户是心理咨询师、疗愈师、教练或转行者时，先判断客户类型，不直接推荐 AI 助理。

| 客户类型 | 先问什么 | 可进入 |
| --- | --- | --- |
| 成熟从业者 | 当前最耗精力的是内容、初访、预约、资料、跟进，还是记录？ | 内容到咨询诊断、初访流程诊断、脱敏资料整理 |
| 转行 / 启航者 | 当前卡在学习、模拟练习、内容启动、专业呈现，还是初访流程？ | 学习路径、概念卡、内容启动、初访导航清单 |

初访助理类需求必须追问：

- 当前初访前会问哪些固定问题？
- 哪些问题可以标准化为选择题，哪些必须人工判断？
- 是否已有收费、预约、保密、知情同意和危机处理话术？
- 是否会接触真实来访者信息、量表、咨询记录或高风险表达？
- 如果出现自伤、自杀、伤害他人等高危表达，当前人工流程是什么？
- 摘要中哪些字段只能提取用户原话，不能由 AI 推断？

边界判断：

```text
只涉及预约前 FAQ、流程说明、字段收集和摘要
  -> 可做诊断或模拟 demo

涉及诊断、治疗建议、风险等级判断、危机干预或真实未脱敏个案
  -> 不承接，或仅做人工流程和合规边界梳理
```

转行者需求必须避免“速成”和“伪装专家”。如果客户希望 AI 帮他包装资历、编造案例、生成专业背书或替代学习训练，直接拒绝。

## 6. 报价触发条件

满足以下条件，再报价：

- 已经有具体流程或资料对象。
- 客户当前痛点能说清。
- 高频 / 结构化 / 可评判 / 人工兜底已有判断。
- 买单人、使用人、资料方、验收人基本清楚。
- 客户知道下一步需要投入时间、资料或反馈。
- 本次交付物能写清。
- 本次不包含事项能写清。
- 是否需要合作方已判断。
- 是否涉及敏感数据、账号、系统权限已判断。

不满足时：

- 继续补访谈。
- 只报价小诊断 / 资料盘点。
- 或明确结束，不进入方案和价格讨论。

## 7. 跟进规则

跟单不是催促付款，而是推动下一步判断。

只跟进这些事项：

- 是否提供资料。
- 是否确认流程。
- 是否确认使用人。
- 是否确认决策人。
- 是否确认验收口径。
- 是否约下一次诊断。
- 当前顾虑是什么。

不做这些事：

- 重复发送大段服务介绍。
- 在需求不清时发价格表。
- 为了推进承诺结果。
- 在使用人没参与时推进复杂报价。

## 8. 记录字段

每次沟通后记录到 `records/`，至少包含：

- 日期。
- 客户类型。
- 信任来源。
- 具体流程 / 资料对象。
- 客户认知阶段：AI 没用 / AI 万能 / AI 可试。
- 上车方式：认知对齐 / 场景诊断 / 样板验证 / 试点陪跑。
- To Boss / To Business 判断。
- 高频 / 结构化 / 可评判 / 人工兜底判断。
- 买单人 / 使用人 / 资料方 / 验收人 / 总牵头人。
- 预算来源。
- 是否涉及敏感资料、账号或系统权限。
- 本次使用了哪些售前资产：demo / PPT / 小分享 / 自用工作流 / 模拟样板 / 诊断提纲。
- 是否涉及资源方，以及获客 / 售前 / 策略 / 执行 / 回款 / 售后责任是否拆清。
- 是否报价。
- 报价前缺口。
- 客户顾虑。
- 下一步动作。
- 是否可脱敏成案例。
- 可抽取的复用资产：问题清单、流程模板、验收口径、行业术语、demo 素材。
