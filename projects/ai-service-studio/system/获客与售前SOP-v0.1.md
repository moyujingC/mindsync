## 1. 售前目标

售前不是收集“客户想要什么 AI”，而是把客户的业务语言翻译成：

- 一条流程或一批资料。
- 当前人工怎么做。
- 哪些节点可能适合 AI。
- 哪些节点暂不适合。
- 成功怎么判断。
- 失败谁兜底。
- 下一步是否值得报价。

第一轮沟通不追求成交，只追求判断：

```text
这个客户、这个场景、这个资料基础，是否值得进入一次付费诊断 / 小实验 / 工作坊。
```

## 2. 获客入口

### 2.1 优先入口

当前优先从低压力关系和小范围演示开始：

- 熟人、前同事、弱关系。
- 小团队负责人。
- 有企业客户资源的人。
- 做企业服务、培训、咨询、代运营、SaaS、实施的人。
- 内容、销售、客服、交付、资料管理压力明显的人。

暂不优先：

- 投放获客。
- 大规模公开课。
- 城市组局官。
- 年框咨询销售。
- 培训平台招商。
- 团队化交付宣传。

### 2.2 低压力邀约模板

```text
我最近在验证一个小型 AI 服务，不做大而全的转型。

更像是拿一条具体流程或一批资料，看哪里适合 AI 介入，哪里暂时不适合。

如果你们最近也在想 AI 怎么先用起来，我可以先帮你看 30 分钟。
不用准备方案，拿一个真实流程聊就行。
```

面向资源方：

```text
我最近在整理企业 AI 服务的小诊断方法。

不急着接大项目，主要想找一些真实流程样本：
比如销售跟进、客服回复、资料整理、内容生产、项目交付这些。

如果你手上有企业客户正在问 AI，但还没想清楚怎么落地，
我们可以先聊一次资源方访谈，看看有没有适合做脱敏样本的小场景。
```

### 2.3 小分享承接动作

分享只讲一个具体场景，不讲泛 AI 转型。

可选主题：

- 企业做第一个 AI 小实验前要先问哪几个问题。
- 销售跟进流程怎么用 AI 辅助。
- 小团队项目资料怎么整理成可复用知识库。
- To Boss 和 To Business：企业 AI 服务到底服务谁。
- 一个 AI 服务产品矩阵怎么设计：引流品、利润品、明星品。
- 我怎么把一套自用 AI 内容工作流给团队跑起来。

会后只做三件事：

- 记录谁主动提到具体团队、流程、资料或预算。
- 24 小时内约 20-30 分钟诊断。
- 不发长服务介绍，直接问对方想跑通哪条流程。

## 3. 访谈前准备

### 3.1 访谈边界

开场说明：

```text
今天先不做完整方案。
我主要想了解你们现在一条具体流程怎么跑，
再判断它适不适合用 AI 做第一步。
```

如果要录音、转写或用 AI 生成纪要，先取得同意：

```text
为了避免遗漏，我希望对这次沟通做录音或整理 AI 会议纪要。
内容只用于需求确认、后续报价和本次服务记录，不会对外公开。
如果你不方便录音，我就只做手工笔记。
```

### 3.2 不直接问的问题

第一轮不要直接问：

- 你们有什么 AI 需求？
- 你们预算多少？
- 你们要不要做 Agent？
- 你们要不要做自动化？
- 你们要不要做知识库？

更好的入口：

- 哪个岗位最难招人或最依赖老员工？
- 哪个流程最耗时间、最容易返工或最容易出错？
- 哪批资料最难找、最难复用或最难交给新人？
- 哪个环节现在经常让客户、销售、交付或老板等待？
- 如果这件事快一天或少错一次，对收入、交付、客户体验或风险有没有影响？

## 4. 四张访谈检查表

真实访谈按四张表走。每次不一定全部问完，但报价前必须补齐。

### 4.1 客户认知检查表

目的：判断客户处在什么 AI 认知阶段，避免误导和错配。

| 检查项 | 访谈问题 | 判断 |
| --- | --- | --- |
| AI 没用 | 你们之前有没有试过 AI？哪里不好用？ | 用真实小 demo 建立信任，不讲大方案 |
| AI 万能 | 你希望 AI 最后替你完成到什么程度？ | 先讲资料、流程、人工校对、系统适配和使用人配合边界 |
| AI 可试 | 如果先用一个小场景试 7 天，你愿意提供什么资料和反馈？ | 可进入诊断、资料盘点或小实验 |
| To Boss | 这件事主要是老板个人体验，还是团队流程要变？ | 老板个人需求只作为破冰，不直接按组织交付报价 |
| To Business | 是否有员工、资料、SOP、流程、验收和复盘参与？ | 优先进入企业服务判断 |

老板或业务负责人可追问：

- 这件事半年后你希望变成什么样？
- 这条流程离开某个关键人能不能正常跑？
- 当前最卡的是执行、人员、流程、资金、渠道，还是资源整合？
- 你希望 AI 帮你省人，还是帮你放大业务？
- 你现在最想沉淀的是流程、内容、客户资产，还是员工经验？

### 4.2 业务流程检查表

目的：从业务路径里找可诊断节点，而不是从工具名出发。

| 检查项 | 访谈问题 |
| --- | --- |
| 流程对象 | 这条流程叫什么？从哪里开始，到哪里结束？ |
| 负责人 | 现在由谁负责？谁最懂细节？ |
| 频次 | 每天或每周重复几次？是否有旺季 / 淡季？ |
| 输入 | 每次开始前需要什么信息、文件、表格、客户消息或系统数据？ |
| 输出 | 做完以后产出什么？谁会使用这个产出？ |
| 最慢节点 | 哪一步最慢？慢在哪里？ |
| 返工节点 | 哪一步最容易漏、错、返工或被客户打回？ |
| 业务影响 | 它影响获客、成交、交付、客户体验、风险，还是新人上手？ |
| 当前判断标准 | 做得好和做得差，现在谁来判断？按什么判断？ |
| 人工兜底 | 如果 AI 做错，谁能发现？多久能发现？谁能改？ |

场景筛选规则：

```text
高频 + 结构化 + 可评判 + 有人工兜底
  -> 优先进入小实验

高频 + 非结构化
  -> 先做资料整理 / SOP / 话术库

低频 + 高价值
  -> 可做诊断，不优先自动化

非结构化 + 不可评判
  -> 不承接自动化
```

### 4.3 资料 / 数据基础检查表

目的：判断是否能直接进入诊断、知识库或自动化，还是要先做入场前整理。

| 检查项 | 访谈问题 |
| --- | --- |
| 资料位置 | 资料在微信、飞书、企微、网盘、CRM、本地文件、纸质文件还是其他系统？ |
| 资料形态 | 是文档、表格、PDF、扫描件、图片、聊天记录、视频、语音还是旧系统导出？ |
| 电子化程度 | 是否已经电子化？是否需要 OCR、转写、格式清洗或人工校对？ |
| 结构化程度 | 是否有字段、分类、标签、命名规则和版本管理？ |
| 术语和规则 | 是否有行业术语、内部黑话、公式、合规规则或不能乱答的内容？ |
| 可提供样本 | 是否能提供真实或脱敏样本？样本规模多大？ |
| 敏感边界 | 是否涉及客户隐私、商业机密、账号、cookie、API Key 或密钥？ |
| 持续维护 | 谁负责后续补资料、改标签、反馈错误答案？ |

知识库 / 内部 AI 助手类需求的前置规则：

```text
资料未盘点、未电子化、未清洗、未校对时，
只报价资料盘点 / 清洗 / 分类 / 入库前诊断，
不直接报价知识库问答效果。
```

自动化类需求的前置规则：

```text
没有完整手动流程、测试环境、成功标准、失败检测和人工兜底人，
不进入自动化试点报价。
```

### 4.4 决策链检查表

目的：确认谁买单、谁使用、谁给资料、谁验收，避免只和单点联系人聊天。

| 检查项 | 访谈问题 |
| --- | --- |
| 发起人 | 这次是谁先提出要看 AI？ |
| 买单人 | 谁决定是否付费？ |
| 使用人 | 最后谁每天用？ |
| 资料方 | 谁能提供流程资料、历史样本和账号权限？ |
| 验收人 | 谁判断这件事有没有价值？ |
| 推进人 | 如果做 7 天小实验，谁每天反馈？ |
| 时间窗口 | 你们希望什么时候看到第一版结果？ |
| 预算信号 | 你们更想先做诊断、工作坊，还是小实验？ |
| 内部阻力 | 哪些人可能不愿意用、没时间用或担心被替代？ |

报价前必须至少确认：

- 买单人知道这件事。
- 使用人认可当前流程描述。
- 资料方知道需要提供什么。
- 验收人能说清“什么算有价值”。

## 5. 场景处理规则

### 5.1 案例启发

客户答不上“有什么重复工作”时，用案例启发，不用案例替代需求。

使用原则：

- 可以用公开案例、同行样本和自建 demo 做场景启发。
- 必须说明哪些是公开材料、哪些是模拟案例、哪些是自己真实交付。
- 不能把别人的案例包装成自己的客户案例。
- 案例只用于激发需求，不能替代真实访谈。

### 5.2 自动化需求

客户说“想做自动化”“想做 Agent”“想批量处理”时，先影子跟跑手动流程。

额外追问：

- 这条流程如果完全手动跑一遍，需要多少步骤？
- 每一步涉及哪些平台、系统、账号、表格、文档或群聊？
- 哪些动作有平台审核、验证码、登录过期、权限限制或风控风险？
- 当前如何判断“发布成功、录入成功、通知成功、处理成功”？
- 如果自动化失败，客户内部谁能发现，多久能发现？
- 是否接受先用测试账号 / 测试数据跑小样，而不是直接上生产环境？

判断规则：

```text
动作可执行，但结果不可验证
  -> 不进入自动化试点

动作可执行，结果可独立验证
  -> 可以做小范围试运行
```

### 5.3 知识库需求

客户说“做知识库”“做内部 AI 助手”“把资料丢进去问答”时，先做入库前判断。

不能直接承诺：

- 资料丢进去就能问。
- 能替代老师傅。
- 能自动保持长期准确。
- 能处理未清洗、未校对、未授权的资料。

可进入的第一步：

- 资料盘点。
- 分类结构。
- 可入库 / 暂不入库清单。
- 命名和标签规则。
- 需要人工校对的问题清单。
- AI 使用入口建议。

## 6. 报价触发条件

满足以下条件，再报价：

- 已经有具体流程或资料对象。
- 客户当前痛点能说清。
- 高频 / 结构化 / 可评判 / 人工兜底已有判断。
- 买单人、使用人、资料方、验收人基本清楚。
- 客户知道下一步需要投入时间、资料或反馈。
- 本次交付物能写清。
- 本次不包含事项能写清。
- 是否需要合作方已判断。
- 是否涉及敏感数据、账号、系统权限已判断。

不满足时：

- 继续补访谈。
- 只报价小诊断 / 资料盘点。
- 或明确结束，不进入方案和价格讨论。

## 7. 跟进规则

跟单不是催促付款，而是推动下一步判断。

只跟进这些事项：

- 是否提供资料。
- 是否确认流程。
- 是否确认使用人。
- 是否确认决策人。
- 是否确认验收口径。
- 是否约下一次诊断。
- 当前顾虑是什么。

不做这些事：

- 重复发送大段服务介绍。
- 在需求不清时发价格表。
- 为了推进承诺结果。
- 在使用人没参与时推进复杂报价。

## 8. 记录字段

每次沟通后记录到 `records/`，至少包含：

- 日期。
- 客户类型。
- 信任来源。
- 具体流程 / 资料对象。
- 客户认知阶段：AI 没用 / AI 万能 / AI 可试。
- To Boss / To Business 判断。
- 高频 / 结构化 / 可评判 / 人工兜底判断。
- 买单人 / 使用人 / 资料方 / 验收人。
- 是否涉及敏感资料、账号或系统权限。
- 是否报价。
- 报价前缺口。
- 客户顾虑。
- 下一步动作。
- 是否可脱敏成案例。
- 可抽取的复用资产：问题清单、流程模板、验收口径、行业术语、demo 素材。

## 9. 待沉淀资产

- 售前问答库。

- 报价记录。
- 跟单记录。
- 资源方访谈记录。
- 可脱敏案例库。
- 行业术语表。
- 流程模板。
- 失败案例和拒单案例。
