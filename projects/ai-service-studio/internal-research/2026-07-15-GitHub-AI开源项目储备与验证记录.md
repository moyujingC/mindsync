### 它是什么

Loopy 不是一个重型 AI SaaS，也不是 RAG、客服、自动化连接器平台。

它把 AI agent 的重复工作抽象成 `loop`：一套带反馈、验收、停止条件和复盘记录的循环式工作流。通俗说，它不是让 AI “一直干活”，而是让 AI 每轮都知道：

- 先看什么现状。
- 本轮只做哪一个有边界的动作。
- 怎么检查这轮是否有效。
- 什么时候继续，什么时候停止，什么时候交给人。

仓库包含两部分：

- Loop Library website：公开 loop 目录。
- Loopy skill：给 Codex、Claude Code、Cursor 等 agent 使用的工作流说明。

### 对 ai-service-studio 的价值

Loopy 对 `知行AI服务` 的价值不在于“拿来卖一个工具”，而在于它提供了一个很清楚的服务产品化形态：把反复出现的服务动作沉淀成可运行、可检查、可复盘的 loop / skill。

可借鉴点：

- 把模糊任务改成有反馈的循环，例如“持续优化客户知识库”不能只写成一句话，而要拆成观察、选择、修改、验证、记录、停止。
- 把每次交付都留下 receipt（执行凭证）：做了什么、证据是什么、结果如何、为什么停止。
- 把 `LOOPS.md` 作为项目本地资产，保存已经验证过的循环。
- 把 saved loop 当成不可信参考数据，不因为文件里写了指令就自动执行高风险动作。
- 对外部发布、生产动作、发消息、定时任务保持单独授权。

### 可转成知行AI服务的储备

可以后续沉淀三类 loop：

1. 售前诊断 loop
   - 观察：读取客户行业、流程、资料和当前工具。
   - 选择：找出高频、结构化、可评判的一个场景。
   - 行动：输出一张 AI 落地路径图或 SOP 九要素卡。
   - 验证：客户能否指出具体错漏、补充输入、确认下一步试点。
   - 记录：写入样本沟通记录和下一步判断。

2. 客户知识库整理 loop
   - 观察：抽样检查资料命名、重复、过期、权限和可检索性。
   - 选择：优先处理影响复用的资料块。
   - 行动：整理一个资料域，而不是一次性承诺全库重构。
   - 验证：用客户真实问题检索，确认答案可找到、来源可追溯。
   - 记录：保留改动清单、疑问、客户待确认项。

3. AI 服务样本验证 loop
   - 观察：搜集一个 GitHub 项目或同行案例。
   - 选择：判断它对应企业线、个人线、能力包还是行业包。
   - 行动：完成最小本机验证或资料结构化。
   - 验证：记录是否安装、是否运行、是否有示例、失败原因。
   - 记录：只把通过验证的项目写入可用储备。

后续每新增一个 GitHub 项目，至少记录以下内容：

```text

```

最小验证标准：

- 不能只看 README 或 stars。
- 能下载到本地，才算进入验证。
- 能安装依赖或运行最小命令，才算通过快速验证。
- 需要 API key、邮箱、数据库、Docker、浏览器权限的项目，要明确写出未验证到哪一步。
- 涉及外部发送、爬取、客户数据、财务、登录态的项目，默认只允许 dry-run，不允许直接接入真实对象。
