## 3. 反复出现的模式

### 3.1 培训是信任场，不是终点产品

多篇材料都指向同一条路径：

```text
小分享 / 培训 / 工作坊
  -> 建立信任和共同语言
  -> 识别流程、资料和岗位场景
  -> 进入诊断、样板、小实验或陪跑
```

稳定判断：

- 培训可以作为企业服务入口。
- 通识工具课不能成为主产品。
- 企业内训必须围绕岗位、流程、资料和后续承接设计。
- 培训后如果没有诊断和交付承接，就会停在低天花板。

### 3.2 企业客户需要先判断“上车方式”

反复出现的上车路径：

| 客户状态 | 第一动作 | 禁止动作 |
| --- | --- | --- |
| 认知未对齐 | 认知对齐 / 小培训 / 小分享 | 直接立项目、买平台 |
| 方向拿不准 | 场景诊断 / 工作坊 | 直接收一堆 AI 需求 |
| 场景明确 | 样板 demo / POC / 小实验 | 直接全量生产上线 |
| 已有样板 | 陪跑 / 试点定义 / 合作交付 | 承诺全公司转型 |

稳定判断：

```text
企业 AI 服务的第一步不是报价，而是判断客户处在哪个上车阶段。
```

### 3.3 售前信任资产开始变重要

多篇材料都强调，企业客户不是听服务方说“我懂 AI”就会相信。

可复用售前资产包括：

- 服务方介绍。
- 可演示 demo。
- 案例 / 方案 PPT。
- 试讲或小分享视频。
- 自用工作流。
- 模拟样板。
- 脱敏案例。
- 诊断提纲和交付样例。

稳定判断：

```text
无案例阶段不能伪造案例，但必须准备可信的替代资产。
```

### 3.4 资源方合作必须先拆分策略和执行

新材料反复出现资源方、培训机构、流量博主、企业服务商、经纪公司和实施方。

稳定判断：

- 有资源的人不一定能交付。
- 能交付的人不一定有前端客户。
- 合作前必须拆清获客、售前、策略、执行、回款和售后责任。
- 不能在合作方未确认时直接报价完整交付。

### 3.5 知识库项目必须按阶段治理

多篇材料已经支持“入库前整理”，本次材料进一步把知识库拆成：

```text
样板阶段：手工精修，跑通一个场景
扩展阶段：规则抽查，形成客户自查和整改规则
生产阶段：准入机制 + 机器辅助治理
```

稳定判断：

- 企业知识库不是个人知识库放大版。
- 企业知识库处理的是组织知识秩序。
- 万级以上资料不能直接导入。
- 资料准入、版本、权限、责任人、可信度、使用价值和错误回溯是生产级知识库的前置条件。

### 3.6 SOW / SOP / SLA 是交付边界的共同语言

材料中出现的 `SOW / SOP / SLA` 可以和现有报价、合同文件结合：

- `SOW`：服务范围，做什么、不做什么、交付物是什么。
- `SOP`：交付流程，客户输入、服务动作、节点、复盘。
- `SLA`：响应时间，答疑期限、响应方式、紧急程度。

稳定判断：

```text
凡是进入付费交付、工作坊、陪跑或合作交付，都应至少有轻量 SOW / SOP / SLA。
```

## 4. 只有单篇支持的信号

- 年入百万、千万级营收、百万项目、3000 万项目：结果数字未核验，不进入 system。
- 具体日薪、课酬、返佣比例：受渠道、城市、资历、客户类型影响，不进入正式价格表。
- 国央企、高校、大企业作为优先客户：对作者路径成立，但当前 `墨予镜企业AI服务` 不宜直接采用。
- 经纪公司独家合作：适合成熟讲师，不适合当前验证期。
- 个人知识库 / LLM Wiki 直接转企业知识库：只能借鉴结构化思路，不能照搬为企业治理方案。

## 5. 互相冲突的判断

### 5.1 高客单企业服务 vs 当前验证期

外部材料展示了高客单路径，但当前 `墨予镜企业AI服务` 仍处于验证期。

处理方式：

- 可以学习高客单服务的边界、资产和交付规范。
- 不能把高客单成交结果写成当前能力或对外承诺。
- 当前仍应从诊断、小分享、工作坊、小实验和资料整理做可复盘样本。

### 5.2 培训规模化 vs FDE 式服务

培训师路径追求课程和排课规模，FDE 式服务追求深度理解业务和交付闭环。

处理方式：

- 企业内训作为信任场和认知对齐动作。
- 工作坊作为培训走向交付的中间层。
- 不把自己定位成纯培训师。

### 5.3 资源方放大 vs 合作边界风险

资源方能带来客户，但也会带来返佣、客户归属、售后、回款、独家限制和责任模糊。

处理方式：

- 可以把资源方访谈作为获客入口。
- 合作必须先小样本验证。
- 正式合作要写清责任和利益分配。

## 6. 可以升级为 system 的规则

### 6.1 产品体系

可升级：

- 企业内训 / 小分享 = 信任场和认知对齐，不是终点。
- 工作坊 = 从培训走向交付的中间层。
- 企业服务阶段应显式增加：认知对齐、场景诊断、样板验证、试点 / 陪跑。
- 知识库服务按样板 / 扩展 / 生产分阶段。

### 6.2 获客与售前

可升级：

- 增加“上车方式判断”：认知、场景、样板、陪跑。
- 增加“预算来源 / 总牵头人 / 资源方角色”检查。
- 增加售前资产检查：服务方介绍、demo、案例 / 方案 PPT、试讲 / 小分享素材。
- 资源方访谈要判断获客、售前、策略、执行、回款、售后责任。

### 6.3 报价与边界

可升级：

- 策略诊断和执行交付分开报价。
- 培训 / 工作坊报价不默认包含方案设计、系统搭建、资料整理和长期答疑。
- SOW / SOP / SLA 作为报价边界结构。
- 大规模知识库治理必须单独报价。
- 回款周期和现金流风险要进入报价判断。

### 6.4 合同条款

可升级：

- 服务确认单 / 项目协议中加入轻量 SOW / SOP / SLA。
- 合作方参与时写清客户归属、返佣 / 分成、回款路径、售后责任、复购归属。
- 案例、授课照片、视频、客户名称、项目结果对外展示必须授权。
- 知识库项目写清资料准入、版本确认、责任人、错误回溯和维护边界。

## 7. 暂不升级的候选规则

- 具体价格区间、课酬、返佣比例：继续作为报价观察样本。
- 经纪公司 / 培训机构规模化排课路线：不适合当前阶段。
- 大企业、国央企、高校作为主目标：当前只作为低优先观察，不主动推进。
- 生产级 RAG、智能体部署、大模型私有化：需要合作方，不作为自交付能力。
- 年框咨询：等待真实交付、回款和复购反馈后再讨论。

## 8. 应删除 / 合并 / 降级的旧 system 内容

当前 system 不需要大删，但需要合并和前移：

- `AI服务产品体系` 中培训、工作坊和 FDE 关系可合并为“培训到服务闭环”，减少分散描述。
- `获客与售前SOP` 需要把资源方、总牵头人、预算来源和售前资产从零散判断升级为检查项。
- `报价与服务边界` 需要把 SOW / SOP / SLA 从合同语境前移到报价边界。
- `合同条款清单` 需要补资源方合作、案例授权、知识库准入和维护边界。

不应删除：

- 当前价格候选区间仍可保留，但必须继续标注为候选。
- 零案例获客和最快启动最小闭环仍适合验证期。
