## 1. 总体判断

这篇材料对 `墨予镜企业AI服务` 很重要，因为它从企业 AI 项目内部视角说明了一件事：

```text
企业 AI 服务最难的不是技术实现，而是客户认知、数据基础、流程现实和决策链对齐。
```

它和当前项目的判断一致：不能把企业 AI 服务做成“我会某个工具，所以我来搭系统”。真正的服务价值在于：

- 识别客户材料和流程是否具备 AI 化前提。
- 让客户从“AI 没用”走到“AI 有用”。
- 再让客户从“AI 万能”回到“AI 有边界”。
- 把预算方、使用方、数据方和执行方的诉求对齐。
- 将大企业已经验证过的知识库、流程自动化、Vibe Coding 能力，拆成中小企业可承接、可支付、可试点的形式。

本材料最值得同步进 `system/` 的不是大企业案例本身，而是售前和交付判断规则。

## 2. 可借鉴的业务模式

材料提出的可迁移路径是：

```text
大企业 AI 项目经验
  -> 拆解成中小企业可用的小方案
  -> 从知识库、流程自动化、Vibe Coding 培训陪跑切入
  -> 通过一个熟悉场景跑通首个案例
```

对 `墨予镜企业AI服务` 来说，可以转成三条当前候选服务路径：

- 企业知识库：资料整理、文档结构化、FAQ / SOP / 经验库、AI 查询入口。
- AI 自动化流程：表单填报、文件批处理、邮件分类、多系统数据搬运、重复流程自动化。
- Vibe Coding 培训陪跑：让业务人员用 Claude Code、Cursor、OpenCode 等工具做小工具、看板、流程助手。

这三条路径都不能从“大系统”开始，而要从一个熟悉行业的小场景开始。

## 3. 产品和服务设定

这篇材料支持继续保留当前产品阶梯：

- 入口：流程诊断、小范围演示、认知澄清。
- 主产品：AI 工作流诊断、AI 文档 / 知识库整理。
- 升级：流程自动化试点、工作坊、Vibe Coding 陪跑、垂直行业知识库。

需要补充的是两个前置产品判断：

### 入库前整理

很多客户以为“资料丢进去就能做知识库”，但真实项目里，资料可能是纸质、扫描件、图片、旧版表格、口头经验、历史记录。

因此知识库服务前面要增加一个明确阶段：

```text
入库前资料盘点和清洗
```

它可以包括：

- 资料盘点。
- 电子化状态判断。
- OCR / 转写 / 表格结构判断。
- 缺失资料清单。
- 可入库 / 暂不入库分类。
- 人工校对工作量估算。

这部分不能被隐藏在“知识库搭建”里免费消化。

### 认知 gap 设计

客户可能先觉得 AI 没用，看到 demo 后又觉得 AI 万能。产品和售前都要设计这两个阶段的引导：

- 先用真实小 demo 建立信任。
- 再明确边界、客户配合事项和合理预期。

## 4. 获客与销售

材料对获客有两个启发：

- 大企业不是当前优先目标，个人和小团队很难进入供应商体系。
- 中小企业是真实窗口，因为决策链短、试错快、数字化基础参差不齐。

对当前项目：

- 不要把目标客户设成大型金融、央国企、政企和高安全行业。
- 优先找熟悉行业里的中小企业、小团队、资源方、业务负责人。
- 内容里可以讲“AI 服务难点不是工具，而是先把资料、流程、预期和人对齐”。
- 演示时不要炫工具，优先展示一个熟悉场景的小 demo。

可写内容方向：

- 企业知识库为什么不是“资料丢进去就完了”。
- 做 AI 自动化前，先确认流程是不是 SOP。
- 为什么老板觉得能做，使用人却说流程对不上。
- 中小企业为什么比大企业更适合先做 AI 小实验。

## 5. 售前和需求诊断

这篇材料最应该沉淀进售前 SOP。

新增售前判断：

### 资料基础

- 资料是否已经电子化。
- 是否有纸质、扫描件、图片、旧表格。
- OCR 后是否需要人工校对。
- 专业术语、公式、表格是否会影响识别质量。
- 客户是否愿意投入资料整理和校对工作。

### 认知阶段

客户属于哪个阶段：

- AI 没用：需要真实小 demo 建立信任。
- AI 万能：需要边界说明、客户配合清单和合理预期。
- AI 可试：可以进入诊断或小实验。

### 决策链

- 谁有预算。
- 谁实际使用。
- 谁提供资料。
- 谁负责流程改造。
- 谁验收。
- 关键使用人是否参加了售前访谈。

如果预算方和使用方没有同时对齐，不进入完整方案报价。

## 6. 报价、付款和商业边界

这篇材料提醒：报价不能低估“入库前”和“对齐成本”。

知识库类报价应单独考虑：

- 资料盘点。
- 资料电子化和 OCR。
- 人工校对。
- 文档清洗。
- 知识切分和标签。
- 试问答和效果调优。
- 客户培训和预期管理。

流程自动化类报价应单独考虑：

- 业务流程梳理。
- 使用方访谈。
- 系统入口和操作方式确认。
- 模型 / 算力 / 工具成本确认。
- 测试环境和生产环境差异。
- 异常处理和人工兜底。

边界表达：

```text
这不是单纯搭一个工具。
如果资料还没整理、流程还没对齐、使用人没参与，
我只能先报诊断和试点定义，不能直接报完整交付。
```

## 7. 交付、验收和复购

交付上要避免两个误区：

- 客户把 AI 当老师傅，期望一次性回答所有复杂问题。
- 服务方把技术跑通当成项目完成，忽略客户内部使用和运营。

知识库验收不能只看“能问答”，还要看：

- 哪类问题能答。
- 哪类问题不能答。
- 引用来源是否清楚。
- 错误如何反馈。
- 后续谁持续补资料、改标签、优化问答。

自动化验收不能只看“Agent 能操作”，还要看：

- 操作对象是否稳定。
- 模型和算力是否匹配。
- 使用方流程是否一致。
- 失败后谁兜底。
- 生产环境和测试环境是否一致。

复购机会：

- 知识库持续运营。
- 新资料入库。
- 问答效果优化。
- 新流程自动化。
- Vibe Coding 员工陪跑。

## 8. 合同、数据和合规边界

本材料涉及金融、央国企、政府和制造业场景，但当前 `墨予镜企业AI服务` 不应承接高监管真实数据项目。

合同边界应提醒：

- 高敏数据、金融合规、政企系统、监管报送等场景当前不作为主交付。
- 如涉及客户资料、系统账号、生产数据，必须先做脱敏和权限边界确认。
- 知识库效果受资料质量、客户校对、使用反馈和后续运营影响，不承诺一次性达到“老师傅”水平。
- Agent 自动化受系统稳定性、模型能力、算力和客户流程配合影响，不承诺无人值守长期稳定运行。

## 9. 能力边界判断

当前自己可以直接吸收：

- 售前认知 gap 判断。
- 入库前资料盘点。
- 知识库整理前置诊断。
- 中小企业小场景筛选。
- 使用人 / 决策人 / 数据方访谈。
- Vibe Coding 培训陪跑的产品方向。

需要合作或谨慎：

- 生产级 RAG 系统。
- 多模态 OCR / 大规模文档解析。
- 金融和政企合规环境。
- Agent 操作客户生产系统。
- 模型和算力部署方案。

当前不碰：

- 大型金融、政企、央国企真实生产系统。
- 监管报送自动化。
- 高敏数据和核心业务系统接入。
- 承诺知识库“回答任何问题”。
- 承诺 Agent 长期无人值守。

## 10. 不适合直接照搬的部分

不直接照搬：

- 百万级项目经验。
- 大型金融、央国企、政企客户打法。
- 企业级 RAG 全链路方案。
- 生产级 Agent 报送系统。

原因：

- 这类客户有供应商准入、合规审查、采购流程，不适合当前个人 / 小团队阶段。
- 当前项目还在验证首单和小闭环。
- 直接复制大企业方案会导致交付成本、责任边界和合规风险失控。

适合吸收：

- 中小企业窗口判断。
- 入库前资料整理的重要性。
- 认知 gap 两阶段。
- 决策人和使用人必须同时对齐。
- 从熟悉小场景开始做案例。
