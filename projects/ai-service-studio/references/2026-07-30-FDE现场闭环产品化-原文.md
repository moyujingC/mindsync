## 结果与边界

作者称，截至 2026 年 6 月 30 日，10+ 家门店按 500 元/店付费参加小程序内测，20+ 家门店预约年费 9800 元的正式版。

作者特别区分：前者是已发生付费，后者只是预约意向；这些数字不能证明持续使用、续费或经营改善。

作者的转折来自一段获得授权的门店服务录音：AI 将录音与门店项目资料、服务标准对照，呈现顾客顾虑、员工接住或漏掉的环节，以及下一次跟进建议。作者据此把 FDE 概括为“从现场到钱箱的脏活闭环”。

## 七步与三个检查问题

作者给出的七步：

1. 混进去：到客户现场，看实际工作怎么发生。
2. 抓痛点：找到客户嘴上未必会说、但反复烦恼的点。
3. 做最小：第一版把功能压得足够小。
4. 一起搞：拉业务方参与共同搭建。
5. 塞进去：接入客户已有工作流程，而非要求客户改变习惯。
6. 盯着用：观察是否真的解决问题。
7. 要反馈：验证“有用”是否转成继续投入时间、材料或付费。

三个检查问题：

1. 这件事是否值得做，即是否存在真需求？
2. 第一版最小要做到哪里才算完成？
3. 客户认可后，是否愿意投入钱、时间和材料？

## FDE 的工作定义

作者认为，普通 AI 交付常停在工具、页面或报告做出之后；FDE 需要继续推进：以获授权的真实材料产出结果、与业务方核对、让结果进入员工辅导或顾客回访，并观察实际采用和改进。

> FDE 结果 = 真问题 x 可用结果 x 进入工作 x 持续使用

- 真问题：反复发生，已经损失时间、金钱或机会。
- 可用结果：人能核对，并知道下一步如何做。
- 进入工作：在正确时刻交到实际做决定的人手中。
- 持续使用：用户持续使用、改进并提供新材料。

作者还提出三问：最近一次具体发生在什么时候、谁在为它付出代价；一份真实材料能否产生可核对结果并改变某人的下一步；客户是否愿意继续提供材料、投入时间和支付真实金钱。

## 七步责任链的三段与过关证据

三段：做之前看清问题（进入现场、发现问题、定义范围）；交付时把结果接进工作（共同搭建、部署工作流）；用过后判断是否有价值（促进采用、验证影响）。之后把反复出现的输入、判断、输出和异常沉淀为 SOP、提示词、Skill 或产品模块。

每一步的过关信号：

1. 进入现场：能说清最近一次事件，并取得合规、获授权的真实材料。
2. 发现问题：能说清角色、卡点、损失和当前补救办法。
3. 定义范围：第一版只有一个用户、一个输入、一个结果、一个下一步，并说明不做什么。
4. 共同搭建：业务方提供标准、样本和判断，真人可核对结果。
5. 部署工作流：确定结果在何时交给谁、对方接下来做什么。
6. 促进采用：用户看得懂、信得过、使用成本低，且知道下一步。
7. 验证影响：记录谁使用、改了什么、是否再次提供材料或付费，而不是只记“挺厉害”。

作者把闭环区分为：

- 客户现场闭环：真实材料 -> AI 处理 -> 可用结果 -> 下一步动作 -> 使用反馈。
- 产品反馈闭环：使用反馈 -> 比较重复与例外 -> 沉淀最小能力 -> 放进下一次交付。

## 现场、角色与真需求

作者认为“现场”不等于线下地点，而是一条真实业务正在发生、有人判断、有人承担结果的工作链。是否进入现场看三点：能否看到最近一次真实事件；能否拿到合规、获授权材料；结果出来后能否追到下一步。

文章把客户拆为四种角色：使用者、受益者、决策者、付费者。它们不一定是同一人。

作者建议从完整业务流程中，用六个维度排序：频次、耗时、错误率、收入影响、个人依赖、AI 适配度（材料、判断标准、可检查结果）。

作者给出的真需求追问包括：谁遇到；最近一次何时、在哪一节点发生；现在如何处理；不解决损失什么；能拿到什么获授权、可脱敏材料；以及频次与已有投入。

> 真需求证据 = 具体角色 x 最近事件 x 当前做法 x 明确后果 x 真实材料 x 付费角色

文章进一步给出“真需求卡”的七项：具体角色、最近事件、当前做法、明确后果、已有投入、真实材料、七天内唯一验证动作。只有观点没有事件、只有痛点没有后果、或没有可用材料，均暂不过关。

## 范围收敛、共同搭建与 Demo

作者主张第一版最多选一个到两个同链节点。筛选条件是：问题高频、后果具体、有真实材料、结果后能快速得到使用/核对/拒绝反馈。

业务方共同搭建时至少要提供：

1. 获授权、脱敏的真实材料；
2. 项目知识、服务规范、风险边界和优秀样例等判断标准；
3. 能判断结果是否可用的验收角色；
4. 结果交给谁、何时使用、如何采取下一步的动作定义。

可核对的复盘至少应让业务方看见：原始表达、当时回应、AI 判断依据、下一次改进建议。

作者认为 Demo 可以是结果文档、可点击 Demo、离线 HTML 或小程序页面，但只有同时具备真实授权材料、输入/判断依据/结果可见、真实角色接走结果行动、采用/修改/拒绝被记录、并由反馈决定继续/修改/停止或扩展，才能算进入小闭环。

文章最后给出“关键节点卡”方向：现场边界、现场节点、问题节点、首版节点、入选理由、节点输入、节点结果等应在开工前写清。

## 采用与商业证据阶梯

作者将采用概括为：

> 采用 = 看得懂 x 信得过 x 不麻烦 x 有下一步

- 看得懂：使用者一眼知道结果在表达什么。
- 信得过：关键判断可以回到原始材料和业务依据。
- 不麻烦：不需要反复搬运、填写或解释。
- 有下一步：看完知道应采取哪个动作。

作者提出，当客户没有使用时，应先检查输入采集、授权隐私、结果长度与时机、判断依据可见性、登录/搬运成本和下一步是否清楚，而非先归咎于员工不懂 AI 或执行力不足。

文章还给出一条商业证据阶梯：称赞 -> 愿意继续聊 -> 愿意提供真实材料 -> 愿意让真实用户使用 -> 愿意支付首次费用 -> 愿意复购、扩展或介绍同行 -> 出现可核验经营改善。

作者强调不能跨级推断：提供材料不等于采用；一次使用不等于持续使用；一次付费不等于续费，更不等于经营改善。经营改善还需要基线、周期和清楚的归因口径。

## 文章中的案例与证据边界

- 美业服务录音：作者称“真实录音、AI 复盘和门店付费试用已经发生”，同时明确持续采用、复购和经营改善仍需后续行为证明。
- 白白兔与曼贝莲：文章以客户提供的项目资料、话术和知识库界面说明输入和标准可进入产品；作者也明确部分图片只能证明资料交付或功能入口存在，不能证明训练、采用、成交或复购已经发生。
- 飞书录音豆：作者将其作为“保留上下文”的记录入口，认为工具本身不是业务答案，决定价值的是后续判断标准、结果接收者与下一步动作。

## 原文中的提示词原则

文章提供两个 FDE 式需求访谈提示词：一个用于从真实经历中找问题，另一个用于将已有方向磨成真需求卡。共同约束包括：一次只问一个问题；未知事实标为未知；证据不足前不建议功能；不替用户补故事；输出已知事实、缺失证据、唯一下一步动作与不做事项。
