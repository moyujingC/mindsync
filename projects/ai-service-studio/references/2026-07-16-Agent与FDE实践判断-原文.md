## 1 从 AI 工具到 Agent：未来十年的核心机会
这几个月，我自己亲自动手做了很多事：在生财内部搭建了几十个 AI 员工，并且让它们全部进入真实生产线。现在很多生产工作，已经不是人在一项项推进，而是 AI 在持续执行。在我的带动下，团队内部也开始大量创建各种 AI Aegnt：有的是对自己工作的一部分升级，有的是对原来 AI 用法的重构。到现在，整个团队里每天都有新的 agent 上线，我估计内部加起来已经有三五百个 agent。

这件事走到今天，已经不只是“做几个 demo”那么简单了。真正值得讨论的是：这些 agent 怎么被创造出来，怎么迭代，怎么维护；更重要的是，demo 怎么变成生产级 agent，真正进入公司生产系统。

过去几个月也是我学 AI 以来成长最快的几个月。除了搭建内部 AI 员工，我还并行推进了几十个项目，有些只是 demo，有些已经在持续开发。其中感受最深的，是把一个项目真实推向生产线、推给用户使用，也就是 tokenrank。https://scys.com/tokenrank/ 这个产品从 0 到 1 所有东西都是我自己做的，所以它带来的体验完全不同：以前很多产品可能只是自己用，或者推给公司内部用；但当它真的面向用户，遇到的问题、迭代的节奏、反馈的压力，都会把你对 AI 和产品的理解推到另一个层次。

基于这些实践，我现在有一个非常强烈的判断：未来十年最大的机会，只有一个，就是 Agent。

这不是说某个 AI 工具、某个细分行业、某个小产品会有机会，而是 agent 会颠覆几乎所有行业、所有服务、所有产品。去年我们讲 OEAI，今年在公司内部和生财社区里，已经进一步变成了 OEAgent。也就是说，不只是“把 AI 用起来”，而是要把 AI 进化成 agent，成为能够承担任务、串联流程、进入生产线的工作单元。

这也是所有人需要尽快达成共识的一点：AI 工具只是局部提效，Agent 才是重组生产关系。

## 2 FDE：普通人可以抓住的高价值角色
当 agent 成为未来十年的核心机会，一个关键角色也会被推到台前：所有领域、所有公司、所有人都需要做 agent，但谁来做？不可能每个人都同时具备 AI 能力、技术理解、业务拆解和落地部署能力。

这个角色就是 FDE。它的全称是 Forward Deployed Engineer，也就是前端部署工程师。这个概念最早由一些前沿 AI 公司提出：公司拥有强技术平台，然后派员工进入客户企业，借助 AI 增强能力，把技术真正部署到客户的业务里。

现在 FDE 的概念已经进一步扩散，不只是少数平台公司在使用。OpenAI、Claude、国内大模型公司、飞书等，都在招募和培养 FDE。它不是某一家公司的职位，而是一类新的能力结构。

但我过去几个月实践下来，反而认为：FDE 不只是大厂和大模型公司的机会，更是超级个体、普通人可以把握的机会。

每个层次的机会当然不同。对普通人来说，如果能抓住 FDE 这个机会，可能会有十倍增长的空间。如果你正在经历职场转型、正在寻找方向、正在找项目，那么成为 FDE 这件事值得认真了解。也许几年之后回头看，你会感谢今天开始投入的努力。

我自己这几个月其实就是在把自己变成公司的 FDE。我希望自己能够支撑公司所有关键项目、产品和服务的 agent 化改造：我先把这些东西做出来，再把团队成员培养出来，让团队成员跟我一起推进。

传统外包模式里，一个人可能只能服务一家企业。但随着模型能力提升，以及你对 AI、业务和部署的理解加深，一个人同时支撑多个企业的能力会越来越强。未来，一个足够强的 FDE，可能同时支撑几十家企业。这种人的价值会非常可怕。

## 3 把飞书变成 AI 员工工作台
我现在飞书左侧导航栏已经不再是过去那些会议纪要、营业执照、会议时间安排、日程等内容，而是我的 AI 员工。几十个 AI 员工都待在左侧导航里，随时等待我安排任务。

这套体系大概是在 5 月、6 月搭起来的。当时飞书 CLI 刚推出不久，爱马仕等相关工具也出来了。我试用一段时间后，把这些东西组合在一起，搭建了公司内部的 AI agent 体系。

目前在飞书里的 agent 被分成多个部门，其中第一个很重要的部门是“Agent 组织部”。它相当于 agent 的人力部门，负责创建 agent、维护 agent、审核 agent，以及处理 agent 的入职、运维等事情。

### 3.1 Agent 架构师：发现哪些工作值得智能化
Agent 组织部里有一个角色叫“Agent 架构师”。它接入了 Claude Code，并且拥有比较完整的权限。因为有些 agent 只在内部使用，没有开放给其他公司或外部流程，所以可以给到较高权限。

这个 Agent 架构师每天能看到我和不同人的聊天、我在群里的发言、当天开的会、群里谁转了什么文档，以及工作群里同事之间的互动和流程。它的任务是每天告诉我：昨天哪些工作流可以智能化，哪些工作流有被 agent 替代或重构的价值。

我每天会收到一批建议：这个工作可以智能化，那个流程可以智能化。然后我判断是否有价值。如果有价值，我就让它创建一个 agent，把这项工作替代掉。

也就是说，Agent 架构师替代了我一部分“观察公司流程并判断哪些环节可以智能化”的工作。

### 3.2 Agent 运维官：自动维护所有 agent
真正开始使用 agent 后，会发现运维并不轻松：一会儿权限有问题，一会儿授权过期，一会儿飞书升级导致流程变化。于是我专门做了一个 Agent 运维官。

它每天定时维护我的所有 agent。很多问题不需要我自己修。如果不是特别紧急，我可以等它自动处理。这样一来，我不再需要把大量精力花在琐碎的权限、授权、版本兼容问题上。

### 3.3 Agent 审核官：处理团队每天上线的新 agent
现在公司里每天可能有十几个 agent 上线，团队成员各自创建 agent。如果所有 agent 都由我来审，我根本审不过来。每个 agent 涉及各种权限、工具和调用范围，人工逐一检查成本非常高。

所以我又做了一个 Agent 审核官，专门处理 agent 上线审核。它会帮我看权限、看风险、看配置是否合理。这个角色让 agent 的扩张不再完全依赖我个人审核。

这套 Agent 组织部还包括技术专家等角色。每一个 agent 展开讲都很有意思，但核心思路很清楚：当 agent 数量增加之后，你不能只创建“干业务的 agent”，还必须创建“管理 agent 的 agent”。

## 4 已经落地的三类业务 agent
目前内部已经落地的 agent 大致覆盖几大类。

第一类是运营类，包括周报、申请、会议、财务、微信日报等。很多运营事项已经可以由 agent 直接完成。

其中微信数据是一个特别有意思的方向。如果你知道如何拿到微信数据，就可以做出非常好玩的应用：它可以读取你的微信聊天记录、公众号文章、收藏、通讯录，并围绕这些数据生成各种自动化服务，比如微信日报。不过具体实现方式不方便展开。

第二类是内容生产类，覆盖选题、改写、发布、转录等环节。内容生产链条里有大量重复但又需要判断的工作，适合用 agent 拆成多个子任务来完成。

第三类是社群管理类，包括评分卡、帖子筛选、打标签、用户洞察等。例如用户在群里提出了什么问题，具体困惑是什么，哪些帖子值得筛选出来，哪些用户行为值得关注，这些都可以通过 agent 流程处理。

这些还只是开始。如果进一步分类，公司里方方面面的工作都可以被 agent 化。我们现在还在做一个内部 agent 工作台。这个工作台完成之后，整个 agent 体系还会进一步展开。

## 5 案例：多平台音视频转录 Agent
我自己用得最多的一个 agent，是多平台音视频转录 agent。

它的背景很简单：我现在基本不太看长视频了。几十分钟、一两个小时的课程，或者三四个小时的长播客，即使内容很好，我也很难花整段时间去看完、听完。比如 YouTube 上有很好的长播客，小宇宙里也有很多值得听的内容，但时间成本太高。

市面上也有很多转录和总结类工具，但它们通常有两个问题：

要么把内容压缩成高度摘要，细节丢失严重；

要么保留了大量口水话，读起来很累。

我真正想要的是另一种结果：既不要废话，又不能丢细节。因为很多内容的价值恰恰藏在细节里。抽象结论往往大家都知道，真正拉开差距的是细节、案例、判断过程和上下文。

所以我自己做了一个多平台转录 agent。它可以把主流视频平台、音频平台、图文内容等转成非常干净的文档：没有口水话，同时尽可能保留细节。对我来说，这个价值非常大。如果我自己做不出来，市面上有人卖这样的产品，我愿意花一万块钱买。

现在我的使用方式很简单：刷推特、看 YouTube、看小宇宙时，只要看到任何好帖子、好播客、好视频，我就直接转给这个 agent。它叫“小D”，也就是视频转录助手。比如一个关于 Claude 的 4 小时教学视频，它可以基本一次不差地转录出来。我不可能自己花 4 小时看完，但它能把全文整理出来。

更重要的是，它不是只做机械转录。转录之后，它会在文档里标重点。因为它知道我的偏好，知道哪些内容对我有帮助，哪些是我已经知道的，哪些是我可能不知道但值得关注的。它相当于一个超级助理，而且是一个很懂我的助理。

这个 agent 背后不是单一步骤，而是一整套工作流：下载、转录、提纯、创建飞书文档，再根据我的上下文标注重点。它也可以理解为若干个子 agent 的合集。

我已经把这套 agent 的部分固定方法、提示词、流程和 skill 文档发到星球里。这个 agent 给我节省了非常多时间。类似这样的 agent，我们团队内部还有很多。

## 6 人在 Agent 流程里的核心作用
当 agent 能够主导整体流程之后，人到底还起什么作用？我现在越来越明确：人的作用不是去做每一个步骤，而是集中在几个更关键的点上。

第一个，是能不能提出好问题。你要知道自己到底要干什么，能不能把问题定义清楚。有想法的人，在 agent 时代会迎来最好的时代。 如果你没有问题、没有好奇心、没有想做事的欲望，agent 也很难帮你创造出真正有价值的东西。

第二个，是判断力。你要判断什么事情有价值，判断该往哪个方向走。以前我用 AI 时，常常是我在等 AI：我给它一条指令，它去开发，我在后面等结果。现在反过来了，基本是 AI 在等我。因为我可以同时开很多个进程、推进很多个项目。最多的时候，我可能同时开发 15 个项目，每个项目里还有几个 agent 在运行。

这时最重要的不是你会不会亲自执行，而是你能不能快速判断：哪个方向要驳回，哪个方向要继续，哪个结果有价值，哪个结果应该重做。

很多人用 AI 会越用越累，感觉事变多了，一个原因是他们仍然在原有工作流上加 AI。也就是说，旧流程不变，只是把 AI 当成中间某个环节的工具。这样当线程变多时，人会被大量判断和衔接动作压垮。

真正更好的做法，是让 AI 主导整个生产流程，人去做配合。你应该完整告诉它：我要干什么，我的意图是什么，目标是什么，怎么判断结果，可能的样本是什么。然后让 agent 重新组织流程，而不是在旧流程里补一个 AI 环节。

这也是 agent 和传统工作流最大的区别。过去讲工作流，很多时候还是围绕旧有生产流程，把 AI 当成工具做局部改造。但 agent 出现之后，效率可能是 10 倍甚至百倍提升，核心区别就在于：不是让 AI 嵌入旧流程，而是让 AI 主导新流程。

## 7 AI 幻觉的根源：问题定义、标准和上下文
很多人会说 AI 有幻觉，或者 AI 生成的东西不可靠。但我一直有一个判断：AI 是人的能力放大器。

如果你自己做事就容易幻觉，AI 的幻觉也会多。如果你讲不清楚边界是什么、标准是什么、目标是什么，AI 当然只能靠猜。反过来，如果你能清晰定义问题，告诉 AI 什么是好东西、产出边界在哪里、判断标准是什么，它给你的结果往往会非常惊艳，也足够进入生产。

对大多数应用者来说，我们离 AI 的真实边界还很远。OpenAI 的研究员也许能看到模型边界，但对我们普通业务场景而言，绝大多数时候 AI 只会给我们惊喜。很多所谓“AI 不行”，大概率不是模型真的碰到了能力边界，而是我们没有把问题、上下文、标准和授权讲清楚。

幻觉还和上下文工程有关。现在有一个词很火，叫 Harness。可以粗略理解为：agent 减掉大模型能力，剩下的配套体系就是 Harness。它包括你有没有构建足够好的上下文，有没有给 AI 充分的授权和信任，有没有让它理解事情的目标、流程、结果，以及人与 agent 之间的角色分工。

如果这些都清晰，AI 产出的效果会远远超过“幻觉阶段”的想象。

但最后还有一条底线：高风险决策必须由人兜底，不能完全授权给 AI。 尤其是可能带来法律、财务、品牌或重大业务风险的事项，人必须做最终判断。Agent 可以主导流程，但人要承担最后责任。

## 8 从工具栈统一到组织重构：AI 时代的团队工作方式
### 8.1 为什么团队要统一到飞书、Codex 和 Hermes Agent 框架
过去很长一段时间，团队内部的 AI 基建其实是比较分散的。每个人按自己的工作需要使用不同工具：有人用 Claude Code，有人用 Codex，也有人在飞书里做各种自动化。随着实践越来越多，团队逐渐意识到，如果要让 AI 真正进入组织协作，而不是只停留在个人效率工具层面，技术栈必须统一。

飞书是必须使用的基础设施。原因很简单：团队过去几年的工作本来就在飞书上，文档、项目、汇报、沟通都沉淀在飞书里。当飞书开放相关 AI 能力之后，Agent 就可以无缝介入这些工作场景：帮忙发消息、看文档、整理汇报、盯项目、整理内容。对一个团队来说，这不是额外增加一个工具，而是让原有协作系统长出 AI 能力。

服务层面之所以统一到 Codex，并不是因为不想用 Claude Code，而是现实上很难完全依赖 Claude Code。Claude Code 的 token 额度消耗太快，个人每周 200 多美元的额度，往往周日凌晨刷新，周二就可能用完；团队账号还经常面临封号问题。因此，目前 Claude Code 只能优先供给核心的五位工程师使用。

新成立的工程师团队则统一配置更稳定的资源：每个人 200 美元 Codex 配额，再加 250 美元 Pro Code 配额。判断很明确：要给工程师足够的 token 和工具保障，才可能产出更高质量的成果。

所以团队现在鼓励所有人把 Codex 当作主力工作台，在 Codex 里创建项目、开发 Agent、做产品。此前工作台可能散落在不同工具里，接下来会尽量收拢到 Codex。

但如果只是单独使用 Codex，虽然也能做出很多 Agent，要让这些 Agent 自动维护、在飞书、企微、微信等协作环境里持续运转，还需要一套 Agent 框架。这里引入的是爱马仕 Agent 框架。它不是让每个人都去手工维护 Agent，而是让 Codex 去修、去维护、去处理问题。对于大多数成员来说，真正需要掌握的是 Codex；框架要理解，但维护可以交给 AI。

目前智能团队统一下来的技术栈，可以概括为三件套：

- Codex，作为核心工作台；

- 爱马仕 Agent 框架，用于 Agent 的自动维护和多平台接入；

- 飞书 AI / 飞书协作体系，用于文档、项目、消息和办公场景落地。

团队内部还在建设一个 Agent 工作台客户端，把公司内部所有 Skill、Agent、MCP 聚合起来，让大家可以共享 Agent、共享 Skill、共享能力。对于大多数团队来说，如果能把这套技术栈用好，已经会释放非常大的价值。

### 8.2 Obsidian、知识库与 Skill：个人工具和团队协作不是一回事
Obsidian 仍然是好工具，但更适合个体。它本质上是一个个人知识库：把大量个人信息、内容、资料沉淀进去，再通过插件把 Claude Code 或 Codex 接入，用来处理内容。

但团队最重要的不是“存知识”，而是协作。协作在 Obsidian 里很难顺畅完成，而飞书天然适合协作。比如团队在 Codex 里做出了一个产品 Demo，可以直接调用飞书的能力生成一个所有人都能讨论的 Demo；这些事情如果放在 Obsidian 里，往往还需要外部网络或其他工具配合，链路会复杂很多。

因此，对团队来说，飞书比个人知识库更关键。甚至对于个体，也强烈建议提前使用飞书，因为未来一定会面对协作、共创、和外部伙伴一起工作的场景。飞书文档在分享和协作上的体验，仍然是非常强的。

同时，对“知识库”和“Skill”的感知也在变化。AI 工具在进化，越来越多知识库和 Skill 的能力正在被模型和工作流内化。现在更理想的方式是：让 AI 用它最能理解的格式去维护知识库，沟通过程自动沉淀成本地知识库，项目结束后自动整理成 Skill，下次执行类似任务时再自动调用。

如果使用飞书 Bot 作为入口，它还有一个很大的优势：上下文和记忆能力更好，可以在同一协作环境里延续任务、复用 Skill。这样一来，人不一定需要频繁打开知识库，也不一定需要手动管理每个 Skill。

知识库不是不重要，而是它不应该成为人的负担。更好的状态是：AI 自己维护知识库，人只负责提出问题、定义标准和推动产出。

### 8.3 普通人真正要跨过的门槛：先把 Codex 用起来
很多人会觉得这套配置很复杂，但实际落地时，最重要的学习对象只有一个：Codex。爱马仕框架、Agent 维护、Skill 管理，都可以让 Codex 去做。遇到问题时，不需要人手工逐个修 Agent，而是直接把问题交给 Codex，让它自己修。

如果暂时用不了 Codex，国内也有一些替代工具可以尝试。但如果对自己有更高要求，还是建议尽量想办法使用 Codex；如果愿意折腾，也可以继续使用 Claude Code。不同工具带来的能力边界和使用感受会非常不同。

AI 工具的门槛，很多时候不是靠自己闭门摸索跨过去的。参加线下聚会，找一个会的人现场教你，给对方发个红包或请对方吃顿饭，可能就能跨过关键门槛。跨过去之后，对 AI 的理解会完全不同。

生财最近把线下聚会作为重要方向来推进，一个月大约有三四百场线下聚会。目的就是让成员在线下链接、学习、互相帮助。过去一个月里，仅不带词的聚会就推了七八十场。很多分享者自己参加过大课，在 AI 工具使用上有基础，而且分享的不是单纯“工具怎么用”，而是“业务高手怎么结合业务使用 AI”。这种结合业务的学习，对落地更有价值。

### 8.4 AI 小程序的新红利：低成本软件会重塑供需关系
这次航海只保留了七条船。过去航海项目更多，十几条船会给大家太多选择，反而容易困惑；这一次团队反复筛选，只留下“砍到最后不得不留下”的方向。每一条船都代表一个有价值的方向，都能支撑参与者去学习、实践和获得新能力。

其中第一条重点方向，是用 AI 做小程序。

用 AI 做小程序并不难，而且过去一年已经出现了很多通过小程序赚到百万以上的案例。以前做小程序仍然有开发难度，很多细分需求也很难被抓住；现在因为 AI 降低了软件生产成本，新的红利正在出现。

一个典型案例是圈友郭东超。他做的是小程序和虚拟产品，基本没有成本，做得好的时候一个月收入上百万。另一个案例是卧龙，一个 05 年的小朋友，高中没毕业就辍学，在小红书上卖课堂管理小工具，卖给老师使用，最好的时候一个月做到接近 50 万。

这背后真正重要的变化，不只是“AI 能做小程序”，而是软件生产成本大幅下降之后，供需关系发生了变化。过去做一个 App，可能需要几十万成本，周期也要三个月。结果是很多细分人群的小需求没人满足，也没有产品愿意去满足。

但中国市场足够大。很多看起来很小的需求，只要有 1% 的人需要，放到中国市场里就可能对应上千万用户。在中国，再小的需求都可能不小。

所以，如果你有自己的需求，或者看到身边朋友有某种需求而没有产品满足，就可以大胆去创造。先从 0 到 1 做出来，然后找到具体人群，去做流量。如果能找到 100 个、1000 个愿意付费的人，这件事就可能成为一个不错的生意。

对于很多新手来说，用 AI 做一个小程序，并尝试一个商业模式，是非常好的起步方式。未来中国的软件市场可能会千倍、万倍地增加，各种细分赛道都会出现有意思的 App 和小程序。

小程序相比海外产品，更适合大多数人作为起点。做海外产品看起来可以赚美金，但难度更高：不了解海外用户需求，还要做 SEO、投放、社交推广，几个月都未必有反馈。小程序不一样，产品做出来之后往朋友圈、微信群一转，可能很快就有第一单 9.9 元，甚至 2.9 元。这个正反馈会让人有信心继续迭代。

因此，AI 小程序航海会围绕完整闭环展开：如何找需求、如何做产品、如何推广、如何从 0 到 1 跑通。过去半年到一年观察到的方法论，会被提炼出来教给大家。判断是：未来每个人都能做很多小程序，其中一定会涌现出非常厉害的爆品。

### 8.5 从“讨论想法”到“拿 Demo 说话”
组织内部的工作方式也在发生变化。现在最不愿意听到的是“我有一个想法，我们讨论一下”。有想法，就不要只讨论；把 Demo 拿出来，把真实在线跑的产品拿出来。行就行，不行就不行。

去年团队要求全员学习 AI 编程；今年 6 月之前，要求全员做 Agent；到了现在，要求全员进后端。所谓进后端，意味着每个人都要学会调 API、打数据库、把产品运营上线，并且用 Git 或类似方式持续迭代产品。

这不是对工程师的要求，而是对公司所有成员的要求。因为在 AI 时代，想法和产品之间的距离被大幅缩短了。有了想法，Demo 就应该出来。

组织结构也因此发生变化。过去一个项目从想法到上线，需要运营、产品经理、设计师、开发、测试，一轮一轮传递。现在这种按照职能切分的模式正在失效。AI 极大增强了个体能力，个人就应该成为入口：如果一个运营有想法，就应该自己把产品开发出来并上线。

这也对应现在很火的概念：Loop。它指的是 AI 时代个体能力被极大丰富后，公司部门分工不应再按照传统职能来推进项目。项目不再是部门之间层层流转，而是由少数人围绕目标快速闭环。

全球最火的 AI 公司之一 Anthropic，也呈现出类似趋势。它是一家约 3000 人的公司，但整体以项目制方式运作：一个人有想法，就找两个人组队，三个人开干。

生财内部也正在演变成这种状态。未来所有人都要成为 FDE，所有人都要全栈。现在公司里很多运营已经做出了生产级别的产品。以后可能两个人搭档做一个产品：一个人更多负责推广 Agent，另一个人更多负责产品 Agent，组合起来就能完成过去一个团队才能完成的事情。

### 8.6 AI 是老板的一把手工程：只让员工学 AI，只能得到局部最优
在很多大厂和传统组织里，AI 化更多发生在中台：开发部门、数据部门、后台部门开始使用 AI。但前台业务端很难真正 AI 化，受限于部门墙、权限、人数和流程，很多业务人员并没有把 AI 用起来。

生财的不同之处在于，成员拥有更完整的权限、数据阅读权限和工具使用权限，token 不设限，配备顶级账号。一个从阿里出来加入团队的同事，再回头和过去同事交流时，会感觉像“鸡同鸭讲”。不是因为原来的同事不努力，而是两边的上下文、权限、工具和成长速度已经完全不同。

这对老板尤其重要。超过 5 人、10 人，甚至百人规模的公司，都应该认真考虑如何把公司改造成 AI Native 组织。因为这不是单点提效，而是组织结构重构。

这里有一个很直接的判断：老板不下场，没有好下场。

AI 是一把手工程。创业以来，老板会发现很多事情都是一把手工程：人力是一把手工程，流量是一把手工程，团队建设是一把手工程。现在 AI 也是真正的一把手工程，而且是革命级变化。老板如果不知道 AI 的边界在哪里，就不知道公司应该怎么用 AI。

只让员工学 AI，最多让组织效率提升 20% 到 30%。因为员工通常站在自己部门、自己模块、自己岗位的角度做优化，只能得到局部最优。老板学 AI 之后，看到的是全局工作流，可能会发现原有工作流应该被直接扔掉，整个公司需要搭建一个全新的结构。

所以，AI 组织改造不是“每个部门各自提效一点”，而是从公司整体重新设计工作方式。

### 8.7 新团队方向：FDE、SD 与企业 AI 服务
随着每个人的能力提升、边界消除，团队现阶段并不急于大规模招人。因为每个人都能承接更多事情，组织反而不需要按照传统方式不断扩张。

但接下来会成立新的团队，重点开放两类合作机会。

第一类是 FDE 团队。适合那些在某个行业里本来有资源、有经验，可能一年能赚几十万到上百万，但 AI 能力还不强的人。这类人加入之后，未来有机会成为某个细分行业的合伙人，与团队共同做行业 AI 落地。

第二类是 SD 团队。适合 AI 用得非常好、已经比较熟练，但缺少商业方向的人。这类人可以加入团队，一起为企业提供 AI 服务。

这两类人会持续开放合作机会，后续也可能专门做招聘直播，系统讲生财最近在招什么样的人。相关团队会由主理人亲自带。

### 8.8 AI 航海家：看见最佳实践，本身就是生产力
针对老板、组织和从 0 到 1 之后希望系统学习 AI 的人，还有一个社群叫 AI 航海家。它可以理解为 AI 方向的老板私董会，主要交付在线下：教大家怎么用 AI，也组织大课和游学。

下周末会有一场大课，主题是内容 Agent。日常也会带大家去看各行各业里 AI 和 Agent 用得最好的企业是什么样子。

一个很典型的参访案例是方片传媒。方片传媒的 Agent 化改造非常成功，已经做出了类似 Skill + Agent 的内部工作台。他们公司有 500 人，其中 100 人已经会做 Agent，工作台里沉淀了 100 多个各种各样的 Skill 和 Agent。甚至出去谈业务的商务人员，也在搭自己的 Agent 系统，让跑业务更顺利。

这套经验也分享给过无忧传媒等 MCN 公司老板。它说明一件事：看到最佳实践长什么样子非常重要。

AI 时代尤其如此。很多时候你不一定要当场学会，只要看见就够了。看到一个好的工作台、好的 Agent 系统，拍照或录视频带回去，发给 Codex，说“我要做成这个样子，但按照我们公司的标准来”。5 到 10 分钟后，就可能得到一个适合自己公司的 Agent 雏形。

所以 AI 时代最重要的能力之一，是眼界、标准和审美。审美就是你见过好东西。老板尤其需要出去看：哪些公司已经实现了 AI 化、Agent 化，它们的组织和工作台长什么样子。

眼界就是生产力。

这也是为什么主理人每天会花两个小时刷信息流、看 Twitter、看 YouTube。老板最重要的是眼界。没有眼界，再努力也很难知道什么是好东西。

### 8.9 言出法随：想法出现的那一刻，产品就应该开始成形
AI 时代的创业方式正在改变。过去有一个想法，大家要先讨论、评审、写 PRD、出设计稿，再找程序员开发。这个流程已经过时了。

现在更接近“言出法随”：当你有想法的那一刻，产品就已经开始出来了。一个产品想法出现后，接下来一两个小时内，就可以快速和 AI 沟通，把产品雏形做出来。快的时候，20 分钟就能做出一套可看的东西。

这意味着，AI 时代最关键的能力，不只是找项目，而是 AI 工程能力。很多人会问现在应该找什么项目，但更重要的是，你是否具备把想法快速变成产品的能力。

AI 编程、数据库、内容生产、Agent 搭建，这些能力会极大拓宽一个人的边界。没有这些能力时，你能选择的空间很小，往往只能抓短期信息差，而信息差很快会消失；有了 AI 工程能力之后，你会发现自己能做的事情突然变多。

项目不是最重要的，Agent 工程能力才是核心竞争力。

更长期看，各行各业都需要 AI 化和智能化改造。未来甚至可能是一个 Agent 和 Agent 交互的世界：人类可以雇很多 Agent 给自己打工，自己成为消费者。AI 会把过去富人才能享受的服务平权化，让普通人用很低的价格获得医疗、健康、咨询、助理等各种高质量服务。

今天的商业世界主要还是人和人交互构建出来的，今天使用的 App 也大多服务于人与人之间的交互。但未来很可能会被 Agent 交互重构。真正值得投入的，是尽早学习 AI 能力，建立想象力和实践能力，让自己能在这个新世界里参与生产，而不是只做旁观者。

## 9 AI 时代的产品方法：用 Demo 定义未来，用 Agent 交付结果
### 9.1 结构性机会来了：把精力放到 AI 编程和 Agent 上
未来的交互方式会发生很大变化。今天我们使用的手机、微信，以及大量现有软件，未来都可能被新的 Agent 形态替代。对创业者来说，这会带来一批全新的机会，所以当下不要只盯着小机会，而要盯结构性的变化。

在这个阶段，最重要的事情是把精力投入到 AI 编程、Codex 和 Agent 上。哪怕从就业角度看，AI 使用能力也已经成为一个非常直接的筛选标准：AI 用得差，可能连深入聊的机会都没有；AI 用得好，就值得进一步交流。

对普通人更切实可行的路径，是先把 AI 学会，先看到最佳实践：那些真正用 AI 做业务的人，工作流是什么样的，生产力工具是怎么用的。今天最值得投资的事情之一，就是花最多的钱、最多的精力去学 AI。

这里有一个很重要的判断：再省不能省 token。

社区里曾经讨论过“如何用 10 个亿 token”。这个问题的价值不在于今天真的能不能用掉，而是它会倒逼你重构工作流。按照现在的做法，大多数人一天肯定用不了 10 个亿 token，这说明现有方法本身不对。于是你就会开始思考：

- 哪些事情可以做减法？

- 哪些事情可以做乘法？

- 哪些事情根本不应该再做？

- 如果目标是赚 100 万、1000 万，现在还缺什么条件、资源和人？

一个人不是把手头所有事情都按原样做完，就能做到 1000 万规模。真正的变化发生在他开始倒推：为了达到那个目标，我现在什么不具备？需要请教谁？需要补什么资源？需要改变什么做事方式？当他这样思考时，大脑和工作流才会被重构，也才会慢慢靠近目标。

### 9.2 AI 产品方法论：第一版如果不尴尬，说明上线太晚了
做 AI 产品的方法论很简单，第一条就是快。

第一版不要管做得多完整，先把最核心的功能做出来，哪怕非常粗糙，也要推给用户。如果你的第一版产品上线时，你自己都不觉得尴尬，那就说明它上线得太晚了。

TokenRank 就是这样做出来的。最早只是花了大约 20 分钟做了一个 demo，甚至没有注册新域名，只是用了一个老域名的子域名直接上线。上线后发到群里，很快就有 100 多个圈友把自己的 token 统计发上来。看到这个反馈之后，才开始认真把 TokenRank 作为一个产品继续做。

所以，做产品不要有完美主义。先把 demo 做出来，推给用户，然后高频迭代。迭代频率可以非常高，一天提交几十次代码、做几十次功能调整和版本发布。

当然，对不懂技术的人来说，产品大概率会在某个时间点崩掉，或者再也改不上去，也就是所谓的“屎山代码”。但这不是一开始就要避免的事情。因为一开始你根本不懂，却要求自己先学完整架构、先设计完美架构，这并不现实。

更合理的路径是：

先做一个非常 demo 的产品；

推出去，让真实用户使用；

高频迭代，逐渐想清楚产品功能和用户需求；

到某个临界点，再让 AI 做重构。

前期乱的是代码，但被验证出来的是功能和需求。当产品功能、用户需求进一步明确之后，再基于这些确定性去重构代码，AI 重构会非常快，也更容易让代码支撑当前阶段的性能和产品要求。

工具选择上，能用 Codex 就用 Codex。如果暂时用不了，就找身边能用的人帮忙。关键不是纠结工具名，而是要真正把产品做出来。

### 9.3 用 Demo 文化替代评审：老板和负责人要亲自定义问题
在 Agent 时代，协作方式也会变化。过去一个想法要写 PRD、开评审会、讨论方向；现在更高效的方式是直接做 demo。不要只是说“我有个想法，咱们讨论一下”，因为当你准备讨论的时候，完全可以先把它做成一个真实可看的产品雏形。

Demo 一出来，团队立刻就知道：原来是这样，不是那样。一个抽象想法在每个人脑子里可能有 10 个不同方向，但 demo 会把方向收敛成一个共识。

这也是为什么 AI 是老板的一把手工程。老板、合伙人、操盘手、负责人，在 Agent 时代的核心职责会变成：

看见未来，判断未来方向；

用 AI 把未来的产品形态做成 demo；

通过 demo 定义问题、审美、标准和方向；

再把产品交给擅长工程的人持续迭代和维护。

没有任何人会比一把手更懂自己的用户、需求、场景，也更懂长期想象、使命和愿景。团队成员未必能理解这些抽象信息，但 demo 做出来以后，所有人会立刻达成共识：这就是我们要的东西。

这样的协作模式可以大幅提高效率。擅长判断方向和做 demo 的人，就负责快速定义 demo；擅长工程的人，就负责工程化、迭代和维护。比如 TokenRank，先由负责人定义出形态，再交给团队成员参与维护。这样每个人的效率都会被拉到最高。

这个方法不只适合内容型团队，也适合电商、制造业、传统行业。因为做 demo 的成本在 AI 时代已经很低，主要成本就是 token。比如传统行业过去做一个 3D 或 AR 模型，可能要花几十万；现在用 AI 先做出一个模型给老板看，老板立刻就能判断方向行不行。不管什么行业，用 demo 降低沟通成本、提高决策效率，都是成立的。

### 9.4 生财的下一步：从交付内容，转向交付结果
过去两三个月里，一个很重要的发现是：生财未来不应该只是给用户看内容，也不应该只是让用户参加航海，而应该直接给用户交付结果。

比如一个人想做自媒体，过去的路径是自己学习内容、参加训练、照着方法做。未来的路径应该是：用户选择一个方向，平台通过大量 Agent 直接把结果交付给用户。无论是做视频、做内容，还是做电商，平台都应该把可执行的作品、方案和反馈循环交付出来。

半年前这还只是一个愿景，但现在内部已经开始真正做这件事。团队正在全员转向 FDE、后端和 Agent 工程能力，目标是让几十个人都能开发 Agent 产品，服务用户拿结果。

这意味着用户不一定要先学会所有东西。用户只要选一个感兴趣的方向，平台先交付一个结果，用户拿去执行；执行后，AI 帮他复盘、调整，再交付新的产品或作品，用户继续发布。这样循环下去，用户会更轻松地获得正反馈。

这个体系不一定能帮人直接发大财，但可以帮助用户达到一个初级水平，甚至行业腰部水平。到了腰部之后，天花板能有多高，更多取决于个人天赋和手艺。顶尖水平仍然是手艺活，平台未必能替代；但把大量用户送到腰部水平，是完全有机会做到的。

未来一部分商业业态会变成：用户不再只是学习一个东西，而是购买对应的 skill 和 Agent，让它直接帮自己做。

有人会担心，如果人人都能这样做，是不是就会同质化？这里有两个判断。

第一，内容和平台本质上有概率属性。两个人发同样的内容，哪怕都发 20 条，结果也可能完全不同。没有人能承诺谁一定会被概率击中，但有一个原则是：**数量可以抵抗概率。**只要数量足够多，坚持去做，大概率就会获得一些小反馈或中等反馈。

第二，Agent 反而可以解决同质化。过去只有一篇内容、一个模板，大家照着复刻，才更容易同质化。未来 Agent 可以研究爆款、调研数据，同时结合每个人自己的行业、个性、对标对象和表达方式，生成更个性化的东西。不是让所有人一样，而是让每个人更不一样。

### 9.5 Agent 时代的精华是 Skill：工作台会变成 Skill 和 Agent 中台
Agent 时代，真正的精华形态会是 skill。过去社区里的“精华帖”沉淀的是经验和方法，未来这些经验和方法会被进一步沉淀成可调用的 skill、Agent 和 MCP。

所以生财会从内容社区，逐步变成一个 skill 商城和 Agent 中台。用户进入平台后，能够看到大量优秀 skill、优秀 Agent，以及团队整合的数据和实战经验。

这里的关键是“实战”。公域里也有一些平台在做 skill，但很多 skill 太宽泛，对创业者和具体业务不够落地。真正能帮人赚到钱的，往往是从实战派经验里总结出来的 skill 和 Agent。

内部已经在做 AI 工作台的内测。团队先面向内部配置工作台，因为几十个人手上已经有大量 skill 和 Agent。内部跑通之后，再面向生财用户开放。目标节奏是 8 月上线内测版本，9 月进一步正式化。

未来也会欢迎用户上传自己的 skill 和 Agent。如果某个 skill 被调用很多，帮助其他用户拿到收益，平台也会给上传者对应的激励和奖励。这会形成一种共赢：用户把自己的经验 SOP 化、工具化，别人可以调用，自己也有机会获得管道收益。

### 9.6 七条 AI 航海：从小程序、海外到视频、Agent 和 Skill
接下来一轮航海会全部围绕 AI，不再做跟 AI 无关的方法。核心方向是把经验提炼成可共享、可复用、可操作的 SOP 和 skill。

第一条是 AI 小程序。小程序非常适合中国人做产品：成本低，不需要供应链，能快速获得反馈，在小红书、抖音等平台还能享受到一些推广红利。现在依然有很多细分需求没有被充分满足。这个方向不只是“做一个小程序”，而是研究并服务一群具体人群，可以被当成长期事业来做。

第二条是用 AI 做海外网站，包括海外游戏站、海外文章等方向。这个方向不要求学员懂技术，因为 AI 正在把技术门槛拉低。过去 2022、2023 年开始做海外工具站时，已经有教练和参与者拿到不错反馈；现在如果想长期切入海外，AI 海外网站仍然是一个低成本入口。

航海和深海圈的区别在于：航海是周期性的，通常两三个月开一次，一次 21 天左右，更适合探索方向、寻找方向；深海圈则是一年周期，会配置老师和助教，陪伴用户在某个领域长期深耕。如果还在探索，航海是低成本切入点；如果已经想清楚要在某个领域深耕，深海圈更合适。

第三条是 AI 高质量视频。过去 AI 视频更多是赚一点视频号、YouTube、抖音的流量收益，但最近几个月，AI 做高质量视频、短电影、短剧的能力已经大幅提升。抖音 6、7 月份的 AIGC 大赛里，已经出现很多质量很高的 AI 电影；推特上也经常能看到 5 到 10 分钟的 AI 电影。

这个方向要教的不是一眼粗糙的 AI 视频，而是有剧情、有质感、可落地的高质量视频。落地场景可以是短剧、带货、电影，也可以是流量收益；可以真人出镜，也可以结合数字人。比如图像模型、数字人、视频生成之间如何融合，都会成为实操内容。相关团队从 2024 年 9 月左右就开始做海外 AI 视频，到现在已经积累了接近两年的实践。

第四条是 AI 视频带货。这个方向已经出现了一些非常赚钱的案例。

一个案例来自视频号大健康类数字人视频。那条自然流视频的点赞和转发总量不到 500，但带的是一个六七十元的大健康产品，据说连续卖了 70 万，接近 1 万单。这个案例无法完全证实，只能说明存在这种可能性，但类似机会在视频号里确实很多。

另一个案例是宁波做专升本获客。一个销售通过非常简单的 AI 数字人线索视频获客，视频形式朴素到只是一个素人出来讲“你可能是专科，可以来报本科”。但这类视频对家长非常有效。机构里一单成交提成 1 万元，他两个月赚了 27 万。

还有抖音中视频计划的案例。有人用 AI 做不露脸的 PPT 类、讲解类视频，平台曾给出很高激励：一个点赞几百、比如 700 左右的视频，可能拿到三四千元费用。这个激励现在是否还存在不确定，但它说明 AI 视频和平台激励结合时，放大效应会非常明显。

还有圈友在 3 月份左右用 AI 视频带货，在视频号做出几百万 GMV。整体判断是：**会用 AI 的人，正在碾压不会用 AI 的人。**如果你不会用 AI，即便找到一个项目，也可能被会用 AI 的人从效率和产能上碾压。

第五条是 Agent 从 0 到 1。核心技术栈是 Codex、爱马仕 Agent 和飞书 Cli，目标是教大家如何把这一套闭环跑通，搭出自己的第一个 APP。这个判断不是简单列三个工具，而是团队踩了很多坑、交了很多学费之后沉淀下来的统一技术栈。有老板愿意花 10 万来学这套方法，因为真正有价值的是背后的判断和路径。对学员来说，学习过程会被尽量简化，有些步骤甚至只需要复制一段提示词给 ChatGPT，它就能帮你完成。

第六条是 AI 第二大脑。这个方向会结合 Obsidian 和自媒体场景：选题、素材收集、素材生产、内容分发。目标是帮助用户构建自己的 AI 计算大脑和 AI 知识库。很多人用 AI 越用越累，本质上是没有重构工作流；AI 第二大脑要解决的就是工作流改造问题。

第七条是如何做 skill。过去社区教大家“如何写精华帖”，现在要进一步教大家“如何做 skill”：如何把自己的业务经验、方法论提炼成 skill，如何把经验 SOP 化，并共享给别人调用。

这七个方向分别是：AI 小程序、AI 海外网站、AI 高质量视频、AI 视频带货、Agent 从 0 到 1、AI 第二大脑、AI Skill。每一个都和 AI 强相关，也都代表了更长期的趋势。

### 9.7 线下大课：用 AI Native 的方式重构工作流
线下大课的核心，也不是单纯讲工具，而是用 AI Native 的方式重构工作流。很多人做 AI 越用越忙、越用越累，原因是没有把整个工作流改掉，只是在旧流程上叠加新工具。

课程会包含两个重点：第一，搭建 AI 原生知识库；第二，在现场两天时间里做出自己的 Agent。上海场是广州场的复刻和升级，内容会进一步加强，比如现场用 Codex 做 AI 视频，用 Remotion 这套技术把 AI 视频做出来。

广州场曾经有 500 人同时现场实操，有人第一天晚上做到凌晨 3 点，有人直接通宵交稿，现场氛围很强。甚至有学员带着新买的 Mac 到现场，电脑包装纸都还没撕开，就直接开始学习，这种勇气本身就是 AI Native 的状态。

这次线下课的三位老师分别代表三个方向。

包子本身是抖音高客单业务的头部 IP，他自己的视频、直播间框架、评论区回复、后端产品，很多都是 AI 完成的。一个人基本能顶 100 个人的战斗力。

叁斤是多次航海教练，在知识库搭建和 Agent 基建方面有丰富经验，会负责带大家搭建相关基础设施。

楚川服务过很多头部电商公司和本地生活公司。他的团队 10 个人一个月能生产 150 万张 AI 图片、10 万个 AI 视频，背后依靠的是扎实的 AI 工程化体系。对于想放大 AI 产能的人来说，这套体系尤其有价值。

整体来看，无论是航海、工作台，还是线下大课，核心都指向同一个方向：不只是学习 AI，而是把 AI 变成产品、工作流、Agent、skill 和可交付结果。

## 10 从线下大课到 AI 中心：把“看见”变成可落地的产品能力
### 10.1 最后一场 AI 线下大课：用两天时间跨过从 0 到 1
这次 AI 主题线下大课会在上海开，也是这一主题的最后一次。北京和深圳不再开同主题场次，后续会切换到新的主题。上海站可以理解为广州站的升级复刻，适合两类人：一类是已经会用 AI、希望放大自己能力的人；另一类是还不太会用 AI，但愿意拿出勇气来学的人。哪怕是带一台刚拆封的 Mac 到现场，从零开始一步一步学，也可以。

之所以强调线下，是因为成年人学习 AI 最大的挑战，往往不是钱，而是勇气：愿不愿意拿出完整两天，什么事都不干，去挑战一条很陡的学习曲线。真正要学会 AI、学会做 agent，中间有无数个从 0 到 1 的小门槛：搭环境、装工具、充值、买设备、理解工作流、把一个业务目标拆成 agent 能执行的任务……这些琐碎门槛会把很多人挡在门外。

线下大课的设计，就是把人放到一个高密度环境里逼自己完成突破。现场 500 个人一起做，有老师、有教练、有组长、有同伴，也会给每个人一个明确的业务 agent 目标。上一站广州 500 人现场实操，效果很好，后来有 200 多人发朋友圈反馈。

这里有一个很重要的判断：**AI 时代最重要的是“看见”。**很多时候，不是一个人完全学不会，而是没有真正看到别人怎么做、工具怎么跑起来、一个 agent 如何从无到有地被搭出来。看见之后，认知和行动会立刻不一样。

这次大课定价为非圈友 5999 元，圈友 4999 元。如果加入航海家，则是 16700 元，包含四次大课/大会权益。后续 9 月还会在杭州开一场千人大会，类似的千人大会每年大概会有两场。

直播中也提到，现场来不及回答的评论区问题会被导出整理，后续可能以文章或帖子的形式集中回应。同时，生财的 agent 工作台已经在内部上线调整，预计 8 月在生财内部小范围内测，如果内测效果好，9 月正式上线。

### 10.2 生财有术 AI 中心：内容由 AI 生产，也由 AI 消费
第二个重点是生财有术正在做的 AI 中心。背后的判断很直接：**内容不再只是给人看的，内容也不再只是由人写的。未来会越来越多地出现“AI 创造内容，AI 消费内容”。**既然这个趋势挡不住，不如进一步顺着趋势往前走。

过去大家会去生财官网看帖子、找内容。接下来，生财有术会把首页调整成 AI 主页，也就是 AI 中心。这个主页背后会有几百个，甚至几千个 agent 作者，在不同领域持续寻找、创作和整理优质内容。

这些 agent 作者会有非常明确的分工。比如：

有的 agent 专门看 GitHub 最近有什么好项目；

有的 agent 专门看推特上最近有什么新玩法；

有的 agent 专门盯产品负责人 Tibo 今天有没有发帖、有没有“重置”；

有的 agent 研究 Reddit、小红书，或者特定人物和领域。

未来如果出现一个新工具、新项目、新机会，AI 中心里的 agent 可以直接生产从 0 到 1 的完整教程，并把相关内容呈现在首页。用户以后再打开生财，可能刷到的不再是传统的信息流，而是一个由大量 agent 作者持续生产的 AI 首页。

这个产品已经在内部上线并进入内测。节奏上，如果顺利，下周可能先上线 0.1 版本，先快速上线，再快速调整。第一版会通过后台定义不同的 agent 作者，让它们分别研究 GitHub、Reddit、小红书、特定人物等方向，然后统一在 AI 中心发布内容。

更关键的是，AI 中心未来会开放 MCP。生财有术会先自己使用，确认体验足够好之后，再把 MCP 开放给大家。到时候用户可以用自己的 Claude Code、Codex、WorkBuddy，或者其他 agent 接入生财内容，让自己的 agent 浏览、筛选、总结出真正重要的内容。

这意味着，生财有术不只是自己用 agent 生产内容，也会把这些内容供给用户自己的 AI。用户的 AI 将获得大量围绕赚钱、创业、AI 的高质量内容，再按个人需求重新筛选和使用。

### 10.3 FDE here：让真正会 AI 的人把技能变成收入
生财接下来会在官网上线一系列服务型产品，其中一个重要方向是帮助大家成为 FDE，掌握并变现 AI 能力。

很多人会遇到一个问题：我学了 AI，也确实有能力，但怎么赚钱？我既要学 AI，又要跑市场、接单、谈客户，这些商务动作并不是每个人都擅长。FDE here 想解决的就是这件事：做一个匹配和撮合平台，把有 AI 服务需求的老板，和真正会用 AI、能做服务的人连接起来。

现实里有很多老板并不想自己研究所有细节。他们可能通过学习知道了 AI 的边界在哪里，也知道某件事大概能怎么做，但不愿意亲自下场处理工具、流程和交付。这时平台就可以把需求接过来，匹配给会 AI 的人。只要你 AI 用得好，就可以通过平台对接企业，帮他们做服务，并获得收入。

这里有一个很大的市场背景：中国大约有 6000 多万家企业，未来几乎都会面临 AI 转型。但真正懂 AI 的人非常少。生财目前有 3 万个会员，其中 AI 能力特别强的人可能只有几千个；这几千人里，真正有精力、愿意接单服务企业的，可能只有 1000 人左右。把这 1000 人放到中国企业市场里，供给是严重不足的。

所以，问题不是 AI 能力没有价值，而是缺少市场和评估平台。生财前面做航海、大课、项目训练，本质上都是在提升大家的 AI 能力。拥有这些能力之后，你可以自己做 agent、做产品、创业；如果暂时没有创业能力，也可以带着 AI 能力去服务企业。平台负责帮你解决商务需求，帮你找需求、找老板。哪怕一年服务几家企业，可能就能覆盖掉原本一年的工资收入。

关于“核心 SOP 会不会泄露”的担心，也有一个判断：**FDE 最重要的不是一份可复制的文档，而是 AI 技术能力和行业认知能力。**前者来自长期做 agent、做产品的实践积累；后者来自服务足够多企业后形成的行业经验。这些都是习得的知识，不是简单可见、可偷走的信息。别人即使拿到一些资料，如果没有亲自实践，也很难真正习得。

### 10.4 IdeaHunt：用 agent 捕捉用户吐槽里的赚钱机会
另一个即将上线的产品，可以理解为 agent 时代的风向标，暂定叫 ID Hunt。它会派出很多 agent 去找赚钱情报，把分散在各个平台上的用户需求和吐槽收集出来，再转化成可能的产品机会。

这些 agent 会去 Reddit、小红书以及各种评论区，搜索用户未被满足的需求。很多时候，用户在评论区的一句吐槽，背后就是一个具体产品需求。比如有人参加“AI 做小程序”的航海，真正卡住的并不是技术，而是不知道做什么、不懂需求在哪里。ID Hunt 要做的就是把需求先找出来，让会员看到：原来这个也可以做，那个也可以做。

找到需求之后，行动可以非常直接。你甚至可以回到评论区，找到正在吐槽的人，告诉他：我做了一个东西，你要不要？1.9 元卖给你。甚至可以先卖，再做。这类情报收集 agent 的核心价值在于，输出的不是抽象趋势，而是一个个可尝试的赚钱机会。

这个产品被认为可能是大家最想要的，因为它呈现的几乎全是赚钱机会。项目方自己也会用很直接的方式验证需求：把 demo 发给大家，如果有人愿意付 99 元定金，就说明这个东西确实有市场。

它还会承担收集、整理和翻译的工作。很多机会最早出现在海外，例如英文站点、海外社区或产品案例里。即使有翻译工具，直接阅读仍然很痛苦。把这些机会整理成更适合中文用户理解和使用的内容，会显著降低行动门槛。

### 10.5 优质 Skill 与项目仓库认证：降低判断成本
现在懂技术的同学经常会去 GitHub 搜 TikTok 相关项目，也会看到大量 Skill、习作和各种项目仓库。但问题是内容太多，普通用户很难判断什么是好的、什么值得学、什么值得用。

因此，生财会在 AI 中心里做一类认证和背书：对围绕赚钱、搞流量、做产品等方向的优质 Skill、优质项目仓库进行筛选、认证和推荐。它解决的不是“有没有资源”的问题，而是“面对海量资源，用户如何判断优劣”的问题。

### 10.6 数矿：解决 agent 产品最容易卡死的数据获取问题
最后一个产品叫“数框”。它要解决的是很多人做 agent 时最容易被卡住的问题：数据拿不到。

做 agent 或 AI 产品，光有模型和想法不够，还必须有独特的数据。小红书数据怎么拿？推特数据怎么拿？自己的飞书知识库怎么拿？微信数据怎么拿？各种平台上的录音怎么拿？这些问题会直接决定一个产品能不能做出来。没有数据，就很难做出真正独特的产品。

数框会成为一个关于“各个平台数据怎么获取”的集合地，把团队和社区在实战中总结出的零散方法整合起来。它会告诉你：什么情况下应该用爬虫，什么情况下应该用接口，什么情况下应该用 cookie，哪些平台有哪些可行路径。拥有这样一个集合后，数据获取这一块就不再是大问题。

这类信息的价值在于，它原本非常零散，而且有些方法并不会出现在公开场合。生财有术会把这些从实战中来的经验整合起来，形成一个可复用的产品。相关功能大概率会在一个月内陆续上线，多数功能会面向会员免费，只有高 token 消耗场景可能收少量服务费。

从这些 demo 里可以看到一个共同逻辑：**AI 时代，“看见”本身就是推动产品落地和用户买单的关键。**过去只讲概念，用户可能不知道你在说什么；但把图、demo、流程拿出来，大家立刻能判断这是好东西。

团队之所以有信心快速上线这些功能，是因为内部已经有 agent 工程师，并且正在用“十倍产出”的方式做产品。以前可能三四个人做一个东西、做一个月；现在目标是一个人完成三四个人的工作，一周做完。只要这个方向跑通，很多产品都可以快速被做出来。可以理解为，背后有七八十个人在围绕会员需求做产品、提炼需求、验证需求，并持续满足这些需求。

## 11 从 Agent 黑客松到生产级产品：把 AI 能力变成可分发、可售卖、可迭代的工具
### 11.1 会员权益、数据能力与 Agent 黑客松平台
围绕即将上线的一系列 AI 产品和工具，核心原则是：大多数能力都会优先纳入会员权益，对圈友免费开放。只有在某些功能涉及大量额外 token 消耗、成本明显较高时，才可能收取少量 token 服务费。也就是说，平台不是把每一个新功能都单独收费，而是尽量把能免费提供的能力都打包给会员。

其中一个重要规划，是 Agent 黑客松平台。很多企业想组织内部黑客松，很多社群也想组织黑客松，但往往缺少方法、流程和组织经验。团队过去已经组织过不少黑客松，因此希望把这些沉淀下来的流程和方法产品化，让其他人可以借助这个平台组织自己的 AI 黑客松。

这个平台不仅服务外部组织，也会服务生财内部。未来的周末聚会可以是一场黑客松，未来的航海也可以是一场黑客松。比如一次航海有 1 万人参与，大家一起比赛，看谁能把一个 Agent 做出来。做出来之后，再从中评选好的 Agent，由生财帮助分发、展示甚至售卖。

这背后对应的是一个 Agent marketplace 的思路：圈友做出的产品，不只是自己用，也可以进入生财的作品广场，被更多真实用户看到。比如有人做了选题平台、AI 客服、AI 销售、数据抓取工具、AI 视频剪辑工具，只要自己用得好，也有可能发布到生财。生财会帮助展示这些 Agent、Skill 或工具，如果用户反馈好，就进一步帮助售卖。

很多普通创业者最缺的不是想法，而是第一批真实用户。 有了第一批客户之后，开发者才能知道产品该怎么高速迭代，才能让产品越做越好。未来生财作品广场的价值，就在于让圈友做出的产品先在圈友中获得真实反馈和初始用户。

### 11.2 生财官网将改造成 AI 主页，白话 AI 小百科帮助补齐基础概念
现场展示的七八个 demo，虽然被称为 demo，但并不是早期概念原型，其中很多已经接近生产级工具、Agent 或平台，具备实际使用价值。接下来一两个月内，生财官网也会进行一次大改版，原来的主页会被替换成 AI 主页。甚至“生财有数”这个名称，也在考虑是否需要调整，因为未来承载的内容已经不只是原来的形态。

在这些规划中，还有一个面向基础学习者的产品：白话 AI 小百科。

虽然现在很多人在深入使用 AI，但仍然有大量用户不了解 AI 的基础概念。比如 loop、token、模型、神经网络等词，大家在直播、课程、工具说明里经常听到，但未必真正理解。白话 AI 小百科要做的事情，就是把这些常见概念以通俗方式展示出来，并为每个概念配上对应案例。

它的目标不是把知识讲得很学术，而是让普通用户看完之后能够意识到：原来这些概念并没有那么神秘。只要先把基础概念弄清楚，后面理解工具、理解 Agent、理解 AI 工作流，都会轻松很多。

### 11.3 航海将上线 AI 亦仁匹配项目，七个 Agent 要在 8 月上线
关于航海活动，现场明确了一点：航海本身是免费的，不额外收费。同时，本次航海会把“AI 亦仁”和“找项目”结合起来，上线一个 AI 亦仁帮用户匹配项目的功能。

用户只需要输入自己的基础背景和信息。如果自己判断不了该选什么项目，AI 亦仁会根据这些信息帮助推荐更适合的方向。这个功能会在本次航海中上线。

此前展示的 7 个 Agent，也有明确上线要求：团队内部的目标是 8 月份必须上线。主讲人提到，自己目前很大一部分时间仍然在承担工程师角色。他会把自己的工作状态切分成两类：

战略日：主要思考战略，几乎不消耗 token；

工程师模式：当战略想清楚之后，开始进入开发和迭代，token 消耗会逐步上升。

接下来，一旦进入工程师模式，这些产品就会开始高速迭代。

### 11.4 用 AI 写程序越修越乱，本质是技术判断力还不够
现场有人提出一个很实际的问题：做程序报错后让 AI 修复，结果 bug 越修越大，应该怎么办？

这个问题的本质，不完全是 AI 不行，而是使用者自身对技术的功底和判断力还不够。当你不知道问题出在哪里，也判断不了 AI 给出的修改方案是否合理时，AI 很容易把代码越改越复杂。这个阶段会经历很多试错，但它本身就是成长的一部分。

不经历几次重构，技术能力很难真正成长。 做产品时，不要一开始就追求架构完全正确，也不要幻想存在一套放之四海皆准的正确架构方法论。每个产品都不一样，早期最重要的是先把东西推出去，只要能用、能跑，就先让它跑起来。

等到某一天，产品跑着跑着发现确实跑不动了，功能也相对成熟了，需求也相对清晰了，这时再用更好的模型进行一次重构，反而更合适。因为这时你已经知道真正的问题在哪里，也积累了足够多的经验。此前所有踩过的坑、所有 AI 改不好的地方，都会成为你的学习素材。

主讲人也提到，自己一开始甚至不会用 worktree，不会用 Git，但产品照样能跑；后来才在实践中慢慢补齐这些能力。所以关键不是一开始就完美，而是做中学、干中学，不怕犯错，不要完美主义。

团队内部也在通过统一技术栈和 Agent 脚手架来降低这类问题出现的概率。比如有人曾经因为代码问题导致线上客服产品报错，花了两个月重构整个项目，这类过程很痛苦，但也是从 demo 走向生产级产品时必经的训练。

### 11.5 内部三套 AI Agent 培训课：从做出 Agent 到做成产品
围绕 AI Agent 的生产能力，内部已经形成三套有梯度的培训课。

第一套，是面向从 0 到 1 做 Agent 的基础训练。它会讲 Codex、爱马仕 Agent、飞书 Cli 这一套技术栈，帮助一个人完成从零开始做出 Agent 的过程。这套内容未来也会在航海中给圈友讲，内部也在用同样的方式培训团队。

第二套，是从 demo agent 变成真正生产级产品的训练。这个阶段不能只停留在前端 demo，而要进入数据库、MCP、API、网络、产品发布、Git、worktree 等完整工作流。主讲人希望团队成员都能从 demo agent 进一步进入后端，具备持续维护和迭代产品的能力。

第三套，则进入更前沿的层面，包括产品判断、AI 基建和 loop 工程。这里要回答的问题包括：什么产品需求是有价值的？什么值得做，什么不值得做？知识库怎么搭建？怎样为 AI 做基础设施？怎样让人尽可能从循环中跳出来，让 AI 管理 AI，从而提升整体消耗量和生产效率？

这三套课是逐级递进的。第一套更适合普通圈友入门；第二套适合已经进入 AI 生财圈、想把 demo 做成真实产品的人；第三套目前团队自己也还在学习和探索，但一旦跑通，也会逐步同步给大家。

整体路径是：先改造自己的工作流，先做一些工具；接下来尝试推出面向 C 端的产品，让别人真实使用；随着产品上线、功能复杂度提升，再通过后续培训补齐技术和产品能力。核心不是闭门学理论，而是跟着生产节奏往前走。

### 11.6 AI 商学院、3365 会员与生财的服务对象
在未来的 AI 主页中，还会有一个“AI 商学院”模块。团队会把常用的 AI 课程录成视频，上传到网站上，用户可以直接观看。内部也已经培养了不少 AI 老师和 AI 讲师，后续会由他们为大家上课。

如果是圈友，这些 AI 相关课程会免费开放。这也是为什么现场反复强调 3365 会员权益很划算：不仅有商学院课程，还会有多个 Agent 可用，也包括过去和未来的航海内容。

主讲人解释，生财之所以能在知识付费很难做的环境下继续成长，是因为团队并不是单纯把自己定义为“做知识付费”。知识付费只是一种交付形式，真正想服务的是像他们自己一样的草根群体：没有资源、没有背景、能力也普通，但希望在 AI 时代找到机会，赚到钱，拥有生存和生活的底气。

很多产品需求也来自这里。主讲人提到，有人问这些需求是怎么想出来的，其实是因为他真切地看到圈友还有很多痛点没有被解决。过去有些事情能力做不到，比如直接交付结果、帮大家把内容发到平台拿反馈；现在 AI 能力和团队能力到了，就可以大胆往前走。

这种真心实意想帮用户解决问题的态度，也形成了双向反馈。团队做的事情被认可，用户也愿意继续支持。2025 年生财续费率达到 70% 多，这是一个很高的续费率，也被视为圈友认可的结果。

所以，未来这些 Agent 和产品，能免费的都会尽量免费，能打包到会员里的都会尽量打包。对于还不是圈友、或者资金比较紧张的人，AI 亦仁目前每天也开放了几次免费体验机会。主讲人希望这也能成为一种福利，让经济条件暂时不够的用户，也能把自己的困惑讲给 AI 亦仁，获得一些帮助。

### 11.7 先把 demo 跑通，再用真实反馈决定是否继续开发
谈到应用 demo 应该怎么用，主讲人的建议很直接：先在本机把 demo 跑通，然后通过飞书妙搭，或者飞书 CLI 的能力，把它分享给同事或用户体验。这种能力有点类似海外的 Vercel，也类似最近一些工具上线的站点功能。

把 demo 分享出去之后，看真实用户是否觉得有用。如果反馈好，再进入开发、迭代和正式推出；如果反馈不好，就换一个想法。不要一开始就憋一个完整产品，先做出可运行 demo，用反馈决定下一步。

这也是从想法到生产级项目的重要过渡：不是先追求完美，而是让产品尽快进入真实场景，让同事、用户、圈友先用起来。

### 11.8 Token 排行榜：消耗量不是能力的全部，但低消耗很难有高产出
最后提到的一个项目，是 AI 编程 token 消耗排行榜。这个产品会抓取用户本地各种 AI 编程软件的 token 消耗数据，并聚合到榜单中，让大家可以看到自己的使用强度和相对位置。

早期可能一天消耗 1 亿 token 就能进入 Top 100，但现在一天 5 亿 token 可能都不一定能进 Top 100，难度已经明显提高。用户可以去统计自己在 Cursor、Workbody、ProCode 等工具中的日 token 消耗。如果每天能消耗几个亿，已经相当不错，可能有机会在生财的排行榜中上榜。

主讲人也提到，在社区里已经有一些高强度使用者，平均一天能消耗十几个亿 token；他自己目前大概是一天小几个亿。

这里的判断很重要：token 消耗高，不一定代表能力强；但 token 消耗太低，大概率说明你的 AI 工作流还没有真正重构起来。 当一个人真的把大量工作交给 AI、让 AI 参与开发和生产，token 消耗自然会上升。排行榜不是为了炫耀数字，而是用数字反推工作流是否发生了变化。

## 12 用 Token 消耗倒逼工作流重构：AI 时代的并发生产能力
### 12.1 Token 消耗不是能力本身，但低消耗很难产生高能力
现在最顶级的一批 AI 编程玩家，日消耗 Token 已经到了非常夸张的水平：当天排行榜第一名是 45 亿，第二名 38 亿，第三名 34.7 亿。包子老师复工后，上午测试大课的 Remotion 视频流程，就已经消耗了十几个亿；李香君、小排老师也都在 18 亿左右，李香君据说同时在跑 10 个项目。

这组数字不是为了制造焦虑，而是为了让大家看到一个新的参照系：Token 消耗不代表你一定厉害，但不消耗 Token，大概率是不厉害的。

因为真正高强度使用 AI 的人，一定会在持续交互中执行大量任务、调整架构、拆解需求、重构流程。哪怕一个人每天能稳定消耗 10 亿 Token，也不要小看他。也许他在现实世界里看起来并不显眼，但他能把 10 亿 Token 用掉，背后必然有任务管理、工作流设计、多线程调度和持续执行的能力。

所以可以给自己设一个阶段性目标：不是一上来就追 20 亿、50 亿，而是先想办法把每天的 AI 使用量拉上去。比如每天至少投入一两个小时，哪怕不知道做什么，也可以直接问 AI：

我今天应该做点什么？

我今天想消耗 1 亿 Token，应该如何安排任务？

我现在的工作流有哪些可以交给 AI？

哪些事情可以拆成并发任务？

先把使用强度拉起来，再观察边界在哪里。只有当 Token 消耗上去了，你才会发现什么任务值得做、什么任务没价值、什么流程需要重构。

这也是 Token 排行产品的意义。这个产品 6 月上线，目前还没有正式推广，已经有 1600 多名圈友上榜。早期因为技术架构和数据采集不够扎实，统计上也出现过问题，比如 GPT 5.6 的子节点导致重复计算。产品经过几次重构之后，才逐渐稳定下来，后续会推广给更多用户使用。这个过程本身也说明：做产品必然会遇到问题，技术功底不扎实就会有 bug，只有持续重构，产品才能变得可靠。

### 12.2 AI 时代的核心指标：同时运行多少项目、多少线程
在 AI 时代，一个人厉不厉害，不只看他会不会用某个工具，而要看他背后同时有多少个项目、多少条线程在运行。

过去很多人习惯单线程工作：想到一个需求，自己慢慢做；做完一个，再做下一个。但 AI 时代真正拉开差距的，是多项目、多线程、并发生产的能力。只有 AI 供给能力上去了，人才有可能把判断力、审美、标准和产品直觉放大。

一个典型案例是 OpenClaw 创始人 Peter。他一个电脑上同时开了将近 40 个线程，还把更多任务分发到更多电脑上，估计同时可能有 100 个线程在跑。这样的任务管理一定不是靠人脑硬扛，而是 AI 在管。

这背后对应的是一种新的工程能力：Look Engineering。也就是通过工程化方式，让 AI 帮你管理任务、拆解流程、推进项目、持续反馈。当 Look Engineering 能力上去之后，一个人就可以同时并发跑多项目、多线程，生产能力和判断力会被无限释放。

这也是为什么要先学 AI 编程、学 AI 技术。不是因为每个人都要变成传统意义上的程序员，而是因为如果没有工程能力，判断力无法被放大。光有产品直觉、审美和想法，但没有能力把它们变成系统、流程和产品，最终还是上不去。

所以短期看，Token 消耗像是一个“虚荣指标”；但在早期阶段，先过正是有必要的。先把消耗量拉上去，逼自己重构工作流，逼自己从单线程走向多线程，逼自己思考如何让 AI 接管更多任务。过了这个阶段之后，才有能力反过来判断哪些消耗是有价值的，哪些只是浪费。

### 12.3 不要在模型和 Token 上省钱
很多人担心每天消耗 10 亿 Token 成本太高，但实际情况并不一定需要通过 API 去烧钱。现在榜单上大部分高消耗用户，用的是订阅账号额度，而不是 API。比如 200 多元的订阅账号，基本可以支撑每天几个亿的额度；如果不够，还可以通过多个账号、重置机会等方式扩展。

关键不是鼓励大家乱花钱，而是提醒大家：再省不能省 Token，再穷不能穷模型。

如果你真的想提升 AI 能力，就不要在最关键的模型和额度上过度节省。能用更强模型，就尽量用更强模型；能用更适合编程和任务执行的工具，就不要只停留在普通对话式聊天。

这里有一个很重要的分水岭：很多人觉得 AI 没用，是因为他们用的模型不够强，或者使用方式停留在浅层对话。不是说国产模型不好，但如果你从来没有用过 Claude、Codex、Claude Code 这类更适合复杂任务和代码执行的工具，你对 AI 的理解会完全不同。

现在真正重要的，不是只会打开一个聊天窗口问问题，而是要学会用 Codex、Claude Code 这样的工具，把 AI 放进实际工作流里。能不能用好这些工具，已经成为理解 AI 能力边界的关键。

如果是公司内部，也可以搭建中转服务，解决团队成员网络环境或统一管理的问题。分享者所在公司内部也做了中转，供同事使用，目前整体付费消耗大概一天 100 亿 Token，其中专业技术同事每天大概消耗五六十亿。预计再过一两个月，公司内部日消耗可能会到 1000 亿级别。

但对个人来说，优先建议还是买好订阅账号，少走质量不稳定的中转站。中转站能不能用，很大程度上取决于服务方是否靠谱；能用订阅号，就尽量用订阅号。

### 12.4 产品判断力和工程能力要同时升级
当一个人开始多项目、多系统地开发产品时，会发现真正稀缺的不只是执行力，还有判断力。

因为所有问题都会被抛到你面前：要不要做这个功能？什么时候做减法？什么时候继续往前推？什么时候停下来重构？什么时候砍掉一个需求？如果没有产品判断力，多线程并发只会让你手忙脚乱。

这里特别推荐张小龙的产品观。张小龙最厉害的地方，是产品直觉和做减法的能力：不无限加东西，而是在极度聚焦的基础上，把核心能力放大。只有先聚焦、先做减法，再叠加工上的控制能力，能量才会非常可怕。

接下来要提升的方向有两个：

第一，把产品判断力继续提升，可以读《微信背后的产品观》，理解产品如何做减法、如何保持克制、如何聚焦核心体验。

第二，深入研究 HALLIS 和 Mook 这一类工程方法，把 AI 工程能力再推上一个台阶。

这两者是乘法关系。不是在所有方向上乱铺，而是在极少数、极聚焦的领域里做得非常深、非常透，再用工程杠杆放大。这样一个人有机会变成 10 倍强、100 倍强，甚至 1000 倍强。

真正有想法、有判断力、有抱负的人，在这个时代是可以做到 1000 倍强的。

因为未来一个人有可能服务过去几百个人才能服务的需求，一个人有可能为圈友做几千个产品，一个人有可能把大量重复、繁琐、复杂的流程全部交给 AI 执行。前提是，他既有判断力，也有工程化能力。

### 12.5 万事先让 AI 做：从小任务开始重塑习惯
AI 不应该只在“我要做一个大项目”的时候才出现，而应该进入日常工作的每一个环节。

比如整理发票这件小事，过去要自己去邮箱里找、下载、归类、做成表格。现在可以直接让 AI 帮你下载下来，再整理成飞书表格。人离开电脑两个小时，回来之后事情已经处理好了。

这类小案例的重点不是技术有多复杂，而是习惯要改变。万事第一反应先想：能不能让 AI 去做？尤其是你想偷懒的时候，更应该让 AI 去做。

如果今天只记住一句话，那就是：用 Codex 帮你干任何事。

不是只用它写代码，而是让它处理各种事务：整理资料、拆解任务、生成脚本、下载文件、做表格、跑流程、写产品、改后端、迭代功能。你越早把这种习惯建立起来，越早能进入真正的 AI 工作方式。

这也是为什么不用过度担心某个赛道会不会很多人做。比如 AI 做小程序，理论上参与者可以很多，但真正有执行力、能长期做下来的人没有那么多。与其担心别人也在做，不如关注自己能不能坚持把 AI 用起来，能不能持续迭代，能不能把产品推到生产级。

### 12.6 未来三类核心人才，都需要具备自研 Agent 的能力
未来最有价值的人才，大致会分成三类。

第一类是 Owner。也就是老板、操盘手、负责人。他们能够对结果兜底，事情交给他之后，老板就不用再操心。他能承担责任、推动结果，这类人未来有很大的创业机会。

第二类是 Agent Builder。也就是能开发、迭代、维护 Agent 的人。企业会非常需要这类人，因为未来大量业务流程都会被 Agent 化，需要有人把需求变成系统，把经验变成流程，把流程变成可运行的智能体。

第三类是 IP 或 Influencer。也就是能跟用户沟通、理解用户、建立共情、影响用户的人。人和人的连接依然重要，这类人依然有很大价值。

但一个关键变化是：无论你是哪一类人，如果你自己不会开发和使用 Agent，也没有人能持续为你提供这套能力，你的效率会非常受限。你的竞争对手一旦有了自研 Agent，你会发现自己慢慢跟不上。

包子老师就是一个典型案例。他既是 IP，也是 Owner，但他学会了 AI 编程，给自己做了大量功能和产品。现在他的视频内容已经可以托管给 AI，全自动生成，再发布到抖音。他做的是 7 分钟左右的长视频，每条视频至少几百个赞，有的几千个赞；短短两周内，围绕高考志愿填报赛道，他做出了接近 100 条视频。

这就很难竞争。因为你面对的不是一个人，而是一个人背后由 AI 放大的生产系统。你如果不懂这套能力，只能靠老天爷赏饭吃；但对方可以持续、高频、稳定地产出。

所以，不管你是 Owner，还是 IP，都不能长期寄生于别人。每个人都要勇敢地往后端走，去开发 Agent、维护 Agent，把自己的业务流程和产品能力沉淀成系统。

### 12.7 进后端，是能力跃迁最快的方式之一
很多人以前没有真正进过后端，也没有独立把一个产品开发上线、让用户持续使用。但一旦真正做过一次，能力会发生明显跃迁。

分享者在 6 月开发 Token Rank 产品时，一天提交了将近 40 次代码，从凌晨 5 点一直提交到晚上 11 点。过程中 AI 帮忙做了大量辅助工作，也暴露了很多问题，需要不断试错、修复和重构。但正是这次深入后端、解决实际问题的经历，让他的能力比之前强了很多，也建立了非常重要的信心。

这种信心不是听课听出来的，而是把产品做出来、让用户用起来、遇到 bug 再修掉之后长出来的。

所以大家要有勇气接触后端。AI 做小程序、AI 做网站、AI 做 App、AI 做生产级产品，都会不可避免地遇到后端问题。刚开始不懂没关系，跟着做、跟着错、跟着迭代，慢慢就会积累。积累到一定程度，就可以承接更复杂的项目。

这件事不是只有年轻人能做。20 岁、40 岁、60 岁，本质上没有区别。年龄不应该成为限制。40 岁、50 岁的人反而有经验、有判断力、有社会资源，如果再叠加 AI，可能非常适合转型。AI 可以弥补体力上的短板，把经验、创造力、判断力放大。

## 50 岁也可以是创业正当时，40 岁更还很年轻。

### 12.8 学会用 Codex，是普通人进入 AI 时代的最短路径
如果把今天的技术建议压缩成一句话，就是：学会用 Codex。

不用先纠结复杂的技术三件套，也不用一上来就担心自己是不是懂技术。先把 Codex 用好，过一段时间你会感谢这个选择。

学会 Codex 之后，至少有两条路：

第一，自己用它做产品。无论是小程序、网站、App，还是内部工具，都可以从一个小产品开始，做出来、迭代、推广，慢慢跑通路径。

第二，把这个能力卖给企业。现在企业非常需要 AI 用得好、能落地工具、能打通流程的人。你可以入职，也可以提供服务。

市场上已经有报告提到，FD 相关岗位日薪大概在 2000 到 4000 元之间，但真正能提供工具和落地能力的人非常少。如果你 AI 用得好、认知能力强，就有机会为身边的老板、企业和团队提供服务，对方大概率愿意付费。

不过，如果想从事更深入的 AP 或 FDE，只会做基础 demo 不够。企业需要的是生产级能力，不是玩具级演示。你必须学 AI 编程，必须进入后端，必须能够打通生产线。市面上有很多免费课程可以学；如果需要系统学习，也可以通过 AI 编程生产圈、航海实战训练营等方式跟着老师和项目走。

这类训练的重点不是“听懂概念”，而是让你真正做出东西。比如 AI 做国内小程序、AI 做海外网站、AI 做高质量视频、AI 做视频带货、AI 做知识库、给 Agent 沉淀专属技能等，每一条都应该尽量精挑细选，保留那些无法再删、学完就能带来实际收获的方向。

### 12.9 不要只盯短期赚钱，先掌握创造价值的能力
有人会问：如果 10 个人里只有 1 到 2 个人短期赚到钱，那普通人参与这些 AI 项目有什么意义？

这里最重要的回答是：不要只盯着钱。越只盯着钱，反而越赚不到钱。

长期来看，收入一定会回归到个人创造价值的能力。短期会有波动，有些项目会赚钱，有些不会；但长期一定会回到一个均值：你能创造多少价值，就会获得多少回报。

而在新的时代，创造价值的核心能力，越来越接近于几件事：

你消化数据和信息的能力；

你使用 AI 的能力；

你把 AI 变成产品和流程的能力；

你开发、维护、迭代 Agent 的能力。

所以学习 AI、做 Agent、用 AI 做产品，并不只是为了某个短期项目赚多少钱。短期项目可以作为训练场，带大家更接近结果，但真正重要的是把能力长出来。

能做 Agent，比短期赚钱更重要。

不管你未来是上班、做服务，还是自己创业，最终都需要这套能力。如果没有这些能力，哪怕一开始靠项目赚到一点钱，很快也会发现自己做不下去。

### 12.10 打工人同样需要 AI 能力，它会变成职场稀缺价值
AI 能力并不只适合老板和超级个体，打工人同样适合，而且非常需要。

在相关生产群体里，打工人的比例可能有 40%，甚至更多。很多人并不想马上转型，也不想创业，但这并不影响他们学习 AI。因为如果一个打工人 AI 用得好，在职场中会极具竞争力。

现在几乎所有企业都需要 AI 用得好的员工。企业需要的不只是会聊天的人，而是能把 AI 用进业务、流程、工具和结果里的人。只要你具备独特价值、稀缺价值，就会在供需关系里变得更抢手。

所以对打工人来说，最现实的策略不是先辞职创业，而是在当前岗位上尽可能给自己增加独特能力：让 AI 帮你提高产出、优化流程、自动化重复工作、承担更复杂任务。当你能做到别人做不到的事，你的职场价值自然会提高。

## 13 从内容社区到 Agent 平台：AI 时代的组织、人才与个人跃迁
### 13.1 生财的两个战略方向：Agent 平台与 FDE 人才服务
生财接下来会从一个内容社区，转向一个「成果工作台」。所谓成果工作台，核心不是继续让用户看更多内容，而是通过 Agent 直接给用户交付结果。这个事情过去还只是想象，现在已经开始变成现实。未来一两个月内，希望能有一些 Demo 做出来，让用户可以直接使用。

内部已经先做了一个自媒体平台，团队里相关部门的人都开始做自媒体，并且已经有人做出了爆款。这个平台如果能够赋能整个公司做自媒体，也就有机会赋能整个社区做自媒体。生财希望把类似的能力产品化，把结果交付给用户，而不是只交付信息。

AI 主页已经上线了 0.1 版本，目前正在高速迭代。接下来希望让大家看到 Agent 时代的生财会变成什么样：航海不再只是一个需要阅读和执行的项目手册，而会直接变成 Agent。用户不需要自己一页页看内容，而是跟着航海 Agent 拿结果。无论是做短视频、做网站、做小程序、选框架、写公众号爆文、做星图、做抖音，背后都会基于项目整合大量 Skill 和 Agent，把这些能力直接交付给用户。

这一次航海已经有一个明显变化：会提供大量 Skill。未来基于项目，平台会持续整合 Skill 和 Agent，让用户甚至可以直接调用 Agent 拿结果，再把结果发布到对应的平台。

因此，生财正在押注的第一个方向，是从内容社区转向 Agent 平台，通过 Agent 给用户直接交付结果。

第二个方向，是成为 FDE 人才的培养和服务机构。平台会帮助圈友掌握 AI 的技术、知识和能力，并通过项目训练这些能力。同时，生财也会整合外部企业资源，让掌握能力的人可以去接企业的单子、服务企业。

现在外部已经有很多企业在问：有没有 FD 人才可以推荐？有没有人可以帮他们做 AI 化服务？但现实是供不应求。内部虽然也有这样的人才，但自己都不够用，根本没法大规模对外输出。很多企业都有 AI 化改造的需求，但市场上没有足够多的人能进入每一家企业。

所以，生财的第二个战略方向，是推进圈友成为 FD 人才：掌握 AI 技术，靠这些能力要么自己做 Agent，要么去帮企业做运营和改造赚钱。

这件事不是短期机会，而是至少十年的机会。因为中国有大量企业都需要做 AI 化转型。现在在身边真正会用 AI、会用会员、会用工具的人其实非常少。生财才 3 万个会员，即便 3 万个会员全部成为 FD，也依然供不应求。

也不需要太担心被大厂挤压。中国市场太大了，出来创业和赚钱时，不应该把「大厂会不会做」当成主要顾虑。下一个时代一定会长出新的大厂，而不是所有机会都被今天的大厂拿走。很多大厂现在只是在原有产品上加 AI 能力，目的是维护既有用户量，但并不是真正的 AI Native。Agent 原生的新机会，反而会给小团队和个体带来新的窗口。

### 13.2 企业 AI 化改造：第一责任人一定是老板
企业做 AI 化改造，第一责任人一定是老板。老板不能只让员工学，也不能只是找外部机构来做改造。真正有效的前提，是老板自己必须懂 AI，必须亲自深入使用 AI。

只有老板自己深度用过、学过，才会对 AI 的能力边界有强烈认知：什么东西能做到，什么东西做不到；什么要求合理，什么要求不合理。否则，老板不知道该如何给团队提要求，也不知道如何设立标准。员工说做不到，老板也没有能力判断是真的做不到，还是标准太低。

当老板自己能通过 AI 做后端，能并行推进多个项目，才有资格对同事说：我能做到，你也可以做到。这样企业才有机会进入深入的 AI 改造。

因此，团队内部现在提出的标准是：过去 30 天的工作，现在要尝试一周干完；过去一周的工作，现在要尝试一天干完。到 8 月底，希望团队里的 Agent 工程师有人能做到稳定的 10 倍输出，也就是同时有 10 个进程在产出。团队里已经有人出现这样的苗头。一旦榜样出现，整个团队就会向他看齐。

当每个人每天的生产都可以稳定消耗大量 Token、调度多个进程时，企业的价值创造会非常可怕。一个人创造的价值，可能相当于过去一个小团队的总和；几十个人，可能相当于几十个生产团队，甚至一两千个生产单元的产出量。

这也是为什么 AI 工程能力、AI 编程能力不只是程序员该学，而是所有职场人、所有老板，只要对未来还有追求，都应该掌握的能力。它就像当年「上网」一样。早年上网也需要自己配置路由器、拨号网络，很多人搞不定就没法上网。今天学 AI、搞定 Agent，也有类似的门槛。越早上车，越早享受红利；等所有人都会了，就不再稀奇。

FD 背后有两个基础：第一，老板或服务者本身业务能力足够强；第二，要 AI Native 地做改造。未来好的 FD，很可能来自各行各业本身的一线经营者。因为企业改造不是抽象地接入工具，而是要理解行业上下游、业务流程和真实场景。

一个例子是做珠宝的夜息。他原本是珠宝行业老板，看到珠宝行业未来几年增量有限，便开始做 FD，帮助一些电商企业做 AI 化改造。因为他自己先在企业里做过 AI Native 的改造，有最佳实践，所以很愿意给电商行业做服务。未来各行各业都会出现本行业自己的 FDE：既懂业务，又懂 AI，又能把案例、判断和审美反哺回自己的业务。

### 13.3 孩子、高考生和不懂代码的人，也可以进入 AI 产品时代
AI 学习不只适合成年人，也适合更低龄的人群。高考后的孩子如果有空闲时间，可以尽早来学 AI。初中、高中、大学阶段的人，学习 AI、做 AI 产品都非常适配。

一个 5 岁孩子也可以开始做 AI 小游戏：让她用语音输入，说清楚自己想做什么，把需求按 1、2、3 表达出来；Demo 出来之后，再问她想怎么改。这个过程能帮助孩子建立一个闭环：只要把需求表达清楚，就可以把产品做出来。 等孩子再大一点，就可以进一步带她做商业化产品。

此前线下大课也有高中生参加，上完之后收获很大。对于孩子来说，先来学习、先了解 Agent 相关内容，本身就是很好的起点。

很多人担心不懂代码能不能学 AI 编程。答案是可以。Token revenue 产品就是一个例子：整个产品做出来的过程中，没有写过一行代码，甚至没有看过一行代码。核心不是会不会看代码，而是有没有判断力。

过程中当然需要不断了解基础技术架构，但有了判断力之后，并不需要亲自看代码、写代码。代码本质上是逻辑，而 AI 可以帮助完成代码实现。这个时代最关键的不是懂代码，而是懂逻辑、懂判断、懂产品。

### 13.4 团队 AI 化改造的三步：老板先懂、员工提效、统一技术栈
团队做 AI 化改造，可以分三步走。

第一步，老板自己要懂。老板要具备 AI 编程能力，能够通过 Codex 或 Claude Code 做出生产级项目。老板不懂，AI 改造第一步就已经失败了。不能指望团队其他人替老板完成组织改造。老板自己要去学、去链接高手、去提高标准。

第二步，鼓励团队所有人用 AI。这个阶段不要设太多限制，而是提供支持：Token 支持、账号支持、网络支持、电脑升级支持。过去半年，团队内部就是支持大家尝试，AI 账号可以报销，电脑要升级也可以支持。

这个阶段员工会百花齐放地尝试，但公司业务未必立刻发生明显变化。即使员工个人效率提高了，也只是压缩了自己的工作时间，多出来的时间不一定马上转化为业务产出。这是正常的。第二阶段的目标，就是先让员工把个人工作的一部分时间压缩掉。

第三步，统一技术栈，树立标杆。团队现在统一的技术栈是 Codex、Hermes 和飞书，并围绕这个技术栈设计三套培训：

第一套课是「三道剑」，让所有人都可以做 Agent；

第二套课让所有人进入生产级流程，每个人都可以做产品；

第三套课让所有人追求 10 倍产出，每个人都可以稳定消耗多个进程。

与此同时，内部要聚合好的 Agent 和 Skill。团队自己开发了一个类似 Agent 导航网站、Skill 导航网站的内部平台，并建立评价体系，把好的 Skill 和 Agent 梳理出来，奖励对应的同学和作品。这样大家能看到标杆是什么，也会形成氛围和压力，推动所有人进一步学习 Skill、学习 Agent、学习如何做产品。

内部还有一个 AI 局小组，每天分享自己怎么用 AI，有什么新玩法。好的东西会在这个过程中慢慢涌现出来。

所以，团队 AI 化改造是一个从上到下、再从下到上的过程：一开始老板自己写、自己实践，理解边界和方向；接着团队开始大面积尝试；等有了规范和标准之后，再大量涌现好的 Agent 和 Skill。

### 13.5 未来人的差距：谁能调度更多 Agent
未来人与人的差距，核心不再是谁更努力，而是谁能调度更多 Agent。

一个明显的标杆是沈龙潇创始人，他能同时调动上百个 Agent。这件事非常夸张，也给人一个清晰的努力方向：如何创造出更多 Agent，如何调度更多 Agent，让它们帮助自己干活、创造价值。

这件事目前比单纯做项目更值得投入时间。今年 418 时曾经说过：如果上班影响你学 AI，那你应该辞职学 AI。现在这个观点仍然成立，只是 AI 这件事变得更具体了——它具体成了 Agent。

如果老板年纪大、没耐心学，年纪本身不是限制。没耐心往往是因为看不到正反馈。解决办法是找一个 AI 助教，贴身带一带，让学习者尽快获得正反馈。另一个办法是进入学习环境：线下几百个人一起学，白天老师带着实操，晚上还有晚自习，氛围会倒逼人持续投入。环境会成就人。

### 13.6 进入「言出法随」的创造时代
两三个月前，很多工作还没有 Agent 可以替代；现在，大多数工作已经可以由 Agent 协助完成。进入正循环之后，会明显感觉自己每一两个月都在升级：两个月前的自己和两个月后的自己，能力差距非常大。

这种变化不是幻觉，而是真实能力的提升。尤其是创造价值的能力变大了。过去只有想法，现在可以把 Demo 做出来；过去只是设想一个产品，现在下个月就可能开发出来。

现在已经进入一个新的时代：你想要什么，就可以把它创造出来。核心四个字是——言出法随。你有一个想法，AI 就能帮你实现。中间的路径，就是每个人需要学习的部分：如何让 AI 快速、稳定、可靠地帮你做到。

很多人关心 Token 成本，觉得一天消耗 5 个亿、10 个亿很贵。但如果这些 Token 能创造有价值的东西，它仍然是便宜的。过去要创造同样的东西，可能需要招很多人来完成。真正稀缺的不是 Token，而是好的想法和好的判断力。

好的想法和判断力从哪里来？答案是实践出真知。要弄脏双手，亲自动手，不断犯错、不断尝试、不断学习，再继续动手、继续犯错、继续从实践中学习。

如果只用一句话指向 AI 能力的路径，那就是：动手，用好 Codex，是目前最好的路。

### 13.7 方向选择、工具选择与后续学习
如果参加了几次线下活动，尤其是大航海之后仍然迷茫，不知道往哪个方向努力，建议先从一个方向开始。今天已经讨论了很多方向，本次航海也有 7 个方向，可以先瞄准一个自己感兴趣的方向。与此同时，把 AI 用起来，至少先玩起来，把它当成自己的兴趣。

工具选择上，如果能把 Coze 用通，其他类似工具就不必都学。但也要看到，Coze 目前体验并不算特别好，也还在探索方向。它一段时间推 Skill，一段时间又像验证工具，仍处于转型中。

更值得优先投入的是 Claude Code、Codex 这类优质工具。可以看到，Codex 和 Claude Code 的方向正在越来越像。既然有最好的工具，就先把最好的用好，不要退而求其次。

不建议再去学 N8。与其分散精力追很多工具，不如围绕最强的工具和 Agent 工作流，真正把生产能力跑出来。
