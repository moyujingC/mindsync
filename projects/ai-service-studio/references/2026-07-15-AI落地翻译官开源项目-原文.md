## README 关键内容

### 项目标题

AI 落地翻译官（AI Landing Translator）

### 项目标语

你说你的业务，我翻译成 AI 能做的事。

### 项目提出的问题

README 中把企业老板面对 AI 落地时的卡点概括为：

- 知道 AI 很厉害，但不知道能帮自己的业务做什么。
- 问 AI 后得到的结果要么是技术术语，要么是泛泛的工具建议。
- 问题不在 AI 能力本身，而在缺少“业务到 AI 可执行事项”的翻译。

项目把这个问题称为三个“翻译问题”：

1. 场景翻译：有哪些业务环节可以让 AI 来做。
2. 执行翻译：具体怎么操作、用什么工具、花多少钱。
3. 落地翻译：先做什么、后做什么、如何避免翻车。

### 核心方法论

README 里提到三组方法：

1. 四层拆解法
   - 第一层：这个环节具体在做什么事。
   - 第二层：这件事的完整流程是什么。
   - 第三层：AI 在每一步里怎么介入，包括触发、输入、处理、输出、交付。
   - 第四层：AI 搞砸了怎么办，也就是兜底闭环。

2. 场景筛选矩阵
   - 用结构化程度和 AI 替代潜力筛选业务环节。
   - 目标是先做适合 AI 化的环节，不做不该做的环节。

3. SOP 九要素卡
   - 从需求定义到成功标准，把每个 AI 化环节变成完整作业标准。
   - 避免只停留在“让 AI 试试”的模糊状态。

### 六步流程

README 给出的流程是：

1. 破冰：了解业务，不聊技术聊业务。
2. 业务路径：把核心业务画成流程图。
3. 场景筛选：用矩阵筛出最值得 AI 化的环节。
4. 四层拆解：对优先环节做深度分析。
5. 工具成本：推荐具体工具，并算清投入产出。
6. 输出报告：生成完整的 AI 落地路径图。

README 声称整个过程大约 20-30 分钟，输出一份行动指南。该时间和效果为项目作者表述，未在本次录入中独立验证。

### 使用方式

项目提供两种使用方式：

- 直接对话：把 `SKILL.md` 内容放进 Claude、ChatGPT、DeepSeek 等 AI 助手的 System Prompt 或 Custom Instructions 中，再通过自然语言描述业务。
- 生成 HTML 路径图：进入 `references` 目录，使用 `generate.py` 和行业配置文件生成可保存、可分享的 HTML 报告。

示例命令：

```bash
cd references
python generate.py --config config_ecommerce.json --output AI落地路径图_电商.html
```

README 中列出的适用对象包括：

- 企业老板：想用 AI 提效但不知道从哪里下手。
- 业务负责人：需要给团队制定 AI 落地计划。
- AI 从业者：需要一个结构化方法论帮客户落地。
